# 宽泛主题 → 分层 prompt 库 → 逐条取证报告 → 对抗质检 → 知识库

一条把"想系统学/审/调研某个大主题"变成"一套查全、查实、可复现、经得起质检的报告库"的完整流水线。
把工作分两半、分账：**准备工具**（造 prompt 库，阶段 1–3）与**使用工具**（逐条取证出报告，阶段 4–6）。
先把"要查什么"做全，再把"查实了什么"做深。适用：备考/学习某领域、审计某代码库、调研某技术栈。

---

## 贯穿全程的核心原则

**编排类**
- **逐层细化**：coarse(定范围) → medium(定方向) → fine(造 prompt) → deep(逐条取证)，每层比上层细一个量级。
- **每层并发**：多个 subagent 并行（按正交维度 / 按相关性分组），**一条消息里发多个 Agent tool call**。
- **每层落盘复用**：每层产物写成文件，下一层的 subagent 读上一层的文件作输入。
- **subagent 直接落盘**：让产出内容的 subagent 自己 Write 文件，**不要**让主 agent 逐字转录（省 token、防失真）。
- **优先级贯穿**：每个最小单元标 P0/P1/P2，便于按执行顺序产出与消费。
- **进度可恢复**：committed ledger + push 是唯一抗上下文压缩 / 容器回收 / 额度中断的进度真相源。

**严谨性红线（决定"事实是否成立"，全程不变）**
- **一手优先，逐级下沉**：结论坐落在一手来源（规范 / 官方文档 / 提案 / 源码 / 亲自实证）；二三手只补白、交叉验证、指路，**绝不承重**、一律打 `⚠`。
- **无定位不成结论**：任何非平凡断言都有可回溯的精确定位（章节 / 符号 / 源码路径@版本 / 提案编号 / 命令+环境串）。定位落到文末脚注，不逐句内联。
- **严禁凭记忆编造**：可核验的细节（版本号、默认参数、反汇编下标、命令输出）**要么真跑取证、要么如实留白**。这是最易违反、最伤信任的一条。
- **规范与实现分账**：标准/规范保证的语义 与 某具体实现的实际行为，分开标注，绝不混为一谈。
- **基线锚定 + 版本溯源**：固定一个版本/环境作基线，结论**先给基线状态**再标 delta（无变化也明写）；每个对象交代引入版本、演进史、当前成熟度。
- **前沿/未定型硬标**：预览 / 孵化 / 草案 / 已撤回 / 未 GA 的对象，全文硬标"非 GA、目标版本、随时可变、不作结论"，并实证坐实"基线上确实不可用"（撤回 ≠ 暂停）。
- **偏执复核**：关键命题至少用一个独立一手源尝试证伪一次，通过才落稿。

**交付形态红线（决定"理解是否传递到位"）**
- **严谨性 vs 交付形态分账**（最容易搞反的一条）：严谨性纪律是**作者的内部工作流**（过程痕迹**不进成品**：对抗复核怎么做的、检索打嗝、覆盖自查表——都是工作记录）；交付物是**教学叙事**（心智模型→机制→真实证据→陷阱）。判据：**读者读到的是"这东西是什么、为什么、怎么运作"的连贯讲解，不是"我如何做研究"的审计轨迹。** 仅当某处存疑**直接影响读者要用的结论**时，才用一句 `⚠存疑` 点明并给替代定位。
- **对抗质检是交付的一部分**：产出后用**独立** subagent 逐点对照原始 prompt 复核、判级、再修。自己写的自己审 = 没审。

## 阶段 0 · 对齐范围（问用户，用 AskUserQuestion 一次问清）
决定后面每一层的四件事：
- **主题**与**广度**（全部 / 核心子集 / 含前瞻热点）。
- **基线**：锚定哪个版本/环境？（所有结论的参照系）
- **取证强度**：只读文档，还是要读源码 + 本机实证（决定"三条腿"要几条）。
- **交付形态**：纯机制详解 / 含示例 / 含真题…；引用用内联还是脚注。
- **节奏**：并发度、分几轮。

---

## 阶段 1 · 广度 scoping（并发多路，正交维度）—— 造对象地图
从 N 个**互补、少重叠**的正交视角并发收集"待研究对象清单"。
- **通用视角模板**：权威规范 / 行业实践 / 最新动态。
  - 示例（AWS SAP-C02）：① 官方考纲 in-scope ② 生产高频服务（不唯考试） ③ 近 1–2 年热点。
- 每路一个 subagent：联网检索、优先官方一手、**核实时效**（标注核实日期）。
- 合并去重 → 一份「对象地图」，每个对象标注"来自哪些视角 + 归属分类/域"。
- 落盘 `round1-<主题>-map.md`。

## 阶段 2 · 中度定方向（按相关性分组并发）—— 定重点 + 选型对比
- 把对象按相关性编 **~10–15 组**（组内紧密相关，便于横向对比；组太多合并累、太少不聚焦）。
- 每组一个 subagent：对组内每个对象给「重点方向」+ **组内选型/对比表**（对比正是高价值点）+ 标优先级。
- 合并落盘 `round2-<主题>-deep-dive.md`，附"下一层入口"的优先级清单。

## 阶段 3 · 细度造 prompt（分组并发 + subagent 直接落盘）—— 产出 prompt 库
最小单元 = 「对象 × 方向」（一个对象可拆多个方向）。每组一个 subagent，读 round2 对应章节，为每个单元写一条**可直接投喂给调查 agent 的 prompt**：
- **格式**：首行 `[P0/P1/P2] 对象 — 方向`；正文是指令，导向阶段 0 定的交付形态（如"纯机制深度详解，覆盖：工作机制 / 数据流 / 参数默认值 / 边界配额 / 失败模式 / 与相邻对象差异 / 设计权衡 / 时效核实点"），明确"不要出练习题""标来源"等约束；用 ```text 代码块包裹（便于复制 + 后续按块切分）。
- **subagent 直接 Write** 到 `round3-prompts/NN-组名.md`（首行加组标题、末尾留统计）。
- 主 agent 另写主索引 `round3-<主题>-index.md`（全清单 + 优先级 + 统计 + 执行建议）。

**阶段 3 合并（脚本，可选）**：把分文件合并成单文件，支持两种视图——**按组** 或 **按优先级（P0→P1→P2）**。切块单位 = 每个 ```text 代码块一条 prompt；读首行优先级标签分桶；桶内保持原组顺序；每条前加分隔。合并产物 `<主题>-prompts-by-priority.md` 放**源目录之外**（否则重跑会自包含）。

## 阶段 4 · 逐条取证（并发 + 每份三腿 + 每份落盘提交）—— 产出报告库

### 4.0 先备"承重环境"（一次性）
- 把被研究对象的**一手实现 clone 到本地、只读**（源码 / 规范离线副本），`gitignore` 掉——读实现比猜快、能 diff 版本。浅克隆 + 稀疏检出控体积；本地不含的部分报告注明"未取"，不自行推断。
- 装齐本机实证工具链，确认基线版本串（写进 brief）。
- 写一份**共享 brief**（仓库外，所有调查员先读）：基线版本、三条腿要求、源码路径、实证纪律、交付形态、脚注格式、"测试代码只准写仓库外、绝不入库"。brief 是把本方法论一次性灌给所有 subagent 的载体。
- 建 **committed ledger**（`round4-findings/00-progress.md`）：一行一条 `状态 | 优先级 | 组 | 标题 | 文件`，入库并推送——进度真相源。

### 4.1 一手分级阶梯（取证时按可信度自高向低取，同一命题多档可证时优先高档并交叉）
| 档 | 来源类型 | 定位到 | 主要回答 | 备注 |
|----|----------|--------|----------|------|
| 一手·规范/标准 | 官方规范、标准文本 | 章节 + 版本 | 权威语义、约束、留给实现的自由度 | 规范**留白 ≠ "无此行为"** |
| 一手·API 契约 | 官方 API 文档 | 符号 + 版本 + 引入标记（如 `@since`） | 契约、内存序/异常、默认值（若文档化）、引入版本 | 契约 vs 实现细节要分清 |
| 一手·设计意图/版本节点 | 官方提案 / 变更记录 | 编号 + 状态 | 为什么、哪版引入/定型、成熟度、动机权衡 | "哪版 GA/引入"以提案状态为准（版本溯源承重） |
| 一手·实现（**必读必用**） | 被研究对象的**源码本地副本** | 路径@版本标签 | 规范留白处的**真实行为**（工厂逻辑/运行时/布局） + 契约 + 引入标记 | 仅代表该实现、非规范保证；**要真读、不得只列不用**；讲历史 delta 可 diff 两版 |
| 一手·亲自实证（简单可复现的必做） | 就地真跑（反汇编 / 参数快照 / 最小程序 / 日志） | 命令 + 环境版本串 | 编码、默认值、布局、运行时行为 | "编码/默认值/布局"类结论**能实证的必须实证、不得凭记忆** |
| 准一手 | 核心开发者博客/talk/邮件列表 | 链接 + 日期 | rationale、历史缘由 | 噪声大，仅佐证意图 |
| 泛二三手 | 随机博客/问答/教程 | — | 线索 | **不得承重**；仅 (a) 补一手留白 (b) 交叉验证 (c) 指回一手；只靠它支撑的结论打 `⚠仅二手` 并列待补 |

> 严格立场：只对**已定型**（≤ 基线的下一个 GA）的对象做事实取证；未定型的只登记「编号 + 目标版本 + 当前状态」并硬标"不作结论"。

### 4.2 逐条投并发 subagent
每个 subagent：
- 先读 brief + 本方法论的取证与骨架规范 + 一份**范例报告**（形态基线）+ 自己那条 prompt；
- 先把 prompt **拆成若干可证伪的原子命题**，为每条预设"查全了长什么样"（要哪一档一手源、落哪个定位、要不要跨版本 delta）；
- **三条腿取证**（缺腿显式标注"未取/未验证"，不用记忆填平）：① 一手文档 ② 源码 ③ 本机实证——三者承重、贴**真实输出** + 可复现命令 + 环境串；二三手只佐证打 `⚠`；
- **覆盖自查清单**（作者的"信息不漏"检查，**不是**章节骨架）：`① 工作机制 ② 内部数据流 ③ 底层/源码落点 ④ 参数默认值 ⑤ 边界/配额 ⑥ 失败模式 ⑦ 与邻居差异 ⑧ 设计权衡 ⑨ 版本/成熟度`；一件事讲一次讲透，别因它同属①⑧就重复三遍；
- **冲突处理**：规范≠实现、版本 A≠B、来源打架时——**两边都记、各带定位、点明分歧、不和稀泥、不择一隐藏**（分歧本身常最有信息量）；
- **对抗复核**：关键命题换一个独立一手源尝试证伪一次（结果留作者工作记录、**不进正文**）；
- 产出一份**自足**报告（复现代码/命令贴进正文，别指望会被清理的 scratchpad），**自己 Write** 到 `round4-findings/NNN-<slug>.md`；
- 实证测试代码**只写仓库外 scratchpad**，跑完即清，**绝不入库**。

### 4.3 报告骨架（要素齐、顺序活；小标题措辞可调，但**不得**退回"1.工作机制 2.数据流…"编号盒子）
```markdown
# <标题>
> 来源 prompt ｜ 基线 <版本> + delta ｜ 引入 <版本/来源> ｜ 成熟度 GA/Preview/Incubator/Withdrawn ｜ 核实 <日期>

**一句话心智模型**：<把整个对象压成一句能记住的话>

## 它解决什么问题（为什么存在）      —— 背景与动机：没有它会怎样、它换来了什么，给读者"为什么学"的锚
## 机制主线：<用动词短语命名>        —— 工作机制 + 内部数据流（配流程/箭头图），关键结论挂脚注[^s1]
## 看得见的样子（本机实证）          —— 最小复现 → **真实输出**（真下标/真默认值）+ 可复现命令 + 环境串；严禁编造；纯示意图须标"示意"与真输出区分
## 关键规则与边界                    —— 边界/配额、参数约定、竞态与幂等
## 常见误解与陷阱                    —— 读者最可能踩的坑 + 正确认知 + 定位
## 和邻居的区别（辨析）              —— 在体系里的位置
## 设计权衡（为什么这么设计）        —— 成本换来了什么、提案动机
## 版本与成熟度                      —— 一句话溯源 + 表：引入版本 / 演进史(无变化明写) / delta；未定型仅登记
## 规范 vs 实现（想深挖再看）        —— 规范保证 / 实现行为，各带定位，后者标⚠实现级
---
### 一手引用清单（脚注定义）  [^s1]: <规范§/源码路径@版本/命令+环境串> — <一句话> · <URL>
### 二三手（非承重）          - [T1] <专家来源>（⚠仅佐证/指路）· <URL>
```

### 4.4 主 agent 每份完成时
核验抬头（基线串 / 脚注齐 / 无截断 / 无泄漏工具标签或控制字符 / 仓库内无新增测试代码）→ 更新 ledger 那一行 → **提交并推送** → 清该份 scratchpad。**先落盘先提交**：subagent 会因额度/压缩中途死，只有入库的才算数；失败的**重新 launch**（其最终消息常带已查到的关键事实，可作重启提示塞回）。

### 4.5 单份收口标准（同时满足两组才算完成）
- **严谨性**：所有原子命题落在一手定位，或明确标"规范留白/未文档化/未定型"；基线状态 + delta + 引入版本 + 演进史 均已给（含"无变化"）；成熟度标签齐；关键命题过对抗复核；二手承重项为零（或全打标待补）；覆盖自查通过。
- **教学性**：有一句话心智模型 + 问题背景；主线按"背景→模型→机制→实例→边界/陷阱"叙事、**不是**九维盒子；至少一处**本机真跑**的可观察实例（带命令 + 环境串，严禁编造）；有常见误解/陷阱小节；引用为 `[^n]` 上标、过程元信息不入正文；通读检验：一个没读过规范的中级从业者能顺着读完并建立正确心智模型。

## 阶段 5 · 对抗质检（独立分批审计 → 判级 → 修）
全部产出后（或每积累一批），投一组**独立** subagent，每个审 ~10 份：
- 逐份读**全文** + 读它对应的**原始 prompt**，**逐个子点核对**覆盖度；
- 核查方法论符合度（基线 / 三条腿 / 溯源 / 脚注 / 前沿硬标 / 规范-实现分账）；
- 红线抽查：可疑编造（与"真实输出"口吻不符 / 与已知冲突）、规范与实现混账、内部/跨报告矛盾；
- 判级 **PASS / MINOR / MAJOR** —— PASS（达标无实质问题）/ MINOR（小瑕疵，可选修）/ MAJOR（漏了 prompt 明确要求的一整块，如"两组对比只做了一组"；或疑似编造/事实错误，**必修**），给具体缺哪个子点、哪处可疑。

> **编号漂移分账**：产出序列（磁盘文件号）与规范序列（prompt 原序号）会因合并/跳过错位——建一张**显式映射**（disk N ↔ canon M），**按映射给审计员发 prompt**，否则误判"跑错题"；发现真遗漏（某规范条目无任何产物）单独补。

主 agent 汇总判级 → **MAJOR 与事实性错误必修**，MINOR 按价值补（多为"补一段/一句 + 交叉引用"）。修完再扫收口检查、提交。

> **订正 pass（怎么修）**：把 ⚠ 按 **计数 / 覆盖 / 行号 / 结构** 归类，投**最小编辑**订正 subagent——回一手源码/规范复验命中的那一点再改，**只补/改命中处，不重写全篇**（重写费 token、易引新错、易丢原有正确内容）。

## 阶段 6 · 收口与合并
- **整库一致性扫描**：每份有基线串、有文末脚注、结尾无截断、**无泄漏的工具标签/控制字符**（`grep -rlP '[\x01\x02]'`、扫整行 `</…>` 标签）、仓库内**无新增测试代码**（`.java/.class` 之类）。
- 主索引 / 合并视图：按组 或 按优先级两种视图；可复用合并脚本，切块单位 = 每份报告 / 每个代码块一条。
- ledger 汇总最终计数并**对账**：`grep -c` 台账行数 vs 各 counter 自报数，抓 off-by-N；**以真实落盘为准**，别信 subagent 自报。
- **质检留痕声明**：收尾时在 ledger（`00-progress`）汇总一句——"经 N 篇对抗质检，X✅ / Y⚠（判级摘要）"，作为阶段 5 执行过的凭据。

## 经验教训（踩过的坑）

- **让 subagent 自己写文件**：它们有 Write 权限。若只让它们"返回文本"，正文会卡在会话里、还得主 agent 转录——浪费且易失真。第 3、4 阶段一律 subagent 直接落盘。
- **复用已完成的 subagent**：用 SendMessage + agentId（上下文还在），让它把"刚才已生成的内容原样写入文件"，零重新生成；多轮多组时**核对 agentId**（对照"轮次+组名"，极易搞混）。
- **subagent 拒绝编造是对的**：若它发现指令与自身产出不符（如让它写它没生成的东西），它应**拒绝而非凑数**——健康行为，说明该换正确的 agent 或修正指令。
- **编造是头号红线且极隐蔽**：凭记忆写反汇编下标/默认值/版本几乎必错。能真跑的真跑贴真实输出，跑不动的以源码/规范承重并**显式标注未验证**；发现自己在"想当然"就停下去查。
- **前沿一律硬标**：预览/孵化/草案/撤回的对象，实证坐实"基线上还不能用"，标清状态与目标版本，绝不当 GA。
- **committed ledger + push 是唯一可靠进度记忆**：压缩/回收/额度中断都清空会话，只有入库推送的能 `git pull` 恢复；别把进度只记会话里。给报告抬头一个可 grep 的标志（如基线版本串），一眼分清"已做完"与"待做"。
- **subagent 会中途死**（额度/API/压缩）：只有落盘的算数；失败的**重 launch**，用其最终消息里的已知事实作重启提示塞回。
- **测试代码结构性隔离**：只写仓库外 scratchpad（在仓库树之外）+ `.gitignore` 兜底（`*.class`/`scratch/` 等），双保险防污染成果库。
- **报告必须自足**：复现代码 + 命令 + 环境串贴进正文，别写"见 scratchpad/…"（会被清理）。
- **让 subagent 自报"纠正了 prompt 哪一点"**：它们据实纠正 prompt/常见说法（源码/实证推翻假设）是**加分、健康信号**，往往是最有价值的部分，汇报里要专门收集。
- **控制字符 / 工具标签泄漏**：subagent 偶把不可见控制字符或 `</…>` 写进文件，界面上不可见却真实存在，提交前全库扫；**commit message 用 `git commit -F -` heredoc**，别把控制字符塞命令行（会被拒）。
- **计数以"切块 / 真实落盘"为准**：`grep -c '^```text'`（prompt 数）、`grep -c` 落盘报告（报告数），别信各 subagent 自报数。
- **全程核实时效**：知识会过期。每条结论标来源 + 核实日期；改名/退役/新 GA 单独核实。
- **shell 稳健性**：复杂逻辑写脚本文件再执行；双引号 echo 里别放反引号（触发命令替换）；用绝对路径避免权限提示。

## 落盘约定（建议）

```
study/<主题>/
  round1-<主题>-map.md            # 阶段1：对象地图
  round2-<主题>-deep-dive.md      # 阶段2：定方向 + 选型对比
  round3-<主题>-index.md          # 阶段3主索引：全清单 + 优先级
  round3-prompts/NN-组名.md        # 阶段3：prompt 全文（subagent 直接写）
  <主题>-prompts-by-priority.md    # 阶段3合并产物（按 P0→P1→P2；放源目录外）
  round4-00-methodology.md         # 把本方法论具体化到该主题+基线的取证协议
  round4-findings/
    00-progress.md                 # committed ledger：进度真相源
    NNN-<slug>.md                  # 阶段4：每条一份自足报告（subagent 直接写）
  .reference/<clone>/              # 一手源码/规范离线副本（gitignore）
  merge-by-priority.sh             # 合并脚本
<scratchpad,仓库外>/agent-NNN/      # 阶段4：实证测试代码（跑完即清、绝不入库）
```

## 规模弹性
- **轻量主题**：阶段 1 三路 + 直接产 prompt（跳过分组）+ 文档/少量实证 + 审计一遍，几条即可。
- **重型主题（整套认证 / 大型代码库 / 数百条）**：完整六阶段 + clone 一手源码 + ~10–15 组并发 + 并发 10 分多轮 + committed ledger 全程 + 分批对抗质检再修。按用户"全面/快速"伸缩并发度、层数、取证与审计力度。

---

> 一句话：把一个宽泛主题，先做成"要查什么"的分层 prompt 库，再逐条做成"查实了什么"的自足取证报告，最后独立对抗审计再修——产出一套查全、查实、可复现、不编造、经得起质检的知识库。上半场（阶段 1–3）= 利其器，下半场（阶段 4–6）= 善其事。
