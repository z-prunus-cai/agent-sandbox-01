# 报告格式规范（提案 v0 · 待用户改定）

> 本文件定义 Round 4 每份报告的**粒度规则**与**格式骨架**。与 skill `_methodology-skill.md` §4.3 的差异见「相对 skill 的调整」。
> ⚠ 这是提案，等用户改定后才作为 Round 3c/Round 4 的强制模板。

## 一、粒度规则（默认 1 大主题 = 1 报告，可拆）
- **默认**：每个大主题产 1 份自足报告，其小主题作报告内的小节。
- **拆分**：当某大主题满足以下任一，拆成 N 份（每份覆盖一簇连贯小主题，编号 `NNN-<slug>-a/-b`）：
  - 小主题数 ≥ 8，或明显跨两种以上不同机制/工具；
  - 单份预估过长（>教学可读上限）；
  - 一手取证成本差异大（如"概念"与"源码级实现"宜分账）。
- **判定落点**：在 Round 3c 造 prompt 时，由该组 subagent 对每个大主题给出「1 份 / 拆 N 份 + 理由」，主 agent 汇总入 ledger。最终报告总数 ≈ 424 起、按拆分上浮。

## 二、格式骨架（相对 skill 调整版）

### 抬头（每份必带，可 grep）
```
# <课ID·大主题号> <标题>
> 基线 Py3.11.15/np2.4.6/gcc13.3 @2026-07-25 ｜ 先修：<课/大主题> ｜ 一手锚点：<教材§/规范/源码@版本> ｜ 成熟度：GA/Preview/⚙演进快（仅系统/前沿课）｜ 核实：<日期>
```

### 正文段（★必选；○按主题类型可选/可裁）
- ★ **学习目标**（3–5 条「读完你能…」）—— 【新增，skill 无】KB 是学习导向
- ★ **一句话心智模型**
- ★ **为什么存在 / 解决什么问题**（背景与动机）
- ★ **机制主线**（用动词短语命名小节；配流程/箭头图；关键结论挂脚注）
- ★ **代码示例 / 本机实证**（真实输出 + 可复现命令 + 环境串；理论课=Python 数学库验证；严禁编造）
- ★ **关键规则与边界**
- ★ **常见误解与陷阱**
- ○ **与邻居辨析**（在体系里的位置；跨课重叠处引用另一份报告，不重复展开）
- ○ **设计权衡**（系统/工程课必选；纯理论课可省）
- ○ **版本与成熟度**（系统/前沿/工程课必选；数学/理论课通常省）
- ○ **规范 vs 实现**（有标准 vs 实现分歧时才出，如网络/DB/语言）
- ★ **小结**（把本大主题压成 3–5 条要点）
- ★ **脚注**：一手引用清单（`[^sN]` 定义）+ 二三手（非承重，打 `⚠`）

### 按主题类型的段落配置（裁剪指引）
| 类型 | 额外必选 | 通常省略 |
|------|----------|----------|
| 数学/理论（离散/线代/微积分/概率/自动机/算法/PL理论） | Python 验证段承重 | 版本成熟度、规范vs实现 |
| 系统（OS/网络/DB/组成/汇编/编译/并发/架构） | 本机实证、设计权衡、版本成熟度、规范vs实现 | — |
| 前沿（AI/LLM系统/新兴） | 成熟度硬标「⚙演进快·锚版本·不作定论」 | 稳定性承诺 |
| 工程与交付（软工/系统设计/SRE/容器） | 设计权衡、真实工具实证 | 规范vs实现（除非有标准） |
| 人本与社会（HCI/SEP） | 援引权威框架条款；实证腿弱如实说明 | 本机实证（改为案例/框架分析） |

## 三、相对 skill §4.3 的调整（明确差异）
1. **新增「学习目标」段** —— KB 面向自学，skill 原骨架无。
2. **抬头加「先修」** —— 体现课表依赖链，方便读者定位入口。
3. **段落模块化 + 按主题类型裁剪** —— skill 要求"要素齐"，这里允许纯理论课省略"版本成熟度/规范vs实现"，避免硬凑空段。
4. **单元 = 大主题（非整门课/单一对象）** —— 报告标题用「课ID·大主题号」。
5. **保留 skill 的全部严谨性红线**（一手承重/脚注定位/本机实证不编造/前沿硬标/过程痕迹不进正文）—— 这些不放松。
