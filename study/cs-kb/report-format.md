# 报告格式规范（v1 · 广度优先重定义 · 待用户确认）

> 用户重定义（2026-07-25）：知识库以**时效性 > 正确性 > 广度**为序，目标是**覆盖最多、最新**；
> 内容量极大，**深度主动舍弃**。每个内容项只给「核心解释 + 辅助说明」。
> 本文件取代 v0，作为 Round 3c 造 prompt 与 Round 4 产报告的模板。

## 一、粒度规则（不变）
- 默认 **1 大主题 = 1 报告**；小主题多/跨机制/过长时拆成 N 份（`NNN-<slug>-a/-b`）。
- 拆分判定在 Round 3c 由 subagent 逐大主题给「1 份 / 拆 N 份 + 理由」，汇总入 ledger。

## 二、报告内部结构（广度覆盖式，非深度叙事）
```
# <课ID·大主题号> <标题>
> 基线/核实：<日期> ｜ 先修：<课/大主题> ｜ 一手锚点：<教材§/规范/官方文档@版本> ｜ 成熟度：GA/⚙演进快（仅系统/前沿课标）

（可选：一句话点明本大主题在体系里是什么、为何学 —— 归入辅助说明性质，1–2 句即可）

## <小主题号 X.1> <小主题名>
- **<内容项：概念/公式/术语/最佳实践/常见陷阱>**：核心解释（1–3 句，正确、必要处标时效/版本）。〔辅助说明：直觉 / 最小例子 / 何时用 / 易错点 / 该掌握到什么程度〕
- **<内容项>**：…
（列全该小主题下的所有内容项，广度完备；每项浅而准，不展开深证）

## <小主题号 X.2> <小主题名>
- …

### 来源与时效
- 锚点：<教材§ / 规范 / 官方文档 + 版本 + 核实日期>
- 前沿/未定型项标「⚙演进快·锚版本·随时变」；未证实的具体数值/默认值标「待核」，不编造。
```

## 三、内容纪律（正确性保留，深度放松）
**保留（正确性红线）**
- 每个内容项**锚权威来源**（用 round3a 已定的教材目录/官方文档）；结论不承重于随机二手。
- **不编造**：具体数值、默认值、版本号、公式系数——来自来源或标「待核」，绝不凭记忆填。
- **标时效**：每份给核实日期；前沿项硬标演进快；改名/退役/新版单独标。
- **广度完备**：小主题下的内容项要"查全"，宁可多列浅讲，不遗漏。

**放松（深度）**
- **不**要求每项三条腿深证；**不**要求逐项本机实证。
- **本机 Python / 实证降为可选的"正确性抽查"**：仅在便宜且能快速确认某公式/输出/默认值时做一次，用来保正确性，不作深度展开。
- **不**写长篇机制叙事、设计权衡长论；核心解释 + 辅助说明即止。

## 四、相对 skill 的差异（明确）
1. 交付从"深度教学叙事(九要素)"改为"**广度覆盖式清单**"：小主题=章节，章节下列全内容项，每项浅而准。
2. 排序优先级 **时效>正确>广度>（放弃）深度**（skill 是深度取证优先）。
3. 三条腿/本机实证由**强制**降为**可选正确性抽查**。
4. 学习目标并入辅助说明，不单列段。
5. **保留**：一手锚定、不编造、标时效、前沿硬标、subagent 直接落盘、committed ledger、独立对抗质检（质检重点相应改为"覆盖是否查全 + 正确性 + 时效"，而非"深度是否够")。

## 五、待用户确认
- 上述"深度放松、三条腿→可选抽查"的取向是否符合你的意思？
- 内容项的辅助说明长度上限（默认：每项 1–2 句解释 + 1 句辅助）？
- 报告是否仍要脚注式来源，还是每章节末尾集中列锚点即可（当前采后者）？
