## 4.1 哈希函数

### 4.1.1 哈希表 / 哈希函数基本定义
核心概念：哈希表以哈希函数 h 把键空间 U 映射到槽位下标集合 {0,1,…,m−1}（m = 表大小/桶数），键 k 存入槽 h(k)，把「按键查找」从遍历降到期望 O(1)。CLRS §11.1 用**直接寻址表**（direct-address table，数组下标即键，键空间小时可行）作引入，哈希表则是键空间远大于可用内存时的压缩版本——用 h 把大键空间折叠进 m 个槽。

直接寻址是哈希的退化特例（h 为恒等映射、无碰撞）；一旦 |U| > m 必有碰撞（鸽巢原理），故哈希表的核心问题就是碰撞解决（4.2/4.3）。

### 4.1.2 除留余数法（division method）
核心概念：h(k) = k mod m（CLRS §11.3.1）。实现最简，但 m 的选取敏感：应**避开 2 的幂**（m=2^p 时 h(k) 只取 k 的低 p 位，丢弃高位信息），CLRS 建议取**与 2 的幂不接近的质数**。

易错点：取 m=2^p 是常见性能陷阱——若键低位规律性强（如对齐地址）会大量聚集。

### 4.1.3 乘法法（multiplication method）
核心概念：h(k) = ⌊m·(k·A mod 1)⌋，A 为 0<A<1 的常数（CLRS §11.3.2）。取 k·A 的小数部分再乘 m 取整；优点是 m 的取值不敏感（常取 m=2^p 便于位运算实现）。Knuth 建议 A ≈ (√5−1)/2 = 0.6180339887…（黄金比共轭，本机 sympy 核验 `float((sqrt(5)-1)/2)=0.6180339887498949`）。

### 4.1.4 全域哈希（universal hashing，§11.3.3）
核心概念：从一个哈希函数族 H 中**随机**选取 h，使对任意两不同键 k≠l，随机 h 令其碰撞的概率 ≤ 1/m。这样把「对固定 h 的最坏对抗输入」转成随机事件，任何输入下碰撞期望都受控——抵御对手针对已知哈希函数构造的碰撞攻击（呼应 4.5 安全视角）。

CLRS 给出全域族存在的构造（如 h_{a,b}(k)=((ak+b) mod p) mod m，p 为大于键上界的质数，a∈{1..p−1}、b∈{0..p−1} 随机）。

### 4.1.5 简单均匀哈希假设（simple uniform hashing）
核心概念：分析用的理想化前提——每个键等概率、独立地散到 m 个槽中的任一个（CLRS §11.2）。它不是真哈希函数的性质，而是推导期望查找长度（4.2/4.3）时的假设；全域哈希是让实际行为逼近这一理想的手段。

### 4.1.6 好哈希函数的判据
核心概念：确定性（同键同值）、输出**近均匀分布**（各槽概率≈1/m）、低碰撞、**雪崩效应**（输入微小变化引起输出大范围变化，直觉上打散规律键）。工程哈希（非密码学）还要快。

### 4.1.7 〔实证〕Python `hash()` 观察
核心概念：CPython 中小整数 `hash(n)=n`（本机 `hash(42)=42`），`hash(-1)=-2`（−1 被保留作错误标志，特判避开）；字符串哈希经 SipHash 加盐随机化（见 4.5.4）。本机真跑：`PYTHONHASHSEED=0` 下 `hash('abc')=-4594863902769663758` 固定，默认（随机种子）两次运行分别为 `2807365017388533250` 与 `-7884855722933297236`——每进程一变。

## 4.2 链地址法 / 拉链法

### 4.2.1 基本结构
核心概念：桶数组 T[0..m−1]，每桶挂一条链表（CLRS §11.2 用双向链表），所有散到同一槽的键都串在该桶链上；碰撞不占用别的槽。

### 4.2.2 操作与代价
核心概念：插入 O(1)（头插）；查找/删除需扫该桶链，期望 Θ(1+α)，α=n/m 为负载因子（4.4.1）。CLRS 用双向链表使已定位结点的删除为 O(1)。

### 4.2.3 简单均匀哈希下的期望查找长度
核心概念：不成功查找期望扫描 Θ(1+α) 个元素（平均每桶 α 个，CLRS 定理 11.1）；成功查找期望也是 Θ(1+α)（CLRS 定理 11.2，精确为 1+α/2−α/(2n)）。故只要 α=O(1)（m 与 n 同阶），所有操作期望 O(1)。

### 4.2.4 空间开销与优点
核心概念：额外付出链表指针/结点开销（每元素至少一个 next 指针）；但优点明确——删除简单、**α 可 >1**（桶可无限长，不像开放定址受 α≤1 硬约束），表满时优雅退化而非失败。

### 4.2.5 〔实证/代码〕手写链地址哈希表
核心概念：list-of-lists 即可自足实现。最小骨架：

```python
class ChainedHashTable:
    def __init__(self, m=8):
        self.m = m
        self.buckets = [[] for _ in range(m)]
    def _idx(self, key):
        return hash(key) % self.m          # 除留余数法
    def put(self, key, val):
        b = self.buckets[self._idx(key)]
        for i, (k, _) in enumerate(b):
            if k == key:
                b[i] = (key, val); return   # 覆盖
        b.append((key, val))                # 冲突则追加到桶链
    def get(self, key):
        for k, v in self.buckets[self._idx(key)]:
            if k == key:
                return v
        raise KeyError(key)
```

#### 来源与时效
- 锚点：CLRS 4th §11.2（含定理 11.1/11.2 期望查找长度），核实 2026-07-25。
- 二手交叉：CS61B sp24 Hashing I「External Chaining」（Java 视角，同一 Θ(1+α) 结论，指回理论）；Pat Morin《ODS》§5.1 ChainedHashTable（第二一手源）。
- 冲突项：无；「查找期望 Θ(1+α)」CLRS 与 ODS/CS61B 一致。

## 4.3 开放定址法

### 4.3.1 基本思想
核心概念：所有元素存于表内（无外部链），冲突时按**探测序列** h(k,0),h(k,1),… 依次试下一空槽直到找到空位或目标（CLRS §11.4）。因元素占表内槽，**α≤1 是硬约束**（表满即无法插入）。

### 4.3.2 线性探测（linear probing）
核心概念：h(k,i)=(h′(k)+i) mod m，逐槽向后找。实现最简、缓存局部性好；缺陷是**一次聚集（primary clustering）**——连续占用块越长越易继续变长，长块拖慢探测。

### 4.3.3 二次探测（quadratic probing）
核心概念：h(k,i)=(h′(k)+c₁i+c₂i²) mod m。消除一次聚集，但产生较弱的**二次聚集（secondary clustering）**（同初始槽的键走相同探测序列）；c₁,c₂ 与 m 需满足约束才能保证探测序列覆盖全表（CLRS 指出常见取法如 m=2^p、c₁=c₂=1/2，或 m 质数配合半表保证）。

### 4.3.4 双重哈希（double hashing）
核心概念：h(k,i)=(h₁(k)+i·h₂(k)) mod m（CLRS §11.4）。步长由第二个哈希 h₂ 决定，不同键探测序列各异，接近理想的均匀探测、几乎无聚集。要求 **h₂(k) 与 m 互质**（否则探测走不遍全表）；常见做法 m 取质数，或 m=2^p 而 h₂ 恒为奇数。

### 4.3.5 删除的复杂性 —— 墓碑标记
核心概念：开放定址中直接清空一个槽会**切断探测链**（后续键的探测在此提前遇空而误判「不存在」）。解决办法是标记为 **DELETED / 墓碑（tombstone）**：查找时视为已占继续探测，插入时可复用。代价是墓碑累积会拉长探测链、劣化 α 的有效值，需靠再散列（4.4）清理。

### 4.3.6 查找期望代价（与 α 的关系）
核心概念：均匀探测假设下（CLRS 定理 11.6/11.8），不成功查找期望探测数 ≤ 1/(1−α)，成功查找期望 ≤ (1/α)·ln(1/(1−α))。故 α→1 时代价急剧上升（α=0.9 时不成功查找≈10 次探测），这正是 4.4 要控 α 的动因。

### 4.3.7 〔实证机会，可选〕探测序列/聚集可视化
核心概念：可用 Python 数组模拟线性 vs 双重探测，统计平均探测长度随 α 上升的曲线以观察聚集（本报告未跑，标可选）。

## 4.4 负载因子与再散列 ——「CLRS 理论 vs CPython 实现」分账

### 4.4.1 负载因子 α 的支配作用
核心概念：α = n/m（元素数 / 槽数）。链地址期望代价 Θ(1+α)、开放定址 ~1/(1−α)——α 是所有操作期望代价的**单一支配参数**。工程上通过再散列把 α 钉在常数阈值内以保 O(1) 期望。

### 4.4.2 动态扩容 / 再散列（table doubling，均摊 O(1)）
核心概念：n 增长使 α 超阈值时，分配约两倍大的新表并把**所有元素重哈希**迁入（h 依赖 m，故不能简单拷贝）。单次 rehash 为 O(n)，但表**倍增**使 rehash 频率呈几何下降，均摊到每次插入为 **O(1)**（CLRS Ch16 均摊分析，聚合/势能法）。

### 4.4.3 缩容（shrink）与阈值滞后
核心概念：大量删除后可缩表回收空间。为避免在阈值附近反复扩缩（**抖动 thrashing**），缩容阈值应显著低于扩容阈值（滞后带 hysteresis），如「α 降到 1/8 才减半」，使扩缩之间有缓冲。（属通用工程直觉；CPython dict 无独立缩容路径，仅在 rehash 时按当前 used 重算大小。）

### 4.4.4 CPython 紧凑 dict 实现要点（⚙实现量，读源码取证 @v3.11.15）
核心概念：CPython dict 自 3.6 用**紧凑（compact）**布局——两段结构：`dk_indices[]` 是稀疏**索引数组**（存到 entries 的下标），`dk_entries[]` 是**紧凑连续**存 (hash,key,value) 的追加数组。查找走 indices→entries 二跳；**迭代 dk_entries 即得插入序**，这是 dict 保序（3.7 起语言级保证）的实现基础。冲突用开放定址 + 伪随机扰动探测。以下常量为读 `Objects/dictobject.c` @v3.11.15 原文取证：

- **探测递推**：`perturb >>= PERTURB_SHIFT; i = mask & (i*5 + perturb + 1);`，基础序列 `j = ((5*j)+1) mod 2**i`。`#define PERTURB_SHIFT 5`（Tim Peters 实验最优）——伪随机探测，非 CLRS 的线性/二次/双重任一种。
- **扩容触发**：`#define USABLE_FRACTION(n) (((n)<<1)/3)`，注释「resize the table when it's USABLE_FRACTION (currently two-thirds) full」——即装填到 **2/3** 触发 resize。
- **增长率**：`#define GROWTH_RATE(d) ((d)->ma_used*3)`，注释「dicts double in size when growing without deletions … GROWTH_RATE was used*4 up to 3.2, used*2 in 3.3.0」——3.11 为 **used*3**（有删除时留更多余量）。
- 本机观察 dict 扩容（`sys.getsizeof` 台阶，n→bytes）：`[(1,224),(6,352),(11,632)]`——插到第 6、第 11 个元素时字节数跳变，与 2/3 阈值触发扩表一致（初始 8 槽，用满 ~5 个即扩）。

### 4.4.5 规范 vs 实现分账（显式）
核心概念：**CLRS 理论**给的是通用框架——链地址 / 开放定址（线性/二次/双重）/ α 阈值 / 倍增均摊，均为「族」和界，不指定具体常量。**CPython dict** 是其中一组具体工程选择，且**偏离**教科书任一标准探测法：紧凑双数组（教材是单槽数组）、`i*5+perturb+1` **伪随机探测**（非线性/二次/双重）、2/3 触发、used*3 增长率。二者不可混谈：教材问「期望界」，CPython 问「这一实现的确定常量」。（Java `HashMap` 又是另一组选择——见 4.5.3。）

- 锚点（理论）：CLRS 4th §11.2-11.4（α）、Ch16（均摊/table doubling），核实 2026-07-25。
- 锚点（实现，承重·真读）：CPython `Objects/dictobject.c` @tag v3.11.15——`PERTURB_SHIFT=5`、`USABLE_FRACTION=2n/3`、`GROWTH_RATE=used*3`、探测递推 `i=mask&(i*5+perturb+1)`，均引原文宏/注释。二手交叉：Python 官方文档（dict 保序自 3.7）；CS61B sp24 Hashing II（resize/负载因子，Java 视角，同倍增均摊结论）。

## 4.5 最坏 O(n) 退化

### 4.5.1 最坏情形
核心概念：所有键碰撞到同一桶（链地址）或同一探测链（开放定址）时，哈希表退化为一条线性链，查找/插入/删除变 **O(n)**——期望 O(1) 的前提（近均匀分布）被彻底破坏。

### 4.5.2 触发条件
核心概念：两类——(a) **坏哈希函数**（分布严重不均，如只用低位遇 2 的幂表）；(b) **对抗性输入（adversarial input）**：攻击者已知哈希函数，故意构造大量同槽键（碰撞洪水）。

### 4.5.3 缓解：随机化哈希、控 α、桶内改树
核心概念：三条手段——(1) **全域/随机化哈希**（4.1.4）使对手无法预测落槽，把最坏变期望；(2) 良好 **α 控制 + 再散列**（4.4）保持链短；(3) **桶内改用平衡树**：Java 8+ `HashMap` 当单桶链长达 **TREEIFY_THRESHOLD=8** 且表容量 ≥ **MIN_TREEIFY_CAPACITY=64** 时把该桶链转红黑树，使单桶最坏从 O(n) 降到 O(log n)，删除/缩到 **UNTREEIFY_THRESHOLD=6** 退回链表（阈值 8 的依据：0.75 装填下单桶元素服从 λ≈0.5 的泊松分布，k=8 概率≈6e-8，极罕见）。CPython dict **不做** treeify，走随机化哈希 + 保持 α≤2/3 路线。

### 4.5.4 安全视角：碰撞 DoS 与 hash randomization
核心概念：哈希碰撞可被用作 **DoS**（构造碰撞键使服务端哈希退化 O(n²)）。CPython 的对策是**字符串/bytes 哈希随机化**：默认按 `PYTHONHASHSEED` 每进程加随机盐，算法为 **SipHash**——**3.11 默认从 SipHash-2-4 改为 SipHash-1-3**（更快，见 CPython commit ad970e8 / bpo-29410）。`PYTHONHASHSEED=0` 关闭随机化（可复现）。本机真跑证实：`PYTHONHASHSEED=0` 时 `hash('abc')` 恒为 `-4594863902769663758`；不设时两次运行得 `2807365017388533250`、`-7884855722933297236`（每进程随机）。整数哈希不随机化（`hash(42)=42`）。

### 4.5.5 〔实证机会，可选〕制造碰撞键观察退化
核心概念：可在 `PYTHONHASHSEED=0` 下构造大量 `hash(k)%m` 同值的键塞入 dict/自写表以观察查找变慢（本报告未跑该退化计时，标可选）。
