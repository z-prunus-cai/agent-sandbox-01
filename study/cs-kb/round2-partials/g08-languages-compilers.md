## 0 · 一句话把四门串成一条线

一条**从语法到语义再到保证**的主线：
**编译（L4-04）** 是"把源程序机械地翻译成等价机器码"的**构造**工程；**PL 理论（L5-06）** 抽掉工程细节、用 λ 演算 + 类型系统 + 语义学给出"程序到底指什么、类型系统凭什么可靠"的**理论**底座；**程序分析与形式验证（L6-02）** 反过来问"这段程序是否满足某性质"，用抽象解释/符号执行/模型检验/定理证明去**验证**；**Rust（L5-14）** 则是把 L5-06 的类型理论（仿射/线性类型、区域/生命周期）和 L6-02 的轻量静态分析（借用检查=一种编译期别名/生命周期分析）**工程落地**成一门主流语言。四门的分工正是：**构造 / 理论 / 验证 / 落地**。

贯穿性硬约束：**Rice 定理**——任何非平凡语义性质在图灵完备语言上不可判定（承 L3-05 计算理论）。这条定理解释了为什么 L6-02 的每种技术都是"某个方向的近似"：抽象解释牺牲精度换可判定（over-approx，可能误报）、符号执行牺牲完备换精度（under-approx，路径爆炸）、模型检验限制状态空间、类型系统/借用检查是"可判定但保守"的语法级近似。**把四门的取舍都挂到 Rice 定理这根钉子上，是本组的教学主线。**

## 1 · 组内选型 / 对比表（高价值横向对比）

### 表 1-A · LL vs LR 语法分析（L4-04 核心分水岭）
| 维度 | LL(k) / 递归下降 | LR(k) / LALR |
|------|------------------|--------------|
| 方向 | 自顶向下、最左推导、预测 | 自底向上、最右推导逆序、移进-归约 |
| 文法能力 | 弱（不能左递归，需提左公因子） | 强（LR(1) ⊋ LL(1)，覆盖几乎所有实用语法） |
| 手写难度 | 低——递归下降贴着文法写，报错信息友好 | 高——靠 yacc/bison 生成分析表 |
| 工业现状 | 现代前端多回归手写递归下降（clang、rustc、GCC C++）——为诊断质量与错误恢复 | 生成器路线（bison）仍广用于 DSL/脚本语言 |
| 实证抓手 | Python 手写递归下降算术求值器 | ply/lark（LALR）对比同一文法 |
| 边界 | 无法处理需要"看到右端才能决定"的归约 | 表大、冲突（shift/reduce）调试反直觉 |

> 教学落点：**"能力 vs 可维护性/诊断"的经典权衡**——理论上 LR 更强，工程上诊断需求把主流编译器推回手写 LL。

### 表 1-B · 静态 vs 动态类型 + 类型推导谱系（L5-06 ↔ L4-04 语义检查）
| 维度 | 静态（显式/单态） | 静态 + HM 推导 | 动态 |
|------|------------------|----------------|------|
| 检查时机 | 编译期 | 编译期（几乎无需注解） | 运行期 |
| 代表 | Java/C（显式）、Go | ML/Haskell/OCaml；Rust 局部推导 | Python/JS |
| 理论根 | 简单类型 λ 演算 STLC（TAPL Ch.9） | System F 的可判定片段 + Algorithm W（Damas-Milner 1982） | 无静态类型判定 |
| 代价 | 注解负担 | 推导可指数（let 多态），但实用近线性 | 错误推迟到运行期 |
| 实证抓手 | — | Python 实现 HM/Algorithm W 对 `λf.λx.f(f x)` 推出 `(a→a)→a→a` | Python 反例：类型错误运行期才炸 |

> 教学落点：**HM 是"零注解拿到静态安全"的甜点**；理解"principal type（最一般类型）+ 合一（unification）"是把 L5-06 与 L4-04 语义分析缝起来的关键。

### 表 1-C · 操作语义 vs 指称语义 vs 公理语义（L5-06 语义学三支）
| | 操作语义 | 指称语义 | 公理语义 |
|--|----------|----------|----------|
| 回答 | 程序**怎么一步步算** | 程序**是什么数学对象** | 程序**满足什么断言** |
| 形式 | 小步 `→` / 大步 `⇓` 推导规则 | 语义函数 ⟦·⟧ 映到域（domain theory） | Hoare 三元组 `{P}C{Q}` |
| 长处 | 直接指导解释器/编译器实现；证 type safety（progress+preservation） | 组合性强、利于等价推理 | 直接对接程序验证（→ L6-02） |
| 落地 | 本组 λ 求值器即操作语义 | 抽象、教学难 | 是 L6-02 演绎验证/最弱前条件的入口 |

> 教学落点：**三种语义不是竞品而是三个视角**；本组主推**操作语义**（最能落成可跑代码 + 直通 type-safety 证明），指称语义点到域论即可，公理语义作为通向 L6-02 的桥。

### 表 1-D · 验证四法对比（L6-02 主表 · 全部挂在 Rice 定理下）
| 技术 | 近似方向 | 典型误报/漏报 | 状态空间 | 一手锚 | 实证工具 |
|------|----------|---------------|----------|--------|----------|
| **抽象解释** | over-approx（可靠不完备） | 有误报，无漏报 | 抽象域（区间/多面体） | Cousot & Cousot POPL'77 | 手写区间分析 / (astrée 不可得) |
| **符号执行** | under-approx（精确但不完备） | 路径爆炸→漏路径 | 路径公式交给 SMT | King 1976；KLEE | z3 解路径约束 |
| **模型检验** | 状态空间穷举（有界或抽象） | 状态爆炸 | 显式/符号（BDD/BMC） | Clarke-Emerson / Queille-Sifakis | (TLA+/SPIN 待装) |
| **定理证明** | 完备但需人力 | 不自动 | 无限，靠归纳 | Coq/Isabelle；Software Foundations | (coq 未预装) |
| **SMT（横切引擎）** | 判定理论组合 | 理论受限 | 公式级 | Z3（deMoura-Bjørner TACAS'08） | ✅ z3-solver 5.0.0 已跑通 |

> 教学落点：**没有银弹**——四法沿"自动化 / 精度 / 覆盖"三角互相取舍；SMT 是符号执行与很多验证器共享的**底层引擎**，值得单独一节。

### 表 1-E · Rust 借用检查作为一种"轻量形式方法"（本组最强跨课缝合点）
| 传统重型形式方法 | Rust 借用检查 |
|------------------|---------------|
| 需写规约/证明/模型（人力高） | **零额外规约**——检查内建在编译期类型系统 |
| 通用性质（任意断言） | 固定但极有价值的性质：**无 use-after-free / 无数据竞争 / 无别名可变** |
| 抽象解释/模型检验 | 生命周期推断 + 别名分析（NLL/Polonius 的区域推断） |
| 理论根 | 仿射/线性类型 + 区域类型；**RustBelt**（Jung 等 POPL'18）给出机器化可靠性证明 |
| `unsafe` 的角色 | = 把证明义务从编译器**转回程序员**的显式逃生舱；`Rustonomicon` 是其一手规范 |

> 教学落点：**Rust 是"把一个可判定、保守但实用的静态分析做进主流语言"的活样本**——它把 L5-06（类型理论）和 L6-02（静态分析/形式保证）在一门工程语言里合流，是本组四门的天然汇聚点。

## 2 · 逐课重点方向 + 边界分工

> 分工原则：**编译=构造 / PL理论=理论 / 程序分析=验证 / Rust=落地**。同一概念（如类型、生命周期）在四门里从不同高度切，报告里显式交叉引用、不重复展开。

### L4-04 编译原理（P1，见 §4）— 5 个方向
1. **前端：词法（正则→DFA，承 L3-05）+ 语法（LL vs LR，表 1-A）** — 主推手写递归下降 + 一个 LALR 对照。
2. **语义分析 / 类型检查** — 符号表、作用域、类型规则；**边界**：类型系统的"为什么可靠"下沉到 L5-06，这里只讲"怎么查"。
3. **IR 与代码生成** — AST → 三地址码/SSA → 目标码；以 **LLVM IR** 为一手实物（本机 clang 可导出）。
4. **优化** — 常量折叠 / 死代码 / 循环（unroll、LICM）/ 内联；用 `-O0` vs `-O2` 的 IR diff 直观坐实（附录 A 已跑：整个循环折成 `ret i32 90`）。
5. **运行期与 ABI 衔接** — 栈帧/调用约定，交叉引用 L3-03 汇编、L3-02 组成，不重复。
- **边界**：编译原理讲"构造正确的翻译"；程序**是否满足性质**属 L6-02；语义**为何正确**属 L5-06。

### L5-06 编程语言理论（P2）— 4 个方向
1. **λ 演算** — 无类型 λ（β 归约、Church 编码、Y 组合子、confluence/Church-Rosser）→ 可跑求值器。
2. **类型系统谱系** — STLC → System F（参数多态）→ 子类型 → 依赖类型一瞥；进度+保持（progress & preservation）= type safety 的证明骨架。
3. **类型推导 HM** — 合一 + Algorithm W；**principal type**。是与 L4-04 语义分析、L5-14 Rust 局部推导的公共理论。
4. **语义学** — 操作/指称/公理三视角（表 1-C），主推操作语义。
- **边界**：PL 理论是"元层"——研究语言本身的性质；具体翻译实现属 L4-04，具体验证工具属 L6-02。**一手教材 TAPL 几乎就是本课骨架**。

### L6-02 程序分析与形式验证（P2）— 5 个方向
1. **不可判定性框架**（Rice 定理）+ 为何一切皆近似 — 全课的世界观开场。
2. **抽象解释** — Galois 连接、区间/符号域、不动点迭代 + widening；手写一个区间分析器。
3. **符号执行** — 路径公式、路径爆炸、把约束丢给 SMT；用 z3 解一段代码的路径可达性。
4. **模型检验** — 时序逻辑（LTL/CTL）、状态爆炸、BDD/BMC；工具（SPIN/TLA+）**待装**，先概念 + 小手算。
5. **定理证明 + SMT** — Hoare 逻辑/最弱前条件承接表 1-C 的公理语义；SMT（z3）作为贯穿引擎单列。
- **边界**：与 L4-04 的静态检查区别在"目标"——编译器为生成代码做的分析求"够用且快"，L6-02 求"对某性质给出保证（或反例）"。

### L5-14 Rust 与内存安全（P1，见 §4）— 5 个方向
1. **所有权 / move 语义** — 仿射类型的工程化；对比 C++ RAII/移动。
2. **借用检查 + 生命周期** — `&`/`&mut` 的别名异或可变（aliasing XOR mutability）；NLL / Polonius 的区域推断；用真实编译错误复现（附录 B：E0502 已跑通）。
3. **`unsafe` 与安全边界** — 逃生舱语义、不变式义务转移；`Rustonomicon` 为一手。
4. **并发安全** — `Send`/`Sync`、类型系统层面"编译期消除数据竞争"，交叉引用 L4-05 并发。
5. **理论根 + 形式保证** — RustBelt 的机器化可靠性证明，回接 L5-06/L6-02（这一节是四门的汇合点）。
- **边界**：Rust 是**落地**——把前三门的理论/分析装进主流语言；不重复讲类型理论本身（→L5-06）或通用验证（→L6-02），只讲"语言如何内建这层保证"。

## 4 · 优先级校准

- **L4-04 编译原理：确认 P0 → P1**（对齐 round1-map §2-B1）。理由复核：全局 fan-out 仅 2（→L5-06、L6-02，均已在本组内），顶校普遍列选修，CS2023 核心是 FPL 概念层而非全栈编译器实现。**但**：本组即"PL/编译/验证子图"，在**本子图内 L4-04 是上游枢纽**（LL/LR、IR、类型检查为 L5-06/L6-02 提供词汇），故**组内排序仍最先**、内容按 P1 深度即可（讲透机制与 LLVM 实物，不追求造完整编译器）。
- **L5-14 Rust：P1**（承 round1-map N-12→L5-14 "✅建议升级"）。作为四门的工程汇聚点 + 唯一能大量本机实证（rustc 1.94.1 现成、报错即教材）的课，**权重上调标注**：建议在本组内紧随 L4-04，早于 L5-06/L6-02，用作"理论落地"的具体锚。
- **L5-06 编程语言理论：P2**（保持）。理论深、fan-out 集中在本组内（喂 L4-04 类型检查、L5-14 类型基础、L6-02 语义/验证），是本组的"理论心脏"但非关键路径枢纽。
- **L6-02 程序分析与形式验证：P2**（保持）。最深、最依赖前三门（L4-04+L3-05），置于本组最后；实证受限（z3 可跑，模型检验/定理证明工具需装或降级），R4 需按"哪些方向能真跑三腿"再分账。
- **组内建议拓扑**：L4-04 → L5-14 → L5-06 → L6-02（构造→落地→理论→验证）。其中 L5-06 与 L6-02 可并行深化。
