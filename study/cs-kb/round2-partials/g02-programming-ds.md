## 一 · 组内选型 / 对比表（高价值横向对比）

### 表 A · 入门语言取舍：C（面向内存）vs Python（面向表达）

| 维度 | C（gcc 13.3, `-std=c11`） | Python（CPython 3.11.15） | 教学取舍 |
|------|---------------------------|---------------------------|----------|
| 心智模型 | 显式内存：变量=有类型的字节位置，指针=地址 | 对象引用：名字=绑定到堆对象的标签 | C 教"计算机怎么想"，Py 教"问题怎么想" |
| 类型 | 静态、编译期定型、弱（可隐式转/强转） | 动态、运行期定型、强（少隐式转） | Py 少踩类型陷阱；C 逼你理解表示 |
| 内存管理 | 手动 `malloc/free`，悬垂指针/泄漏/越界全暴露 | GC（引用计数 + 分代回收），基本不可见 | C 暴露地基（对接 L4-01/L3-03），Py 隐藏 |
| 执行 | 编译成本机码，直接跑 | 编译成字节码，CPython VM 解释执行 | 性能差 1–2 个数量级（数值密集尤甚） |
| 递归/栈 | 栈溢出=段错误(SIGSEGV)，栈帧按 SysV ABI 布局 | `RecursionError`（默认 `sys.getrecursionlimit()`=1000，本机实测） | Py 有护栏，C 直接崩 → 教栈的两种失败面 |
| I/O | `printf/scanf`，格式串与类型必须手对齐 | `print/input`，自动 `str()` | Py 上手快；C 的格式串不匹配是经典 UB 源 |
| 作入门语言 | 优点：无魔法、直通体系结构；代价：陡、噪声大（分号/指针/编译） | 优点：低摩擦、快见效、聚焦算法思维；代价：藏掉地基 | **主流折衷：Py 先建"计算思维"，C later 补"机器模型"**（MIT 6.100→Berkeley 61A 用 Py；CMU 15-122 用 C 强调不变式）。本 KB 两者都作 L1-01 实证腿 |

> 顶校分野（核实 2026-07-25）：MIT/Berkeley/Stanford 入门主用 Python；CMU 15-122「Principles of Imperative Computation」用 C0/C 强调契约与指针；两条路都被承认，差异是**先教思维还是先教机器**。

### 表 B · 数据结构操作代价对比（平均/最坏，n=元素数）

| 结构 | 按索引访问 | 查找(按值) | 头插 | 尾插 | 任意位置插/删 | 有序遍历 | 空间开销 | 备注 |
|------|-----------|-----------|------|------|--------------|----------|---------|------|
| 动态数组 | O(1) | O(n) | O(n) | 均摊 O(1) | O(n) | 需先排序 O(n log n) | 低（连续，缓存友好） | CPython `list`、C 数组 |
| 单链表 | O(n) | O(n) | O(1) | O(n)\* | O(1)（已有节点指针） | O(n) | 高（每节点 1 指针=8B，本机实测 `struct Node`=16B） | 无随机访问；\*带尾指针尾插 O(1) |
| 栈 / 队列 | — | — | push O(1) | — | — | — | 低 | 受限接口，数组或链表实现 |
| 哈希表 | — | 均摊 O(1)/最坏 O(n) | 均摊 O(1) | 均摊 O(1) | 均摊 O(1) | **不保证顺序** | 中（负载因子 + 桶） | 本机实测 set∈ 比 list∈ 快 ~1万倍（见 L2-01 实证点） |
| BST（不平衡） | — | 平均 O(log n)/最坏 O(n) | 平均 O(log n)/最坏 O(n) | 同左 | 同左 | O(n) 中序有序 | 中 | 退化成链表是核心陷阱 |
| 平衡树(AVL/红黑) | — | O(log n) 保证 | O(log n) | O(log n) | O(log n) | O(n) 中序有序 | 中（额外平衡信息） | 最坏也 O(log n)；C++ `std::map`、Java `TreeMap` |
| 二叉堆 | — | O(n)（找非极值） | — | 插入 O(log n) | 删极值 O(log n) | — | 低（数组存完全二叉树） | 只 O(1) 取极值；优先队列基座 |
| 图（邻接表） | — | 邻边 O(deg) | — | 加边 O(1) | — | BFS/DFS O(V+E) | O(V+E) | 稀疏图首选；稠密图用邻接矩阵 O(V²) |

> 一条线索：**没有免费的午餐**——数组换缓存友好丢了插入，哈希换 O(1) 丢了顺序，平衡树换保证丢了常数因子。选型 = 按操作频率画像匹配代价曲线。这张表是 L3-01 算法课的直接输入。

### 表 C · 编程范式对比：命令式 vs 面向对象 vs 函数式

| 维度 | 命令式/过程式 | 面向对象 (OO) | 函数式 (FP) |
|------|--------------|--------------|-------------|
| 核心抽象 | 语句序列 + 可变状态 | 对象 = 状态 + 行为封装 | 函数 = 值；组合与变换 |
| 状态 | 显式可变 | 封装在对象内 | 不可变优先，副作用隔离 |
| 组织维度 | 按过程分解 | 按数据+行为分类（继承/多态） | 按数据变换管线（map/filter/reduce） |
| 多态机制 | 手动 switch/函数指针 | 动态派发（虚表/鸭子类型） | 参数多态（泛型）+ 高阶函数 |
| 复用手段 | 函数库 | 继承 + 组合 + 接口 | 高阶函数 + 组合子 + 类型类 |
| 典型陷阱 | 全局可变状态耦合 | 继承滥用（脆弱基类/深继承） | 惰性求值内存、性能常数 |
| 语言载体 | C, 早期 Fortran | Java, C++, Python(类) | Haskell, Lisp; JS/Python 支持 FP 子集 |
| 代表格言 | "怎么做" | "谁负责做" | "是什么变换" |

> 关键澄清（防常见误解）：范式是**风格而非语言**——Python/JS 都是多范式语言，能同时写命令式循环、OO 类、FP 的 `map/lambda`。三者不互斥；工业代码常混用（OO 组织模块边界 + FP 处理数据管线 + 命令式写热点循环）。理论根基见 Cardelli-Wegner 的多态分类（一手源候选）。

## 二 · 逐课方向

### L1-01 · 程序设计入门　【优先级 P0 · 枢纽地基】

**重点方向（Round 4 深挖）**
1. **变量的两套心智模型**：C 的"有类型的内存位置" vs Python 的"名字绑定对象"——`a=b` 在两语言的语义差异，可变对象别名陷阱（Python list 别名 / C 指针别名）。
2. **控制流与结构化编程**：分支/循环/短路求值；结构化定理（Böhm-Jacopini，一手源）；C 的 UB 陷阱（有符号溢出、未初始化读、序列点）。
3. **函数与调用约定**：值传递 vs 引用/指针传递；C 全值传递（数组退化为指针的例外）；栈帧建立/销毁（对接 L3-03 的 SysV ABI 栈帧）。
4. **递归与栈**：递归=编译器管理的栈；基例/递归例；尾递归；两种失败面——C 栈溢出→SIGSEGV，Python→`RecursionError`（默认 limit 1000）。
5. **指针与引用**（C 专属地基）：地址算术、`sizeof`、指针与数组、多级指针、悬垂/野指针；对接 L2-01 链表与 L4-01 虚存。
6. **简单 I/O 与类型表示**：`printf/scanf` 格式串与类型对齐；整型/浮点表示的入门直觉（深挖留给 L3-02）。

**与邻课边界**
- ↔ **L2-01 数据结构**：L1-01 给"指针+函数+递归"三件工具，L2-01 用它们造结构。链表/树的实现是两课的接缝。
- ↔ **L3-03 汇编/机器级**：函数调用、栈帧、指针在机器层的落地——L1-01 讲"是什么"，L3-03 讲"机器怎么做"。
- ↔ **L3-04 范式**：L1-01 默认命令式/过程式；范式的对比与升华交给 L3-04。
- ↔ **L3-02 组成原理**：整型/浮点表示、内存层次——L1-01 只给直觉，深挖归 L3-02。

**一手源候选**
- ISO/IEC 9899:2011 (C11) 标准文本——UB/序列点/类型规则的权威裁决。
- K&R《The C Programming Language》(2nd ed)——经典权威教材（注意基于 C89）。
- Python 3.11 官方 Language Reference（数据模型 §3、执行模型 §4）+ Tutorial。
- CPython 源码（`ceval.c` 调用栈、`sys.setrecursionlimit`）——实现级留白处的真实行为。
- System V AMD64 ABI §3.2（栈帧布局）——对接递归/调用约定。

**本机实证点**（已 spot-check）
- 递归栈：Python `sys.getrecursionlimit()` → **实测 1000**；无限递归 → **实测抛 `RecursionError`**。C 版无限递归 → SIGSEGV（段错误），对比两种护栏。
- 指针/表示：`sizeof(void*)=8, sizeof(int)=4, sizeof(struct Node)=16`（**本机实测**，含对齐填充）——讲清指针宽度与结构体对齐。
- 值 vs 引用：Python `id()` 演示别名；C 用 `&` 取址 + 传指针改实参，对比传值不改。
- gcc `-O0` vs `-O2` 反汇编看栈帧（objdump），对接 L3-03。

**优先级理由**：全 KB 依赖链起点（fan-out 极大），P0 无争议。

### L2-01 · 数据结构　【优先级 P0 · ★枢纽课，全组核心】

**重点方向（Round 4 深挖）**
1. **线性结构与内存布局**：数组（连续/缓存友好/O(1) 随机访问）vs 链表（分散/O(1) 拼接/无随机访问）；动态数组的均摊分析（CPython `list` 扩容策略，读 `listobject.c` 实现）。
2. **受限接口结构**：栈/队列/双端队列——LIFO/FIFO 语义、数组 vs 链表实现、环形缓冲；对接 L1-01 递归（调用栈）与 L4-01。
3. **哈希表**：哈希函数、冲突解决（链地址 vs 开放定址）、负载因子与扩容、最坏 O(n) 退化；CPython `dict` 的紧凑+开放定址实现（`dictobject.c`）。
4. **树家族**：BST → 退化问题 → 平衡（AVL 高度平衡 / 红黑树近似平衡 / B 树多路）；堆（完全二叉树+数组表示，优先队列）；各自不变式与旋转/上浮下沉操作。
5. **图表示**：邻接表 vs 邻接矩阵的空间/操作权衡（稀疏 vs 稠密）；为 L3-01 图算法（BFS/DFS/最短路）铺表示层。
6. **操作代价的统一视角**：把表 B 落成"每结构的代价画像"，教会按访问模式选型——这是本课的灵魂，也是与 L3-01 的接缝。

**与邻课边界**
- ↔ **L1-01**：消费其指针/递归/函数工具造结构（下沉边界）。
- ↔ **L3-01 算法**：L2-01 造"数据的容器 + 单操作代价"，L3-01 用容器设计"解决问题的过程 + 整体复杂度"。分界：结构的 `insert/find` 归 L2-01；用结构跑 Dijkstra/DP 归 L3-01。堆是接缝（结构属 L2-01，堆排序/优先队列算法属 L3-01）。
- ↔ **L4-03 数据库**：B+ 树索引是 L2-01 树结构在磁盘/分页场景的工程化——L2-01 给内存版 B 树直觉。
- ↔ **L6-04 数据库内核**：LSM 树/跳表等进阶结构下沉到 L6-04。

**一手源候选**
- CLRS《Introduction to Algorithms》(4th ed, 2022)——数据结构+代价分析的权威教材。
- Sedgewick & Wayne《Algorithms》(4th ed)——实现导向经典。
- Pat Morin《Open Data Structures》——开放获取、定位精确的一手教材。
- CPython 源码 `Objects/listobject.c`（扩容）、`Objects/dictobject.c`（紧凑 dict + 开放定址）——实现级真实行为。
- C++ `std::map`(红黑树) / Java `TreeMap`/`HashMap` 官方文档——工业实现契约。

**本机实证点**（已 spot-check）
- 哈希 vs 线性查找：`set` 成员测试 vs `list` 成员测试，N=10⁵ ×1000 次——**实测 list 0.91s / set 0.00008s，约 1.1 万倍**，坐实 O(1) vs O(n)。
- 动态数组均摊：追踪 CPython `list` 的 `sys.getsizeof` 随 append 的阶梯增长，量化扩容策略与均摊 O(1)。
- 各结构操作计时：C 实现数组/单链表，计时头插（数组 O(n) vs 链表 O(1)）与随机访问（数组 O(1) vs 链表 O(n)），画代价曲线。
- BST 退化：有序 vs 随机插入序列，测树高（退化 O(n) vs 平均 O(log n)），对比 `std::map` 的稳定 log。
- 节点空间开销：`sizeof(struct Node)=16`（**本机实测**）量化链表相对数组的指针税。

**优先级理由（★枢纽确认）**：见下节校准。

### L3-04 · 面向对象与程序设计范式　【优先级 P1】

**重点方向（Round 4 深挖）**
1. **封装/继承/多态三支柱**：数据抽象（信息隐藏）、`is-a` 继承、动态派发；虚表机制（C++ vtable）vs 鸭子类型（Python）——多态的静/动两种落地。
2. **接口与抽象**：抽象基类/接口/协议；Liskov 替换原则（Barbara Liskov 一手论文）；组合优于继承（脆弱基类问题）。
3. **泛型/参数多态**：Cardelli-Wegner 的多态分类（参数/包含/特设/强制）；Java 泛型(擦除) vs C++ 模板(单态化) vs Python 结构化鸭子类型的取舍。
4. **函数式范式**：一等函数、高阶函数、闭包、不可变性、`map/filter/reduce`、纯函数与副作用隔离；对接 L5-06 λ 演算/类型系统的理论根。
5. **范式对比与融合**：表 C 的展开——多范式语言（Python/JS）如何混用；何时选 OO（复杂状态建模）何时选 FP（数据变换管线）。
6. **（可选）设计模式作为范式产物**：GoF 模式是 OO 惯用法结晶（策略/观察者/工厂）；FP 视角下部分模式"消解"为高阶函数。

**与邻课边界**
- ↔ **L1-01**：L1-01 建命令式/过程式基础，L3-04 在其上引入 OO/FP 对比并升华"范式"概念。
- ↔ **L5-06 编程语言理论**：L3-04 讲范式的"用法与工程权衡"，L5-06 讲其"形式语义/类型系统/λ 演算根基"。分界：多态怎么用归 L3-04，类型系统怎么形式化归 L5-06。
- ↔ **L4-06 软件工程**：SOLID/设计模式的工程应用与 L4-06 有交集——L3-04 给语言机制，L4-06 给架构方法。
- ↔ **L5-14 Rust**：Rust 的 trait/所有权是范式新点（无 GC 的内存安全 + 特设多态），可作 L3-04 的现代对照。

**一手源候选**
- Cardelli & Wegner《On Understanding Types, Data Abstraction, and Polymorphism》(1985)——多态分类奠基论文。
- Barbara Liskov《Data Abstraction and Hierarchy》(1987) / LSP 原始表述。
- GoF《Design Patterns》(1994)——OO 模式经典权威。
- Python 3.11 官方 Data Model（`__` 协议、`abc`、descriptor）+ ECMAScript 规范（原型链）。
- SICP（Abelson-Sussman）——过程抽象/数据抽象/高阶函数的经典教学一手。

**本机实证点**（Python/JS 示例）
- 动态派发：Python 鸭子类型 vs 用 `abc.ABC` 显式接口；`__mro__` 看方法解析顺序（多重继承菱形问题）。
- 闭包与一等函数：Python 闭包捕获变量（含晚绑定陷阱）；`functools.reduce`/`map` 管线 vs 命令式循环等价改写。
- 泛型对照：Python 结构化多态 vs（说明性）Java 擦除/C++ 单态化的区别——本机以 Python `typing.Generic` 演示。
- 不可变性：Python `tuple`/`frozenset` vs `list`，纯函数无副作用示例；对比可变默认参数陷阱。
- JS 备用：node 22.22.2 演示原型链继承与高阶函数（与 Python 类式 OO 对照两种 OO 传统）。

**优先级理由**：P1 主干方向课；概念性强、可实证密度低于 L1-01/L2-01，但为 L5-06/L5-14 铺路。

## 三 · 优先级校准（L2-01 枢纽地位确认）

- **L2-01 数据结构 = 全 KB 六大枢纽之一（P0 枢纽，确认无疑）**：
  - 依赖拓扑：round1-map §2/§4 中 L2-01 是 L3-01(算法)、L4-01(OS)、L4-02(网络，A1 改依赖 L2-01)、L4-03(数据库)、L4-04(编译) 的硬先修——**fan-out 最广的中间层枢纽**。
  - 内容枢纽：表 B 的"操作代价画像"是 L3-01 复杂度分析的直接输入；B 树→L4-03 索引、图→L3-01 图算法、堆→优先队列算法，四条外延线全从此发散。
  - 结论：维持 **P0 枢纽**，Round 4 批次中必须最先产出（round1-map §4 批1 首位）；本组三课的产出顺序建议 **L1-01 → L2-01 → L3-04**（依赖序）。
- **L1-01 P0**：依赖链起点，与 L2-01 同批优先。
- **L3-04 P1**：主干方向，可后置于 L1-01/L2-01；与 L5-06/L5-14 存在下游耦合，产出时注意边界切分避免重复立项。

## 四 · 下一层入口（Round 3 造 prompt 的对象×方向清单）
