## 本组一句话定位

这四门课是一条**抽象阶梯**：`布尔代数/门（L2-02）→ 触发器/时序 → 数据通路+控制器 → 单周期/流水线 CPU（L3-02 枢纽）→ 编译产物落到这条通路上跑（L3-03，机器级表示）→ 现代 CPU 如何用超标量/乱序/预测/多核一致性把这条通路榨到极限（L5-05）`。L3-02 是枢纽：向下承接门电路的物理实现，向上被 OS/编译/并发/安全全部依赖；L3-03 是 L3-02 的"可观测面"（把 ISA、栈帧、调用约定变成能反汇编看的字节）；L5-05 是 L3-02 的"性能延伸"（把顺序执行模型换成投机+并行）。

## §1 · 组内选型/对比表（横向对比 = 高价值点）

### 表 1.1 抽象阶梯：门 → 数据通路 → 流水线 → 超标量/乱序（贯穿本组的主轴）
| 层级 | 归属课 | 基本单元 | 状态/时序模型 | 关键指标 | 主要陷阱 |
|------|--------|----------|---------------|----------|----------|
| 组合逻辑（门/MUX/ALU 片） | L2-02 | 与或非/异或门 | 无状态，纯函数 | 门延迟、逻辑深度 | 竞争-冒险(glitch) |
| 时序逻辑（锁存器/触发器/寄存器/FSM） | L2-02→L3-02 | D 触发器 | 时钟边沿采样 | 建立/保持时间、Fmax | 亚稳态、时钟偏斜 |
| 单周期数据通路 + 控制器 | L3-02 | PC/寄存器堆/ALU/内存 | 一条指令一个时钟 | CPI=1，周期=最长指令 | 周期被最慢指令拖死 |
| 经典 5 级流水线 | L3-02 | IF/ID/EX/MEM/WB 段寄存器 | 指令重叠、每级一拍 | 吞吐↑、时钟↑，CPI 名义=1 | 结构/数据/控制冒险；转发+停顿 |
| 超标量 + 乱序 + 投机 | L5-05 | 发射宽度、ROB、保留站、RAT | 动态调度、按序退休 | IPC>1、ILP、MLP | 分支误预测冲刷、幽灵/熔断类投机泄漏 |
| 多核 + 向量/GPU | L5-05 | 缓存一致性目录/总线、SIMD 通道、SM | 一致性协议 + 内存序 | 可扩展性、带宽、SIMT 占用率 | 伪共享、内存序重排、分支发散 |

> 递进主线一句话：**每一层都是"用更多硬件换更高的指令吞吐"**——单周期换流水线（重叠）、流水线换超标量（并行发射）、超标量换乱序（填满空洞）、单核换多核（数量），代价是复杂度、功耗、以及正确性推理（冒险/一致性/内存序）越来越难。

### 表 1.2 RISC vs CISC / x86-64 vs ARM(AArch64)（L3-02/L3-03 核心辨析）
| 维度 | 经典 RISC（教材/AArch64/RV64） | 经典 CISC（x86-64） | 现实校正（2026 视角） |
|------|------|------|------|
| 指令长度 | 定长（ARM/RV 多为 4 字节，RV 有 2 字节压缩 C 扩展） | 变长（1–15 字节） | 变长使 x86 取指/译码更贵→前端 μop cache |
| 指令→操作 | 一指令≈一操作，load/store 架构 | 一指令可含"读内存-算-写回" | x86 内部把复杂指令译成 **μops**，后端其实是 RISC 式 |
| 寄存器可见数 | 通用寄存器多（AArch64 31 个 x0–x30） | 少（x86-64 16 个通用） | 乱序核用**物理寄存器重命名**掩盖架构寄存器少的问题 |
| 内存序 | **弱序**（ARM 需显式 dmb/acquire-release） | **强序 TSO**（几乎只允许 store→load 重排） | 直接影响并发/无锁代码可移植性（接 L4-05） |
| 典型场景 | 移动/嵌入/云 ARM、教材 | 桌面/服务器存量 | ISA 差异对性能已非主因；微架构+工艺才是 |
| 教学取证 | RV/ARM 交叉编译看更"干净"的汇编 | 本机 gcc -S 直接可跑（本组默认基线） | 本机 = x86-64 SysV，AArch64 靠交叉工具链或 QEMU |

### 表 1.3 内存层次各级延迟/容量对比（本机 sysfs 实测容量 + 量级延迟）
> 容量为本机 `/sys/.../cache` 实测（见 §3 实测块 C）；延迟为体系结构量级心智模型（R4 需用 rdtscp/指针追逐实测坐实，不作精确断言）。
| 层级 | 本机容量（实测 @2026-07-25） | 典型访问延迟量级 | 命中它意味着 |
|------|------------------------------|------------------|--------------|
| 寄存器 | 16 个通用 + 32 个 ZMM(AVX-512) | ~0 周期（无访存） | 编译器分配到位 |
| L1d / L1i | 各 32 KiB（每核） | ~4–5 周期 | 热数据、紧内层循环 |
| L2（统一） | 1024 KiB（1 MiB，每核） | ~12–15 周期 | 工作集 < 1 MiB |
| L3（统一，共享） | 33792 KiB（33 MiB，共享） | ~40–75 周期 | 跨核共享、大工作集 |
| DRAM | （主存） | ~200–300+ 周期 | cache 全 miss，带宽/延迟墙 |
| （对照）SSD/网络 | — | 万~百万周期 | 已属 OS/分布式范畴 |

> 心智模型：**每下一层容量约 ×10–30、延迟约 ×3–10**。cache 存在的唯一理由是利用**时间/空间局部性**把平均访存拉回接近 L1；写程序时"改数据布局(AoS→SoA)、按行遍历、分块(tiling)"往往比换算法常数更能提速——这是 L5-05 与 L6-06(HPC) 的接缝。

### 表 1.4 顺序 vs 乱序执行（L3-02 简单模型 → L5-05 现实）
| 维度 | 顺序（in-order，教材/低功耗核） | 乱序（OoO，主流大核） |
|------|------|------|
| 指令启动顺序 | 严格程序序 | 数据就绪即发射（乱序），**按序退休** |
| 遇到 cache miss | 整条流水线停顿等数据 | 后续独立指令继续跑（**MLP**，多个 miss 并行） |
| 寄存器假依赖(WAR/WAW) | 靠停顿 | 寄存器重命名消除 | 
| 硬件成本 | 小、省电 | ROB/保留站/重命名表/大调度窗口，面积功耗大 |
| 分支/异常 | 简单 | 需投机执行 + 精确异常（退休时才提交） |
| 安全副作用 | 少 | 投机执行留下缓存痕迹 → Spectre/Meltdown 类侧信道 |

### 表 1.5 缓存一致性 vs 内存一致性（L5-05 最易混，务必分账）
| | 缓存一致性 (Coherence) | 内存一致性 (Consistency / 内存模型) |
|---|---|---|
| 管什么 | **单个地址**在多核缓存副本间的可见性 | **多个地址**间读写的**顺序**如何被其它核观察到 |
| 机制 | MESI/MOESI 协议、总线嗅探/目录 | 硬件内存序 (x86-TSO / ARM 弱序) + 屏障指令 |
| 程序员接口 | 基本透明（硬件自动维护） | **不透明**：需 `mfence`/`dmb`、C11 `atomic` 的 memory_order |
| 接壤课 | L3-02 内存层次 → L5-05 多核 | L5-05 内存屏障 → L4-05 并发内存模型 |

## §2 · 逐课重点方向（每课 3–6 个）+ 邻课边界

### L2-02 数字逻辑电路（P1｜取证腿 文·证）
1. **布尔代数 ↔ 门电路 ↔ 真值表三位一体**：化简（卡诺图/Quine-McCluskey）、完备集（NAND/NOR 单门完备）、SOP/POS 范式。证：sympy 逻辑化简 + 穷举真值表核对等价。
2. **组合电路构件**：加法器（半加/全加/行波进位 vs 超前进位 CLA 的延迟对比）、MUX/DEMUX、译码器/编码器、比较器、ALU 拼装。
3. **时序逻辑与存储**：锁存器 vs 边沿触发器、D/JK/T、建立/保持时间、亚稳态心智模型。
4. **有限状态机（硬件 FSM）**：Moore vs Mealy、状态编码（独热 vs 二进制）、状态图→状态表→激励方程→门级。证：Python 模拟 FSM 逐拍状态迁移。
5. **（可选）时序分析入门**：关键路径/逻辑深度决定 Fmax，为 L3-02 "流水线为何能提时钟"埋伏笔。
- **邻课边界 →L3-02**：L2-02 的 ALU/寄存器/FSM 正是 L3-02 数据通路的**元件**；触发器→寄存器堆/段寄存器，FSM→（多周期/微程序）控制器。L2-02 讲"怎么用门搭出一个能存 1 bit、能加两数的东西"，L3-02 讲"怎么把这些拼成一台会取指-译码-执行的机器"。

### L3-02 计算机组成原理（P0 枢纽｜文·码·证）
1. **ISA 作为硬件/软件契约**：指令格式、寻址方式、寄存器模型；RISC vs CISC（表 1.2）；ISA vs 微架构分账。
2. **单周期数据通路 + 控制**：PC→取指→译码→读寄存器→ALU→访存→写回；控制信号从指令位段派生。
3. **流水线**（本课高潮）：5 级划分、段寄存器、三类冒险（结构/数据/控制）、转发(forwarding)、停顿(stall/bubble)、分支延迟槽/预测入门。证：用 Python 逐拍模拟冒险与转发。
4. **内存层次与缓存**：局部性、直接映射/组相联/全相联、写直达 vs 写回、替换策略、平均访存时间 AMAT、cache 参数与 miss 率。证：本机 sysfs 读真实 cache 结构（§3-C），步长扫描观测 miss 拐点。
5. **总线与 I/O**：内存映射 I/O vs 端口 I/O、轮询 vs 中断 vs DMA、性能（带宽/延迟）。
6. **性能定律**：`CPU时间 = 指令数 × CPI × 周期`、Amdahl 定律。证：sympy 解 Amdahl 加速比上限。
- **邻课边界**：←L2-02 提供元件；→L3-03 把 ISA/数据通路"落字节"（同一台机器的两个视角：L3-02 讲结构，L3-03 讲编码与运行时布局）；→L5-05 把"单条按序"升级为"多条乱序投机"；→L4-01 OS 依赖其中断/内存/特权模型。**分账提醒**：L3-02 讲的是**教学 RISC（MIPS/RISC-V 风格）单周期/5 级**心智模型，本机实证却是 **x86-64 乱序超标量**——务必标注"教学模型 ≠ 本机真实微架构"，把差异指给 L5-05。

### L3-03 汇编与机器级表示（P1｜文·码·证；本组"可观测面"）
1. **x86-64 指令编码与寻址**：AT&T 语法、`base+index*scale+disp` 寻址、RIP-relative（PIE 默认）、操作数尺寸后缀。
2. **调用约定（SysV AMD64 ABI）**：整型参数寄存器顺序 `rdi,rsi,rdx,rcx,r8,r9`，第 7 参数起入栈；返回值 `rax`(:rdx)；caller/callee-saved 划分；红区(red zone,128B)。**必真跑**（见 §3-A 实测已确认前 6 参数寄存器顺序 + endbr64/CET）。
3. **栈帧与函数序言/尾声**：`push %rbp; mov %rsp,%rbp` vs 省略帧指针(-fomit-frame-pointer)、`call/ret`、返回地址、栈对齐 16 字节要求。证：objdump 看序言，gdb 看真实栈帧。
4. **编译产物的层次**：C→`gcc -S`(汇编)→汇编器→`.o`→链接→可执行；`-O0` vs `-O2` 对照（寄存器分配、内联、常量折叠、循环优化在汇编上肉眼可见）。
5. **数据的机器表示落点**：结构体对齐/填充、数组寻址、跳转表(switch)、位运算、大小端（本机小端，见 lscpu）。
6. **（可选）安全相关代码模式**：栈金丝雀(-fstack-protector)、PIE/ASLR、CET(endbr64) 在反汇编中的痕迹——接 L5-04。
- **邻课边界**：与 L3-02 **强绑定**（L3-02 定义 ISA/通路，L3-03 是它在真实 x86-64+gcc 上的落地字节）；→L4-04 编译原理（L3-03 是编译器的**输出**，编译讲"怎么生成它"）；→L4-01/L4-05（系统调用约定、栈是并发/安全攻击面）。

### L5-05 高级计算机体系结构（P2｜文·码·证）
1. **ILP 与超标量**：多发射、寄存器重命名、Tomasulo（保留站/CDB）、ROB 与精确异常、按序退休。
2. **乱序执行与投机**：动态调度、内存消歧、load/store 队列；MLP。
3. **分支预测**：2-bit 饱和计数器→两级/gshare→TAGE 量级演进、BTB、误预测冲刷代价。证：可预测 vs 随机分支数组的耗时对比（rdtscp 计时）。
4. **多核缓存一致性**：MESI/MOESI 状态机、嗅探 vs 目录、伪共享(false sharing)。证：同 cache line 争用 vs 填充隔离的耗时对比。
5. **内存一致性模型与屏障**：x86-TSO vs 弱序、`mfence`/`lfence`/`sfence`、C11 atomic memory_order——与 L4-05 内存模型分账（表 1.5）。
6. **数据级并行：SIMD/向量与 GPU**：AVX/AVX-512（本机有 avx512f/dq/bw/vl/vnni，见 §3-D）、SIMT、分支发散、占用率——接 L6-06 HPC。
- **邻课边界**：←L3-02（把顺序 5 级升级为乱序超标量，是同一数据通路的"高性能版"）；→L4-05 并发（内存模型/屏障是两课共有对象，须显式分账：L5-05 讲硬件为什么重排，L4-05 讲程序员如何用 atomic 约束它）；→L6-06 HPC（向量/GPU 的编程落地）；投机侧信道 →L5-04 安全。

## §3 · 一手源候选 + 本机实证点

### 3.1 一手文档候选（腿①，R4 定位到章节/符号）
- **Patterson & Hennessy,《Computer Organization and Design》(RISC-V 版)** —— L2-02 末～L3-02 主教材：数据通路/流水线/内存层次/性能定律。RISC-V 版比 MIPS 版更贴近当代且 ISA 免费开放。
- **Hennessy & Patterson,《Computer Architecture: A Quantitative Approach》(6th ed)** —— L5-05 主教材：ILP、乱序、多核一致性、DLP/向量、内存一致性附录。
- **System V AMD64 ABI**（psABI 规范，当前维护版 @gitlab.com/x86-psABI/x86-64-ABI）—— L3-03 调用约定/寄存器分类/栈帧/red zone 的**权威一手**（规范级，非某编译器行为）。核实时效：该规范 2026 年仍在小幅修订，R4 取用需记版本/提交哈希。
- **Intel® 64 and IA-32 Architectures Software Developer's Manual (SDM)** —— L3-03/L5-05 指令编码(Vol.2)、内存序与屏障(Vol.3 §8 多处理器管理)、CET(Vol.1) 的一手。
- **AMD64 Architecture Programmer's Manual** —— TSO 内存模型交叉核对。
- **ARM Architecture Reference Manual (AArch64)** —— 弱内存序 vs x86-TSO 对比取证（表 1.2/1.5）。
- **RISC-V ISA Specification (Unprivileged/Privileged)** —— 干净 RISC ISA 对照，交叉编译取证。
- **Bryant & O'Hallaron,《CSAPP》第 3 章** —— L3-03 机器级表示的最佳教学一手（x86-64 + gcc 反汇编叙事），与本机基线高度一致，强烈建议作 L3-03 范例锚点。
- **Nagle,《Digital Design》/ Harris & Harris《Digital Design and Computer Architecture》** —— L2-02 一手（后者直接从门电路搭到 RISC-V CPU，最贴合本组抽象阶梯主线）。

### 3.2 本机实证点（腿③；命令 + 环境串，R4 贴真实输出）
> 环境：Linux 6.18.5 x86_64 · gcc 13.3.0 · binutils/objdump 2.42 · gdb 15.1 · Intel Xeon(Skylake, family6 model85, AVX-512) · 4 核 · KVM。⚠**本机无 `perf`**（`which perf` → ABSENT），微架构类实证改用 **rdtscp 计时循环** + **valgrind（本机有 /usr/bin/valgrind：cachegrind 建缓存模型、callgrind 建分支模型）**。

- **L3-02**：`/sys/devices/system/cpu/cpu0/cache/` 读真实 cache 层次（已实测 §3-C）；步长数组遍历 + rdtscp 观测 L1/L2/L3/DRAM 延迟拐点；`valgrind --tool=cachegrind` 看 miss 率随分块变化。
- **L3-03**（**核心取证课**）：`gcc -O0/-O2 -S` 看汇编 diff；`objdump -d` 看编码与序言；`gdb` 单步看栈帧/寄存器/返回地址；调用约定实测（§3-A 已跑）；结构体对齐用 `offsetof`/objdump 核对。
- **L5-05**：可预测 vs 随机分支数组求和的 rdtscp 耗时比（分支预测存在性证据）；伪共享 vs cache-line 填充的多线程耗时比；AVX-512 向量化 vs 标量循环耗时比（`gcc -O3 -march=native -fopt-info-vec`）；`valgrind --tool=callgrind --branch-sim=yes` 建模误预测。
- **L2-02**：纯 Python——sympy 布尔化简 + 真值表穷举等价核对；FSM 逐拍模拟。

### 3.3 实测取证块（本轮已真跑，坐实 §2/§3 断言）

**块 A — SysV AMD64 调用约定（前 6 整型参数寄存器顺序）· 已确认**
```text
# 环境: gcc 13.3.0, objdump 2.42, x86-64 Linux 6.18.5 @2026-07-25
# 源: long f6(long a..g){return a+b+c+d+e+g;}  编译: gcc -O0 -std=c11 -c
$ objdump -d --no-show-raw-insn callconv.o   # 节选 <f6>
   0:  endbr64                     # CET, gcc 默认插入
   4:  push   %rbp                 # 序言: 保存旧帧指针
   5:  mov    %rsp,%rbp
   8:  mov    %rdi,-0x18(%rbp)     # 参数1 -> rdi
   c:  mov    %rsi,-0x20(%rbp)     # 参数2 -> rsi
  10:  mov    %rdx,-0x28(%rbp)     # 参数3 -> rdx
  14:  mov    %rcx,-0x30(%rbp)     # 参数4 -> rcx
  18:  mov    %r8,-0x38(%rbp)      # 参数5 -> r8
  1c:  mov    %r9,-0x40(%rbp)      # 参数6 -> r9
  ...  add ...                     # 求和, 结果最终在 rax
  4f:  pop    %rbp
  50:  ret                         # 返回值走 rax
```
结论（实证）：整型参数顺序 **rdi,rsi,rdx,rcx,r8,r9** 与 SysV ABI 一致；返回值 rax；`-O0` 下用 rbp 帧指针；gcc 默认插入 `endbr64`(CET)。**未验证/留给 R4**：第 7+ 参数入栈方向、red zone、caller/callee-saved 保存实例、`-O2` 省帧指针后的形态。

**块 C — 本机内存层次（sysfs 实测容量）· 已确认（坐实表 1.3）**
```text
$ for i in /sys/devices/system/cpu/cpu0/cache/index*; do \
    echo "L$(cat $i/level) $(cat $i/type) $(cat $i/size)"; done
L1 Data 32K
L1 Instruction 32K
L2 Unified 1024K
L3 Unified 33792K
```
结论：L1d/L1i 各 32 KiB、L2 1 MiB、L3 33 MiB。延迟数字为量级心智模型，R4 需 rdtscp 实测坐实。

**块 D — 本机向量/加密扩展（lscpu flags 实测，坐实 L5-05 SIMD 方向可本机取证）**
```text
$ (来自 lscpu Flags) 含: avx avx2 avx512f avx512dq avx512cd avx512bw avx512vl
   avx512_vnni fma f16c aes pclmulqdq rdtscp constant_tsc nonstop_tsc rtm hle
```
结论：本机支持 **AVX-512**（可做向量化耗时对比实证）、AES-NI（接 L5-04）、rdtscp+constant/nonstop_tsc（**可靠周期计时的前提**，弥补无 perf）。

## §4 · 优先级校准

| ID | 课 | R1 优先级 | 本组校准建议 | 理由 |
|----|----|-----------|--------------|------|
| L3-02 | 计算机组成原理 | P0 | **维持 P0（组内第一枢纽，应最先产）** | fan-out 极高：OS/编译/并发/安全/DB 全依赖；是本组抽象阶梯的轴心。 |
| L3-03 | 汇编与机器级表示 | P1 | **维持 P1，但与 L3-02 打包紧邻产出** | 与 L3-02 强绑定、是其唯一可反汇编取证的"可观测面"；本组**取证密度最高**的一课（调用约定/栈帧全靠真跑），实证 ROI 最大。 |
| L2-02 | 数字逻辑电路 | P1 | **维持 P1，序位应在 L3-02 之前** | 是 L3-02 的元件供应课；纯理论+Python 取证，成本低。可作本组入口。 |
| L5-05 | 高级计算机体系结构 | P2 | **维持 P2** | 深化/方向课，依赖 L3-02 成熟；本机无 perf 使部分实证需降级为 rdtscp/valgrind，取证成本相对高，宜后置。 |

**组内建议产出序**：`L2-02 → L3-02（枢纽，早出）→ L3-03（紧随，打包）→ L5-05（最后深化）`。与 R1 拓扑批次一致（L2-02∈批1；L3-02∈批2；L3-03/L5-05∈批3）。

**跨组接缝提醒（供合并时点出）**：
- 内存序/屏障：L5-05 ↔ **L4-05 并发**（同一对象两视角，必分账）。
- 向量/GPU：L5-05 ↔ **L6-06 HPC**、**N-16 GPU 编程**（勿重复立项，L5-05 讲硬件机制、L6-06 讲编程落地）。
- 投机侧信道(Spectre/Meltdown)：L5-05 ↔ **L5-04 安全**。
- 中断/内存/特权模型：L3-02 ↔ **L4-01 OS**；性能剖析：L5-05 ↔ N-10（微架构 perf 与应用级 profiling 分账，见 R1 §3-B）。
- CET/栈金丝雀/PIE：L3-03 ↔ **L5-04 安全**。
