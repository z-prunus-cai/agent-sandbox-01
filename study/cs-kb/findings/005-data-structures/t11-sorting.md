## 11.1 基础比较排序 — 选择/插入/冒泡

### 11.1.1 插入排序 — 维护一段已排好序的前缀

插入排序（insertion sort）把数组看成「已排序前缀 + 未排序后缀」，每一步取后缀的第一个元素，在前缀里从右向左比较、把比它大的元素逐个右移，直到找到它该待的位置插进去。这样前缀每轮增长 1，n−1 轮后整个数组有序。它是**就地**且**稳定**的比较排序。

代价画像用「比较次数」刻画。已经升序时每个新元素只需和前缀末尾比 1 次就停，最好情况：

C_best(n) = n − 1 = Θ(n)

完全逆序时第 i 个元素要一路比到头，最坏情况：

C_worst(n) = 1 + 2 + … + (n−1) = n(n−1)/2 = Θ(n²)

平均情况（随机排列）仍是 Θ(n²)，因为平均每个元素要移过前缀的一半。

为什么初学者要先学它：它最贴近人整理扑克牌的直觉，且是「最好/最坏情况差异巨大」的最佳范例——同一段代码，输入近乎有序时是线性的，逆序时是平方的。这解释了为什么工业级排序（如 Python 的 Timsort、C++ 的 introsort）在小数组或近乎有序的段上退回插入排序：常数因子小、对已排序数据极快。易错点：内层循环的边界，向右移动元素时若先覆盖再读会丢数据，必须先把待插入的 key 存下来再腾位置。

本机实测（比较次数，n=8）：

```
insertion N=8: best_comps=7 (=n-1=7), worst_comps=28 (=n(n-1)/2=28)
```

升序输入恰好 n−1=7 次比较，逆序输入恰好 n(n−1)/2=28 次，与上面两式吻合。

### 11.1.2 选择排序 — 每轮选出最小值放到位

选择排序（selection sort）每一轮在未排序后缀里扫描一遍、选出最小元素，与后缀的第一个位置交换。n−1 轮后有序。它是**就地**的，但标准实现**不稳定**。

它的比较次数与输入无关，永远是：

C(n) = (n−1) + (n−2) + … + 1 = n(n−1)/2 = Θ(n²)

无论最好、最坏、平均都是 Θ(n²) 次比较——这是它与插入排序最大的区别（插入排序最好情况是线性）。它的一个可取之处是**交换次数**只有 O(n)（每轮至多一次交换），当「移动元素」远比「比较元素」昂贵时（例如元素是大对象）这有意义。

初学者最容易忽略的点是**不稳定性的来源**：那一次「远距离交换」会把一个元素越过中间的等键元素扔到前面，破坏相对顺序。本机实测用键相等的元素演示：

```
输入 data = [(3,'a'),(1,'b'),(3,'c'),(2,'d'),(1,'e')]
稳定排序(键) : [(1,'b'),(1,'e'),(2,'d'),(3,'a'),(3,'c')]
朴素选择排序 : [(1,'b'),(1,'e'),(2,'d'),(3,'c'),(3,'a')]
```

稳定结果里 (3,'a') 仍在 (3,'c') 前；朴素选择排序把二者顺序颠倒成 (3,'c')、(3,'a')，因为第 0 轮把最小的 (1,'b') 与位置 0 的 (3,'a') 交换，(3,'a') 被抛到了 (3,'c') 后面。这就是「一次远距离交换毁掉稳定性」的直观证据。

### 11.1.3 冒泡排序 — 相邻比较逐个上浮

冒泡排序（bubble sort）反复扫描数组，比较**相邻**两元素，若逆序就交换；每一趟扫描会把当前最大元素「冒泡」到末尾。加上「本趟无交换即提前终止」的优化后，它对已排序输入是 Θ(n)。它是**就地**且**稳定**的（相邻交换只在严格逆序时发生，等键不交换，故不破坏相对序）。

代价画像：

C_worst(n) = Θ(n²)，C_best(n) = Θ(n)（带提前终止，输入已排序）

三者（选择/插入/冒泡）同属 Θ(n²) 家族，但要点各不同，务必分清：**插入**最好情况线性、稳定；**冒泡**最好情况线性（需提前终止优化）、稳定；**选择**任何情况都是 Θ(n²) 比较、但交换少、不稳定。冒泡排序在教学外几乎不用（相邻交换导致移动次数多、常数大），它的教学价值是最直白地展示「相邻交换 + 逆序对」的模型：一个数组需要的相邻交换总次数恰等于它的**逆序对**数目。

分歧提示：冒泡排序在 CLRS 4th 不是正文算法，而出现在 Ch2 习题（Problem 2-2）；选择排序也主要出现在习题。CS61B 与 Open Data Structures 则把这几种朴素排序作为入门比较对象讲。本节以「习题/教辅入门算法」定位它们，正文复杂度取两处一致的结论。

## 11.2 归并排序 — 分治与稳定合并

### 11.2.1 分治框架：分、治、合

归并排序（merge sort）是分治（divide and conquer）的范本：把数组从中点**分**成两半，递归**治**（各自排序），再把两个已排序的半段**合**并成一个有序整体。递归到长度 1 的子数组时天然有序，递归触底。它的时间复杂度在**所有情况**下都是：

T(n) = Θ(n log n)

因为递归树有 Θ(log n) 层（每层规模减半），每层的合并操作合计扫过 Θ(n) 个元素。用递归式表达（对应大主题1 的主定理入门）：

T(n) = 2·T(n/2) + Θ(n)

解得 T(n) = Θ(n log n)。这个「与输入无关的稳定 Θ(n log n)」是归并排序相对快排的最大卖点。

代价画像的另一面是空间：标准归并的**合并**步骤需要一块 Θ(n) 的辅助数组来临时存放合并结果，所以它**不就地**（就地归并存在但复杂、常数大，非教学主线）。这是它与堆排序、快排的关键区别——后两者就地。

### 11.2.2 稳定合并：等键时先取左半

合并（merge）是归并排序的心脏：两个已排序子段各有一个指针，每次比较两指针所指元素、把较小者取出放入结果、指针前移，一侧耗尽后把另一侧剩余直接拼接。合并是线性时间 Θ(n) 的，因为每个元素只被取出一次。

归并排序**稳定**的充要写法是：合并时若两侧元素**相等，优先取左半段（下标更小、原本更靠前）的那个**。这样等键元素的原相对顺序被保留。这是初学者最常写错稳定性的地方——把比较写成「左 < 右 取左，否则取右」（即相等时取右）就会破坏稳定性。所以关键在那个等号落在哪一侧：

取左侧当且仅当 left[i] ≤ right[j]（等号归左 → 稳定）

一个最小例子：合并 [ (1,'a') ] 与 [ (1,'b') ]，两键都是 1，稳定合并先取左半的 (1,'a')，得 [(1,'a'),(1,'b')]，保住原序。易错点还包括合并后忘记把结果拷回原数组、以及中点取整导致左右不均（对正确性无碍，仅影响是否恰好平分）。

归并排序也天然适配**链表**（无需随机访问、无需辅助数组即可稳定归并）与**外部排序**（数据大到放不进内存时，分块排序再多路归并），这是它作为「数据结构操作」的重要应用面。

## 11.3 快速排序与划分 — Lomuto/Hoare 划分、枢轴选择

### 11.3.1 划分（partition）：快排的核心操作

快速排序（quicksort）也是分治，但把主要工作放在「分」而非「合」：选一个**枢轴**（pivot），通过一趟**划分**把数组重排成「≤ 枢轴的元素 | 枢轴 | ≥ 枢轴的元素」三段，枢轴就落到了它的最终位置；然后对左右两段递归。划分做完后无需合并，因此快排**就地**（只用 O(1) 额外空间 + O(log n) 递归栈）。

平均与最坏代价画像：

T_avg(n) = Θ(n log n)，T_worst(n) = Θ(n²)

平均情况下每次划分大致均分，递归树 Θ(log n) 层、每层 Θ(n) 划分工作；最坏情况是每次划分极不均衡（一段空、一段 n−1），递归树退化成 n 层，代价 Θ(n²)。标准快排**不稳定**（划分中的远距离交换会打乱等键相对序）。

### 11.3.2 Lomuto 划分 vs Hoare 划分

划分有两种经典写法，初学者常把它们混为一谈，务必分清：

**Lomuto 划分**：取末元素为枢轴，用一个慢指针 i 维护「已知 ≤ 枢轴的区间边界」，快指针 j 从左扫到右，遇到 ≤ 枢轴的元素就与 i+1 处交换、i 前移；扫完把枢轴换到 i+1。代码短、易懂，是 CLRS 正文 PARTITION 采用的版本。

**Hoare 划分**：取首元素（或首）为枢轴，两个指针分别从两端向中间逼近，左指针找 ≥ 枢轴者、右指针找 ≤ 枢轴者，交换之，相遇即停。它平均**交换次数更少、常数更小**，但边界更易写错，且返回的分割点语义与 Lomuto 不同（Hoare 不保证枢轴落到最终位置）。

这是一个应显式记录的**来源分歧点**：CLRS 4th 正文用 **Lomuto** 版 PARTITION（§7.1），而 **Hoare** 原始划分作为 **Problem 7-1** 出现在习题里；许多教材/CS61B 讲快排时反而以 Hoare 双指针为直觉主线。两者都正确、复杂度同阶，但实现细节（枢轴位置、指针不变式、递归调用参数）不同，混用两套下标会写出越界或死循环的 bug。

### 11.3.3 枢轴选择与最坏情况

最坏 Θ(n²) 恰恰发生在「枢轴总是最小或最大值」时——例如对**已排序**数组用「取末/首元素为枢轴」的朴素快排，每次划分都极不均衡，退化成 Θ(n²)。这与直觉相反（有序数组反而最慢），是初学者最该记住的陷阱。

工程上的对策（此处只给直觉，随机化的期望分析深挖归 L3-01）：**随机化枢轴**（随机选一个元素当枢轴，使最坏情况不再由特定输入触发，而是极小概率事件）或**三数取中**（取首、中、尾的中位数）。C++ 标准库的 introsort 还会在递归过深时切换到堆排序，把最坏情况从 Θ(n²) 兜底到 Θ(n log n)。

## 11.4 堆排序 — 就地建堆 + 反复取极值

### 11.4.1 用堆结构驱动的排序

堆排序（heapsort）是「数据结构直接支撑排序」的最清晰例子：把待排数组先原地整理成一个**最大堆**（大主题7 的完全二叉树数组表示），此时最大值在 root（下标 0/1）；然后反复「把 root 与堆末尾交换、堆规模减 1、对新 root 下沉修复堆序」，每次固定一个最大值到数组尾部，n−1 次后整个数组升序。它**就地**、时间**最坏 Θ(n log n)**，但**不稳定**。

两个阶段的代价：

T_build(n) = Θ(n)（自底向上建堆，紧界）

T_sortdown(n) = Σ Θ(log n) = Θ(n log n)（n−1 次「取极值 + 下沉」）

合计 Θ(n log n)。关键直觉：建堆是 Θ(n) 而非 Θ(n log n)——因为大多数结点靠近叶子、下沉距离短，紧界求和收敛到线性（该紧界论证属大主题7，本处只引结论）。真正主导总代价的是第二阶段的 n 次 O(log n) 下沉。

### 11.4.2 与归并/快排的画像对比

堆排序填补了一个空档：它同时拥有**就地**（像快排、不像归并）和**最坏 Θ(n log n) 保证**（像归并、不像快排）。代价是它的**缓存局部性差**（下沉操作在数组里跳跃访问父子下标，跨度大），常数因子通常比同为 Θ(n log n) 的快排大，所以实测常慢于随机化快排。它**不稳定**，原因同选择排序——「root 与末尾交换」是一次远距离交换，会打乱等键相对序。

初学者的心智模型：堆排序 ≈「反复执行 n 次 extract-max 的选择排序」，但因为堆让每次「找并移除最大值」从 Θ(n) 降到 Θ(log n)，整体从 Θ(n²) 降到 Θ(n log n)。这正是「换一个数据结构（无序数组 → 堆）就把同一算法思路加速一个量级」的典型，契合本大主题「排序作为数据结构应用」的立意。易错点：下沉时要在**左右孩子中选较大者**再比较交换，只跟一个孩子比会破坏堆序。

## 11.5 比较排序下界 — 决策树 Ω(n log n)

### 11.5.1 下界结论：没有比较排序能突破 Ω(n log n)

比较排序的下界定理是：任何**只靠元素两两比较**来排序的算法，在最坏情况下都至少要做 Ω(n log n) 次比较。因此归并、堆排序在渐近意义上已是**最优比较排序**——不可能有 O(n) 的通用比较排序。形式化地，最坏比较次数满足：

C_worst(n) = Ω(n log n)

这不是「目前没找到更快的」，而是被数学证明**封死**的天花板；要突破它，必须放弃「只比较」这一手段，改用键的数值结构（见 11.6）。

### 11.5.2 决策树直觉：为什么是 n log n

证明模型是**决策树**（decision tree）：把一个比较排序在长度为 n 的输入上的全部执行画成一棵二叉树，每个内部结点是一次比较「a_i ≤ a_j ?」，两条分支对应比较的两种结果，每片叶子对应一种最终输出的排列。

关键两点：其一，n 个不同元素有 **n! 种排列**，算法必须能区分它们全部，所以决策树至少有 n! 片叶子——

叶子数 ≥ n!

其二，一棵高度为 h 的二叉树最多有 2^h 片叶子，而树的高度 = 最坏情况下的比较次数。于是：

2^h ≥ n!  ⟹  h ≥ log₂(n!)

再用 Stirling 近似 log₂(n!) = Θ(n log n)，即得 h = Ω(n log n)。直觉：每次比较只能给出 1 bit 信息（是/否），而要从 n! 种可能里锁定唯一答案需要 log₂(n!) ≈ n log₂ n 个 bit，所以至少要 Ω(n log n) 次比较。

本机实测核对 log₂(n!) 的渐近主项（sympy loggamma 展开 + 数值比值）：

```
log2(n!) 主项 ≈ n·log2(n) − n/ln2 + (1/2)log2(n) + ...   → Θ(n log n)
N=   10  log2(N!)=      21.8  N*log2N=      33.2  ratio=0.6560
N=  100  log2(N!)=     524.8  N*log2N=     664.4  ratio=0.7899
N= 1000  log2(N!)=    8529.4  N*log2N=    9965.8  ratio=0.8559
N=10000  log2(N!)=  118458.1  N*log2N= 132877.1  ratio=0.8915
```

比值随 n 增大缓慢趋近 1，坐实 log₂(n!) 与 n·log₂n 同阶（Θ(n log n)）——注意收敛很慢（有 −n/ln2 的低阶拖累项），这也是初学者容易误判「log(n!) 远小于 n log n」的原因：它们只是渐近同阶，前者的系数在有限 n 下明显小一截。

易错点：这条下界**只约束比较排序**。学生常错误地把「排序至少要 Ω(n log n)」当成排序问题的绝对下界，从而否定 11.6 的线性排序——其实线性排序不属于比较模型，不受此界约束。

## 11.6 线性时间排序 — 计数/基数/桶排序及其假设

### 11.6.1 计数排序 — 用键当下标，稳定且线性

计数排序（counting sort）不比较元素，而是**统计每个键出现的次数**，再据此把元素直接放到最终位置。设键取值范围是 0..k−1，其时间与空间为：

T(n) = Θ(n + k)，空间 Θ(n + k)

当 k = O(n) 时它是**线性** Θ(n) 的，突破了 11.5 的比较下界——因为它根本不做元素间比较，而是利用「键是小整数、可当数组下标」这一额外假设。它是**稳定**的：标准写法先对计数做前缀和得到每个键的结束位置，再**从右向左**扫描输入放置元素，从而保住等键的原相对序（稳定性对下一步基数排序至关重要）。

代价与前提是绑定的：k 很大时（如键是 32 位整数，k=2³²）空间与时间都会爆炸，此时计数排序不适用。所以它的适用面是「键为范围不大的非负整数」。

### 11.6.2 基数排序 — 逐位调用稳定子排序

基数排序（radix sort）处理「键是 d 位数字」的情形：从**最低位到最高位**，逐位用一个**稳定**的排序（通常是计数排序）对该位排序，d 趟之后整体有序。时间为：

T(n) = Θ(d·(n + k))

其中 k 是单位数字的取值基数（如十进制 k=10）。当 d 为常数、k=O(n) 时它是线性的。

为什么必须从**最低位**开始、且每趟子排序必须**稳定**：稳定性保证「本趟按低位排好的顺序，在处理更高位时不被同高位数字打乱」。若子排序不稳定，低位排序的成果会在高位趟被破坏，结果错误。这是基数排序最反直觉、也最常被初学者写错的点——它是计数排序稳定性的直接下游应用，把 11.6.1 的「稳定」从性质变成了正确性的必要条件。

### 11.6.3 桶排序 — 靠输入分布假设的期望线性

桶排序（bucket sort）假设输入**均匀分布**在某区间（如 [0,1)），把区间等分成 n 个桶，按值把每个元素扔进对应桶，桶内用插入排序等排好，再顺序拼接。它的**平均**时间为：

T_avg(n) = Θ(n)（输入在区间内均匀分布的假设下）

但这条线性只在**分布假设成立**时成立：若所有元素挤进同一个桶，桶内排序退化，最坏为 Θ(n²)。这与前两者不同——计数/基数的线性来自「键的取值结构」（确定性假设），桶排序的线性来自「键的概率分布」（统计假设）。

统一的初学者心智模型：这三种排序都是「用关于键的额外信息换掉比较」——计数用「键是小整数」、基数用「键是定长数字串 + 稳定子排序」、桶用「键均匀分布」。它们不违反 11.5 的下界，因为它们压根不在比较模型内。易错点：把它们当成「万能更快的排序」——一旦键范围大（计数/基数）或分布不均（桶），线性优势立刻失效，甚至不如 Θ(n log n) 的比较排序。
