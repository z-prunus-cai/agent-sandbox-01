## 5.1 树术语与二叉树表示

### 5.1.1 树是什么：根、父子、边与无环连通

树（tree）是一种分层的非线性数据结构：它由一组结点（node）和连接结点的边（edge）组成，有一个特殊结点叫根（root），其余每个结点恰好有一个父结点（parent），沿边从根出发能到达任意结点且不存在环。直观上它长得像一棵倒挂的树——根在最上面，枝叶向下展开。

把树想成「一个老板（根）带若干直接下属（孩子），每个下属又各带自己的下属」的组织结构图。关键约束有两条：一是「每人只有一个直接上司」（单一父结点），二是「顺着上下级关系走不会绕回自己」（无环）。这两条合起来保证了从根到任意结点的路径是唯一的——这一点是后面所有树上算法能「不重复、不遗漏」地工作的根基。

几个常配对出现的术语：没有孩子的结点叫叶结点（leaf）；有孩子的结点叫内部结点（internal node）；同一个父结点下的结点互为兄弟（sibling）；从某结点一路向下能到达的所有结点构成它的子树（subtree）。CLRS §12.1 与 CS61B 的 BSTs 讲次都用这套术语，措辞一致。

### 5.1.2 高度与深度：两个方向相反的距离

深度（depth）和高度（height）都是用边数衡量的距离，但方向相反。某结点的深度是从根到该结点这条唯一路径上的边数；某结点的高度是从该结点到它子树中最深叶结点这条最长路径上的边数。整棵树的高度定义为根的高度。

单结点树高度为 0，深度也为 0：

height(单结点) = 0

约定空树的高度为 −1（CLRS 与多数教材采用此约定，使递归式 height(n) = 1 + max(height(左), height(右)) 在叶结点处自然给出 0）。

初学者最常见的混淆是把「高度」「深度」「层数」三者混为一谈，以及在「按边数」还是「按结点数」上摇摆。务必钉死一个约定：本报告一律按边数。于是根的深度是 0（不是 1），一棵只有根的树高度是 0（不是 1）。CS61B 课件同样按边数，但也提醒不同教材可能按「结点数」定义（那样单结点高度就成了 1）——遇到别处的题目先确认它用哪套约定，否则会差 1（off-by-one）。

为什么要关心高度？因为树上大多数「从根往下走」的操作，代价正比于走过的路径长度，最坏就是树高。后面 5.3–5.5 里 BST 查找、插入、删除全都是 O(h) 的操作，h 就是这里的树高——高度决定性能，是贯穿整章的主线。

### 5.1.3 二叉树与几类特殊形态

二叉树（binary tree）是每个结点至多有两个孩子的树，两个孩子有左右之分，分别叫左孩子、右孩子。左右有序这一点很重要：交换左右孩子会得到一棵不同的二叉树（而在一般的「无序树」里孩子之间没有先后）。

几类会反复出现的特殊形态需要区分清楚（术语以 CLRS §12 与算法教材通用定义为准）：

- 满二叉树 / 真二叉树（full / proper binary tree）：每个结点要么是叶，要么恰好有两个孩子（没有「只有一个孩子」的结点）。
- 完全二叉树（complete binary tree）：除最后一层外每层都填满，且最后一层的结点尽量靠左。这是大主题7 堆用数组表示的前提，此处先埋个伏笔。
- 完美二叉树（perfect binary tree）：所有内部结点都有两个孩子，且所有叶在同一层。

一个对理解复杂度极关键的量化关系：高度为 h 的二叉树，结点数 n 最少 h+1 个（退化成一条链），最多 2^{h+1} − 1 个（完美二叉树填满）。把它反过来解，就得到 n 个结点的二叉树高度的取值范围：

⌊log₂ n⌋ ≤ h ≤ n − 1

左端 log₂ n 是「尽量矮胖」时的高度，右端 n−1 是「退化成一条链」时的高度。这条不等式解释了两件事：为什么我们总希望树「矮」（h 越接近 log n，操作越快），以及为什么朴素 BST 有退化风险（h 可能滑到 n−1）——这正是 5.5 与大主题6 要处理的核心矛盾。

### 5.1.4 链式表示：结点结构体与指针

二叉树最常见的实现是链式表示：每个结点是一个包含「数据 + 左孩子指针 + 右孩子指针」的记录，空指针表示「没有这个孩子」。这与大主题2 的链表是同一套指针思想，只是从「一个 next」扩成「left / right 两个方向」。

C 语言里典型的结点定义：

```c
struct TreeNode {
    int key;
    struct TreeNode *left;
    struct TreeNode *right;
};
```

CLRS §12.1 的表示还额外给每个结点存一个父指针 p，构成 key / left / right / p 四个字段——加父指针是为了让「求后继、删除时向上回溯」更方便（见 5.3、5.4）。Open Data Structures §6.2 的 BinarySearchTree 同样采用带父指针的结点。是否存父指针是一个实现权衡：存了向上走方便但每个结点多占一份空间、且插删时要多维护一个字段；不存则要靠递归调用栈或额外传参记住来路。CS61B 的 Java 实现里孩子用引用（reference）表达，语义与 C 指针一致，只是没有裸指针的手动内存管理。

一是忘记初始化孩子指针为空（NULL / None / null），导致误把野指针当成有孩子；二是把「叶结点」与「空指针」搞混——叶结点是真实存在、只是两个孩子都为空的结点，而空指针代表「这里根本没有结点」。CLRS 在图示里常用带斜杠的方框或 NIL 表示空，帮助区分二者。

## 5.2 遍历 — 前/中/后序、层序（DFS/BFS）

### 5.2.1 深度优先遍历：前序、中序、后序

遍历（traversal）是「系统地访问树中每个结点恰好一次」。二叉树的深度优先遍历（DFS）有三种，区别只在于「访问当前结点」这个动作插在「递归左子树」和「递归右子树」之间的哪个位置：

- 前序（preorder）：先访问根，再递归左子树，最后递归右子树（根—左—右）。
- 中序（inorder）：先递归左子树，再访问根，最后递归右子树（左—根—右）。
- 后序（postorder）：先递归左子树，再递归右子树，最后访问根（左—右—根）。

递归写法几乎是定义的直译：

```python
def inorder(node, visit):
    if node is None:
        return
    inorder(node.left, visit)
    visit(node)                 # 把 visit 这行挪到三个位置就得到前/中/后序
    inorder(node.right, visit)
```

初学者最好用一棵三结点小树（根 2、左 1、右 3）手推一遍：前序得 2,1,3；中序得 1,2,3；后序得 1,3,2。记忆口诀是「pre/in/post 指的是根被访问的时机在最前 / 中间 / 最后」。三者都恰好访问每个结点一次，因此对 n 个结点的树，遍历时间是：

T(n) = Θ(n)

为什么线性？因为每个结点被进入常数次（进入、处理、离开），总工作量与结点数成正比。不同遍历只改变输出顺序，不改变这个总量。

中序遍历在 BST 上会按键升序输出（见 5.3，这是 BST「有序」的直接体现）；后序适合「先处理完孩子再处理自己」的场景，如释放整棵树的内存、计算每个子树的高度；前序适合「先记录自己再展开孩子」的场景，如复制/序列化一棵树。

### 5.2.2 广度优先遍历：层序与队列

层序遍历（level-order traversal）按「层」自上而下、每层从左到右访问结点，它是广度优先搜索（BFS）在树上的形态。实现的核心不是递归而是一个队列（queue）：先把根入队，然后反复「出队一个结点、访问它、把它的非空孩子依次入队」，直到队列空。

```python
from collections import deque

def level_order(root, visit):
    if root is None:
        return
    q = deque([root])
    while q:
        node = q.popleft()      # 队头出队 = 先进先出
        visit(node)
        if node.left:  q.append(node.left)
        if node.right: q.append(node.right)
```

初学者要抓住的直觉是「队列的先进先出恰好实现了按层推进」：第 k 层的结点全部先于第 k+1 层入队，也就全部先出队被访问。这与 DFS 用（显式或递归的）栈「一条道走到黑再回头」形成鲜明对照——换容器（栈↔队列）就换了遍历策略，这是本课大主题3 里「受限接口结构」思想的一次实际应用。

一个常见易错点是层序里忘了判空就把孩子入队，导致 None 混进队列后在 visit 时崩溃；上面的代码用 `if node.left` / `if node.right` 先过滤。另一个是想「用递归做层序」——可以做但要额外传层号、并不自然，队列才是层序的顺手工具。

关于 DFS/BFS 的措辞，CLRS 把「前/中/后序」作为二叉树遍历（§12.1 及练习）单独讲，把 BFS/DFS 作为图算法（Ch20）系统讲；CS61B 则直接把树遍历纳入 DFS/BFS 框架讲解。两者不冲突：树是图的特例，树的三种深度优先遍历就是图 DFS 在「无环、每结点单父」上的具体化，层序就是图 BFS 的具体化。图上的 DFS/BFS（时间戳、边分类、O(V+E)）归本课大主题9，此处只讲树上的形态。

## 5.3 BST 查找/最值/前驱后继 — 有序性质与搜索

### 5.3.1 二叉搜索树性质

二叉搜索树（binary search tree, BST）是在二叉树上加一条有序约束的结构。CLRS §12.1 给出的 BST 性质是：对任意结点 x，其左子树中所有结点的键都 ≤ x.key，右子树中所有结点的键都 ≥ x.key。

设 y 是 x 左子树中的结点、z 是 x 右子树中的结点，则：

y.key ≤ x.key ≤ z.key

这条性质是「局部」的——它对每个结点各自成立，但合起来就产生一个「全局」结论：对 BST 做中序遍历，会按键升序输出所有元素（承接 5.2.1）。这也是「搜索树」名字的来源：有序让我们能像二分查找一样，每一步排除掉一整棵子树。

初学者要注意两点。其一，性质里对相等键的处理各家略有差异：CLRS §12.1 用「≤ / ≥」允许重复键落到某一侧；CS61B 与许多入门实现干脆假设键互不相同（distinct），把相等当作「已存在、不插入」。这不是谁对谁错，而是接口约定不同——用之前先确认这棵 BST 允不允许重复键。其二，别把 BST 性质误记成「左孩子 < 根 < 右孩子」这种只管直接孩子的弱版本；正确版本管的是「整棵左/右子树」，只看直接孩子会漏判更深处的违规。

### 5.3.2 查找：沿高度下降的 O(h) 搜索

在 BST 中查找键 k，从根开始：k 等于当前结点键则命中；k 更小则走左孩子；k 更大则走右孩子；走到空指针说明不存在。每一步都把搜索范围缩小到一棵子树，因此走过的路径长度不超过树高。

TREE-SEARCH(x, k) 时间为：

T = O(h)

其中 h 是树高。递归/迭代两种写法等价，CLRS §12.2 两种都给：

```python
def search(node, k):
    while node is not None and k != node.key:
        node = node.left if k < node.key else node.right
    return node          # 命中返回结点，否则返回 None
```

这里 O(h) 是关键，也是全章的枢纽。结合 5.1.2 的高度范围 ⌊log₂ n⌋ ≤ h ≤ n−1：如果树是平衡的（h ≈ log n），查找就是 O(log n) 的快操作；如果树退化成链（h = n−1），查找就退化成 O(n) 的线性扫描。BST 的「快」不是无条件的，它挂靠在「树不要太高」这个前提上——这个前提何时会破，就是 5.5 的主题。

### 5.3.3 最小值、最大值

BST 的最小值一定在「一路向左到底」的结点，最大值一定在「一路向右到底」的结点。原因直接来自 BST 性质：任何结点的左子树键都不大于它，所以最小值不可能在右边；对称地最大值一路向右。

```python
def tree_min(node):
    while node.left is not None:
        node = node.left
    return node
```

两者都是 O(h)。这个「一路到底」的小操作看似简单，却是 5.3.4 求后继和 5.4 删除双子结点的零件，务必先吃透。

### 5.3.4 前驱与后继

某结点 x 的后继（successor）是「中序遍历中紧跟在 x 之后的结点」，也就是所有键大于 x.key 的结点里键最小的那个；前驱（predecessor）对称。CLRS §12.2 给出的 TREE-SUCCESSOR 分两种情况：

- 若 x 有右子树：后继就是「x 的右子树中的最小结点」（右拐一步再一路向左到底）。
- 若 x 没有右子树：后继是「x 的第一个『把 x 留在其左子树里』的祖先」——从 x 沿父指针向上走，直到某一步是从左孩子上来的，那个父结点就是后继（若一路走到根都没有，说明 x 是最大值，无后继）。

第二种情况需要父指针（呼应 5.1.4 为何 CLRS 存父指针）。初学者对第一种情况通常一看就懂（右子树最小即紧邻的更大者），对第二种容易卡壳；直觉是：没有右子树意味着「比 x 大且在 x 下方」的候选不存在，紧邻的更大者只能在上方——具体是那个「x 位于其左子树」的最近祖先，因为从它看 x 属于「较小的一半」，而它本身是这一子树里刚好比整个左子树都大的门槛值。用一棵小树手推两三个结点的后继能很快建立感觉。前驱把「右/左」「最小/最大」全部镜像即可。

## 5.4 BST 插入与删除 — 删除三情形（叶/单子/双子）

### 5.4.1 插入：查找失败位置后挂新叶

BST 插入的思路是「先按查找的走法一路下降，走到空指针的位置就是新键该待的地方，把新结点挂成那里的叶」。因为一路下降时每一步都遵守 BST 性质选择左右，落点必然使插入后整棵树仍满足 BST 性质。

```python
def insert(node, k):
    if node is None:
        return Node(k)               # 走到空位，新叶诞生
    if k < node.key:
        node.left = insert(node.left, k)
    elif k > node.key:
        node.right = insert(node.right, k)
    return node                      # k == node.key：视约定去重或忽略
```

插入代价与查找一样是 O(h)：主要开销就是那趟下降。要点：新结点总是作为叶插入，不会插到中间打断已有结构。初学者易错点是插入顺序会决定树形——同一组键换个插入顺序会长出完全不同（可能很矮也可能很高）的树，这个「插入顺序敏感」正是 5.5 退化问题的种子。

无论怎么插，只要维持 BST 性质，中序遍历一定升序。下面这条在基线环境实测通过（详见本节末实测串）：随机插入 50 个键后中序输出与 sorted(keys) 完全一致，返回 True。

### 5.4.2 删除：三种情形

删除是 BST 里最需要小心的操作，因为要在移走一个结点后仍维持 BST 性质。按被删结点 z 的孩子数分三种情形（CLRS §12.3 用 TRANSPLANT 子过程统一处理，下面按经典「三情形」讲直觉）：

- 情形一，z 是叶（无孩子）：直接把它从父结点摘掉（父对应指针置空）。
- 情形二，z 只有一个孩子：用那个孩子「顶替」z 的位置（父结点原来指向 z，现在改指向 z 的唯一孩子）。
- 情形三，z 有两个孩子：找到 z 的中序后继 y（即 z 右子树的最小结点，见 5.3.4），把 y 的键搬到 z 的位置，再删掉原来的 y。关键在于 y 至多只有一个（右）孩子——因为它是右子树的最小值、必然没有左孩子——所以「删掉原 y」退化成情形一或情形二，不会无限递归。

为什么情形三要用后继（或对称地用前驱）而不能随便挑一个结点顶上？因为后继是「大于 z 的所有键里最小的」，把它放到 z 的位置，恰好能同时满足「比整个左子树都大」和「比右子树其余都小」这两个 BST 约束，替换后整棵树仍有序。这是删除算法的灵魂，务必理解而非死记。

删除代价同样是 O(h)：找后继、搬键、摘结点都不超过一趟树高。CLRS 的 TRANSPLANT formulation 把「用一棵子树替换另一棵子树」抽象成一个子过程，从而把三种情形写得更统一（尤其借助父指针），但产生的结果与上面的三情形描述一致——这是「同一算法、两种写法」，不是分歧。

情形三删的是「原后继结点 y」而不是又去删 z（键已经搬走，要清理的是腾出来的 y）；用后继时别忘了后继可能带一个右孩子需要顶替（退化到情形二）；以及务必用中序验证——删完后中序仍升序才说明没破坏 BST 性质。

### 5.4.3 用中序遍历验证正确性

因为「BST 性质 ⇔ 中序升序」，中序遍历是检验插入/删除实现是否正确的最省事探针：每次改动后跑一遍中序，若输出不再严格升序（或去掉了不该去的键），实现必有 bug。本报告在基线环境用一棵 50 键随机 BST 验证「插入后中序 == 排序结果」返回 True（实测串见下）。

这也是把「抽象性质」变成「可执行断言」的一个范例，与本课大主题1 讲的表示不变式（representation invariant）思想一脉相承：BST 的表示不变式就是「中序升序」，任何操作前后都应保持它。

实测串：Python 3.11.15 / Linux 6.18.5 x86_64（对应基线）。随机 50 键插入后 `inorder(root) == sorted(keys)` 输出 `True`。

## 5.5 退化陷阱与随机化直觉 — 有序插入退化成链表

### 5.5.1 退化：有序插入把 BST 变成链表

朴素 BST 不含任何自动平衡机制，它的形状完全由插入顺序决定。当键按已排好序（升序或降序）的顺序插入时，每个新键都比已有的全部键大（或小），于是一路挂到最右（或最左），BST 退化成一条只有右孩子的链。此时树高达到最坏：

h = n − 1

而查找/插入/删除都是 O(h)，于是全部退化成 O(n)——BST 相对链表/有序数组的优势荡然无存。

本机在基线环境实测这一退化：把 0..999 按升序插入一棵朴素 BST，测得树高 = 999，正好是 n−1（n=1000），完全退化成链。实测串见本节末。这不是抽象威胁，而是真实、必然发生的最坏情形：现实里「按主键顺序批量导入」「时间戳递增插入」都极易触发。

BST 的 O(log n) 是「树平衡时」的最好/平均表现，不是保证。CLRS §12.2–12.3 里所有操作的严谨界都写成 O(h)，正是因为 h 本身不受朴素 BST 控制。谁来控制 h，就是大主题6 平衡搜索树（AVL / 红黑 / B 树）要解决的问题——它们通过旋转/变色/分裂强行把 h 压在 O(log n)。

### 5.5.2 随机化直觉：随机插入顺序期望高度 O(log n)

退化只发生在「刻意有序」的坏输入上吗？CLRS §12.4「随机构建的二叉搜索树」给出的结论是：如果 n 个互异的键以随机排列（每种排列等概率）的顺序插入一棵朴素 BST，则得到的树的期望高度是

E[h] = O(log n)

也就是说「大多数插入顺序」长出的树是矮的，只有极少数（如恰好有序）会退化。这解释了为什么在随机数据上朴素 BST 往往表现不错，也是「随机化平衡树」（如 treap、跳表思想）的理论根基——主动把输入打乱，就能大概率避开最坏形状。

对 n=1000，升序插入得高度 999；而随机打乱顺序插入、200 次试验的平均高度约 21.13（约 2.1·log₂1000，log₂1000 ≈ 9.97）。有序与随机两种顺序的树高差了约 47 倍，直观展示了「顺序敏感」的威力。实测串见下。

E[h] = O(log n) 这个渐近界来自 CLRS §12.4 定理，属可靠结论；但期望高度的精确前导常数（文献给出约 4.31·ln n，即约 3·log₂ n 量级）超出本报告的入门广度，此处不展开推导，仅指出「常数比 log₂ n 略大」，与上面实测的约 2.1 倍在数量级上一致（有限 n 与渐近常数本就有差距，不构成矛盾）。

### 5.5.3 从退化到平衡：交棒给大主题6

把 5.5 的两条结论并起来看：朴素 BST 在坏输入下必然退化（h = n−1），在随机输入下期望是好的（E[h] = O(log n)）。工程上不能赌输入是随机的，于是需要「无论输入怎样都强制 h = O(log n)」的结构——这正是平衡搜索树的使命，归本课大主题6。

朴素 BST 教会我们「有序 + 二叉 = 能二分查找」的核心思想，但把「保持矮」这件事交给了运气；平衡树在同样的 BST 骨架上，额外花一点每步操作的常数代价（旋转/变色），换来「永远矮」的最坏保证。理解了本章的 O(h) 与退化，才能理解大主题6 为什么值得那些额外机制。

实测串：Python 3.11.15 / Linux 6.18.5 x86_64（对应基线）。n=1000 升序插入树高 = 999；随机打乱插入 200 次试验平均树高 ≈ 21.13；log₂1000 ≈ 9.97。脚本仅存 scratchpad，不入库。
