## 6.1 平衡不变式概念 — 高度界 O(log n) 的维持思想

### 6.1.1 问题的根：普通 BST 会退化成链表

平衡搜索树要解决的，是大主题5 结尾暴露的那个陷阱：普通二叉搜索树（BST）的查找、插入、删除代价都正比于**树高** h，而 h 在最坏情况下会退化到 n。当你把已经有序的数据（如 1,2,3,…,n）逐个插入一棵普通 BST，每个新键都挂到最右下方，整棵树变成一条只往右伸的「藤」，高度就是 n，所有操作退化成 O(n)——和链表一样慢。

平衡搜索树的核心承诺是：无论插入顺序多么刁钻，都通过额外的结构约束把树高**强制压在 O(log n)**：

h = O(log n)

于是查找/插入/删除稳定在 O(log n) 最坏情况，而不是「平均 O(log n)、最坏 O(n)」。这就是「平衡」二字的全部意义。

对初学者来说，关键是把「BST 的正确性（中序遍历有序）」和「BST 的效率（树高）」分开看：平衡机制**从不改变**元素间的大小顺序（中序遍历始终有序，这条不能破），它只调整树的形状，把「瘦高」的树捏成「矮胖」的树。

### 6.1.2 为什么矮胖的树就快：高度即代价

二叉树里，高度为 h 的树最多能装

n ≤ 2^(h+1) − 1

个结点。反过来，装 n 个结点的树，高度**至少**是 ⌊log₂ n⌋。这是信息论下界：每下降一层最多把候选范围减半，找一个键至少要 log₂ n 次比较。

「平衡」的目标就是让实际高度**尽量贴近**这个下界 log₂ n，而不是放任它涨到 n。所有平衡树的差别，本质只是「用什么规则、花多大常数因子把 h 摁在 c·log₂ n（c 是个小常数）」。理解了这一点，后面 AVL 的 1.44、红黑树的 2 就都只是「那个常数 c 是多少」的问题。

### 6.1.3 两大机制家族：旋转 vs 结点重构

维持平衡的手段可归为两大家族，本大主题各占一半：

第一类是**旋转（rotation）** ——保持二叉结构不变，只在局部重新连接父子指针，把偏重的一侧「转」上来。AVL 树（6.2）、红黑树（6.3）、左倾红黑树（6.4）都属于这一类。旋转是 O(1) 的局部操作：只改动常数条指针，不搬动整棵子树。

第二类是**改变结点容量与结点数**：允许一个结点装多个键（2 个、3 个乃至 2t−1 个），插入使某结点「撑满」时就**分裂**，删除使某结点「太空」时就**合并/借键**。2-3 树、2-3-4 树、B 树（6.5）属于这一类。它天生保证**所有叶子在同一层**，因此完美平衡。

一个贯穿全章的桥梁：**2-3-4 树与红黑树一一对应，2-3 树与左倾红黑树一一对应**。也就是说，第二类的「多键结点分裂」可以被第二类的低阶特例翻译成第一类的「红黑二叉 + 旋转变色」。这条对应关系是理解红黑树「为什么这样设计」的钥匙（在 6.4 展开）。

## 6.2 AVL 树与旋转 — 高度平衡、单/双旋转

### 6.2.1 AVL 的平衡不变式：平衡因子 ∈ {−1,0,+1}

AVL 树（Adelson-Velsky 与 Landis，1962，最早的自平衡 BST）在普通 BST 上加一条**高度平衡不变式**：任一结点的左右子树高度之差不超过 1。定义结点的**平衡因子**（balance factor）为

BF(x) = height(x.left) − height(x.right)

AVL 要求每个结点始终满足

BF(x) ∈ {−1, 0, +1}

只要有一个结点的平衡因子跑到 ±2，就说这个结点「失衡」，必须立刻旋转修复。

这是一条**很严**的不变式——它逐结点、逐层地卡死左右高度差。严带来的好处是树非常矮（见 6.2.3 的 1.44 常数，比红黑树的 2 更好），代价是插入/删除后可能要做旋转来维持，且每个结点要额外存高度（或平衡因子）。

平衡因子比的是**子树高度**，不是子树的**结点个数**。左边 3 个结点、右边 3 个结点也可能高度差 2 而失衡；反之左边 7 个、右边 3 个却可能都高度 2 而平衡。AVL 管的是「高度差」，不是「结点数差」。

### 6.2.2 旋转：LL / RR / LR / RL 四种情形

插入一个新结点后，从它到根回溯，第一个失衡（BF=±2）的结点记为 z。失衡形态由「z 到新结点的前两步方向」决定，共四种：

- **LL**（左-左）：新结点插在 z 的左孩子的左子树。对 z 做一次**右旋**。
- **RR**（右-右）：插在 z 的右孩子的右子树。对 z 做一次**左旋**。
- **LR**（左-右）：插在 z 的左孩子的右子树。先对 z.left 左旋、再对 z 右旋（**双旋**）。
- **RL**（右-左）：插在 z 的右孩子的左子树。先对 z.right 右旋、再对 z 左旋（**双旋**）。

旋转本身是 O(1) 的指针重接。以左旋为例，把 x 的右孩子 y 提上来当根、x 变成 y 的左孩子、y 原来的左子树 T2 挂回 x 的右边：

```
    x                y
   / \             /   \
  T1  y    左旋→   x    T3
     / \         / \
    T2 T3       T1 T2
```

用 Python 表示这个纯指针操作（示意，非完整 AVL 实现）：

```python
def rotate_left(x):
    y = x.right
    x.right = y.left      # y 的左子树 T2 挂到 x 右边
    y.left = x            # x 成为 y 的左孩子
    return y              # y 是新的子树根，交给上层重新挂接
```

**旋转不破坏中序顺序**。上图中无论怎么转，中序遍历都是 T1 < x < T2 < y < T3。所以旋转只改形状、不改 BST 的正确性——这是所有旋转型平衡树都依赖的基石。

单旋（LL/RR）对应「直线型」失衡，双旋（LR/RL）对应「拐弯型」失衡。为什么拐弯型不能一次旋转搞定？因为直接旋一次会把树转成另一边的拐弯，仍然失衡；必须先把内侧那棵「拐」的子树先转直，再整体转上来。初学者可先记「插入路径连成直线就单旋、拐了弯就双旋」。

### 6.2.3 AVL 的高度界与 Fibonacci 关系

AVL 到底有多矮？反过来问：高度为 h 的 AVL 树**最少**要装多少结点？设这个最小值为 N(h)。一棵高度 h 的最瘦 AVL，其两棵子树必然一棵高 h−1、另一棵高 h−2（相差 1，压到极限），于是

N(h) = N(h−1) + N(h−2) + 1

这正是（错位的）Fibonacci 递推。本机用 sympy 核对（Python 3.11.15, Linux 6.18.5 x86_64），确认

N(h) = F(h+3) − 1

其中 F 为标准 Fibonacci（F(0)=0, F(1)=1）。真实输出：

```
h : N_min(h) : F(h+3)-1
0 1 1 OK
1 2 2 OK
2 4 4 OK
3 7 7 OK
4 12 12 OK
5 20 20 OK
6 33 33 OK
```

因为 Fibonacci 以黄金比 φ=(1+√5)/2 指数增长，N(h) 约为 φ^h 量级，反解得高度界

h ≤ (1 / log₂ φ) · log₂(n+2) ≈ 1.4404 · log₂(n+2)

本机核对 1/log₂φ = 1.4404200904125566。也就是说 AVL 高度最多约为最优高度 log₂n 的 1.44 倍——比红黑树的 2 倍更紧，查找更快；但它维持这条严不变式的代价，是删除时最坏可能沿路做 O(log n) 次旋转（插入至多 1 次旋转即可恢复）。

### 6.2.4 AVL 在 CLRS 4th 的章节归属【待核】

## 6.3 红黑树 — 五性质、插入/删除的旋转 + 变色修复

### 6.3.1 红黑树的五条性质

红黑树是一棵每个结点额外带一个**颜色位（红/黑）**的 BST。CLRS 4th §13.1 给出五条性质，它们联合起来保证树高 O(log n)：

1. 每个结点或红或黑。
2. 根结点是黑色。
3. 每个叶子（NIL 空哨兵）是黑色。
4. 若一个结点是红色，则它的两个孩子都是黑色（即**不存在两个连续的红结点**）。
5. 对每个结点，从它到其所有后代叶子的每条简单路径上，**黑结点数目相同**。

性质 5 里「从某结点到叶子路径上的黑结点数」称为该结点的**黑高**（black-height）bh(x)。

初学者不必死背五条，抓两条核心即可：**性质 4「红不连红」**限制了红结点不能扎堆，**性质 5「黑高一致」**保证各条根到叶路径长度不会相差太多。这两条一夹，树就不可能一边特别长。

### 6.3.2 黑高与 2 lg(n+1) 高度界

红黑树为什么矮？因为性质 5 保证每条根到叶路径上**黑结点数相同**（都等于根的黑高 bh(root)），而性质 4 保证红结点不能连续、所以任一路径上红结点数不超过黑结点数。于是最长路径至多是最短路径的 2 倍。CLRS Lemma 13.1 给出精确界：一棵有 n 个内部结点的红黑树，高度满足

h ≤ 2 · log₂(n + 1)

对比 AVL 的 1.44 log₂n：红黑树的常数 2 更松，因此树可能略高、查找略慢；但它换来的是**插入/删除时旋转次数更少**（红黑树插入至多 2 次旋转、删除至多 3 次旋转即可恢复，其余靠变色），维护更便宜。这是「查询密集 → 偏 AVL、增删密集 → 偏红黑」的经典取舍，也解释了为什么工业界的有序 map（如 C++ `std::map`、Java `TreeMap`、Linux 内核）大多选红黑树。

### 6.3.3 插入修复：变色为主、旋转为辅

新结点一律先**染红**挂到 BST 该在的位置。染红是为了不破坏性质 5（黑高不变）；但可能破坏性质 4（若父结点也是红，就红红相连）。修复分情形，取决于**叔叔结点（uncle，父的兄弟）的颜色**：

- **叔叔是红色**：把父与叔都变黑、祖父变红，然后把「问题」上移到祖父，继续向上检查（纯变色，不旋转）。
- **叔叔是黑色（或不存在）**：靠旋转 + 变色把局部转正，之后不再上移。

变色是「把红红冲突往树根方向推」，一路推到根为止（根最后强制染黑，可能使整树黑高 +1）；只有当变色推不动时才动用旋转。因为大多数情况靠变色解决、旋转是少数，红黑树的插入总旋转次数才被压到常数级。按 v3 要求这里只给直觉，完整的三情形正确性证明归专家纵深，不展开。

### 6.3.4 删除修复：双黑的直觉

删除比插入麻烦，因为删掉一个黑结点会使经过它的路径黑高 −1，破坏性质 5。红黑树用一个「**双黑**（doubly black）」的记账技巧：被删黑结点的位置暂时背上「额外一重黑」，然后通过向兄弟「借黑」（旋转 + 变色）或把这重额外黑向上传递，直到这重黑能被某个红结点吸收（染黑）或到达根被丢弃。

知道「删除靠双黑记账 + 借/传，把黑高缺口补平」即可，不必背四种删除情形。完整情形分析同样归专家纵深。

## 6.4 左倾红黑树 LLRB — 与 2-3 树的对应、简化实现

### 6.4.1 先看 2-3 树：完美平衡的多键树

要讲清 LLRB，得先有 2-3 树。2-3 树的每个内部结点是**2-结点**（1 个键、2 个孩子）或**3-结点**（2 个键、3 个孩子），且**所有叶子严格在同一层**——天生完美平衡。

它怎么维持平衡？插入时**从不往下新增层**，而是把键塞进已有的叶结点：2-结点塞成 3-结点即可；3-结点再塞会「撑爆」成临时 4-结点，于是把中间键**向上挤**到父结点，自己分裂成两个 2-结点。这个「撑满→中键上挤」的动作一路向上，只有当根被挤爆时整棵树才升高一层——所以所有叶子始终齐平。这正是 6.1.3 说的「结点分裂」家族，也是 B 树（6.5）的二叉特例。

### 6.4.2 LLRB 的不变式与 2-3 树的一一对应

2-3 树概念优雅但直接实现要处理 2-结点/3-结点两种形态，代码繁琐。Sedgewick 的**左倾红黑树**（LLRB）用一棵普通 BST 加红/黑**链**（把颜色记在「指向孩子的链」上）来编码 2-3 树：

- **3-结点** = 两个 2-结点用一条**红链**连接，且红链**一律左倾**（红孩子必须是左孩子）。
- **2-结点** = 普通黑链连接的单结点。

由此 CS61B 给出 LLRB 的三条不变式：

1. 红链一律左倾（不存在右红链）。
2. 没有任何结点同时连着两条红链（对应「4-结点会被立刻分裂」）。
3. **完美黑平衡**：从根到每个空链，路径上黑链数目相同。

这三条与 2-3 树是**一一对应**的：每棵 LLRB 唯一对应一棵 2-3 树，反之亦然。于是 LLRB 的插入就是「模拟 2-3 树插入」，用三个 O(1) 操作组合完成：`rotateLeft`（把右倾红链扶正为左倾）、`rotateRight`、`colorFlip`（把两条子红链翻成一条上红链，模拟 4-结点向上分裂）。

### 6.4.3 LLRB 为何比经典红黑树好写

经典红黑树（6.3）允许红链左倾或右倾，插入/删除要分很多镜像情形；LLRB 硬加一条「红链只准左倾」的约束，把镜像情形砍掉一半，插入可以写成一个简洁的递归：先照普通 BST 插入，回溯时依次判断「右红则左旋、左红且左左红则右旋、两子皆红则 colorFlip」。这就是 CS61B 主推 LLRB 的原因——**教学上比经典红黑树好实现好证**。

LLRB **不是**任意红黑树，而是红黑树中「红链全部左倾」的那个受限子集。所以同一份数据，经典红黑树（对应 2-3-4 树）和 LLRB（对应 2-3 树）会长成不同形状、不变式也不同。CLRS 讲的是前者，CS61B/Sedgewick 讲的是后者，初学者不要把两套不变式混用。

#### 来源与时效
- 锚点：CS61B sp24「2-3 Trees / LLRBs」讲次——2-3 树完美平衡与插入分裂、LLRB 三不变式、与 2-3 树一一对应、rotateLeft/rotateRight/colorFlip（核实 2026-07-26）。
- 锚点：Sedgewick & Wayne《Algorithms》4th ed §3.3 Balanced Search Trees——LLRB 一手定义与「红链左倾」约束（核实 2026-07-26）。
- 锚点：CLRS 4th §13（经典红黑树）作对照源，用于点明 LLRB 是其受限子集（核实 2026-07-26）。
- 冲突：**LLRB 不变式 ≠ 经典红黑树不变式**。LLRB 额外要求「红链左倾」，对应 2-3 树；经典红黑树无此约束、对应 2-3-4 树。两者是不同结构，本报告分账说明，不混用。

## 6.5 B 树 / B+ 树 — 多路平衡、分裂/合并、阶与高度

### 6.5.1 多路平衡搜索树与最小度数 t

B 树（Bayer & McCreight，1972）把 2-3 树的思想推到高扇出：每个结点可以装**很多个键**、有**很多个孩子**。CLRS 4th Ch18 用**最小度数**（minimum degree）t ≥ 2 刻画一棵 B 树：

- 除根外，每个结点至少有 t−1 个键（即至少 t 个孩子）。
- 每个结点至多有 2t−1 个键（即至多 2t 个孩子）。
- 所有叶子在同一层（完美平衡）。
- 根若非空，至少有 1 个键。

一个有 k 个键的结点，其 k+1 个孩子把键域切成 k+1 段，第 i 个孩子子树里的所有键都落在第 i−1 个和第 i 个键之间——这就是「多路 BST」：从二叉的「小于/大于」推广到「落在哪一段」。

t 越大，结点越「胖」、扇出越大、树越**矮**。当 t=2 时每个结点 1~3 个键、2~4 个孩子，这正是 **2-3-4 树**；再限制到 1~2 个键就是 2-3 树。所以 2-3 树、2-3-4 树都是 B 树的低阶特例——这条线把 6.4 和 6.5 缝在一起。

### 6.5.2 阶与高度的关系

B 树为什么在磁盘/大数据场景称王？因为它极矮。CLRS Theorem 18.1：一棵含 n 个键、最小度数 t 的 B 树，高度满足

h ≤ log_t((n + 1) / 2)

因为底数是 t（可以取几百上千）而非 2，log_t n 比 log₂ n 小一个 log₂t 因子。直观后果：几百万个键的 B 树高度往往只有 3~4，查一个键只需 3~4 次「读一个结点」——在磁盘上就是 3~4 次 IO。这就是数据库索引、文件系统偏爱 B 树/B+ 树的根本原因（工程化深挖归 L4-03/L6-04）。

CLRS 用「最小度数 t」；而 Knuth 及很多教材用「**阶（order）m**」，通常指**每个结点最多的孩子数**（即 m = 2t）。两套记法都对，但「阶 m」在不同书里有时指最大孩子数、有时指最大键数，读题时务必先确认定义，别把 t 和 m 直接代入对方公式。本报告以 CLRS 的 t 为准。

### 6.5.3 分裂与合并：插入/删除如何维持平衡

B 树维持平衡靠**分裂/合并**，不靠旋转：

插入永远发生在叶子。B 树采用**主动分裂**（split）策略下降：沿查找路径往下走时，一旦遇到已满（2t−1 个键）的结点，就先把它按**中位键**分裂成两个各含 t−1 个键的结点、中位键升入父结点，再继续下降。这样保证要插入的叶子一定不满、能直接容纳新键。分裂可能连锁上传，直到根——根分裂时整树升高一层，这也是 B 树**唯一**长高的方式，因此所有叶子永远齐平。

删除相反：若某结点键数掉到 t−1 以下（下溢），就向兄弟**借键**（旋转式地经父结点转移一个键），或与兄弟**合并**（把父里的分隔键拉下来、两结点并一个）。合并可能使父下溢、连锁上传，根被合空时整树降低一层。

**插入靠分裂、删除靠借/并，长高长矮都只发生在根**——这就是完美平衡的来源。

### 6.5.4 B+ 树与 B 树的区别（内存版直觉）

B+ 树是 B 树的常用变体，两点差别：

- **数据只放叶子**：B 树的内部结点也存卫星数据（值），B+ 树的内部结点**只存路由用的键**、所有真实数据/值都在叶子层；内部结点因此更「瘦」、扇出更大、树更矮。
- **叶子串成链表**：B+ 树把所有叶子按序用指针连成一条链，**范围扫描**（如「找出所有 10~50 的键」）只需定位到起点叶子、再顺链扫，不必反复回溯内部结点。

B 树适合「点查为主、值可能在任意层」；B+ 树适合「点查 + 大量范围/顺序扫描」，几乎所有关系数据库和文件系统索引用的是 B+ 树。为什么范围查询是 B+ 树杀手锏、磁盘页如何映射结点、并发与日志如何做，属于存储引擎工程化，深挖归 L4-03（数据库）/L6-04，本报告只到「结构与代价直觉」为止。
