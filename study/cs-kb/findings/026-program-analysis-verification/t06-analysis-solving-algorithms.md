**一份静态分析做完两件事——先"写方程"（V2 数据流的 Analysis 方程 / V3 的 ⊆ 约束 / V4 抽象域上的方程），再"解方程"。V6 讲的就是"解"这一半：把所有这些方程看成同一种东西——每个程序点挂一个未知量，未知量取值于一个格，彼此由单调函数关联；解法永远是"从最小猜测（⊥）出发，反复用方程把信息往上推，推到不再变化（不动点）为止"。worklist 算法就是这台迭代引擎的高效实现：它不傻乎乎地每轮重算所有点，而是维护一张"待办清单"，只重算那些"上游刚变过、可能受影响"的点。** 关键的安心感来自序理论：因为格满足升链条件（不能无限往上升）、传递函数单调（输入变大输出不变小），这个"只升不降"的迭代必然停在最小不动点上——它就是我们要的 MFP 解。

## V6.1 worklist 算法：通用不动点迭代引擎

### V6.1.1 worklist 要解的是什么：一个单调方程/约束系统的最小不动点

worklist 算法是一台**通用求解器**：输入是一组互相依赖的方程（或约束），每个未知量取值于一个满足升链条件的完全格 L，方程右边是单调函数；输出是这组方程的**最小解**，也就是最小不动点。V2 的四大经典数据流分析、V3 的集合约束、V4 抽象域上的分析，在"求解"这一步全都长成同一副样子，因此可以共用这一台引擎。

在 PPA 的记法里，数据流分析被写成对每个标号 ℓ 的一对方程（这里 ⊔ 是格的最小上界，may 分析取并、must 分析取交；F 是控制流 flow 或其反向 flow^R；E 是入口/出口的极值标号集，ι 是极值初值）：

Analysis_∘(ℓ) = ⊔ { Analysis_•(ℓ') | (ℓ', ℓ) ∈ F }   （当 ℓ ∉ E）

Analysis_∘(ℓ) = ι   （当 ℓ ∈ E）

Analysis_•(ℓ) = f_ℓ( Analysis_∘(ℓ) )

其中 f_ℓ 是标号 ℓ 处基本块的传递函数。求解目标就是找到满足全部这些等式、且逐点最小的一族 (Analysis_∘, Analysis_•)。

对初学者，先把"方程系统"这个词去神秘化。它不是中学的一元二次方程，而是一堆"这个点的信息 = 它所有前驱点信息汇合后、再过一遍本块的传递函数"的相互约束。因为一个点的答案依赖别的点、别的点又反过来依赖它（尤其有循环时会成环），没法一次算清，只能反复迭代逼近。

为什么要的是**最小**不动点而不是随便一个不动点？因为分析要 sound（V1.3 的过近似世界观）而又尽量精确：最大的不动点往往是"什么都可能"这种平凡而无用的解，最小不动点才是"在保证不漏的前提下、信息最紧"的那个。从 ⊥（最小元、"目前一无所知"）出发往上迭代，天然停在最小不动点上——这正是 worklist 的起点设计。

这里的"最小"是按格的偏序 ⊑ 说的，不是数值最小。对活跃变量分析（格是变量集合的幂集、⊔ 取并、⊑ 就是 ⊆），最小不动点意味着"每个点算出的活跃变量集合尽可能小、但不漏掉任何真会活跃的变量"。

### V6.1.2 worklist 算法的三步骨架与伪码

worklist 算法维护两样东西：一个数组 Analysis[ℓ] 存每个标号当前的分析结果；一张工作表 W，装着一批"边"(ℓ, ℓ')，含义是"ℓ 的结果刚变过，所以依赖它的 ℓ' 需要重新计算"。算法分初始化、迭代、出结果三步，迭代到 W 空为止。以下是 PPA §2.4 给出的原版伪码（⊑ 为格偏序，⊔ 为最小上界，⊥_L 为格底，f_ℓ 为传递函数，F 为流关系）：

Step 1  初始化（W 与 Analysis）

W := nil;

for all (ℓ, ℓ') in F do  W := cons((ℓ, ℓ'), W);

for all ℓ in F or E do

　if ℓ ∈ E then Analysis[ℓ] := ι  else Analysis[ℓ] := ⊥_L;

Step 2  迭代（更新 W 与 Analysis）

while W ≠ nil do

　ℓ := fst(head(W));  ℓ' := snd(head(W));  W := tail(W);

　if f_ℓ(Analysis[ℓ]) ⋢ Analysis[ℓ'] then

　　Analysis[ℓ'] := Analysis[ℓ'] ⊔ f_ℓ(Analysis[ℓ]);

　　for all ℓ'' with (ℓ', ℓ'') in F do  W := cons((ℓ', ℓ''), W);

Step 3  出结果（MFP_∘ 与 MFP_•）

for all ℓ in F or E do

　MFP_∘(ℓ) := Analysis[ℓ];

　MFP_•(ℓ) := f_ℓ(Analysis[ℓ]);

对初学者，把它想成"传闻扩散"。每个程序点是一个人，手上有一份当前掌握的信息（Analysis[ℓ]）。W 是一张"谁需要被通知"的便条堆。取一条便条 (ℓ, ℓ')，意思是"ℓ 有新消息，去更新 ℓ'"。更新时把 ℓ 经过传递函数 f_ℓ 后的信息，⊔ 进 ℓ' 已有的信息里。若 ℓ' 的信息真的因此变大了（那句 if 判断 f_ℓ(Analysis[ℓ]) ⋢ Analysis[ℓ']，即"新消息不被旧信息覆盖"），就说明 ℓ' 有了新消息，于是把 ℓ' 的所有下游便条 (ℓ', ℓ'') 再塞回 W。没人再有新消息（W 空）时，扩散停止，此时人人手上的信息就是不动点。

三个必须抓住的要点。其一，那句 if 是效率关键：**只有信息真的变化了才把下游加回 W**，否则白算一遍、还可能死循环。其二，更新用的是 ⊔（取上界）而非直接赋值，这保证 Analysis[ℓ'] 单调只升不降，是终止性的基础。其三，初值除极值点设为 ι 外，其余一律设 ⊥_L（"最保守的空信息"），从最小处起步才能收敛到最小不动点。

W 里放的是"边"而不是"点"。放边是为了精确知道"是哪条依赖关系触发的重算"，实现上也可以放点（把某点标记为 dirty），龙书 §9.3 的经典版本就是"把改变了的基本块放进 worklist"。两种写法等价，差别只在便条的粒度。

### V6.1.3 终止性与正确性：算出的正是最小(MFP)解

PPA 给出定理：worklist 算法**总会终止**，并且算出的是输入实例的**最小解（即 MFP，Maximal Fixed Point 的历史叫法，实际是 least fixed point 最小不动点）**。终止性靠两条：格 L 满足升链条件（任何只升不降的链必在有限步后稳定），且每次有效更新都严格抬高某个 Analysis[ℓ]，所以有效更新的总次数有限。

对初学者，"MFP" 这个缩写极易望文生义，务必留意 PPA 的原话——它写作 "Maximal Fixed Point" 是沿用历史术语，但按现代序理论它其实是**最小**不动点（从 ⊥ 往上爬到的第一个不动点）。之所以历史上叫 "maximal"，是因为早期文献把格的方向画反了。记结论即可：worklist 算出的解是"在所有满足方程的解里、信息最紧（最小）的那个"。

为什么"从 ⊥ 往上、单调、ACC"就必然停在最小不动点？直觉是：迭代序列 ⊥ ⊑ F(⊥) ⊑ F²(⊥) ⊑ … 是一条不降链（F 单调保证每步不倒退），ACC 保证它不能无限升、必在某步 k 稳定于 F^k(⊥)，稳定点即不动点；而 Kleene 不动点定理告诉我们，从 ⊥ 出发得到的正是**最小**不动点。这也解释了 V4 为何要引入 widening：当格无穷高（如区间分析）、ACC 不成立时，这条链可能永不稳定，widening 人为地"加速跳到上界"以强制终止，代价是牺牲精度。

一个关键辨析（回收 V2.4）：worklist 算出的 MFP 与 MOP（meet/join-over-all-paths，沿所有路径分别算再汇合的理想解）在一般单调框架下满足 MFP ⊒ MOP，即 MFP 是对 MOP 的 sound 过近似；仅当框架**可分配**（f(x ⊔ y) = f(x) ⊔ f(y)，如所有位向量分析）时二者相等。而 MOP 本身通常**不可计算**（PPA 证明可归约到不可判定的 Modified Post Correspondence Problem），MFP 却因 ACC 总可计算——这正是我们退而求其解 MFP、并用 worklist 去算它的根本理由。

## V6.2 方程/约束系统求解：chaotic iteration 与迭代序

### V6.2.1 chaotic iteration：任意公平顺序都收敛到同一最小解

chaotic iteration（混沌迭代）指的是这样一类求解策略：**每一步任选一个（尚未稳定的）方程来更新，只要保证每个方程被无限次公平地选到，最终都收敛到同一个最小不动点。** worklist 算法就是 chaotic iteration 的一种带调度的高效实现——"待办清单"只是决定"下一个更新哪个方程"的具体策略而已。

对初学者，"混沌"不是"混乱到出错"，而是"顺序自由"。核心洞见是：因为传递函数单调、更新用 ⊔ 只升不降，谁先谁后都不会把已经推上去的信息推回来，也不会漏掉任何该传播的信息（公平性保证每条依赖迟早被处理）。于是**最终答案与顺序无关**——这是 chaotic iteration 最漂亮也最实用的性质：它把"正确性"和"效率"彻底解耦，你可以放心地为速度任意调度，而不必担心调错顺序会算错。

一个最小例子帮助体会。设两个方程

x ⊒ f(y)

y ⊒ g(x)

从 x = y = ⊥ 出发。先更新 x 还是先更新 y，或者交替更新，路径不同，但只要都反复更新到不再变化，落点是同一个最小 (x, y)。区别只在中间走了几步。

易错点有二。其一，"顺序无关"仅指**最终解**，不指**收敛步数**——顺序对快慢影响极大（见 V6.2.2）。其二，公平性是前提：若某个方程永远不被选中，就可能停在一个"假不动点"上；worklist 用"变化即把下游加回表"来自动保证公平——只要还有点没稳定，就一定还有便条待处理。

chaotic iteration 一词的正式出处是抽象解释奠基作 Cousot & Cousot（POPL'77）：他们用它作为在抽象域上逼近最小不动点的通用迭代范式，worklist、round-robin 都可视为它的特例。

### V6.2.2 迭代序影响收敛速度：round-robin、逆后序、栈 vs 队列

迭代顺序（iteration order）不改变最终解，但对**需要迭代多少轮/多少次基本运算**影响巨大。两大类顺序：**round-robin（轮询）**——固定一个节点线性次序，一遍遍扫过所有节点直到某一整遍无任何变化；**worklist（工作表驱动）**——只处理"待办"节点，用某种数据结构决定取出次序。经验与理论都表明，选对次序能把迭代轮数从"与程序规模同阶"压到"与循环嵌套深度同阶"。

对初学者，为什么顺序影响这么大？想象信息要从循环入口一路传播到循环体深处再绕回来。若你恰好**逆着信息流动的方向**去更新节点，每一遍只能往前推进一格，信息像挤牙膏；若你**顺着信息自然流动的方向**更新，一遍就能把信息推很远。所以对前向分析（信息沿控制流正向流），最优的线性次序是**逆后序（reverse postorder）**——它保证"尽量先处理前驱、后处理后继"，即祖先优先；对后向分析则用后序（postorder）。逆后序的算法定义是：对 CFG 做深度优先遍历得到后序编号，再取 (|N|+1) − 后序号 作为处理次序。

worklist 的数据结构选择也体现同一直觉。用**栈（LIFO）**取出，倾向深度优先地把信息一路推到底（对处理循环体较友好）；用**队列（FIFO）**取出，倾向广度优先地一层层推进；更讲究的实现用**优先队列**按逆后序号排序节点，或先把 CFG 分解成强连通分量（SCC）、在 SCC 的 DAG 上按拓扑序处理、每个 SCC 内部再局部迭代到稳定（Bourdoncle 的 weak topological order 即此思想）。

这些都是**性能工程**，不影响正确性。初学者实现时可以先用最朴素的"队列 + 有变化就把后继入队"，跑对了再谈优化次序。龙书也明确指出：worklist 算法通常显著快于朴素 round-robin，因为它省掉了"一整遍里大量根本没变的节点"的无谓重算。

### V6.2.3 收敛步数界：loop-connectedness d 与 d+2 / d+3 遍（冲突项）

对**位向量/rapid 框架**（如到达定值、活跃变量等可分配分析），若按逆后序做 round-robin 迭代，收敛所需的遍数与程序规模几乎无关，而只取决于控制流图的**回边深度**——即 loop-connectedness d(G)：任一无环路径上最多含多少条回边（直觉上就是循环的最大嵌套深度）。经验规律是现实程序里 d 极少超过 3，所以这类分析实践中只需常数遍就收敛。

对初学者，先建立"回边=循环"的图像。CFG 里指回祖先的边就是回边，一层循环贡献一条回边，嵌套三层循环的路径上就可能串起三条回边。d 就是这个"最深要穿过几层循环"的数。为什么信息传播遍数和它挂钩？因为每绕一圈循环、信息才能沿回边多渗透一层，穿过 d 层就需要约 d 轮，外加固定的常数遍（首遍铺开 + 末遍确认无变化）。

这里有一个必须显式标注的**来源冲突**（系数取值分歧）：
- 龙书 2nd ed §9.6.7 的表述是"不超过 **d+2** 遍"（对逆后序 round-robin、reducible 图上的常见位向量问题；其中把'检测到某遍无变化'的确认遍算在内）。
- Kam & Ullman（JACM 1976）及部分文献的表述是 **d(G, D)+3** 遍（对 rapid 框架、按某 DFS 树 D 的逆后序）。

二者差在"+2 还是 +3"，根源是**计数约定不同**（是否把初始化遍、以及那"最后一遍确认无变化"分别计入）以及框架条件（bit-vector 可分配 vs 一般 rapid）的细微差别，并非某方算错。教辅结论取其共识部分即可：**收敛遍数是 d 加一个小常数（2 或 3），与程序规模无关，实践中 d 很小故很快**。需要精确系数时，须回到你所用的具体定义（是否含确认遍、框架是否 rapid）逐案确定，不可凭记忆填。

这套"d + 常数遍"的乐观界只对 **reducible（可归约）** 控制流图和 **rapid/位向量** 框架成立。对不可归约图或非分配框架（如常量传播），界会退化，一般只能回到 worklist 的通用复杂度 O(e·h)（见 V6.3.2）来估。

## V6.3 算法共性与复杂度：同一台引擎与它的代价

### V6.3.1 统一骨架：V2–V5 都归约到"格 + 单调函数 + 迭代到最小不动点"

前面所有分析——V2 数据流、V3 约束式（CFA/0-CFA）、V4 抽象解释、V5 类型与效果系统的推断——在**求解层**其实是同一件事。把它们各自的"分析域"抽象成一个满足 ACC 的完全格 L，把"每条程序结构如何影响信息"抽象成一族单调函数，把整份分析写成"每个未知量 ⊒ 某个单调表达式"的约束/方程系统，然后就都交给同一台 worklist 引擎迭代到最小不动点。差别只在"格是什么、传递函数是什么、约束怎么生成"，求解骨架完全共享。

对初学者，这就是本课"抽象解释是统一框架"论断（V4.4）在算法上的兑现。你学一次 worklist，就等于学会了解所有这些分析——换分析只需换三样输入：(1) 格 L（活跃变量用集合幂集、区间分析用区间格、常量传播用 Z 加顶底、CFA 用 lambda 集合幂集）；(2) 传递函数 f_ℓ；(3) 约束/流关系。引擎一字不改。

V3 的集合约束"求最小解"本质是在幂集格上求最小不动点，其"图闭包/条件约束触发"求解法，正是 worklist 在"约束依赖图"上的另一种外衣——某个变量的解变大，就把依赖它的约束重新入表。所以 V3 的求解器和 V2 的 worklist 是同一台机器的两个皮肤。这也呼应了另一支求解传统：把分析写成 **Datalog** 规则、交给 Datalog 引擎做半朴素求值（semi-naïve evaluation），其"只对新导出的元组重新触发规则"正是 worklist 的声明式版本（现代指针分析如 Doop 即走此路）。

### V6.3.2 通用复杂度界 O(e·h) 与位向量特例 O(b²)

PPA 给出 worklist 算法的通用复杂度界。设方程系统里最多有 b 个不同标号、流关系 F 最多含 e 条边（e ≥ b）、格 L 的有限高度至多 h（h ≥ 1），把"应用一次传递函数 f_ℓ、做一次 ⊔、或更新一次 Analysis"计为基本运算，则总基本运算数至多

O(e · h)

对位向量分析的特例（如到达定值，假设标号唯一），有 O(h) = O(b) 且 O(e) = O(b)，代入得

O(b²)   （b 为程序规模）

对初学者，这个界的两个因子各有直观含义。**h（格高度）**是"任一未知量最多能被抬高几次"——因为更新只升不降、且格高度有限，每个点的信息最多变 h 次。**e（边数）**是"每次某点变化，最多触发多少条下游依赖重算"。两者相乘就是总工作量上界。所以想让分析快，要么压低格高度（用更粗的抽象域，牺牲精度换速度），要么减少依赖边（更稀疏的流图）。

为什么位向量分析特别快（O(b²) 且实践中近线性）？因为它的格是有限集合的幂集，高度 h 就是集合大小、约等于程序规模 b；更关键的是它**可分配**（V6.2.3 的 rapid 框架），能用逆后序在 d+常数遍内收敛，实际远优于最坏界。而常量传播这类**非分配**单调框架，只能吃通用 O(e·h) 界，且格更高时更慢——这就是"精度越高、代价越大"在复杂度上的体现。

O(e·h) 是"基本运算次数"，一次基本运算（尤其 ⊔ 和 f_ℓ）本身在大格上可能不是 O(1)。位向量上 ⊔ 是按机器字并/交、近似常数；但在区间、多面体等复杂域上，单次 ⊔ 或 f_ℓ 可能很贵，真实墙钟时间要把"单次运算成本"再乘进去。教辅层面记住"O(e·h) 基本运算 + 单次运算另计"即可。

### V6.3.3 求解算法上的精度—代价旋钮：格高度、分布性、widening

把 V2–V6 串起来看，一份分析的"快慢/精度"由几个可调旋钮共同决定，而这些旋钮恰好都落在求解算法的参数上：格的高度 h（决定迭代次数与最坏复杂度）、传递函数是否**可分配**（决定 worklist 算出的 MFP 是否等于理想的 MOP，即精度是否无损）、以及格是否满足 ACC（决定迭代是否天然终止、还是需要 widening 强行收口）。

对初学者，把这三个旋钮和已学内容对齐就清楚了。分布性旋钮：位向量分析可分配，MFP = MOP，worklist 给的就是最精确解；常量传播不可分配，MFP ⊒ MOP，worklist 会比理想解略保守（V6.1.3、V2.4）。高度旋钮：区间/多面体这类抽象域高度无穷，ACC 失效，V4 的 **widening ▽** 就是在求解循环里人为把上升链"跳"到某个上界以强制终止、随后再用 **narrowing △** 往回收一点精度——它本质是给 worklist 迭代装的"限速+急停"装置。

为什么要显式讲这个？因为它揭示 V6 不是孤立的"算法课"，而是 V2–V5 全部分析的公共底座：你选择的抽象域和传递函数，一旦确定，就同时决定了"喂给 worklist 的格与函数长什么样"，从而决定了这台通用引擎跑得多快、算得多准、要不要 widening 才能停下来。理解求解算法，才真正理解"为什么某个分析既 sound 又能在有限时间跑完"。

#### 来源与时效（本小主题末集中列）
- PPA §2.4「Solving the Constraints」：worklist 通用复杂度界 O(e·h) 的定义（b/e/h 的含义、基本运算计数）与到达定值特例 O(b²)；MFP=MOP 当且仅当可分配。核实 2026-07-30。
- PPA Ch.4（抽象解释）与 V4 报告：无穷高格上 ACC 失效、widening/narrowing 保证终止并恢复精度，作为 worklist 迭代终止的补充机制。核实 2026-07-30。
- PPA Ch.6「Algorithms」与 V4.4：各类分析归约到"格 + 单调函数 + 约束系统 + 迭代求最小不动点"的统一骨架（抽象解释框架涵盖数据流分析）。核实 2026-07-30。
- 龙书 2nd ed 2006，§9.3：数据流框架三要素（半格 + 传递函数族 + 汇合）与迭代求解，交叉核对"格高度决定收敛、可分配决定精度"的复杂度直觉。核实 2026-07-30。
- 交叉核对（求解范式的另一支，非承重）：Datalog/半朴素求值作为 worklist 的声明式对应（现代指针分析 Doop 等），仅用于说明"同一求解骨架的不同外衣"，未展开。核实 2026-07-30。
- 两主来源一致：复杂度由"格高度 × 依赖边数"主导、可分配框架 MFP=MOP。无冲突。
