## 10.1 按需分页与缺页处理

### 10.1.1 按需分页 (demand paging)

按需分页指：一个页只有在**第一次真正被访问到**时才装入物理内存，而不是在程序启动时把所有页一次性读进来。实现它的关键是页表项（PTE）里的**有效位/存在位**（valid/present bit，见大主题09）：装入了的页 PTE 存在位为 1、指向某个物理帧；没装入的页存在位为 0。CPU 的 MMU 在翻译地址时若发现目标页存在位为 0，就产生一次**缺页异常**（page fault），陷入内核，由内核决定这一页从哪来、装到哪。

把物理内存想成一张小书桌，磁盘上的可执行文件/交换区是身后的大书架。按需分页就是"用到哪一页才从书架取哪一页放到桌上"，而不是开工前把整架书都搬上桌。好处有三——启动快（不用等全部读入）、省内存（从不访问的页永远不占 RAM）、能运行比物理内存更大的程序（虚拟地址空间可远大于 RAM）。代价是每个"第一次访问"都要付一次缺页处理的开销，因此下面几节都在想办法让"贵的那种缺页"尽量少发生。

### 10.1.2 缺页异常的处理时序 (page fault handling flow)

缺页发生后，硬件与内核协作完成一套固定时序。以"合法但页不在内存"的情形（需读盘）为例，块级流程如下：

```
1. CPU 访问某虚拟地址 → MMU 查 PTE，发现存在位=0
2. 触发 page fault，硬件陷入内核：保存出错地址（x86-64 放入 CR2）与错误码（读/写、用户/内核、是否权限问题）
3. 内核缺页处理程序检查该地址是否落在合法的 VMA（虚拟内存区域）里
       └─ 非法（越界/无映射） → 发 SIGSEGV（段错误），进程可能被杀
4. 合法 → 找一个空闲物理帧；若没有空闲帧，运行页替换策略换出一页腾位（见 10.2）
5. 从后备存储读入该页内容（可执行文件 / 交换区 / 文件映射）——这一步是磁盘 I/O，进程在此阻塞
6. 更新 PTE：填入帧号、存在位置 1、设好权限；必要时刷新对应 TLB 项
7. 从"出错的那条指令"重新执行（restart），这次翻译成功、程序无感继续
```

初学者最常见的误解是"缺页 = 出错 = 程序崩溃"。恰恰相反：绝大多数缺页是**正常且预期**的机制事件（步骤 3 判定合法后走 4–7），进程完全无感地继续运行；只有第 3 步判定地址非法时才转成 SIGSEGV 那种"真错误"。另一个要点是步骤 7 的"重执行"——缺页处理不是跳过出错指令，而是补好页后让**同一条指令**再跑一遍，所以对用户程序完全透明。

### 10.1.3 minor fault 与 major fault

缺页按"是否需要磁盘 I/O"分两类。**次缺页**（minor fault，也叫软缺页）指目标页其实已经在物理内存里、只是当前进程的页表还没建立到它的映射——例如页已在页缓存中、或是共享的零页、或另一进程已把同一文件页读入——内核只需填好 PTE 即可，**不读盘**，非常快。**主缺页**（major fault，硬缺页）指目标页不在物理内存、必须从磁盘（交换区或文件）读入，要付一次真实的磁盘 I/O，慢上几个数量级。

在 Linux 上这两个计数是逐进程可见的。`/proc/[pid]/stat` 的第 10 个字段是 `minflt`（本进程累计次缺页）、第 12 个字段是 `majflt`（主缺页）。本机对当前 shell 之下的 Python 进程取样：

```
$ awk '{print "minflt="$10, "majflt="$12}' /proc/self/stat
minflt=136 majflt=0
```

majflt=0、minflt 上百，符合直觉：一个刚起、内存充裕、无 swap 的进程，其缺页几乎全是"建立映射"的次缺页（含下面 10.4 的按需置零/COW），基本不需要读盘。注：本机 GNU `/usr/bin/time -v`（会打印 "Major (requiring I/O) page faults" / "Minor" 两行）**未安装**，故未用它取证，改以 `/proc` 字段佐证；判断一个程序是否被换页拖慢，看的正是它的 majflt 是否在飙升。

### 10.1.4 有效访问时间 (EAT) 与缺页代价

缺页贵在哪，用有效访问时间（Effective Access Time, EAT）量化。设 p 为缺页概率（page fault rate），一次正常内存访问耗时为

EAT = (1 − p) × t_mem + p × t_fault

其中 t_mem 是命中时的内存访问时间、t_fault 是一次缺页的完整服务时间（含陷入、可能的换出、读盘、重执行）。OSTEP Ch22 用平均内存访问时间（AMAT）表达同一件事：

AMAT = T_M + (P_miss × T_D)

T_M 为内存访问成本、T_D 为磁盘访问成本、P_miss 为未命中（缺页）概率。

关键直觉来自两个成本的巨大悬殊：内存访问约几十到上百纳秒，一次机械盘随机读约几毫秒（SSD 约几十到上百微秒），两者差约五到六个数量级。代入公式就能看到：**极小的缺页率也会主导平均时间**。举例，若 t_mem = 100 ns、t_fault = 8 ms = 8,000,000 ns，即使 p 只有 0.001（千分之一访问缺页），EAT ≈ 100×0.999 + 8,000,000×0.001 ≈ 8100 ns，比无缺页时慢约 80 倍。这就是为什么后面所有替换策略、工作集控制的唯一目标都是"把 p 压到极低"——不是让缺页快一点，而是让它尽量别发生。

## 10.2 替换策略

### 10.2.1 替换的目标与命中率/缺页率度量

当发生缺页而没有空闲帧时，内核必须选一个"受害页"（victim）换出，把帧腾给新页——这就是页替换（page replacement）。选谁换出由替换策略决定，好策略让未来的缺页尽量少。衡量一个策略在某段访问序列（reference string）上的表现，用缺页率与命中率：

缺页率 (miss rate) = 缺页次数 / 总访问次数

命中率 (hit rate) = 1 − 缺页率 = 命中次数 / 总访问次数

初学者要建立的框架是"访问序列 + 帧数 + 策略 → 缺页次数"这个三元关系：给定同一串页访问和同样的物理帧数，不同策略跑出的缺页次数不同；同一策略下，帧数一般越多缺页越少（但 FIFO 会违反这条，见 10.2.3）。教材里所有替换策略的比较，本质都是在同一 reference string 上比缺页次数。下面各策略均以"访问一个不在内存的页记一次缺页"为口径。

### 10.2.2 最优替换 OPT (MIN / Belady)

最优替换（OPT，又称 MIN 或 Belady 算法）规则是：换出**未来最久才会被再次用到**（或再也不用）的那个页。它能证明产生的缺页次数最少，是所有策略的理论下界。

但 OPT **不可实现**：它需要预知未来的访问序列，而运行时无法知道。那它有什么用？它是**标尺**——把真实策略（LRU、clock 等）跑出的缺页数和 OPT 比，就知道离最优还差多远。本机模拟中（下节的经典序列、3 帧），OPT 只缺 7 次，而 FIFO 缺 9 次、LRU 缺 10 次，直观展示了"再好的可实现策略也追不上上帝视角"。OPT 的思想还启发了近似：既然真的未来拿不到，就用"最近的过去"去预测未来（这正是 LRU 的立论基础）。

### 10.2.3 FIFO 与 Belady 异常

FIFO（先进先出）换出**最早装入**的页，实现极简单（一个队列即可）。但它有个反直觉的缺陷——**Belady 异常**（Belady's anomaly）：增加物理帧数，缺页次数**反而可能变多**。本机用经典反例序列做数值模拟坐实：

```
reference string: 1,2,3,4,1,2,5,1,2,3,4,5
  帧数=3:  FIFO=9   LRU=10   OPT=7   （缺页次数）
  帧数=4:  FIFO=10  LRU=8    OPT=6
```

看 FIFO 那一列：3 帧时 9 次缺页，给到 4 帧反而涨到 10 次——多给内存却更差，这就是 Belady 异常。

为什么会这样？直觉上"内存越多越好"应当成立，但 FIFO 的淘汰依据（装入时间）和"这页有没有用"完全脱钩：一个刚被访问、马上还要用的页，可能仅仅因为"装得早"就被换出。帧数变化会打乱队列的进出节奏，于是更多帧下的淘汰序列反而更"倒霉"。这说明 FIFO 不满足下一节的"栈性质"。对比 LRU 那一列（10 → 8，帧数增加缺页单调减少）就能看出差别。

### 10.2.4 LRU 与栈算法 (stack algorithm)

LRU（Least Recently Used，最近最少使用）换出**最久没被访问**的页，思想是"最近用过的很可能马上还要用"（时间局部性），用最近的过去近似 OPT 的未来。

LRU 属于**栈算法**（stack algorithm）：它满足包含性质——n 个帧时驻留内存的页集合，一定是 n+1 个帧时驻留集合的子集。栈算法的一个重要好处是**不会出现 Belady 异常**，帧数增加缺页数单调不增（上面模拟里 LRU 从 10 降到 8 正是这一性质）。

LRU 的难点在**精确实现的代价**：要么每次内存访问都更新一个时间戳/计数器（硬件开销大），要么维护一个按访问顺序排列的链表（每次访问都要移动节点）。在每条 load/store 都要动一下的量级上，这个开销无法承受。所以真实系统几乎不用精确 LRU，而是用下面的 clock 等**近似 LRU**。初学者记住这条工程结论即可：LRU 是"理想的可实现目标"，但落地要用近似版。

### 10.2.5 时钟 / 二次机会 (clock / second-chance)

Clock 算法（又叫 second-chance，二次机会）是 LRU 的低成本近似，靠硬件维护的**访问位/引用位**（reference/accessed bit，PTE 里的一个位；见大主题09）工作。所有物理帧排成一个环，一根"时钟指针"绕圈扫描：

```
指针指到某页时，看它的访问位 R：
  R == 1  → 给"第二次机会"：清零 R（R←0），指针前进，不换出它
  R == 0  → 选它作受害页换出；指针停在下一个位置
每次页被访问时，硬件自动把该页 R 置 1
```

可以这样体会这个规则：最近被访问过的页 R=1，扫到时不会立刻被杀，只是被"降级"（清零 R）；若它一直没再被访问，下一圈扫到时 R 仍是 0，就被换出。于是"最近有活动"的页得以留下，效果近似 LRU，但每次访问只需硬件置一个位、无需更新时间戳或移动链表，成本极低。实践中常再加一个"脏位"（dirty/modified bit）做增强版：优先换出"没被改过"的干净页（换出不用写回，更便宜）。这解释了真实 OS 的替换器为何都建立在访问位+脏位之上，而非精确 LRU。

### 10.2.6 工作集近似与 Linux 的多级 LRU 现状

把工作集思想（见 10.3）落进替换策略，经典做法是 **WSClock**：在 clock 环上额外记录每页的"上次使用时间"，扫描时不在工作集窗口内、且干净的页优先换出——等于把"二次机会"和"工作集判定"合到一起。这是教材层面对"如何近似 LRU 又兼顾工作集"的标准答案。

需**规范与实现分账**：真实 Linux 并不用单一的全局 clock 或精确 LRU。Linux 把每个内存区/内存 cgroup 的页维护成两条 LRU 链——**active（活跃）与 inactive（不活跃）**，且**匿名页与文件页各自一套**，靠访问位在两条链间升降级，近似 LRU 而非全局环扫描（⚙演进快，细节随版本变）。更新的 **MGLRU（Multi-Gen LRU，多代 LRU）** 把 LRU 泛化成"多代"，访问过的页往新代移、回收从最老代开始；它在 **Linux 6.1** 合入内核（`CONFIG_LRU_GEN`），但**默认不启用**，需运行时经 `/sys/kernel/mm/lru_gen/enabled` 打开（部分发行版会默认开）。本机 Linux 6.18.5 上 `cat /sys/kernel/mm/lru_gen/enabled` **无此接口**（该内核未编入或未暴露 MGLRU），故本机走的是传统 active/inactive 多级 LRU。教材的 OPT/FIFO/LRU/clock 是理解框架，Linux 实际是"多链近似 + 可选 MGLRU"，两者分开记。

## 10.3 抖动与工作集

### 10.3.1 抖动 (thrashing)

抖动（thrashing）指系统把绝大部分时间花在换页（换入换出）上、几乎没时间执行真正的工作，表现为 CPU 利用率骤降、磁盘狂转、系统近乎卡死。根因是：同时运行的进程所需的活跃页总量超过了物理内存，于是每个进程刚换回一页、马上又因缺另一页而把别人的页挤出去，大家互相拆台，缺页率飙到接近 100%。

当抖动发生时，如果调度器看到"CPU 利用率低"就以为"还能多跑几个进程"而**提高多道程序度**，会让内存更紧张、抖动更严重——利用率不升反降。这个正反馈是理解为什么需要"工作集"来主动限制并发进程数的动机。初学者可类比：书桌太小，你同时摊开五本书，结果每翻一本都要先把另一本收回书架再取回来，一整天都在搬书没读几页。

### 10.3.2 工作集模型 (working-set model)

Denning 的工作集模型用"最近一段访问历史"来估计一个进程当前真正需要多少页。定义工作集窗口 Δ（最近 Δ 次访问），则在时刻 t 的工作集为

W(t, Δ) = { 在最近 Δ 次内存访问中被引用过的页的集合 }

工作集大小 WSS = |W(t, Δ)|，即这段窗口里用到的**不同页数**。它随程序执行阶段变化（进入新阶段时会短暂变大）。把所有进程的工作集大小加起来，若超过可用物理帧数，就会抖动：

Σ WSS_i > 可用物理帧数  ⟹  抖动

于是防抖动的策略变成：内核给每个进程分配约等于其 WSS 的帧数；当帧不够满足所有工作集时，**主动挂起（换出整个）某些进程**、降低多道程序度，而不是让大家一起抖。

工作集就是"当前这个执行阶段真正在用的那撮页"。窗口 Δ 选得好，WSS 能相当准地反映需求——太小会漏掉刚要用的页，太大会把早已不用的页也算进来。工作集不是要精确算出，而是给内核一个"该给这个进程多少内存、能不能再塞进一个进程"的判断依据。

### 10.3.3 缺页频率 (PFF) 控制

直接实现工作集（精确追踪窗口内的页集合）开销大，实践中常用一个更简单的等价手段——**缺页频率控制**（Page-Fault Frequency, PFF）：不去算工作集，而是直接盯住每个进程的缺页率，用它反馈调节帧数。

规则很朴素：给缺页率设上下阈值。某进程缺页率**高于上限**，说明它帧不够、正在挨饿，就多分给它几帧；**低于下限**，说明它帧太富余，就收回几帧给别人。当没有帧可再分、且所有进程都在高缺页率时，就该挂起一个进程了。PFF 把抽象的"工作集大小"翻译成一个可直接测量、可直接反馈的量（缺页率），是工作集思想的工程近似。

### 10.3.4 Linux 页回收与 swappiness 调参

Linux 不显式实现工作集/PFF，而是用 **kswapd（后台回收内核线程）+ 直接回收（direct reclaim，分配内存时当场腾）** 维持空闲页水位，回收对象从上节的 inactive LRU 链尾选取。其中一个关键可调旋钮是 **swappiness**：控制回收时"换出匿名页（走 swap）"相对"丢弃/回写文件页（page cache）"的倾向。

内核文档（docs.kernel.org vm.html，核实 2026-07-29）对当前语义的表述是：swappiness 表示 swap I/O 相对文件系统分页 I/O 的**相对成本**，取值范围 **0–200**（100 时假设两者 I/O 成本相等而对二者施加同等回收压力，低于 100 表示 swap 更贵、更不愿换匿名页，高于 100 表示 swap 更便宜——对 zram/zswap 这类内存内 swap 才用得上 >100）。默认值为 **60**。本机取证：

```
$ cat /proc/sys/vm/swappiness
60
```

与文档默认值一致（Linux 6.18.5 @2026-07-29）。

两个易错点要点明。其一，swappiness **不是"用多少 swap 的百分比"**，而是"倾向"参数——这是最常见的误解。其二，**swappiness=0 并不彻底禁用 swap**：它只是把换匿名页的倾向压到最低，在内存严重不足、为避免 OOM 时内核仍可能换出匿名页；真正"没有 swap"是像本机这样根本不配置 swap 空间（`SwapTotal: 0 kB`）。此外 swappiness 的**上限从早期的 100 提升到 200**（配合 zram/zswap 场景），是较新的演进，用旧资料时需注意（⚙演进快）。

## 10.4 COW 与按需置零

### 10.4.1 写时复制 (copy-on-write, COW)

写时复制指：需要"复制一块内存"时，先不真复制，而是让两方**共享同一份物理页并都标成只读**；直到某一方真的**写**它，才由缺页触发、当场复制出一份私有副本给写者。最典型的用武之地是 `fork()`（呼应大主题02 OS-02.4）：子进程和父进程 fork 后共享全部物理页（只读），谁先写某页，谁就在那次写缺页里得到该页的私有拷贝。

机制细节：内核把共享页的 PTE 权限改为只读，并在 VMA 上打 COW 标记。此后任一方写该页 → 因"写只读页"触发缺页 → 缺页处理程序发现这是 COW 页（合法写，非真错误）→ 分配新帧、把原页内容拷入、把**写者**的 PTE 指向新帧并恢复可写。这是一次**次缺页**（minor fault，不读盘）。

`fork` 后子进程往往马上 `exec` 换成别的程序，此时把父进程整个地址空间都真复制一遍纯属浪费。COW 让复制的代价"推迟到真正需要、且只对被写的那几页发生"——绝大多数页从未被写，就永远共享、零复制成本。这就是为什么现代 `fork` 又快又省内存。

### 10.4.2 按需置零与零页共享 (demand-zero / zero page)

程序新申请的、内容应为全零的匿名内存——BSS 段（未初始化全局变量）、堆、匿名 `mmap`——不会在分配时就为每一页找一个清零的物理帧。取而代之，这些页的 PTE 先统统**只读地映射到内核唯一的一个"零页"**（一整页全 0 的共享物理页）。只要进程只读不写，大家共用这一个零页，几乎不耗物理内存。

当进程**第一次写**某个这样的页时，触发缺页（写只读页），内核才真正分配一个新帧、清零、把该页 PTE 指向它并置可写——这叫**按需置零**（demand-zero）。它和 COW 是同一套"只读共享 + 写触发分配"机制的两个应用：COW 复制的是"某页的现有内容"，按需置零复制的是"那个全零页"。二者产生的都是次缺页（无磁盘 I/O）。

本机 smaps 佐证这套共享/私有的划分（当前进程的汇总）：

```
$ grep -E 'Shared_Clean|Private_Dirty|Anonymous' /proc/self/smaps_rollup
Shared_Clean:       1624 kB    # 只读共享（含库代码、尚未写过的共享页）
Private_Dirty:       148 kB    # 已被写过、私有化的页（COW/按需置零后的结果）
Anonymous:           148 kB    # 匿名（堆/栈/匿名 mmap）中已实际占帧的部分
```

Shared_Clean 远大于 Private_Dirty，正符合"多数页只读共享、只有写过的少数页才真正私有占帧"的直觉。

### 10.4.3 与 fork 的呼应及本课边界

本节的 COW 与大主题02 的 OS-02.4「写时复制」是同一机制的两个视角：那边从**进程 API/fork 生命周期**讲"子进程为何能便宜地拿到父进程地址空间副本"，这边从**缺页/虚拟内存机制**讲"那次便宜是靠只读共享 + 写缺页复制实现的"。fork/exec/wait 的完整语义与僵尸/孤儿等归大主题02，本报告只讲 COW 缺页这一机制点，不重复展开。

## 10.5 swap 机制与策略

### 10.5.1 换出与换入 (swap out / swap in)

swap（交换）是"物理内存装不下时，把某些页暂存到磁盘"的后备存储机制，是 10.1–10.3 那套换页的落地介质。两个方向：**换出**（swap out）——回收时把一个选中的匿名页写到磁盘的交换区，然后把它的 PTE 从"指向物理帧"改成一个记录了磁盘位置的**交换项**（swap entry），并清存在位；该帧就腾出来了。**换入**（swap in）——之后进程再访问这个页，因存在位为 0 触发缺页（这是一次**主缺页**，需读盘），内核从交换项记的磁盘位置把内容读回一个新帧、恢复 PTE。

换出改 PTE 为交换项、腾帧；换入靠缺页把它读回、复原 PTE。整个过程对用户程序透明——它只是"访问了一个碰巧被换出去的页"，感觉不到中间有过磁盘往返，只是那次访问变慢了（主缺页的代价，见 10.1.4）。注意只有**脏的**匿名页换出前才需写盘；若某匿名页自上次换入后没被改过（有干净副本在 swap 里），可直接丢弃、下次从 swap 读回。

### 10.5.2 匿名页 vs 文件页：谁去 swap

**只有匿名页（anonymous pages）才会被换到 swap**。匿名页指没有文件后备的内存——堆、栈、匿名 `mmap`、BSS；它们在磁盘上没有"老家"，要腾走就必须写进 swap 才能日后找回。而**文件页（file-backed pages）**（可执行文件、mmap 的文件、page cache）在磁盘上本就有对应文件：干净的文件页可直接**丢弃**（要用再从原文件读回，根本不进 swap）、脏的文件页**回写到它自己的文件**（不是 swap）。

这正是 10.3.4 里 swappiness 调的那个平衡：回收时是更多地"换出匿名页（占用 swap I/O）"还是"回收文件页（丢弃/回写文件）"。理解了"匿名页 → swap、文件页 → 原文件"这条分账，就理解了为什么无 swap 的机器（如本机 `SwapTotal:0`）仍能正常回收内存——它只是不能换出匿名页，但照样能回收文件页/page cache。

### 10.5.3 swap 分区 vs swap 文件

swap 空间有两种承载形式：**swap 分区**（一块专用于交换的裸块设备分区）和 **swap 文件**（普通文件系统里的一个文件被当作 swap 用）。功能等价，都能 `swapon` 挂上、`swapon --show` 查看。差别在：分区是连续裸设备、少一层文件系统间接，历史上略快、管理更"硬"；文件更灵活——可随时创建/删除/改大小，不必预先分区。现代内核里两者性能差距通常不显著（⚙实现相关）。

无任何 swap 配置。

```
$ swapon --show
（无输出）
$ free -m
               total   used   free   shared  buff/cache   available
Mem:           16075    756  14822        4         778        15319
Swap:              0      0      0
```

`Swap: 0 0 0` 且 `swapon --show` 空，说明本机**未配置 swap**，故本报告"换出到磁盘"的路径本机无法实测，仅作机制讲解（如实标注）。

### 10.5.4 压缩 swap：zswap 与 zram

现代 Linux 常用"用内存换磁盘"的两种压缩式 swap 变体。**zram** 在 RAM 里创建一个**压缩的块设备**并把它当作 swap——换出的页被压缩后仍留在内存，根本不碰磁盘，适合无盘/嵌入式/内存吃紧但 CPU 有余的场景。**zswap** 则是一个位于真实 swap 设备**前面的压缩缓存**：换出的页先压缩存进内存里的 zswap 池，池满或冷页再真正写到后端 swap 设备，相当于给慢速 swap 加一层压缩 cache。

这两者正是 10.3.4 里"swappiness 可取 >100"的动机来源：当 swap 其实落在内存（zram/zswap）而非慢磁盘时，换匿名页的成本比传统认知低得多，故内核允许把倾向调到 100 以上。本机 `/proc/meminfo` 中 `Zswap: 0 kB`、`Zswapped: 0 kB`、`SwapTotal: 0 kB`，即本机既没配 swap 也没启用 zswap/zram（如实标注；这两项具体默认启用状态随发行版/内核配置不同，本机为未启用）。
