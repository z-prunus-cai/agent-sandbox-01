## 1.1 设计度量

### 1.1.1 性能：响应时间与吞吐率

性能（performance）在体系结构里有两个互不等价的量纲，用哪个取决于你关心什么。一个是响应时间（response time），又称执行时间（execution time）或延迟（latency），指从任务开始到完成经过的时间；另一个是吞吐率（throughput，又称带宽 bandwidth），指单位时间完成的任务总量。对单个程序，性能定义为执行时间的倒数：

```
性能 = 1 / 执行时间
```

于是"机器 X 比机器 Y 快 n 倍"精确地表示为：

```
性能_X / 性能_Y = 执行时间_Y / 执行时间_X = n
```

个人用户和交互任务关心响应时间（"我的任务多久跑完"），数据中心和服务器更关心吞吐率（"每秒能服务多少请求"）。二者不是一回事：把一个任务拆成流水线并行做，可能单个任务的延迟没变甚至变长，但整体吞吐率大幅提高。初学者易错点是把"快"默认成延迟——先问清是延迟快还是吞吐快，再谈优化。另一个陷阱是 MIPS（每秒百万条指令）之类指标：不同指令干的活不一样多，指令率高不代表任务完成得快，QA/COD 都把"用 MIPS 比不同 ISA 的机器"列为经典谬误。

### 1.1.2 成本：晶圆、良率与学习曲线

成本（cost）在 QA ch1 里被拆成可量化的芯片制造模型。集成电路刻在圆形硅晶圆（wafer）上，切成一个个方形裸片（die）。单个裸片的成本近似为：

```
裸片成本 = 晶圆成本 / (每片晶圆裸片数 × 裸片良率)
```

其中每片晶圆裸片数约等于晶圆面积除以裸片面积（再扣掉边缘无法利用的部分）：

```
每片晶圆裸片数 ≈ π × (晶圆直径/2)² / 裸片面积 − π × 晶圆直径 / √(2 × 裸片面积)
```

裸片良率（die yield，即能正常工作的比例）随裸片面积增大而下降，因为面积越大越容易碰上缺陷。QA 用一个经验模型描述它（N 为工艺复杂度参数）：

```
裸片良率 = 晶圆良率 × (1 + 单位面积缺陷数 × 裸片面积 / N)^(−N)
```

成本对裸片面积高度敏感——面积翻倍不只是材料翻倍，良率还会掉，于是单片成本涨得比线性更快。这解释了为什么"把芯片做小"始终是省钱主线。另一条经验规律是学习曲线（learning curve）：同一款芯片随生产成熟，良率上升、成本下降，所以芯片价格会随时间走低。初学者要区分成本（cost，厂商造出来花的钱）与价格（price，卖给你的钱）——两者之间还隔着毛利、分销、研发摊销等。这些具体数字随工艺代际和厂商剧烈变动，属⚙演进项，本报告只给模型不锚死数值。

### 1.1.3 功耗与能耗：动态、静态与"能量才是账本"

功率（power，单位瓦特）是单位时间耗能，能量（energy，单位焦耳）是完成一件事总共耗掉的。CMOS 电路的动态功率（dynamic power）来自晶体管开关翻转：

```
动态功率 ∝ 1/2 × 电容负载(C) × 电压(V)² × 开关频率(f)
```

一次翻转消耗的动态能量与频率无关：

```
动态能量 ∝ 电容负载(C) × 电压(V)²
```

除动态部分外还有静态功率（static power），来自晶体管即使不翻转也存在的漏电流（leakage current）：

```
静态功率 ∝ 静态电流 × 电压(V)
```

电压是平方项，对动态功耗影响最猛，所以降压最省电——但降压会降低晶体管速度、并让漏电相对更突出。QA 强调一个反直觉但重要的结论：比"功率"更该优化的常常是"能量"。因为频率翻倍让功率翻倍但任务也更快完成，若只看功率会误判；而"每个任务的能量"和"能量·延迟积"才反映真实代价。初学者常把功率和能量混用——记住功率是"多快在烧钱"，能量是"这件事总共烧了多少钱"，电池续航、数据中心电费本质上都是能量账。为什么这件事在 2004 年后变成头等约束（功耗墙、Dennard 缩放终结）已在 L3-02 CO-1.4 讲过，此处不重复。

### 1.1.4 能效：每瓦性能

能效（energy efficiency）把性能和功耗合成一个指标，最常用的形式是每瓦性能（performance per watt）：

```
能效 = 性能 / 功率
```

等价地也可用"每焦耳完成的工作量"或其倒数"每个操作的能量"（如每次浮点运算的皮焦 pJ/FLOP）来表达。

功耗墙时代，单纯比峰值性能已无意义——两台机器算得一样快，耗电差一倍的那台在数据中心里就是输家。所以现代评价普遍转向能效：手机 SoC 要"每毫瓦能跑多少"，数据中心加速器要"每瓦多少 TFLOPS"。初学者易错点是把高性能和高能效当同一件事——它们经常打架：把频率推到极限能拿到峰值性能，但因为功率随电压平方涨，能效反而崩掉；反过来，很多低频多核、专用加速器（本课大主题 8 DSA）牺牲单核峰值换取远高的每瓦性能。这也是为什么 SPEC 专门出了 SPECpower 基准（见 1.4）。

### 1.1.5 可靠性：MTTF、FIT 与失效率累加

可靠性（reliability）刻画一个模块"连续正确工作多久"。核心量是平均无故障时间（Mean Time To Failure, MTTF），失效率（failure rate）是它的倒数。工业界常用 FIT（Failures In Time）作单位，定义为每十亿（10⁹）小时的失效次数：

```
失效率 = 1 / MTTF
```

```
FIT = 10⁹ / MTTF(小时) = 失效率 × 10⁹
```

一个由多个部件串联组成的系统（任一部件坏则系统坏），在"失效相互独立且失效率恒定"的假设下，整体失效率是各部件失效率之和，整体 MTTF 是其倒数：

```
系统失效率 = Σ 各部件失效率
系统 MTTF = 1 / (Σ 各部件失效率)
```

举个 QA 风格的最小例子：10 块磁盘每块 MTTF 为 1,000,000 小时，1 个电源 MTTF 500,000 小时——把失效率相加，系统失效率 = 10×(1/10⁶) + 1/(5×10⁵) = 1.2×10⁻⁵ /小时，系统 MTTF ≈ 83,333 小时，远小于任何单个部件。这就是"部件越多越容易坏"的量化根据。初学者易错点：MTTF 不是"保证用这么久"，而是大量样本的统计均值；且"失效率累加"依赖独立与恒定失效率假设，真实器件早期/末期失效率更高（浴盆曲线）。可靠性正是八大伟大思想里"借冗余保证可靠"（见 L3-02 CO-1.1）要对抗的对象。

### 1.1.6 可用性：MTTR 与 MTBF

可用性（availability）回答另一个问题：系统在需要时"正在正常服务"的时间占比。它引入平均修复时间（Mean Time To Repair, MTTR）——坏了以后修好平均要多久。模块可用性定义为：

```
可用性 = MTTF / (MTTF + MTTR)
```

其中分母 MTTF + MTTR 常记为平均故障间隔时间（Mean Time Between Failures, MTBF）：

```
MTBF = MTTF + MTTR
```

可靠性和可用性是两个不同的问题：可靠性问"多久坏一次"，可用性问"坏了之后能多快恢复、总体在线比例多高"。一个每月坏一次但一秒就自愈的系统，可靠性一般但可用性极高。这就是为什么大规模系统宁可用"能快速替换/热备"的廉价部件，也不追求单件永不损坏——降低 MTTR 往往比拉高 MTTF 更划算。可用性常用"几个 9"表述（99.9%、99.99%…），"5 个 9"约等于每年停机 5 分钟。初学者易错点：把 MTBF 当成 MTTF——在 MTTR 远小于 MTTF 时二者数值接近，但概念不同（MTBF 含修复时间）。这条度量在本课大主题 7 仓库级计算机（WSC）里会以海量部件的尺度再登场。

## 1.2 量化原理

### 1.2.1 加速常见情形（make the common case fast）

QA 把"加速常见情形"列为计算机设计的首要经验原则：把资源投在最频繁发生的事件上，收益远大于优化罕见事件。判断"常见"要靠测量（profiling），而非直觉。

这条原则的道理是"投入产出比"——罕见事件即便优化到消失，对整体贡献也有限；常见事件哪怕只快一点点，因为发生次数多，累积收益巨大。它同时也简化设计：常见情形往往比罕见情形简单，优先把简单的高频路径做快，罕见的复杂情形做对即可（哪怕慢一点）。初学者易错点是凭感觉猜"哪里是热点"——真实的时间分布常常出人意料，必须用测量数据说话。这条原则的量化"多快才值得"由下面的 Amdahl 定律精确回答，二者是一体两面：Amdahl 告诉你收益上界，常见情形原则告诉你该往哪投。

### 1.2.2 Amdahl 定律：局部改进的整体上界

Amdahl 定律（Amdahl's Law）给"只加速程序的一部分，整体能快多少"一个精确答案。设 F 为可被改进部分占原执行时间的比例（fraction enhanced），S 为该部分自身的加速倍数（speedup of enhanced part），则整体加速比：

```
加速比 = 1 / ( (1 − F) + F / S )
```

当把那部分加速到极限（S → ∞）时，得到整体加速比的硬上界：

```
加速比上界 = 1 / (1 − F)
```

整体天花板只由"没被优化的比例 (1 − F)"决定，与你把可优化部分做得多猛无关。举个最小例子：某程序 80% 的时间可被加速（F = 0.8），哪怕把这 80% 加速到无穷快，整体也只能快 1/(1−0.8) = 5 倍，那剩下的 20% 就是天花板。反面例子：一个只占 5% 时间的函数（F = 0.05）即便优化到消失，整体也最多快 1/(1−0.05) ≈ 1.053 倍，约 5.3%，通常不值得投入。本机 numpy 复核：F=0.8、S=10¹² 时 amdahl≈4.99999998（逼近上界 5），F=0.3、S=20 时 ≈1.399（快约 40%，远不如"20 倍"给人的印象），F=0.9、p→∞ 上界 =10——数值与公式一致。

Amdahl 定律是"加速常见情形"的数学根据：要投资就投在占比 F 最大的部分。它同样支配并行——当"加速手段"是并行到 p 个核时，把 S 换成 p、F 换成可并行比例即可，上界仍是 1/(1−F)，这解释了"堆核"边际收益急剧递减（详见 L3-02 CO-1.5，本课大主题 5/6 会再深化）。初学者最常踩的坑是"忘了还有不可加速部分"，只报局部加速倍数而不提它占多少时间；另一个坑是把 F 当成"代码行数比例"——F 是按时间算的，一个几行的循环可能占 90% 时间，判断该优化谁必须看时间画像。

### 1.2.3 处理器性能公式作为设计工具

在体系结构里，"执行时间"通常被展开成 QA 称为处理器性能公式（processor performance equation）的三因子乘积，也常被叫作性能的"铁律"（iron law）：

```
CPU 时间 = 指令数(IC) × 每指令周期数(CPI) × 时钟周期
```

其中时钟周期与时钟频率互为倒数，等价地：

```
CPU 时间 = (IC × CPI) / 时钟频率
```

这条公式的用途是把模糊的"快慢"拆成三个可分别优化、且由不同层负责的旋钮：指令数 IC 由算法/编译器/ISA 决定，CPI 由微架构与 ISA/指令组合决定，时钟周期由微架构关键路径与工艺决定。想让程序更快，只有三条路——减少 IC、降低 CPI、提高频率。CPI 是按各类指令频率加权的平均：

```
CPU 时钟周期总数 = Σ_i (CPI_i × IC_i)
```

本机 numpy 量纲复核：IC=10⁹、CPI=1.5、时钟周期=0.5 ns（2 GHz）时 CPU 时间 = 0.75 s，与公式一致。三因子并非彼此免费独立——提频往往抬高功耗（见 1.1.3）、用更精简指令可能降 CPI 却升 IC，真正的设计是三者联合权衡。这条公式在 L3-02 CO-1.2 已建立，本课把它当作贯穿全书评估微架构技术的统一标尺（如流水线是在"逼近 CPI=1"、cache 是在"降低访存带来的 CPI 惩罚"）。

### 1.2.4 局部性与并行作为经验规律

QA 的量化原理里还有两条"经验规律"性质的支柱，为上面的定律提供物理与程序层面的依据。一条是局部性原理（principle of locality）：程序倾向于重复访问最近用过的数据/指令（时间局部性）以及其邻近地址（空间局部性）。一条常被引用的经验法则（rule of thumb）是"程序约 90% 的时间花在约 10% 的代码上"，这正是"加速常见情形"能奏效的现实前提。另一条是利用并行（take advantage of parallelism）：从系统级的多处理器、到指令级的流水线、到位级的进位加速，各个层次都可以靠并行提升吞吐。

把这些叫作"大数定律式经验法则"是一种松散的类比——它们不是严格的概率极限定理，而是从海量程序行为中统计出来、在设计中反复奏效的规律；本报告如实标明这是经验规律而非数学定理，避免把类比当成证明。初学者可以这样串起来：局部性解释了为什么存储层次（本课大主题 2）有效、90/10 规律解释了为什么优化热点划算（呼应 1.2.1）、并行的可利用性则是从大主题 3 到大主题 8 的技术脊梁。局部性的入门定义已在 L3-02 CO-6.1 讲过，此处只强调它作为"量化设计原理"的地位，三类并行的展开见 1.3。

## 1.3 局部性与并行

### 1.3.1 局部性原理：时间与空间

局部性原理（principle of locality）指出程序对内存的访问不是均匀随机的，而高度集中：时间局部性（temporal locality）指最近访问过的地址很可能很快再被访问；空间局部性（spatial locality）指某地址被访问后，其邻近地址很可能紧接着被访问。

这条经验规律是整个存储层次（memory hierarchy）存在的理由：正因为访问集中，把"最近/邻近用到的一小块"放进又快又小的 cache，就能用小成本命中绝大多数访问，制造出"又大又快"的错觉。最小例子：一个遍历数组求和的循环，循环体指令被反复执行（时间局部性），数组元素按地址顺序读取（空间局部性）——所以第一次读某个 cache 行会带回一整行的相邻元素，后续几次访问直接命中。初学者易错点是把两种局部性搞混：时间局部性关心"同一地址再用"，空间局部性关心"相邻地址接着用"；写出局部性差的代码（如大步长跳跃、随机访问）会让 cache 几乎失效，性能断崖下跌。局部性的机制细节（cache 组织、AMAT）是本课大主题 2 的主题，此处只确立它作为量化设计基石的地位。

### 1.3.2 三类并行：ILP、DLP、TLP（与 RLP）

应用天生带有可利用的并行，QA 从应用角度把它分类。指令级并行（Instruction-Level Parallelism, ILP）指单一指令流内部彼此无依赖、可同时执行的指令，靠流水线与多发射挖掘。数据级并行（Data-Level Parallelism, DLP）指对大量数据施加同一操作（如向量、矩阵），靠向量/SIMD/GPU 挖掘。线程级并行（Thread-Level Parallelism, TLP）指多个可并行的任务/线程，靠多核与多处理器挖掘。QA 还提请求级并行（Request-Level Parallelism, RLP），指彼此独立的用户请求，在仓库级计算机尺度上挖掘。

这套分类是本课后半程的路线图：ILP → 大主题 3/4（静态与动态调度），DLP → 大主题 5（向量/SIMD/GPU），TLP → 大主题 6（多处理器），RLP → 大主题 7（WSC）。理解它们的关键是"并行的粒度和来源不同，需要的硬件也不同"——ILP 藏在一条指令流里、由硬件/编译器自动挖，程序员基本无感；DLP 需要数据规整（同构、无依赖），一条指令干一批数据；TLP 需要程序员或运行时显式划分任务。初学者易错点是把它们当成互斥的四选一——真实系统同时利用多个层次（一个多核 CPU 每个核内有 ILP、核间有 TLP，核里的 SIMD 单元还在做 DLP）。

### 1.3.3 Flynn 分类：SISD/SIMD/MISD/MIMD

从硬件组织角度，QA 沿用经典的 Flynn 分类（Flynn's taxonomy, 1966），按"指令流数 × 数据流数"分四类：

```
SISD  单指令流单数据流   传统单核标量处理器
SIMD  单指令流多数据流   向量处理器、SIMD 扩展、GPU（主体）
MISD  多指令流单数据流   罕见，几乎无商用通用机
MIMD  多指令流多数据流   多核 / 多处理器 / 集群
```

Flynn 分类和 1.3.2 的并行分类是"硬件视角"与"应用视角"的对应：SIMD 硬件用来榨取 DLP，MIMD 硬件用来榨取 TLP/RLP，SISD 里的流水线/多发射榨取 ILP。初学者易错点：GPU 常被笼统称作 SIMD，但 QA 把 GPU 的执行模型单列为 SIMT（Single Instruction, Multiple Thread），是 SIMD 的一个变体（本课大主题 5 展开）；MISD 基本是分类完备性的占位，别费劲找它的实例。这套四格表历史悠久、简单好记，但粒度粗——它只是入门坐标，真实机器往往是多类混合。

## 1.4 评测方法学

### 1.4.1 基准套件：为什么不能只跑一个程序

要公平比较不同机器，最理想是跑用户真实的工作负载（real applications），但这不现实——负载各异且难移植。于是业界用基准套件（benchmark suite）：一组精心挑选、有代表性的真实程序打包在一起，一起跑、汇总打分，避免"只挑对自己有利的单个程序"。

QA 按可信度给基准分级：真实应用最可信；内核（kernel，从真实程序抽出的关键片段，如 Livermore Loops）次之；玩具基准（toy benchmark，如排序、埃拉托斯特尼筛）和合成基准（synthetic benchmark，如 Whetstone、Dhrystone）最不可信，因为它们小到能被编译器/厂商专门"针对性优化"而不反映真实性能，QA 明确不推荐用它们下结论。最主流的套件是 SPEC（Standard Performance Evaluation Corporation）系列——SPEC CPU 测处理器（分整数 SPECint 与浮点 SPECfp），SPECpower 测能效（每瓦性能，呼应 1.1.4），另有面向事务处理的 TPC、嵌入式的 EEMBC 等。初学者易错点是以为"跑分越高机器越好"而不看用的是哪套基准、哪个版本——脱离负载谈性能没有意义。

### 1.4.2 几何平均：为什么汇总比值要用它

一套基准里多个程序的成绩怎么合成一个总分？SPEC 报告的是相对性能——某机在程序 i 上相对参考机（reference machine）的 SPECratio：

```
SPECratio_i = 参考机执行时间_i / 被测机执行时间_i
```

SPECratio 越大越快。汇总这些比值时 SPEC 用几何平均（geometric mean），而非算术平均：

```
几何平均 = ( SPECratio_1 × SPECratio_2 × … × SPECratio_n ) ^ (1/n)
```

用几何平均的决定性理由是它与参考机的选择无关：换一台参考机会让每个 SPECratio 同比例缩放，但几何平均的比值关系不变，于是不同报告仍可比。本机 numpy 复核这条尺度无关性：对 [100, 1] 几何平均 = 10；把两个数都乘 7.3（模拟换参考机）后几何平均 = 73 = 7.3×10，比值关系保持，而算术平均从 50.5 变成 368.65 就没有这种性质。这也顺带说明算术平均对比值不公平——[100,1] 的算术平均 50.5 被极端值主导，几何平均 10 更能反映"综合快约 10 倍"。初学者要记住配对规则：汇总"比率/加速比"用几何平均；汇总"可直接相加的总时间"回到算术和；汇总"速率（如 MFLOPS）"在特定条件下用调和平均——用错平均会得出误导性结论。

### 1.4.3 结果的统计有效性与可复现性

一次测量给一个数，但真实测量有波动（缓存状态、系统噪声、频率调节等）。QA 强调报告性能要讲统计有效性：多次运行、报告分布而非单点，用几何标准差/置信区间刻画离散程度，并公开完整的实验条件（机器配置、编译器与优化选项、基准版本）以保证可复现（reproducibility）。SPEC 正是靠强制公开这些配置和运行规则来维持可比性。

不可复现、不带误差的单个跑分几乎无法用来做可信比较——你不知道它是精心调优的最好一次还是普通一次，也不知道差异是真实的还是噪声。最小直觉：若 A 机比 B 机快 1%，但两者各自的运行波动就有 3%，那这 1% 很可能是噪声，不能下"A 更快"的结论。初学者易错点是拿两个孤立数字直接比大小——正确做法是多次测量、看区间是否重叠。本机 perf 应用级实证（读 instructions/cycles 求实测 CPI 或 IPC）在此本可作补充，但须与微架构分账（应用级计数不等于微架构内部行为）；本机 `perf` 未安装（`which perf` 无输出），且为 KVM 虚拟机、硬件 PMU 通常不透传，故标**未取**——按纪律如实留白，不以编造数字充数，本节结论由 QA/COD 两处一手交叉坐实，不受影响。

## 1.5 ISA 原理（附录 A）

### 1.5.1 ISA 的定义与内部存储分类

指令集体系结构（Instruction Set Architecture, ISA）是软件所见的硬件抽象——硬件对软件的完整承诺：有哪些指令、有哪些寄存器、内存怎么编址、指令怎么编码。QA 附录 A 按"操作数放在 CPU 内部何处"给 ISA 做经典分类：

```
栈式(stack)         操作数隐式在栈顶，如老式 x87
累加器式(accumulator) 一个隐式累加器 + 一个内存操作数
寄存器式(register)  多个通用寄存器 GPR，又分：
    寄存器-内存(register-memory)  运算可直接带内存操作数，如 x86
    load-store(寄存器-寄存器)     仅 load/store 访存，运算只碰寄存器，如 RISC-V/ARM/MIPS
```

现代通用机几乎都是通用寄存器（General-Purpose Register, GPR）架构，尤其是 load-store 型。原因是寄存器比内存快得多、且能被编译器灵活分配以复用中间结果；load-store 把"访存"和"运算"分开，使指令定长、流水线好切、编译器好调度。这是"ISA 是软硬件契约"的最底层——ISA 之上编译器只面向它生成代码，ISA 之下厂商可用完全不同的微架构实现（ISA ≠ 微架构，见 L3-02 CO-1.1/CO-2.6）。初学者易错点是把 ISA 与具体芯片混为一谈：同一套 RISC-V ISA 可以有几十种快慢功耗迥异的实现。

### 1.5.2 内存寻址：字节编址、对齐与字节序

绝大多数 ISA 用字节编址（byte addressing）——每个内存地址指向一个字节。访问多字节对象（如 4 字节的字）时有两个必须交代的约定。对齐（alignment）指对象地址应是其大小的整数倍（4 字节字放在 4 的倍数地址），未对齐访问在有些 ISA 上禁止、在有些上允许但更慢。字节序（endianness）指多字节对象在内存里字节的排列顺序：小端（little-endian）低位字节在低地址，大端（big-endian）高位字节在低地址。

对齐存在的理由是硬件访存以固定宽度的块进行——对齐的对象一次取到，跨界的未对齐对象要拆成两次访问再拼接，慢且复杂。字节序则纯是约定，无优劣，但跨机器/网络传数据时若两端字节序不同又不转换，读出来的数值就是错的（网络协议因此规定"网络字节序"为大端）。最小直觉：把 32 位数 0x01234567 存到地址 0，小端在地址 0,1,2,3 依次放 67 45 23 01，大端放 01 23 45 67。初学者易错点是以为对齐/字节序只是"底层细节"——它们会实打实地影响正确性（跨端口移植出乱码）和性能（未对齐惩罚）。本机 x86-64 是小端、允许未对齐访问但对齐更快（L3-03 汇编课已实测坐实）。

### 1.5.3 寻址模式

寻址模式（addressing mode）规定一条指令怎样算出操作数的位置。附录 A 列出常见模式，各 ISA 取其子集：

```
立即数 immediate         操作数是指令里的常数
寄存器 register           操作数在寄存器
寄存器间接 register indirect  地址在寄存器里
偏移/基址+偏移 displacement    地址 = 寄存器 + 常数偏移
变址 indexed             地址 = 基址寄存器 + 变址寄存器
比例变址 scaled          地址 = 基址 + 变址×比例 + 偏移（x86 通式）
直接/绝对 direct/absolute  地址是指令里的常数
内存间接 memory indirect   地址存在内存里（需二次访存）
自增/自减 auto-increment/decrement  访问后自动调整指针
PC 相对 PC-relative       地址 = PC + 偏移（用于分支/跳转）
```

寻址模式是"表达能力 vs 复杂度"的权衡：模式越丰富，一条指令能干越多（如 x86 的比例变址 `disp(base,index,scale)` 一步算出数组元素地址），代码更短，但译码和流水线更复杂。RISC 型 ISA 刻意只保留少数几种（立即、寄存器、偏移、PC 相对），换取定长指令和简单流水线。QA 用测量数据支撑取舍——偏移寻址和立即数寻址在真实程序里占绝大多数，所以精简 ISA 优先保留它们，这正是"加速常见情形"（1.2.1）落到 ISA 设计上的体现。初学者易错点：别把"寻址模式多"等同于"更强"——多出来的复杂模式若很少被用，只是在给硬件添负担。

### 1.5.4 操作数的类型与大小、指令集操作

ISA 还要规定支持哪些操作数类型与大小，以及有哪些操作。类型/大小方面：整数（字节 8、半字 16、字 32、双字 64 位）、IEEE-754 浮点（单精度 32、双精度 64 位）、有时还有字符/字符串、十进制等。操作方面 QA 按类归纳：算术逻辑、数据传送（load/store/move）、控制流（分支/跳转/调用）、系统（调用/特权）、浮点、以及可选的十进制、字符串、SIMD 多媒体等。

操作数编码进指令时如何指明大小，是 ISA 设计的一部分：有的用不同操作码（x86 的尺寸后缀）、有的用指令字段。指令集里真正被高频使用的其实是很少一部分——QA/附录 A 用测量指出 load、store、加法、比较、条件分支等简单操作占了执行的绝大多数，复杂/专用指令使用率极低。这又回到"加速常见情形"：把高频简单指令做快做对，是比堆砌大量专用指令更划算的设计。初学者易错点是被 x86 上千条指令的规模吓到——绝大多数程序只用到其中很小的常用子集，学 ISA 先抓这个核心子集即可。

### 1.5.5 指令编码：定长、变长与混合

指令编码（instruction encoding）决定操作码和操作数字段如何塞进指令的二进制位。三种主要风格：

```
定长(fixed length)    每条指令等长（如 RISC-V/ARM/MIPS 的 32 位）
变长(variable length)  指令长度随操作数个数/寻址模式而变（如 x86，1–15 字节）
混合(hybrid)          少数几种固定长度（如某些 ISA 提供 16/32 位两档）
```

编码方式是"代码密度 vs 译码简单"的核心权衡。变长编码代码更紧凑（常用短指令用少字节），省内存和取指带宽，但每条指令要先解析长度才能定位下一条，译码复杂、难并行、难流水；定长编码浪费一些空间，但取指和译码极其规整——固定位置就是操作码、就是寄存器号，可轻松并行译码多条，天然适配流水线与超标量。这是 RISC 选定长、CISC（x86）选变长的根本分野。RISC-V 还提供可选的压缩指令（C 扩展，16 位）作为混合折中，兼顾密度。初学者易错点是以为"变长省内存所以更好"——在流水线/多发射时代，译码简单带来的吞吐优势通常压过代码密度，这也是现代高性能核大多是定长 load-store RISC 的原因（x86 则在前端把变长指令译码成定长微操作 μops 来兼顾）。RISC vs CISC 的完整权衡与 ISA/微架构分账见 L3-02 CO-2.6，本节只讲编码层面的取舍。
