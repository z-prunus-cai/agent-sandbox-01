## 8.1 DSA 设计原则（AA-8.1）

### 8.1.1 什么是领域专用体系结构

领域专用体系结构（DSA, Domain-Specific Architecture）指为**某一类特定应用**（一个"领域"，如深度神经网络推理、图像信号处理、网络包处理）量身定制的处理器，而不是像通用 CPU 那样什么都能跑但样样不极致。它介于两个极端之间：一端是完全通用的 CPU/GPU（灵活但每瓦性能一般），另一端是只能做一件事的固定功能 ASIC（专用电路，极快极省但完全不可编程）。DSA 保留**领域内**的可编程性，同时把领域外的通用能力砍掉，以此换取远超通用处理器的性能与能效。

初学者要先建立时代背景。过去几十年靠 Dennard 缩放（晶体管越做越小、单位面积功耗不变）和摩尔定律，通用处理器每代自动变快，没人需要为单个领域专门造芯片。但 Dennard 缩放约 2005 年终结、摩尔定律近年也放缓（本课大主题1 讲过的"功耗墙"），通用处理器的单线程性能几乎停滞。既然不能再靠"通吃"的芯片自动变快，唯一还能大幅提效的路子就是**针对具体领域定制硬件**——这就是 DSA 在 2010 年代重新兴起、并成为 H&P 第 6 版新增一整章的原因。DSA 不是"又一种加速器"，而是后摩尔时代提升性能的主要手段。

要分清 DSA 和它的邻居。ASIC 完全不可编程（改需求就得重新流片），DSA 在领域内仍可编程（同一块 TPU 能跑不同的神经网络）；FPGA 是可现场重构的硬件，灵活性介于 DSA 与 ASIC 之间（H&P ch7 的 Microsoft Catapult 就是 FPGA 方案）。"领域专用"的关键词是**领域**：范围比"某个程序"宽（不是硬连一个网络），又比"任意程序"窄（不打算跑操作系统或数据库），这个"不宽不窄"正是 DSA 拿捏效率与实用性的位置。

### 8.1.2 专用化收益从哪来

通用处理器把大量晶体管和能量花在"猜程序想干什么、并在不确定中保持高性能"上：分支预测器、乱序执行的保留站与重排序缓冲、多级 cache 的标记比对与一致性、寄存器重命名、投机执行(本课大主题4 全在讲这些)。这些机构对"事先不知道要跑什么"的通用负载是必要的，但它们本身**不做任何有用的算术**——它们是为通用性付的"管理费"。DSA 的核心洞察是：一旦锁定领域，程序的访存模式和并行结构在编译期就基本已知，这些昂贵的动态机构大多可以砍掉，把省下的芯片面积和功耗**全部投到真正干活的算术单元和片上存储上**。

一个直观的数量级对比能说明收益来源。在通用 CPU 上跑一次乘加，指令要经历取指、译码、寄存器重命名、进保留站、等待发射、访存、写回、退休——真正的"乘加"只占其中极小一部分能量，绝大部分能量花在搬数据和维护流水线状态上。研究界常引用的经验是：一次片外 DRAM 访问的能耗比一次乘加高出约**两到三个数量级**，而通用处理器每条指令都要走一遍重型前端。DSA 用大片的片上存储让数据"不出芯片"，用成百上千个精简的乘加单元同拍并行，于是同样的芯片面积和功耗预算能做的有用算术多出一两个数量级。这就是专用化收益的物理来源：不是"魔法电路"，而是**把为通用性付的管理费省下来买算术**。

初学者容易误以为"专用就是主频高"，其实恰恰相反。TPU v1 的时钟只有 700 MHz，远低于同期 CPU 的三四 GHz；它靠的是每拍并行做几万次乘加（大规模数据级并行），而不是把每次乘加做得更快。记住这条主线：DSA 的性能来自**并行度和数据本地性**，不是频率；能效来自**砍掉通用开销**，不是新工艺。

### 8.1.3 H&P 的五条 DSA 设计准则

H&P ch7 §7.1 从若干成功 DSA 的共性中总结出**五条设计准则（guidelines）**，是本小主题的一手核心，逐条如下。

准则一，用专用存储把数据搬运距离降到最低。通用处理器用多级 cache 自动管理数据，但 cache 会为了通用而做很多"以防万一"的搬运。DSA 改用软件显式管理的**便签存储（scratchpad）/专用缓冲**，编译器精确知道每份数据什么时候用、放哪，避免无谓搬运。

准则二，把砍掉高级微架构优化省下的资源，投到更多算术单元或更大的存储上。省下乱序、投机、多级 cache 的面积，换成成千上万个乘加单元和大块片上缓冲——这正是 8.1.2 说的"省管理费买算术"的工程落地。

准则三，用最契合领域的、最简单的那种并行形式。深度学习是规整的数据级并行（同一操作作用于大批数据），那就用向量/矩阵式 SIMD，而不是去做复杂的乱序 ILP；简单的并行形式硬件开销小、能效高。

准则四，把数据的尺寸和类型缩到领域所需的最小。神经网络推理不需要 FP64 甚至 FP32，8 位整数或 16 位浮点往往足够。数据越窄，同样面积能放的算术单元越多、片上能存的数据越多、搬运带宽压力越小——这直接引出 8.3 的混合精度。

准则五，用领域专用编程语言把软件移植到 DSA 上。DSA 不能只交付硬件，必须配套能把领域程序高效映射到这套硬件的语言与编译器（如 TensorFlow/XLA、Halide）——这直接引出 8.4 的软硬协同。

这五条不是互相独立的清单，而是一条逻辑链：锁定领域 → 领域的并行和数据模式已知（准则三、四）→ 于是能砍通用机构、把资源换成算术和专用存储（准则一、二）→ 但硬件专用了就需要专用软件把程序喂进去（准则五）。初学者只要抓住"省通用、买算术、配软件"这九个字，就抓住了整章的骨架；后面 TPU（8.2）几乎是这五条的教科书式示范，可以逐条对照。

### 8.1.4 DSA 的代价与适用边界

专用化不是免费的。第一重代价是**灵活性**：DSA 只在其领域内高效，领域一变（比如神经网络的算子结构换代）就可能水土不服，甚至需要新一代芯片；这也是为什么 DSA 厂商必须紧跟领域算法演进。第二重代价是**一次性成本与风险**：设计和流片一款芯片要投入巨大的人力和资金（NRE, 非重复性工程成本），只有当这个领域的计算需求足够大、足够持久（如超大规模数据中心的 AI 负载）时，摊薄到每颗芯片才划算——这正是 DSA 先在大型云厂商内部落地（Google TPU、Amazon Trainium 等）的经济学原因。

初学者要理解 DSA 的"甜区"判据：一个领域值得做 DSA，通常要同时满足几点——计算需求巨大且长期存在（有量摊薄成本）、领域内有规整可利用的并行与数据复用（专用化才有收益）、通用处理器在这个领域确实效率低下（有提升空间）、且算法相对稳定或至少可预测（避免芯片一出就过时）。深度学习恰好全部命中，所以成了 DSA 最成功的战场。反过来，一个负载多变、数据不规整、量又不大的领域，做 DSA 往往得不偿失，通用处理器反而是对的选择。这条判据能帮你判断"什么该上 DSA、什么不该"，而不是把 DSA 当万金油。

## 8.2 TPU 与脉动阵列（AA-8.2）

### 8.2.1 TPU v1 总体结构

张量处理单元（TPU, Tensor Processing Unit）是 Google 为神经网络**推理**定制的 DSA，H&P ch7 §7.3 以其第一代（TPU v1，2015 年部署于数据中心）为详解范例。它的核心是一块很大的**矩阵乘单元（MXU, Matrix Multiply Unit）**——由 256×256 个 8 位乘加单元排成的**脉动阵列**，共 65536 个 MAC。围绕它的是一块约 24–28 MiB 的片上**统一缓冲（Unified Buffer）**存放激活值、一组权重先入先出队列从片外 DDR3 DRAM 取权重、以及累加器。TPU v1 作为协处理器挂在 PCIe 总线上，由主机 CPU 通过 CISC 风格的指令（如"矩阵乘""激活"）驱动，自己不跑操作系统、不取指令流做通用计算。

用 8.1.3 的五条准则逐条对照，TPU v1 几乎是标准示范：巨大的片上统一缓冲 + 软件管理，把数据搬运距离压到最低（准则一）；砍掉 CPU 的乱序/投机/多级 cache，把面积全给了 65536 个 MAC 和大缓冲（准则二）；用最规整的矩阵乘 SIMD 并行，不做复杂 ILP（准则三）；数据类型缩到 8 位整数（准则四）；配套 TensorFlow 软件栈把模型编译下发（准则五）。初学者可以把 TPU v1 当作"五条准则的活体标本"来记。

这里必须硬标时效。TPU v1 的这些数字（256×256、8 位、700 MHz、DDR3）是 2015 年的一代，教材 2017 年记录的也是它；到 2026 年 TPU 已迭代到第七代，结构、精度、存储、峰值算力全都大不相同（见 8.2.6）。请把 8.2.1–8.2.5 理解为"讲清脉动阵列矩阵乘加速器的机制"，用的是 v1 这个清晰的教学样本，**不要当成当下 TPU 的规格**。

### 8.2.2 脉动阵列的基本思想

脉动阵列（systolic array）由 Kung 与 Leiserson 于 1970 年代末提出，是一种把大量相同的处理单元（PE, Processing Element）排成规则网格、让数据像心脏泵血（systole，"脉动"由此得名）一样**有节奏地在阵列中逐拍流动**的结构。每个 PE 只做一件极简单的事（对流经它的数据做一次乘加），并把结果和输入按固定方向传给相邻 PE。关键在于：数据一旦从边界进入阵列，就在阵列内部被众多 PE 反复使用、逐级加工，而不必每步都回到寄存器堆或存储器——**一次读入、多次复用**。

脉动阵列为什么特别适合矩阵乘？因为矩阵乘的本质是大量"乘加并累加"，且数据复用度极高（矩阵 A 的每一行要和 B 的每一列都乘一遍）。传统处理器算矩阵乘，每次乘加都要从寄存器/cache 反复读同一批元素，访存次数远多于算术次数；脉动阵列让一个元素进来后沿途被一排 PE 连续使用，把访存次数摊薄到极低。用 8.1.1 的语言说，脉动阵列是准则一（最小化数据搬运）和准则二（把资源堆成算术单元阵列）的电路级化身。

初学者最容易卡在"脉动"二字。它强调的是**时空规律性**：所有 PE 用同一个时钟，每拍所有数据同步向固定方向挪一格，像传送带上的工件整齐前进，而不是各自随机访存。正因为这种规律性，脉动阵列的控制极其简单（不需要复杂调度）、布线极短（只连相邻 PE）、能效极高——代价是它只擅长这类规整的流式计算，不规整的负载放不进来，这又回到 8.1.4 的适用边界。

### 8.2.3 脉动阵列的数据流（权重固定）

TPU v1 的 MXU 采用**权重固定（weight-stationary）**数据流：先把权重矩阵预加载并"驻留"在阵列的各个 PE 里不动，然后让输入激活值从阵列一侧逐拍流入、部分和沿另一方向逐拍累加流出。下面用一个 3×3 的小阵列示意一拍拍的推进（把它想象成 256×256 的缩微版）。

```
权重预加载后驻留（每个 PE 存一个权重 w[i][j]，不再移动）：

        列0     列1     列2
行0    w00     w01     w02
行1    w10     w11     w12
行2    w20     w21     w22

激活从左侧逐拍流入（错开一拍，形成斜波前），部分和向下逐列累加：

第 t 拍，进入 PE 的每个激活 a 与驻留权重 w 相乘，
加上从上方传下来的部分和，结果传给下方 PE：
    PE 计算：  下传部分和 = 上传部分和 + a × w
    同时把 a 向右传给同行下一个 PE

激活斜着注入（对角线波前），保证每个 PE 在正确的拍拿到
正确的 (激活, 权重) 配对；走完阵列后，每一列底部输出
就是输出矩阵对应位置的点积（一列权重 · 一段激活）。
```

激活向右传（复用给同行各 PE）、部分和向下累加（累积成点积）、权重钉在原地不动。为什么权重固定？因为推理时同一层权重要作用于一大批输入（batch 里很多样本、一张特征图很多位置），把权重装一次、让海量激活流过它反复使用，权重的加载成本被彻底摊薄——这是权重复用度最高的选择。作为对照，也存在"激活固定""部分和固定"等其它数据流（不同加速器的设计选择），它们在不同复用模式下各有优劣，但基本思想都是"让复用度最高的那个操作数驻留、让别的流过"。

初学者读这段最容易被"斜着注入"绊住。之所以要错开一拍让激活形成对角线波前，是因为脉动阵列靠"数据在正确的时刻到达正确的 PE"来省掉控制逻辑：第 j 列的 PE 要比第 j−1 列晚一拍拿到激活，这样部分和一路向下累加时，每一步加进来的正好是该配对的乘积。把它想成多条流水线错位排开即可，不必纠结每个下标——记住"权重驻留、激活横流、部分和纵累"这条主干就够了。

### 8.2.4 脉动阵列的吞吐与延迟

一个 N×N 的脉动阵列，在稳态下每个时钟每个 PE 都在做一次乘加，因此**每拍完成 N² 次乘加（MAC）**。把一次 MAC 记为 2 次运算（一乘一加），峰值算力为：

峰值算力 = 阵列行数 × 阵列列数 × 2 × 时钟频率

代入 TPU v1（256×256 阵列、700 MHz）：

峰值算力 = 256 × 256 × 2 × 700×10⁶ ≈ 9.2 × 10¹³ 次运算/秒 ≈ 92 TOPS（8 位整数）

这个约 92 TOPS 与 Jouppi 等 2017 年 TPU 论文及 H&P ch7 报告的 TPU v1 峰值一致（TOPS = Tera Operations Per Second，每秒万亿次运算；因是 8 位整数运算故用 OPS/TOPS 而非 FLOPS）。

但阵列不是一进就出，存在**填充与排空延迟**：数据要先流过整个阵列才有第一个结果出来，之后才进入满负荷稳态。对 N×N 阵列，从第一个激活进入到最后一列产出结果，填充延迟量级为：

填充延迟 ≈ 2N − 1 拍

于是脉动阵列的效率高度依赖"喂得够久够满"：只有当流过的数据量远大于 2N（即批量大、矩阵大），填充/排空的开销才被摊薄到可忽略，阵列才逼近峰值。这解释了一个初学者常困惑的现象——同一块 TPU，跑大 batch 的大矩阵乘能接近峰值，跑小 batch 或小矩阵却远达不到：不是硬件坏了，而是脉动阵列"启动开销大、要吃饱才划算"，这与本课大主题5 向量机的条带挖掘/启动延迟是同一类道理。8.5 的 Roofline 会把这件事量化成"算术强度不够就触不到算力屋顶"。

### 8.2.5 确定性执行与量化推理

TPU v1 刻意做成**确定性执行（deterministic）**：没有 cache（用软件管理的统一缓冲代替）、没有分支预测、没有乱序、没有多线程切换。因此一段给定的矩阵乘负载，其执行拍数是可精确预测的、每次都一样。这对数据中心推理服务是巨大优点——延迟可预测，能稳稳满足服务的响应时间上限（tail latency），不会像通用 CPU 那样因 cache 命中与否、分支猜中与否而抖动。这也是准则二"砍掉不确定性来源、换算术"的又一体现。

TPU v1 用 **8 位整数量化（quantization）**做推理：把训练好的浮点权重和激活映射到 8 位定点整数再计算。为什么可行？因为神经网络推理对数值精度有相当的容忍度，8 位往往足以维持模型精度，却能让同样面积塞进四倍于 32 位的乘加单元、片上多存四倍数据、带宽压力降四倍——直接兑现准则四"数据缩到最小"的全部好处。这是"降精度换吞吐与能效"的经典范例，也为 8.3 的 GPU 混合精度做铺垫（二者是同一思想在两类硬件上的不同实现）。

初学者要区分**推理**与**训练**这条分界。TPU v1 只做推理，用 8 位整数够用；但训练需要更宽的动态范围和梯度精度，8 位整数不够，所以从 TPU v2 起 Google 转向支持训练并引入 bfloat16 等浮点格式（见 8.2.6）。"推理可以很激进地降精度、训练要保守些"是贯穿整个 AI 加速器领域的重要直觉，后面张量核的精度格局也遵循同一逻辑。

## 8.3 GPU 张量核（AA-8.3）

### 8.3.1 张量核是什么

张量核（Tensor Core）是 NVIDIA 从 Volta 架构（V100，2017）起在 GPU 的流多处理器（SM）里加入的**专用矩阵乘加单元**。普通 GPU 的 CUDA 核每条指令做的是标量或短向量的乘加（本课大主题5 的 SIMT 通用运算），而一个张量核在一条指令里直接完成一个**小矩阵块的乘加**——早期为每拍一个 4×4×4 的矩阵乘累加（即 D = A×B + C，A、B、C、D 均为小矩阵块）。这等于把 8.2 那种"矩阵乘专用硬件"以小型单元的形式嵌进通用 GPU 里，让 GPU 既保留通用可编程性，又在深度学习最吃重的矩阵乘（GEMM）上获得数量级的吞吐提升。

理解张量核的关键，是把它看作"GPU 里的迷你脉动阵列/矩阵引擎"。TPU 是一整块巨大的脉动阵列专用芯片；张量核则是把矩阵乘能力切成许多小块，散布在通用 GPU 的每个 SM 中。二者走的是 DSA 光谱的不同位置：TPU 更专、能效更极致但只做这类负载；GPU + 张量核更通用、灵活性高，同一块卡既能跑图形、跑通用 CUDA，也能高速跑矩阵乘。这也解释了产业现状——训练大模型的人多用 GPU（生态与灵活性），而超大规模自有推理常用 TPU 这类更专的 DSA。

初学者别把张量核和 CUDA 核搞混：它们在同一个 SM 里共存，CUDA 核处理通用逐元素/控制类运算，张量核专门吃矩阵乘块。程序（或更常见地，底层库如 cuBLAS/cuDNN）会把一个大矩阵乘切成许多小块喂给张量核，由众多张量核并行吞吐。你写高层框架代码时通常感知不到它，是编译器和库在替你调度——这正好引出 8.4 的软硬协同。

### 8.3.2 混合精度（FP16 乘、FP32 累加）

张量核的标志性设计是**混合精度（mixed precision）**：输入的两个矩阵用较低精度（早期为 FP16 半精度）相乘，但乘积的累加在内部用较高精度（FP32 单精度）进行，最后按需输出。用一层数据流表达：

低精度输入 A、B（如 FP16） → 乘法 → 高精度累加器（FP32）逐项累加 → 结果（FP16 或 FP32）

为什么要这样"低精度乘、高精度加"？因为矩阵乘要把很多个乘积**累加**起来，如果全程用 FP16，累加会因动态范围和精度不足而严重丢位、误差累积；而用 FP32 累加器兜住累加过程，就能在几乎不损失最终数值质量的前提下，享受 FP16 输入带来的双份好处——同样面积/带宽下算术单元更多、数据更小搬得更快。这正是 8.1.3 准则四"数据缩到领域所需最小"与 8.2.5 TPU 量化思想在 GPU 上的对应实现。

初学者要记住混合精度的心法：**存储和乘法可以激进降精度，累加要保守留精度**。这与 8.2.5 "推理比训练更敢降精度"是同一族直觉的延伸。也要注意，混合精度是"硬件提供能力 + 软件正确使用"的配合——训练时通常还需配合损失缩放（loss scaling）等软件技巧防止 FP16 下溢，这属于软硬协同（8.4）范畴，此处只点到，不深入。

### 8.3.3 低精度格式家族（⚙演进快·锚版本）

随着代际推进，张量核支持的低精度格式不断扩充，几种关键格式的定位如下（格式的比特分配是定义性的、稳定的；**哪代硬件支持哪种则演进快，锚 2026-07**）。FP16（半精度）为 1 符号 + 5 指数 + 10 尾数，动态范围较窄。BF16（bfloat16）为 1 符号 + 8 指数 + 7 尾数——指数位与 FP32 一样多，故动态范围与 FP32 相当、只牺牲尾数精度，特别适合训练（不易溢出/下溢），由 Google Brain 提出并被 TPU v2、NVIDIA Ampere 等广泛采用。TF32（TensorFloat-32，Ampere 引入）内部用 8 位指数 + 10 位尾数做张量核累加的中间格式，兼顾 FP32 的范围与更高吞吐。FP8（Hopper 引入，含 E4M3、E5M2 两种分配）与更激进的 FP4/FP6（Blackwell 引入）进一步压低推理精度、换取更高吞吐。

初学者抓两条主线即可。其一，**指数位决定动态范围、尾数位决定精度**——BF16 之所以好训练，就是它宁可砍尾数也保住 8 位指数，保住范围；这解释了为什么"位数一样多"的 FP16 和 BF16 用途不同。其二，精度是**逐代往下探底**的：从 FP32 到 FP16/BF16 到 FP8 再到 FP4，每降一档，同硬件的矩阵乘吞吐大致翻番，代价是数值精度下降、越来越依赖软件技巧（缩放、混合精度、量化感知训练）来守住模型质量。这条"越来越低精度"的曲线是 AI 加速器十年演进的主旋律，也是 8.1.3 准则四被反复推向极限的过程。

### 8.3.4 张量核与脉动阵列的对照

把 8.2 的 TPU 脉动阵列和张量核并排看，能看清 DSA 的两种落地风格。相同点是内核都是"专用矩阵乘加单元 + 降精度 + 大规模并行 MAC"，都服务同一领域（深度学习的 GEMM）。不同点在于集成方式与灵活性：TPU 是**独立专用芯片**，一整块超大脉动阵列 + 软件管理的片上缓冲，确定性执行、能效极致，但只擅长这类负载；张量核是**嵌进通用 GPU 的众多小型矩阵单元**，与 CUDA 核、cache、SIMT 调度共存，灵活性和生态远好，代价是保留了更多通用开销、单位能效通常不及最专的 DSA。

实现细节上也有差异。经典脉动阵列靠数据在 PE 网格中逐拍流动、权重固定来复用（8.2.3）；张量核对程序员/库暴露的是"给定小矩阵块、一条指令算完块乘加"的抽象，其内部微架构由厂商实现（各代不同，不公开逐拍细节），并深度依赖 GPU 的寄存器/共享内存把数据喂进喂出。初学者不必纠结二者内部电路谁更像谁——记住定位差异即可：**同一个 DSA 思想（专用矩阵乘），一个做成整块专用芯片，一个做成通用芯片里的加速单元**，分别占据"更专更省"与"更通用更灵活"两端。这个对照也是 8.5 用 Roofline 把两类硬件放到同一张图上比较的基础。

### 8.3.5 张量核代际演进（⚙演进快·锚版本·随时变）

以下为产品代际快照，锚 2026-07，来自 NVIDIA 官方与公开报道；**演进极快，数字随时变**。第一代张量核 Volta（V100，2017）支持 FP16 混合精度。Turing（2018）增加 INT8/INT4 推理。Ampere（A100，2020）引入 TF32、BF16、结构化稀疏、FP64 张量核。Hopper（H100，2022）第四代引入 FP8 与 Transformer Engine。Blackwell（B200，2025）第五代把精度下探到 FP4/FP6，公开资料称 B200 稠密 FP4 张量运算达约 9 PFLOPS。Rubin（2026，GTC 2026 确认、下半年首批交付）换用 HBM4，公开资料称 FP4 算力约达 50 PFLOPS 量级。

对初学者，这张时间线要提取的是**规律**而非数字：每一代都在"更低精度 + 更大吞吐 + 更宽/更快存储 + 新的领域技巧（稀疏、Transformer Engine 等）"上迭代，与 8.2.6 的 TPU 曲线高度平行——两条独立的产品线被同一个领域需求（越来越大的深度学习/大模型）拉着朝同一方向跑。凡本报告出现的具体 PFLOPS/精度支持，请回 NVIDIA 官方架构白皮书核对当代规格，勿当长期结论。

## 8.4 软硬协同（AA-8.4）

### 8.4.1 为什么 DSA 必须软硬协同

DSA 交付的从来不只是一块芯片，而是**硬件 + 把领域程序高效映射到该硬件的整套软件栈**——这就是 8.1.3 准则五的实质。原因是 DSA 故意砍掉了通用处理器那些"自动适配任意程序"的动态机构（乱序、cache、动态调度），于是"什么数据在什么时候放哪、算术单元怎么排布、并行怎么切分"这些原本硬件在运行时替你搞定的事，现在必须由**编译期的软件**精确安排好。硬件只提供高效但"死板"的能力，软件负责把领域程序翻译成正好契合这套死板能力的形式；两边任何一边脱节，专用硬件的性能都兑现不出来。

通用 CPU 像一个能听懂各种模糊指令、自己随机应变的老练工人；DSA 像一条效率极高但只认标准化工序的自动化产线。产线本身再快，若没有把订单拆解成标准工序卡的"排产系统"（编译器）和让人下单的"标准工单格式"（领域语言），产线就转不起来。所以做 DSA 的团队里，编译器/软件栈的工作量往往不亚于硬件本身——这也是为什么 DSA 的成败常取决于软件生态（NVIDIA 的 CUDA 生态之强，是其护城河的核心）。

### 8.4.2 领域专用语言 DSL

领域专用语言（DSL, Domain-Specific Language）是为特定领域设计的编程语言或框架，让程序员用贴近领域概念、且**便于编译器优化到 DSA** 的方式表达计算，而不是用通用语言写死执行细节。深度学习领域的 TensorFlow、PyTorch 就扮演这种角色：你描述的是"这些张量做卷积、那些做矩阵乘"这样的**计算图**，而不是手写每个循环怎么在硬件上跑；图像处理领域的 Halide 则让你把"算什么"（算法）和"怎么在硬件上排布"（调度）分开写，H&P ch7 的 Pixel Visual Core 即用 Halide。

DSL 的关键价值在于**把"做什么"和"怎么做"解耦**。用通用语言写死了循环顺序、访存方式后，编译器很难再重排到另一套硬件上；而 DSL 让程序员只声明领域意图（一张计算图、一组张量运算），把"映射到具体 DSA 的哪个单元、怎么切块、怎么排布数据"留给编译器按目标硬件决定。这样同一段模型描述，能被编译到 CPU、GPU+张量核、TPU 等不同后端，各自跑出接近该硬件峰值的性能——这既是准则五的落地，也是为什么现代 AI 软件普遍是"高层框架 + 后端编译器"的两层结构。

初学者别把 DSL 想成"又要学一门新语言"。多数时候它就是你已经在用的框架 API（写 PyTorch/TensorFlow 就是在用 DSL）；它之所以叫"领域专用"，是因为它的抽象刻意收窄到张量运算/计算图，正是这种收窄让编译器有足够的语义信息去做激进的硬件专用优化——通用语言给不了这种信息。

### 8.4.3 领域专用编译器

领域专用编译器负责把 DSL 描述的计算图翻译并优化成目标 DSA 上的高效执行，是软硬协同的"排产系统"。深度学习领域的代表有 XLA（编译 TensorFlow/JAX 到 TPU、GPU 等）、TVM（面向多种后端的张量编译器）、以及作为通用编译基础设施的 MLIR（多层中间表示，让不同抽象层次的优化在统一框架里做）。它们做的核心优化包括：算子融合（把多个小算子合成一个内核，减少中间结果的存储与搬运）、按目标硬件的存储层次做数据切块（tiling）与布局变换、把矩阵乘映射到脉动阵列/张量核的块尺寸、以及自动选择精度与并行切分。

这些优化几乎每一条都直接呼应前几节的硬件事实。算子融合减少数据搬运，对应准则一和 8.1.2 "省搬运"的收益；切块与布局要匹配脉动阵列"喂满才划算"（8.2.4）和张量核的块尺寸（8.3.1）；精度选择对应混合精度与量化（8.2.5、8.3.2）。换句话说，编译器优化的清单，就是把硬件设计准则反过来在软件侧执行一遍——这正是"协同"二字的含义：硬件和编译器是照着同一套领域假设共同设计的，谁也离不开谁。

初学者不必掌握每个工具的细节，抓住一点即可：**DSA 的性能有很大一部分是编译器"编"出来的**。同一块 TPU/GPU，用好编译器（融合、切块、选精度得当）和不用，实测性能可能差几倍。这也解释了为什么"换了新硬件但软件栈没跟上"时，加速器常常跑不出标称性能——瓶颈在软件映射，不在硅片。

### 8.4.4 协同设计的迭代循环

软硬协同（hardware-software co-design）不是"先定硬件再写软件"的单向过程，而是**硬件与软件（及领域算法）互相迭代、共同演化**的循环。领域算法的新需求（如 Transformer 成为主流）会催生新的硬件特性（如 Hopper 的 Transformer Engine、各代新增的精度格式与稀疏支持）；反过来，硬件提供的新能力（如 FP8、结构化稀疏）又会反向影响算法与模型的设计（研究者据此设计对低精度更友好、更稀疏的模型）。8.2.6 与 8.3.5 那两条平行的代际曲线，本质就是这个循环在两条产品线上转了很多圈的结果。

DSA 时代，**算法、编译器、硬件是被一起设计的三位一体**，而不是三个独立环节。这与通用计算时代"软件写好丢给通用 CPU 自动跑快"的心智模型截然不同——那种时代靠 Dennard 缩放红利，软硬件可以各自独立演进；红利消失后（8.1.1），只有让三者协同、针对领域一起优化，才能继续大幅提效。这也是为什么本大主题反复强调"专用化"不只是硬件的事：脱离软件栈和领域算法谈 DSA，等于只造了半台机器。

## 8.5 DSA 上的 Roofline（AA-8.5）

### 8.5.1 Roofline 模型复习

Roofline 模型（Williams, Waterman & Patterson, 2009；本课大主题5 AA-5.5 已详）用一张对数-对数图把处理器的性能上界画成"屋顶"：横轴是算术强度 I（每搬运 1 字节数据所做的运算次数，FLOP/Byte 或 OP/Byte），纵轴是可达性能。核心公式是一个取小：

可达性能(I) = min( 峰值算力, 峰值内存带宽 × I )

脊点（两道屋顶的交点）对应的算术强度为：

I_ridge = 峰值算力 / 峰值内存带宽

I 小于脊点时性能被带宽斜线压住（带宽受限），大于脊点时被算力水平线压住（算力受限）。本节不重复推导（细节回看大主题5 报告），只做"面向 DSA"的应用：用 Roofline 来判断一个加速器在给定负载上到底跑得多满、被什么卡住。

初学者只需记住 Roofline 回答的问题："这台机器上这个核，天花板在哪、我离它多远、该往哪使劲。"它是**上界与诊断**工具，不是精确性能预测器。把它用到 DSA 上，就是要看 TPU、GPU 张量核这类"算力被堆得极高"的机器，在真实深度学习负载下有没有被带宽拖住。

### 8.5.2 为什么 DSA 的脊点普遍靠右

DSA（尤其 AI 加速器）为了极致吞吐，把峰值算力堆得极高（8.2.4 的几万个 MAC、8.3.5 的 PFLOPS 级张量核），而内存带宽虽然也用 HBM 猛堆，却涨得没有算力快。代入脊点公式，分子（峰值算力）涨得比分母（带宽）快，脊点 I_ridge 就**逐代右移**。脊点靠右意味着：只有算术强度**很高**的负载才够得着峰值算力屋顶，算术强度不够的负载会被死死压在带宽斜线下，无论算力堆得多高都用不上。

这解释了 AI 加速器领域一个反复出现的现象——"算力过剩、带宽吃紧"。芯片标称几百上千 TFLOPS，但很多真实负载（尤其访存密集、复用不足的）实际只用到其中一小部分，因为它们落在带宽屋顶下。初学者由此能理解为什么厂商每代都拼命堆 HBM 带宽、为什么"内存墙"是 AI 硬件的头号矛盾：不是算力不够，而是喂不饱那么多算力。这也回扣 8.1.3 准则一"最小化数据搬运"——脊点越靠右，减少搬运、提高数据复用（把算术强度做上去）就越是决定实际性能的关键。

### 8.5.3 用 Roofline 比较 TPU、GPU、CPU

H&P ch7 §7.9 的一个经典用法，是把 TPU v1、同期 GPU（NVIDIA K80）、同期 CPU（Intel Haswell）画到各自的 Roofline 图上，用同一批神经网络负载对比。方法是：为每台机器画出它的两道屋顶（各自的峰值算力和峰值带宽决定），再把每个负载按其算术强度和实测性能标成点，看点落在屋顶下的什么位置、离屋顶多远。这样比较的洞见在于——不能只比峰值算力数字，要看**在真实负载的算术强度处**，谁的屋顶更高、谁的点更贴屋顶（利用率更高）。

教材当年（2017）用这套方法得出的定性结论是：TPU 作为专用 DSA，在这些神经网络负载上相对当时的 CPU/GPU 有显著的性能与能效优势，且其点更贴近自身屋顶（专用化让它利用率高）。这里必须硬标时效——这是 **TPU v1 对 K80/Haswell** 的 2017 年结论，此后三方都历经多代演进（8.2.6、8.3.5），当年的相对优势数字**完全不能**外推到 2026 年的任何一代对比；把它当"TPU 就是比 GPU 快 N 倍"是典型的误用。

初学者要带走的是**方法**而非当年的具体倍数：比较不同架构时，Roofline 逼你在"真实负载的算术强度"这个公平的坐标上比，而不是比空洞的峰值。这能戳破很多"峰值营销"——峰值算力再高，若负载算术强度落在带宽屋顶下，两台机器的实际性能可能相差无几。

### 8.5.4 算术强度、批量与 DSA 效率

深度学习负载的算术强度差异很大，直接决定它在 DSA 上能不能跑满。矩阵乘/卷积这类操作，算术强度会随**矩阵规模和批量（batch size）增大而升高**——因为一次加载的数据被复用的次数更多（8.2.3 权重固定就是为了最大化复用）。所以同一块加速器，跑大 batch 的大矩阵乘容易触到算力屋顶（利用率高），跑小 batch、小矩阵或访存密集的算子（如逐元素操作、某些注意力/归一化）则容易掉到带宽屋顶下（利用率低）。这与 8.2.4 "脉动阵列要喂饱才划算"是同一件事在 Roofline 上的量化表达。

由此得出 DSA 上提升效率的方向，和 Roofline 的通用诊断（大主题5 AA-5.5.4）完全一致，只是语境换成加速器。若负载贴着带宽斜线（低算术强度），堆更多算力没用，该做的是**提高算术强度**——增大 batch、算子融合减少中间结果往返（8.4.3 编译器就干这个）、改善数据复用与片上驻留、用更低精度让同样字节搬进更多元素（8.3.2/8.3.3，等效于抬高每字节的运算数）。若负载已贴着算力屋顶，才轮到靠更高峰值算力或更高利用率去榨。

拿到一个"加速器跑不满"的抱怨，先估算负载的算术强度、判断它在斜线还是水平屋顶下，再决定动带宽相关手段还是动算力相关手段——而不是盲目怪硬件或盲目堆资源。Roofline 在 DSA 上最大的价值，就是拦住"给带宽受限的负载拼命堆算力"这类南辕北辙。

### 8.5.5 本机实证（不适用，标注）

本机无 TPU/张量核硬件，无法对 DSA 直接做 Roofline 实测，故本小主题的加速器数字一律标未取/不适用，不以本机 CPU 结果冒充加速器结论。Roofline 方法本身在本机 CPU 上的定性验证（带宽受限核加宽 SIMD 无收益、计算密集核加宽 SIMD 兑现）已在本课大主题5（AA-5.5.5）用 AVX-512 SAXPY 与计算密集多项式核做过，可作为"脊点两侧行为差异"的实物教具迁移理解到 DSA 场景，但那是 CPU 数据，不等于 TPU/GPU 的屋顶高度。

初学者据此要接受一个诚实的边界：本报告对 DSA 的 Roofline 论述是**原理 + 教材方法 + 厂商公开峰值**层面的，具体某代加速器在某负载下的实测点位置需要相应硬件才能坐实，此处不编造数字。要动手实测，应在具备目标加速器的环境用厂商工具（如 NVIDIA Nsight Compute 的 Roofline 分析）测算术强度与实测性能点，这属于 L6-06 HPC / N-11 AI 系统 的实践范畴。
