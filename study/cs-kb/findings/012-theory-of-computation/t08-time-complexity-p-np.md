## 8.1 复杂度度量（§7.1）

### 8.1.1 运行时间与时间复杂度类

一台图灵机 M 的**运行时间（running time）**或时间复杂度是一个函数 f(n)，表示 M 在任意长度为 n 的输入上运行时所走的**最大**步数。Sipser 3e Definition 7.1 采用**最坏情形（worst-case）**分析：对所有长度 n 的输入取步数上确界。相应地把「同一时间预算内能判定的语言」打包成一个类，Definition 7.7 记作

TIME(t(n)) = { L ｜ L 可被某个 O(t(n)) 时间的图灵机判定 }

这里「判定」沿用大主题04 的含义：对每个输入都停机，属于语言就接受、不属于就拒绝，绝不循环。

初学者要抓住两点。一是**为什么用最坏情形而不是平均**——最坏情形给的是「不管输入多刁钻都不会更慢」的硬保证，分析上也最干净（不必先假定输入的概率分布）。二是**运行时间是输入长度 n 的函数，n 是编码后的位数**，不是「数值大小」或「元素个数」的模糊说法；把一个整数 N 写成二进制只需约 log₂N 位，这个「位数」才是 n。后面 8.2 判 RELPRIME 在 P 里，全靠对这个 n 的正确理解。

### 8.1.2 大 O 与小 o 记号

大 O 记号刻画渐进**上界**。Sipser Definition 7.2：设 f, g 为定义在非负整数上、取正实数值的函数，称

f(n) = O(g(n))

当且仅当存在正整数 c 和 n₀，使得对所有 n ≥ n₀ 有

f(n) ≤ c · g(n)

小 o 记号刻画**严格更小**的增长。Definition 7.5：称 f(n) = o(g(n)) 当且仅当

lim (n→∞) f(n) / g(n) = 0

大 O 与小 o 的区别是初学者的第一个易错点：f(n) = O(g(n)) 允许两者同阶（差一个常数倍即可，例如 2n² = O(n²)）；f(n) = o(g(n)) 则要求 f 被 g **甩开**、比值趋于 0（例如 n = o(n²)，但 n² ≠ o(n²)）。复杂度理论里大 O 用得最多，因为我们只关心「随规模怎么长」而不在乎常数因子——常数因子会随机器型号、编码方式变动，而增长阶不会。这也解释了下一条：多项式与指数的鸿沟远比常数因子重要。

### 8.1.3 计算模型对运行时间的影响与多项式等价

同一个问题换一种图灵机模型，运行时间可能变，但**只在多项式范围内变**，这条「鲁棒性」是整个 P/NP 理论能立住的地基。Sipser 给了两条关键定理。Theorem 7.8：任何在 t(n) 时间内运行的**多带**图灵机，都有一台等价的**单带**图灵机在 O(t²(n)) 时间内运行（要求 t(n) ≥ n）。也就是多带到单带的代价是**平方级**——多项式。Theorem 7.11 则揭示另一道鸿沟：任何在 t(n) 时间内运行的**非确定**单带图灵机，都有一台等价的**确定**单带图灵机在

2^O(t(n))

时间内运行——这个代价是**指数级**，不再是多项式。

把这两条并读，初学者就能理解为什么理论上「合理」的确定性模型（单带 TM、多带 TM、随机存取机 RAM 等）彼此只差多项式，于是「多项式时间可解」是一个**与具体机器无关**的稳健概念；而确定与非确定之间目前只知道有指数级的模拟代价，这道确定/非确定的缝，正是 P vs NP 的雏形。这也是为什么复杂度理论把「多项式 vs 超多项式」当作「易 vs 难」的分界线，而不去区分 n² 与 n³——前者跨模型稳定，后者不稳定。这一思想在 CLRS 4e §34.1 以「多项式相关的编码之间可互相多项式转换」的形式独立给出，与 Sipser 相互印证。

- 交叉核对：CLRS 4e §34.1「多项式相关编码」与「多项式时间对合理模型稳健」的论述与 Sipser 一致；渐进记号定义交叉 CLRS 4e Ch3、Hopcroft–Motwani–Ullman Ch10.1，三者对大 O/小 o 定义一致。

## 8.2 类 P（§7.2）

### 8.2.1 类 P 的定义

类 P 是「确定性单带图灵机在多项式时间内可判定的语言」的全体。Sipser 3e Definition 7.12：

P = ∪ₖ TIME(nᵏ)

其中并集对所有常数 k ≥ 1 取。等价地说，L ∈ P 当且仅当存在常数 k 与一个判定 L 的算法，其运行时间是 O(nᵏ)。

直觉上，**P 就是「实践中真算得动」的问题类**：多项式（n、n²、n³……）随规模温和增长，而指数（2ⁿ）会迅速爆炸到宇宙年龄也算不完。为什么用多项式而非某个具体的 n² 当分界？因为多项式类对「合理编码 + 合理模型」都封闭（多项式的和、积、复合仍是多项式，见 8.1.3），换机器、换编码只差多项式因子，界线不会挪动——这正是 Cobham–Edmonds 论题的内容。要注意这是一条**理论分界**：n¹⁰⁰ 在数学上算多项式却毫不「实用」，但作为「易/难」的粗分类，多项式是公认最合适的一刀切。

### 8.2.2 PATH 属于 P

PATH 问题问「有向图里从 s 到 t 有没有一条有向路径」，形式化为

PATH = { ⟨G, s, t⟩ ｜ G 是有向图，且存在从 s 到 t 的有向路径 }

Sipser Theorem 7.14 证明 PATH ∈ P。

关键教学点在于「朴素想法为什么不够」。若暴力枚举所有路径，路径条数可随节点数指数增长，那是指数时间。多项式算法改用**标记扩散（图搜索）**：先标记 s，然后反复扫描——只要有一条边从「已标记」节点指向「未标记」节点，就把后者也标记，直到没有新节点可标记；最后看 t 是否被标记。每一轮至少新标记一个节点，故最多 n 轮，每轮扫描所有边，总时间是节点数与边数的多项式。这正是广度/深度优先搜索的雏形。可选实测（脚本见文末环境说明）：在链 0→1→2→3 上判 0 能否到 3 得 `True`，删去中间边后得 `False`，与手算一致。

### 8.2.3 RELPRIME 属于 P

RELPRIME 问「两个整数是否互质（最大公约数为 1）」，形式化为

RELPRIME = { ⟨x, y⟩ ｜ x 与 y 互质 }

Sipser Theorem 7.15 证明 RELPRIME ∈ P，算法是**欧几里得算法（辗转相除）**。

这个例子专门用来敲碎一个经典陷阱——**输入长度按位数算，不按数值算**。若「试除法」逐个试 2, 3, …, min(x,y) 是否为公约数，试除次数正比于数值 x，而数值 x 是其二进制长度 n 的**指数**（x ≈ 2ⁿ），所以试除法是指数时间、**不**在 P 的多项式判据内。欧几里得算法反复做 (x, y) → (y, x mod y)，可证每两步余数至少减半，因此步数是 O(n) 级（n 为输入位数），每步一次带余除法也是多项式，总体多项式。初学者由此要建立习惯：判断「多项式与否」永远先问「输入规模 n 是几位」。可选实测：对 1..59 全部数对，自实现的欧几里得递归与 Python 内置 `math.gcd` 判互质结果**完全一致**（输出 `True`）。

### 8.2.4 每个上下文无关语言都属于 P

Sipser Theorem 7.16：每一个上下文无关语言（CFL）都在 P 中。

这条把大主题03 的成果接进复杂度框架。朴素地按文法尝试所有派生可能指数爆炸，但用**动态规划**（本质是 CYK 算法的思路，先把文法化成 Chomsky 范式，再自底向上填一张记录「哪段子串能由哪个变元派生」的表）可在 O(n³) 时间判定成员资格。教学意义是：正则语言、上下文无关语言这些「弱机器」识别的语言不仅可判定，而且**多项式可判定**——它们稳稳落在 P 内，难度问题只在图灵机层面的通用问题上才真正紧张起来。

#### 来源与时效
- 锚点：Sipser 3e §7.2「The Class P」——Def 7.12（P = ∪ₖ TIME(nᵏ)）、Thm 7.14（PATH∈P）、Thm 7.15（RELPRIME∈P，欧几里得）、Thm 7.16（每个 CFL∈P）；核实 2026-07-26。
- 交叉核对：CLRS 4e §34.1 类 P 定义（多项式时间可判定）与 Sipser 一致；一元/二进制（伪多项式）陷阱在 CLRS §34.5 子集和处独立点明，与本节 RELPRIME 陷阱同理相互印证；CFL∈P 的 O(n³) DP 交叉 Hopcroft–Motwani–Ullman（CYK）。
- 可选实测（直觉演示，非证明）：PATH 的图搜索、RELPRIME 的欧几里得对拍 `math.gcd`，输出见 8.2.2 / 8.2.3。
- 无冲突项。

## 8.3 类 NP（§7.3）

### 8.3.1 一个动机问题：HAMPATH

哈密顿路径问题问「有向图里从 s 到 t 有没有一条恰好经过每个节点一次的路径」，形式化为

HAMPATH = { ⟨G, s, t⟩ ｜ G 是有向图，存在从 s 到 t 恰好过每个节点一次的路径 }

目前无人知道 HAMPATH 是否在 P 里；已知最好的确定算法在最坏情形仍是指数级。

但 HAMPATH 有一个救命特征：**如果有人塞给你一条声称是哈密顿路径的节点序列，你能很快核对它对不对**——只需检查它是否从 s 到 t、每个节点恰好出现一次、相邻两点间确有边，全是多项式时间的检查。「找」很难，「验」却容易——这个不对称正是类 NP 要捕捉的东西。初学者可用「拼图/密码」类比：拼好一张拼图或猜出密码可能极难，但**验证**一张拼好的图、或**验证**一个密码对不对，往往一眼可辨。

### 8.3.2 验证器与类 NP 的定义

Sipser 3e Definition 7.18：语言 A 的一个**验证器（verifier）**是一个算法 V，满足

A = { w ｜ 对某个字符串 c，V 接受 ⟨w, c⟩ }

这里 c 叫**证书（certificate）**或证明。称 V 是**多项式时间验证器**，若它的运行时间是 |w|（输入本身长度）的多项式。Definition 7.19 据此定义：

NP = { A ｜ A 有一个多项式时间验证器 }

初学者要盯住两个细节，否则定义会走样。第一，运行时间是按 **|w|（原输入长度）**的多项式来算，这就隐含证书 c 也只能是 |w| 的多项式长（太长的证书验证器根本读不完），所以证书不能「把答案偷藏成天文数字」。第二，定义里是「**对某个** c，V 接受」——只要存在一张能让 V 通过的证书就算 w∈A；若 w∉A，则**任何** c 都无法让 V 接受。这正好对上 8.3.1 的直觉：证书就是那条待核对的哈密顿路径，验证器就是那套多项式检查。可选实测：为 CLIQUE 写的证书验证器，对图 {01,12,02,23} 验证节点集 {0,1,2} 构成 3-团得 `True`，验证 {0,1,3} 得 `False`（因 1–3 无边），与定义一致。

### 8.3.3 非确定图灵机刻画与 NTIME

类 NP 有一个等价的、看起来毫不相干的定义。Sipser Theorem 7.20：

一个语言在 NP 中，当且仅当它能被某台**非确定**图灵机在多项式时间内判定。

配套 Definition 7.21 给出非确定时间类 NTIME(t(n)) = { L ｜ L 可被 O(t(n)) 时间的非确定 TM 判定 }，于是 Corollary 7.22：

NP = ∪ₖ NTIME(nᵏ)

这就是缩写 NP 的真正来历——**N**ondeterministic **P**olynomial time（非确定多项式时间），**不是**望文生义的「Not Polynomial」，这是初学者的头号误解，务必纠正。

两个定义为何等价，直觉上很顺：非确定机在每个分叉点可以「猜」一位，一条成功的计算分支所猜出的那串选择，恰好就是验证器要的证书；反过来，给定验证器，就造一台非确定机先非确定地「猜」出整张证书、再模拟验证器核对。「猜一张证书再验证」与「非确定地并行探索所有分支」是同一件事的两种说法。这个双视角很有用：定义验证器时用「找证书」的说法最自然（8.3.1 的 HAMPATH），而证明 Cook–Levin（8.5）时用「非确定机的计算表」的说法最顺手。

### 8.3.4 NP 中的更多实例：CLIQUE 与 SUBSET-SUM

团问题问「无向图里有没有 k 个两两相连的节点」，形式化为

CLIQUE = { ⟨G, k⟩ ｜ G 是无向图，含一个 k-团 }

Sipser Theorem 7.24：CLIQUE ∈ NP（证书就是那 k 个节点，验证器检查它们两两有边）。

子集和问题问「一组数里有没有一个子集加起来正好等于目标 t」，形式化为

SUBSET-SUM = { ⟨S, t⟩ ｜ S = {x₁,…,xₖ}，存在子集其元素之和为 t }

Sipser Theorem 7.25：SUBSET-SUM ∈ NP（证书是那个子集，验证器把它们加起来核对是否等于 t）。

这两个实例的意义是让「验证器/证书」从抽象定义落到具体：证书总是那个「解本身」（哪几个节点、哪几个数），验证器总是「拿着解做一遍多项式检查」。初学者到此应能对任意「找起来像很难、验起来很容易」的问题，自己说清它的证书和验证器是什么——这是理解 NP 的操作性标准。

#### 来源与时效
- 锚点：Sipser 3e §7.3「The Class NP」——HAMPATH 动机、Def 7.18（验证器）、Def 7.19（NP）、Thm 7.20（NP ⇔ 非确定多项式时间可判定）、Def 7.21（NTIME）、Cor 7.22（NP=∪NTIME(nᵏ)）、Thm 7.24（CLIQUE∈NP）、Thm 7.25（SUBSET-SUM∈NP）；核实 2026-07-26。
- 交叉核对：CLRS 4e §34.2「多项式时间验证」以证书/验证器定义 NP，与 Sipser Def 7.18–7.19 一致；「NP 即 Nondeterministic Polynomial」在 CLRS §34.2 与 Hopcroft–Motwani–Ullman Ch10.1 均明确，交叉纠正「Not Polynomial」误解。

## 8.4 P vs NP 问题（§7.3）

### 8.4.1 问题陈述与已知包含关系

P vs NP 追问的是这样一件事——**每一个「解能被快速验证」的问题，是不是也「能被快速求解」**？用类的语言就是问

P = NP ？

目前确凿知道的只有一侧包含：

P ⊆ NP

理由极简单——若一个问题自己就能多项式时间求解，那就干脆把「解」当成空证书，用求解算法本身当验证器，它自然多项式时间可验证。悬而未决的是反方向 NP ⊆ P 是否成立，也就是 P 与 NP 到底是相等还是 P ⊊ NP。

初学者常问「不是已经有一堆算不动的 NP 问题了吗，怎么还没解决」。要点在于：我们**没有证明**任何 NP 问题「必然」需要超多项式时间——只是**至今没找到**它们的多项式算法。「找不到」不等于「不存在」，把「不存在快速算法」严格证出来，正是这道难题的硬核，而这类下界证明恰恰是数学上最难的一类。

### 8.4.2 两种可能各意味着什么

若 P = NP 成立，则每个能高效验证的问题都能高效求解：意味着密码学（其安全性大量建立在「某些 NP 问题难解」上）会大面积崩塌，同时最优化、定理自动证明、蛋白质折叠等海量实际难题都会突然变得可高效解决——世界会天翻地覆。若 P ≠ NP 成立（这是学界主流相信的方向），则确实存在「验得快却解不快」的问题，NP 完全问题（8.5–8.6）就是这堵墙上撞不过去的那批，现今基于计算困难性的密码学也就有了坚实地基。

初学者要接受的一个反直觉事实是：**这两种可能哪个为真，目前谁也没证出来**，尽管绝大多数专家凭经验押注 P ≠ NP。「大家都相信」不是「已经证明」；复杂度理论里「相信」与「证明」之间隔着的，恰恰就是这道千禧难题。

### 8.4.3 时效状态（硬标：截至 2026-07-26 仍未解，演进随时变）

P vs NP 是 Clay 数学研究所设立的七大千禧年难题之一，悬赏一百万美元。**截至本报告核实日 2026-07-26，它仍然未解**；七题中唯一被解决的是庞加莱猜想（且获奖者拒领奖金）。这是一个演进随时可变的时效项：任何号称的证明都需经同行评议长期检验，历史上多次「已证明」的公告最终都被找出漏洞而作废。引用本结论时应随时以最新的权威动态（如 Clay 官网、复杂度理论社区）复核，本报告在核实日维持「未解」这一唯一负责任的结论，不对任何未定型的证明尝试下判断。

## 8.5 NP 完全性与 Cook–Levin（§7.4）

### 8.5.1 多项式时间归约 ≤ₚ

要谈「NP 里最难的问题」，先要有一把「A 不比 B 难」的尺，这把尺是**多项式时间（映射）归约**。Sipser 3e Definition 7.29：语言 A **多项式时间可归约**到 B，记

A ≤ₚ B

当且仅当存在一个多项式时间可计算的函数 f : Σ* → Σ*，使得对每个 w，

w ∈ A ⟺ f(w) ∈ B

f 把 A 的实例「翻译」成 B 的实例，且保持「是/否」答案不变。由此立得 Sipser Theorem 7.31：

若 A ≤ₚ B 且 B ∈ P，则 A ∈ P

初学者的直觉抓手是「用 B 的解法解 A」：要判 w 是否属于 A，先花多项式时间把它翻译成 f(w)，再用 B 的多项式算法判 f(w) 是否属于 B，答案照搬即可；两段都多项式，合起来还是多项式。所以 ≤ₚ 读作「A 的难度不超过 B」——B 能高效解则 A 也能。要注意方向：A ≤ₚ B 说的是「B 至少和 A 一样难」，箭头是把待解的 A 归约**到**已知工具 B，方向别记反（这是最常见的错误）。

### 8.5.2 NP 完全性的定义与两条支柱定理

Sipser 3e Definition 7.34：语言 B 是 **NP 完全（NP-complete）**的，若同时满足

（一）B ∈ NP；

（二）NP 中的每一个语言 A 都满足 A ≤ₚ B。

条件（二）说 B「至少和 NP 中所有问题一样难」，这样的 B 叫 NP 难（NP-hard）；再加上 B 自己也在 NP 里（条件一），就是 NP 完全——它是 NP 内部「最难的一档」的代表。

两条定理说明它为什么重要。Theorem 7.35：

若 B 是 NP 完全且 B ∈ P，则 P = NP

这说明只要**任何一个** NP 完全问题被找到多项式算法，整个 NP 就整体塌进 P。Theorem 7.36：

若 B 是 NP 完全，C ∈ NP，且 B ≤ₚ C，则 C 也是 NP 完全

这是**扩散机制**：手里已有一个 NP 完全的 B，只要把它归约到某个 NP 里的新问题 C，C 就跟着 NP 完全。于是证明「新问题 NP 完全」不必每次都对回所有 NP 语言，只需从**一个**已知 NP 完全问题归约过去即可——但这条流水线得先有「第一个」NP 完全问题来启动，那正是 Cook–Levin 定理的使命。

### 8.5.3 Cook–Levin 定理：SAT 是 NP 完全的

布尔可满足性问题 SAT 问「一个布尔公式有没有一组变元真假赋值使它为真」：

SAT = { ⟨φ⟩ ｜ φ 是可满足的布尔公式 }

Cook–Levin 定理（Sipser 3e Theorem 7.37）：

SAT 是 NP 完全的

这是复杂度理论的奠基结果，由 Cook（1971）与 Levin（1973，独立）证明，它提供了那个「第一个」NP 完全问题，此后所有 NPC 证明都能踩着它、经 Theorem 7.36 扩散出去。

SAT ∈ NP 是容易的一半（证书就是那组满足赋值，验证器代入求值一遍）。难的一半是要证 **NP 中每个语言 A 都 ≤ₚ SAT**，即对任意 A 都造出多项式时间的翻译。初学者只需看懂下面 8.5.4 的构造脉络，不必啃逐格推导。

### 8.5.4 构造脉络：把「非确定机的一次接受计算」编码成布尔公式

设 A ∈ NP，由某台非确定图灵机 N 在 O(nᵏ) 时间内判定。核心想法是把 N 在输入 w 上的一次运行画成一张**计算表（tableau）**：一个 nᵏ 行 × nᵏ 列的方格表，第 i 行是运行到第 i 步时的整条格局（纸带内容 + 状态 + 读写头位置），每格填一个来自 C = Q ∪ Γ ∪ {#} 的符号（# 是行边界）。因为 N 至多走 nᵏ 步、读写头至多够到第 nᵏ 格，这张表边长 nᵏ 就够用。「N 接受 w」等价于「存在一张各步都合法、且某处出现接受状态的计算表」。

归约函数 f(w) 造出一个布尔公式 φ，让「φ 可满足」恰好对应「存在这样一张接受计算表」。为每个格子 (i,j) 与每个符号 s 设一个布尔变量

x_{i,j,s}（取真表示第 i 行第 j 列那一格填的是符号 s）

然后 φ 写成四块的合取：

φ = φ_cell ∧ φ_start ∧ φ_move ∧ φ_accept

四块各管一件事：φ_cell 保证每一格**恰好填一个**符号（不空、不重）；φ_start 保证第一行正是输入 w 的**起始格局**；φ_accept 保证表中**某处出现接受状态** q_accept；φ_move 是灵魂——它逐个检查表中每一个 2×3 的小窗口是否符合 N 的转移规则，只要所有相邻两行的每个局部窗口都「合法」，整张表就是 N 的一次真实合法运行。之所以只查 2×3 局部窗口就够，是因为图灵机一步只改动读写头附近的常数个格子，格局的其余部分原样抄下——局部合法即全局合法。

表有 nᵏ × nᵏ = n^{2k} 个格子，变量数与 |C| 成正比也是 n^{2k} 级；四块公式里 φ_move 项数正比于窗口数（约 n^{2k} 个），每项大小是只与 N 有关的常数，故 φ 总长是 n 的多项式，且能在多项式时间内机械地写出来。这就凑齐了「多项式时间可计算的 f，w∈A ⟺ f(w)∈SAT」。初学者记住这条脉络即可：**变量记录每格填什么 → 四块合取分别管『格子合法/起点对/有终点/每步转移合法』→ 公式可满足 ⟺ 存在接受计算 → 规模多项式**。

### 8.5.5 从 SAT 到 3SAT

3SAT 是 SAT 限制到「合取范式且每个子句恰好 3 个文字」的版本。Sipser 3e Corollary 7.42：

3SAT 也是 NP 完全的

方法是把 8.5.4 得到的一般公式 φ 多项式时间改写成等可满足的 3-cnf 公式（长子句用引入新变量的标准手法拆成一串 3 文字子句，短子句用重复文字补齐），保持可满足性不变。3SAT 之所以重要，是因为它「形状整齐」，做后续归约（8.6）时比一般 SAT 好摆弄，几乎成了所有 NPC 归约的标准出发点。

#### 来源与时效
- 锚点：Sipser 3e §7.4「NP-completeness」——Def 7.29（≤ₚ）、Thm 7.31（A≤ₚB 且 B∈P ⟹ A∈P）、Def 7.34（NP 完全）、Thm 7.35（NPC∈P ⟹ P=NP）、Thm 7.36（归约扩散）、Thm 7.37（Cook–Levin：SAT NP 完全，含 φ_cell/φ_start/φ_move/φ_accept 与 2×3 窗口构造）、Cor 7.42（3SAT NP 完全）；核实 2026-07-26。
- 交叉核对：CLRS 4e §34.3–34.4 给同一套多项式归约与 NP 完全定义、并同证「电路可满足性/SAT NP 完全」；史料一手 Cook 1971（STOC）首证、Karp 1972 扩散出 21 个 NPC 问题——三源对「SAT 为奠基性第一个 NPC 问题」一致。注：CLRS 从**电路可满足性 CIRCUIT-SAT** 起手再到 SAT，Sipser 从**计算表编码**直接到 SAT——路线不同但结论与构造精神一致，无实质冲突。
- 可选实测（直觉演示，非证明）：见 8.6 的 3SAT≤ₚCLIQUE 对拍；Cook–Levin 全证本身为纯理论，无实证。
- 无冲突项（CLRS 与 Sipser 的起手问题差异已并列说明，非分歧）。

## 8.6 更多 NP 完全问题（§7.5）

### 8.6.1 归约链的全景

有了 Cook–Levin 提供的第一个 NPC 问题，其余经典问题的 NP 完全性都靠**从 3SAT 出发的一条条多项式归约**接力证得（Theorem 7.36 保证「归约到 NP 里的问题就传染 NP 完全」）。Sipser 3e §7.5 走的主链大致是

3SAT ≤ₚ CLIQUE，3SAT ≤ₚ VERTEX-COVER，3SAT ≤ₚ HAMPATH ≤ₚ UHAMPATH，3SAT ≤ₚ SUBSET-SUM

每证一个新问题 NPC，只需（一）说明它在 NP 里，（二）从某个已知 NPC 问题多项式归约到它。初学者要建立的全局图景是：**NPC 问题不是一堆孤立的难题，而是被归约这张网绑在一起的「等难度俱乐部」**——它们要么随 P=NP 一起全部变易，要么一起保持难解，命运共享。

### 8.6.2 3SAT ≤ₚ CLIQUE

Sipser 3e Theorem 7.32：3SAT 多项式时间可归约到 CLIQUE，故 CLIQUE 是 NP 完全的。

给定有 k 个子句的 3-cnf 公式，为每个子句造一「组」共 3 个节点（对应该子句的 3 个文字）。两个节点之间连边，当且仅当它们**属于不同子句**且**不互相矛盾**（不是同一变量的正负两形，如 x 与 ¬x 不连）。则公式可满足 ⟺ 该图有一个 k-团。直觉是：一个 k-团必然从 k 个不同子句里各选一个节点（同组内部不连边，选不出两个），团内无矛盾就意味着能一致地把这些文字都赋成真，即每个子句都被满足；反之亦然。可选实测：把上述归约实现，对 400 个随机 3-cnf 小实例，用暴力 SAT 判可满足与用暴力找 k-团判有无 k-团，两者结果**完全一致**（输出 `True`），佐证归约保答案。

### 8.6.3 3SAT ≤ₚ VERTEX-COVER

顶点覆盖问题 VERTEX-COVER 问「无向图里能否用 k 个节点『盖住』所有边（每条边至少有一端被选）」。Sipser 3e Theorem 7.44：VERTEX-COVER 是 NP 完全的（由 3SAT 归约）。

构造用两种「小零件（gadget）」：每个变量造一个「变量零件」——一条连接 x 与 ¬x 的边（覆盖它必须至少选一端，对应给该变量定真/假）；每个子句造一个「子句零件」——一个三角形（3 个节点对应子句 3 文字，覆盖三角形至少要选 2 个）。再把子句零件的节点连到对应文字在变量零件里的那一端。取覆盖预算

k = m + 2l （m 为变量数，l 为子句数）

可以证明，公式可满足 ⟺ 该图有大小为 k 的顶点覆盖。直觉是变量零件每个必选 1 个（定变量真假）、子句零件每个必选 2 个，剩下那 1 条通往「被满足的那个文字」的边由变量端来盖——盖得住当且仅当每个子句都有一个为真的文字。

### 8.6.4 HAMPATH 与 UHAMPATH

Sipser 3e Theorem 7.46：HAMPATH（有向哈密顿路径，8.3.1 已定义）是 NP 完全的，由 3SAT 经一套精巧的「菱形（diamond）小部件」归约得到——每个变量用一个可从左往右或从右往左穿行的菱形结构编码真/假，每个子句用一个必须被「经过」的节点编码，路径能一笔走完当且仅当公式可满足。Theorem 7.55 进一步把无向版

UHAMPATH = { ⟨G, s, t⟩ ｜ 无向图 G 有从 s 到 t 的哈密顿路径 }

也证成 NP 完全（由 HAMPATH 归约，每个有向节点拆成入/中/出三个无向节点以强制方向）。

初学者不必记菱形部件的逐节点接线，只需把握归约的通用套路：**用图上的局部结构模拟「变量的真假选择」和「子句的被满足约束」，让一条合法的哈密顿路径恰好对应一组满足赋值**。这与 8.6.2、8.6.3 是同一种「零件编码」思想的不同实现。

### 8.6.5 SUBSET-SUM

Sipser 3e Theorem 7.56：SUBSET-SUM（8.3.4 已定义）是 NP 完全的，由 3SAT 归约。

构造把每个变量和每个子句都对应成一些**十进制大数**：数字的每一位（列）对应一个变量或一个子句，精心设置各数在各列的取值与目标 t，使「选出一个子集正好加到 t」恰好编码「每个变量取唯一真假、且每个子句至少被一个真文字满足」。之所以能用「加法不进位地各列独立」，靠的是把基数取得足够大、让每列的和不会溢出干扰邻列。这个归约展示了 NP 完全性能跨越「图问题」与「数论/算术问题」两个看似无关的世界。

SUBSET-SUM 的经典动态规划（按目标值 t 建表）是**伪多项式**——它对 t 的数值线性，但对 t 的二进制**位数**是指数，故并不证明 SUBSET-SUM∈P，与其 NP 完全性并不矛盾（呼应 8.2.3 的「按位数算规模」）。

- 锚点：Sipser 3e §7.5「Additional NP-complete Problems」——Thm 7.32（3SAT≤ₚCLIQUE）、Thm 7.44（VERTEX-COVER，k=m+2l 零件构造）、Thm 7.46（HAMPATH，菱形部件）、Thm 7.55（UHAMPATH）、Thm 7.56（SUBSET-SUM，十进制大数编码）；核实 2026-07-26。
