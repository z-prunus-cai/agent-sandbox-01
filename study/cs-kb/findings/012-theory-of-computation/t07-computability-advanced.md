## 7.1 递归定理（§6.1）

### 7.1.1 自指的核心：程序可以取得自己的描述

递归定理（recursion theorem）背后的核心事实是：一台图灵机可以在运行时**获得自己的完整描述**（自己的源码），并把它当作数据来用。这听起来像"先有鸡还是先有蛋"——机器的描述要先写好才能运行，怎么在运行时又引用到还没写完的自己？递归定理正是说明这种自指**不循环、总能构造出来**。

Sipser 3e 用一个引理式构造打底：存在一台图灵机 SELF，它不读输入、直接把自己的描述 ⟨SELF⟩ 打印到带上并停机。它的做法是把机器拆成两段 A 和 B：A 段是"打印出 B 的描述"这段固定代码，B 段读带上 A 留下的内容后，反推出 A 的描述、再拼上 B 自己，合成完整的 ⟨AB⟩。

初学者最容易卡在"B 怎么知道自己长什么样"。关键技巧是**不对称**：B 不直接引用自己，而是从"A 打印出来的东西"里**重建** A，再把 B 自己的固定代码接上去。因为 B 的代码是我们写死的常量，B 里可以内嵌一段"制造任意串 s 的打印机"的模板 q(s)，于是"打印我自己"被拆成了"打印对方 + 从对方重建我"两个都可具体写出的步骤。这正是下一节 quine 程序用的同一套把戏。

### 7.1.2 递归定理的陈述（Theorem 6.3）

递归定理把上面的自指能力一般化：任何图灵机在计算时，都可以额外免费得到一份"自己的描述"作为输入。Sipser 3e Theorem 6.3 的陈述是：

设 T 是一台计算函数 t : Σ\* × Σ\* → Σ\* 的图灵机；则存在一台计算函数 r : Σ\* → Σ\* 的图灵机 R，使得对每个 w：

r(w) = t(⟨R⟩, w)

可以这样直观地读它——你可以随便写一个"想用到自己源码 ⟨R⟩"的程序 T（它把 ⟨机器⟩ 当第一个参数 dₒ），定理保证真的存在这样一台 R，它运行时第一个参数就自动填成了它**自己**的描述 ⟨R⟩。换句话说，"在代码里合法地写下 `⟨我自己⟩`"这件事是被允许的——编程时可以直接假设"我能拿到自己的源码"，不必真去构造 SELF。

初学者应把它当成一条**编程许可证**而不是一个要背的公式：以后设计图灵机时，只要想用到自己的描述，就直接写"令 ⟨M⟩ 为本机的描述……"，递归定理保证这样的机器存在。它与数学里的"不动点"是同一精神（见 7.1.4 的 Theorem 6.8）。

### 7.1.3 quine：自我复制程序的直觉

最贴近日常的例子是 **quine**——一段不读任何输入、却能原样打印出自己源码的程序。quine 是递归定理在真实编程语言里的化身：SELF 打印 ⟨SELF⟩，quine 打印自己的源码，是同一件事。

它的写法就是 7.1.1 的"两段式"：把源码分成"数据部分 s"和"用 s 重建整段代码的指令"，让数据 s 恰好编码了指令本身。一个 56 字节的 Python quine：

s = 's = %r\nprint(s %% s, end="")'

print(s % s, end="")

本机实证（直觉演示，非证明）：把它存成文件运行，输出与源码逐字节相等（`QUINE_SELF_REPRODUCES: True, len=56`）。`%r` 取字符串的"带引号可回读"表示，于是 `s % s` 先重建出第一行的数据、再拼出第二行的打印指令——数据描述了指令，指令又打印了数据，闭环。

这里要强调，quine 只是**直觉演示**，不是递归定理的证明。它让人相信"程序引用自身"可以实现，但定理的力量在于它对**任意**计算 t 都成立，且是在图灵机模型里严格构造出来的。

### 7.1.4 递归定理的应用

递归定理最常见的用途是给不可判定性/不可识别性一个**更短、更直觉**的证明：不再显式做对角化，而是"假设判定器存在，就造一台用递归定理拿到自己描述、然后专门跟判定器对着干的机器"，导出矛盾。

用它重证 A_TM 不可判定（Sipser 3e Theorem 6.5）：假设 H 判定 A_TM，构造 B——B 用递归定理取得自己的描述 ⟨B⟩，在自身输入 w 上问 H"⟨B⟩ 在 w 上会接受吗"，然后**做相反的事**（H 说接受就拒绝，反之接受）。B 于是与 H 的判断处处矛盾，H 不存在。这比第 5 章的对角化更省力，因为自指被递归定理一次性提供了。

另一应用是 MIN_TM 不可图灵识别（Sipser 3e Theorem 6.7）：MIN_TM 是所有"最小"（没有更短的等价机描述，Definition 6.6）图灵机描述的集合。若有枚举器 E 列出 MIN_TM，就造一台 C 用递归定理拿到 ⟨C⟩、扫描 E 的输出直到找到一台比自己**更长**的最小机 D，然后模拟 D——C 与 D 等价却比 D 短，与"D 最小"矛盾。

递归定理还有个等价的"不动点"面孔（Sipser 3e Theorem 6.8）：对任意可计算的程序变换 t，总存在一台机器 F，使得 F 与 t(⟨F⟩) 计算同一个函数：

存在 F，使 F 与 t(⟨F⟩) 等价

直觉是"任何对程序做的可计算改写，都有一个改了等于没改的程序"——比如"给每台机器的代码加一行注释"这种变换，也一定有个不动点程序，改写前后行为一致。这与经典递归论里 **Kleene 第二递归定理**是同一结果（见交叉源）。

## 7.2 逻辑理论的可判定性（§6.2）

### 7.2.1 什么是一个逻辑"理论"

一个数学结构（论域 + 若干运算/关系）的**理论**，是所有在该结构里为真的一阶逻辑句子的集合。Sipser 3e 记结构 M 的理论为 Th(M)：

Th(M) = { φ ： φ 是一阶句子且 φ 在 M 中为真 }

"这个理论可判定吗"问的是：有没有算法，输入任意一句关于该结构的一阶命题，就能判定它到底真还是假。这把"能不能机械地做某类数学"变成了一个可判定性问题。

初学者要抓住两点。其一，这里只允许**一阶逻辑**句子：可以对论域元素用 ∀/∃ 量化、可以用结构给定的运算与关系、可以用 ∧∨¬→ 连接，但不能对"所有子集/所有函数"量化（那是二阶）。其二，判定的是**真假**，不是可证性——一个句子可以为真却在某公理系统里不可证（这正是 7.2.4 的分岔点）。

### 7.2.2 Th(N,+) 可判定（Theorem 6.12）

只带加法的自然数算术——论域是 N、唯一运算是 +（含常量、等号）——它的全部真句子是**可判定**的。Sipser 3e Theorem 6.12：

Th(N, +) is decidable.

这套只有加法的算术就是经典的 **Presburger 算术**。可判定的原因很符合本课主线：一个只含加法与量词的公式，其满足的自然数组可以被一台有限自动机识别（把数按二进制逐位喂入），量词消去对应自动机的投影与补运算，最后判断句子真假归约为判断一个自动机是否接受——这是可判定的。

加法之所以"驯服"，是因为"x 是若干个数之和"这类性质有**周期/线性**结构，能被有限状态机的有限记忆捕捉；一旦只有加法，就没有能编码任意计算的空间，于是可判定。注意这与"停机问题不可判定"不冲突——Presburger 算术表达力太弱，编码不了图灵机运行。

### 7.2.3 Th(N,+,×) 不可判定（Theorem 6.13）

一旦在加法之外再加上**乘法**，理论立刻变得不可判定。Sipser 3e Theorem 6.13：

Th(N, +, ×) is undecidable.

证明沿用第 4 章的**计算历史法**：把 A_TM 归约到 Th(N,+,×)——对给定的图灵机与输入，构造一个一阶算术句子，它为真当且仅当该机在该输入上接受（用 +、× 把"一段合法的计算历史存在"编码成关于自然数的算术命题）。若 Th(N,+,×) 可判定，就能判定 A_TM，矛盾。

关键直觉是"乘法带来了编码能力"：有了 + 和 ×，就能表达整除、素数、序列编码（如哥德尔配数）等，足以把"图灵机第 t 步的格局"翻译成数与数之间的算术关系。加法单独做不到这件事——所以分水岭恰好在乘法。这也解释了为什么"数论"（研究 +、× 的整数）如此之难：它的真句子集合根本没有判定算法。

### 7.2.4 与哥德尔不完全性的连接

Sipser 在同一节顺带给出不完全性的一个精简版，值得点到，因为它和 7.1 的递归定理直接咬合。先是 Theorem 6.15：Th(N,+,×) 中**可证**的句子集合是图灵可识别的（把所有候选证明逐一喂给证明检查器即可枚举）。

由此推出 Theorem 6.16：Th(N,+,×) 中存在**为真却不可证**的句子。反证——若所有真句子都可证，那"可证的句子可识别"加上"假句子的否定为真因而可证"就能拼出一个判定"真/假"的算法，与 Theorem 6.13（不可判定）矛盾。更进一步，Theorem 6.17 用**递归定理**显式造出一句"这句话不可证"的自指句 ψ，坐实它确实不可证。

初学者只需带走一个心智模型：可判定 ⊋ 可证枚举。"真"的句子集合（Th）在 +,× 下不可判定，但"可证"的句子集合可枚举——两者的落差就是哥德尔不完全性，而制造那句自我指涉的"不可证句"用的正是 §6.1 的递归定理。这条线把本大主题的 7.1 与 7.2 缝在了一起。

## 7.3 图灵归约（§6.3）

### 7.3.1 预言机与预言机图灵机（Definition 6.18）

图灵归约把"用一个问题的答案去解另一个问题"这件事形式化。工具是**预言机（oracle）**：一个可以瞬间回答"串 w 是否属于语言 B"的黑盒，不管 B 本身可不可判定。Sipser 3e Definition 6.18：

B 的预言机是一个外部装置，对任意串 w 都能报告 w 是否属于 B；**预言机图灵机** Mᴮ 是一台可以查询 B 的预言机的图灵机。

直觉是"假设我白嫖到了 B 的判定器，我能解出什么"。预言机图灵机每一步照常运算，但允许它进入一个"提问状态"，把带上某个 w 交给预言机，下一步就拿到"是/否"继续算——即使 B 是停机问题这种不可判定语言，也照样能问。

初学者要把预言机当成"理想化的子程序调用"：现实里没有停机问题的判定器，但在**相对可计算**的框架里，我们允许假设它存在，专门研究"问题之间的相对难度"，而不纠结绝对可解性。

### 7.3.2 图灵归约 ≤_T 与它的基本性质（Definition 6.20、Theorem 6.21）

若能用 B 的预言机造出一台判定 A 的（预言机）图灵机，就说 A **图灵归约**到 B。Sipser 3e Definition 6.20：

A ≤_T B 当且仅当 A 相对于 B 可判定（即存在判定 A 的预言机图灵机 Mᴮ）

它的招牌性质是"难度传递"，Sipser 3e Theorem 6.21：

若 A ≤_T B 且 B 可判定，则 A 可判定

B 可判定就把预言机换成 B 的真判定器，Mᴮ 就变成一台普通图灵机判定 A。逆否地读更有用——**若 A 不可判定，则任何能归约到的 B 也不可判定**，这正是用归约证明不可判定性的骨架（如 E_TM ≤_T A_TM，Sipser Example 6.19）。

初学者要分清"归约方向"：A ≤_T B 读作"A 不比 B 难"（有了 B 的答案就能解 A）。易错点是把方向记反——记住是"被解的 A 站在弱侧，被借用的 B 站在强侧"。

### 7.3.3 图灵归约与映射归约的关系

图灵归约比第 6 章的**映射归约 ≤ₘ** 更宽松：Sipser 指出 A ≤ₘ B 蕴含 A ≤_T B（映射归约是"只问预言机一次、且直接照搬答案"的特例），反之不成立。

差别体现在**补集**上：映射归约下 A ≤ₘ B 不能推出 Ā ≤ₘ B（补语言不一定跟着归约过去），但图灵归约天然对补封闭——预言机图灵机可以把"是/否"取反，所以 A ≤_T B 立即给出 Ā ≤_T B。经典例证：A_TM 的补 co-A_TM 图灵归约到 A_TM（问一次取反即可），但它并不映射归约到 A_TM。

图灵归约"能多次提问、能对答案做任意后处理（包括取反）"，因此比映射归约强、更接近日常的"调用子程序"，代价是它不能像 ≤ₘ 那样精细区分一个语言和它的补。

### 7.3.4 图灵度

把"互相图灵归约"当作等价关系（A ≤_T B 且 B ≤_T A 记 A ≡_T B），每个等价类叫一个**图灵度（Turing degree）**——即"计算难度完全相同"的语言归在一起。可判定语言全体构成最低的度 **0**；停机问题所在的度记 **0′**（读作"0 跳"），严格高于 0。

Sipser 3e §6.3 只把图灵归约讲到 Theorem 6.21 与 ≤ₘ 对比的程度，**图灵度是点到为止的延伸**；系统的度理论（度的偏序结构、跳跃算子、Post 问题——是否存在严格介于 0 与 0′ 之间的可枚举度）属于经典递归论专著的范围。

可判定问题在最底层，停机问题高一层，"停机问题的停机问题"再高一层……图灵度把不可判定问题按"到底有多不可判定"排成了一张丰富的地图。想深入的落点是 Rogers/Soare（见来源），本课不展开。

## 7.4 信息定义（§6.4）

### 7.4.1 最小描述与描述（Kolmogorov）复杂度（Definition 6.23）

一个字符串"含多少信息"，用**能生成它的最短程序的长度**来度量——串越有规律、越可被短程序生成，信息量越低。Sipser 3e Definition 6.23 把它精确化：串 x 的**最小描述** d(x) 是最短的 ⟨M, w⟩，其中图灵机 M 在输入 w 上停机且带上恰为 x（有并列时取字典序最小者）；x 的**描述复杂度** K(x) 定义为：

K(x) = |d(x)|

这就是 **Kolmogorov 复杂度**（Sipser 称"descriptive complexity"，与 Kolmogorov/Solomonoff/Chaitin 复杂度为同一概念）。

"信息量 = 最短的说明书长度"。字符串 `010101…01`（一百万位）虽长，却能被"重复 01 五十万次"这句短话生成，K 很小；而一串真正随机的二进制位，除了"照抄它本身"没有更短的说法，K ≈ 它自己的长度。易错点：K(x) 度量的是**这一个具体串**的复杂度，与概率分布无关——它是"这串能被压到多短"，不是"这串多罕见"。

### 7.4.2 描述复杂度的基本上界（Theorem 6.24 / 6.25 / 6.26）

任何串的描述复杂度都不会比它自身长太多。Sipser 3e Theorem 6.24：

∃c ∀x [ K(x) ≤ |x| + c ]

因为总可以用"照抄"这台固定机器把 x 原样打印，描述长度就是 |x| 加上这台机器的固定开销 c。所以 K 有一条"天花板"——最坏也就是原样描述。

接着是两条关于**组合**的上界。重复一个串不增加多少信息，Theorem 6.25：

∃c ∀x [ K(xx) ≤ K(x) + c ]

拼接两个串的信息量不超过各自之和（外加编码分隔的开销），Theorem 6.26：

∃c ∀x, y [ K(xy) ≤ 2K(x) + K(y) + c ]

初学者要注意 6.26 里那个 **2K(x)** 的系数：因为要把 x 的描述和 y 的描述拼在一起，解码时得知道"x 的描述到哪结束"，最省事的办法是把 x 的描述每一位翻倍来标记边界，于是多花一份 K(x)。这不是笔误，而是"自定界编码"的代价——它提醒初学者，描述复杂度的加法性只在相差一个可控常数/因子的意义下成立。

### 7.4.3 不可压缩串（Definition 6.28、Theorem 6.29）

如果一个串没有明显短于它自身的描述，就称它**不可压缩**。Sipser 3e Definition 6.28：串 x 是 c-可压缩的，若

K(x) ≤ |x| − c

若 x 不是 c-可压缩的，就说它 c-不可压缩；特别地 1-不可压缩就直接叫**不可压缩**。

关键存在性结论 Theorem 6.29：每个长度都存在不可压缩串。

证明是一个漂亮的计数（鸽巢）论证：长度为 n 的串有 2ⁿ 个，而长度**小于** n 的描述只有 2ⁿ−1 个（长度 0,1,…,n−1 的二进制串共 1+2+…+2ⁿ⁻¹ = 2ⁿ−1 个），每个描述至多生成一个串，所以至少有一个长度 n 的串没有更短的描述——它就是不可压缩的。

初学者从这里应该获得一个反直觉但正确的世界观：**绝大多数字符串是不可压缩的**（更强地，c-不可压缩串占了至少 1−2⁻ᶜ 的比例）。我们日常见到的文件能压缩，只是因为人类产生的数据高度有规律；随机数据压不动。本机实证（直觉演示，非证明）：10000 字节的 `os.urandom` 随机串 gzip 后比例 ≈1.002（不减反略增），而规则串 `b'ab'*5000` 压到 ≈0.005——两端恰好对应"不可压缩"与"高度可压缩"。注意 gzip 只是一个具体压缩器，压得动只能证明可压缩、压不动**不能证明** K 大，所以这仅是直觉演示。

### 7.4.4 不可压缩串的"随机性"与 K 的不可计算

不可压缩串不仅存在，还**表现得像随机串**：任何"几乎所有串都满足"的可计算性质，都必然被所有足够不可压缩的串满足（只有有限多个例外）。Sipser 3e Theorem 6.31：

设 f 是对几乎所有串成立的可计算性质；则对任意 b>0，f 在"b-不可压缩串"上只对有限多个串为假。

直觉是"如果一个不可压缩串违反了某条普遍规律，那这条规律本身就给了它一个短描述（'第几个违反 f 的串'），与它不可压缩矛盾"。于是不可压缩串自动通过一切可计算的统计检验——这正是用 Kolmogorov 复杂度**定义**"单个串的随机性"的基础。相关地 Theorem 6.32 说：某常数 b，使每个串的最小描述 d(x) 本身都是 b-不可压缩的（最短的说明书自己没法再被显著压缩）。

一个必须点明的边界：函数 K(x) **本身不可计算**（Sipser 以 Problem 6.23 给出，证明用递归定理构造"输出一个描述复杂度大于本机描述长度的串"导致矛盾，即 Berry 悖论的形式化）。所以"求任意串的 Kolmogorov 复杂度"没有算法——这也是为什么 7.4.3 只能用 gzip 做直觉演示、无法真正计算 K。

其一，"随机 = 不可压缩"是 Kolmogorov 给"单个有限串随机性"的定义（不诉诸概率）；其二，K 虽定义清晰却**不可算**，它是理论工具而非可运行的度量。

### 7.4.5 下游联系点名（边界 B7）

Kolmogorov 复杂度是若干下游主题的理论源头，本报告仅点名不展开：**L6-01 随机性/去随机化**用不可压缩性刻画算法随机性、支撑概率方法（"不可压缩性方法"做平均情形下界）；**L5-04 密码学**里"随机 = 不可预测/不可压缩"的直觉与单向函数、伪随机生成器相关。这些落点的完整框架在各自课程，此处只标明来路。
