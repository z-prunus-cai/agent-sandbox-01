**把「解一个问题要占多少内存」当成第一资源，而不再计较「要跑多少步」**。时间复杂度问「要多少步」，空间复杂度问「同一时刻最多要用到多少格工作带」。这一视角转换带来两个反直觉但极重要的事实：其一，空间可以**反复擦写重用**，一个可能跑指数步的计算，其占用的空间可能只是多项式甚至对数级——所以「空间是比时间更宽松的资源」，同样的界下空间类通常比时间类更大（例如 P ⊆ PSPACE，而 PSPACE 里塞得下整个多项式层级）。其二，**非确定性对空间的帮助远小于对时间的帮助**：时间上 P 与 NP 是否相等悬而未决，而空间上 Savitch 定理证明「非确定只能把空间平方一下」，NL=coNL 更证明「非确定对数空间对取补封闭」——这两件事在时间世界里都被认为多半不成立。抓住「空间可重用、非确定省不了多少空间」这两句话，本章的所有定理都是它们的展开。

一个贯穿全章、必须先立住的约定：谈对数空间（L、NL）时，图灵机采用**双带模型**——一条**只读输入带**（不计入空间）加一条**可读写工作带**（只计工作带用的格数）。若把输入本身也算进去，任何机器都至少用线性空间，对数空间就无从谈起；把输入设为只读且不计费，才使「只用 O(log n) 格草稿纸」成为有意义的度量。O(log n) 格恰好够存下几个指向输入位置的指针（指向长度 n 的输入的指针需 ⌈log₂ n⌉ 位），这就是对数空间机器的典型能力边界。

## 9.1 空间度量与 Savitch 定理

### 9.1.1 空间复杂度的度量与 SPACE、NSPACE 类

一台确定型图灵机 M 的**空间复杂度**是函数 f(n)，表示 M 在任何长度为 n 的输入上，计算过程中扫描到的工作带格子的最大数目（Sipser 定义 8.1）。据此定义两族复杂度类：

SPACE(f(n)) = { L ｜ L 可被某台 O(f(n)) 空间的确定型图灵机判定 }

NSPACE(f(n)) = { L ｜ L 可被某台 O(f(n)) 空间的非确定型图灵机判定 }

其中 NSPACE 里的空间指非确定机在其**任一**计算分支上用到的最大格数（Sipser 定义 8.2）。

初学者要建立的第一直觉是「空间可以循环利用，时间不能」。跑一步就消耗一个时间单位、永不退回；但一块工作带格子可以先存 A、擦掉再存 B、再擦掉存 C。所以同一段算法，占的空间往往远小于它花的时间。一个反复被用到的量化事实是：**一台用 f(n) 空间的机器，其不同"格局（configuration）"的总数是空间的指数**——大约

2^{O(f(n))}

个（因为格局 = 工作带内容 × 读写头位置 × 状态，工作带内容有 |Γ|^{f(n)} 种）。这个「空间 f → 格局数 2^{O(f)}」的换算是本章几乎每个定理的引擎：一台判定器若不想陷入死循环，运行步数不能超过格局总数（否则必有格局重复即进入循环），于是**空间界立刻转成时间界**，例如 SPACE(f) ⊆ TIME(2^{O(f)})。

### 9.1.2 Savitch 定理：非确定空间至多平方

Savitch 定理（Sipser 定理 8.5）是本章第一块基石：任何"合理"的非确定空间都能被确定机以其**平方**的空间模拟。形式陈述为，对任意满足 f(n) ≥ n 的函数 f：

NSPACE(f(n)) ⊆ SPACE(f²(n))

（对 f(n) ≥ log n 的情形结论同样成立，需用只读输入带的对数空间模型陈述；Sipser 正文取 f(n) ≥ n，习题给出对数空间版本。）

这个定理为什么成立，直觉全在一个叫 CANYIELD 的递归可达性判断上。要判断非确定机能否从起始格局 c₁ 走到接受格局 c₂，等价于问「在它的格局图（configuration graph）里，c₁ 能否到达 c₂」。朴素做法是记住走过的路径，但路径可能指数长、存不下。Savitch 的巧招是**中点递归（分治）**：c₁ 能在 2^t 步内到 c₂，当且仅当存在某个中间格局 c_m，使得 c₁ 能在 2^{t-1} 步内到 c_m，且 c_m 能在 2^{t-1} 步内到 c₂：

CANYIELD(c₁, c₂, t) = ∃ c_m [ CANYIELD(c₁, c_m, t−1) ∧ CANYIELD(c_m, c₂, t−1) ]

关键在于枚举中间点 c_m 时，两个子问题**可以顺序进行、复用同一块空间**——先算左半，得答案后擦掉、再算右半——所以空间不随递归展开而累加，只随递归**深度**累加。总步数上界是格局数 2^{O(f)}，故 t 从 O(f) 起步；递归深度 = t = O(f)，每层递归栈帧要存一个格局（O(f) 空间），深度 × 每层 = O(f) × O(f) = O(f²)。这就是"平方"的来历：**深度贡献一个 f，每帧大小贡献一个 f**。

本机验证（可选，非承重）：对链图 0→1→2→3→4（n=5）实现 CANYIELD 递归可达性，判「0 可达 4」为真、「4 可达 0」为假，与 BFS 基准一致；且实测最大递归深度 = 3 = ⌈log₂ 5⌉，印证"递归深度 = O(log n)、每帧 O(log n)、合计 O(log²n) 空间"这一 PATH 上的 Savitch 特例（Python 3.11.15，2026-07-26 本机跑通）。

### 9.1.3 Savitch 定理的直接推论

Savitch 定理最重要的一个即时后果，是把"非确定多项式空间"塌缩回"确定多项式空间"：因为多项式的平方还是多项式，所以在多项式空间这一档，非确定性完全不增加能力。这条推论直接支撑下一节 PSPACE = NPSPACE（9.2.2），是理解「为什么空间复杂度里 P 与 NP 之别在多项式档消失」的关键。

Savitch 的平方开销**只针对空间**，不针对时间。用 f² 空间模拟出来的确定机，其运行时间可能高达 2^{O(f²)}，是指数的——省了空间却极其费时。所以 Savitch 不是"免费加速"，而是"用海量时间换取空间的平方压缩"。另外，f(n) ≥ n（或对数版的 f(n) ≥ log n）这个"空间可构造/够大"的前提不能丢：太小的空间连递归所需的计数器都存不下，定理不适用。

## 9.2 类 PSPACE

### 9.2.1 PSPACE 的定义

PSPACE 是"多项式空间可判定"的语言类，即在某个多项式空间界下确定机能判定的所有问题的并（Sipser 定义 8.6）：

PSPACE = ⋃_{k} SPACE(n^k)

对应地，NPSPACE = ⋃_{k} NSPACE(n^k) 是其非确定版本。

初学者可把 PSPACE 想成"内存受多项式限制、但时间随便花"的问题集合。它比想象中大得多：因为空间可重用，一个 PSPACE 机器可以系统地把指数多种可能性**一个接一个地试遍**，每次试完擦掉草稿再试下一个，全程只占多项式内存——只是要花指数时间。典型例子是布尔公式可满足性 SAT：n 个变量有 2^n 种赋值，逐一枚举需指数时间，但同一时刻只需记住"当前这一种赋值 + 一个计数器"，是多项式（实为线性）空间，故 SAT ∈ PSPACE。这解释了"为什么 PSPACE 里装得下所有 NP 问题"——穷举证书正是这种"多项式空间、指数时间"的做派。

### 9.2.2 PSPACE = NPSPACE：非确定在多项式空间无用

由 Savitch 定理（9.1.2），非确定多项式空间可被确定机以平方空间模拟，而多项式的平方仍是多项式，故两类相等：

PSPACE = NPSPACE

这条等式是本章最"干净"的结论之一，也是与时间世界最尖锐的对照。时间上 P 与 NP 是否相等是千禧年难题、普遍猜测 P ≠ NP；但**空间上，确定与非确定在多项式档完全一样**。原因回到那句主线心智模型：非确定性的威力在于"同时探索指数多条分支"，这在时间上省得多（一步顶指数步），但在空间上省不了多少——因为确定机可以靠"顺序地、复用空间地"重走每条分支，只多付平方的空间代价。记住这个对照，就抓住了空间复杂度区别于时间复杂度的灵魂。

### 9.2.3 PSPACE 与 P、NP、EXPTIME 的包含链

把已知包含关系串起来，得到本章的"地图"：

P ⊆ NP ⊆ PSPACE = NPSPACE ⊆ EXPTIME

其中 P ⊆ PSPACE 因为多项式时间的机器至多访问多项式个格子（每步至多动一格）；NP ⊆ PSPACE 因为可多项式空间穷举证书（见 9.2.1）；PSPACE ⊆ EXPTIME 因为多项式空间机器的格局总数是 2^{O(n^k)}，判定器运行步数不能超过它否则循环，故指数时间内必停（用的正是 9.1.1 的"空间→时间"换算）。

这条链有一个著名且重要的事实：**链上必有至少一处是真包含**。因为由时间层级定理可知 P ⊊ EXPTIME（大主题10 详述），而 P 与 EXPTIME 是链的两端，中间那串包含不可能全是等号——但目前**没人知道具体哪一处是严格的**。也就是说 P vs NP、NP vs PSPACE、PSPACE vs EXPTIME 至少有一个是真不等，可我们连是哪个都指不出来。这个"知道有真包含却抓不出位置"的窘境，是复杂度理论开放性的经典写照，@2026-07-26 三处是否严格均为未解。

## 9.3 PSPACE 完全性

### 9.3.1 PSPACE 完全的定义

一个语言 B 是 **PSPACE 完全**的，需同时满足两条（Sipser 定义 8.8）：B ∈ PSPACE；且 PSPACE 中每个语言都**多项式时间可归约**到 B。第二条称为 PSPACE 难（PSPACE-hard）。

这里有一个关键且易被忽视的设计选择：归约仍用**多项式时间**归约，而不是多项式空间归约。初学者常问"研究空间类为什么不用空间归约"。原因是归约本身若允许多项式空间，它的能力就可能强过被研究的类，使"完全性"失去意义（归约器自己就能解问题了）。用较弱的多项式时间归约，才能保证"B 完全"真的意味着"B 抓住了整个 PSPACE 的难度"：一旦某个 PSPACE 完全问题落入 P，就会推出 P = PSPACE。所以 PSPACE 完全问题是 PSPACE 里"最难的代表"，其地位类比 NP 里的 SAT。

### 9.3.2 TQBF：典范的 PSPACE 完全问题

TQBF（True Quantified Boolean Formula，真的全量化布尔公式）是 PSPACE 完全性的典范问题（Sipser 定理 8.9）。它的输入是一个**每个变量都被 ∀ 或 ∃ 量化**的布尔公式，问它是否为真：

TQBF = { ⟨φ⟩ ｜ φ 是一个为真的全量化布尔公式 }

TQBF 是 PSPACE 完全的（Theorem 8.9）。

先看它为什么在 PSPACE。求值一个量化公式可以递归地做：遇到 ∃x ψ 就分别令 x=0、x=1 求值 ψ，两者有一为真则真；遇到 ∀x ψ 则两者都真才真。关键同 Savitch——两个子情形**顺序求值、复用空间**，所以空间只随公式的量化深度线性累加，是多项式空间。再看它为什么 PSPACE 难：对任意 PSPACE 语言，可以把"机器 M 在输入 w 上是否接受"这件事，用一个模仿 CANYIELD 中点递归结构的量化布尔公式表达出来——量词交替恰好编码了"存在中间格局，使得前后两段都可达"的递归。这个构造直接复用了 Savitch 定理的分治骨架，故 TQBF 完整地"承载"了 PSPACE 的难度。

本机验证（可选，非承重）：实现 TQBF 递归求值器，判 ∀x∃y(x∨y) 为真、∃x∀y(x∧y) 为假，后者与暴力枚举一致（Python 3.11.15，2026-07-26 本机跑通）。求值器的"顺序试 x=0/x=1、复用空间"结构即 TQBF ∈ PSPACE 的算法核心。

### 9.3.3 广义博弈的 PSPACE 完全性：FORMULA-GAME 与广义地理

TQBF 与**两人博弈**有深刻联系。把 ∃/∀ 量词读成两名玩家轮流出招——∃ 玩家想让公式为真、∀ 玩家想让它为假——"公式为真"就等价于"∃ 玩家有必胜策略"。这个博弈叫 FORMULA-GAME，Sipser 证明它与 TQBF 本质是同一问题，故也 PSPACE 完全（Sipser 定理 8.11）。

由此进一步，许多"广义化到 n×n 棋盘/任意大图"的双人完美信息博弈都是 PSPACE 完全的。教科书的代表是**广义地理（Generalized Geography, GG）**：在一张有向图上，两名玩家从指定起点轮流沿出边走到未访问过的新节点，谁无路可走谁输——判断先手是否有必胜策略是 PSPACE 完全的（Sipser 定理 8.14）。

要建立的直觉是"为什么博弈天然对应 PSPACE"。博弈的必胜策略判定要问的是"**存在**我的一步走法，使得**对任意**对手回应，都**存在**我的下一步……"——正是 ∃∀∃∀ 的量词交替，与 TQBF 的结构严丝合缝。而博弈树虽指数大，却可以深度优先地遍历、复用空间地回溯，故落在 PSPACE。一个常见误区是把这些结论套到广义国际象棋/围棋上就断言"也是 PSPACE 完全"——不尽然：当博弈的**回合数可能指数长**（如可重复局面、需数步数规则）时，问题会升到 EXPTIME 完全，而非 PSPACE 完全。只有"回合数被多项式界住"的广义博弈才稳落 PSPACE 完全，这条边界务必记清。

## 9.4 类 L 与 NL

### 9.4.1 对数空间模型与 L、NL 的定义

L 与 NL 是"只用对数级工作空间"的语言类。它们建立在双带（只读输入 + 可读写工作带）模型上（Sipser 定义 8.17）：

L = SPACE(log n)

NL = NSPACE(log n)

即 L 是确定型对数空间可判定、NL 是非确定型对数空间可判定的语言类。

初学者要抓的核心是"O(log n) 空间到底能干什么"。log n 格草稿纸大约只够存**常数个指向输入的指针/计数器**（一个指向长度 n 输入位置的指针需 ⌈log₂n⌉ 位）。所以对数空间算法的典型形态是"我不把数据搬进工作带，只在只读输入上来回移动几个指针、维护几个计数器"。例如判断输入是否为回文，可用两个指针从两端向中间比对，只需对数空间。为什么工作带要和输入带分开、且输入不计费——因为若把输入也算进空间，任何机器都至少花 n 格（得先读完输入），对数空间将永远达不到；只读且不计费的输入带，才使"次线性空间"成为有意义的研究对象。

### 9.4.2 L、NL 与时间类的关系

对数空间机器很省内存，但它们同样受"空间→时间"换算（9.1.1）约束。一台对数空间机器的格局数是 2^{O(log n)} = n^{O(1)}，即多项式个，故其判定器多项式时间内必停：

L ⊆ NL ⊆ P

同时由 Savitch 定理（对数空间版）可得 NL ⊆ SPACE(log²n)，即非确定对数空间被确定机以 log²n 空间模拟。

这里把三条事实并置最有助记忆：L ⊆ NL 显然（确定是非确定的特例）；NL ⊆ P 来自"对数空间 → 多项式格局数 → 多项式时间"；NL ⊆ SPACE(log²n) 来自 Savitch。要注意 L 与 NL 是否相等（L vs NL 问题）**至今未解**（@2026-07-26），与 P vs NP 平行——只是没那么出名。一个易混点：NL ⊆ P 是"包含在多项式时间里"，并不意味着 NL = P；后者是另一个开放问题。对数空间之所以值得单列研究，正因为它是"比 P 更细"的一档，能区分出一些问题的更精细难度。

## 9.5 NL 完全性

### 9.5.1 对数空间归约与 NL 完全的定义

研究 NL 内部难度需要一种"比对数空间还弱"的归约，否则归约器自己就能解问题、完全性失去意义。这就是**对数空间归约（log-space reduction, ≤_L）**：由一台**对数空间转换器（log-space transducer）**计算的映射归约（Sipser 定义 8.21 附近）。转换器有只读输入带、只写输出带、和一条对数空间的工作带，输出带只写不计费。语言 B 是 **NL 完全**的，当且仅当 B ∈ NL 且 NL 中每个语言都对数空间可归约到 B（Sipser 定义 8.24 附近）。

对数空间归约的一条核心性质是**沿归约传递 L 成员资格**：若 A ≤_L B 且 B ∈ L，则 A ∈ L（Sipser 定理 8.23 附近）。这条性质是"完全性有用"的技术保证——它意味着：只要某个 NL 完全问题被证明属于 L，就立刻推出 L = NL。初学者要理解为什么归约必须弱到对数空间：如果允许多项式时间归约来研究 NL，那归约本身（多项式时间）就已超出 NL 的能力，"NL 完全"这个标签就说明不了"这个问题抓住了 NL 的全部难度"。归约器的能力必须被压到不超过被研究类，完全性才有分量。这里有一个技术细节值得点出：对数空间转换器可能输出多项式长的结果（比工作带大得多），所以它不把整个输出存在工作带里，而是"边算边吐"、需要哪一位就重算哪一位——这是对数空间归约区别于普通归约的实现要点。

### 9.5.2 PATH 是 NL 完全的

有向图可达性 PATH 是 NL 完全性的典范问题（Sipser 定理 8.25）：

PATH = { ⟨G, s, t⟩ ｜ G 是有向图且存在从 s 到 t 的有向路径 }

PATH 是 NL 完全的（Theorem 8.25）。

先看 PATH ∈ NL：非确定机从 s 出发，每步**猜**下一个要走到的邻居，只在工作带上记住"当前节点"和"已走步数计数器"两个值——各占对数空间——最多走 n 步若到达 t 就接受。它无需记住整条路径（那要线性空间），只记当前位置，靠非确定地猜下一步。再看 PATH 是 NL 难：任意 NL 机器 M 在输入 w 上的计算可以画成一张"格局图"，M 接受 w 当且仅当从起始格局能走到接受格局——这恰是 PATH 问题，而这张图能对数空间地从 ⟨M, w⟩ 构造出来。于是每个 NL 问题都归约到了 PATH。

PATH 之于 NL，正如 SAT 之于 NP、TQBF 之于 PSPACE——它是这个类的"最难代表"，且它恰好就是"非确定对数空间在做的事"的最纯粹形态（沿边猜着走、只记当前点）。要留意的对照：PATH（有向可达性）是 NL 完全的，而**无向**图可达性 USTCON 由 Reingold 2008 证明属于 L（确定对数空间即可，SL=L），是更"容易"的一档——有向与无向在对数空间世界里难度不同，别混为一谈（USTCON∈L 属 Sipser 正文之外的后续结果，本报告仅点名）。

本机验证（可选，非承重）：对链图 0→1→2→3→4 用 BFS 判定 PATH，「0 可达 4」为真、「4 可达 0」为假，与 9.1.2 的 Savitch 递归可达性结果对拍一致（Python 3.11.15，2026-07-26 本机跑通）。BFS 需线性空间，仅作正确性基准；NL 的对数空间做法是"非确定猜下一步、只记当前点"，二者判定结果相同而空间代价不同。

## 9.6 NL = coNL

### 9.6.1 定理陈述与 coNL 的含义

Immerman–Szelepcsényi 定理（Sipser 定理 8.27）是本章的压轴结论：非确定对数空间对**取补运算封闭**，即：

NL = coNL

其中 coNL = { L ｜ L 的补集 L̄ ∈ NL } 是 NL 语言取补后得到的类。

要读懂这句话，先弄清 coNL 是什么。若 L∈NL 意味着"当答案是**是**时，存在一条接受路径来见证"，那 L̄∈coNL（即 L∈coNL）意味着"当答案是**否**时，存在见证"。以 PATH 为例：PATH∈NL 因为"t 可达"可由猜一条路径见证；而它的补 PATH‾（"t **不**可达"）表面上很难非确定地见证——你怎么"猜"出一条不存在的路径的不存在？NL=coNL 的惊人之处正在于：连"t 不可达"这种否定性断言，也能用非确定对数空间见证。等价地说，PATH‾ 也在 NL，从而 PATH‾ 是 coNL 完全并落入 NL。

### 9.6.2 证明思想：非确定地"数"可达节点

证明的核心技巧叫**归纳计数（inductive counting）**。要非确定地确认"t 从 s 不可达"，思路是：先**精确算出**从 s 出发恰好能到达的节点总数，记作 c；再逐个枚举所有节点、非确定地为每个"声称可达"的节点猜一条到它的路径来核实，数出被核实为可达的节点个数；若核实到的可达节点恰好凑满 c 个、且 t 不在其中，就断定 t 不可达。

关键子问题是"怎么非确定地算出可达节点数 c 而不出错"。归纳计数按"i 步内可达"分层推进：设已知"至多 i 步可达的节点数" c_i，则可非确定地算出 c_{i+1}——对每个节点逐一判定它是否至多 i+1 步可达（做法是重新数一遍 i 步可达的节点并检查其邻居），全程只需存几个对数空间的计数器和当前节点指针，不存路径。层层递推到 i=n 即得总数 c=c_n。整个过程只用对数空间，且非确定分支要么"猜对并得到唯一正确的计数"、要么"猜错并中止"，保证不会给出错误的"是"。

初学者要记住的直觉是"用计数把否定变成肯定"。直接见证"不存在路径"很难，但见证"可达节点恰好这么多个、且 t 不在其中"是一个肯定性断言，能靠非确定猜测逐个核实。这就是把 coNL 的问题转化成 NL 能处理的形式的诀窍。历史与意义上，此定理 1987 年由 Immerman 与 Szelepcsényi**独立**证明、同获 1995 年哥德尔奖，它把结论推广到所有 s(n) ≥ log n 的空间界：NSPACE(s) = coNSPACE(s)，即**非确定空间类普遍对取补封闭**。这与时间世界形成又一尖锐对照——NP 是否等于 coNP 至今未解且普遍猜测不等，而空间世界里对应的问题被彻底解决为"相等"。再次印证本章主线：非确定性在空间上的威力远比在时间上受限。
