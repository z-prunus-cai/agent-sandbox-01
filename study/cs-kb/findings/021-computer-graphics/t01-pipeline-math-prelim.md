## G-01.1 渲染任务定义与实时 vs 离线的取舍谱系

### G-01.1.1 渲染就是从三维场景描述计算出二维图像

渲染（rendering）指的是：给定一个三维场景的数字化描述——包含几何体（三角形、曲面等）、材质、光源、以及一个虚拟相机——通过计算得到一张从该相机看出去的二维图像（一个像素颜色的二维数组）。

场景描述 + 相机  ──渲染──▶  二维像素图像

换句话说，渲染回答的问题是"从这个视点看这个世界，每个像素应该是什么颜色"。

初学者最该先分清的是"建模"和"渲染"的分工。建模（modeling）负责造出场景里的物体——决定有哪些几何、长什么样、什么材质；渲染负责把这个已经造好的场景"拍成照片"。本课绝大部分内容属于渲染。渲染这件事之所以不平凡，是因为一个像素的颜色原则上取决于全场景的光如何传播、反射、遮挡，把它算准（或算得足够像）正是整门课要层层展开的核心问题。

渲染并不总要求"物理真实"。很多场景（游戏、卡通）追求的是"看起来对/看起来好看"，而非严格模拟光学。所以渲染有一整条从"经验近似"到"物理精确"的谱系，本课从经验着色（G-05）一直讲到基于物理的光传输（G-09），就是沿着这条谱系走。

### G-01.1.2 实时渲染 vs 离线渲染：用"每帧多长时间"划线

同样是渲染，按"允许花多少时间算一帧"可分成两大阵营。实时渲染（real-time rendering）要求交互帧率，每帧只有毫秒级预算；离线渲染（offline rendering）不要求即时出图，每帧可花几秒到几小时，换取更高画质。

实时（交互）：每帧约 16.7 ms（60 FPS）或 33.3 ms（30 FPS）量级

离线（批处理）：每帧数秒至数小时，追求物理精确

这条线不是画质高低的绝对分界，而是"时间预算"的分界，它反过来决定了两边用什么算法。

为什么帧率会倒逼算法选择？因为预算极紧时，你负担不起"追踪每条光线在场景里反复弹射"这种昂贵计算，于是实时渲染历史上以**光栅化**（rasterization，G-03）为主力——它把三角形直接"刷"到屏幕上，快但对全局光照只能近似；离线渲染则更多用**光线追踪 / 路径追踪**（ray/path tracing，G-08、G-09）——顺着光线模拟光传播，慢但能自然得到阴影、反射、全局光照。60 FPS 这个数字要记住背后的算术：1 秒 60 帧，每帧只有

1000 ms ÷ 60 ≈ 16.7 ms

这点时间里要处理成百上千万三角形并着色数百万像素，所以实时管线的每一步都为速度做了取舍。

需要澄清一个正在模糊的边界：近年 GPU 有了专门的光线追踪硬件（RT Core 等，属 G-08 且演进快），实时光追已在游戏里落地，"实时=只能光栅化"的旧划分正在松动。但"实时受严格时间预算约束、离线不受"这条本质划线依然成立。这属于快速演进的前沿，具体状态见 G-06 / G-08，本节只给谱系直觉。

## G-01.2 图形管线阶段总览

### G-01.2.1 管线是把几何变成像素的分阶段流水线

图形管线（graphics pipeline，也叫渲染管线）指从"输入几何+相机+光照"到"输出图像"这一过程被拆成的一串有序阶段，数据像在工厂流水线上一样，从前一阶段的输出流进后一阶段的输入。Real-Time Rendering 4th 把它归纳为四个概念阶段：

应用（Application） → 几何处理（Geometry Processing） → 光栅化（Rasterization） → 像素处理（Pixel Processing）

其中最后的像素处理内部又常细分为片元着色（fragment/pixel shading）与输出合并（merging，含深度测试与混合）。

应用阶段决定"要画什么"（在 CPU 上准备几何、做剔除、提交绘制），几何处理把顶点从模型空间一路变换到裁剪/屏幕空间并做投影（G-02 的主题），光栅化把每个三角形转成它覆盖的一批像素候选（片元），像素处理给每个片元算颜色并按深度/透明度合并进帧缓冲。

初学者应把它先记成"逐三角形、逐像素"的两段节奏：几何处理是**逐顶点/逐图元**的（对每个顶点做同样的矩阵变换），光栅化之后转成**逐片元/逐像素**（对每个覆盖到的像素做同样的着色）。这个"先按顶点、再按像素"的切换点正是光栅化，理解了它就理解了整条管线的骨架。后续每个大主题基本都是在放大其中一个阶段：G-02 放大几何处理的变换/投影，G-03 放大光栅化与可见性，G-04/G-05 放大像素处理的采样与着色，G-06 讲这条管线在真实 GPU/API 上的可编程实现。

### G-01.2.2 各阶段职责一览（文字流程）

按数据流方向，各阶段的核心职责如下：

应用阶段：在 CPU 端准备场景数据、动画/物理更新、视锥剔除等粗剔除、决定绘制哪些物体，并把顶点与绘制命令提交给 GPU。

几何处理阶段：对每个顶点做模型→世界→视图→投影的变换（顶点着色），随后做裁剪（clipping，剔除视锥外部分）与屏幕映射（透视除法 + 视口变换，把裁剪坐标变成屏幕像素坐标）。

光栅化阶段：对每个三角形，找出它覆盖了哪些像素，为每个被覆盖像素生成一个"片元"（fragment），并用重心坐标把顶点属性（颜色、纹理坐标、法线等）插值到片元上。

像素处理阶段：片元着色器对每个片元计算颜色（采样纹理、算光照）；随后输出合并做深度测试（Z-buffer 决定谁在前、谁被遮挡）与颜色混合（透明合成），把最终颜色写入帧缓冲。

这里要提醒几个易混点。第一，"片元（fragment）"不完全等于"像素（pixel）"：片元是"某三角形在某像素位置产生的一个候选贡献"，同一像素可能收到多个片元（来自多个三角形），最后由深度测试/混合决定像素的最终值。第二，阶段划分是**概念模型**，不同教材/API 的粒度和命名略有差异（有的把"裁剪+屏幕映射"单列，有的并入几何阶段），但数据流顺序一致。第三，本节讲的是逻辑管线；它在真实硬件上哪些阶段固定、哪些可编程（顶点/片元着色器），是 G-06 的内容，此处不展开。

一个常被忽略但重要的方向性事实：管线是**单向流水**——几何在前、像素在后，信息基本不回流。正因如此，"一个像素最终什么颜色"在光栅化管线里是靠"多个片元竞争同一像素、由深度缓冲裁决"来解决的，而不是像光线追踪那样从像素出发反查场景。这正是光栅化与光线追踪两条路线在数据流方向上的根本区别（对照 G-01.1.2 与 G-08）。

## G-01.3 点、向量、仿射空间与坐标系约定

### G-01.3.1 点与向量是两种不同的对象

在图形学里必须把**点**（point）和**向量**（vector）当作两种不同的几何对象。点表示空间中的一个位置；向量表示一个位移/方向+大小（从某处到某处的箭头），不绑定具体位置。

点 − 点 = 向量（两点之差是从后者指向前者的位移）

点 + 向量 = 点（从一个位置沿位移走到另一个位置）

向量 ± 向量 = 向量（位移可叠加）

而"点 + 点"没有几何意义（两个位置相加是什么？没有定义）。承载这套"点与向量+其上合法运算"的结构就叫**仿射空间**（affine space）。

初学者常把点和向量都当成"一串数字 (x,y,z)"而混为一谈，这会在变换时埋雷。关键区别在于**平移**：把整个世界平移，点会跟着挪位置，但向量（比如两点之差、或表面法线方向）**不该被平移改变**——一个"向右"的方向平移之后还是"向右"。这正是 G-02 引入齐次坐标时，点写成第四分量 w=1、向量写成 w=0 的原因：让矩阵乘法自动对点施加平移、对向量忽略平移。此处先建立"点和向量是两类东西"的意识，具体齐次坐标机制留给 G-02。

一个能立刻检验理解的最小例子：三角形三个顶点是**点**；它的两条边 e₁ = p₁ − p₀、e₂ = p₂ − p₀ 是**向量**；求面法线要对两条边向量做叉积（G-01.5），而不是对顶点坐标直接叉积——因为法线是"方向"，只依赖边向量、不依赖三角形整体平移到哪。

### G-01.3.2 坐标系与基：把几何对象写成数字

要对点和向量做计算，就要选一个**坐标系**：一个原点 O 加一组基向量。选定后，任意向量能唯一写成基向量的线性组合，其系数就是它的坐标；点则用"从原点到该点的位置向量"的坐标表示。

v = x·e₁ + y·e₂ + z·e₃   （向量 v 在基 {e₁,e₂,e₃} 下的坐标为 (x,y,z)）

标准正交基（如 x/y/z 三个互相垂直的单位向量）是最常用的选择，因为在它下面内积、长度、投影的公式最简单（见 G-01.4）。

**同一个几何对象，换一组基/坐标系，坐标数字就变，但对象本身没变**（这与 L1-03 线代"坐标依赖基"完全同源）。图形管线里同一个顶点会先后活在很多坐标系中——模型空间、世界空间、相机/视图空间、裁剪空间、屏幕空间——每换一个空间就是换一组坐标，靠矩阵变换来回翻译（G-02 的核心工作）。所以"坐标随坐标系变"不是麻烦，而是管线赖以运作的机制。

坐标系必须"原点 + 基"配套。只给基向量不给原点，只能表示向量（方向），不能表示点（位置）——因为点的坐标是相对原点量出来的。这再次呼应 G-01.3.1 的点/向量之分。

### G-01.3.3 列向量 vs 行向量、左手系 vs 右手系：必须显式声明的约定

图形学有两组"没有对错、但各家不同、必须先声明"的约定，弄反会导致变换全错。

第一组是**列向量 vs 行向量**。把向量当成列（n×1），变换写成矩阵左乘：

v′ = M · v      （列向量约定，矩阵在左）

把向量当成行（1×n），变换写成矩阵右乘：

v′ = v · M      （行向量约定，矩阵在右）

这两种写法互为转置关系（vᵀ 与 v、M 与 Mᵀ），复合变换的书写顺序也随之相反。

第二组是**右手系 vs 左手系**，指三个坐标轴的朝向手性：右手系里 x×y = z（右手四指从 x 转向 y，拇指指向 z）；左手系则 z 方向相反。

这些是**任意约定**，选哪种都能自洽，但**同一个项目内必须统一**，且读任何公式/代码前要先查清它用哪种，否则矩阵会转置错、法线/正面会翻面。给几个真实世界的锚点帮助记忆（这些属于快速演进的具体 API，仅作约定示例）：数学教材与 OpenGL/GLSL 传统上用**列向量**、变换矩阵左乘；旧 DirectX/HLSL 文档常用**行向量**、矩阵右乘。手性方面，OpenGL 的观察/世界空间传统是**右手系**，DirectX 传统是**左手系**。Real-Time Rendering 4th 与 Fundamentals of CG 正文主要采用列向量 + 右手系。

最容易踩的坑有两个。其一，把列/行约定和"矩阵在内存里按列存还是按行存"（column-major vs row-major，属存储布局）混为一谈——它们是**两件独立的事**：前者是数学写法，后者是内存排布，OpenGL 恰好用列向量 + 列主存储，容易让人误以为二者是一回事。其二，抄来一个变换矩阵却不查它的约定，直接用在相反约定的框架里——正确做法是要么整体转置、要么统一约定。本报告后续（G-02 起）除非另行声明，统一采用**列向量、矩阵左乘、右手系**。

## G-01.4 线性映射、矩阵表示、内积/范数与正交基

### G-01.4.1 线性映射与它的矩阵表示

线性映射（linear map）是保持加法与数乘的向量变换 T，满足

T(a·u + b·v) = a·T(u) + b·T(v)

一旦选定基，线性映射就唯一对应一个矩阵 A，且"对向量作用映射"等于"对坐标左乘矩阵"：

T(x) = A · x

矩阵 A 的第 j 列，正是第 j 个基向量的像 T(eⱼ) 的坐标。

图形学关心线性映射，是因为旋转、缩放、剪切、正交投影这些几何变换全都是线性映射，因而都能写成矩阵、用统一的矩阵乘法来算和复合。要特别提醒：**平移不是线性映射**（它把原点挪走，违反 T(0)=0），所以纯 3×3 矩阵表达不了平移——这正是 G-02 要引入 4×4 齐次坐标的直接原因，此处先埋下伏笔。

二维逆时针旋转 90° 把 e₁=(1,0) 映到 (0,1)、把 e₂=(0,1) 映到 (−1,0)，按"像当列"拼出矩阵

R = [[0, −1],
     [1,  0]]

验证 R·(1,0)ᵀ = (0,1)ᵀ、R·(0,1)ᵀ = (−1,0)ᵀ，正是把整个平面逆时针转了 90°。记住"矩阵的列 = 基向量变到哪里"，几乎所有变换矩阵都能这样一眼构造出来。

### G-01.4.2 内积、范数与它们量出的几何

内积（点积，dot product）把两个向量映成一个标量，在标准正交基下就是对应分量相乘再相加：

u · v = u₁v₁ + u₂v₂ + … + uₙvₙ

它也等于两向量长度与夹角余弦之积：

u · v = ‖u‖ · ‖v‖ · cos θ

由内积定义**范数**（长度）：

‖v‖ = √(v · v)

内积是图形学里最"多产"的运算，因为它一次算出的东西到处都要用。夹角信息 cos θ = (u·v)/(‖u‖‖v‖) 直接用于光照——Lambert 漫反射的亮度就是"法线与光线方向夹角的余弦"（G-05），所以着色器里满是点积。内积为零意味着两向量**垂直**（正交），这用于判断朝向、构造正交基。内积还给出**投影**：v 在单位向量 û 上的投影长度就是 v·û，投影向量是 (v·û)û——这在分解速度、反射、构造相机坐标轴时反复出现。

给初学者两个立刻能用的直觉。其一，点积的符号告诉你"大致同向还是反向"：u·v > 0 夹角为锐角（同侧），= 0 垂直，< 0 钝角（反侧）——背面剔除就靠"面法线·视线方向"的符号判断三角形正对还是背对相机（G-03）。其二，用单位向量（长度归一化为 1 的向量）时公式最省：此时 u·v 直接就是 cos θ，不用再除长度。归一化即

v̂ = v / ‖v‖

只有在**标准正交基**下内积才等于"分量对应相乘求和"这个简单式子；非正交基下要带上度量矩阵，别无脑套用。图形学默认用标准正交基，所以平时可放心用简式，但换基/换坐标系时要留意。

### G-01.4.3 正交基与 Gram-Schmidt 正交化

一组基若两两垂直（内积为 0）就叫**正交基**，若还各自长度为 1 就叫**标准正交基**（orthonormal basis）。标准正交基极其好用：向量在它下面的坐标可直接用内积取出（第 i 个坐标 = v·eᵢ），且表示这组基的矩阵 Q 满足 QᵀQ = I（正交矩阵，其逆等于转置）。

Gram-Schmidt 正交化是"把任意一组线性无关向量改造成标准正交基"的标准流程：逐个取向量，减去它在前面已定好的正交向量上的投影分量，再归一化。对第 k 个向量 aₖ：

wₖ = aₖ − Σ_{i<k} (aₖ · qᵢ) qᵢ

qₖ = wₖ / ‖wₖ‖

"减去投影"这一步的直觉是：把 aₖ 中"与已有方向重复"的成分全部扣掉，剩下的必然与它们都垂直，再拉成单位长即得新的正交单位向量。

为什么图形学在意正交基？因为相机坐标系（视图空间）就是要即时造出一组以相机为原点的标准正交基——相机的前/上/右三个轴必须互相垂直且单位长，才能保证变换只旋转不拉伸变形。G-02 的 lookAt 构造本质上就是一次小型 Gram-Schmidt（用视线方向和一个大致的"上"向量，正交化出右/上/前三轴）。此外正交矩阵的逆=转置，让相机/旋转变换的求逆几乎免费，这在管线里是实打实的性能红利。

本机已用 numpy 加固：对三个线性无关向量做上式 Gram-Schmidt 得到 Q，验证 QQᵀ = I（各行两两正交且单位长），并与 numpy 内置 QR 分解交叉核对正交性一致（脚本与真实输出见文末）。要提醒的易错点：手写 Gram-Schmidt 在数值上不够稳定（近平行向量时误差放大），工业实现常用"修正版"或直接调 QR/Householder；导论阶段理解"减投影→归一化"的几何即可，数值稳健版属专家纵深，本报告不深挖。

## G-01.5 叉积、法线与重心坐标的几何直觉

### G-01.5.1 叉积：造出垂直向量与有向面积

叉积（cross product）只对三维向量定义，它吃两个向量、吐出一个**同时垂直于二者**的新向量，其长度等于两向量张成的平行四边形面积：

u × v = ( u₂v₃ − u₃v₂,  u₃v₁ − u₁v₃,  u₁v₂ − u₂v₁ )

‖u × v‖ = ‖u‖ · ‖v‖ · sin θ

方向由右手定则确定（右手四指从 u 转向 v，拇指指向 u×v）；因此交换次序会反向：

u × v = − (v × u)

叉积在图形学的头号用途是**求法线**：一个三角形所在平面的法向量，就是它两条边向量的叉积。给三角形顶点 p₀、p₁、p₂：

n = (p₁ − p₀) × (p₂ − p₀)

再归一化 n̂ = n/‖n‖ 即得单位法线。法线是着色（光照）、背面剔除、反射计算的基础，几乎每个后续大主题都要用。

给初学者两个关键直觉。其一，叉积的**长度**是面积（含 sin θ），所以两向量越接近平行、叉积越短、张成面积越小——若三点共线，叉积为零向量，说明"这不是个有面积的三角形"，这也可作退化三角形的检测。其二，叉积的**方向依赖顶点绕序**（winding）：按逆时针取边和按顺时针取边，法线正好反向。管线正是用这个符号来判断三角形是正面还是背面朝向相机（背面剔除，G-03）——所以整个项目必须统一"逆时针为正面"之类的绕序约定，否则正反面会全反。本机已用 numpy 验证：对 p₀=(0,0,0)、p₁=(1,0,0)、p₂=(0,1,0)，(p₁−p₀)×(p₂−p₀) = (0,0,1)，反转绕序则得 (0,0,−1)（见文末）。

### G-01.5.2 法线：表面朝向，且不按普通向量变换

法线（normal）是垂直于表面的单位向量，代表表面在某点的"朝向"。它决定了光照计算里表面接收多少光（Lambert 项 = 法线·光向的余弦，见 G-05）。

n · l = cos(法线与光线方向的夹角)

对平坦三角形，法线由 G-01.5.1 的叉积得到；对光滑曲面的近似（如球被三角化），通常在顶点处存一个"顶点法线"（相邻面法线的平均），再靠重心坐标插值到片元，得到平滑的着色。

这里有一个初学者极容易踩、又特别重要的坑，必须先埋下警示：**法线在物体被非均匀缩放/一般线性变换时，不能像普通方向向量那样直接乘同一个矩阵**。如果模型被变换矩阵 M 变换，法线要用 M 的**逆转置** (M⁻¹)ᵀ 来变换，否则变换后的"法线"会不再垂直于表面（比如把物体沿某轴压扁，直接乘 M 的法线会歪掉）。

法线变换用 (M⁻¹)ᵀ

其几何原因是"法线是与表面正交的方向，正交关系在非均匀缩放下不被普通矩阵保持"。完整推导与陷阱是 G-02.6 的专门主题，本节只先建立"法线是特殊向量、变换方式和点/普通向量不同"的意识，避免初学者一上来就错用同一个矩阵。对纯旋转（正交矩阵）而言 (M⁻¹)ᵀ = M，此时才可以直接乘，这也是为什么很多教程"看起来直接乘也没事"——因为他们只做了旋转。

### G-01.5.3 重心坐标：点相对三角形的"混合比例"

重心坐标（barycentric coordinates）用三个权重 (α, β, γ) 把三角形内（或平面上）任意一点 P 表示成三个顶点 A、B、C 的加权平均，权重之和恒为 1：

P = α·A + β·B + γ·C ，其中 α + β + γ = 1

当且仅当三个权重**都 ≥ 0** 时，点 P 落在三角形内部（或边界上）。

重心坐标是光栅化的心脏。它一身兼两职：一是**点在三角形内测试**——把像素中心的重心坐标算出来，看三个权重是否都非负，就知道该像素是否被三角形覆盖（G-03）；二是**属性插值**——顶点上的颜色、纹理坐标、法线等，用同一组权重加权，就平滑地插到三角形内每个片元上：

属性(P) = α·属性(A) + β·属性(B) + γ·属性(C)

给初学者最好的直觉是"混合比例/占比"。想象三个顶点各是一种纯色颜料，(α,β,γ) 就是在点 P 处三种颜料的调配比例，和为 1 保证是"配比"而非放大；越靠近某顶点，该顶点的权重越接近 1。权重也等于"对面小三角形面积占总面积的比"（面积坐标解释），这解释了为什么它能用叉积/边函数（有向面积）高效算出来（G-03 的 edge function 就是这么来的）。

两个必须点破的要点。其一，本节讲的是**二维/仿射意义**的重心坐标；在透视投影下直接线性插值属性会出错，必须做"透视校正插值"（按 1/w 加权），这是 G-03.3 的专门主题，此处先标记别踩。其二，权重可以为负——负值表示点在三角形**外部**，这正是点内测试的判据来源，不是错误。本机已用 numpy 验证：三角形 A=(0,0)、B=(4,0)、C=(0,3)，内点 (1,1) 得权重约 (0.417, 0.250, 0.333) 三者皆正、和为 1，且 α·A+β·B+γ·C 重建回 (1,1)；外点 (3,3) 出现负权重 (−0.75, 0.75, 1.0)，判定在外（见文末）。
