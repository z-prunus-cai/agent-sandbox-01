## 3.1 整数加减与溢出

### 3.1.1 补码加减法

在补码（two's complement）表示下，加法与减法用同一套二进制加法器完成，不需要为符号单独设计电路。n 位补码把无符号的位模式重新解释：最高位（MSB）的权重取负。一个 n 位补码数 X = x_{n-1}x_{n-2}…x_0 的数值为：

```
X = −x_{n-1}·2^{n-1} + Σ_{i=0}^{n-2} x_i·2^i
```

加法直接把两个 n 位模式按无符号规则相加、丢弃第 n 位的进位即可；减法 A − B 则先求 −B 的补码再做加法：

```
−B = (~B) + 1        （按位取反再加 1）

A − B = A + (~B) + 1
```

这套统一之所以成立，直觉是补码把数轴"卷成一个圈"（模 2^n 的环）。在这个环上，加 −B 和加 (2^n − B) 落到同一点，而 2^n − B 正好等于 (~B)+1。所以硬件只要有一个加法器，减法就是"把减数取反、再从最低位塞进一个进位 1"——RISC-V 的 `sub` 与 x86 的 `sub` 内部都是这么干的。

最小例子（4 位）：计算 5 − 3。5 = 0101，3 = 0011，~3 = 1100，(~3)+1 = 1101（即 −3 的补码）。

```
  0101   (5)
+ 1101   (−3)
------
1 0010   → 丢弃进位 → 0010 = 2   ✓
```

补码取负是"取反加一"，不是只取反（那是反码）。还有一个特例——n 位能表示的最小负数 −2^{n-1} 取负会溢出（−(−8) 在 4 位下仍是 −8），因为 +8 超出了 4 位补码的正数上界 +7。

### 3.1.2 有符号溢出检测

有符号溢出指运算结果超出了 n 位补码能表示的范围 [−2^{n-1}, 2^{n-1}−1]，此时保留的低 n 位不再是正确数值。硬件用两个等价判据之一来检测：

```
判据一：两个同号数相加，结果符号与它们相反 → 溢出
```

```
判据二：进入 MSB 的进位 C_in 与 MSB 产生的进位 C_out 不相等（C_in XOR C_out = 1）→ 溢出
```

这两个判据是等价的，都对应硬件里溢出标志位 V（x86 称 OF, overflow flag）的置位逻辑。

为什么"同号相加得异号"就是溢出？因为两个正数之和只可能是正数，若结果位显示成负数，唯一的解释是真值太大、进位冲进了符号位。异号相加（正+负）永远不会溢出——结果的绝对值只会变小，一定落在范围内，所以减法（同号减=异号加）也永远不溢出。

最小例子（8 位补码，本机 Python 实测，真实输出）：

```
127+1  = -128   （两正得负 → 溢出，正确值 128 越界）
-128+-1 = 127   （两负得正 → 溢出，正确值 -129 越界）
100+27 = 127    （=127，未越界 → 不溢出）
```

上面用 8 位掩码 `(a+b)&0xFF` 再按补码解释复现，与判据一逐条吻合；命令环境 Python 3.11.15 @ Linux 6.18.5（基线串见抬头）。

溢出是"是否发生"的一个事实，硬件只置标志、并不自动报错；C 语言里有符号溢出是未定义行为，而无符号是定义好的模 2^n 回绕。是否理会溢出取决于指令与语言——RISC-V 的加法指令本身不陷入（trap），需要软件用比较指令自行检测。

### 3.1.3 无符号溢出与进位

无符号加法的溢出判据与有符号完全不同：只看最高位是否产生进位。若两个 n 位无符号数相加，最高位向第 n 位进了位（C_out = 1），说明真值 ≥ 2^n，n 位装不下，即无符号溢出：

```
无符号溢出 ⟺ 最高位进位 C_out = 1
```

减法则看借位（borrow）：A − B 若需要向更高位借位（即 A < B），无符号结果回绕。x86 用同一个进位标志 CF 兼表加法进位与减法借位。

同一次二进制加法，硬件同时算出"进位标志"和"溢出标志"两个不同的位，分别服务无符号解释和有符号解释。CPU 不知道你把这堆位当有符号还是无符号——它两个标志都算好，由后续的条件分支指令挑用哪个。

最小例子（4 位）：1111 + 0001。

```
  1111   （无符号 15；有符号 −1）
+ 0001   （无符号 1；  有符号 +1）
------
1 0000   → 低 4 位 = 0000
```

无符号看：C_out=1 → 无符号溢出（15+1=16 越界，回绕成 0）。有符号看：−1+1=0，C_in 到 MSB 与 C_out 都为 1、异或为 0 → 不溢出，结果 0 正确。同一次加法，两种解释下一个溢出一个不溢出，正说明两标志各管一摊。

### 3.1.4 符号扩展与位宽

把一个窄补码数放进更宽的寄存器时必须做符号扩展（sign extension）：把符号位复制填满高位，才能保数值不变。无符号数则做零扩展（zero extension），高位补 0。

```
符号扩展：4 位 1101 (−3) → 8 位 1111 1101 (−3)
零扩展：  4 位 1101 (13) → 8 位 0000 1101 (13)
```

为什么符号扩展要复制符号位？因为补码里高位的负权重 −2^{n-1} 扩展后变成 −2^{m-1}，只有让新增的高位全等于原符号位，那些新增位的正负权重才恰好相互抵消、总值不变。这也是 RISC-V `lb`（load byte，符号扩展）与 `lbu`（load byte unsigned，零扩展）区分两条指令的原因——同样从内存取一个字节，扩展方式不同结果就不同。

立即数（immediate）在 RISC-V 中默认符号扩展到 32/64 位，因此一个"看起来是小正数"的立即数若最高位为 1 会被当成负数，这是新手读汇编常见的坑。

## 3.2 乘法

### 3.2.1 移位相加乘法算法

二进制乘法沿用小学竖式：逐位扫描乘数（multiplier），每遇到一个为 1 的位，就把被乘数（multiplicand）左移到相应位置后累加进部分积（partial product）。n 位 × n 位最多产生 2n 位结果，因此乘积寄存器要 2n 位宽。核心迭代（对乘数从最低位起，共 n 步）为：

```
若 当前乘数位 = 1： 积 ← 积 + (被乘数 << i)
每步：i 增 1（等价于被乘数左移一位）
```

十进制里乘以 10 就是左移一位补 0，二进制里"乘以 2"同样是左移一位。所以任何数乘以二进制乘数，都可拆成"若干个被乘数各自左移不同位数后求和"，位为 0 的那几项贡献 0、直接跳过。这就是为什么乘法在硬件里能归约成"移位 + 加法"这两个已有构件的组合，不需要发明全新运算。

最小例子（4 位无符号，3 × 5）：3 = 0011，5 = 0101。

```
被乘数 3 (0011)，乘数 5 = 0101，逐位（从 LSB）：
位0=1 → 加 0011<<0 = 0000 0011
位1=0 → 跳过
位2=1 → 加 0011<<2 = 0000 1100
位3=0 → 跳过
累加 = 0000 1111 = 15   ✓
```

结果位宽翻倍是必须的——两个 n 位数乘积可达 (2^n−1)^2，需要 2n 位才装得下，忽略高半部分就是溢出。RISC-V 因此提供 `mul`（取低 64 位）与 `mulh`/`mulhu`（取高 64 位）配合取完整乘积。

### 3.2.2 顺序乘法的硬件迭代

教材给出的"改进版"顺序乘法器不真的把被乘数左移，而是固定被乘数、每步把部分积右移一位，并让乘数与部分积共享同一个 2n 位寄存器。这样只需一个 n 位加法器（而非 2n 位）和一次右移，硬件面积更省。一轮迭代做：

```
1. 看积寄存器最低位（当前乘数位）：为 1 则 积的高半部 ← 高半部 + 被乘数
2. 整个 2n 位积寄存器算术/逻辑右移一位
重复 n 轮
```

为什么"部分积右移"能替代"被乘数左移"？因为二者是相对运动：把被乘数逐步左移去对齐高位，等价于把已累积的部分积逐步右移去让新加数总落在同一固定位置。右移方案的好处是加法器永远只作用在固定的高半部，宽度减半。

这一版本每步只处理 1 位，n 位乘法约需 n 个时钟周期，是"用时间换面积"的典型。它把 3.2.1 的概念算法落成可迭代的时序电路：一个寄存器、一个 n 位加法器、一个移位控制，配一个数到 n 的计数器。

### 3.2.3 有符号乘法与 Booth 概览

上面的无符号算法直接用于有符号数会出错，因为符号位的负权重没被正确处理。最朴素的修法是"记录符号、取绝对值相乘、最后回填符号"。更优雅的是 Booth 算法（Booth's algorithm），它扫描乘数相邻两位的组合，把"一串连续的 1"识别成"一次加、一次减"，从而在补码上直接得到正确带符号乘积，并对含长连续 1 的乘数减少加法次数。Booth 每步依据 (当前位, 更低一位) 做：

```
10 → 部分积 − 被乘数
01 → 部分积 + 被乘数
00 或 11 → 不加不减（仅移位）
```

一串二进制 1（如 0111 = 8−1）可以写成"高位加一次、低位减一次"，Booth 正是用这个恒等式把连续 1 段折成一头一尾两次运算。对初学者，记住两点即可：一是补码乘法不能照搬无符号规则，二是 Booth 用"加减混合 + 移位"在补码上统一处理正负号，是经典的有符号乘法硬件方案。

COD RISC-V 2nd ed 正文以无符号顺序乘法讲原理，Booth 算法在经典体系结构教材（含 COD 早期版本的选读与 Hennessy & Patterson《QA》相关内容）中作为有符号优化给出；此处只做入门概览，不展开完整推导。

### 3.2.4 快速乘法概览

顺序乘法要 n 个周期，太慢。快速乘法把 n 个部分积一次性摊开，用一棵加法器树并行相加，把延迟从 O(n) 降到大约 O(log n)。最常见的是把众多部分积先用进位保留加法器（carry-save adder, CSA）压缩，最后只做一次进位传播加法。

```
n 个部分积 → CSA 树逐层压缩为 2 个 → 一次进位传播加法 → 乘积
```

加法慢在进位要一位一位往上爬（行波进位）；CSA 的技巧是"暂不解决进位、把和与进位分成两路各自保留"，等到最后一步才真正传播一次进位。这样多个数相加时，中间层都不用等进位链，层与层之间是并行的。初学者层面只需建立"面积换速度：铺开更多加法器把乘法并行化"的心智模型，具体的 Wallace/Dadda 树结构不在本报告纵深范围内。

- 交叉源①：CSAPP 3rd ed ch2 §2.3.4–2.3.5（无符号/补码乘法的位级定义、乘积需 2w 位、编译器用移位加法替代常数乘法）——与 COD 在"移位+加法"本质、位宽翻倍上一致。

## 3.3 除法

### 3.3.1 恢复余数除法

除法是乘法的逆，硬件同样用"移位 + 减法 + 判断"迭代。恢复余数除法（restoring division）逐位求商：每步把余数寄存器左移一位、试着减去除数，若结果为负说明"减多了"，就把除数加回去（恢复）并置该商位为 0；否则保留、置商位为 1。对 n 位除法迭代 n 轮：

```
每步：余数 ← (余数 << 1) − 除数
若 余数 < 0： 余数 ← 余数 + 除数（恢复）， 商位 ← 0
否则：                              商位 ← 1
```

这就是竖式长除法——每次把被除数的下一位"拉下来"（左移），试探"够不够减一个除数"，够就商 1 不够就商 0。"恢复"这一步是因为硬件先斩后奏：它先减了再看符号，发现减错了才把值补回去。

初学者容易忘记结果寄存器要同时容纳商和余数，且除数与被除数的位宽对齐（除数放在寄存器高半部再逐步右移，或余数逐步左移，两种等价视角）。除以 0 是硬件必须单独处理的异常情形，算法本身不产生有意义结果。

### 3.3.2 不恢复余数除法

不恢复余数除法（non-restoring division）省掉"减多了再加回去"的额外周期：如果某步减出了负余数，它不立刻恢复，而是在下一步改成"加除数"而非"减除数"，用符号累积的方式抵消误差。规则为：

```
若 当前余数 ≥ 0： 余数 ← (余数 << 1) − 除数
若 当前余数 < 0： 余数 ← (余数 << 1) + 除数
商位：本步余数结果 ≥ 0 记 1，< 0 记 0
最后若余数为负，做一次末尾修正（加回除数）
```

为什么可以不恢复？因为"减错后恢复再下一步左移减"与"不恢复、下一步直接左移加"在代数上等价——(2·(R+D)) − D 与 2·R + D 只差在被 2 乘的项，展开后落到同一条递推。好处是每步最多一次加或减，省掉恢复步，平均更快。代价是逻辑略复杂且末尾可能要一次修正。

对初学者，抓住对比即可：恢复法"错了就退回"，直观但慢；不恢复法"错了不退、下一步反向补"，快但需末尾校正。二者商与余数的最终结果相同。

### 3.3.3 有符号除法与余数符号

有符号除法通常同样"取绝对值相除、再定符号"：商的符号由被除数与除数异号决定，余数的符号约定与被除数相同（截断向零取整下）。必须满足的恒等式是：

```
被除数 = 商 × 除数 + 余数
```

且余数绝对值小于除数绝对值。

不同语言/硬件对"负数除法向哪取整"约定不同——C99 及之后、RISC-V 的 `div`/`rem` 采用截断向零（余数与被除数同号），而某些语言（如 Python）用向负无穷取整（余数与除数同号）。同一对操作数在两种约定下商和余数都可能不同，跨语言移植时是常见 bug 源。本机 Python 实测：`-7 // 2 = -4`、`-7 % 2 = 1`（向下取整）；而 C/RISC-V 语义下 `-7 / 2 = -3`、`-7 % 2 = -1`（向零取整）。核心恒等式 被除数 = 商×除数 + 余数 在两种约定下都成立，只是分账方式不同。

#### 来源与时效
- 主锚：P&H《COD》RISC-V 2nd ed (2020) ch3 §3.4（Division；恢复余数除法器结构、迭代 n 步、除以 0 处理、`div`/`rem`）。核实 2026-07-26。
- 交叉源①：CSAPP 3rd ed ch2（整数除法/取余语义，C 截断向零约定）及 C 标准 C99 §6.5.5（`/` 向零截断、`a = (a/b)*b + a%b` 恒等式）——与 COD 在恒等式、符号约定上一致。
- 交叉源②（本机 Python 3.11.15 实测）：`-7//2=-4, -7%2=1` 复现 Python 向下取整语义，与 C/RISC-V 向零取整对照，确认两约定下核心恒等式均成立。
- 冲突项：负数取整方向——C/RISC-V 向零截断（余数随被除数）vs Python/向负无穷（余数随除数）；两边都记，移植时以目标语言为准，不作单一普适结论。不恢复法末尾修正为经典算术教材内容，标为原理性介绍。

## 3.4 IEEE-754 表示

### 3.4.1 浮点的动机与规格化科学计数法

整数无法表示分数与极大/极小量，浮点数（floating-point）借用科学计数法：把一个实数写成"符号 × 尾数 × 基的指数"，让小数点能"浮动"。二进制下规格化（normalized）形式规定尾数整数部分恒为 1（隐藏位），于是一个规格化浮点值为：

```
value = (−1)^s × 1.f × 2^(e − bias)
```

其中 s 是符号位、f 是小数字段（fraction/尾数的小数部分）、e 是存储的偏置指数字段、bias 是偏置常数。

科学计数法 6.022×10^23 里，符号、有效数字、指数三者分开存。二进制照搬，唯一巧思是"任何非零二进制数规格化后整数位一定是 1"（因为最高有效位就是 1），既然一定是 1，就不必存它，省下的一位让尾数精度白赚一位——这就是"隐藏位/隐含 1"。

这个隐含的 1 只在规格化数里存在；对非规格化数（3.4.4）与零，隐含位是 0 而非 1，套错公式会得到荒唐值。

### 3.4.2 单精度与双精度字段布局

IEEE 754 二进制交换格式把 32 位（单精度 binary32）或 64 位（双精度 binary64）切成三段：符号、指数、尾数小数部分。位宽与偏置为：

```
单精度 binary32：  s(1) | exp(8)  | frac(23)   bias = 127
双精度 binary64：  s(1) | exp(11) | frac(52)   bias = 1023
```

单精度总位数 1+8+23 = 32，双精度 1+11+52 = 64。

最小例子（单精度，本机 Python `struct.pack('>f', x)` 实测位模式，真实输出）：

```
     1.0  hex=3f800000  sign=0 exp=01111111 frac=00000000000000000000000
    -2.0  hex=c0000000  sign=1 exp=10000000 frac=00000000000000000000000
 0.15625  hex=3e200000  sign=0 exp=01111100 frac=01000000000000000000000
```

验读 1.0：s=0，exp 字段 = 01111111 = 127，减 bias 127 得指数 0，尾数 1.0，值 = +1.0×2^0 = 1.0 ✓。验读 0.15625 = 1.25×2^{−3}：exp 字段 = 127−3 = 124 = 01111100，frac = .010…（=0.25，配隐含 1 得 1.25）✓。命令环境 Python 3.11.15 @ Linux 6.18.5（基线串见抬头）。

字段顺序是"符号在最高位、指数在中间、尾数在最低"，且大端书写时高位在左。初学者手工解码常把 exp 字段与"真实指数"混为一谈——存的是加了偏置的 e，真实指数要减 bias。

### 3.4.3 偏置指数

指数用偏置（biased/excess）表示而非补码：真实指数加上 bias 后存成一个无符号字段。单精度 bias=127，双精度 bias=1023。规格化数的 exp 字段取值范围是 1 到 (全 1 减 1)，对应真实指数：

```
真实指数 = exp字段 − bias
单精度规格化真实指数范围：1−127 = −126  到  254−127 = +127
```

为什么用偏置而不用补码存指数？关键理由是让浮点数能按位当作整数比较大小：同号浮点数，位模式作为无符号整数比较，大小关系与数值大小关系一致。偏置指数使"指数越大位模式越大"，若用补码则负指数的位模式反而更大，破坏这个性质。这让硬件能用整数比较器实现浮点比较、排序。

exp 字段的两个极端值被征用作特殊含义——全 0 表示零与非规格化数（3.4.4），全 1 表示无穷与 NaN（3.4.5），所以规格化数的 exp 字段不含全 0 与全 1，真实指数范围因此是 [−126, +127] 而非 [−127, +128]。

### 3.4.4 非规格化数（渐进下溢）

当 exp 字段全为 0 时，数被解释为非规格化（denormal/subnormal）：隐含位改为 0，真实指数固定为 (1 − bias)（不是 −bias）。非规格化值为：

```
value = (−1)^s × 0.f × 2^(1 − bias)
```

单精度即 (−1)^s × 0.f × 2^{−126}。

作用是填补 0 与最小规格化数之间的空隙，实现渐进下溢（gradual underflow）：没有非规格化数时，比最小规格化数还小的量只能直接跳到 0，造成 a≠b 但 a−b==0 的怪事；有了非规格化数，这段区间被均匀细分，下溢是渐进的。

最小例子（单精度，本机 Python 实测）：

```
最小非规格化数 2^-149     exp=00000000 frac=00000000000000000000001
最大非规格化数(约2^-126)  exp=00000000 frac=11111111111111111111111
最小规格化数 2^-126       exp=00000001 frac=00000000000000000000000
```

可见非规格化区间的 exp 字段恒为全 0，靠 frac 从 1 递增到全 1，步长恒为 2^{−149}，正好平滑衔接到最小规格化数。

非规格化数的真实指数是 (1−bias)=−126 而非 −127——这是为了让最大非规格化数与最小规格化数无缝衔接的刻意设计，套 −bias 会算错一档。

### 3.4.5 特殊值：零、无穷与 NaN

exp 字段全 1 用于表示两类特殊值，加上全 0 的零，构成 IEEE-754 的特殊编码：

```
零：      exp 全 0，frac 全 0（符号位区分 +0 与 −0）
无穷：    exp 全 1，frac 全 0（符号位区分 +∞ 与 −∞）
NaN：     exp 全 1，frac 非 0（Not a Number）
```

无穷来自溢出或 x/0（x≠0）等；NaN 来自 0/0、∞−∞、负数开方等无意义运算，用于把错误沿计算链传播而非直接崩溃。

最小例子（单精度，本机 Python 实测）：

```
+inf  exp=11111111 frac=00000000000000000000000  hex=7f800000
 nan  exp=11111111 frac=10000000000000000000000  hex=7fc00000
```

NaN 与任何值（包括它自己）比较都返回假，所以 `x != x` 为真是检测 NaN 的经典技巧；而 +0 == −0 为真（两者数值相等），但 1/(+0)=+∞、1/(−0)=−∞ 又能区分。NaN 分 quiet（qNaN，静默传播）与 signaling（sNaN，触发异常）两类，由 frac 最高位区分；本机 `float('nan')` 生成的是 qNaN（frac 最高位为 1，如上 hex=7fc00000）。

无穷与 NaN 都占用 exp 全 1，区别只在 frac 是否为 0；初学者易把二者混淆。另外 −0 存在且位模式与 +0 不同，但绝大多数比较里二者相等，只在除法/符号敏感场景才显出差别。

- 主锚：IEEE 754-2019 §3.3–3.4（binary interchange formats：binary32/binary64 的位宽 1/8/23 与 1/11/52、指数偏置、规格化/非规格化/无穷/NaN 编码）。规范 2019 版为现行；相对 2008，二进制格式字段/偏置/特殊值编码未变，主要更新在十进制与操作澄清。核实 2026-07-26。

## 3.5 浮点运算与舍入

### 3.5.1 浮点加法流程

浮点加法不能直接把位模式相加，必须先把两个数的小数点对齐（指数相同）才能加尾数。标准五步流程为：

```
1. 对阶：比较指数，把较小指数的数右移尾数，使两数指数相等
2. 尾数相加/减（按符号）
3. 规格化：结果尾数移位，恢复 1.f 形式，相应调整指数
4. 舍入：按舍入模式把超出尾数位宽的部分处理掉
5. 舍入后若破坏规格化，再规格化一次
```

像 1.5×10^2 + 3.0×10^0 要先把后者写成 0.03×10^2 再加。二进制同理，指数小的那个要"让位"——尾数右移、丢弃低位，这一步就已经可能损失精度。

易错点（大数吃小数）：当两数指数相差超过尾数位宽，小数右移后尾数全变 0，加法等于没加。这导致浮点加法不满足结合律：

```
(大 + −大) + 小 = 0 + 小 = 小
大 + (−大 + 小) = 大 + (−大) = 0   （小被大数吃掉）
```

两种括号法结果不同，是浮点求和顺序影响结果的根源，数值计算里"先加小的、后加大的"正是为缓解此问题。

### 3.5.2 浮点乘法流程

浮点乘法比加法简单，因为不需要对阶：指数相加、尾数相乘、符号异或，再规格化与舍入。流程为：

```
1. 指数相加并减去一个 bias（因两个偏置指数相加多带了一份 bias）
2. 尾数相乘（含隐含 1，即 1.f × 1.f）
3. 结果符号 = 两操作数符号位异或
4. 规格化 + 舍入
```

为什么指数相加要减 bias？因为存的是 (e1+bias) 与 (e2+bias)，直接相加得到 e1+e2+2·bias，多了一份 bias，要减掉一份才还原成 (e1+e2)+bias。

乘法在"指数域"是加法、在"尾数域"是乘法，符号单独异或，三条线并行，比加法的对阶-规格化往返简单。初学者只需记住"加法难在对阶、乘法难在尾数相乘的位宽"，二者最后都要规格化 + 舍入收尾。

### 3.5.3 舍入模式

尾数位数有限，运算的中间结果往往超出可存位数，必须舍入（rounding）。IEEE 754-2019 定义 5 种舍入方向属性，其中二进制默认是"舍入到最近、平局取偶"：

```
roundTiesToEven（默认）：舍到最近可表示值；正好在中间时取尾数末位为偶的那个
roundTiesToAway：        舍到最近；平局时取绝对值较大的
roundTowardPositive：    向 +∞ 舍（向上取整）
roundTowardNegative：    向 −∞ 舍（向下取整）
roundTowardZero：        向 0 舍（截断）
```

为什么默认"平局取偶"而不是四舍五入的"平局向上"？因为总是向上会引入系统性正偏差，长串运算累积成漂移；取偶让平局一半向上一半向下，统计上无偏。这也是为什么 Python `round(0.5)=0`、`round(2.5)=2`（银行家舍入），常令初学者意外。

roundTiesToAway 是 754-2008 才为十进制引入、754-2019 保留的模式，二进制运算的默认始终是 roundTiesToEven；"截断"（toward zero）是最简单但误差最大的模式，不是默认。

### 3.5.4 保护位、舍入位、粘位与精度误差

为了正确舍入，硬件在尾数右侧多留三个位：保护位（guard）、舍入位（round）、粘位（sticky，记录再往下是否还有任何 1）。正是靠这三位，硬件能判断被丢弃部分究竟"不到一半 / 恰好一半 / 超过一半"，从而正确执行"最近偶数"舍入而不引入额外偏差。

浮点最根本的坑是：大多数十进制小数在二进制里无法精确表示，存进去就已经是近似值。经典例子（本机 Python 实测）：

```
0.1 + 0.2 = 0.30000000000000004    （!= 0.3）
0.1 存储的真实值 = 0.1000000000000000055511151231257827021181583404541015625
```

0.1 在二进制是无限循环小数 0.0001100110011…，双精度只能截断存储，于是 0.1、0.2 各带微小误差，相加后误差显现。这解释了为什么浮点数绝不能用 == 直接比较，工程上要用"相差小于某容差 ε"来判等。

这类误差不是"bug"而是有限位宽的必然，也不是 Python 独有——任何遵循 IEEE-754 的语言（C、Java、JS…）结果相同。numpy 的 `np.isclose`、算法里的相对/绝对容差判等，都是应对此问题的标准手段。另一个衍生现象是抵消（catastrophic cancellation）：两个相近的大数相减，有效数字大量抵消，剩下的低位误差被放大。

#### 来源与时效
- 主锚：IEEE 754-2019 §4.3（rounding-direction attributes：roundTiesToEven 为二进制默认、roundTiesToAway、三个定向舍入）、§5（加/乘等操作的正确舍入要求）。核实 2026-07-26。
- 交叉源①：P&H《COD》RISC-V 2nd ed (2020) ch3 §3.5（浮点加法对阶-相加-规格化-舍入四/五步流程、浮点乘法指数相加减 bias、guard/round/sticky 三位、加法不满足结合律）——与 754 一致。
- 交叉源②：CSAPP 3rd ed ch2 §2.4.4–2.4.6（round-to-even 无偏动机、浮点不满足结合律、`0.1` 不可精确表示）；本机 Python 3.11.15 实测 `0.1+0.2=0.30000000000000004`、`Decimal(0.1)` 展开真实存储值，佐证舍入误差与"勿用 == 比较"。
- 无实质冲突；roundTiesToAway 属版本时效点（2008 起引入、2019 保留，二进制默认仍为 roundTiesToEven），已标注。舍入误差现象跨语言一致（IEEE-754 保证）。

## 3.6 ALU 构造

### 3.6.1 一位 ALU 与位切片

算术逻辑单元（ALU, arithmetic logic unit）是 CPU 里做加减与与或等运算的核心组合电路。构造思路是位切片（bit-slice）：先造一个"1 位 ALU"，能对一位做与/或/加，再把 n 个 1 位 ALU 串起来（进位链相连）组成 n 位 ALU。单个 1 位 ALU 的骨架是：

```
一位 ALU = { AND 门, OR 门, 全加器 } → 各自结果送入一个 MUX
MUX 由操作选择信号 ALUop 挑出本次要哪一路输出
```

ALU 不是"一个会算术的黑盒"，而是"把与、或、加的电路都常备着，同时算出所有结果，再用一个多路选择器（MUX）按控制信号选一路输出"。这正是 L2-02 学过的构件（全加器 DL-3.1、MUX DL-3.3）的直接组装——ALU 是它们的顶层集成。

ALU 是纯组合逻辑（无时钟、无状态），所有候选运算并行算出、由 MUX 选择；它本身不存结果，结果要靠外部寄存器锁存。初学者常误以为 ALU"按指令一步步算"，其实是"全都算好、选一个"。

### 3.6.2 加减与逻辑运算的统一

同一个 ALU 靠若干控制线切换功能。减法复用加法器：给一条 Binvert 线，把 B 输入按位取反，并把最低位的进位输入 CarryIn 置 1，就实现了 A + (~B) + 1 = A − B（呼应 3.1.1）。逻辑运算则由 MUX 直接选 AND/OR 路。典型控制约定（RISC-V 教学 ALU，COD 图）：

```
Ainvert Binvert CarryIn(bit0)  Operation  → 功能
   0       0         0             00       A AND B
   0       0         0             01       A OR B
   0       0         0             10       A + B
   0       1         1             10       A − B（B 取反 + 进位 1）
```

为什么减法不用单独的减法器？因为补码下 A−B = A+(~B)+1，取反由 Binvert 完成、"+1"由把整条进位链最低位的 CarryIn 置 1 完成，加法器一件硬件两用。这是"用控制信号复用数据通路"的最小例子，也是 3.1.1 补码统一加减在硬件上的落地。

Binvert 和 CarryIn=1 必须成对出现才是正确减法，只取反不加进位得到的是"A 加 B 的反码"，差 1。

### 3.6.3 溢出、比较与移位的支持

完整 ALU 还要支持有符号比较（如 `slt`, set-less-than）与溢出检测。比较借减法实现：算 A−B，看结果符号即可判 A<B；溢出则由最高位 ALU 的进位逻辑给出（3.1.2 的 C_in⊕C_out）。这些扩展让 ALU 不仅算数，还能为分支指令产生判定。

```
slt（A < B）：计算 A − B，取结果最高位（符号位）作为 Less 输出，回填到最低位 ALU
溢出（有符号）：最高位 ALU 输出 C_in XOR C_out
```

条件分支（如 `blt`）需要知道"谁大谁小"，ALU 通过做一次减法、看符号位来回答，结果不当数值用而当"真/假"信号。这解释了为什么比较和算术能共享同一套加法器硬件——比较本质就是一次不保留结果、只看符号的减法。

无符号比较与有符号比较用的判据不同（前者看进位/借位，后者看符号且要排除溢出干扰），RISC-V 因此分 `slt`（有符号）与 `sltu`（无符号）两条指令，对应 3.1.2 与 3.1.3 两套溢出/大小判据。

### 3.6.4 标志输出

ALU 除了数据结果，还输出一组条件标志（condition flags/codes），供分支指令使用。经典四标志（x86 命名，很多架构类似）为：

```
Z (Zero)     ：结果是否为全 0
N/S (Negative/Sign)：结果最高位（符号位）
C (Carry)    ：无符号进位/借位（无符号溢出判据，见 3.1.3）
V/O (oVerflow)：有符号溢出（C_in⊕C_out，见 3.1.2）
```

一次运算过后，硬件顺手记下"结果是不是 0、是不是负、有没有进位、有没有有符号溢出"这四件事，条件跳转指令（如"相等则跳""小于则跳"）就靠读这几位来决定分支。C 与 V 分别服务无符号与有符号解释，正好对应 3.1 里"一次加法两套溢出判据"。

架构差异（实现分账）：x86/ARM 有专门的标志寄存器（FLAGS/CPSR），算术指令自动更新标志，条件跳转读标志；而 RISC-V 刻意不设全局标志寄存器，改用比较指令直接把布尔结果写进通用寄存器、再用带比较的分支指令（如 `beq`/`blt`），以简化流水线。因此"ALU 输出标志"在概念上通用，但是否存进独立标志寄存器是实现选择——教学通式与具体 ISA 要分开记。

不要把 C（无符号）和 V（有符号）当同一件事——同一次加法二者可各自独立置位（回看 3.1.3 的 `1111+0001` 例：C=1 而 V=0）。
