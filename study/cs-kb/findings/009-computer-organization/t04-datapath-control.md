**单周期处理器 = 一张固定的组合+时序连线图 + 一组由指令编码决定的开关（MUX 选择端）**。数据通路（datapath）是"路"——一堆功能部件（PC、指令存储器、寄存器堆、ALU、数据存储器、加法器、多路选择器）用导线连死；控制单元（control）是"信号灯"——它只看当前指令的 opcode/funct 位段，就把每个 MUX 拨到该拨的方向、把每个存储部件的读写使能开到该开的状态。抓住三句话贯穿全篇：（1）**同一套硬件要跑所有指令**，不同指令的差异全部体现在"MUX 拨向哪边、哪些使能打开"上，这正是为什么处处需要 MUX；（2）单周期意味着**一条指令在一个时钟周期内从取指走到写回全部做完**，时钟上升沿之间是纯组合逻辑在"流"数据，上升沿才把结果锁进 PC、寄存器堆或存储器；（3）时钟周期必须 ≥ 最慢那条指令的关键路径，这个"一刀切"就是单周期的原罪，直接催生流水线。

## 4.1 指令执行五步

### 4.1.1 五步抽象数据流：取指 / 译码 / 执行 / 访存 / 写回

无论哪条指令，处理器执行它都可以抽象成同样的一串动作：取出指令、读出要用的寄存器、用 ALU 算一个值、（若需要）访问数据存储器、把结果写回寄存器；同时更新 PC 指向下一条。P&H 把这套通用流程概括为"两步核心 + 后续"（先取指并按 opcode 译码，再按类型完成运算/访存/写回），而在流水线章节它被固定命名为五个阶段：

    IF  (Instruction Fetch)   取指
    ID  (Instruction Decode)  译码 + 读寄存器
    EX  (Execute)             ALU 执行 / 算地址
    MEM (Memory access)       访存（仅 load/store 真正用到）
    WB  (Write Back)          写回寄存器堆

在**单周期**实现里，这五步不是五拍，而是在**同一个时钟周期内、由组合逻辑一路"流"下来**——五步是逻辑上的先后（数据依赖顺序），不是时间上的五个节拍。把它们分成五拍是下一大主题（流水线）才做的事。

为什么要先把执行抽象成"固定五步"？因为这是"用一套硬件跑所有指令"的前提：如果每条指令走的步骤完全不同，就没法共用部件。P&H 的关键观察是——绝大多数 RISC-V 指令在**前两步（取指、读寄存器）完全一样**，差异只从第三步（EX）起才显现。所以数据通路可以让所有指令共享取指和读寄存器的硬件，只在后段用 MUX 分流。初学者最常见的误解是把五步当成"五个时钟周期"——那是多周期/流水线；单周期里五步挤在一拍内，靠的是组合逻辑的信号传播，代价就是这一拍必须很长（见 4.5）。

### 4.1.2 每一步在单周期里具体做什么

把上面的五步落到 RISC-V 的几类代表指令上，就能看清哪些指令用到哪些步：

    指令类     | IF   | ID(读寄存器)    | EX(ALU)          | MEM        | WB
    R 型 add  | 取指  | 读 rs1,rs2      | rs1 (op) rs2      | —          | 写 rd
    I 型 ld   | 取指  | 读 rs1          | rs1 + 立即数(算址) | 读内存      | 写 rd
    S 型 sd   | 取指  | 读 rs1,rs2      | rs1 + 立即数(算址) | 写内存      | —
    B 型 beq  | 取指  | 读 rs1,rs2      | rs1 - rs2(比较)   | —          | —

从这张表能直接读出三件对后面至关重要的事实：第一，**只有 load/store 真正访问数据存储器**（MEM 步），R 型和分支跳过它；第二，**只有 R 型和 load 会写回寄存器**（WB 步），store 和分支不写；第三，**ALU 在不同指令里干不同的活**——R 型做算术逻辑、load/store 做"基址+偏移"的地址加法、分支做减法比较。这三件事正好对应后面主控制单元要产生的三个关键信号族：MemRead/MemWrite（要不要访存）、RegWrite（要不要写回）、ALUOp/ALUSrc（ALU 做什么、第二操作数从哪来）。

初学者容易以为 store 和 branch"没结果所以简单"，其实它们照样占满关键部件——store 要读两个寄存器、算地址、写内存；branch 要读两个寄存器、做减法、算跳转目标地址。它们只是不写回寄存器堆而已。

## 4.2 单周期数据通路

### 4.2.1 数据通路：把功能部件连成一张固定的图

数据通路是把 PC、指令存储器、寄存器堆、ALU、数据存储器，以及若干加法器、立即数生成器和多路选择器（MUX）用导线连接起来的**固定电路**。它本身不"决定"做什么——所有"选择"都通过 MUX 的选择端交给控制单元。搭建它的思路是"沿着一条指令的数据流增量地加部件"：先满足取指，再满足 R 型，再叠加 load/store 的访存，最后叠加分支的 PC 改写。

    数据流主干（一拍内组合逻辑从左到右）：
    PC → 指令存储器 → 寄存器堆(读) → [ALUSrc MUX] → ALU → [数据存储器] → [MemtoReg MUX] → 寄存器堆(写)
                                                     └→(分支)→ PCSrc MUX → PC(下一拍锁存)

为什么是"固定的图"却能跑不同指令？关键在于图里每个岔路口都放了一个 MUX：ALU 第二个输入是"另一个寄存器"还是"立即数"，由一个 MUX 选；写回寄存器的数据是"ALU 结果"还是"从内存读出的值"，由另一个 MUX 选；下一条 PC 是"PC+4"还是"分支目标"，由第三个 MUX 选。控制单元只要拨这几个 MUX，就能让同一张图表现出不同指令的行为。**MUX 的数量 ≈ 指令之间行为分歧的数量**——这是理解整张图最省力的抓手。

### 4.2.2 取指硬件与 PC 自增

取指部分最简单：PC 寄存器保存当前指令地址，送进指令存储器读出 32 位指令；同时一个专用加法器算出 PC+4（RISC-V 指令定长 4 字节），作为顺序执行时的下一地址候选。

    下一 PC 候选一：PC + 4          （顺序执行）
    下一 PC 候选二：PC + 立即数偏移   （分支/跳转成功时）

这两个候选送进 PCSrc MUX，选中的值在时钟上升沿写回 PC。注意 PC 是本图里为数不多的**时序**部件之一（带时钟、会锁存状态），指令存储器/寄存器堆的读端口和 ALU 都是**组合**的（给输入立刻出输出）。初学者常问"为什么 PC+4 用一个独立加法器而不复用 ALU"——因为单周期里 ALU 同一拍要给本指令算数据结果，不能又去算地址；单周期靠"多摆几个部件"换"一拍干完"，这也预告了它硬件利用率不高的毛病。

### 4.2.3 寄存器堆、ALU 与 ALUSrc 多路选择器

寄存器堆（register file）是一个"两读一写"的多端口存储：两个读端口按指令的 rs1、rs2 字段并行读出两个源操作数，一个写端口在 RegWrite 使能时把结果写进 rd 字段指定的寄存器。ALU 接收两个操作数：第一个恒为 rs1 读出的值；第二个由 ALUSrc MUX 在"rs2 读出的值"与"立即数生成器扩展出的立即数"之间二选一。

    ALUSrc = 0 → ALU 第二操作数 = 读出的 rs2      （R 型、分支比较）
    ALUSrc = 1 → ALU 第二操作数 = 符号扩展的立即数  （load/store 算地址、I 型算术）

为什么必须要这个 MUX？因为 R 型指令（add x1,x2,x3）的第二操作数是寄存器，而 load（ld x1, 8(x2)）的第二操作数是立即数偏移 8——同一根线、同一个 ALU 输入口，两类指令要喂不同的东西，唯一的办法就是放个 MUX 让控制信号来拨。这就是"MUX = 行为分歧的物化"的第一个具体例子。易错点：RegWrite 使能只在"要写回"时打开；写端口的**写地址永远接 rd 字段**，RISC-V 里 rd 固定在指令 bit[11:7]，所以（与 MIPS 教学版不同）**不需要一个选择目的寄存器字段的 MUX**（详见 4.3.3）。

### 4.2.4 数据存储器与写回（MemtoReg）多路选择器

数据存储器（data memory）只被 load/store 用到：load 在 MemRead 使能下按 ALU 算出的地址读出一个字，store 在 MemWrite 使能下把 rs2 的值写进该地址。写回寄存器堆的数据，则由 MemtoReg MUX 在"ALU 结果"与"从数据存储器读出的值"之间二选一。

    MemtoReg = 0 → 写回寄存器的数据 = ALU 结果        （R 型、I 型算术）
    MemtoReg = 1 → 写回寄存器的数据 = 数据存储器读出值  （load）

为什么又要一个 MUX？因为 add 要写回的是 ALU 算出的和，而 ld 要写回的是从内存搬来的数——两类指令的"写回来源"不同，共用一个寄存器堆写端口，就得用 MUX 选。注意指令存储器与数据存储器在单周期里画成两块独立存储（哈佛式），这样取指和访存能在同一拍并行，不抢端口——这正是 4.5 里"结构冒险"在单周期被回避、却在流水线复现的伏笔。

### 4.2.5 PC 更新、分支目标与 PCSrc 多路选择器

分支指令（beq）要在"顺序 PC+4"和"跳转到分支目标"之间选择。分支目标由一个独立加法器算出：

    分支目标地址 = PC + 立即数偏移

RISC-V 的 B 型/J 型立即数以 **2 字节为单位**编码（最低位隐含为 0），立即数生成单元直接给出字节偏移后再与 PC 相加，因此 P&H RISC-V 版数据通路里分支加法器的输入就是"已扩展好的字节偏移"（不同教材/讲义在图上是否再画一个显式的"左移 1 位"取决于立即数生成单元如何定义——这属于画法差异，不影响最终地址）。是否真的跳转，取决于 ALU 对 rs1、rs2 做减法后的 **Zero 输出**：

    PCSrc = Branch AND (ALU 的 Zero 输出为 1)
    PCSrc = 1 → 下一 PC = 分支目标；PCSrc = 0 → 下一 PC = PC + 4

这里出现了控制信号与数据通路输出的**联合决策**：Branch 是控制单元看 opcode 给的"这是不是分支指令"，Zero 是 ALU 看数据算出的"两数是否相等"，两者相与才真正拨动 PCSrc。初学者要抓住的直觉是：**控制单元光看指令编码无法知道分支到底成不成立**（那要看运行时数据），所以分支的最终方向必须等 ALU 算完——这条"必须等数据出来才知道往哪走"的性质，正是后面控制冒险（CO-5.5）的根源。

### 4.2.6 最小例子：一条 `ld x1, 8(x2)` 走完全程

把上面的部件串起来，跟一条 load 走一遍（同一时钟周期内的组合逻辑传播顺序）：

    1. PC 送指令存储器，取出 ld 指令；并行算出 PC+4
    2. 按 rs1 字段读出 x2 的值；立即数生成器从指令高位提取偏移 8
    3. ALUSrc=1 → ALU 第二操作数选立即数 8；ALU 做加法算地址 = x2 + 8
    4. MemRead=1 → 数据存储器按该地址读出一个字
    5. MemtoReg=1 → 写回 MUX 选"内存读出值"
    6. RegWrite=1 → 时钟上升沿把该值写进 x1；PCSrc=0 → PC 锁存为 PC+4

对照 4.1.2 的表可以看到，这条 load 用满了五步；而一条 add 会在第 3 步做寄存器-寄存器运算、跳过第 4 步、第 5 步 MemtoReg 选 ALU 结果。**同一张图、不同 MUX 拨向**——这就是单周期数据通路的全部秘密。

## 4.3 主控制单元

### 4.3.1 控制信号清单：每根线管一件事

主控制单元（main control）是一个**纯组合逻辑译码器**：输入是指令的 opcode（RISC-V 中在 bit[6:0]），输出是一组开关信号，逐一驱动数据通路里的 MUX 和使能端。P&H RISC-V 版的基础控制信号（针对 R 型 / ld / sd / beq 子集）如下：

    RegWrite  : 1 = 允许写回寄存器堆（R 型、load）
    ALUSrc    : 1 = ALU 第二操作数取立即数（load/store/I 型）；0 = 取 rs2
    MemRead   : 1 = 数据存储器读使能（load）
    MemWrite  : 1 = 数据存储器写使能（store）
    MemtoReg  : 1 = 写回数据取自内存（load）；0 = 取自 ALU
    Branch    : 1 = 这是分支指令（与 ALU Zero 相与后决定 PCSrc）
    ALUOp[1:0]: 交给 ALU 控制的"粗分类"码（见 4.4）

每根线只管一件事，且大多互斥于指令类型。初学者最好把它理解成"给数据通路填一张开关表"：拿到一条指令，控制单元查 opcode，一次性把七八个开关全部拨到位，数据就沿着被拨通的路径流一遍。

### 4.3.2 从 opcode 派生控制：主控制真值表

主控制的核心就是这张真值表——**输入 opcode 类型，输出各控制信号取值**（`X` 表示无关项 don't-care，因为该指令不写回/不访存，这些线取什么都不影响结果）：

    指令类     | ALUSrc | MemtoReg | RegWrite | MemRead | MemWrite | Branch | ALUOp
    ----------|--------|----------|----------|---------|----------|--------|------
    R 型       |   0    |    0     |    1     |    0    |    0     |   0    |  10
    ld (load) |   1    |    1     |    1     |    1    |    0     |   0    |  00
    sd (store)|   1    |    X     |    0     |    0    |    1     |   0    |  00
    beq       |   0    |    X     |    0     |    0    |    0     |   1    |  01

对应的 RISC-V 7 位 opcode（bit[6:0]，来自 CO-2 编码，本报告不重复深挖编码）：

    R 型 (add/sub/and/or/slt) : 0110011
    load  (ld/lw)             : 0000011
    store (sd/sw)             : 0100011
    branch(beq)               : 1100011

逐行读懂这张表就掌握了单周期控制的全部：R 型只需写回、ALU 用两个寄存器、ALUOp=10 交给下级按 funct 细译；load 把 ALUSrc/MemRead/MemtoReg/RegWrite 全开、ALUOp=00 让 ALU 做地址加法；store 与 load 前半段相同（ALUSrc=1、ALUOp=00 算地址）但改成 MemWrite、不写回；beq 两操作数都取寄存器、Branch=1、ALUOp=01 让 ALU 做减法比较。易错点：**ALUOp 不是最终 ALU 操作码**，它只是"粗分类"（00=一定做加、01=一定做减、10=看 funct 再定），真正的 4 位 ALU 控制由下一级（4.4）译出——这正是"两级控制"存在的理由。

### 4.3.3 三家来源的命名/分解差异（非矛盾，需识别等价）

P&H、H&H、CS61C 讲的是同一个单周期 RISC-V 处理器，但控制信号的**命名与分解粒度**不同；把它们并排看能避免"换本书就看不懂"：

    功能                | P&H COD          | H&H DDCA         | Berkeley CS61C
    -------------------|------------------|------------------|------------------
    写回来源选择         | MemtoReg (2 路)   | ResultSrc        | WBSel (3 路,含 PC+4)
    立即数类型选择        | (子集隐含,单一扩展)| ImmSrc           | ImmSel
    下一 PC 选择         | PCSrc=Branch&Zero | PCSrc=(Br&Zero)|Jump | PCSel
    是否跳转判定          | ALU 的 Zero 输出   | ALU 的 Zero 输出  | 独立分支比较器 BrEq/BrLT/BrUn
    目的寄存器字段选择     | (无需,rd 位置固定) | (无需)           | (无需)

（1）**写回路数**——P&H 基础子集 2 路（ALU/内存），H&H 的 ResultSrc 和 CS61C 的 WBSel 因为把 jal/jalr（要写回 PC+4 作返回地址）纳入，需要 3 路；这不是矛盾，是覆盖指令范围不同。（2）**立即数生成**——P&H 基础子集只处理少数格式、常隐含一个符号扩展器；H&H/CS61C 显式用 ImmSrc/ImmSel 按指令格式（I/S/B/U/J）选择不同的立即数拼接方式，更贴近真实 RISC-V 六型编码。（3）**分支判定**——P&H 复用 ALU 的 Zero 输出判等，CS61C 则用一个**独立的分支比较器**（输出 BrEq/BrLT，配 BrUn 处理无符号比较），把"比较"从主 ALU 里拆出来，这样 blt/bltu 等指令更自然。此外，MIPS 教学版有的 **RegDst**（选 rd 字段位置）信号在 RISC-V 三家里都**不需要**——因为 RISC-V 的 rd 恒在 bit[11:7]，写地址直接接线即可。

## 4.4 ALU 控制

### 4.4.1 为什么需要两级控制

主控制不直接产生 4 位的 ALU 操作码，而是先产生 2 位的 ALUOp"粗分类"，再由一个小的 **ALU 控制单元**结合指令的 funct 字段译出最终 4 位 ALU 控制。这种"两级译码"的动机是**信息分工**：

    第一级（主控制）：只看 opcode → 知道"这类指令大概要 ALU 做什么"（加/减/看 funct）
    第二级（ALU 控制）：看 ALUOp + funct7/funct3 → 定"具体是 add/sub/and/or/slt 哪一个"

为什么不让主控制一步到位？因为 R 型指令的 opcode 全都相同（0110011），add、sub、and、or、slt 的区别**只在 funct3/funct7 里**。若主控制要直接分辨它们，就得把 funct 也接进主控制，做一个又大又杂的译码器。两级分工让主控制只管"粗类"、把"细活"下放给一个专门看 funct 的小电路，逻辑更清晰、更好扩展。初学者可类比"先分部门（ALUOp）再分具体岗位（funct）"。

### 4.4.2 ALUOp + funct → 4 位 ALU 控制真值表

第二级的真值表：ALUOp=00 无条件出加法（给 load/store 算地址）、ALUOp=01 无条件出减法（给 beq 比较）、ALUOp=10 才去看 funct7 的一个位和 funct3 三位来分辨 R 型的具体运算：

    ALUOp | funct7[5] | funct3 | ALU 操作      | 4 位 ALU 控制
    ------|-----------|--------|--------------|-------------
    00    |    X      |  XXX   | add(算地址)   | 0010
    01    |    X      |  XXX   | subtract(比较)| 0110
    10    |    0      |  000   | add          | 0010
    10    |    1      |  000   | subtract     | 0110
    10    |    0      |  111   | AND          | 0000
    10    |    0      |  110   | OR           | 0001
    10    |    0      |  010   | set-less-than| 0111

4 位 ALU 控制码的含义（与 CO-3.6 的 ALU 构造对应）：

    0000 = AND
    0001 = OR
    0010 = add
    0110 = subtract
    0111 = set-less-than (SLT)

load/store（ALUOp=00）和分支（ALUOp=01）**根本不看 funct**——它们的 ALU 任务固定（加地址 / 减比较），funct 位是无关项；只有 R 型（ALUOp=10）才真正解码 funct。这解释了为什么 add 指令（R 型，funct3=000, funct7[5]=0）和 sub 指令（R 型，funct3=000, funct7[5]=1）**funct3 完全相同**，全靠 funct7 里那一位区分。

### 4.4.3 区分 add / sub 的关键位是 instruction[30]

RISC-V 里 add 和 sub 的 opcode、funct3 都一样，唯一区别是 funct7：add 的 funct7=0000000，sub 的 funct7=0100000。funct7 占指令 bit[31:25]，其中起区分作用的是 **funct7 的第 5 位，即指令的 bit[30]**：

    instruction[30] = 0 → add （funct7 = 0000000）
    instruction[30] = 1 → sub （funct7 = 0100000）

所以 ALU 控制单元实际只需接入 funct3（3 位）和 instruction[30]（1 位）即可完成 R 型内部的区分——不必接入整个 7 位 funct7。这是一个高频考点也是常见错误来源：**不要以为 add/sub 由 funct3 区分**；funct3 只区分 add/sub 与 and/or/slt 这些"运算种类"，而 add 与 sub 这对"加减同族"必须靠 funct7 的那一位（bit[30]）分开。P&H 正是利用了 RISC-V 编码把这个区分位放在固定位置这一点，让 ALU 控制电路非常小。

#### 来源与时效
- 一手锚点：P&H《COD》RISC-V 2nd ed (2020) ch4 §4.4（ALU 控制两级译码、ALUOp 编码、funct7 bit[30] 区分 add/sub，核实 2026-07-26）。
- 交叉核对：ALU 控制两级方案与 4 位编码（00→0010 add、01→0110 sub、10→按 funct 译 AND 0000/OR 0001/SLT 0111）经两个独立开源实现坐实——merledu `SIngle-Cycle-RISC-V-In-Verilog/ALUControl.v`、DeepWiki `ikeofilic1/RISCV-processor` 控制单元（均 2026-07-26 读取）；H&H《DDCA》RISC-V ed ch7 ALUControl。
- 冲突项：无。4 位 ALU 控制的**具体位型**是 P&H 教学约定（0010=add 等），各实现沿用；不同 HDL 实现可能用枚举名（ADD/SUB/AND/OR/SLT）替代位型，语义一致。RISC-V 官方 ISA 只规定 funct7/funct3 编码（add funct7=0000000、sub funct7=0100000），不规定内部 ALU 控制位型——规范与教学实现分账。

## 4.5 单周期局限

### 4.5.1 CPI = 1：单周期的定义性优点

单周期实现每条指令恰好用一个时钟周期完成，因此**每指令周期数 CPI = 1**，且没有任何指令间重叠或停顿。这是它唯一但重要的优点：控制极简、行为最好理解。CPU 时间公式（承 CO-1.2）在这里退化为：

    CPU 时间 = 指令数 IC × CPI × 时钟周期 = IC × 1 × 时钟周期

也就是说，单周期处理器的性能完全由"时钟周期能压多短"决定——而这恰恰是它的死穴。初学者容易把"CPI=1"当成好性能的同义词，但性能是 CPI 与时钟周期的乘积；单周期用一个大得离谱的时钟周期"买"来了 CPI=1，总账并不划算（见下）。

### 4.5.2 时钟周期由最慢的那条指令决定

单周期里时钟周期必须 ≥ **关键路径最长的那条指令**走完全程所需的时间。不同指令路径长度差别很大：

    R 型  : 取指 + 读寄存器 + ALU + 写回
    load  : 取指 + 读寄存器 + ALU(算址) + 读内存 + 写回   ← 最长
    store : 取指 + 读寄存器 + ALU(算址) + 写内存
    beq   : 取指 + 读寄存器 + ALU(比较)

load 因为多穿过一次数据存储器且仍要写回，路径最长。用 P&H 的教学示例延迟（**仅为说明量级、非某具体芯片**）：

    指令存储器 ≈ 200 ps ；寄存器堆访问 ≈ 100 ps ；ALU/加法器 ≈ 200 ps ；数据存储器 ≈ 200 ps ；MUX/控制/立即数生成/PC ≈ 0
    load 关键路径 ≈ 200 + 100 + 200 + 200 + 100 = 800 ps
    R 型 ≈ 200 + 100 + 200 + 100 = 600 ps ；store ≈ 700 ps ；beq ≈ 500 ps

时钟周期必须取最长的 800 ps，于是**即使一条 beq 只需 500 ps 也得等满 800 ps**。这就是"一刀切时钟"的浪费：快指令被迫按慢指令的节拍走。

### 4.5.3 为什么不能"变长时钟"，以及走向流水化

让时钟周期可变，快指令用短拍、慢指令用长拍。但这在硬件上不现实——时钟是全局周期性信号，无法逐指令临时伸缩；而且即便能做，单周期每拍只处理一条指令、每个部件一拍只用一次，硬件利用率极低（load 用内存时 ALU 闲着，反之亦然）。P&H 因此判定：**单周期实现虽正确、易懂，但对真实机器"慢得不可接受"**，尤其当指令集里存在浮点等远超其他指令耗时的操作时更糟。

出路不是缩短单条指令的时间，而是**让多条指令重叠执行**：把 4.1 的五步拆成五个流水段（IF/ID/EX/MEM/WB），每段配一个流水寄存器，时钟周期只需容纳**最慢的一段**（约 200 ps 量级）而非整条指令（800 ps），同时让五条指令在五个段里并行流动。理想情况下吞吐提升接近段数倍——这正是下一大主题 CO-5 流水线的起点。要留意的伏笔：单周期用两块独立存储器（指令/数据）回避了取指与访存争用，但流水线里 IF 与 MEM 会在同一拍同时活动，那个"结构冒险"又会回来（CO-5.2）；单周期"分支要等 ALU 算完才知方向"的性质，则变成流水线的控制冒险（CO-5.5）。

（进阶提示：本机 x86-64 是深流水、超标量、乱序执行的实现，与这里的教学单周期模型是两回事；乱序/超标量深化归 L5-05，勿在此深挖。）
