前面两大主题的系统搜索（BFS/UCS/A\*）都在解决同一类问题：从初始状态出发，找到一条通往目标的**路径**，路径本身就是答案。本主题松开这个设定，进入三种更贴近现实的复杂环境：一是只关心"最终落在哪个好状态"、根本不在乎怎么走到的**优化问题**（局部搜索）；二是动作结果**不确定**、执行同一个动作可能有多种后果的环境；三是智能体**看不全世界**、只能靠有限感知甚至完全无感知行动的环境。它们共同的对照面是：局部搜索通常**不保证完备、也不保证最优，只求一个足够好的解**，用极小的内存换取在巨大甚至连续空间里的可行性。

## 4.1 爬山法与局部极值

### 4.1.1 局部搜索与优化问题：为什么不要路径

局部搜索面向的是一类特殊问题：解就是某个**状态**本身，而不是抵达它的路径。典型如八皇后——只要给出一个没有皇后互相攻击的棋盘布局即可，谁也不关心你是按什么顺序摆上去的。这类问题的目标常写成一个**目标函数**（objective function），要最大化（或最小化）它，因此又叫优化问题。

局部搜索只在内存里保留**当前一个（或极少数几个）状态**，反复用它的邻居替换它，逐步改善，而不像系统搜索那样维护一棵不断膨胀的搜索树。带来两个直接好处：内存占用几乎是常数，与状态空间大小无关；而且能处理状态空间无限大、根本画不出完整搜索树的问题（例如连续参数优化）。代价是它放弃了系统性——走过的地方不记账，也就谈不上完备或最优。

理解局部搜索的一个好心智图像是**状态空间地形图**（state-space landscape）：横轴铺开所有状态，纵轴是目标函数值，于是解空间变成一片高低起伏的山地，优化就是"在这片山地里爬到尽可能高的山峰"。这个地形图的比喻贯穿本节所有算法。

### 4.1.2 爬山法（最陡上升）

爬山法是最朴素的局部搜索：每一步都环顾当前状态的所有邻居，挑目标函数值**最高的那个**移动过去；一旦所有邻居都不比当前状态更高，就停下并返回当前状态。因为总朝着"最陡的上坡"方向走，它也叫最陡上升爬山法（steepest-ascent hill climbing）。

```
function HILL-CLIMBING(problem) returns 一个局部最优状态
    current ← problem.初始状态
    loop do
        neighbor ← current 的邻居中 VALUE 最高的一个
        if VALUE(neighbor) ≤ VALUE(current) then return current
        current ← neighbor
```

它的直觉就是"贪心地一路往高处走"，实现简单、每步只看局部、内存极省。要注意的关键点：它**没有前瞻**，只比较眼前一圈邻居，看不到山那边可能有更高的峰；而且判停条件是"邻居没有更高的"，这只能保证走到一个**局部**高点，不能保证是全局最高。正因如此，爬山法有时被戏称为"贪婪的登山者在浓雾中只能摸到脚边"。

### 4.1.3 局部极值的三类陷阱：局部极大、平台、山脊

爬山法之所以不完备，是因为地形图里有三种典型地形会让它提前卡死。

局部极大（local maximum）是比周围都高、但低于全局最高峰的山头；爬山法一旦登顶就再也不肯下山，于是困死在次优解。

平台（plateau）是一片平坦区域，邻居的目标值都和当前相等；其中若整片是"平顶"（flat local maximum）则彻底走不动，若是通往更高处的"肩台"（shoulder）则本可穿过去，但因为没有上坡方向，普通爬山法同样会停下。

山脊（ridge）是一串斜向排列的小峰，像连续的高地脊线；由于智能体只能沿坐标轴方向（离散邻居）移动，无法直接沿脊线斜着走，只能在脊的两侧来回小步蹭，进展极慢甚至卡住。山脊是三者中最不直观、也最容易被初学者忽略的一种。

在随机初始化的八皇后问题上，最陡上升爬山法只有约 14% 的概率解出，其余大多卡在局部极值；但引入下面的变体后成功率大幅提升。这个 14% 的量级见于 AIMA 与 CS188 教材，具体数字随实现和邻居定义略有出入，此处取教材口径。

### 4.1.4 爬山法的常见变体

为了缓解卡死，教材给出几种改良。随机爬山（stochastic hill climbing）不总选最陡的邻居，而是在所有上坡邻居里按某种概率随机挑一个，收敛更慢但有时能探到更好的解。首选爬山（first-choice hill climbing）随机生成邻居、遇到第一个比当前好的就走，适合邻居数量极多、逐一枚举太贵的场景。

真正把成功率拉高的是随机重启爬山（random-restart hill climbing）：反复从随机初始状态跑普通爬山，保留历次结果里最好的一个。它的直觉是"多试几个出发点，总有一个落在通往全局峰的坡上"。如果每次成功概率为 p，那么期望大约

重启次数 ≈ 1 / p

次就能找到解。对八皇后这类 p 不算太小的问题，随机重启几乎能瞬间解出。这里体现了局部搜索的一贯哲学：不追求单次的完备性，而用廉价的重复与随机性去逼近好解。

## 4.2 模拟退火

### 4.2.1 核心思想：让搜索"有时候下山"

纯爬山法永不下山，所以困在局部峰；纯随机游走什么都不管地乱走，虽然理论上能到处跑但效率极低。模拟退火（simulated annealing）是这两者的折中：大部分时候像爬山一样往高处走，但**允许以一定概率接受"下坡"（变差）的移动**，从而有机会跳出局部峰、越过山谷去够更高的峰。

名字来自冶金：把金属加热再缓慢冷却，让原子有足够能量跳出局部的晶格缺陷、最终落到能量更低更稳定的排列。算法里"温度"高时更容易接受坏移动（大胆探索），温度随时间下降后越来越保守（收敛到爬山）。

### 4.2.2 接受概率与温度调度

模拟退火每步随机选一个邻居 next，计算它相对当前的改善量

ΔE = VALUE(next) − VALUE(current)

若 ΔE > 0（邻居更好）就无条件接受；若 ΔE ≤ 0（邻居更差）则**只以下面的概率**接受：

P(接受) = e^(ΔE / T)

其中 T 是当前温度，由一个随时间递减的调度函数 schedule(t) 给出。这里 ΔE ≤ 0，所以指数为负、概率在 0 到 1 之间：邻居越差（ΔE 越负）接受概率越低；温度 T 越高，同样的坏移动越容易被接受。随着 T → 0，接受坏移动的概率趋于 0，算法退化为普通爬山。

上面写法沿用 AIMA 的**最大化**约定（VALUE 越大越好，改善 ΔE > 0）。很多资料按**最小化**能量/代价来写，则改善意味着 ΔE < 0，接受概率写成

P(接受) = e^(−ΔE / T)

两种写法只是符号约定不同、机制完全一致：改善必接受，变差按指数概率接受。初学者最容易在这里被两套符号绕晕，认准"对'变差'的那一步、其概率随'变差幅度'和'温度倒数'指数衰减"即可。

### 4.2.3 伪代码与收敛性质

```
function SIMULATED-ANNEALING(problem, schedule) returns 一个解状态
    current ← problem.初始状态
    for t = 1, 2, 3, ... do
        T ← schedule(t)
        if T = 0 then return current
        next ← current 的一个随机邻居
        ΔE ← VALUE(next) − VALUE(current)
        if ΔE > 0 then current ← next
        else current ← next 仅以概率 e^(ΔE / T)
```

一个重要而带前提的理论结论：**如果温度下降得足够慢，模拟退火以趋于 1 的概率找到全局最优**。但"足够慢"在实践中往往慢到不可接受，所以现实里用的是几何降温（T 每步乘一个略小于 1 的系数）等启发式调度，只求好解、不追理论保证。调度函数的选择（初温、降温速率、停止条件）对效果影响很大，属于需要调参的工程部分。

本机用几何降温的模拟退火解一个 12 城 TSP（随机坐标，交换两城为邻居动作，最小化总回路长），可复现地把一条乱序回路显著缩短：

```
基线 Py3.11.15/np2.4.6/gcc13.3 @2026-07-25
$ python3 sa_tsp.py
start_len=7.7506  best_len=3.4133  improvement=56.0%
```

脚本核心：`dE = cur_len - tour_len(nxt)`（回路变短则 dE>0 视为改善），`if dE>0 or rng.random() < np.exp(dE/T): 接受`，`T = max(1e-4, 0.9999**step)`。这坐实了"改善必接受、变差按 e^(ΔE/T) 概率接受"的机制在最小化任务上的落地形态；它是对多来源比对的补充，不替代比对。

## 4.3 局部束搜索 / 遗传算法

### 4.3.1 局部束搜索

局部束搜索（local beam search）同时保留 **k 个状态**而非一个。每轮生成这 k 个状态的所有邻居，把它们汇成一个大候选池，再从池里挑出**全局最好的 k 个**进入下一轮；如此往复。

它和"跑 k 次独立的随机重启爬山"有一个关键区别，初学者常混淆：随机重启的 k 条线彼此完全独立、各走各的；而局部束搜索的 k 个状态在每轮**共享信息**——因为下一轮的 k 个是从所有邻居里统一挑的，如果某个状态附近特别有希望，它会生出很多好邻居，从而"吸引"整个种群的搜索资源涌向那片高地。这既是优点（快速集中到好区域），也是缺点（k 个状态容易迅速聚成一团、丧失多样性，退化成一次爬山）。

为缓解聚集，随机束搜索（stochastic beam search）不选"绝对最好的 k 个"，而是按目标值高低赋概率、随机抽 k 个后继，保留一定多样性。它与下面的遗传算法有直接的思想血缘。

### 4.3.2 遗传算法：种群、适应度与选择

遗传算法（genetic algorithm）是随机束搜索的一个变体，灵感来自生物进化。它把候选解编码成**字符串**（如八皇后用长度 8 的串，每位记一列皇后所在行），维护一个 k 个个体的**种群**（population）。每个个体有一个**适应度**（fitness，就是目标函数值）。

每一代按适应度做**选择**（selection）：适应度越高的个体被选作父母的概率越大（常用"轮盘赌"——选中概率正比于适应度）。这一步给进化提供方向：好解更可能把自己的片段传下去。

### 4.3.3 交叉与变异

被选中的两个父母通过**交叉**（crossover）产生后代：随机选一个切点，把父 A 的前半段和父 B 的后半段拼成一个孩子（另一种拼法得到另一个孩子）。

```
父A:  3 2 7 5 | 2 4 1 1
父B:  2 4 7 4 | 8 5 5 2
------------------------- 切点在第4位之后
子1:  3 2 7 5 | 8 5 5 2
子2:  2 4 7 4 | 2 4 1 1
```

之后对每个孩子做**变异**（mutation）：以一个小概率随机改动某些位（如把某列皇后挪到随机行）。交叉负责"重组已有的好片段"，变异负责"注入新基因、维持多样性、避免整个种群早早收敛到同一点"。

如果两个父母各自在解的不同部分表现好，交叉有机会把两段好片段拼到一个孩子身上，从而"1+1>2"。但这依赖一个前提——**编码方式要让"相邻的位"构成有意义的、可独立组合的子结构**（教材称 schema/构件块思想）；若编码随意、切开后两半拼起来毫无意义，交叉就退化成纯随机扰动。这是遗传算法最大的易错点：它的成败高度依赖问题的**表示（representation）**设计，换个编码效果可能天差地别。它同样**不保证最优、不保证完备**，是一种靠群体随机性搜好解的启发式。

## 4.4 连续空间局部搜索

### 4.4.1 从离散邻居到连续地形

前几节的邻居都是离散的（挪一个皇后、交换两座城）。但很多现实问题的状态是**连续的实数向量**（如把三座机场放在平面上，使各城市到最近机场的距离平方和最小，变量是 6 个坐标）。连续空间里"邻居"有无穷多个，无法枚举，爬山法那套"看一圈邻居选最高"直接失效，必须换用**微积分**的工具。这一节是符号搜索通向数值优化的桥，只作对照、不深挖。

离散局部搜索靠"枚举有限邻居 + 比较"，连续局部搜索靠"求目标函数的**梯度**、沿梯度方向迈步"。

### 4.4.2 梯度上升 / 梯度下降

对连续可微的目标函数 f(x)，其**梯度** ∇f 是各偏导数组成的向量，指向 f **上升最快**的方向。要最大化 f，就沿梯度方向按步长 α 更新：

x ← x + α ∇f(x)

要最小化则朝反方向（梯度下降）：

x ← x − α ∇f(x)

直觉上梯度就是"当前点最陡的上坡方向"，梯度上升是爬山法在连续空间的自然对应物。关键的调参点是步长 α：太大可能越过峰顶来回震荡甚至发散，太小则收敛极慢。当梯度为零（∇f = 0）时到达驻点（可能是极大、极小或鞍点），迭代停下——所以它同样只找**局部**最优，和离散爬山法一样会被局部极值困住。

### 4.4.3 牛顿-拉夫森法

若能进一步算出二阶导数信息，可用牛顿-拉夫森法（Newton–Raphson）更快收敛。它本用于解方程 g(x)=0，令 g=∇f 即把"求极值"转化为"求梯度的零点"，更新式用到**Hessian 矩阵** H（二阶偏导矩阵）：

x ← x − H⁻¹(x) ∇f(x)

它的直觉是"用二次曲面局部逼近目标函数，一步跳到该抛物面的顶点"，因此在接近最优时收敛比一阶梯度法快得多。代价是每步要计算并求逆 Hessian，维度 n 高时 H 是 n×n、求逆昂贵，所以大规模问题里常用只近似 Hessian 的拟牛顿法（如 L-BFGS）。这些细节属于数值优化的纵深，此处只登记它与梯度法的分工。

### 4.4.4 约束优化与通往机器学习优化的桥

上面都是无约束优化。若变量还要满足约束（如坐标必须落在某区域内），就进入**约束优化**（constrained optimization）；最简单的一类是线性规划（目标与约束都线性），有成熟多项式算法。AIMA 在此点到为止。

机器学习里训练模型（最小化损失函数）本质就是这里的连续空间局部搜索——梯度下降及其变体正是深度学习优化器的基础。区别只在于 ML 的目标函数是"在数据上的损失"、维度动辄百万。这条线的系统展开归机器学习与深度学习课程，本主题只搭桥、不展开。

## 4.5 非确定性动作与 AND-OR 搜索

### 4.5.1 非确定性环境与条件计划

前面所有搜索都假设动作是**确定的**：在某状态执行某动作，结果状态唯一可知，于是解是一条动作序列（一条路径）。但很多环境是**非确定的**：同一个动作可能产生多种结果，智能体事先不知道会落到哪个。AIMA 用"反常吸尘器世界"（erratic vacuum world）举例——执行 Suck 有时清一格、有时反而弄脏一格，结果不唯一。

此时一条固定的动作序列不再可靠，解必须是一个**条件计划**（conditional plan / contingency plan）：它像带 if-then-else 的程序，根据动作**执行后感知到的实际结果**分支决定下一步。例如"先 Suck，如果发现还脏就再 Suck，否则前进"。理解这一转变是本节的核心：从"给一条路"变成"给一棵能应对各种意外的决策树"。

### 4.5.2 AND-OR 搜索树

为求解条件计划，搜索树里出现两类交替的节点。

OR 节点是智能体**自己选动作**的地方——它有多个动作可选，只需选**一个**能成功的（"或"关系），和普通搜索的分支一样。

AND 节点是动作执行后环境**掷出多种可能结果**的地方——因为智能体无法控制落到哪个结果，计划必须对**每一个**可能结果都有应对（"与"关系），即所有分支都得成功，这个节点才算解决。

于是搜索树在 OR 层和 AND 层之间交替，称 AND-OR 搜索树。一个解不再是一条路径，而是这棵树的一个**子树**：在每个 OR 节点选定一个动作、在每个 AND 节点包含全部结果分支、且每条叶子都抵达目标。这正是条件计划的树形表示。

### 4.5.3 应急计划与循环计划（try, try again）

有些非确定问题里，某个坏结果可以通过**重试**来纠正。比如动作偶尔失败、失败后状态不变，那么"一直重试直到成功"是合理的解。这引出**带循环的计划**：条件计划里允许出现"回到之前某步"的循环，表达"反复尝试直到达成"。

```
[Suck, while 感知到 Dirty do Suck, ...]
```

这类循环计划的成立需要一个前提——只要不断重试、成功的结果**终会出现**（AIMA 称环境的这种性质，直觉上即"坏运气不会无限持续"）；否则循环可能永不终止。这里体现了非确定搜索与确定搜索的又一差异：解的"完备"含义从"找到一条到目标的路"变成"找到一个在所有可能演化下都能到达目标的（可能带循环的）计划"。

## 4.6 部分可观测 / 在线搜索

### 4.6.1 信念状态

前面都假设环境**完全可观测**——智能体随时知道自己确切处在哪个状态。现实中传感器有限甚至没有，智能体常常**不确定自己身处哪个状态**。应对办法是引入**信念状态**（belief state）：不是单个物理状态，而是"当前所有可能所处状态的集合"。

虽然对物理世界不确定，但智能体对"自己的信念状态"是完全确定、完全可观测的。于是可以在**信念状态空间**上重新做一次普通搜索——起点是初始信念集，动作把一个信念集映到另一个信念集，目标是"这个信念集里所有状态都满足目标"。代价是信念状态空间可能巨大：n 个物理状态就有多达 2ⁿ 个信念状态。这是理解后续所有部分可观测搜索的基石。

### 4.6.2 无传感（无观测）搜索

最极端的情形是**完全没有传感器**（sensorless，又称 conformant 规划）：智能体行动时得不到任何反馈。此时解必须是一条**固定动作序列**，它要保证无论真实初始状态是哪个、无论过程如何，执行完都落到目标。

即使看不见，动作本身也可能**缩小信念状态**。例如吸尘器世界里，不管初始在哪、脏成什么样，只要执行足够多的 Right、Suck 组合，就能把"可能所在状态的集合"逐步压成单点、强制到达干净状态。所以无传感问题就是在信念状态空间里找一条使信念集收敛到目标的路径。

### 4.6.3 部分可观测搜索

介于全可观测与无传感之间的是**部分可观测**：有传感器但只提供局部信息。此时每次动作后，感知会把当前信念状态**分割**成若干更小的信念状态（对应观测到的不同结果）——因为"观测到什么"取决于真实状态，而智能体事先不知道会观测到哪个。

于是部分可观测问题天然结合了前一节的 AND-OR 结构：动作（预测）是 OR 分支，观测（把信念集按可能感知分裂）是 AND 分支，解又是一个条件计划——根据实际观测在信念状态树里选分支前进。这把 4.5 的 AND-OR 搜索和 4.6 的信念状态两条线缝在一起。

### 4.6.4 在线搜索与探索

前面都是**离线搜索**：先在脑中把完整解算好，再一步步执行。**在线搜索**（online search）则是"边走边算"——执行一个动作、观察结果、再决定下一动作，交错进行。它适用于**未知环境**：地图事先不知道，智能体只有真正走到某状态、才知道那里有哪些可用动作和后继（如机器人首次进入陌生迷宫）。

在线搜索无法像 A\* 那样先看全局再规划，因为它根本没有全局信息，只能在探索中逐步建图。衡量在线算法好坏常用**竞争比**（competitive ratio）：智能体实际走过的代价，与"事先若知道完整地图、最优路径"的代价之比；比值越接近 1 越好。有些地形（如带死胡同的图）会让任何在线算法的竞争比无界地差——这坐实了"信息缺失本身就有代价"，是在线搜索区别于离线搜索的根本点。

### 4.6.5 LRTA\*（实时学习 A\*）

在线局部搜索的代表算法是 LRTA\*（Learning Real-Time A\*）。它把爬山法搬到未知环境，并加两个关键改造使之不再困于局部极值：一是给每个到访过的状态维护一个"到目标的代价估计" H(s)，用实地经验不断更新它；二是当发现当前处身于局部极小（周围都不更好）时，不是卡死，而是**把当前状态的估计值抬高**（"这里其实没那么好走"），从而下次会主动避开、转向别处探索。

它的直觉是"一个会记路、会在碰壁后修正自己地图判断的实时登山者"。因为每步只做局部计算并立即行动，LRTA\* 满足**实时**约束（适合必须马上出招、来不及全局规划的场景）；随着反复行走、H 值逐渐收敛，它能在有限、可探索的环境中最终找到目标。这是本主题"局部/实时/不完备但可行"思路在未知环境下的收束点。
