# L5-08·大主题3 启发式（有信息）搜索

> 基线 Py3.11.15/np2.4.6/gcc13.3 @2026-07-25 ｜ 核实日期：2026-08-01 ｜ 先修：L5-08·大主题2 无信息搜索（通用搜索框架、UCS/Dijkstra、树搜索 vs 图搜索、b/d/m 复杂度符号） ｜ 一手锚点：AIMA《人工智能：现代方法》4th ed 2020 Ch3 §3.5–3.6；Berkeley CS188 Spring 2025 L3 ｜ 成熟度：GA（经典内容，多版本稳定）

无信息搜索（BFS/UCS/DFS 等）只知道"已经走了多远"，对"离目标还有多远"一无所知，只能盲目地把前沿铺开。启发式搜索给算法加上一个额外的知识来源：一个估计函数，对每个状态给出"从这里到目标大约还要多少代价"的猜测。有了这个猜测，算法就能优先朝目标方向走，往往把要探索的状态数从指数级压下一大截。本报告讲清这个估计函数（启发函数）怎么用、A\* 如何把"已走代价"与"预估剩余"合成一个评价、以及两条决定 A\* 能否找到最优解的性质——可采纳性与一致性——它们的区别、各自保证哪种搜索（树搜索 vs 图搜索）最优，是本主题最核心也最易混的点。最后讲怎么系统地设计出好的启发函数。

## 3.1 贪心最佳优先搜索

### 3.1.1 启发函数 h(n) 与"有信息"的含义

启发函数（heuristic function）记作 h(n)，输入一个状态（或对应的搜索节点）n，输出一个非负数，表示"从 n 到最近目标状态的代价"的估计。约定目标状态处 h 为 0。

"有信息搜索"（informed search）就是指算法在决定下一步扩展谁时，用上了 h 这个来自问题领域的额外知识；与之相对，"无信息搜索"只用问题定义本身（初始态、动作、目标测试、代价），不带任何"离目标多远"的线索。

h 是"估计"这一点要抓牢。它不必精确，也几乎从不精确——如果 h 恰好等于真实剩余代价，搜索就能一步不错地直奔目标，但那等于已经解出了问题。h 的价值在于用一个便宜就能算出的粗略猜测，去引导本来盲目的搜索。典型例子：在地图上找最短公路路线时，两点间的直线距离就是一个现成的 h——它一定不超过实际要开的公路里程，却能立刻告诉算法哪个方向"看起来更近"。初学者容易把 h 和"已经走过的代价"混为一谈：已走代价是回头看、是确定的事实；h 是向前看、是对未来的猜测。两者在 A\* 里会被明确分成两项（见 3.2）。

### 3.1.2 贪心最佳优先搜索的定义

贪心最佳优先搜索（greedy best-first search）是最直接地使用 h 的策略：它总是扩展当前前沿中 h(n) 最小的节点，也就是"看起来离目标最近"的那个。它把评价函数直接取成

f(n) = h(n)

用一个按 h 排序的优先队列实现：每次弹出 h 最小的节点扩展，把它的后继按各自的 h 值插回队列。

"贪心"二字点明了它的行为：每一步都只顾眼前最诱人的选择，只看"预估还剩多远"，完全不管"为了到这里已经花了多少"。在路线规划里，它会一直挑那个直线距离离终点最近的城市往前冲。这样做通常很快、扩展的节点很少，因为它不像 UCS 那样均匀铺开，而是径直朝目标扑过去。

### 3.1.3 为什么贪心快却不最优、也不（总）完备

贪心最佳优先不保证找到最优解，因为它完全忽略了已走代价 g。它可能一头扎进一条"看起来近、实则绕远"的路：某个后继的 h 很小，于是被优先选中，但通往它的那一步本身代价很高，或它之后其实还要绕一大圈。经典的地图例子里，贪心会选直线距离更近的下一城，结果走出一条比最短路更长的路线。

完备性也没有保证。在树搜索版本（不记录已访问状态）里，贪心可能在两个互相"看起来更近"的状态间来回跳、陷入死循环，永远到不了目标；在有限状态空间上用图搜索版本（记录已达状态、去重）则可以做到完备，但仍然不最优。

它的最坏情况时间和空间复杂度都是

O(b^m)

其中 b 是分支因子、m 是状态空间的最大深度——也就是说最坏情况下并不比无信息搜索好。但一个好的启发函数能在实践中把这个开销大幅压低。一句话记住贪心的取舍：只看 h、不看 g，所以跑得快、找得省，但可能找错、甚至找不到。A\* 正是为了修掉"不看 g"这个毛病而来。

## 3.2 A\* 算法

### 3.2.1 评价函数 f(n) = g(n) + h(n)

A\*（读作 A-star）在贪心的基础上补回了被忽略的已走代价。它扩展的不是 h 最小的节点，而是 f 最小的节点，其中

f(n) = g(n) + h(n)

这里 g(n) 是从初始状态到达 n 的实际路径代价（回头看，确定值），h(n) 是从 n 到目标的估计剩余代价（向前看，猜测值）。于是 f(n) 就是"经过 n 的这条解路径，其总代价的估计值"。

把两项合起来看，A\* 的每一步都在问同一个问题：在所有还没走完的候选路径里，哪一条的"预计全程总代价"最小？它优先推进那一条。这既避免了贪心"只顾眼前不问来路"的短视，又比 UCS（相当于 h 恒为 0、只看 g）更有方向感。两个极端很有助记忆：h≡0 时 A\* 退化成 UCS（等价 Dijkstra）；g 被忽略时退化成贪心最佳优先。A\* 是二者的合流。

### 3.2.2 A\* 的展开规则与"目标出队才算数"

A\* 用一个按 f 值排序的优先队列（前沿）实现：每次弹出 f 最小的节点扩展，为其每个后继 n′ 计算

f(n′) = g(n′) + h(n′) = g(n) + c(n, a, n′) + h(n′)

其中 c(n, a, n′) 是从 n 经动作 a 到 n′ 的这一步代价，然后把后继插回队列。

A\* 在目标节点被"生成"时还不能停，必须等它被"从前沿弹出（选中扩展）"时才终止并返回。原因是：某个目标节点第一次被生成时，可能是沿一条较贵的路径到达的，此刻队列里也许还压着另一条通往同一目标、f 更小（更便宜）的路径没被处理。只有当目标节点成为队列里 f 最小者被弹出时，才能确信没有更便宜的解在等着——这正是 A\* 最优性论证的落点（见 3.3）。初学者若在"生成目标即返回"处收手，就可能拿到次优解。

### 3.2.3 完备性、复杂度与"最优效率"

在代价有正的下界、状态空间可数（或有限）且启发式满足下节条件时，A\* 是完备的（有解必找到）且最优的（找到的是最小代价解）。

复杂度方面，A\* 最坏情况下时间与空间仍是指数级，随启发式的"误差"增长——粗略地说，启发式越接近真实剩余代价，被扩展的节点越少。真正的瓶颈通常是空间：A\* 要把所有已生成的节点保存在内存里（前沿加已达记录），内存往往先于时间被耗尽。

A\* 还有一条常被引用的性质：在使用同一个（可采纳的）启发函数、且要保证最优的所有算法中，A\* 是"最优效率的"（optimally efficient）——不存在另一个保证最优的算法，能在扩展节点数上确定地比 A\* 更少（对 f 值恰好等于最优代价的那些节点，不同的平局处理会有出入）。直觉是：任何保证最优的算法都必须扩展所有 f(n) 严格小于最优解代价的节点，否则就可能漏掉一条更便宜的路；而 A\* 恰好只扩展这些"不得不扩展"的节点。

下面是就地跑出的真实对比，用一个 21×21 的开阔网格（四邻域、每步代价 1）从 (10,10) 走到 (10,16)，UCS 相当于 h≡0，A\* 用曼哈顿距离作 h：

```
open 21x21 grid, start(10, 10)->goal(10, 16)
UCS  (h=0)   : cost=6 expanded=74
A*(Manhattan): cost=6 expanded=7
```

两者都找到代价为 6 的最优路径，但 UCS 向四面八方铺开、扩展了 74 个状态，A\* 在启发式引导下几乎径直走向目标、只扩展 7 个。这直观展示了"有信息"的价值：不改变解的最优性，却大幅减少工作量。

### 3.2.4 内存受限变体（登记，不深挖）

因为 A\* 的空间开销常先爆掉，实践中派生了若干省内存变体，这里只作广度登记：迭代加深 A\*（IDA\*）借迭代加深的思路，用不断放宽的 f 上界做深度优先式探索，空间降到线性；递归最佳优先（RBFS）与 SMA\*（简化的内存受限 A\*）在有限内存下尽量逼近 A\* 的行为；加权 A\* 用

f(n) = g(n) + W·h(n)　（W > 1）

放大启发项，牺牲最优性换更快、更省的近似解——它找到的解代价不超过最优代价的 W 倍。这些变体的机制细节不在本报告纵深范围内，知道它们都是为缓解 A\* 内存/速度瓶颈而生即可。

## 3.3 可采纳性（admissible）

### 3.3.1 可采纳启发式的定义

一个启发函数是可采纳的（admissible），当且仅当它对每个状态都不高估到达目标的真实最小代价。记 h\*(n) 为从 n 到最近目标的真实最小代价，则可采纳的条件是对所有 n：

h(n) ≤ h*(n)

也就是说，可采纳启发式是"乐观的"——它永远不会把剩余路程说得比实际更远，最多说得偏近。

一个乐观的估计为什么有用？因为它保证 A\* 不会因为"高估了某条好路的剩余代价"而错过它。地图上的直线距离是可采纳的典型例子：任何两点间的公路里程都不可能短于直线距离，所以用直线距离当 h 一定不高估。h 恒为 0 也是可采纳的（0 显然不超过任何真实代价）——这正是 UCS 可看作 A\* 特例的原因。

### 3.3.2 可采纳 ⇒ 树搜索版 A\* 最优

若 h 可采纳，则树搜索版本的 A\*（不做重复状态去重、把每条路径当独立节点）返回的一定是最优解。这是本节的核心结论。

论证的直觉（不做完整推导）：设最优解代价为 C\*。考虑任意一个位于次优目标（代价 > C\*）路径上、已在前沿的目标节点 n₂，它的 f(n₂) = g(n₂) + 0 = g(n₂) > C\*。另一方面，最优解路径上总存在某个已在前沿的节点 n，它满足 f(n) = g(n) + h(n) ≤ C\*——这一步正是用到可采纳性：h(n) 不高估，所以 g(n)+h(n) 不超过经过 n 的最优路径总代价 C\*。于是 f(n) ≤ C\* < f(n₂)，A\* 会先弹出并推进最优路径上的 n，而不会先弹出次优目标 n₂。因为 A\* 只在目标被弹出时才终止（见 3.2.2），它必然先经由最优路径抵达并返回代价为 C\* 的解。

初学者要记住这条结论的适用范围：可采纳性单独只保证树搜索 A\* 最优。若做了状态去重（图搜索）而启发式只是可采纳、并不"一致"，最优性可能被破坏，需要额外条件或额外处理——这正是下一节一致性要解决的问题，也是本主题最大的易错点。

### 3.3.3 高估会破坏最优性（实证）

反过来，如果启发式高估了某处的剩余代价（不可采纳），A\* 就可能返回次优解：被高估的那条路的 f 被人为抬高，显得不划算，于是算法转而选一条真实更贵、但 f 看起来更小的路。

下面用一个小图就地演示。图中从 S 到目标 G 有两条路：S-A-G 总代价 2（最优），S-B-G 总代价 6。先用一个可采纳的 h（处处不高估），再故意把 A 处的 h 从真实值 1 高估到 6：

```
graph: S-A-G=2 (optimal), S-B-G=6
admissible h  : (2, ['S', 'A', 'G'])
inadmissible h: (6, ['S', 'B', 'G'])  <- returns costlier path
```

可采纳启发式下 A\* 正确返回代价 2 的最优路 S-A-G；一旦在 A 处高估，A 这条本该最优的路被"看扁"，A\* 改走了代价 6 的 S-B-G，丢掉了最优性。这就是"不高估"这一条为什么是硬要求——它是 A\* 最优性的地基。

## 3.4 一致性（consistent）

### 3.4.1 一致启发式的定义（三角不等式）

一个启发函数是一致的（consistent，又称单调 monotone），当且仅当对每个状态 n、每个动作 a 及其后继 n′，都满足

h(n) ≤ c(n, a, n′) + h(n′)

其中 c(n, a, n′) 是从 n 经 a 到 n′ 的这一步代价。这是一条"三角不等式"：从 n 直接估计到目标的代价，不超过"先走一步到 n′、再从 n′ 估计到目标"的代价。

直觉上，一致性要求启发式的估计在每走一步时"下降得不过分"——从 n 迈到 n′，剩余估计 h 至多减少这一步的真实代价 c。它排除了那种"相邻两状态的估计忽高忽低、自相矛盾"的启发式。地图直线距离又是天然一致的例子：直线距离满足三角不等式，从 n 到目标的直线距离，不会超过 n 到 n′ 的实际里程加上 n′ 到目标的直线距离。

### 3.4.2 一致 ⇒ f 沿任意路径单调不减

沿任意一条路径，f 值单调不减（这也是"单调 monotone"这一别名的由来）。设 n′ 是 n 的后继，则

f(n′) = g(n′) + h(n′) = g(n) + c(n, a, n′) + h(n′) ≥ g(n) + h(n) = f(n)

其中不等号那一步正是代入一致性条件 h(n) ≤ c(n,a,n′) + h(n′)。

单调不减意味着：A\* 按 f 递增的顺序一层层地弹出节点，就像水位缓缓上涨的等高线扫过状态空间。它的直接推论是：当 A\* 第一次弹出某个状态时，就已经是沿最优路径到达该状态的——后面不会再冒出一条到同一状态更便宜的路。这正是下一条结论的基础。

### 3.4.3 一致 ⇒ 图搜索版 A\* 最优（本主题头号易错点）

若 h 一致，则图搜索版本的 A\*（用已达/已探索集合去重、每个状态只保留一次）返回的一定是最优解，且每个状态至多被扩展一次。这是本节的核心结论。

这里就是可采纳与一致必须分清的地方。图搜索会在一个状态第一次被扩展后就把它"关闭"、丢弃后来指向它的其他路径。如果第一次到达它的不是最优路径，最优解就可能被永久丢掉。一致性恰好排除这种情况：由 3.4.2，一致启发式下 A\* 第一次弹出（扩展）某状态时走的必是最优路径，所以放心去重不会误杀最优解。一致性还顺带保证每个状态至多扩展一次，避免了重复展开的浪费。

务必记牢这组对应关系，它是本主题最常考也最常错的点：

可采纳（不高估）　⇒　树搜索 A\* 最优

一致（三角不等式）⇒　图搜索 A\* 最优（且每状态至多扩展一次）

这里有一处需要点明的**教材表述差异**，不要死记成绝对律条。经典表述（AIMA 3rd ed、以及 CS188 等课堂常用口径）是：图搜索 A\* 要最优，需要一致性；仅可采纳不够。AIMA 4th ed 改用带"重开"机制的最佳优先框架——当发现通往某状态的更便宜路径时，即使该状态已在已达表中，也更新它并把节点重新放回前沿（允许再次扩展）。在这种会"重开节点"的实现下，仅凭可采纳性，图搜索 A\* 也能保持最优；此时一致性的额外价值在于保证不会发生任何重开、每个状态至多扩展一次（效率更好）。两种说法并不矛盾，差别在于"图搜索 A\* 遇到已见状态时是否允许重开"：不重开（经典 closed-set 版）就需要一致性来保最优；允许重开（AIMA 4th 版）则可采纳即够、一致性负责效率。遇到不同教材结论"打架"，先看它默认的是哪种图搜索实现。

### 3.4.4 一致性蕴含可采纳性

一致性比可采纳性更强：每个一致的启发式都是可采纳的（前提是目标处 h=0），反之不成立——存在可采纳但不一致的启发式。

一致性对"每一步"都施加了三角不等式约束，把这些约束沿任意一条到目标的路径累加起来，就得到"从任意状态出发的估计不超过该状态到目标的真实代价"，也就是可采纳。而可采纳只对"到目标的总估计"设限，并不管相邻状态间的估计是否协调，所以可采纳的启发式未必一致。实践中，绝大多数自然设计出来的可采纳启发式（如曼哈顿距离、直线距离）本身就一致，需要特意构造才能得到"可采纳但不一致"的例子；但只要你在图搜索里用了仅可采纳、不保证一致的启发式，就要警惕上一条讲的最优性风险。

## 3.5 启发式设计

### 3.5.1 松弛问题导出可采纳启发式

设计可采纳启发式最系统的一招是"松弛问题"（relaxed problem）：把原问题的动作限制去掉一些，得到一个更容易解的问题；这个松弛问题的最优解代价，就是原问题的一个可采纳启发式。

为什么一定可采纳？因为松弛问题的动作只多不少（原问题的每个动作在松弛问题里仍合法），所以原问题的任何一条解，在松弛问题里也是一条合法的解；于是松弛问题的最优代价不会超过原问题的最优代价，即"不高估"。而且这样得到的启发式通常还自动是一致的。

八数码是标准示范。原问题的规则是"一块只能滑进相邻的空格"。松弛掉不同的限制，得到两个经典启发式：

去掉"必须滑进空格、且只能移到相邻格"两条限制，允许任一块一步直接飞到它的目标格——解这个松弛问题要走的步数，就是"不在位的块数"（misplaced tiles）启发式。

只去掉"目标格必须是空格"这一条、但仍要求每步只能移到相邻格——解这个松弛问题就是每块各自走到目标格的网格距离之和，即"曼哈顿距离"（Manhattan distance）启发式。

两者都可采纳。哪个更好？见下一条。

### 3.5.2 主导性（dominance）与搜索效率

给定两个都可采纳的启发式 h₂ 和 h₁，若对每个状态都有 h₂(n) ≥ h₁(n)，就称 h₂ 主导（dominate）h₁。主导者更好：用 h₂ 的 A\* 扩展的节点数不会多于用 h₁ 的 A\*（平局处理的细节除外）。

在不高估的前提下，启发式的估计越大就越贴近真实剩余代价，A\* 就越少被"看起来还很近其实很远"的节点骗去扩展。极端地，h≡0（UCS）被一切可采纳启发式主导，所以最盲目、扩展最多。在八数码里，曼哈顿距离处处不小于不在位块数（每个不在位的块对曼哈顿贡献至少 1，对块数只贡献 1，且移位远的块贡献更多），所以曼哈顿主导块数、更高效。

下面是就地跑出的对比，同一个八数码初始局面，分别用两种启发式做图搜索 A\*：

```
8-puzzle start=(7, 2, 4, 5, 0, 6, 8, 3, 1)
misplaced-tiles h: cost=20 expanded=3667
manhattan      h: cost=20 expanded=283  (dominates -> fewer expansions, same optimal cost)
```

两者都找到 20 步的最优解，但曼哈顿距离只扩展 283 个状态，不在位块数扩展了 3667 个——十几倍的差距，正是"主导者更贴近真实、更省"的体现。选启发式时，在都可采纳的前提下，尽量选主导性更强（估计值更大）的。

### 3.5.3 组合多个启发式（取最大值）

如果手上有若干个都可采纳的启发式 h₁, h₂, …, h_k，而它们互不主导（各有各强的地方），可以把它们组合成一个更强的可采纳启发式，方法是逐状态取最大值：

h(n) = max( h₁(n), h₂(n), …, h_k(n) )

这个组合启发式仍然可采纳：既然每个 h_i 都不超过真实剩余代价 h\*(n)，它们中的最大值也不超过 h\*(n)。同时它主导其中每一个 h_i（因为处处不小于任何单个）。

直觉是"博采众长"：每个状态处，谁给出的（乐观）估计最大、就最接近真相，就采信谁。代价是每步要多算几个启发式再取最大，但只要单个都便宜，这个组合几乎总是划算——它能确保效果不差于其中最好的那个。初学者常犯的错是把多个启发式相加来"增强"——相加一般会破坏可采纳性（会高估），除非能证明它们计的是"互不重叠的代价"（见下一条的可加模式数据库）。默认安全的组合方式是取最大，不是求和。

### 3.5.4 模式数据库（pattern databases）

模式数据库是自动生成强可采纳启发式的一类实用技术。它的思路：选取问题状态的一个"模式"（pattern，即只关心状态的一部分，例如八数码里只盯住 1–4 号四块、其余当作可以随意穿插的"无关块"），预先穷举计算出"仅把这几块归位"这个子问题的精确最小步数，把每种模式局面对应的代价存进一张查找表（数据库）。搜索时，把当前状态投影到这个模式上查表，得到的就是一个可采纳启发式——因为解决整个问题至少要付出解决这个子问题的代价。

这类启发式往往比曼哈顿距离强得多，因为它捕捉了多块之间的相互牵制（曼哈顿把每块独立看待、忽略了它们会互相挡路）。数据库在搜索前一次性算好、反复查用，把在线代价换成了离线预计算。

进一步有"不相交（可加）模式数据库"（disjoint / additive PDBs）：把所有块划成互不重叠的几组，每组建一个只统计"本组块自身移动步数"的数据库；因为不同组的步数计的是不重叠的移动，几个数据库的值可以相加而仍然可采纳。这是前一条"默认取最大、除非可证不重叠才可加"的正例——正因为各库只记本组块的移动、不重复计数，相加才不会高估。可加模式数据库能给出比取最大更强的启发式，是让十五数码乃至更大滑块问题可解的关键技术之一。

### 3.5.5 用有效分支因子衡量启发式质量

要比较两个启发式好在哪，除了直接数扩展节点，还有一个常用的单一指标：有效分支因子（effective branching factor）b\*。若 A\* 用某启发式解一个问题共生成了 N 个节点、最优解深度为 d，则 b\* 是"一棵深度为 d、总节点数为 N 的均匀树"所对应的分支因子，由下式（近似）确定：

N + 1 = 1 + b* + (b*)^2 + … + (b*)^d

b\* 越接近 1，说明启发式把搜索收得越窄、越接近一条直线冲向目标；b\* 越大说明越发散、越接近盲目搜索。它的好处是把"生成节点数"这个随问题规模剧烈变化的量，归一成一个跨问题、跨规模都可比的小数字。经验上曼哈顿距离在八数码上的有效分支因子明显小于不在位块数，量化地印证了 3.5.2 的结论。这个指标主要用于实验性地评估和挑选启发式，具体数值随测试问题集而变，此处不引具体数字（避免凭记忆填数，如需精确值以 AIMA Ch3 §3.6 实验表为准，待核）。
