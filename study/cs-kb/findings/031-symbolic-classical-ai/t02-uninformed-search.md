无信息搜索（uninformed / blind search）是符号 AI 里最基础的一族问题求解算法：智能体手上只有问题的形式化定义——状态、动作、目标测试、代价——但**没有任何关于"哪个状态离目标更近"的额外提示**。它只能靠系统地展开状态空间来找解。本报告把这一族算法（通用骨架、BFS、UCS、DFS/DLS、IDDFS）逐一讲清，并在最后用一张四维对比表把它们放在一起核对。它们与图论里的图遍历同源，但这里关心的是"从初始态到目标态的一条动作序列（计划）"这一 AI 问题求解语义，而非单纯访问所有顶点。

## 2.1 通用搜索框架

### 2.1.1 搜索问题的输入

一个搜索问题由五部分定义：初始状态、每个状态可用的动作、描述动作后果的转移模型（后继函数）、目标测试、以及路径代价函数。无信息搜索算法就是在这五元组之上工作的通用过程，不关心问题具体是八数码、迷宫还是路网。

之所以先强调"输入是什么"，是因为无信息搜索的全部信息就来自这五元组，一点不多。它无法回答"从当前状态到目标还差多远"这类问题——那需要启发式函数，属于下一大主题。理解这一点，就理解了"无信息"三个字：算法对状态的好坏一无所知，只能盲目而系统地铺开。

### 2.1.2 frontier（边界 / 开表）

frontier（AIMA 术语，中文常译"边界"，等价于其它教材的"开表 / open list"）是**已经生成、但还没有被展开（expand）的节点的集合**。搜索的每一步就是从 frontier 里取出一个节点、检查它、然后把它的后继放回 frontier。

frontier 是搜索算法之间差异的核心所在：**用什么数据结构组织 frontier，就得到什么算法**。先进先出队列给出 BFS，后进先出栈给出 DFS，按路径代价 g(n) 排序的优先队列给出 UCS。算法骨架完全一样，只有这一个"取哪个节点"的策略不同。初学者常把这几种搜索当成毫不相干的算法背，其实它们是同一个模板的不同实例，抓住 frontier 的组织方式就能一眼看穿区别。

### 2.1.3 reached / explored set（已达表 / 闭表）

为了避免反复处理同一个状态（尤其是状态空间图里有回路时），搜索通常维护一个记录"哪些状态已经生成/到达过"的表。AIMA 第 4 版称之为 reached（一张从状态到"到目前为止到达它的最好节点"的查找表）；第 3 版及很多教材称之为 explored set（已探索集 / 闭表 closed list）。

它的作用是**去重**：当一个状态第二次被生成时，如果新路径不比旧路径更好，就直接丢弃，不再入 frontier。没有它，带回路的状态空间会让搜索无限打转或指数级重复扩展。

这里有一个第 3 版与第 4 版的措辞差异值得留意：第 3 版的 explored set 只记"已展开"的状态；第 4 版的 reached 记的是"已到达"的状态并连带记住到达它的最优节点，这让 reached 版本能在发现更短路径时更新记录（对 UCS/A* 很关键）。两版本思想一致，只是粒度和命名不同，读不同资料时不要因为名字对不上就以为是两种东西。

### 2.1.4 节点与状态的区分

frontier 和 reached 里装的是**节点（node）**，不是状态（state）。一个节点是搜索树上的一个数据结构，通常包含：它对应的状态、指向父节点的指针、产生它的那个动作、以及从根到它的路径代价 g(n)。多个不同的节点可以对应**同一个状态**（因为可以从不同路径到达同一状态）。

状态是"世界的样子"，是客观的、可重复的；节点是"我搜索时走到这个样子所留下的记录"，带着来路信息。目标测试作用在状态上，去重作用在状态上，但代价、父指针、深度这些都挂在节点上。把这条分清楚，后面 BFS 为什么能靠父指针回溯出解路径、UCS 为什么要在发现更优节点时替换记录，就都顺理成章了。

### 2.1.5 树搜索与图搜索两种骨架

同一套流程有两个版本。树搜索（tree-like search）不维护 reached 表，任由同一状态被反复展开——实现简单、省内存，但在有回路的图上可能陷入死循环或做大量重复功。图搜索（graph search）维护 reached 表做去重，避免重复与回路，代价是要为记录见过的状态付出内存。

选哪个取决于状态空间：如果状态空间本身就是一棵树（无回路、无重复状态），树搜索就够了；一旦有回路（比如迷宫里可以来回走），就需要图搜索的去重。这个二分会直接影响后面每个算法的完备性与复杂度结论——例如 DFS 在树搜索版下不完备，但在有限状态空间的图搜索版下变得完备。

### 2.1.6 通用最佳优先骨架

AIMA 第 4 版把 BFS/UCS/DFS 等统一写成一个"最佳优先（best-first）"模板，只靠一个评价函数决定 frontier 的出队顺序：

```
function BEST-FIRST-SEARCH(problem, f) returns a solution node or failure
    node ← NODE(problem.INITIAL)
    frontier ← 一个按 f 排序的优先队列，初始只含 node
    reached ← 一张查找表，记录 {problem.INITIAL: node}
    while frontier 非空 do
        node ← POP(frontier)
        if problem.IS-GOAL(node.STATE) then return node
        for each child in EXPAND(problem, node) do
            s ← child.STATE
            if s 不在 reached 中 or child.PATH-COST < reached[s].PATH-COST then
                reached[s] ← child
                将 child 加入 frontier
    return failure
```

取不同的 f，就落到不同算法：f = 节点深度得到 BFS（浅的先出），f = 路径代价 g(n) 得到 UCS。DFS 更自然地用 LIFO 栈实现而非优先队列，但语义上相当于"深的先出"。

你不必把五种算法当五段独立代码记忆，而是记住"一个模板 + 一个 f"。后面所有关于完备性、最优性、复杂度的讨论，本质都是在问"这个 f 让 POP 先吐出哪些节点、吐出的顺序有什么保证"。

## 2.2 广度优先搜索 BFS

### 2.2.1 机制：FIFO 队列、逐层展开

BFS 用先进先出（FIFO）队列作为 frontier。它先展开根节点，再展开根的所有后继，再展开那批后继的所有后继……即**严格按层（离初始态的步数）由浅到深**推进。

直觉上想象往池塘里丢石子激起的同心圆波纹：BFS 就是那圈波纹，一圈一圈均匀向外扩，先把距离为 1 的状态全看完，才看距离为 2 的。之所以 FIFO 队列能实现这个效果，是因为浅节点总比深节点更早入队、于是也更早出队，队列天然保证了"先来（浅）先服务"。

### 2.2.2 目标测试的时机：生成时 vs 展开时

一个容易被忽略却影响复杂度结论的细节：目标测试是在节点**生成时（刚被 EXPAND 产出就测）**做，还是等它**从 frontier 被选出准备展开时**才做。AIMA 第 4 版采用"早期目标测试"——生成即测，一旦生成出目标节点就立刻返回。

这个选择直接改变时间复杂度的表述。第 4 版早测得到时间 O(b^d)；第 3 版在"展开时才测"的写法下会多展开一整层，给出 O(b^{d+1})。这不是谁错了，而是两种实现约定；本报告后文采用第 4 版的 O(b^d)。初学者对着不同教材看到 d 和 d+1 不一致时，先去看它在什么时机做目标测试，往往就对上了。

### 2.2.3 完备性与最优性

BFS 是完备的：只要分支因子 b 有限、且解存在，它一定能找到解（因为它系统地穷举每一层，浅解不会被漏过）。

BFS 找到的是**最浅的解**（步数最少）。当所有动作代价相同（单位代价）时，最浅即最省代价，此时 BFS 是代价最优（cost-optimal）的。但一旦动作代价不等，最浅的解未必最便宜——BFS 只保证步数最少、不保证代价最小。这是初学者的高频误区：BFS 的最优性是有前提的（等代价），不是无条件的。需要按代价最优时，要用下一节的 UCS。

### 2.2.4 复杂度

设 b 为分支因子、d 为最浅解的深度：

```
时间：O(b^d)
空间：O(b^d)
```

时间是 O(b^d)，因为最坏情况下要生成到第 d 层的所有节点，节点数按 b 的幂次增长。空间同样是 O(b^d)，这是 BFS 最痛的短板：它必须**把整个 frontier（可达 b^d 量级）同时留在内存里**，因为下一层要用到这一层的全部节点。指数级内存往往比指数级时间更先把你逼到墙角——等得起，但内存爆得快。这正是后面 IDDFS 想解决的问题。

## 2.3 一致代价搜索 UCS

### 2.3.1 机制：优先队列按 g(n)

一致代价搜索（Uniform-Cost Search, UCS）把 frontier 组织成一个**按路径代价 g(n)（从初始态到 n 的累计代价）排序的优先队列**，每次弹出当前 g 值最小的节点来展开：

```
f(n) = g(n)   （g(n) = 从初始态到 n 的路径总代价）
```

也就是"目前累计花费最少的路先走"。当所有动作代价相等时，g(n) 与深度成正比，UCS 就退化成 BFS——所以 UCS 是 BFS 在"代价不等"场景下的推广。

### 2.3.2 与 Dijkstra 的等价

UCS 在算法上等价于图论里的 Dijkstra 最短路算法：都是按已知最短距离从小到大"定型"节点。区别只在目标与停止条件——Dijkstra 通常计算源点到**所有**节点的最短距离；UCS 面向单一目标，一旦把目标节点从优先队列弹出就停下，不必跑完全图。

这条等价关系让你可以把两门课的知识打通：学过 Dijkstra 的读者，理解 UCS 几乎零成本，只要把"顶点距离"换成"状态路径代价"、把"跑完全图"换成"弹出目标即停"。反过来也解释了为什么 UCS 要求非负动作代价——Dijkstra 在负权边下会失效，UCS 同理。

### 2.3.3 完备性与最优性

UCS 是完备且代价最优的，但完备性有一个前提：**每个动作的代价必须有一个正的下界 ε > 0**。

为什么要 ε > 0？若允许出现代价为 0（甚至可累积无穷多个 0 代价动作）的动作序列，UCS 可能永远在一堆零代价动作里打转、g 值不增长，从而卡住、不完备。有了 ε > 0 这个正下界，每展开一步累计代价至少增加 ε，g 值单调爬升，保证有限步内触达目标层。

UCS 总是先弹出当前 g 最小的节点，第一次弹出目标节点时，不可能还存在一条更便宜的到达目标的路径（否则那条路径上某个更便宜的前缀节点会先被弹出）。这就是它保证找到代价最小解的原因。

### 2.3.4 复杂度

设 C* 为最优解代价、ε 为最小动作代价：

```
时间：O(b^{1 + ⌊C*/ε⌋})
空间：O(b^{1 + ⌊C*/ε⌋})
```

指数里出现的是 C*/ε 而不是解的深度 d。原因是 UCS 按代价而非层数推进：它可能在到达目标之前，先把所有代价小于 C* 的节点都展开掉。当所有动作等代价时，C*/ε 就回到 d，复杂度回退成 BFS 的 O(b^d)——再次印证 UCS 是 BFS 的推广。这个 C*/ε 指数是初学者背复杂度表时最容易记错成 d 的地方，务必分清 UCS 用的是代价刻度、BFS 用的是深度刻度。

### 2.3.5 与 BFS 的关系小结

BFS 按"步数"分层，UCS 按"累计代价"分层。等代价时两者行为完全一致；不等代价时只有 UCS 保证代价最优。可以把 UCS 记成"带权版 BFS"或"面向单目标、遇目标即停的 Dijkstra"。

## 2.4 深度优先搜索 DFS 与深度受限搜索 DLS

### 2.4.1 DFS 机制：LIFO 栈 / 递归

深度优先搜索用后进先出（LIFO）栈作为 frontier（或等价地用递归调用栈），总是**优先展开最深的、最近生成的那个节点**：一条路走到黑，走不通了才回溯到最近的岔口换一条。

直觉是走迷宫时"贴着一面墙一直往前，撞墙了才退回上一个路口"。因为最近生成的节点排在栈顶最先出栈，搜索会一头扎到底再回头，与 BFS 的均匀铺开形成鲜明对照。

### 2.4.2 为什么 DFS 既不完备也不最优

在树搜索版本（不维护 reached 表）下，DFS 既不完备也不最优。

不完备：如果状态空间里有环、或有一条无限深的路径，DFS 可能顺着它一直往下钻、永远回不来，即使别处存在解也发现不了。不最优：DFS 返回的是它**第一个撞见的**解，而不是最浅或最便宜的解——它扎进去的那条深路上先碰到的目标，可能远比另一条浅路上的解更深、更贵。

在**有限**状态空间上、用图搜索版本（维护 reached 表去重）时，DFS 变得完备（不会重复访问、迟早遍历完所有状态）。但这样一来就要存下见过的状态，DFS 引以为傲的省内存优势也随之消失。所以谈 DFS 的性质时必须先说清是哪个版本。

### 2.4.3 空间优势

DFS 最大的卖点是省内存。树搜索版 DFS 的空间是：

```
空间：O(b·m)   （m = 状态空间/搜索树的最大深度）
```

因为它任一时刻只需保存"当前这条从根到叶的路径"（长 m）外加路径上每个节点尚未展开的兄弟节点（每层约 b-1 个），合计 O(bm)——**多项式级**，而非 BFS 的指数级。这就是 DFS 存在的理由：当解很深、内存吃紧时，BFS 的 O(b^d) 内存直接爆掉，而 DFS 只吃线性内存。（若递归实现且不显式保存兄弟，某些教材记为 O(m)；差别在是否计入待展开兄弟，属实现细节。）

这个 O(bm) 优势**只属于不维护 reached 表的树搜索版**。一旦为了完备性加上去重表，空间又回到与状态数同阶，优势不再。

### 2.4.4 深度受限搜索 DLS

深度受限搜索（Depth-Limited Search, DLS）是给 DFS 加一个深度上限 ℓ：走到深度 ℓ 就当作"此路不通"回溯，绝不再往下。这样至少堵死了"沿无限深路径一去不返"的问题。

```
时间：O(b^ℓ)      空间：O(b·ℓ)
```

但它引入新麻烦：如果最浅解的深度 d 大于所设的 ℓ，DLS 会因为提前截断而找不到本来存在的解，因此仍**不完备**；它也不保证最优。怎么设 ℓ 是个难题——设小了漏解，设大了退化回 DFS。有些问题有天然上限（例如 n 个城市的路径至多经过 n-1 步，可取 ℓ = n-1），但很多问题并没有。这个"ℓ 到底设多少"的两难，正是下一节 IDDFS 要一并解决的。

### 2.4.5 回路与重复状态的处理

在带回路的图上，纯树搜索 DFS 会沿环无限打转。缓解手段有两级：轻量做法是只检查"当前路径上是否已出现该状态"（避免眼前的环，不需大表，仍省内存）；重量做法是维护完整 reached 表（彻底去重，换来完备性但牺牲内存）。前一种正是 DLS/IDDFS 里常用的做法——只查当前路径成环，既防环又不放弃 DFS 的内存优势。

## 2.5 迭代加深搜索 IDDFS

### 2.5.1 机制：外层递增深度限、反复 DLS

迭代加深深度优先搜索（Iterative Deepening DFS, IDDFS）把 DLS 套在一个不断增大深度限的外循环里：先以 ℓ=0 跑一次 DLS，没找到就 ℓ=1 再跑一次，再 ℓ=2……直到找到解为止：

```
for ℓ = 0, 1, 2, … do
    result ← DEPTH-LIMITED-SEARCH(problem, ℓ)
    if result ≠ cutoff then return result
```

它的巧妙之处是把 DFS 的省内存和 BFS 的"由浅到深、找到即最浅"两个优点合到了一起，同时绕开了 DLS"深度限该设多少"的两难——不用猜 ℓ，从 0 逐次加大，第一次找到解时的 ℓ 恰好就是最浅解深度 d。

### 2.5.2 重复扩展为什么不是灾难

"每加大一次 ℓ 都要从头重跑，浅层节点被重复展开好多次，岂不是极大浪费？"结论恰恰相反：重复的开销小到可以忽略。

关键在于搜索树的节点是**指数级向底部堆积**的——最底层（深度 d）的节点数就约等于其上所有层的总和。IDDFS 里，最底层只被生成一次，倒数第二层被生成两次……最顶层被生成 d 次；但顶层节点少，重复它们几乎不花钱。AIMA 给的经典算例（b=10, d=5）：

```
IDDFS 生成节点数 ≈ 5·10 + 4·100 + 3·1000 + 2·10000 + 1·100000 = 123,450
BFS   生成节点数 ≈ 10 + 100 + 1000 + 10000 + 100000       = 111,110
```

IDDFS 只比 BFS 多约 11%，却把内存从指数级 O(b^d) 降到线性 O(bd)。b 越大，这个重复开销的相对比例越小（约为 b/(b−1)）。所以当状态空间大、解深度未知、内存受限时，IDDFS 是无信息搜索里的**首选通用方法**。

### 2.5.3 完备性、最优性与复杂度

```
时间：O(b^d)      空间：O(b·d)
```

IDDFS 完备（b 有限时，逐层加深迟早覆盖到解所在的深度 d）；在动作等代价时代价最优（第一次找到解即最浅解，与 BFS 同）。时间 O(b^d) 与 BFS 同阶（多出的重复只是常数倍），空间 O(bd) 则与 DFS 同为线性——这就是它"取两家之长"的量化体现：**BFS 的完备性与最优性 + DFS 的线性内存**。

与 BFS 一样，IDDFS 的代价最优只在动作等代价时成立；代价不等时要用 UCS 或有信息搜索。另外它天生适合"当前路径查环"这种轻量去重（见 2.4.5），从而在保持线性内存的同时应对有环图。

## 2.6 四维评价对比

### 2.6.1 符号约定：b / d / m 与 C* / ε

比较之前先把复杂度式里的字母钉死，这是读懂整张表的前提：

b = 分支因子（branching factor），任一状态的最大后继数。

d = 最浅解的深度（depth of the shallowest solution），从初始态到最近目标的步数。

m = 状态空间 / 搜索树的最大深度（maximum depth），可能是无穷（有无限路径时）。

C* = 最优解的路径代价；ε = 单个动作代价的正下界（ε > 0）。C*/ε 是 UCS 专用的"代价层数"刻度。

d 与 m 不是一回事。d 是"解有多浅"，m 是"树能多深"，通常 d ≤ m。BFS/IDDFS 的复杂度用 d（它们盯着最浅解），DFS 用 m（它会一路探到底）。此外要注意教材符号差异：CS188 讲义常用 s 表示最浅解深度（即 AIMA 的 d），对照不同资料时先把符号翻译对齐，否则会把同一结论误读成矛盾。

### 2.6.2 横向对比表

下表汇总五种算法的四个维度（依 AIMA 4th ed Fig 3.15；BFS/IDDFS 的最优性均以"动作等代价"为前提）。

| 算法 | 完备性 | 代价最优性 | 时间 | 空间 |
|------|--------|-----------|------|------|
| BFS 广度优先 | 是（b 有限） | 是，仅当动作等代价 | O(b^d) | O(b^d) |
| UCS 一致代价 | 是（b 有限且 step cost ≥ ε>0） | 是 | O(b^{1+⌊C*/ε⌋}) | O(b^{1+⌊C*/ε⌋}) |
| DFS 深度优先（树搜索版） | 否 | 否 | O(b^m) | O(b·m) |
| DLS 深度受限（限 ℓ） | 否（ℓ<d 时漏解） | 否 | O(b^ℓ) | O(b·ℓ) |
| IDDFS 迭代加深 | 是（b 有限） | 是，仅当动作等代价 | O(b^d) | O(b·d) |

### 2.6.3 逐条要点与易错点

BFS 与 IDDFS 的最优性都带"动作等代价"这个限定词，不是无条件最优——这是本表最容易被漏掉的注脚。需要代价最优且动作不等代价时，只有 UCS 在无信息这一族里能给保证。

UCS 的指数用 C*/ε（代价刻度）而非 d（深度刻度）；当动作等代价时 C*/ε 退化成 d，UCS 就变回 BFS。别把 UCS 的复杂度背成 O(b^d)。

DFS 的"不完备/不最优"结论是针对**树搜索版**说的；改成有限状态空间上的图搜索版，DFS 会变完备，但空间优势随即消失。谈 DFS 性质务必先声明版本。

IDDFS 用 O(b^d) 时间买到 O(bd) 空间，这笔"重复扩展"的账单只是常数倍开销（约 b/(b−1) 倍），在大 b 下几乎免费——这是它成为无信息搜索默认推荐的根本原因。

### 2.6.4 本机实证坐实

在一个 5×5 迷宫（起点左上、终点右下、单位步代价、后继按上/下/左/右固定顺序）上分别跑四种算法，统计解的步数与展开节点数，结果如下（Py3.11.15；脚本贴于本节末，可复现）：

```
BFS    解长 8, 展开 17
UCS    解长 8, 展开 17
DFS    解长 8, 展开  9
IDDFS  解长 8, 展开 81（累计，limit=8 时命中）
```

这组真实数字坐实了三点：其一，单位代价下 BFS 与 UCS 行为完全一致（同为 17，印证 2.3.5"等代价时 UCS 退化成 BFS"）；其二，DFS 展开数最少（9），体现它一头扎到底、不铺开的省事省内存特性；其三，IDDFS 累计展开 81，明显多于 BFS 的 17，直观展示了它的重复扩展开销——本例迷宫小、b 小，重复比例才显得大，b 越大该比例越趋近可忽略（2.5.2）。

需诚实说明：本例是走廊型迷宫、路径受限，DFS 恰好也返回了长度 8 的解，这是该地图的巧合，**不代表 DFS 一般能给最优解**——2.4.2 已论证 DFS 不最优。实证在这里只作辅助坐实，不替代表中依教材多源比对得出的结论。

复现脚本（放在仓库外临时目录跑，不入库）：

```python
from collections import deque
import heapq

grid = ["S....", ".###.", ".#.#.", ".#.#.", "...#G"]
R, C = len(grid), len(grid[0])
def find(ch):
    for r in range(R):
        for c in range(C):
            if grid[r][c] == ch: return (r, c)
start, goal = find('S'), find('G')
def succ(s):
    r, c = s
    for dr, dc in [(-1,0),(1,0),(0,-1),(0,1)]:   # 上/下/左/右固定序
        nr, nc = r+dr, c+dc
        if 0 <= nr < R and 0 <= nc < C and grid[nr][nc] != '#':
            yield (nr, nc)

def bfs():
    seen = {start}; fr = deque([(start, [start])]); exp = 0
    while fr:
        s, path = fr.popleft(); exp += 1
        if s == goal: return len(path)-1, exp
        for n in succ(s):
            if n not in seen: seen.add(n); fr.append((n, path+[n]))
    return None, exp

def ucs():
    pq = [(0, 0, start, [start])]; best = {}; exp = 0; c = 1
    while pq:
        g, _, s, path = heapq.heappop(pq)
        if s in best and best[s] <= g: continue
        best[s] = g; exp += 1
        if s == goal: return len(path)-1, exp
        for n in succ(s):
            heapq.heappush(pq, (g+1, c, n, path+[n])); c += 1
    return None, exp

def dfs():
    stack = [(start, [start])]; seen = set(); exp = 0
    while stack:
        s, path = stack.pop()
        if s in seen: continue
        seen.add(s); exp += 1
        if s == goal: return len(path)-1, exp
        for n in succ(s):
            if n not in seen: stack.append((n, path+[n]))
    return None, exp

def dls(limit):
    exp = [0]
    def rec(s, depth, path):
        exp[0] += 1
        if s == goal: return len(path)-1
        if depth == 0: return None
        for n in succ(s):
            if n not in path:               # 当前路径查环（轻量去重）
                r = rec(n, depth-1, path+[n])
                if r is not None: return r
        return None
    return rec(start, limit, [start]), exp[0]

def iddfs(maxd=30):
    total = 0
    for lim in range(maxd+1):
        res, e = dls(lim); total += e
        if res is not None: return res, total, lim
    return None, total, None

print("BFS  ", bfs())
print("UCS  ", ucs())
print("DFS  ", dfs())
print("IDDFS", iddfs())
```

### 2.6.5 与图遍历同源、AI 语义上的差异

这一族算法在数据结构课的图遍历里都见过：BFS/DFS 是标准图遍历，UCS 就是 Dijkstra。同源之处在于它们都在图上按某种顺序访问节点。

差异在于问题语义。图遍历常关心"访问到所有顶点"或"两点间是否连通"；AI 问题求解关心的是**从初始态到目标态的那条动作序列本身**——因为这条序列就是智能体要执行的"计划"。所以这里节点带父指针（为了回溯出完整路径与动作序列），关心解的深度/代价（为了最优计划），且状态空间往往是**隐式**的（由后继函数按需生成，而非事先给出一张显式邻接表，因为八数码这类问题的状态数天文级、无法预先列全）。把握"显式图遍历 vs 隐式状态空间搜索 + 求动作序列"这一层语义差异，就理解了为什么同样的算法在 AI 课里要重讲一遍。
