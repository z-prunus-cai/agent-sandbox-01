约束满足问题把「状态是不可拆的黑箱」这一假设打开：一个状态不再是任意数据结构，而是「一组变量各取一个值」的结构化对象，目标测试也统一成「满足全部约束」。正因为结构暴露出来，我们能用一套与具体问题无关的通用方法（约束传播、通用启发式、结构分解）去求解，而不必为每个问题手写后继函数和启发式。这一章的主线就是：回溯搜索打底，约束传播（前向检查 → 弧相容 AC-3）剪枝，通用启发式（MRV/度/LCV）选序，最后利用约束图结构（树、割集）把某些问题从指数降到多项式。

## 6.1 CSP 形式化（变量、域、约束、约束图）

### 6.1.1 CSP 的三要素：变量、域、约束

一个约束满足问题由三部分定义：一组变量 X₁…Xₙ；每个变量 Xᵢ 有一个非空的取值域 Dᵢ（该变量允许取的值的集合）；一组约束 C₁…Cₘ，每个约束指定某个变量子集上「哪些取值组合是允许的」。求解目标是给所有变量各赋一个值，使得没有任何约束被违反。

把它写成一个紧凑的三元组：

CSP = ⟨X, D, C⟩

其中 X 是变量集合，D 是各变量域的集合，C 是约束集合。

CSP 和普通搜索问题的差别不在「难不难」，而在「状态有没有内部结构」。普通搜索里，一个状态是黑箱，你只能通过后继函数、目标测试这些问题专属的钩子去访问它。CSP 里，一个状态就是「变量到值的部分映射」，目标测试就是「所有约束都满足吗」——这个统一格式让所有 CSP 都能共用同一套求解器和同一套启发式，这正是单独把 CSP 拎出来讲的原因。

一个贯穿全章的例子是给澳大利亚地图着色：变量是各行政区 WA、NT、SA、Q、NSW、V、T，每个变量的域是 {红, 绿, 蓝}，约束是「相邻区颜色不同」。找到一种不冲突的涂法就是一个解。

### 6.1.2 赋值、相容、完全赋值与解

给一部分或全部变量指定值，叫一次赋值（assignment）。不违反任何约束的赋值叫相容（consistent）或合法赋值。给每个变量都赋了值的叫完全赋值。既完全又满足所有约束的完全赋值，就是这个 CSP 的解。

这里的易错点是把「相容」和「解」混为一谈。一个部分赋值可以是相容的（目前为止没违反约束），但它离解还远，甚至可能根本无法扩展成解——比如地图着色里前几步都合法，但已经逼得某个未赋值区没有颜色可选了。后面前向检查和弧相容做的事，正是尽早发现「这个相容的部分赋值其实是死路」。

有些 CSP 还带一个目标函数，要在所有解里找最优的，那叫约束优化问题（COP）；本章聚焦「找任一解」的判定型 CSP。

### 6.1.3 约束的元数：一元、二元、高阶与全局约束

按约束涉及的变量个数分类：一元约束只管一个变量（如「SA 不能是绿色」）；二元约束管两个变量（如「WA ≠ NT」）；高阶约束（n 元）涉及三个及以上变量；还有一类涉及任意个变量的常用约束叫全局约束，最典型的是 Alldiff（一组变量两两不同）。

初学者需要知道的关键事实是：任何有限域上的高阶约束都可以转化为二元约束（引入辅助变量），所以理论上只研究二元 CSP 不失一般性。这就是为什么教材里的算法（弧相容、约束图）几乎都以二元 CSP 为默认设定——不是因为高阶约束不重要，而是因为它们能被归约掉。

一元约束更简单：直接从对应变量的域里删掉违反它的值即可，这一步预处理叫节点相容（node consistency），见 6.4.4。

### 6.1.4 约束图（constraint graph）

当所有约束都是二元的，可以画一张图：每个变量是一个节点，每条二元约束是一条连接对应两变量的边。这张图叫约束图。地图着色的约束图就长得和地图的邻接关系一样。

约束图不是画着好看，它是后半章所有「利用结构」方法的地基。图的形状直接决定问题难度：如果约束图是一棵树，问题可以线性时间解（6.6.1）；如果几乎是树、只差几个节点，可以用割集条件化（6.6.2）快速解。换句话说，问题结构 = 约束图结构，而约束图结构 = 求解难度，这是本章后半部分的核心洞见。

约束图的边表示「这两个变量之间有约束」，不表示「它们必须相等」或「必须不等」——具体是什么约束由边上标注的关系决定，图本身只记录「谁和谁有关系」。若约束是高阶的，则要用约束超图（每条超边连一组变量），或先归约为二元再画普通图。

### 6.1.5 为什么 CSP 值得单独成章：结构可见带来的通用能力

CSP 相对普通状态空间搜索的根本增益，是「用通用方法替代问题专属方法」。因为状态结构统一，我们可以：用与领域无关的启发式（MRV/度/LCV）决定搜索顺序；用约束传播在搜索前和搜索中主动裁剪不可能的取值；用约束图结构做问题分解。这些在黑箱搜索里都做不到，因为你根本看不见状态内部。

对照本课「从数据拟合函数」的机器学习范式：CSP 是典型的符号 AI 世界观——世界被显式建模成「变量 + 域 + 约束」这样的符号结构，求解是在这个结构上做确定性推理与搜索，而不是从样本里学一个函数。这里只作范式对照，不展开。

有限域 CSP 的完全赋值数量是 O(dⁿ)（n 个变量、域大小 d），指数级；而且 CSP 把 3SAT 作为特例包含在内，所以不要指望有多项式时间的通用精确算法——本章所有技巧都是「在最坏仍指数、但实际大幅剪枝」的努力，或是「对特殊结构（树）才多项式」的结果。

## 6.2 回溯搜索（backtracking search）

### 6.2.1 朴素枚举为何爆炸：交换律与提交单变量

如果把 CSP 当普通搜索做——每一步「选一个还没赋值的变量并给它赋一个值」当作一个动作——那么在顶层有 nd 个动作（n 个变量各 d 个值），下一层 (n−1)d 个……最终生成一棵有 n!·dⁿ 个叶子的树，可实际上不同的完全赋值只有 dⁿ 个。多出来的 n! 倍纯属浪费。

浪费的根源是忽略了 CSP 的一个关键性质：交换律。变量的赋值顺序不影响最终结果——「先 WA=红 再 NT=绿」和「先 NT=绿 再 WA=红」到达同一个状态。既然顺序无所谓，那么在每个节点上，我们只需固定考虑「一个」未赋值变量、枚举它的取值即可，不必把「选哪个变量」也当成分支。这样分支因子从 nd 降到 d，树的叶子回到 dⁿ 量级。

### 6.2.2 回溯搜索算法

利用交换律 + 深度优先，就得到 CSP 的标准求解骨架——回溯搜索：每次挑一个未赋值变量，依次尝试它域中的值，只保留与当前部分赋值相容的值，然后递归；一旦某个变量无值可用就回退（撤销上一步赋值，换下一个值）。

```
function BACKTRACKING-SEARCH(csp) returns 一个解或 failure
    return BACKTRACK({}, csp)

function BACKTRACK(assignment, csp) returns 一个解或 failure
    if assignment 是完全的 then return assignment
    var ← SELECT-UNASSIGNED-VARIABLE(csp, assignment)      // 变量排序启发（6.5）
    for each value in ORDER-DOMAIN-VALUES(var, assignment, csp)  // 值排序启发（6.5）
        if value 与 assignment 相容 then
            把 {var = value} 加入 assignment
            inferences ← INFERENCE(csp, var, value)         // 约束传播（6.3/6.4）
            if inferences ≠ failure then
                把 inferences 并入 assignment
                result ← BACKTRACK(assignment, csp)
                if result ≠ failure then return result
            撤销 {var = value} 及 inferences
    return failure
```

本质上回溯搜索就是「一次赋一个变量的深度优先搜索 + 每步做相容性检查」。因为任何解都是深度 n 的完全赋值，搜索树深度固定为 n、路径本身无意义（我们只要终点不要路径），所以深度优先天然适合 CSP，空间只需 O(n)。

朴素回溯里 INFERENCE 是空的（什么都不推断），SELECT/ORDER 是随意的。它虽然正确，但在中等规模问题上就会慢到不可用。回溯搜索之所以强，是因为它是个「插槽框架」——三个插槽（选变量、选值、做推断）各插入一个改进，性能就能提升几个数量级。这正是 6.3–6.5 要填的三个槽。

### 6.2.3 三个改进旋钮：推断、排序、回跳

回溯框架上有三类正交的改进。推断（inference / 约束传播）：每次赋值后主动裁剪其他变量的域，把死路提前暴露——前向检查（6.3）、弧相容 AC-3（6.4）。排序（ordering）：先选哪个变量、先试哪个值——MRV、度启发、LCV（6.5）。回跳（backjumping）与冲突学习：失败时不是傻退一层，而是跳回真正制造冲突的那个变量。

这三类改进互相独立又可叠加：实践中最常见的组合是「MAC（维持弧相容）+ MRV + LCV」。本章按「先讲清每个旋钮、再组合」的顺序展开；回跳属进阶，本报告只登记名字不深挖。

## 6.3 前向检查（forward checking）

### 6.3.1 前向检查机制：赋值后即时裁剪邻居域

前向检查是最轻量的一种推断。每当给变量 X 赋一个值，就去看约束图上所有与 X 相邻、且尚未赋值的变量 Y，把 Y 的域里「与 X 当前取值冲突」的值删掉。如果某个 Y 的域被删空了，说明当前赋值已无法扩展成解，立即回溯，不必等到真正走到 Y 才发现。

直觉上，前向检查就是「每走一步就向前看一眼直接邻居，把它们已经不可能的选项划掉」。它带来两个好处：一是提前发现死路（域空即回溯），二是把邻居的域缩小，间接给后面的 MRV 启发式提供信息（域越小的变量越该先选）。它很便宜——只扫当前赋值变量的邻居一遍。

以澳大利亚着色为例，本机复现（Python，基线环境）：设 WA=红、Q=绿，前向检查扫它们的未赋值邻居后得到

```
WA:{红}  Q:{绿}  NT:{蓝}  SA:{蓝}  NSW:{红,蓝}  V:{红,绿,蓝}  T:{红,绿,蓝}
```

NT 和 SA 都被逼到只剩 {蓝}——这是前向检查的功劳。

### 6.3.2 前向检查的盲区：不看未赋值变量之间的约束

前向检查有个本质局限：它只检查「已赋值变量 → 未赋值邻居」这一个方向的弧，从不检查「两个都未赋值的变量之间」的约束。所以它看不出「NT 和 SA 都只剩蓝、而 NT≠SA」这个已经注定失败的矛盾。

前向检查停在 NT:{蓝}、SA:{蓝}，两者相邻且必须不同色，实际上已经无解，但前向检查察觉不到，会继续往下搜直到撞墙才回溯。这正是引出弧相容（AC-3）的动机——AC-3 会传播「未赋值变量之间」的约束，把这类隐藏矛盾提前挖出来。

前向检查只做「一步、单向、到直接邻居」的裁剪；它是弧相容的一个特例（只处理指向当前新赋值变量的那些弧、且不递归传播）。

## 6.4 约束传播与弧相容 AC-3

### 6.4.1 弧相容（arc consistency）的定义

一条有向弧 (X, Y) 称为弧相容，当且仅当：X 域里的每一个值 x，在 Y 的域里都至少能找到一个值 y 使得约束 (X, Y) 被满足。换句话说，X 里没有「找不到搭档」的孤值。

弧相容化（enforcing arc consistency）就是反复删除这类孤值：若 x 在 Y 里找不到任何相容搭档，就把 x 从 X 的域里删掉。整个 CSP 弧相容，指的是每一条有向弧都弧相容。

弧相容比前向检查强，因为它检查「任意两个变量之间」的弧，而不只是「已赋值 → 邻居」。注意弧是有向的，(X,Y) 相容不代表 (Y,X) 也相容，两个方向都要处理。还要注意删值会传染：把 x 从 X 删掉后，原本靠 x 支撑的其他变量的某些值可能又变成孤值，所以必须把受影响的弧重新拉回来检查——这就是 AC-3 用队列传播的原因。

### 6.4.2 AC-3 算法与复杂度

AC-3 是 Mackworth 1977 提出的经典弧相容算法（名字里的 3 是原论文里的第三版）。它维护一个待检查弧的队列，反复取出一条弧做「修正」（REVISE，删孤值），一旦某变量的域被删小，就把「指向它的所有弧」重新入队，直到队列空。

```
function AC-3(csp) returns false（发现不相容）或 true
    queue ← csp 中所有弧 (Xi, Xj)
    while queue 非空 do
        (Xi, Xj) ← queue.pop()
        if REVISE(csp, Xi, Xj) then
            if Di 为空 then return false
            for each Xk in NEIGHBORS[Xi] \ {Xj} do
                把 (Xk, Xi) 加入 queue
    return true

function REVISE(csp, Xi, Xj) returns 是否删过值
    revised ← false
    for each x in Di do
        if Dj 中不存在 y 使 (x,y) 满足约束 (Xi,Xj) then
            从 Di 删除 x
            revised ← true
    return revised
```

最坏时间复杂度为

O(n²·d³)

推导（AIMA 给出）：二元 CSP 至多 O(n²) 条弧；每条弧 (Xk, Xi) 最多被重新入队 d 次（因为 Xi 最多删 d 个值，每删一个才会触发邻居重检）；每次 REVISE 检查一条弧要 O(d²)；三者相乘得 O(n²d³)。

这里有一个跨来源的记法差异需点明：AIMA 用「二元 CSP 至多 n² 条弧」把复杂度写成 O(n²d³)；而 CS188 及不少资料用弧/约束条数 c（或 e）直接写成 O(c·d³)（或 O(e·d³)）。两者是同一结论的不同写法（因 c ≤ n²），不是真冲突——用 c 的写法在稀疏约束图上更紧。此外 AIMA 注明更精细的 AC-4 算法（Mohr & Henderson 1986）最坏为 O(n²d²)，但常数更大、实际未必更快，所以 AC-3 因简单仍是默认。

### 6.4.3 前向检查 vs AC-3：裁剪范围的区别

两者都在裁剪域，区别在裁剪的「广度」与「是否传播」：前向检查只在一次赋值后，处理「指向新赋值变量的那些弧」，且不递归传播；AC-3 处理「所有弧」，并且删值后会把受影响的弧重新入队、层层传播，直到全图弧相容。所以 AC-3 能发现前向检查漏掉的、隐藏在未赋值变量之间的矛盾。

接 6.3 的澳大利亚例子做本机对照（Python 3.11.15，基线环境）：同样在 WA=红、Q=绿 下，前向检查停在 NT={蓝}、SA={蓝} 而未报错；对同一局面跑 AC-3：

```
AC-3 返回 False；SA 的域被清空（[]）
```

AC-3 处理 (SA, NT) 这条「两个未赋值变量之间」的弧时，发现 SA 唯一剩的蓝在 NT 里找不到不同色搭档（NT 也只剩蓝），把蓝从 SA 删掉，SA 空 → 立即判定当前赋值无解。这正是前向检查察觉不到、而 AC-3 能提前剪掉的死路。

复现脚本要点（约束为相邻异色，neighbors 为澳大利亚邻接表）：

```python
def revise(dom, xi, xj):
    removed = False
    for x in dom[xi][:]:
        if not any(x != y for y in dom[xj]):  # x 在 xj 域中无相容搭档
            dom[xi].remove(x); removed = True
    return removed
# AC-3：初始所有 (xi,xj) 入队；revise 删值后把 (xk,xi) 重新入队；某域空则 return False
```

AC-3 更强但仍不完备——它保证弧相容，不保证有解就一定不被剪成矛盾之外的假通过。经典反例（AIMA）：部分赋值 {WA=红, NSW=红} 其实不相容，但 AC-3 检测不出来，需要更强的路径相容（3-相容）才能发现。也就是说，弧相容能剪掉很多但不是全部矛盾。

### 6.4.4 一致性的层级：节点相容、弧相容、路径相容、k-相容

弧相容只是一族「相容强度」里的一档。按涉及变量数排：节点相容（node consistency）= 1-相容，指单个变量的域已满足其所有一元约束；弧相容 = 2-相容，任一变量的任一取值都能在某个相邻变量里找到搭档；路径相容（path consistency）= 3-相容，任意两个相邻变量的相容取值对，都能扩展到第三个相邻变量。一般地，k-相容指任意 k−1 个变量的相容赋值都能扩展到第 k 个变量。

若一个 CSP 强 k-相容（strongly k-consistent，即同时是 k、k−1、…、1 相容），则可无回溯地在 O(nd) 时间内构造解：每步只需在当前变量域里扫 d 个值就必能找到与已赋值部分相容的值。代价是天下没有免费午餐——建立 n-相容（强 n-相容）本身在最坏情况下要 n 的指数时间。所以实践中停在弧相容（2-相容）是「传播成本」与「剪枝收益」的甜点：再强的相容往往「花在传播上的时间超过省下的搜索时间」。

相容度数 = 一次考虑几个变量。1 个（一元约束）、2 个（弧）、3 个（路径），越高剪得越狠但越贵。

### 6.4.5 维持弧相容 MAC（在搜索中传播）

把弧相容当成回溯搜索里的 INFERENCE 步，就得到 MAC（Maintaining Arc Consistency）：每次给变量赋值后，不只做前向检查，而是从「与该变量相关的弧」出发跑一遍 AC-3（增量式），把传播能挖出的死路全部提前暴露，再递归。

MAC 与「先跑一遍 AC-3 预处理、搜索中只做前向检查」的区别在于：MAC 在搜索的每个节点都维持全图弧相容，剪枝更彻底。实践中 MAC + MRV 通常显著快于纯前向检查，是通用 CSP 求解器的常见默认配置。代价是每步传播更贵，需权衡；但在约束紧的问题上几乎总是划算的。

## 6.5 变量与值排序启发式（MRV、度启发、LCV）

### 6.5.1 MRV：最少剩余值（fail-first）

选下一个要赋值的变量时，MRV（Minimum Remaining Values）启发式选「当前合法取值最少」的那个变量。它也叫「最受约束变量」或「fail-first」启发式。

如果某个变量只剩一个（或很少）合法值，那它迟早要被处理，早处理能立刻发现是否走不通；一旦它无值可选，马上回溯，避免在别处白白搜一大片再回来撞墙。之所以叫 fail-first——「要失败就趁早失败」，把注定失败的子树尽早砍掉。配合前向检查/弧相容使用效果最好，因为传播会把变量的域缩小，MRV 才有准确的「剩余值数」可比。

以澳大利亚为例：赋了 WA、NT 后，SA 因相邻两色被占往往只剩一个合法色，MRV 会优先选 SA，从而把 Q、NSW、V 的选择也连带钉死，大幅减少分支。

### 6.5.2 度启发（degree heuristic）：作 MRV 的平局裁决

MRV 在开局无能为力——一开始每个变量都有满域（如着色时每区都 3 个色），剩余值数相同，MRV 无从选择。这时用度启发：选「与其他未赋值变量约束数最多」的变量，即约束图上度数最高的节点。

先给「牵扯最多」的变量定值，能最大程度压低后续变量的分支因子。澳大利亚里 SA 的度是 5（与除 T 外几乎所有区相邻）最高，其余多为 2–3，T 为 0；先定 SA，后面几乎可以一路无回溯着色。度启发通常不单独用，而是作为 MRV 的平局裁决（MRV 选出多个并列变量时，用度启发在其中挑度数最高的）。

### 6.5.3 LCV：最少约束值

选定变量后，该按什么顺序试它的值？LCV（Least Constraining Value）启发式优先试「排除邻居选择最少」的值——也就是给未来留下最多灵活性的那个值。

既然我们（在这个变量上）只需要一个能走通的值，就该先试那个「对别人限制最小、最可能让整体仍有解」的值，从而更快撞见解、少回溯。澳大利亚里若已 WA=红、NT=绿，给 Q 选色时，蓝会用掉 SA 最后的合法色（SA 已被红绿夹击），红则不会——LCV 于是偏好红而非蓝。

### 6.5.4 为什么变量选 fail-first、值选 fail-last

变量排序要「最可能失败的先选」（MRV/fail-first），值排序却要「最不可能失败的先试」（LCV/fail-last），方向为什么相反？

因为两者的目标不同。选变量时，我们迟早要给每个变量都赋值——所有变量都逃不掉，那就让「注定失败的」尽早暴露，好整片剪枝，所以 fail-first。选值时，我们只需要找到一个能走通的值就够了（其余值不必都试），那就先试最可能成功的，好尽快找到解，所以 fail-last。一句话：变量非试不可，故先试坏的以早剪；值只需一个成，故先试好的以早成。

还需知道：这些通用启发式虽有效，但不保证最优，也不改变最坏复杂度——它们是「实际大幅提速」的经验法则，在不同问题上收益不同（LCV 尤其只在「找单个解」时明显，找全部解时无益）。

## 6.6 利用问题结构（树结构线性可解、割集条件化）

### 6.6.1 树结构 CSP 线性可解：O(n·d²)

如果一个 CSP 的约束图是一棵树（无环），它可以在最坏 O(n·d²) 时间内解出或判定无解，无需任何回溯——这是 CSP 里「结构决定难度」最漂亮的结果。

算法两步。第一步，对树做拓扑排序，选一个根，把变量排成「每个节点的父亲都排在它前面」的顺序 X₁…Xₙ。第二步，从后往前做有向弧相容（对 j = n 到 2，令弧 (parent(Xⱼ), Xⱼ) 相容，即根据孩子裁剪父亲的域）；再从前往后逐个赋值：每个变量按顺序取一个与其（已赋值的）父亲相容的值。

```
function TREE-CSP-SOLVER(csp) returns 一个解或 failure
    n ← 变量数
    root ← 任选一个变量
    (X1,…,Xn) ← 拓扑排序（使每个 Xj 的父亲排在其前）
    for j = n down to 2 do                    // 自底向上做有向弧相容
        MAKE-ARC-CONSISTENT(parent(Xj), Xj)
        if 某域为空 then return failure
    for j = 1 to n do                          // 自顶向下赋值，保证无需回溯
        Xj ← 一个与 parent(Xj) 相容的值
    return {X1,…,Xn}
```

自底向上的弧相容处理后，每个变量的域里剩下的值都保证「至少能和它子树里的某种赋值兼容」；于是自顶向下赋值时，给 Xⱼ 挑一个与父亲相容的值总能成功，不会走进死路。复杂度里，弧相容处理 n−1 条边、每条 O(d²)，故 O(n·d²)——从一般 CSP 的指数一举降到线性（对 n）。

### 6.6.2 割集条件化（cutset conditioning）：把「近似树」化归为树

大多数约束图不是树，但可能「几乎是树」——去掉少数几个节点就无环。割集条件化利用这一点：找一个变量子集 S，使得从约束图删掉 S 后剩下的是树，S 称为环割集（cycle cutset）。然后枚举 S 的每一种（满足 S 内部约束的）赋值，对每种赋值：把它对邻居域的影响裁剪掉，再用树算法（6.6.1）解剩下的树结构 CSP。任一种成功即得解。

设割集大小为 c，总时间为

O(d^c · (n − c)·d²)

前半 d^c 是枚举割集赋值的代价，后半 (n−c)d² 是每种赋值下解剩余树的代价。直觉：若图「近似树」则 c 很小，d^c 就不大，相比朴素回溯（O(dⁿ)）省得惊人。找最小环割集本身是 NP 难的，但即便用近似/启发式找到的较小割集也常有巨大收益。

### 6.6.3 树分解与树宽（tree decomposition / treewidth）

另一条利用结构的路线是树分解：把原约束图分解成若干「子问题（团）」并组织成一棵树，每个子问题当作一个「超变量」求解，再在这棵树上用树算法合并。分解的质量由树宽 w（最大子问题含变量数减一）刻画，求解复杂度约为

O(n · d^{w+1})

树宽越小越好——树本身树宽为 1。这与割集条件化是「利用图结构降复杂度」的两种互补手段：割集靠删点变树，树分解靠聚点成树。本报告只登记概念，不展开分解构造。

### 6.6.4 与 SAT / 约束求解器的邻接

CSP 与命题可满足性（SAT）紧邻：布尔 CSP（变量取真/假）就是 SAT，而 CSP 一般又含 3SAT 为特例，故 CSP 求解与 SAT/SMT 求解器共享大量思想（回溯 = DPLL 的骨架、约束传播 ≈ 单元传播）。工业级问题常直接编码成 SAT/CP 交给成熟求解器。此处只提一句邻接，DPLL/SAT 的机制归本课逻辑与求解器相关主题展开。
