本报告讲清"世界被显式建模成状态、智能体在状态空间里搜索"这一符号 AI 的世界观，作为后续搜索 / CSP / 逻辑 / 规划各主题的共同入口。它与"从数据里拟合一个函数"的机器学习范式形成对照：符号 AI 把知识和环境**写成显式结构**（状态、动作、目标），求解是**推理与搜索**；数据驱动范式把知识**藏在参数里**，求解是**优化拟合**。本报告只做这一层对照，不深入数据驱动那一侧。

## 1.1 理性智能体与 PEAS

### 1.1.1 智能体与理性智能体的定义

智能体（agent）是任何能通过传感器感知环境、通过执行器作用于环境的东西。它的行为由智能体函数刻画：把到目前为止的整个感知序列映射到一个动作。

理性智能体是对每一个可能的感知序列，都选择一个"在该感知序列所提供的证据加上其内建知识之下、期望使性能度量最大化"的动作的智能体。

这个定义有四个必须一起看的部件：性能度量、感知序列所提供的证据、智能体对环境的先验知识、以及它当下可执行的动作集。理性不等于全知，也不等于结果一定好——它是"在已知信息下做期望最优的选择"。一个理性智能体过马路前左右看了、但仍被天上掉下的东西砸中，它依然是理性的：它无法感知的事不构成对它理性的否定。

初学者最容易把"理性"误当成"完美"或"总是成功"。要区分两点：一是理性是相对于性能度量、当前证据和已有知识而言的，信息不足时的错误选择不违背理性；二是理性智能体应当在有价值时主动采取"信息收集"和"探索"动作（比如先看一眼再决定），甚至从经验中学习——这些都被"期望最大化性能"所涵盖。

### 1.1.2 PEAS 任务环境刻画

在设计一个智能体前，先要把它面对的任务环境说清楚。PEAS 是四个要素的首字母：

Performance（性能度量）/ Environment（环境）/ Actuators（执行器）/ Sensors（传感器）

以"自动出租车"为例：性能度量是安全、快速、守法、乘客舒适、利润；环境是道路、其他车辆、行人、天气、乘客；执行器是方向盘、油门、刹车、信号灯、喇叭；传感器是摄像头、雷达/激光、速度计、GPS、里程表。

PEAS 的价值在于它逼你先想清楚"成功长什么样（性能度量）"再谈怎么做。初学者常见的错误是把性能度量设在"智能体自己以为的状态"上而不是"环境真实的效果"上——比如给扫地机器人按"扬起并吸入的灰尘量"计分，它会学会把灰尘扬起再吸、循环刷分。正确做法是按"地板保持干净的程度"这种反映真实目标的外部效果来度量。P 要按你真正想要的结果来定，而不是按容易测量的代理量来定。

四要素里，性能度量属于设计者的目标设定，环境是外部给定的，执行器和传感器是智能体与环境的接口。把四者列全，是后面所有形式化（环境分类、问题五元组）的前提。

## 1.2 环境类型分类

### 1.2.1 六个核心维度

任务环境可以沿几个二元（或谱系）维度分类，分类直接决定该用什么方法。本主题聚焦的六个核心维度：

可观测性：完全可观测 vs 部分可观测。传感器能否在每一时刻拿到决定动作所需的全部环境状态。完全可观测时智能体不必维护内部状态。

确定性：确定 vs 随机。下一状态是否完全由当前状态和动作决定。若由当前状态和动作唯一决定则为确定的。

回合性：回合式 vs 序贯。当前决策是否影响未来。回合式里每个"回合"独立（如流水线上逐件判断零件是否合格）；序贯里当前动作会改变后续局面（如下棋、开车）。

静态性：静态 vs 动态。智能体思考时环境是否会变。静态环境等你想清楚再动；动态环境会在你犹豫时继续变化。

离散性：离散 vs 连续。状态、时间、感知、动作是取有限/可数的离散值，还是连续量。

智能体数目：单智能体 vs 多智能体。环境里是否有其他会针对你优化其性能度量的实体；多智能体又分竞争（如国际象棋对手）与合作（如避免相撞）。

这六维越靠"完全可观测·确定·回合·静态·离散·单智能体"这一端，问题越简单、越接近本课后续可以用纯搜索解决的理想情形；越靠另一端（部分可观测·随机·序贯·动态·连续·多智能体）越难，往往要引入概率、学习或博弈。

### 1.2.2 谱系而非硬二分，及各源的维度差异

这些维度多数是谱系而非非黑即白。半可观测、半动态（环境不变但你的评分随时间流逝而降，如带时钟的棋）等中间态很常见；确定/随机之间还有"策略性"（环境本身确定，但因为有对手而对单个智能体表现为不可预测）这样的中间说法。

这里有一处**来源口径差异**，初学者要留意：

其一，AIMA 4th ed 在这六维之外还列了第七维**已知 vs 未知（known / unknown）**——指智能体是否知道环境的"游戏规则"（动作的结果、各状态的表现）。AIMA 明确指出：known/unknown 严格说不是环境本身的属性，而是智能体对环境**知识状态**的属性，因此和前面六维不完全同类。本主题清单按"六维谱系"组织，把 known/unknown 作为 AIMA 额外补充的一维单独记，不并入前六维。

其二，"确定 vs 随机"的措辞在不同版本有别。AIMA 用 deterministic 与 stochastic，其中 stochastic 通常隐含"结果带概率量化"；当环境结果不唯一但**不以概率量化**时，AIMA 另用 nondeterministic（非确定性）一词。部分课堂讲义（含 CS188 早期版本）会直接用 deterministic / stochastic 二分而略去 nondeterministic 这一细分。遇到"nondeterministic"与"stochastic"混用时，按 AIMA 4th 口径理解：前者只说"结果不唯一"，后者进一步"给了概率"。

## 1.3 智能体程序结构

### 1.3.1 五类智能体程序的递进

智能体程序把感知（或感知历史）映射到动作。AIMA 给出由简到繁、能力递增的五类：

简单反射型（simple reflex）：只看**当前**感知，按"条件-动作规则"（if 条件 then 动作）反应，不记历史。实现简单，但一旦当前感知不足以定夺就会失灵，在部分可观测环境里常陷入死循环。

基于模型的反射型（model-based reflex）：内部维护一个反映"世界现在大概是什么样"的状态，靠两类知识更新——世界如何独立演化、自己的动作如何改变世界。这让它能在部分可观测下工作，但它仍只按规则反应，不显式表达"想要达成什么"。

基于目标型（goal-based）：除了当前状态，还持有目标信息，会考虑"哪个动作序列能达到目标"——这正是搜索与规划登场的地方。它比反射型灵活：换目标只需换目标描述，不必重写全部规则。

基于效用型（utility-based）：当有多条路都能到目标、或目标之间要权衡（快 vs 安全）、或结果不确定时，用效用函数把"状态有多可取"量化成实数，选期望效用最高的。目标只区分"达成/未达成"，效用能表达"多好"，从而处理冲突目标与不确定性。

学习型（learning agent）：在以上任一类之上加"学习"，由四部件构成——性能元件（负责选动作，即上面那套）、评判元件（依固定的性能标准反馈表现好坏）、学习元件（据反馈改进性能元件）、问题产生器（主动提出探索性动作以获取新经验）。它能让智能体在未知环境里逐步变好。

### 1.3.2 递进关系与常见误解

把这五类看成一条能力递增的线：简单反射 → 加内部状态（基于模型）→ 加目标（基于目标）→ 加效用量化（基于效用）→ 加自我改进（学习）。每一步都在补上一步的短板：没内部状态就应付不了部分可观测，没目标就不能规划长序列，没效用就无法在多个可行方案间权衡或处理不确定，没学习就无法适应未知。

初学者的两个常见误解。其一，以为"目标"和"效用"是一回事——目标是布尔的（到没到），效用是标量的（有多好、期望多高），后者才能表达权衡与风险。其二，把"学习型"当成一种独立的第五种结构，其实它是**正交**的一层：学习可以叠加在前四类任何一种之上，改进的是"性能元件"这个内核。

本课后续的搜索、CSP、逻辑、规划，主要服务于"基于目标"（有时"基于效用"）这一层的智能体：它们提供的正是"给定目标，如何找到达成目标的动作序列"的机器。

## 1.4 问题形式化五元组

### 1.4.1 搜索问题的形式定义

要用搜索求解一个目标导向问题，先把它形式化。一个搜索问题由以下几个部件定义：

状态空间：所有可能状态的集合（问题中世界可能处的所有构型）。

初始状态：智能体开始时所处的状态。

后继/动作与转移：在某状态下可执行的动作，以及每个动作把当前状态带到哪个状态。

目标测试：判断一个给定状态是否是目标状态。

路径代价：为每条状态序列（路径）赋一个数值代价，通常是各步动作代价之和；求解通常要最小化它。

以八数码（3×3 华容道式滑块）为例：状态是九个格子（含一个空格）的一种排布；初始状态是给定的乱序局面；一个状态下的动作是把空格上/下/左/右滑（即与相邻块交换）；某动作后的状态就是交换后的新排布；目标测试是"是否等于目标有序排布"；每步代价记为 1，路径代价即步数。

### 1.4.2 各版本"五元组"的构成差异（重要易错点）

"五元组"这一说法在不同来源里**成员不完全相同**，这是初学者最容易混的地方，务必分清：

AIMA 4th ed 把问题的形式部件列为：初始状态、动作 ACTIONS(s)、转移模型 RESULT(s, a)、目标状态（或目标测试 IS-GOAL）、动作代价函数 ACTION-COST(s, a, s′)。这里"动作"和"转移模型"是**分开的两项**。

AIMA 3rd ed 及许多沿用其表述的课堂材料（含常见的 CS188 表述）则用"后继函数 SUCCESSOR-FN"把"在 s 能做哪些动作、各自到达哪个状态、各自代价多少"打包成一项，于是五元组常写成：状态空间 / 初始状态 / 后继函数 / 目标测试 / 路径代价（或 step-cost）。本主题清单采用的正是这一版本。

所以同是"五元组"，一种把 ACTIONS 与 RESULT 拆开、另一种用 SUCCESSOR-FN 合并，成员对不上是版本差异不是错误。抓住不变的本质即可：必须说清"从哪开始（初始状态）、能怎么动且动了到哪（动作+转移，或后继函数）、什么算到了（目标测试）、每步/每条路多贵（代价）"。状态空间在 AIMA 4th 里被视为由初始状态经动作/转移隐式生成，不总单列为一"元"；在合并版里常把状态空间显式列为第一元。

路径代价与步代价要分清。步代价是单个动作的代价，路径代价是整条路径各步代价之和；最优解是路径代价最小的解，而不是步数最少的解（除非每步代价都为 1，此时二者一致）。

## 1.5 状态空间图 vs 搜索树

### 1.5.1 状态 vs 节点：两种结构的根本区别

状态空间图与搜索树是两个不同层面的东西，混淆二者是搜索入门第一大坑。

状态空间图：以"世界的状态"为顶点、以"动作导致的状态转移"为有向边的数学图。同一个状态在图里**只有一个顶点**。它是问题客观拥有的结构，通常极大甚至无法完整画出，只在概念上存在。

搜索树：搜索算法在图上探索时**动态生成**的树，它的每个**节点代表一条从初始状态出发的路径**（不是一个状态）。因为通往同一状态可以有多条不同路径，所以**同一个状态会对应搜索树里的多个不同节点**。搜索树的根是初始状态，分支对应算法尝试的各条路径。

状态是"世界的样子"，节点是"到达这个样子所走的一条路"。状态空间图里 N 个状态就是 N 个顶点；搜索树里同一状态可以反复出现许多次。

### 1.5.2 重复状态、冗余路径与回路

因为搜索树按路径展开，一旦状态空间图里有多条路通向同一状态（尤其是有回路时），朴素展开就会反复生成代表同一状态的节点，甚至沿环无限扩展。区分两个概念：重复状态是不同树节点对应了同一个图状态；冗余路径是到同一状态有多条路径而其中一些永远不比另一些更优。

用一个 4 状态带环的小图直观感受这一点（A→B、A→C、B→D、C→D、D→A）：状态空间图里只有 4 个状态，但若把搜索树按路径不加去重地展开到有限深度，每个状态会作为许多个不同的树节点反复出现。下面是就地跑出的真实计数：

```
tree-node appearances per state (depth-bounded): {'A': 7, 'B': 7, 'C': 7, 'D': 9}
distinct states in state-space graph: {'A', 'B', 'C', 'D'}
```

图里只有 4 个不同状态，但在深度受限展开的搜索树里，每个状态都出现了 7–9 次——这正是"节点 ≠ 状态"的直接体现，也说明为什么不去重的树搜索会做大量重复劳动、遇到环还会不终止。

解决办法是维护一个已达/已探索集合（reached / explored set），记住已经见过的状态，从而把"树搜索"升级为"图搜索"：新生成的节点若其状态已在集合中（且不带来更优路径）就丢弃。这就是后续无信息搜索里 graph-search 相对 tree-search 的关键差别——用一份"见过的状态"记录，把搜索树对同一状态的重复展开压掉。

谈"有多少种局面/构型"时说的是状态（图的顶点）；谈"算法探索了多少条路径、扩展了多少次"时说的是节点（树的节点）。完备性、避免死循环、控制时间空间开销，很大程度上就取决于是否正确地用已达集合区分并去重这两者。
