给定一个用逻辑刻画的世界初始状态、一组可执行的动作、以及一个目标条件，如何自动算出一串（或一组）动作，把世界从初始状态变到满足目标的状态。它是"搜索"与"逻辑表示"的合流——大主题2/3 提供了搜索算法，大主题7 提供了用命题描述世界的方式，本主题把两者拼起来：世界被显式地建模成一堆逻辑事实，动作被建模成对这堆事实的增删，规划就是在这个由逻辑描述的状态空间里搜索。与前面几个搜索主题最大的不同是，这里的状态不再是黑箱（如八数码的一个棋面），而是**因子化**的、由许多命题拼成的结构化状态——正是这种结构，才让"自动导出启发式"成为可能，这也是本主题的高潮（10.5）。

## 10.1 经典规划表示 STRIPS/PDDL

### 10.1.1 经典规划的世界假设

经典规划（classical planning）研究的是一类被严格限定的规划问题：环境**完全可观测、确定性、静态、离散、单智能体**，且动作瞬时完成、执行者是唯一的变化来源。在这套假设下，智能体在规划阶段就能完整预测每个动作会把世界变成什么样，因此可以"闭门造车"地一次性算出整条计划，再去执行，无需边走边看。

这些假设是理解后面一切的地基。之所以叫"经典"，正是因为它把现实世界里最麻烦的几个维度（不确定性、部分可观测、并发、时间、连续量）都先砍掉了。初学者容易把规划和"机器人在真实环境里实时决策"混为一谈——那属于放松了这些假设之后的扩展问题（非确定性规划、部分可观测规划、时序规划等，均归入大主题11 与更专门的课程）。先把经典情形吃透，是必要的台阶。一个直接的推论是：既然确定且完全可观测，一条计划就是一个**无条件的动作序列**，不需要"如果……则……"的分支。

### 10.1.2 状态的因子化表示与封闭世界假设

经典规划中的一个状态被表示成一组**基原子（ground fluent，即不含变量的命题）的合取**。凡是没有被列出的原子，一律默认为假，这叫**封闭世界假设（closed-world assumption）**。

举个积木世界（blocks world）的例子，一个状态可能写成：

```
On(A, B) ∧ OnTable(B) ∧ Clear(A) ∧ HandEmpty
```

这表示 A 在 B 上、B 在桌上、A 顶上没东西、机械手空着。注意这里没写 `On(B, A)`，按封闭世界假设它就是假。

因子化是与前面搜索主题最关键的分野。八数码里一个状态是一个整体棋面，你无法"部分描述"它；而这里一个状态是命题的集合，你可以谈论"某个命题成不成立"。正因状态由许多可独立成立/不成立的命题拼成，动作才能被写成"只改动其中几条命题、其余不动"，也才让机器能自动分析"要达成目标 G，哪些命题还差、哪些动作能补上"——这是 10.5 自动启发式的前提。封闭世界假设让状态描述得以有限：只需列出为真的命题，其余全假，不必穷举无穷多的"假事实"。

### 10.1.3 STRIPS 动作模式：前置条件、添加表、删除表

STRIPS（Stanford Research Institute Problem Solver，Fikes & Nilsson 1971，为机器人 Shakey 开发）用三个部分刻画一个动作：**前置条件（precondition）** 是执行该动作前必须为真的文字合取；**添加表（add list）** 是执行后变为真的正文字集合；**删除表（delete list）** 是执行后变为假的正文字集合。

以积木世界"把 x 从 y 上移到桌面"为例，动作模式（schema，带变量）写作：

```
Action: MoveToTable(x, y)
  Precond: On(x, y) ∧ Clear(x) ∧ HandEmpty  ... （AIMA 常写作机械手模型；不同教材细节略异）
  Effect:  OnTable(x) ∧ Clear(y) ∧ ¬On(x, y)
```

在 STRIPS 记法里，效果中的正文字构成添加表（`OnTable(x)`、`Clear(y)`），带 ¬ 的构成删除表（`On(x, y)`）。

这套表示之所以经典，是因为它用极简的方式绕过了逻辑推理里著名的**框架问题（frame problem）**——"动作没提到的事情如何保持不变？"。STRIPS 的答案简单粗暴：凡是不在添加表也不在删除表里的命题，一律保持原值。你不必为每个动作显式写下"它不改变什么"（那会是天文数字的公理），只需写它改变什么。初学者最常踩的坑是把删除表忘掉：如果 `MoveToTable` 只加 `OnTable(x)` 而不删 `On(x, y)`，那么 x 就会诡异地"既在桌上又在 y 上"，状态自相矛盾。删除表正是维持状态一致性的关键。带变量的叫**动作模式**，代入具体对象后叫**基动作（ground action）**，如 `MoveToTable(A, B)`。

### 10.1.4 动作的适用性与后继状态

一个基动作 a 在状态 s 中**可用（applicable）**，当且仅当 a 的前置条件在 s 中全部为真。执行后的后继状态由下式给出：

```
Result(s, a) = (s − Delete(a)) ∪ Add(a)
```

即：从当前状态里去掉删除表中的命题，再并入添加表中的命题。

这个集合运算就是经典规划里"动作如何改变世界"的全部机制，简单到可以一行代码实现，这正是 STRIPS 表示的威力所在。可用性检查（前置条件是否满足）对应搜索里的"哪些动作能在当前节点扩展"；后继状态计算对应"扩展出的子节点是什么"。于是一个规划问题就被翻译成了一个标准的图搜索问题：节点是状态，边是可用动作，起点是初始状态，终点是任何满足目标的状态。理解了这一点，就能看出为什么大主题2/3 的所有搜索算法（BFS、UCS、A*）都能直接搬来解规划——差别只在于状态和动作现在是逻辑描述的。

### 10.1.5 PDDL：规划的标准描述语言

PDDL（Planning Domain Definition Language，McDermott 等人 1998 年为首届国际规划竞赛 IPC / AIPS-98 制定）是描述规划问题的事实标准语言。它把一个问题拆成两个文件：**域文件（domain）** 描述与具体实例无关的部分（谓词、动作模式），**问题文件（problem）** 描述具体实例（对象、初始状态、目标）。

PDDL 的动作模式与 STRIPS 同构，但语法更规整，一个动作大致长这样：

```
(:action move-to-table
  :parameters (?x ?y)
  :precondition (and (on ?x ?y) (clear ?x) (handempty))
  :effect (and (ontable ?x) (clear ?y) (not (on ?x ?y))))
```

PDDL 的意义在于"让不同的规划器可比"：有了统一语言，同一批 benchmark 问题就能喂给任意规划器横向比较，这直接催生了两年一届的国际规划竞赛（IPC），成为该领域几十年进步的引擎。PDDL 在 STRIPS 基础上吸收了 ADL（Action Description Language）的扩展，允许**带类型的变量、否定前置条件、析取前置条件、量词、等词、条件效果**等，表达力比纯 STRIPS 强不少。初学者需要区分：STRIPS 是一种最小的动作表示形式（一个"表达力等级"），PDDL 是一门承载它并层层扩展的语言；说"用 PDDL 写 STRIPS 问题"是完全正常的表述。要注意 PDDL 本身在演进（PDDL2.1 引入数值与时间、PDDL3 引入偏好与约束等），但本主题的经典规划只用到其 STRIPS/ADL 子集。

### 10.1.6 规划问题的解与最优性

一个经典规划问题的**解**是一个从初始状态出发、依次可用、执行完后目标为真的基动作序列。若只要求"能到达目标"，任何这样的序列都是解（satisficing，可满足解）；若还要求总代价（如动作数或加权代价之和）最小，则要的是**最优解**。

这与大主题2/3 里"完备性 vs 最优性"的区分完全一致，只是换了外衣。可满足规划通常快得多（找到一条能走通的路即可），最优规划则难得多（要证明没有更短的路）。实际系统里绝大多数应用只需可满足解，因此像 FF 这样的可满足规划器影响力极大（见 10.5）。一个常见误解是以为规划器总给最短计划——除非明确用可采纳启发式配 A* 之类求最优，否则贪心式的可满足规划器给出的往往是"能用但不最短"的计划。经典规划判定问题（是否存在计划）本身是 PSPACE-完全的，这解释了为什么启发式如此关键。

## 10.2 状态空间规划：前向与后向搜索

### 10.2.1 前向（渐进）搜索 progression

前向搜索（progression / forward search）从初始状态出发，反复应用可用动作生成后继状态，直到某个状态满足目标。它就是把 10.1.4 的图搜索直接跑起来：节点是完整世界状态，起点是初始状态。

前向搜索最大的优点是**状态永远是完整、具体、无歧义的**——每一步你都确切知道整个世界长什么样，可用动作也一目了然（前置条件在当前状态里查得到），实现起来最直接。它的致命弱点是**分支因子巨大**：任意时刻可能有大量动作可用，其中绝大多数与目标毫不相关（比如目标是搭积木塔，你却可以反复地拿起放下无关的积木）。因此纯前向盲搜在稍大的问题上立刻爆炸。历史上前向搜索一度被认为不实用，直到 2000 年前后**自动启发式**（10.5）的出现才让它翻身，如今"前向搜索 + 松弛启发式"是主流规划器（HSP、FF）的骨架。初学者要记住：前向搜索本身平平无奇，让它变强的是启发式。

### 10.2.2 后向（回归）搜索 regression

后向搜索（regression / backward search）反过来，从**目标描述**出发向初始状态倒推。它的节点不是完整状态，而是**子目标（一组还需要成立的文字）**。给定当前子目标 g 和一个"相关"动作 a，回归算出"执行 a 之前必须成立什么"，得到前驱子目标：

```
Regress(g, a) = (g − Add(a)) ∪ Precond(a)
```

即：g 中被 a 添加的部分算是 a 帮我们达成了，可以去掉；但为了能执行 a，又必须把 a 的前置条件加进来当作新的子目标。

一个动作 a 对子目标 g 是**相关（relevant）** 的，须满足两点：a 至少添加了 g 中的某个文字（确实有贡献），且 a 不删除 g 中的任何文字（不帮倒忙、保持一致）。后向搜索的最大好处是**只考虑相关动作**——它从目标反推，天然过滤掉了海量无关动作，分支因子往往远小于前向。代价是它操作的是"部分状态"（子目标集合），可能对应许多真实状态，容易产生实际上不可达或自相矛盾的子目标，一致性维护更麻烦，也更难设计好的启发式。初学者常把 `Regress` 公式记反——关键在于"减去动作添加的、加上动作要求的"。

### 10.2.3 前向 vs 后向的取舍

前向搜索节点是完整状态、分支因子大但状态精确、易配启发式；后向搜索节点是子目标、分支因子小（只看相关动作）但状态抽象、易生成不可达子目标、难配启发式。

理解这组对比的关键直觉是"信息量与聚焦度的权衡"：前向掌握完整信息却不聚焦（不知道哪些动作有用），后向高度聚焦却信息残缺（不知道子目标是否真的可达）。历史结局很有戏剧性：理论上后向的"目标导向"看似更聪明，但 2000 年后由于删除松弛启发式（10.5）在前向搜索上出奇好用——完整状态让松弛计算变得直接——**前向搜索反而成了赢家**，主流可满足规划器几乎都是前向的。这是一个"好启发式胜过好搜索方向"的经典教训，也呼应大主题3 的主旨：搜索的成败很大程度上取决于启发式的质量。

## 10.3 计划空间与偏序规划

### 10.3.1 最小承诺原则

偏序规划（partial-order planning, POP）的指导思想是**最小承诺（least commitment）**：在没有被迫的情况下，不对动作的先后顺序、变量的取值做出决定，把选择尽量推迟。

这与前面所有搜索的思路截然不同。状态空间搜索是"全序"的——它一步步把动作排成一条确定的流水线，即便有些动作彼此无关、谁先谁后都行，也被迫排了个死顺序。最小承诺说：如果两个动作互不干扰，就别急着定谁先谁后，让它们"偏序并存"，只在真正冲突时才决断。直觉上这更接近人类做计划的方式——你计划出门要"戴钥匙"和"穿外套"，但根本不会去纠结先做哪个。好处是避免了在无关排序上做无谓的分叉，理论上能压缩搜索空间；代价是每个搜索节点变复杂了（是一个"半成品计划"而非一个状态）。

### 10.3.2 计划空间搜索：节点是部分计划

偏序规划在**计划空间（plan space）** 里搜索：搜索节点不再是世界状态，而是一个**部分计划（partial plan）**——一个尚未完工、可能还有"待办"的计划草稿。搜索从一个几乎空的计划开始，每一步通过"修补缺陷"逐步把它补全。

这是一次视角的根本转换，初学者务必分清三种"空间"：状态空间搜索里走一步=世界变一个状态；计划空间搜索里走一步=计划草稿被改进一点（补一个动作、加一条顺序约束）。前者的路径就是解，后者的某个节点（一个完整无缺陷的计划）才是解。换句话说，状态空间搜索"在世界里前进"，计划空间搜索"在图纸上作画"。

### 10.3.3 部分计划的四个构成要素

一个部分计划由四部分组成：一组**动作**（含两个虚拟动作 Start 和 Finish，Start 的效果=初始状态，Finish 的前置=目标）；一组**顺序约束**，形如

```
A ≺ B   （A 必须在 B 之前，但不必紧邻）
```

一组**因果链接（causal link）**，形如

```
A --p--> B   （A 产生命题 p，专门用于满足 B 的前置条件 p）
```

以及一组尚未被满足的**开放前置条件（open precondition）**。

因果链接是偏序规划的精髓，也是初学者最陌生的概念。它记录的是"意图"：不只是"A 在 B 前"，而是"A 之所以在这里，就是为了给 B 提供 p"。这层意图信息让规划器能检测"威胁"（见 10.3.4）——如果中间冒出个动作要删掉 p，就会破坏这条因果链接。一个部分计划完工（成为解）的标志是：没有开放前置条件（每个前置都由某因果链接支撑），且没有未消解的威胁。

### 10.3.4 因果链接、威胁与消解

一个动作 C 对因果链接 A --p--> B 构成**威胁（threat）**，如果 C 删除 p，且顺序约束允许 C 排在 A 与 B 之间。威胁必须消解，办法有两种：

```
降级（demotion）：加约束 C ≺ A   （把威胁者挪到因果链接之前）
升级（promotion）：加约束 B ≺ C   （把威胁者挪到因果链接之后）
```

威胁机制回答了"最小承诺会不会导致计划出错"这个疑虑。因为不强行全序，某个删除 p 的动作可能"漂浮"在 A 和 B 之间，把 B 依赖的 p 给毁了。规划器识别出这种威胁后，通过增加一条顺序约束把威胁者赶到安全位置（要么在 A 前用不着 p、要么在 B 后 p 已被消费）。这正是"只在被迫时才承诺顺序"的体现：平时不排序，一旦发现威胁才补一条最小的排序约束。若两种消解都行不通（都产生矛盾约束），说明当前部分计划走不通，回溯。

### 10.3.5 POP 算法主循环与历史地位

POP 的主循环是一个"挑缺陷、补缺陷"的过程：

```
while 部分计划仍有缺陷:
    若有开放前置条件 p（属于动作 B）:
        选一个能产生 p 的动作 A（已有的或新引入的）
        加因果链接 A --p--> B，加约束 A ≺ B
    对每条因果链接检查威胁，用 promotion / demotion 消解（不能消解则回溯）
返回：动作集 + 顺序约束（一个偏序计划）
```

输出不是一条动作序列，而是一个偏序——任何与该偏序相容的**线性化（拓扑排序）** 都是一条合法执行序列。这是偏序规划一个实用优点：一次规划得到一族等价执行方案，便于并行执行或临场调整顺序。历史地位要如实交代：偏序规划在 1990 年代（SNLP、UCPOP 等系统）是规划研究的主流范式，理论优雅；但 1995 年 Graphplan、随后 2000 年前后基于删除松弛启发式的前向状态空间搜索（HSP、FF）在速度上大幅超越了它，偏序规划遂退居次要。今天它更多作为思想遗产（最小承诺、因果链接）被学习，其偏序输出的理念也影响了时序与多智能体规划。初学者不必把它当当前 SOTA，而应把它当"理解规划本质的一个重要视角"。

## 10.4 规划图与 Graphplan

### 10.4.1 规划图的结构

规划图（planning graph）是一种分层的数据结构，由**命题层**和**动作层**交替叠成：S₀（初始命题层）、A₀（动作层）、S₁、A₁、S₂……层号 i 表示"最快第 i 步能达成"。每个动作层包含所有前置条件在上一命题层中出现的基动作，外加每个命题的**持续动作（no-op / persistence action）**——一个前置和效果都是该命题本身的虚拟动作，用来把命题"带"到下一层。

规划图的妙处是它能在**多项式时间**内构建（层数、每层大小都有多项式上界），却编码了关于问题的大量结构信息。持续动作是初学者容易忽略的细节：没有它，一个在 S₁ 为真的命题就无法"活到"S₂，规划图会漏掉"某命题保持不变同时别处发生动作"的情形。要点在于：规划图**不是**在做规划，它是在做一个乐观的、放松的可达性分析——"如果动作可以任意并行、只要前置齐了就都能做，那么第 i 层最多能让哪些命题为真"。这个乐观估计正是它作为启发式来源（10.4.6）和 Graphplan 算法（10.4.5）基础的原因。

### 10.4.2 动作层互斥（mutex）

同一动作层里的两个动作互斥（mutually exclusive, mutex），若满足以下三种情形之一：

```
不一致效果（inconsistent effects）：一个动作删除了另一个动作的某个效果
干扰（interference）：一个动作删除了另一个动作的某个前置条件
竞争需求（competing needs）：两个动作各有一个前置条件，而这两个前置条件在上一命题层互斥
```

动作互斥刻画的是"这两个动作不可能在同一步并行执行"。前两种（不一致效果、干扰）是"直接冲突"——一个动作会破坏另一个动作的效果或前提；第三种（竞争需求）是"间接冲突"——两个动作各自没错，但它们分别需要的东西已经彼此打架了，所以也没法同时上。初学者最容易混淆"不一致效果"与"干扰"：前者是效果 vs 效果（两个动作想把同一命题分别设为真/假），后者是效果 vs 前置（一个动作把另一个动作赖以执行的前提给删了）。记牢这三条，因为它们是 Graphplan 剪枝威力的来源。

### 10.4.3 命题层互斥

同一命题层里的两个命题互斥，若满足以下两种情形之一：

```
互否（negation）：一个命题是另一个的否定（p 与 ¬p 显然不能同真）
不一致支持（inconsistent support）：产生这两个命题的所有动作对，两两都互斥
```

命题互斥刻画的是"这两个命题不可能在这一步同时为真"。互否是显然的。真正微妙的是不一致支持：一个命题可能有多种达成方式，只要**存在至少一对**分别达成两命题的动作是不互斥的，这两个命题就还有希望同真，就不互斥；只有当所有达成方式两两冲突时，它们才真正互斥。这个"对所有达成方式全称量化"的定义是初学者最难绕过去的一处——它体现了规划图"乐观"的底色：只要有一线并存的可能，就不判死刑。命题互斥与动作互斥逐层交替计算、互相依赖（本层动作互斥决定下层命题互斥，下层命题互斥又决定再下层动作互斥）。

### 10.4.4 单调性与稳定（leveling off）

随着层数增加，规划图具有单调性：命题只增不减（持续动作保证已出现的命题一直出现），互斥关系只减不增（曾经互斥的可能在更高层变得不互斥）。因此规划图必然在有限层数后**稳定（level off）**——某一层与前一层的命题集和互斥集完全相同，之后再展开也不会变。

这条性质保证了基于规划图的算法会终止。直觉上：命题的宇宙是有限的（就那么多基原子），互斥对也是有限的，一个只增（命题）一个只减（互斥）的过程必然收敛到不动点。稳定层的意义是一个可判定的信号：如果规划图已经稳定，而目标里的某些命题仍未全部出现、或它们之间仍互斥，那么问题**无解**——这是 Graphplan 判定无解的依据之一。初学者可以把"leveling off"理解为"这个乐观分析已经榨干了所有可能性，再算下去也是一样"。

### 10.4.5 Graphplan 算法

Graphplan（Blum & Furst 1997）交替进行"扩展"与"抽取"两个阶段：

```
循环：
  1) 扩展：把规划图向前延展一层
  2) 检查：目标的所有命题是否都出现在当前最后命题层、且两两不互斥？
        否 → 回到 1) 继续扩展（若已稳定且仍不满足 → 报告无解）
        是 → 进入抽取
  3) 抽取（backward search + mutex 剪枝 + no-good 记忆化）：
        从最后一层的目标出发，逐层往回选一组不互斥的动作来支持当前子目标，
        其前置构成上一层的新子目标；若某层无法选出相容动作集 → 回溯，
        并把该"(层, 子目标集)"记为 no-good 缓存，避免重复失败
  抽取成功 → 返回分层计划；抽取失败且图已稳定到 no-good 也稳定 → 无解
```

Graphplan 的算法思想是"先便宜地建一张放松的可达图，再在图上做带强剪枝的回溯搜索"。它相对纯状态空间搜索的巨大优势来自互斥关系：mutex 让抽取阶段在每一层都能砍掉大量不可能的动作组合，搜索空间远小于盲搜。no-good 记忆化则避免在不同扩展轮次里重复撞同一堵墙。Graphplan 是**可靠且完备**的——找到的计划一定合法，有解一定找得到，无解一定能判定。它输出的是**分层（并行）计划**：每层可含多个可同时执行、两两不互斥的动作，因此天然给出并行度信息。历史上 Graphplan（1995/1997）是规划领域的一次飞跃，速度远超当时的偏序规划器，直接开启了 1990s 末的规划复兴。初学者要抓住的主线是：**规划图的价值一半在算法（Graphplan），一半在启发式（下一节）**。

### 10.4.6 规划图作为启发式来源

即便不用 Graphplan 完整抽取计划，规划图本身也是一台强力的**启发式发生器**。一个命题第一次出现的层号（level cost）是"达成它至少要几步"的乐观下界；一组目标命题的达成难度可用它们的最大层号（max-level）、层号之和（sum/level-sum）或"从图中抽取的松弛计划长度"（set-level / relaxed plan）来估计。

这是把 10.4 与 10.5、以及大主题3 的 A* 缝合起来的关键。规划图既然是对"最快几步能达成什么"的乐观分析，那么它给出的层号自然就是一种**不高估**（在恰当定义下可采纳）的距离估计，可以直接喂给 A* 或贪心最佳优先，用于前向状态空间搜索。换句话说，规划图不必非得跑完整个 Graphplan，很多现代规划器只是"借它的前半段"来算启发式，然后用大主题3 的搜索算法去找解。这正是"规划 = 搜索 + 逻辑"合流的最佳注脚，也顺势引出下一节的松弛启发式家族。

## 10.5 规划启发式

### 10.5.1 松弛：自动导出启发式的总思路

规划启发式的核心思想是**松弛（relaxation）**：把原问题简化成一个更容易解的"松弛问题"，用松弛问题的最优解代价作为原问题的启发式估计。因为松弛问题的约束更少、解更容易达成，它的解代价一定**不超过**原问题的真实代价，因此得到的启发式天然满足可采纳性（不高估）。

这与大主题3「启发式设计」中"松弛问题给可采纳启发式"是同一条原理，只是在规划里它变得格外强大。原因正是 10.1.2 强调的**因子化表示**：因为状态和动作都是逻辑描述的、结构透明的，机器可以**自动地、领域无关地**对任何 PDDL 问题施加松弛、算出启发式，而不需要人为每个问题手工设计。这是经典搜索（八数码要人手写曼哈顿距离）与自动规划（规划器自动生成启发式）的分水岭，也是 2000 年后规划技术爆发的根本原因。下面几种启发式，就是不同的松弛方式。

### 10.5.2 忽略前置条件启发式

最简单的松弛之一是**忽略前置条件（ignore preconditions）**：把所有动作的前置条件删掉，于是任何动作随时可用。这样问题退化成"需要多少个动作才能把目标里缺失的命题都添加出来"，可近似为一个集合覆盖问题。

前置条件是"做这件事之前得先满足的门槛"，把门槛全拆掉，规划就只剩"凑齐目标命题"这件事，显然比原问题容易，故其解代价是下界、可采纳。这个启发式简单但通常偏弱（估得太乐观、太小，指导力有限）。它的价值更多是教学性的——展示"删掉一类约束就得到一个松弛"的模式。集合覆盖本身是 NP-难，实际中还要再近似。

### 10.5.3 删除松弛与 h⁺

规划中最重要的松弛是**忽略删除表（ignore delete lists / delete relaxation）**：把每个动作的删除表清空，只保留正效果。松弛后世界变得"单调"——命题一旦为真就永远为真，动作只会让更多命题成立、绝不会撤销任何已成立的命题。这个松弛问题的**最优解代价**记作

```
h⁺ = 删除松弛问题的最优（最短）计划代价
```

h⁺ 是可采纳的，且是删除松弛这一族启发式的理论标杆。

删除松弛为何如此关键？因为现实规划里"绝大多数难度来自动作的副作用（删除效果）会破坏已经辛苦达成的子目标"（所谓"子目标之间相互破坏"）。删掉删除表，等于假设"做过的努力永不白费"，问题立刻变得温和：你只需不断往前堆命题直到目标齐了。这个假设显然乐观（真实世界会有破坏），故 h⁺ 不高估、可采纳。要点在于：h⁺ 本身**计算仍是 NP-难的**（求松弛问题的最优解不便宜），所以实践中不直接算 h⁺，而是用下面两个多项式时间的近似（h_max、h_add）或抽取一条松弛计划（h_FF）来逼近它。理解 h⁺ 是理解整个现代规划启发式家族的钥匙。

### 10.5.4 h_max 与 h_add

在删除松弛下，可用递推估计每个命题的达成代价。对一组子目标 G，两种经典聚合方式为：

```
h_max(G) = max over p in G   of cost(p)      —— 取最难子目标的代价
h_add(G) = sum over p in G   of cost(p)      —— 各子目标代价求和
```

其中 cost(p) 递归定义为"达成 p 的最便宜动作的（其前置代价按同样方式聚合 + 动作代价）"。

这两个启发式（Bonet & Geffner 2001，HSP 系统）体现了一个根本权衡。**h_max 可采纳但偏弱**：它假设"完成一组子目标的代价 = 其中最难那个的代价"，等于乐观地认为达成最难子目标的路上会顺带把其他子目标全办了，估得太小、指导力弱。**h_add 更强但不可采纳**：它假设"各子目标彼此独立、代价相加"，忽略了子目标之间可以共享动作（一个动作可能同时推进多个子目标），因此会**重复计数**、可能高估，从而牺牲可采纳性换取信息量。初学者要记住这对经典对立：max 保守可采纳、add 激进更 informed。实践中若追求可满足解（不要求最优），常选信息量更足的 h_add 或下面的 h_FF；若要 A* 求最优，则需可采纳的 h_max 或 h⁺ 的可采纳近似。

### 10.5.5 h_FF：松弛计划启发式

FF 启发式（Hoffmann & Nebel 2001，FF 系统）不去算抽象代价，而是**真的从规划图里抽取一条删除松弛下的可行计划**，用这条松弛计划包含的动作数作为估计：

```
h_FF = 从松弛规划图中反向抽取的一条松弛计划的动作数
```

h_FF 一般**不可采纳**（抽取到的松弛计划未必是松弛最优解，可能偏长而高估），但实践中信息量极佳、计算高效。

h_FF 的高明之处在于它比 h_add 更聪明地处理了"共享动作"问题：因为它抽取的是一条**真实的松弛计划**（一组具体动作），同一个动作只会被数一次，天然避免了 h_add 的重复计数；同时它又比 h_max 信息量大得多。FF 规划器把 h_FF 配上前向搜索（加上"helpful actions 优先"等增强），在 2000 年 IPC 上大获全胜，"前向搜索 + 忽略删除表启发式"由此确立为可满足规划的主流范式（呼应 10.2.3 的结论）。要如实标注：h_FF 用可满足解质量换取了可采纳性，因此**不适合直接用于最优规划**；追求最优时人们转向 h⁺ 的可采纳近似、地标（landmark）启发式或抽象启发式。

### 10.5.6 其他启发式家族与现代走向

除删除松弛外，规划领域还有两大启发式思路。**抽象启发式**（如模式数据库 PDB、笛卡尔抽象、merge-and-shrink）把问题投影到一个更小的抽象空间，在抽象空间里算精确距离作下界，可采纳，是最优规划的主力。**地标启发式**（landmark heuristics）识别"任何计划都必须达成的中间命题/动作（地标）"，用还需达成的地标数量或代价作估计，信息量强、也可导出可采纳变体。

这些与删除松弛互补，共同构成现代规划器（如 Fast Downward 框架下的各种配置）的启发式工具箱。抽象启发式呼应了大主题3 里"模式数据库"的思想（八数码的 PDB 是其特例），只是在规划里同样做到了领域无关、自动构造。初学者不必深究这些的实现，只需知道：**可满足规划**以删除松弛（h_add/h_FF）+ 前向贪心搜索为主，**最优规划**以可采纳启发式（h_max、h⁺ 近似、PDB/merge-and-shrink、可采纳地标）+ A* 为主。至于把大模型当规划器或"LLM + 工具 + 规划"的当代方向，属于更前沿的题目、只在此点到为止，其可靠性仍在活跃研究中、结论未定，不作定论。
