前四个大主题里只有一个智能体在一个不会跟它作对的世界里找路。本主题把"环境里还有一个也在最大化自己利益、并且会主动跟你对着干"的对手加进来。求解目标从"找一条到目标的路径"变成"找一个策略：无论对手怎么应对，我都走得最好"。主线是从 Minimax（把对手当成完美理性的敌人）出发，经 α-β 剪枝把它变得可算，再用深度限制+评估函数让它能处理真实棋类，最后用期望极小极大接纳骰子这类随机性、用 MCTS 处理分支太大而无法穷举的博弈。

## 5.1 博弈形式化

### 5.1.1 博弈作为一类搜索问题（六元组）

对抗搜索把一局双人博弈刻画成一组和普通搜索问题类似、但显式区分"轮到谁走"的构件。AIMA 4th ed 用如下六个部分定义一个博弈：

```
S0            初始状态（棋盘的初始摆法）
TO-MOVE(s)    在状态 s 下轮到哪个玩家行动
ACTIONS(s)    状态 s 下的合法走法集合
RESULT(s, a)  在 s 执行走法 a 后到达的新状态（转移模型）
IS-TERMINAL(s) 终止测试：s 是否为游戏结束局面
UTILITY(s, p) 效用函数：终止局面 s 对玩家 p 的最终得分
```

初始状态、ACTIONS 与 RESULT 一起定义出这局博弈的"博弈树"。

和单智能体搜索相比，最大的不同是多了 `TO-MOVE`：每一步不是同一个决策者在连续行动，而是两个玩家轮流行动。因此不能只问"从这里怎么走到终点"，而要问"轮到我时我怎么走、轮到对手时他会怎么走"。UTILITY 只在终止局面上有定义（例如井字棋赢 +1、和 0、输 -1），这也是它和"路径代价"的区别——路径代价沿途累加，效用只在游戏结束时结算。CS188 用几乎相同的构件（状态、玩家、动作、转移、终止效用）介绍博弈，术语细节略有出入但结构一致。

### 5.1.2 零和与常和博弈

零和博弈指两名玩家的效用在每个终止局面上恰好相反、加起来为常数（通常规范化为 0）：一方所得即另一方所失。井字棋、国际象棋、围棋都属此类。

零和的关键推论是"双方目标完全对立"：不存在双赢，一个玩家的最优就是另一个玩家的最差。这让我们可以只用一个数值来描述局面——习惯上取 MAX 玩家的效用，那么 MAX 想让它尽量大、MIN 想让它尽量小，于是"极小极大"这个名字里的 max 和 min 就自然出现了。AIMA 提醒一个易混点：严格说很多棋"和棋+1、输+0、赢+2"这类记分是"常和"而非字面"零和"，但因为常数可以平移抵消，两者在决策上等价，教材里常把两者统称零和。与之相对的是"非零和/一般博弈"（如囚徒困境），双方可以同时变好或变坏，需要用纳什均衡等更一般的博弈论工具，不在本主题的对抗搜索范围内。

### 5.1.3 博弈树、层与 ply

博弈树是一棵以初始状态为根、每个节点是一个局面、每条边是一个走法的树；MAX 与 MIN 的节点在相邻层交替出现，叶子是终止局面并带有效用值。

一个初学者常搞混的计量单位是"步"。一次由某一名玩家走的单步叫一个 ply（半回合）；双方各走一次（一个 ply 对一个 ply）合起来常被口语称作一"回合(move)"。国际象棋里说"往前看 8 步"通常指 8 个 ply（MAX、MIN 各 4 次），而不是 8 个完整回合。博弈树的规模随深度指数爆炸：分支因子 b、深度 m 时叶子约为

b^m

井字棋整棵树叶子不到 9! ≈ 362880（去掉对称与提前终止后更少），可以完全展开；国际象棋 b≈35、一局约几十到上百 ply，树大到无法穷举——这正是后面所有技术（剪枝、截断、采样）存在的理由。

### 5.1.4 极小极大值（博弈的"正确答案"）

一个局面的极小极大值，是在"双方此后都完美地各自最优行动"的假设下，该局面对 MAX 玩家最终能拿到的效用。它是对抗搜索里"这个局面到底值多少"的标准定义：

```
MINIMAX(s) =
  UTILITY(s, MAX)                                  若 IS-TERMINAL(s)
  max over a in ACTIONS(s) of MINIMAX(RESULT(s,a)) 若 TO-MOVE(s)=MAX
  min over a in ACTIONS(s) of MINIMAX(RESULT(s,a)) 若 TO-MOVE(s)=MIN
```

直觉是"我乐观地对自己、悲观地对对手"：轮到我（MAX）时我挑让结果最大的子局面，轮到对手（MIN）时我假设他一定挑让我最小的子局面。这个值是相对"完美对手"而言的——它给出的是最坏情况下的保证。一个重要的实践含义（也是常见误解）：如果对手并不完美，Minimax 仍然安全（不会比这个保证更差），但未必是"利用对手弱点得分最多"的策略；面对犯错的对手，专门针对性的策略有时能赢得更多，但会牺牲对完美对手的保证。极小极大值一旦算出，MAX 的最优走法就是通向该值的那个子节点，这条策略叫极小极大决策。

### 5.1.5 完美信息、确定性与博弈的谱系

对抗搜索的经典结论（Minimax、α-β）默认博弈是"双人、零和、确定性、完美信息、轮流行动"的。完美信息指双方都能看到完整局面（如棋类的整个棋盘），没有隐藏牌。

给这几个假设定位，是为了看清后面每一节在松开哪一条：本主题 5.2–5.4 全都在"确定+完美信息"下工作；5.5 期望极小极大松开"确定性"，引入骰子/洗牌这样的随机性（仍是完美信息）；隐藏信息（如扑克的暗牌）属于"不完美信息博弈"，需要信念状态与博弈论求解，AIMA 在本章后段单列、本主题不展开。把这条谱系记清，能避免把"随机"和"隐藏信息"混为一谈——西洋双陆棋有骰子但双方都看得见棋盘（完美信息+随机），扑克则是牌看不见（不完美信息）。

## 5.2 Minimax

### 5.2.1 Minimax 作为博弈树上的深度优先递归

Minimax 算法就是把 5.1.4 的极小极大值定义直接实现成一次对博弈树的深度优先遍历：递归到叶子取效用，回溯时 MAX 层取子值最大、MIN 层取子值最小，根节点算出的值就是极小极大值，对应的那步就是最优走法。

```
function MINIMAX-SEARCH(game, state) returns an action
  player <- game.TO-MOVE(state)
  value, move <- MAX-VALUE(game, state)
  return move

function MAX-VALUE(game, state) returns (utility, move)
  if game.IS-TERMINAL(state) then return game.UTILITY(state, player), null
  v <- -infinity
  for each a in game.ACTIONS(state):
    v2, a2 <- MIN-VALUE(game, game.RESULT(state, a))
    if v2 > v then v, move <- v2, a
  return v, move

function MIN-VALUE(game, state) returns (utility, move)  # 对称，取 min
```

关键点是"两个互相调用的函数"：MAX-VALUE 里对每个孩子调用 MIN-VALUE，反之亦然，天然对应双方轮流。初学者最容易写错的是在 MIN 层误用 max（或忘记切换玩家），结果算出的策略会假设对手也在帮你——那不是对抗搜索。递归必须一路走到终止局面才有真实效用可回传，这也是为什么纯 Minimax 只能用于能被完全展开的小博弈（井字棋可以，国际象棋不行，后者要靠 5.4 的截断）。

### 5.2.2 复杂度与完备性

对分支因子 b、最大深度 m 的博弈树，Minimax 是完全的深度优先搜索，时间复杂度为指数级、空间复杂度线性：

时间 O(b^m)，空间 O(b·m)

如果博弈树有限，Minimax 完备（一定给出答案）；对手完美时它给出的策略是最优的。

时间 O(b^m) 就是"要看遍整棵树的所有叶子"这一事实的量化——这正是它对真实棋类不可行的根源（国际象棋 b≈35、m 几十，35^几十 是天文数字）。空间 O(b·m) 来自深度优先：任一时刻只需保存当前这条从根到叶的路径（长 m），路径上每层还挂着尚未展开的兄弟（约 b 个）。AIMA 指出若一次只生成一个后继而非全部，空间可进一步降到 O(m)。要记住："完备/最优"是相对"能把树走完"而言；一旦引入截断（5.4），最优性就让位给评估函数的质量。

### 5.2.3 多人博弈的向量化推广

当玩家超过两人时，单一的"MAX/MIN 交替"不再够用，需要给每个节点存一个效用向量——每名玩家一个分量，轮到谁行动谁就挑让自己那一分量最大的走法。

这是对二人 Minimax 的自然推广：二人零和是它的特例（向量两个分量恒相反，退化成一个数取 max/min）。这里两个初学者要注意的点：一是多人博弈通常不是零和，可能出现"联盟"等复杂现象，向量法只处理各自独立最大化的情形；二是正因为不能压成一个数、无法用 α-β 那种"对立"式剪枝，多人博弈的剪枝远比二人零和弱。本主题后续（α-β 起）都聚焦二人零和这一最干净、剪枝最强的情形。

## 5.3 α-β 剪枝

### 5.3.1 α 与 β 的含义

α-β 剪枝在做 Minimax 遍历的同时，维护两个界：α 是"到目前为止、沿这条路径 MAX 至少已能保证拿到的值"（MAX 的下界，只增不减）；β 是"到目前为止、沿这条路径 MIN 至少已能把 MAX 压到的值"（MAX 的上界，只减不增）。

把 α 想成"MAX 手里已经攥着的最好保底"，β 想成"MIN 已经攥着的最狠威胁"。搜索沿着树往下传递这对 (α, β) 区间，表示"最终答案只可能落在 α 与 β 之间才值得继续看"。一旦发现某个子树的值已经跑出这个有意义的区间，就说明无论它内部还有什么，都改变不了上层的选择，可以整枝剪掉不看。初学者要分清：α、β 是"沿路径继承下来的界"，不是某个节点的固定属性；同一状态在不同路径上可以带着不同的 (α, β)。

### 5.3.2 剪枝条件

在一个 MIN 节点上逐个考察其子节点、不断用子值更新该节点当前值 v（并令 β=min(β,v)），一旦

v ≤ α

就可以停止考察它剩余的子节点（α 剪枝）。对称地，在一个 MAX 节点上，一旦

v ≥ β

就停止考察其余子节点（β 剪枝）。

MIN 节点上 v ≤ α 的直觉是：这个 MIN 节点最终只会更小或不变（MIN 还要往下挑更小的），而它现在已经 ≤ MAX 早先在别处保底的 α，说明 MAX 根本不会走到这个 MIN 节点来——那再算它剩下的孩子是白费。β 剪枝对称。一个常见误区是把条件写成严格小于/大于：用 `≤ α` / `≥ β`（含等号）在返回值上是安全的（等值不影响上层最优选择），AIMA 伪代码即用含等号版本。

### 5.3.3 复杂度收益取决于走法排序

α-β 不改变根节点算出的极小极大值，只跳过不影响结果的分支；它能剪掉多少，完全取决于子节点被考察的顺序。若每次都能最先考察最优走法（理想排序），α-β 需要检查的节点数从 O(b^m) 降到

O(b^(m/2))

也就是有效分支因子从 b 降到 √b——同样时间预算下能多看大约一倍的深度。若走法随机排序，AIMA 给出的经验量级约为 O(b^(3m/4))（b 适中时）。

这条"O(b^(m/2)) 需要理想排序"是本节最核心也最易被略去的前提：教科书报"分支因子开方"的收益时，默认你已把最优走法排到前面；现实中做不到完美排序，于是实战里用启发式走法排序（如先试吃子、杀招、历史启发、上一次迭代的最佳走法）去逼近它。排序越好，剪得越多，这也是国际象棋引擎把大量工程花在走法排序上的原因。注意题面常写作 O(b^d)→O(b^{d/2})，其中 d 是搜索深度、与 AIMA 的 m 同义，只是符号不同。

### 5.3.4 结果不变、只是更快（本机验证）

α-β 与 Minimax 返回完全相同的值和最优走法，差别只在展开的节点数。下面在一棵 b=4、深度 d=6 的随机博弈树上对比二者（叶子随机赋值，走法未做最优排序，因此收益介于理想 √b 与随机之间）：

```python
import random
random.seed(0)
b, d = 4, 6
class Node:
    __slots__ = ('children', 'val')
    def __init__(self): self.children = None; self.val = None
def build(depth):
    n = Node()
    if depth == 0:
        n.val = random.randint(-50, 50); return n
    n.children = [build(depth - 1) for _ in range(b)]
    return n
root = build(d)

cnt_mm = 0
def minimax(n, maxi):
    global cnt_mm; cnt_mm += 1
    if n.children is None: return n.val
    if maxi: return max(minimax(c, False) for c in n.children)
    return min(minimax(c, True) for c in n.children)

cnt_ab = 0
def ab(n, a, be, maxi):
    global cnt_ab; cnt_ab += 1
    if n.children is None: return n.val
    if maxi:
        v = -10**9
        for c in n.children:
            v = max(v, ab(c, a, be, False)); a = max(a, v)
            if a >= be: break            # β 剪枝
        return v
    else:
        v = 10**9
        for c in n.children:
            v = min(v, ab(c, a, be, True)); be = min(be, v)
            if a >= be: break            # α 剪枝
        return v

print(minimax(root, True), ab(root, -10**9, 10**9, True))   # 值相同
print(cnt_mm, cnt_ab)                                        # 节点数
```

真实输出（Py3.11.15 @2026-08-01）：两法返回值均为 -22（相同）；Minimax 访问 5461 个节点，α-β 仅 1494 个。作为参照，全树叶子 b^d = 4096，理想排序下 α-β 只需约 b^(d/2)=64 个叶子。这直观印证了"结果不变、代价大减，且减多少看排序"。

## 5.4 深度限制与评估函数

### 5.4.1 截断搜索与启发式极小极大

对无法走到终止局面的真实博弈，做法是在某个深度就"截断"，不再递归到底，转而用一个评估函数给非终止局面估一个分数，当作它的效用回传。把 Minimax 里的"终止测试+效用"换成"截断测试+评估函数"，就得到启发式极小极大 H-MINIMAX：

```
H-MINIMAX(s, d) =
  EVAL(s, MAX)                                        若 IS-CUTOFF(s, d)
  max over a of H-MINIMAX(RESULT(s,a), d+1)           若 TO-MOVE(s)=MAX
  min over a of H-MINIMAX(RESULT(s,a), d+1)           若 TO-MOVE(s)=MIN
```

这是把纯 Minimax 用于现实棋类的关键改造。代价是"最优性"没有了：结果的好坏此刻取决于评估函数估得准不准，以及截断得够不够深。截断深度通常不是固定值，而是配合迭代加深（先搜 1 层、再 2 层……用上一层结果做走法排序并可随时中断返回当前最好走法），以便在时间用尽时给出尽量深的结果。

### 5.4.2 评估函数

评估函数 EVAL(s, p) 对一个非终止局面 s 估计"若从此对弈下去，对玩家 p 最终大概值多少"。它要满足：在终止局面上与真实效用一致、计算要快、且对非终止局面它给的数值要与"实际获胜概率/期望结果"强相关。

经典造法是特征加权线性组合，例如国际象棋按子力赋权（后=9、车=5、象/马=3、兵=1）再叠加位置、机动性等特征：

EVAL(s) = w1·f1(s) + w2·f2(s) + ... + wn·fn(s)

初学者要抓住的直觉是"评估函数是把'看不到底的未来'压缩成一个当下可算的数"，因此它是整套截断搜索质量的天花板：搜得再深，若估值系统性偏差，也会一致地走错。这里也埋着一个"规范 vs 实现"的分账——线性加权是教科书基线，现代顶尖引擎（含用神经网络当评估函数的路线）已远超它，但那属于工程/学习范畴，本主题只讲经典评估函数原理。

### 5.4.3 静默搜索与地平线效应

只在固定深度硬截断会带来"地平线效应"：一个坏结果（如必丢一子）被推到搜索深度之外看不见，程序误以为局面安好，甚至用无意义的将军去把厄运"推过地平线"。静默搜索是针对性的补丁——在截断点若局面"不平静"（还有吃子、将军等剧烈变化正在进行），就沿这些强制性走法继续搜下去，直到到达一个"平静(quiescent)"、可以安全估值的局面才应用评估函数。

直觉是"别在混战正酣时数子力"：正吃到一半的局面用静态评估会严重失真，静默搜索让评估只发生在战斗告一段落时。地平线效应与静默搜索是理解"为什么固定深度截断不够、真实引擎要做变深度处理"的关键一对概念。此外还有"前向剪枝"（如 beam/激进裁剪明显差的走法）以进一步省算力，但它可能剪错、牺牲正确性，属可选加速手段。

## 5.5 期望极小极大

### 5.5.1 机会节点与 expectiminimax

当博弈含有随机因素（掷骰、洗牌、翻牌），博弈树里除 MAX、MIN 节点外还要加入"机会节点(chance node)"，代表一次随机事件；它的值是各随机结果值按概率的加权平均（期望）。把 Minimax 扩展成对机会节点取期望，就是期望极小极大 EXPECTIMINIMAX：

```
EXPECTIMINIMAX(s) =
  UTILITY(s, MAX)                                        若 IS-TERMINAL(s)
  max over a of EXPECTIMINIMAX(RESULT(s,a))              若 TO-MOVE(s)=MAX
  min over a of EXPECTIMINIMAX(RESULT(s,a))              若 TO-MOVE(s)=MIN
  sum over r of P(r) · EXPECTIMINIMAX(RESULT(s,r))       若 s 为机会节点
```

其中 r 遍历该机会节点的所有随机结果、P(r) 是其概率。西洋双陆棋是典型：每步先掷骰（机会节点），再在骰子决定的合法走法里由玩家选择（MAX/MIN 节点）。直觉是"面对运气，理性的做法是按概率加权、最大化期望收益"，而不是只看最好或最坏的骰点。CS188 里对"只有随机、无对抗对手"的情形单讲 Expectimax（把 MIN 层换成机会层），期望极小极大是它与 Minimax 的合体。

### 5.5.2 评估函数对数值尺度变得敏感

一个反直觉但至关重要的结论：在纯 Minimax 里，评估函数只要保持局面之间的"排序"正确就够了（任何保序的单调变换给出相同决策）；但一旦有机会节点，评估函数的具体数值大小也会影响决策——只有对评估值做正线性变换（乘正数、加常数）才保证决策不变，非线性的保序变换可能改变结果。

原因是机会节点要对数值做加权平均，而平均对"数值间的相对间距"敏感，不只对排序敏感。举例：把"稍好"记 2、"好很多"记 4，与记 2、100，在 Minimax 下等价（都是后者更大），但在机会节点求期望时，间距被放大的方案会让程序更倾向于博一个高方差的好结果。初学者容易把 Minimax 那句"评估函数只需保序"错误地搬到期望极小极大上——这是本节要点。

### 5.5.3 复杂度代价

机会节点让分支进一步膨胀：设每个机会节点有 n 种随机结果，则时间复杂度约为

O(b^m · n^m)

因为除玩家分支 b 外，每一层还多乘一个随机结果分支 n。这使得可搜索深度显著变浅——西洋双陆棋每掷骰有 21 种不同点数组合，树增长极快。α-β 式的剪枝在机会节点上也更受限（因为要对所有随机结果求期望，通常不能因为看了一部分就断定整体，除非对评估值有额外的上下界假设）。因此随机博弈的实战程序更依赖浅层搜索+强评估函数，或转向下一节的采样式 MCTS。

## 5.6 MCTS / UCT

### 5.6.1 蒙特卡洛树搜索的四个阶段

当分支因子巨大（如围棋 b≈250）、且难以设计好的评估函数时，用深度受限 α-β 效果很差。蒙特卡洛树搜索(MCTS)换一条路：不穷举、也不靠人写评估函数，而是通过大量随机对弈的统计结果来估计走法好坏。每一轮迭代包含四步：

```
1. 选择(Selection)   从根出发，按某选择策略（如 UCB1）沿已建树下行，
                     直到到达一个尚有未扩展孩子的节点
2. 扩展(Expansion)   为该节点新建一个（或多个）子节点加入树
3. 模拟(Simulation)  从新节点起用快速（常为随机）策略把这局下到终局，
                     得到胜负结果（又称 playout / rollout）
4. 回传(Backprop)    把该结果沿刚走过的路径回填，更新沿途每个节点的
                     访问次数 N 与累计价值/胜数 U
```

反复迭代直到时间用尽，最后在根节点选"访问次数最多"（或平均价值最高）的走法。直觉是"与其精确算一小片树，不如用成千上万次快速试玩去统计哪步赢面大"，胜率高的分支会被越来越多地采样、估计越来越准。它是"随时可停(anytime)"的：迭代越多越准，时间到了就用当前统计结果。

### 5.6.2 UCB1 / UCT 选择公式

选择阶段的核心是平衡"多利用当前看起来好的走法"与"多探索采样还很少、可能被低估的走法"。UCT（把 UCB1 用于树搜索）给树中每个候选子节点 n 打分，取分数最高者下行：

UCB1(n) = U(n)/N(n) + C · sqrt( ln N(PARENT(n)) / N(n) )

其中 U(n) 是经过 n 的模拟累计价值（如胜数）、N(n) 是 n 的访问次数、N(PARENT(n)) 是其父节点访问次数、C 是控制探索强度的常数。

左项 U(n)/N(n) 是该走法目前的平均胜率（利用项）；右项随"父节点被访问很多、但 n 自己访问很少"而变大（探索项）——即一个久未被光顾的走法会逐渐被右项抬高分数，从而获得被再次尝试的机会。C 越大越偏探索、越小越偏利用。关于常数 C：AIMA 指出 C=√2 在理论上有依据（对应奖励取值在 [0,1] 的情形，源自 Kocsis & Szepesvári 2006 的 UCT 原始分析），但实践中博弈程序往往按经验调参、试用不同的 C 值。数值不要凭记忆当成"唯一正确常数"——它是与奖励尺度绑定、且工程上可调的（AIMA 4th ed §5.4 明确此点）。

### 5.6.3 模拟策略与 MCTS 的适用性

模拟阶段的"playout 策略"决定从叶子往下怎么把这局快速下完。最朴素的是纯随机走子；更好的是加入轻量领域知识的"启发式 playout"，让试玩更像真实对弈、统计更有信息量。

MCTS 的两大优势正好补 α-β 的短板：一是不需要人工评估函数（用试玩结果代替），特别适合围棋这种"局面好坏极难用手写特征刻画"的博弈；二是把算力自适应地集中到有希望的分支，而非均匀铺开。它的代价与陷阱是：单条 playout 的结果方差很大，需要海量迭代才收敛；若某个关键但当前统计上看起来平庸的走法采样不足，可能被长期低估（探索项就是为缓解这点）；纯随机 playout 在战术性很强、"一步天堂一步地狱"的博弈里可能严重失真，因此实战常混入领域启发或与评估网络结合。

### 5.6.4 通往 AlphaGo 的桥（纯搜索版定位）

本主题讲的是"纯搜索版"MCTS：选择用 UCB1、模拟用随机或轻启发式、不含任何学习组件。它已足以让围棋程序从远弱于人类跃升到强业余水平，是 2006 年后计算机围棋的分水岭。

把 MCTS 的选择/模拟里的手写策略换成深度神经网络——用一个"策略网络"引导选择该试哪些走法、用一个"价值网络"替代或辅助随机 playout 来评估局面——就得到 AlphaGo 那条"搜索+深度学习"的现代路线，它在 2016 年击败顶尖人类棋手。那套神经网络与搜索深度结合的机制属于深度学习/强化学习课的范畴，本主题只到"纯搜索版 MCTS 是那座桥的搜索侧地基"为止，不展开其学习部分。
