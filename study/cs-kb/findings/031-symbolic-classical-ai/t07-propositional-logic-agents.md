## 7.1 知识库与基于知识的智能体

### 7.1.1 知识库 KB 与句子

知识库（knowledge base，KB）是一组用某种"知识表示语言"写下的**句子**（sentence）的集合，每个句子是对世界某个事实的断言。句子是"公理"意义上的原始断言——不是从别的句子推出来的，而是直接被告知的。

初学者最容易把 KB 当成数据库。区别在于：数据库存的是一条条具体记录，查询只能取回存进去的东西；KB 存的是逻辑句子，查询（ASK）能取回**逻辑上蕴含**的结论——哪怕这个结论从没被显式存进去过。比如 KB 里有"下雨则地湿"和"正在下雨"，即使从没写过"地湿"，ASK 一样能得到"地湿"。这种"从已知推出未明说之事"的能力，是逻辑智能体区别于查表的根本。

### 7.1.2 TELL / ASK 与基于知识智能体的骨架

对 KB 只有两个基本操作：TELL 把新句子加进 KB，ASK 向 KB 提问"某句子是否成立"。ASK 的答案必须遵守一条铁律——只回答"KB 所蕴含"的东西。

一个基于知识的智能体每次感知后，大致按下面骨架运转：

```
function KB-AGENT(percept) returns an action
    TELL(KB, MAKE-PERCEPT-SENTENCE(percept, t))    # 告知本时刻感知
    action ← ASK(KB, MAKE-ACTION-QUERY(t))         # 询问该做什么动作
    TELL(KB, MAKE-ACTION-SENTENCE(action, t))      # 记录已执行动作
    t ← t + 1
    return action
```

这个骨架体现了"知识层"与"实现层"的分离：从外部看，智能体只需要知道它**知道什么**、**目标是什么**，而不必关心 KB 内部用什么算法推理。你可以在不改变智能体行为描述的前提下，把底层推理引擎从真值表换成归结再换成 DPLL。这种"声明式"风格——先告诉系统世界是什么样，再让通用推理去用——正是符号 AI 的招牌，和"写死一套 if-else 规则"的过程式做法相对。

### 7.1.3 Wumpus 世界

Wumpus 世界是 AIMA 用来贯穿全章的玩具环境：一个网格洞穴，某格有会吃人的 Wumpus，某些格是无底坑，某格有金子。智能体看不到全局，只能靠局部感知——与 Wumpus 相邻的格能闻到"臭气（stench）"，与坑相邻的格能感到"微风（breeze）"，金子所在格能看到"闪光（glitter）"。

感知本身不直接告诉你危险在哪，必须**推理**。例如在 (1,1) 没闻到臭气也没感到微风，就能推出相邻的 (1,2) 和 (2,1) 都安全；走到 (2,1) 感到微风，就知道 (2,2) 或 (3,1) 至少有一个坑，但还不能确定是哪个——需要更多感知配合逻辑才能锁定。这个"从不完整局部观测 + 逻辑规则推出隐藏世界结构"的过程，正是命题逻辑推理要解决的问题，比抽象讲蕴含直观得多。

Wumpus 世界是**部分可观测**的，但这里用命题逻辑处理的是"给定已知感知，能确定推出什么"，属于确定性逻辑推理；带概率的不确定推理是后面桥主题（大主题11）的事。

## 7.2 语法·语义·蕴含

### 7.2.1 命题逻辑的语法

命题逻辑的原子是**命题符号**（如 P、Q、W₁,₃），每个符号代表一个非真即假的命题。复杂句子由连接词组合而成，语法可写成：

```
Sentence      → AtomicSentence | ComplexSentence
AtomicSentence → True | False | P | Q | R | ...
ComplexSentence → ( Sentence )
                | ¬Sentence                 (非 negation)
                | Sentence ∧ Sentence        (合取 conjunction)
                | Sentence ∨ Sentence        (析取 disjunction)
                | Sentence ⇒ Sentence        (蕴涵 implication)
                | Sentence ⇔ Sentence        (双条件 biconditional)
```

运算优先级由高到低为 ¬、∧、∨、⇒、⇔，同优先级时用括号消歧。

要分清两层"蕴"字。这里语法层的 ⇒ 是一个**连接词**，叫"蕴涵（implication）"，它和 ∧、∨ 一样只是拼句子的符号；下面 7.2.3 要讲的 ⊨ 是"蕴含（entailment）"，是句子集合之间的**语义关系**，不是连接词。中文两个词发音相近极易混，务必按符号区分：⇒ 在句子内部，⊨ 在句子之间。

### 7.2.2 语义：模型与真值表

语义规定每个句子在每种"世界情形"下的真假。在命题逻辑里，一个**模型（model）**就是给所有相关命题符号各指派一个真值的一种赋值。n 个符号就有 2ⁿ 个可能模型。

给定一个模型 m，任意句子的真值由连接词的真值表递归算出：

```
¬P        为真  当且仅当  P 为假
P ∧ Q     为真  当且仅当  P 为真 且 Q 为真
P ∨ Q     为真  当且仅当  P 为真 或 Q 为真（含两者皆真）
P ⇒ Q     为真  当且仅当  P 为假 或 Q 为真
P ⇔ Q     为真  当且仅当  P、Q 真值相同
```

最反直觉的是 P ⇒ Q：当 P 为假时，无论 Q 真假，整句都为真（叫"空真 vacuously true"）。初学者常觉得"下雨则地湿"在没下雨时应该"无所谓"，但逻辑里它算真。记法：⇒ 只在"前件真而后件假"这一种情况下为假，其余都真。它不表示因果，只表示"不出现前真后假"这种约束。

### 7.2.3 蕴含 entailment

蕴含是整章的核心语义关系。记作：

```
α ⊨ β
```

读作"α 蕴含 β"，其定义是：

```
α ⊨ β  当且仅当  在每一个使 α 为真的模型里，β 也为真
```

换句话说，凡是 α 成立的世界，β 一定也成立；β 的成立"藏在"α 里。这正好对应 KB 与查询的关系——ASK(KB, β) 应当回答"是"，当且仅当 KB ⊨ β。

用模型的集合看最清楚：设 M(α) 是所有使 α 为真的模型的集合，则

```
α ⊨ β  当且仅当  M(α) ⊆ M(β)
```

α 越强（限制越多），M(α) 越小，越容易被包含在别的句子的模型集里，也就越能蕴含更多东西。初学者要防的坑：蕴含是"语义"关系，谈的是所有模型下的真假，与"用什么算法去证"无关；下面归结、链式、DPLL 都是"求蕴含关系是否成立"的不同手段，但蕴含本身的定义只靠模型。

### 7.2.4 有效性、可满足性与蕴含的相互换算（核心易错点）

三个概念必须一次分清。一个句子是**有效的（valid）**，指它在**所有**模型下都为真，也叫重言式/永真式（tautology），例如 P ∨ ¬P。一个句子是**可满足的（satisfiable）**，指它在**至少一个**模型下为真。一个句子是**不可满足的（unsatisfiable）**，指它在**任何**模型下都为假，例如 P ∧ ¬P。

有效 ⟹ 可满足（永真当然至少有一个模型为真）；一个句子有效当且仅当它的否定不可满足。

蕴含可以完全换算成有效性或可满足性，这是后续所有推理算法的桥梁：

```
α ⊨ β   当且仅当   (α ⇒ β) 是有效的            （演绎定理）
α ⊨ β   当且仅当   (α ∧ ¬β) 是不可满足的        （反证 / 归谬）
```

第一条把"判断蕴含"变成"判断永真"，第二条把它变成"判断不可满足"——而判断不可满足正是 SAT 求解器和归结干的事，所以第二条是归结反证和 DPLL 证明蕴含的理论出发点。

把"有效"和"可满足"混为一谈（可满足门槛低得多，几乎所有正常句子都可满足，但很少有效）；以为"α 可满足"就意味着"α 蕴含点什么有用的东西"（可满足只保证有一个模型，蕴含要求所有模型）；忘了第二条换算里必须否定的是**结论 β**，不是 KB。下面用穷举模型的方式把这几条关系当场坐实。

### 7.2.5 真值表模型检验 TT-ENTAILS

判断 KB ⊨ α 最直接的算法就是枚举所有模型：列出全部 2ⁿ 种真值指派，检查"每一个使 KB 为真的模型是否都使 α 为真"。这叫真值表枚举法（AIMA 的 TT-ENTAILS），它是**可靠且完备**的——只要 KB ⊨ α 成立它一定报"是"，不成立一定报"否"。代价是时间随符号数指数增长（O(2ⁿ)），只适合小问题，但作为"蕴含的定义的直接实现"是理解一切的基准。

本机以最小实现坐实了 7.2.4 的三条关系（Py3.11.15）。取 KB = (P ⇒ Q) ∧ P，问它是否蕴含 Q（即经典的肯定前件 modus ponens），并同时验证两条换算：

```
KB=(P⇒Q)&P entails Q: True
(KB⇒Q) valid: True
(KB & ¬Q) satisfiable: False
P∨¬P valid: True
P∧¬P satisfiable: False
```

三行一致：KB 确实蕴含 Q，等价地 (KB⇒Q) 永真、(KB∧¬Q) 不可满足；末两行分别坐实"有效"与"不可满足"的两个课本例子。可靠性（soundness）与完备性（completeness）是评价任何推理算法的两把尺：可靠 = 推出来的都真（只推出被蕴含的），完备 = 该推的都能推出来（所有被蕴含的都推得到）。真值表枚举两者都满足。

### 7.2.6 逻辑等价与标准等价式

两个句子**逻辑等价**（记 α ≡ β），当且仅当它们在所有模型下真值相同；等价地，α ≡ β 当且仅当 α ⊨ β 且 β ⊨ α。一批标准等价式是把句子改写成范式（下一节 CNF）的工具，最常用的几条：

```
(P ⇒ Q) ≡ (¬P ∨ Q)                     消去蕴涵
(P ⇔ Q) ≡ (P ⇒ Q) ∧ (Q ⇒ P)           消去双条件
¬(P ∧ Q) ≡ (¬P ∨ ¬Q)                   德摩根律
¬(P ∨ Q) ≡ (¬P ∧ ¬Q)                   德摩根律
P ∧ (Q ∨ R) ≡ (P ∧ Q) ∨ (P ∧ R)       分配律
```

这里要分清 ≡ 和 ⇔：⇔ 是写在句子里的连接词，≡ 是关于两个句子的元级断言"它们永远同真假"。二者有联系——α ≡ β 成立当且仅当句子 (α ⇔ β) 有效——但 ≡ 本身不是命题逻辑语言的一部分，而是我们谈论句子时用的记号。

## 7.3 CNF 与归结

### 7.3.1 CNF 子句形

合取范式（conjunctive normal form，CNF）是把句子写成"子句的合取"，其中每个**子句（clause）**是若干**文字（literal）**的析取，文字是命题符号或其否定。形如：

```
(A ∨ ¬B) ∧ (¬A ∨ C ∨ D) ∧ (B ∨ ¬C)
```

**任何命题逻辑句子都能等价转换成 CNF**。转换套路固定——先用等价式消去 ⇔ 和 ⇒，再用德摩根律把 ¬ 内推到只作用于符号，最后用分配律把 ∨ 分配进 ∧。

CNF 之所以重要，是因为归结、DPLL 这些高效推理机都只吃 CNF 输入。子句还有个方便的读法：子句 (¬A ∨ ¬B ∨ C) 等价于蕴涵 (A ∧ B) ⇒ C，即"前提都成立就得出结论"，这把 CNF 和规则形式接了起来。初学者易踩的坑：分配律那步可能让子句数量膨胀（最坏指数级），所以实际系统常用引入新变量的 Tseitin 转换来保持规模线性——但那样得到的是**可满足性等价**而非**逻辑等价**，够 SAT 用但不保证同真假集，两者不要混用。

### 7.3.2 归结规则

归结（resolution）是只有一条推理规则的推理系统。对两个子句，若一个含文字 ℓ、另一个含其否定 ¬ℓ，就可以把两子句其余部分并起来得到一个新子句（叫"消解式 resolvent"），把这对互补文字消掉：

```
       (A ∨ B ∨ ℓ)      (C ∨ D ∨ ¬ℓ)
      ─────────────────────────────────
             (A ∨ B ∨ C ∨ D)
```

最小情形：由 (P ∨ Q) 和 (¬P ∨ R) 消去 P，得 (Q ∨ R)。归结是**可靠**的——消解式确实被两个母子句蕴含。要注意每次只能消一对互补文字；若两子句里有多对互补文字，一次只能消一对，否则会得到永真的无用子句。得到的新子句里要去掉重复文字（factoring）。

### 7.3.3 归结反证与完备性

归结单靠自己**不能**推出所有被蕴含的句子（它不是那种意义上的完备），但它是**反证完备的（refutation-complete）**：如果一组 CNF 子句是不可满足的，反复应用归结规则**一定能推出空子句**（记作 □，代表矛盾）。这正好接上 7.2.4 的第二条换算——要证 KB ⊨ α，就把 α 否定加进 KB，全转成 CNF，然后反复归结：

```
证明 KB ⊨ α 的归结反证流程：
  1. 构造子句集 = CNF(KB) ∪ CNF(¬α)
  2. 反复对含互补文字的子句对做归结，把新消解式加入集合
  3. 若推出空子句 □  ⟹ 子句集不可满足 ⟹ KB ⊨ α（证毕）
  4. 若再无新消解式可加且未出现 □ ⟹ KB ⊭ α
```

支撑它的是**基（ground）归结定理**：命题逻辑上，只用归结的反证系统是可靠且完备的——不可满足的子句集必能归结出空子句。这是命题逻辑一个可判定的、完全机械的证明方法，也是自动定理证明的历史起点。

以为"归结完备"意味着能把 KB 蕴含的每个句子逐一生成出来。不是。归结的完备性是**针对反证**的——它保证"检测不可满足"这件事完备，所以任何蕴含问题都能通过"否定结论再找矛盾"来解决，但它不擅长直接枚举结论。本机 7.5 节的 DPLL 实证里，(P∨Q)∧(¬P∨R)∧(¬Q∨R)∧¬R 被判为不可满足，正是这类"加否定结论后出矛盾"的场景：它对应证明 (P∨Q)∧(¬P∨R)∧(¬Q∨R) ⊨ R。

## 7.4 前向链与后向链（Horn 子句上的高效推理）

### 7.4.1 Horn 子句与定子句

一般命题推理（含完整归结、SAT）在最坏情况下是难解的，但把句子限制成一类特殊形式就能换来高效算法。**Horn 子句**是**至多含一个正文字**的子句；其中恰含一个正文字的叫**定子句（definite clause）**。定子句能改写成"前提合取 ⇒ 单个结论"的规则形式：

```
子句形： (¬A ∨ ¬B ∨ C)
规则形： (A ∧ B) ⇒ C
事实：   单个正文字 C，即 True ⇒ C
```

限制的代价是表达力：Horn 形式无法表达"P 或 Q 成立"这种带析取结论的不确定知识（那需要多个正文字），也难直接表达否定结论。换来的好处是：Horn 子句集上的蕴含判定有**线性时间**算法，且推理过程能对人解释成一串"因为…所以…"，这正是 Prolog 和早期专家系统、以及 Datalog 的基础。

### 7.4.2 前向链 forward chaining

前向链是数据驱动的：从 KB 里已知为真的事实出发，不断触发"前提已全部满足"的规则，把规则结论加入已知集，直到目标出现或无新结论可加。

```
function PL-FC-ENTAILS?(KB, q) returns true or false   （KB 为定子句集）
  count[c] ← 每条规则 c 的前提个数
  inferred[s] ← false（所有符号）
  agenda ← KB 中所有为真的事实符号
  while agenda 非空:
    p ← agenda 取出一个
    if p = q then return true
    if inferred[p] = false:
      inferred[p] ← true
      for 每条前提含 p 的规则 c:
        count[c] ← count[c] − 1
        if count[c] = 0 then 把 c 的结论加入 agenda
  return false
```

每条规则维护一个"还差几个前提"的计数器，某前提变真就把相关规则计数减一，减到零规则就"点火"。因为每个符号最多被处理一次、每条规则最多点火一次，总工作量与 KB 大小成正比。

### 7.4.3 后向链 backward chaining

后向链是目标驱动的：从要证的查询 q 倒着走，找结论为 q 的规则，把该规则的前提当成新的子目标，递归去证，直到子目标都落到已知事实上。

两者判定的蕴含关系完全相同，区别在探索方向和代价。前向链会推出所有可推的事实，适合"事实进来就更新一切结论"的场景，但可能算出大量与当前问题无关的结论。后向链只碰与查询相关的事实，通常只触及 KB 的一小部分，适合有明确问题时按需求证；代价是可能重复求同一子目标，且朴素实现遇到规则环会无限递归，需要记忆化或环检测。

### 7.4.4 完备性与线性时间

在定子句 KB 上，前向链和后向链都是**可靠且完备**的：一个符号被 KB 蕴含，当且仅当前向链能把它标记出来。而且前向链判定 KB ⊨ q 的时间与 KB 的规模成**线性**关系。

要精确理解这个"线性"：它是关于 **Horn/定子句 KB** 的结论，不是命题推理的普遍复杂度。一般命题可满足性（SAT）是 NP 完全的；正是"至多一个正文字"这条限制砍掉了组合爆炸，才换来线性时间。所以初学者不要把"逻辑推理是线性的"当成普遍真理——它只在 Horn 这类受限片段上成立，跨过这条线（允许一般子句）就回到 SAT 的难解世界，那正是下一节 DPLL 要对付的一般情形。

## 7.5 DPLL 与 SAT

### 7.5.1 命题可满足性 SAT

SAT 问题问的是：给定一个 CNF 句子，是否存在一个模型使它为真？由 7.2.4 的第二条换算，"KB ⊨ α"等价于"KB ∧ ¬α 不可满足"，所以一切命题蕴含判定都能归约成 SAT。SAT 是历史上第一个被证明为 **NP 完全**的问题（Cook–Levin 定理）：一般 CNF 上没有已知的多项式算法，最坏情况指数级；但实际中的结构化实例往往能被现代求解器高效解决。

### 7.5.2 DPLL 骨架

DPLL（Davis–Putnam–Logemann–Loveland）是一个**完备的、带回溯的**深度优先搜索算法，直接判定 CNF 的可满足性。它本质是"给变量逐个试真/假 + 回溯"的模型枚举，但靠两条剪枝规则和早停，避免真的枚举全部 2ⁿ 个模型。

```
function DPLL(clauses, assignment) returns true/false
  按 assignment 化简 clauses
  if 出现空子句 then return false              # 某子句全为假 → 此路不通
  if 所有子句都被满足 then return true         # 早停：无需给剩余变量赋值
  单元传播（unit propagation）：反复对只剩一个未赋值文字的子句，
      强制该文字为真，并回代化简
  纯文字消去（pure literal）：某变量在剩余子句中只以单一极性出现，
      就按该极性赋值使相关子句全真
  选一个未赋值变量 v
  return DPLL(clauses, assignment ∪ {v=true})
      or DPLL(clauses, assignment ∪ {v=false})
```

### 7.5.3 三个关键机制：早停、单元传播、纯文字

三条机制是 DPLL 相对朴素真值表枚举的全部提速来源。

早停（early termination）：一个子句只要有一个文字已为真，整句就满足，无需再管它的其余文字；反过来一个子句所有文字都为假就立刻剪枝回溯。这让 DPLL 常常在给完所有变量之前就能判定。

单元传播（unit propagation）：若某子句化简后只剩一个未赋值文字，那这个文字**必须**取真该子句才可能满足，于是强制赋值，再回代——这一步常引发连锁，一个赋值逼出一串赋值。这是 DPLL 效率的主要来源，也是现代 CDCL 求解器的核心。

纯文字（pure literal）：若某变量在当前剩余子句里只以一种极性出现（只出现 P，或只出现 ¬P），把它按该极性赋值只会让子句更容易满足、绝不会帮倒忙，于是可直接赋值。

本机以最小 DPLL 实现坐实（Py3.11.15）：

```
DPLL sat of (P∨Q)&(¬P∨R)&(¬Q∨R)&¬R:  False   （不可满足）
DPLL sat of (P∨Q)&(¬P∨R)&(¬Q∨R):      True    （可满足）
```

第一行把 ¬R 加进去后变不可满足，恰好对应证明 (P∨Q)∧(¬P∨R)∧(¬Q∨R) ⊨ R——这就是"否定结论、查不可满足"的蕴含判定套路的当场演示，与 7.3.3 归结反证判同一实例矛盾一致，两条独立路径（归结 vs DPLL）给出相同结论，互为交叉验证。

### 7.5.4 局部搜索求 SAT：WalkSAT

DPLL 是完备的（能确定判定可满足或不可满足）。另一类 SAT 方法是**局部搜索**，代表是 WalkSAT：从一个随机完整赋值出发，反复挑一个不满足的子句，以一定概率随机翻转其中一个变量、否则贪心翻转能满足最多子句的变量，如此迭代。

WalkSAT 常能极快找到大型可满足实例的解，但它**不完备**——找不到解时无法区分"确实不可满足"还是"只是没搜到"，所以它不能用来证明不可满足性（即不能用来证明蕴含成立需要的那半边）。用途分工要记清：要判定或证明"不可满足/蕴含成立"，用 DPLL 这类完备方法；只想在可满足实例里快速捞一个解，才用 WalkSAT 这类局部搜索。这与大主题4"局部搜索只求好解、不保完备"的取舍是同一套哲学。

### 7.5.5 与形式验证 SAT/SMT 的邻接

命题 SAT 求解不只是逻辑课的玩具：硬件电路等价性检查、软件模型检验、规划编码等大量实际问题都被编码成 SAT 交给求解器，而在 SAT 之上加算术、数组、位向量等理论就得到 SMT——这些是形式验证课（L6-02）的主线，此处只作邻接登记，不展开。
