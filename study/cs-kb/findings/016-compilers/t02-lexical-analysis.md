本报告有一条贯穿的心智模型，**词法分析器是编译器最前端的一台有限状态机：它从左到右扫描源程序的字符流，按预先写好的正则规约把字符切成一个个记号（token），顺手丢掉空白与注释，并给后面的语法分析器喂一串干净的记号序列。** 它之所以能用「有限状态机」这么朴素的模型实现，是因为程序设计语言的词法（标识符、数字、运算符长什么样）恰好都能用正则语言描述——而正则语言正好对应有限自动机。于是整章的技术骨架就是一条自动化流水线，**正则表达式（人写的规约）→ NFA（Thompson 机械构造）→ DFA（子集构造）→ 最小化 DFA（压状态）→ 加上「最长匹配 + 规则优先」的运行策略 = 一台扫描器**，Lex/flex 这类词法生成器把这条流水线整个封装起来，让你只写正则规约就自动得到扫描器。下面五节顺着这条链走一遍。

## C2.1 记号、词素、模式与输入缓冲

### C2.1.1 记号(token)、词素(lexeme)、模式(pattern)：三个必须分清的术语

龙书 §3.1 给出词法分析的三个核心术语。**记号（token）**是一个「记号名 + 可选属性值」的对，记号名是语法分析器认得的抽象符号（如 `id`、`num`、`if`、`+`），代表一类词法单位。**词素（lexeme）**是源程序里实际出现的、匹配某个记号模式的那一串字符（如具体的 `position`、`60`、`if`）。**模式（pattern）**是对「某个记号的词素长什么样」的描述，通常用正则表达式写（如 `id` 的模式是「字母开头的字母数字串」）。三者关系是：模式描述一类词素，扫描器在输入里找到一个匹配某模式的词素，就产出对应的记号。

初学者最容易把这三个词当同义词，务必用一个例子钉死区别。看输入片段

E = M * C ** 2

扫描器读到字符串 `E`，它是一个**词素**；这个词素匹配「标识符」这个**模式**；于是扫描器产出记号 `<id, 指向 E 的符号表条目>`——这里 `id` 是**记号名**。同理 `M`、`C` 也都是词素，都产出 `id` 记号，但属性值不同（分别指向各自的符号表条目）。而 `=`、`*`、`**` 各自匹配运算符模式，产出各自的记号。一个关键直觉：**记号名是「词类」，词素是「具体的词」，模式是「这类词的拼写规则」**——就像英语里 "名词" 是词类、"dog" 是具体的词、"名词的构成规则" 是模式。语法分析器只关心记号名（词类），完全不看词素本身长什么样，这正是词法分析把「字符层面的琐碎」挡在语法分析之外的意义。

### C2.1.2 记号的属性值与符号表

当多个词素能匹配同一个模式时，光有记号名不够，扫描器还要附带一个**属性值（attribute）**告诉后续阶段「具体是哪一个」。对标识符记号 `id`，属性值通常是一个指向**符号表（symbol table）**条目的指针，该条目保存这个名字的拼写、类型、位置等信息。对常量记号 `num`，属性值可以是它的数值。像 `if`、`+` 这类每个记号名只对应唯一词素的记号，通常不需要属性值。

初学者要理解「为什么标识符的属性值是符号表指针，而不是直接存名字字符串」。因为同一个标识符会在程序里出现很多次（声明一次、使用多次），编译器需要把这些出现关联到同一个实体上去查类型、查作用域——把它们都指向同一个符号表条目，就天然做到了这种关联，而且避免重复存储名字。举个最小例子，源程序中两次出现的 `count` 会产出两个 `id` 记号，但它们的属性值指向**同一个**符号表条目。要注意的是，词法阶段往往只是把名字**装进**符号表并给出指针，「这个名字在当前作用域是否声明过、类型是什么」这类判断是语义分析（C5）的事——词法器不做作用域解析，它只负责识别「这是一个标识符」并登记。

### C2.1.3 输入缓冲：双缓冲区(buffer pairs)与哨兵(sentinel)

词法器要逐字符扫描源程序，而磁盘 I/O 一次读一个字符代价太高，所以龙书 §3.2 介绍**双缓冲区**方案：开两个大小均为 N 的缓冲区（N 常取一个磁盘块大小），一次系统调用填满一个缓冲区。扫描时用两个指针，`lexemeBegin` 指向当前词素的开头，`forward` 向前扫描找词素的末尾；`forward` 走到一个缓冲区末尾时就触发装载另一个缓冲区，两个缓冲区交替使用，于是长词素跨缓冲区也不会丢。

朴素实现里，`forward` 每前进一步都要判断两件事：是否到了缓冲区末尾（要不要装载下一块）、是否到了输入结尾。**哨兵（sentinel）**技巧把这两个判断合并成一个。做法是在每个缓冲区的末尾多留一个位置，放一个绝不会在真实源程序中出现的特殊字符（龙书用 `eof`）。这样 `forward` 每步只需先测「当前字符是不是 eof」，绝大多数情况下不是，一次比较就过；只有真读到 eof 时，才进一步分辨「是缓冲区末尾的哨兵（该装载下一块）还是真正的输入结尾」。

给初学者的直觉是「用一个不可能的字符当路障」：没有哨兵时，每读一个字符都要问「越界了吗？」，这是每字符两次判断；有了哨兵，平时只问「是路障吗？」一次判断，只有极少数撞上路障时才做那套完整的越界处理。收益是把常态下每字符的比较次数减半。一个易错点：哨兵字符必须选源语言里绝不合法出现的字符，否则会把真实字符误判为缓冲区边界。需要说明的是，双缓冲+哨兵是一种经典的性价比优化，现代生成器（如 flex）内部缓冲机制更复杂，但核心权衡——用一个特殊标记减少边界判断——是相通的。

### C2.1.4 行号/列号跟踪与错误定位

词法器扫描时会顺手维护当前**行号（和有时列号）**：每读到一个换行符就把行号加一。这个信息本身不进记号的语法含义，但它被挂在记号上或记录在一旁，供后续所有阶段在报错时说清「错误在第几行」。词法器是全流水线里唯一还能看到源文本原始物理布局（空白、换行）的阶段，所以行号跟踪的责任天然落在它身上。

初学者可以这样理解它的必要性：语法分析器面对的是一串抽象记号，早就没有了「换行」的概念（换行和空白在词法阶段就被当作分隔符丢掉了）；如果不在词法阶段把行号记下来传下去，等语法或语义阶段发现错误时，就没法告诉用户错在哪一行了。这就是为什么再简单的词法器也要数行号。一个常见易错点是「行号在丢弃空白时忘了更新」——空白和注释虽然不产出记号，但其中的换行符仍必须计入行号，否则后续报错的行号会全部偏移。

## C2.2 正则表达式描述词法

### C2.2.1 串、语言与语言上的运算

要用正则表达式描述词法，先要有「语言」的代数。龙书 §3.3 约定：给定字母表 Σ（符号的有限集合），一个**串（string）**是 Σ 中符号的有限序列，空串记

ε

一个**语言（language）**是串的集合。语言上定义三种基本运算：**并（union）** L ∪ M、**连接（concatenation）** LM（L 中每个串接上 M 中每个串）、以及**克林闭包（Kleene closure）**

L* = L⁰ ∪ L¹ ∪ L² ∪ …

其中 L⁰ = {ε}，Lⁱ 是 L 自身连接 i 次。此外常用**正闭包** L⁺ = L L*（至少一次）。

初学者要抓住三个运算各自的含义。并是「或」——`a|b` 表示的语言是 {a, b}，即「a 或 b」。连接是「接着」——`ab` 表示 {ab}，即「先 a 后 b」。闭包是「重复零次或多次」——`a*` 表示 {ε, a, aa, aaa, …}，注意**包含空串**（重复零次）。最容易错的正是「星号含空串」：`a*` 能匹配「什么都没有」，而 `a⁺` 至少要有一个 a。一个具体例子，若 L={a,b}，则 L* 就是所有由 a、b 组成的串（含空串），也就是二元字母表上的全部串——这解释了为什么 `(a|b)*` 常被用来表示「任意 a/b 串」。

### C2.2.2 正则表达式(RE)与正则定义

**正则表达式（regular expression, RE）**是对语言的一种代数记法，它在 ε、单个符号 a 这两个基础上，用并 `|`、连接、闭包 `*` 递归地构造。每个 RE r 记法上对应一个语言 L(r)。运算优先级从高到低是：`*`（闭包）> 连接 > `|`（并），且 `*` 右结合、连接与并左结合，可用括号改变结合。例如

letter (letter | digit)*

表示「一个字母，后面跟零个或多个（字母或数字）」——正是多数语言标识符的模式。

写实际语言的词法时，模式往往层层依赖，于是引入**正则定义（regular definition）**：给一串命名的正则表达式，后面的可以引用前面已定义的名字。龙书的经典例子（C 风格标识符）是

letter → A | B | … | Z | a | b | … | z | \_

digit  → 0 | 1 | … | 9

id     → letter ( letter | digit )*

初学者要理解正则定义只是「宏展开」式的便利：`id` 里用到的 `letter`、`digit` 都可以就地替换回它们的定义，最终 `id` 仍是一个纯正则表达式，没有增加表达能力。关键约束是**引用必须是「向前」的**——`id` 可以用它上面定义的 `letter`，但定义里不能循环引用自己（不能递归），否则就超出了正则语言的能力（递归属于上下文无关文法，是 C3 的事）。一个易错点：初学者常想用正则表达式匹配「配对的括号」，但那需要计数、是非正则的，词法器做不到，必须留给语法分析。

### C2.2.3 正则表达式的扩展记法(便利缩写)

实用的词法规约还用一批**扩展记法**，它们不增加表达能力，只是缩写：`r⁺` 表示「一次或多次」（= r r*）；`r?` 表示「零次或一次」（= r | ε）；字符类 `[abc]` 表示 `a|b|c`，范围 `[a-z]` 表示 a 到 z 的并。于是标识符可简写为

[A-Za-z\_][A-Za-z0-9\_]*

无符号数（整数或带小数、指数）可写成类似

digit⁺ ( . digit⁺ )? ( E [+-]? digit⁺ )?

这些缩写让规约紧凑可读。给初学者的提醒：这些扩展**都能机械地展回基本 RE**（`r?` 变 `r|ε`，`[a-z]` 变一长串 `|`），所以后面的 Thompson 构造只需处理 `|`、连接、`*` 三种基本算子，`+`、`?`、`[...]` 先展开即可。一个易错点是把编程语言里 PCRE/Perl 正则的高级特性（反向引用 `\1`、前后查找 assertion）当成「正则表达式」——那些是真正超出正则语言能力的扩展，编译原理里说的「正则表达式」严格对应正则语言，不含这些。

### C2.2.4 词法规约与规则优先级

一个完整的**词法规约**是一组「模式 → 动作」的规则，覆盖该语言所有记号类别（关键字、标识符、数字、运算符、分隔符、空白/注释等）。多条模式可能同时匹配同一段输入（例如 `if` 既匹配关键字 `if` 的模式、又匹配标识符 `id` 的模式），于是规约必须定义**消歧规则**。最常用的两条来自 Lex 传统，将在 C2.5 展开：先取**最长**的匹配；若多条规则匹配同样长，取**在规约中列在最前**的那条。因此关键字规则通常写在标识符规则之前，让 `if` 被识别为关键字而非普通标识符。

初学者要建立的直觉是「词法规约不是一堆孤立的正则表达式，而是一个有序、有消歧策略的整体」。同一个输入位置常有多种切法，规约靠「最长匹配 + 规则顺序」把歧义定死，保证扫描器行为确定。一个最小例子：输入 `ifx`，若只看模式，`if`（关键字）和 `ifx`（标识符）都在此处有匹配起点，但按最长匹配，`ifx` 作为标识符是更长的词素，胜出——所以 `ifx` 不会被误当成关键字 `if` 后跟 `x`。这条「规则顺序 + 最长匹配」是词法规约区别于「单个正则匹配」的核心，C2.5 会用本机实证展示：不遵守它（例如 Python `re` 的有序择一）就会得到不同结果。

## C2.3 从正则表达式到 NFA：Thompson 构造

### C2.3.1 NFA、ε-NFA 与 DFA 的区别(承 L3-05，只用不证)

**有限自动机（finite automaton）**是识别正则语言的机器：一组状态、一个开始状态、一组接受状态、以及在（状态, 输入符号）上的转移。**确定性有限自动机（DFA）**每个（状态, 符号）至多一个后继、且无 ε 转移，运行时每读一个字符路径唯一，跑得快。**非确定性有限自动机（NFA）**允许一个（状态, 符号）有多个后继、并允许**ε 转移**（不读输入就换状态），一个串被接受当且仅当**存在**一条到达接受态的路径。二者识别的语言类完全相同（都是正则语言），这是 L3-05 的结论，本篇只用。

初学者要抓住「NFA 好造、DFA 好跑」这对权衡。NFA 允许「同时试探多条路」和「凭空跳转（ε）」，所以从正则表达式机械地拼出来非常容易（下节）；但正因为要试探多条路，直接运行 NFA 慢。DFA 没有分叉和 ε，运行时一条道走到黑、每字符 O(1)，快；但直接为复杂 RE 手造 DFA 很难。词法生成器的策略正是「用 NFA 接住 RE 的易构造性、再转成 DFA 拿运行速度」——C2.3 造 NFA、C2.4 转 DFA。一个易错点：NFA 的「非确定」不是「随机」，而是「存在一条成功路径即接受」，实现上等价于并行地维护「当前可能所处的状态集合」。

### C2.3.2 Thompson 构造：由 RE 机械拼出 ε-NFA

龙书 §3.7 给出 **Thompson 构造（McNaughton–Yamada–Thompson construction）**：按正则表达式的结构递归地拼装 ε-NFA，每个子表达式造出一个「恰好一个开始态、恰好一个接受态」的小 NFA，再按算子把它们粘起来。基本规则如下（每条都新建状态、用 ε 边连接）：

```
ε        新开始态 --ε--> 新接受态
a        新开始态 --a--> 新接受态
s | t    新开始态 --ε--> N(s)开始态、N(t)开始态；两个子块的接受态 --ε--> 新接受态
s t      N(s)接受态 与 N(t)开始态 合并（或 --ε-- 相连）；N(s)开始态为总开始态、N(t)接受态为总接受态
s *      新开始态 --ε--> N(s)开始态、且 --ε--> 新接受态（重复零次）；
         N(s)接受态 --ε--> N(s)开始态（再来一次）、且 --ε--> 新接受态
```

初学者理解 Thompson 构造的钥匙是「每块积木都有唯一入口和唯一出口」，于是像搭乐高一样：`|` 是「开个岔口两条都试」、连接是「首尾相接」、`*` 是「加一条回头路和一条绕过路」。ε 边就是「免费的跳线」，用来把这些积木粘在一起而不消费输入。举个最小例子，`a*` 的 NFA 是：新开始态 s，新接受态 f；s→(ε)→接受，s→(ε)→a 子块，a 子块→(ε)→回到 a 子块入口、也→(ε)→f。这样零个 a（走 s→f 那条 ε）和任意多个 a 都能被接受。一个常见易错点是漏掉「绕过边」（s 直达 f），导致 `a*` 无法匹配空串。

### C2.3.3 构造的规模与关键性质

Thompson 构造出的 NFA 有几条整齐的性质（龙书 §3.7）：恰好一个开始态、恰好一个接受态；接受态没有出边；除接受态外每个状态要么有一条标符号的出边、要么至多两条 ε 出边。规模上，**N(r) 的状态数至多是 r 中算子与运算对象个数的两倍**——即状态数与正则表达式长度成**线性**关系。

对初学者，这条线性规模保证很重要：它说明「把 RE 变 NFA」这一步既简单又便宜，不会爆炸。这也解释了整条流水线为什么先走 NFA——RE→NFA 是线性、安全的，真正可能规模膨胀的是下一步 NFA→DFA（最坏指数，见 C2.4.4 的说明）。「接受态无出边、每态出边受限」这些性质不是摆设，它们让后续的子集构造和模拟都有规整的结构可依赖。一个易错点：Thompson 构造刻意**多用 ε 边、多造状态**（换来构造规则的整齐划一），所以造出来的 NFA 往往「臃肿」，有很多只起连接作用的状态——这不要紧，C2.4 的子集构造和最小化会把冗余压掉。

## C2.4 NFA→DFA 与 DFA 最小化

### C2.4.1 子集构造(subset construction)：ε-closure 与 move

把 NFA 转成等价 DFA 的标准算法是**子集构造（subset construction，亦称幂集构造）**，龙书 §3.7。核心想法：**DFA 的一个状态 = NFA 在读了某段输入后「可能同时所处的 NFA 状态集合」**。需要两个辅助运算。**ε-闭包（ε-closure）** 把一个 NFA 状态集合扩成「从中出发只走 ε 边能到达的所有状态」：

ε-closure(T) = T 加上所有从 T 中状态经任意条 ε 边可达的状态

**move(T, a)** 是「从 T 中某状态出发、读一个符号 a 能直接到达的状态集合」：

move(T, a) = { s' | 存在 s ∈ T，有一条标 a 的边 s → s' }

DFA 的开始状态是 ε-closure(NFA 开始态)；对每个已生成的 DFA 状态 T 和每个输入符号 a，其后继是

T --a--> ε-closure(move(T, a))

把每个新出现的状态集合登记为一个 DFA 状态，直到不再产生新集合；凡含 NFA 接受态的集合就是 DFA 的接受态。

初学者理解子集构造的关键是「用集合并行模拟非确定性」：NFA 读一个字符后「可能在若干状态之一」，我们干脆把「这一堆可能的状态」打包成 DFA 的单个状态，于是不确定性就被「一次性算清所有可能」消化掉了，DFA 因此变确定。ε-closure 的作用是「把免费跳线能到的地方一并算进来」——因为 ε 边不消费输入，所以只要能通过 ε 到达，就属于「当前可能所处」的一员。一个易错点：每次算后继都必须**先 move 再取 ε-closure**（读完符号后还要把新的免费跳转补上），漏掉最后的 ε-closure 会算错后继集合。

### C2.4.2 子集构造实例：(a|b)*abb（本机实证）

用本机手写的 Thompson NFA + 子集构造跑龙书经典例子 `(a|b)*abb`（NFA 状态编号 0–10，10 为接受态；Python 3.11.15 @2026-07-25，脚本仅用于取证、未入库），得到的 DFA 状态（每个是一个 NFA 状态集合）与转移如下，与龙书 Fig 3.35 完全一致：

```
A = {0,1,2,4,7}
B = {1,2,3,4,6,7,8}
C = {1,2,4,5,6,7}
D = {1,2,4,5,6,7,9}
E = {1,2,4,5,6,7,10}   (接受态)

转移表：
        a    b
  A ->  B    C
  B ->  B    D
  C ->  B    C
  D ->  B    E
  E ->  B    C
```

初学者可以顺着读一遍验证直觉。开始态 A = ε-closure({0}) = {0,1,2,4,7}，因为从 NFA 开始态 0 经一串 ε 边能同时到达 1、2、4、7 这些「准备读 a 或 b」的状态。读一个 a 后到 B（含 8，表示「刚匹配到 abb 的第一个 a」），读 b 后到 C。注意只有读到 `...abb` 结尾时才进入含 10 的 E（接受）。这个例子也直观展示了「一个 DFA 状态对应一堆 NFA 状态」——A 一个状态就打包了 NFA 的 5 个状态。一个易错点初学者常犯：以为 DFA 状态数一定比 NFA 少。这里 11 个 NFA 状态压成 5 个 DFA 状态确实变少了，但那是巧合；下节说明最坏情况 DFA 反而可能指数级变多。

### C2.4.3 运行方式：DFA 直接跑 vs 就地模拟 NFA(时空权衡)

有了 DFA 就可以直接拿它扫描输入：从开始态出发，每读一个字符按转移表走一步，走到接受态即匹配成功，每字符 O(1)、与 RE 大小无关，运行最快，代价是可能要预先构造并存储一个大 DFA。另一种选择是**不真正构造 DFA、而是就地模拟 NFA**（龙书 §3.7）：始终维护「当前 NFA 状态集合」，每读一字符做一次 move + ε-closure。这样省去了 DFA 的构造与存储，但每字符的代价是 O(状态数)。

给初学者的对照是一张时空权衡表的两端：DFA 走「用空间换时间」——先把所有可能都算成静态转移表，跑时飞快；NFA 模拟走「用时间换空间」——不预构造，跑时现算，省内存但慢。词法生成器（Lex/flex）默认选前者（构造 DFA），因为词法规约的 RE 通常不大、DFA 也不会爆，换来扫描时的高速；而像某些通用正则引擎在模式可能巨大时会选后者或混合策略。理解这个权衡，就懂了为什么「同样识别正则语言」会有两条实现路线。

### C2.4.4 DFA 最小化：等价类划分与 Hopcroft 算法

子集构造出的 DFA 可能有多余状态（两个状态若对**任何**后续输入串都给出相同的接受/拒绝结果，就是等价的、可合并）。**DFA 最小化**把等价状态合并，得到状态数最少的等价 DFA。龙书 §3.9 给出基于**等价类划分（partition refinement）**的算法：初始把状态分成「接受态」和「非接受态」两组；反复检查每组内的状态——若组内两状态在某个输入符号上转移到了**不同的组**，就把该组按这种区别继续细分；直到没有组再能被细分，每个最终组合并成最小 DFA 的一个状态。**Hopcroft 算法（1971）**是这一思路的高效实现，时间复杂度

O(n log n)

其中 n 为状态数（龙书正文给出的划分算法为较朴素版本，Hopcroft 是其经典加速）。

初学者理解最小化的钥匙是「可区分性」：两个状态「不同」的唯一理由，是存在某个后续输入能把它们区分开（一个最终接受、另一个拒绝）。算法反过来做——一开始只知道「接受态和非接受态肯定不同」，然后不断问「组里还有谁其实能被某个字符区分开吗」，能就拆组，直到无可拆分，剩下的每组内部就是真正不可区分、可以合并的。举例上节 `(a|b)*abb` 的 5 状态 DFA 已是最小的（无可合并）。两点要点给初学者：其一，**最小 DFA 在同构意义下唯一**（Myhill–Nerode 定理保证，属 L3-05），所以「最小化」结果是良定义的、与算法无关；其二，最坏情况下**子集构造可能产生指数级（2ⁿ 量级）的 DFA 状态**，最小化能缓解但不改变最坏界——这是 NFA→DFA 这一步唯一可能规模爆炸的地方，也是为什么有时宁可就地模拟 NFA（C2.4.3）。

## C2.5 最长匹配与词法生成器

### C2.5.1 最长匹配(maximal munch / longest match)

真实源程序是连续字符流，扫描器在每个位置都可能面对「切多长」的选择。**最长匹配（maximal munch，也叫 longest match）**规则规定：在当前位置，扫描器应匹配**能匹配的最长词素**。例如面对 `<=`，应识别成一个记号 `<=`，而不是先切出 `<` 再切 `=`；面对 `count1`，应整体识别为标识符，而不是标识符 `count` 后跟数字 `1`。

实现上，最长匹配靠「DFA 一直往前走、记住最近一次经过的接受态」完成：扫描器让 DFA 从当前位置持续读字符，每当踩到一个接受态就记下「到此为止是一个合法词素、位置在哪」，继续往前试；直到 DFA 走进「死状态」（再没有合法转移）为止，然后**回退**到最近记住的那个接受位置，把这一段作为词素输出。给初学者的直觉是「贪心地尽量多吃，吃到咽不下去为止，再吐回到上一个能咽下的点」——这正是 maximal munch（「最大咀嚼」）名字的由来。一个经典易错/歧义点：某些语言里最长匹配会带来反直觉结果，如 C++ 早期 `a<b<c>>` 中的 `>>` 会被最长匹配成右移运算符而非两个模板闭合尖括号（后由标准特案处理）——这说明最长匹配虽是默认策略，但语言设计者有时要为它打补丁。

### C2.5.2 规则冲突：关键字 vs 标识符、规则顺序优先

即便定死了「最长」，仍可能有**多条规则匹配同样长**的情况——最典型的是关键字与标识符：`if` 既完全匹配关键字规则 `if`、又完全匹配标识符规则 `[A-Za-z_][A-Za-z0-9_]*`，两者长度相同。Lex 传统的第二条消歧规则是：**同样长时，取规约中列在最前的规则**。于是把关键字规则写在标识符规则**之前**，`if` 就被判为关键字。另一种常见工程做法是：只用一条标识符规则，识别出词素后再去一张「关键字表」里查，命中就改成对应关键字记号。

初学者要把这两条消歧规则记成一对：**先比长度（最长匹配），长度相同再比规则顺序（靠前优先）**。它们共同保证「同一段输入的切法唯一确定」。用 C2.2.4 的例子收束：`ifx` 按最长匹配整体是标识符（比 `if` 长），根本轮不到比规则顺序；而 `if`（后面接的是空格/非字母）长度上关键字和标识符打平，这时规则顺序让关键字胜出。一个易错点：如果错误地把标识符规则写在关键字前面，所有关键字都会被吞成普通标识符——顺序在这里是语义相关的，不是随便排的。

### C2.5.3 Lex / flex 内部原理

**Lex**（及其广泛使用的开源实现 **flex**）是**词法分析器生成器**：输入一个 `.l` 规约文件（一组「正则模式 → C 动作」规则），输出一段 C 源码（`yylex()` 函数），编译后就是扫描器。它内部把本大主题的流水线整个自动化：把每条模式用 Thompson 构造成 NFA、给所有模式加一个公共新开始态用 ε 边并起来（于是一台 NFA 同时认所有记号）、子集构造成 DFA、再最小化；运行时用这台 DFA 按最长匹配扫描，并用「记住最近接受态 + 该接受态对应哪条规则」实现「最长 + 规则靠前」两条消歧，匹配到就执行那条规则的动作。

初学者理解 Lex 的钥匙是「你只写正则规约，RE→NFA→DFA→最小化→最长匹配运行这一整套它替你做」——这正是把 C2.2–C2.5 学的东西打包成一个工具。要点是**所有模式共用一台 DFA**：不是每条规则各跑一遍，而是合并成一台自动机一次扫过，接受态携带「命中的是哪条规则」的信息。规范与实现要分账：flex 在细节上做了不少工程优化（如按等价字符类压缩转移表、直接构造 DFA 等），这些是实现层面的加速，语义上仍遵循「最长匹配 + 规则顺序」的 Lex 传统。需要如实标注：本机 flex 未安装（`which flex` 无结果 @2026-07-25），故未跑 flex 产物实证；flex 内部原理依据龙书 §3.5/§3.8 与官方文档，实机验证未取。

### C2.5.4 实证：Python `re` 的有序择一不是最长匹配

一个能直接跑、且对初学者极有校准价值的对照：Python 标准库 `re` 的**交替（alternation）不是最长匹配，而是「有序、最左优先」**——排在前面的分支先匹配成功就采纳，不比较长度。本机实证（Python 3.11.15 @2026-07-25），把关键字 `if`、标识符 `[a-z]+`、数字 `[0-9]+` 按此顺序拼成一个大正则，逐位置 `match` 扫描 `ifx if 123`：

```
输入: "ifx if 123"
输出: [('IF','if'), ('ID','x'), ('IF','if'), ('NUM','123')]
```

注意 `ifx` 被切成了 `if` + `x` 两个记号——因为 `if` 分支排在前面、在位置 0 先匹配成功（2 个字符），`re` 就采纳它、不去比较「`[a-z]+` 能匹配到更长的 `ifx`」。这与真正的词法器行为相反：按最长匹配，`ifx` 应整体是一个标识符。

给初学者的教训有两层。其一，**「正则库」不等于「词法器」**：多数编程语言的正则引擎（Python `re`、PCRE 等）采用回溯式、分支有序优先的语义，而经典词法器/Lex 用 DFA + 最长匹配，二者在交替与切分上行为可能不同，别拿 `re` 的行为当词法语义的标准。其二，要在 Python 里模拟词法器的最长匹配，通常得靠额外手段（如用 POSIX 最长匹配的引擎、或对每个位置尝试所有规则取最长），不能指望 `|` 直接给出最长。这条实证正好反向印证 C2.5.1–C2.5.2：最长匹配是词法器**特意选定**的策略，不是「正则」这个词自带的默认。
