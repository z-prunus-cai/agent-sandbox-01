## 1.1 Fibonacci 堆

### 1.1.1 是什么与操作代价总览

Fibonacci 堆是一种可合并（mergeable）优先队列，由 Fredman 与 Tarjan 于 1987 年提出，其价值全在**摊还代价**上：它让若干"更新型"操作达到 O(1) 摊还，只有真正需要取出元素时才付 O(log n)。在最小堆语义下，各操作的摊还代价为

INSERT = O(1)

MINIMUM（取最小，不删）= O(1)

UNION（合并两个堆）= O(1)

DECREASE-KEY（减小某个键）= O(1) 摊还

EXTRACT-MIN（取出并删除最小）= O(log n) 摊还

DELETE（删除任意节点）= O(log n) 摊还

初学者要抓住两点。第一，这里的 O(1) 是**摊还**而不是最坏情形——单次 DECREASE-KEY 偶尔会引发一连串"级联剪切"而变慢，但把整段操作序列平均下来，每次仍是常数。第二，这张表的关键卖点是 DECREASE-KEY 的 O(1)：二叉堆里减键要 O(log n) 的上浮，而 Dijkstra/Prim 里减键的次数与边数 E 同阶，把它压到 O(1) 正是后面提速图算法的全部动力。

### 1.1.2 结构组成

一个 Fibonacci 堆是一片**满足最小堆序的有根树的森林**（每个节点的键不小于其父节点的键），这些树的根用一个**环形双向链表**（根链表）串起来，堆对象只额外保存一个指向全局最小键节点的指针 min，以及节点总数 n（CLRS Fibonacci 堆章，Fredman–Tarjan §2）。每个节点存有它的度 degree（孩子个数）、指向任一孩子的指针、以及一个**标记位 mark**。

之所以叫"Fibonacci"堆而不必维持二项堆那种严整结构，关键就在于它**允许根链表里有任意多棵、任意形状的小树并存**，只在 EXTRACT-MIN 时才把同度数的树两两合并整理。这就是"惰性"思想：INSERT 只是往根链表塞一棵单节点树、顺手更新 min 指针，UNION 只是把两个根链表首尾拼接——都不做任何整理，所以是 O(1)。标记位 mark 记录的是"这个节点自从上次成为别人的孩子以来，是否已经失去过一个孩子"，它是 DECREASE-KEY 级联剪切的触发器，作用见 1.1.6。初学者易错点：根链表里的"树"没有排好序，min 指针只保证指向全局最小，其余节点的相对位置是乱的，所以 Fibonacci 堆不支持高效的"查找任意键"。

### 1.1.3 势函数与摊还分析框架

Fibonacci 堆的所有摊还界都由同一个势函数导出（CLRS Fibonacci 堆章；Fredman–Tarjan §1）

Φ(H) = t(H) + 2·m(H)

其中 t(H) 是根链表中树的棵数，m(H) 是被标记（mark = true）的节点个数。某操作的摊还代价 = 实际代价 + ΔΦ。

理解这个势函数要盯住"谁在攒信用、谁在花信用"。INSERT 把一棵新树加入根链表，t 增加 1，Φ 涨 1，于是它的 O(1) 实际代价加上这份势涨仍是 O(1)——相当于每次插入都**预存了一点信用**，留给将来 EXTRACT-MIN 里合并这棵树时花。EXTRACT-MIN 会把一大堆根合并掉，t 骤降，释放出的势正好抵掉合并的实际代价，于是昂贵的合并被"报销"成 O(log n)。系数 2 是为 DECREASE-KEY 的级联剪切准备的：每次剪切既产生一棵新树（t +1）又可能清掉一个标记（m −1），2·m 这一项刚好为每次剪切预付了两份信用，保证级联无论多长，净摊还仍是 O(1)。初学者不必会重推这套记账（属先修 L3-01 #09），但要理解"势函数就是把未来要还的债提前记在账上"。

### 1.1.4 INSERT、MINIMUM、UNION 的 O(1)

这三个操作都不触碰树的内部结构，因此实际代价就是常数，摊还代价也是 O(1)。INSERT 新建一棵单节点树挂到根链表、并在新键更小时更新 min；MINIMUM 直接返回 min 指针所指，什么都不改；UNION 把两个堆的根链表拼接、min 取两者较小者（Fredman–Tarjan §2；CLRS Fibonacci 堆章）。

关键直觉是"能拖就拖"。二项堆的 INSERT 要立刻维持结构不变式，可能引发 O(log n) 的进位式合并；Fibonacci 堆干脆不维持这种不变式，把整理全部推迟到 EXTRACT-MIN。UNION 之所以也是 O(1)，正因为根链表是环形双向链表，两个环拼成一个只需改常数条指针。初学者易错点：不要以为"O(1) 插入"意味着堆内部一直很整齐——恰恰相反，插入越多，根链表越长越乱，直到某次 EXTRACT-MIN 才被一次性收拾干净。

### 1.1.5 EXTRACT-MIN 与 consolidate 的 O(log n)

EXTRACT-MIN 是唯一做"重活"的取出型操作。它先把 min 节点的所有孩子提升为根（并入根链表），删掉 min 节点，然后调用 **consolidate**：反复把根链表中**度数相同**的两棵树合并（较大键的根成为较小键根的孩子），直到每个度数至多一棵树为止，最后扫描剩下的根重新定位 min（CLRS Fibonacci 堆章；Fredman–Tarjan §2）。其摊还代价为

EXTRACT-MIN = O(D(n)) = O(log n)

其中 D(n) 是堆中任一节点的最大度数，1.1.7 会证明 D(n) ≤ log_φ n。

理解 consolidate 要借助"用一个下标为度数的数组做归并"的画面：开一个大小约 D(n)+1 的数组 A，A[d] 存"目前见到的度为 d 的树"，遍历根链表时若发现某度 d 已被占用，就把两棵度-d 树合并成一棵度-(d+1) 的树，继续进位——这与二进制加法的进位完全同构。合并后每个度数唯一，所以最终根链表长度 ≤ D(n)+1 = O(log n)。为什么昂贵却仍摊还 O(log n)？因为合并使 t(H) 大幅下降，势函数 Φ 释放出的信用（由此前大量 O(1) 的 INSERT 预存）正好报销掉合并的实际代价，只剩下与最终根数同阶的 O(log n) 净额。初学者易错点：consolidate 里的 D(n) 是"最大度数"而非"树的棵数"；棵数在合并前可能很大（等于此前的插入数量），正是这份"乱账"被势函数一次性结清。

### 1.1.6 DECREASE-KEY 与级联剪切

DECREASE-KEY(x, k) 把节点 x 的键减到 k。若 x 仍不小于其父节点，堆序未破，直接改值即可；否则把 x 连同其子树从父节点**剪切**下来、整棵挂到根链表并清除其 mark。剪切后要检查父节点 y：若 y 未被标记，则标记它；若 y 已被标记，说明 y 这是第二次失去孩子，于是把 y 也剪下来挂到根链表，并对 y 的父节点递归执行同样的检查——这就是**级联剪切**（cascading cut）（CLRS Fibonacci 堆章；Fredman–Tarjan §3）。其摊还代价为

DECREASE-KEY = O(1) 摊还

尽管单次级联剪切可能连续剪掉一长串节点。

理解级联剪切的意义在于"限制树的畸形程度"。如果允许一个节点无限次失去孩子而不受惩罚，树可能退化得又瘦又高，破坏 1.1.7 的度数界。规则"每个非根节点最多失去一个孩子，第二次就被连根拔起"保证了任何度为 k 的节点，其子树规模不会因剪切而缩水太多——这正是 F₍ₖ₊₂₎ 下界成立的前提。摊还上为何仍是 O(1)：势函数里的 2·m(H) 为每个标记预存了两份信用，级联链上每剪掉一个已标记节点就释放两份，一份付剪切的实际代价、一份补偿新增那棵树带来的 t +1，于是无论链多长，净摊还都塌缩为常数。初学者易错点：mark 只对**非根**节点有意义，节点一旦被剪成根就清除标记；根节点永远不标记。

### 1.1.7 最大度界 D(n) ≤ log_φ n 与"Fibonacci"之名

Fibonacci 堆的所有对数界都依赖一条结构定理：n 个节点的堆中，任一节点的度数

D(n) ≤ ⌊log_φ n⌋

其中 φ = (1+√5)/2 ≈ 1.618 是黄金比。证明的核心引理是：一个度为 k 的节点，其子树至少含 F₍ₖ₊₂₎ 个节点，而斐波那契数满足 F₍ₖ₊₂₎ ≥ φᵏ（CLRS Fibonacci 堆章的度数引理；Fredman–Tarjan §1）。

名字"Fibonacci"正来自这里：级联剪切规则（每个节点第二次失孩即被剪）恰好让"度为 k 的节点最少子树规模"这一数列满足斐波那契递推，从而子树规模随度数指数增长，反过来把度数压到对数级。直觉上，度数越大意味着底下藏着越多节点（至少 φ 的度数次方个），而总共只有 n 个节点，所以度数不可能超过 log_φ n。这也是为什么 consolidate 用的度数数组只需 O(log n) 大。本机对该引理不等式做了数值核验（Python 3.11.15 @2026-07-30，标准库）

```
k= 0  F_(k+2)=    1  phi^k=   1.0000  OK
k= 5  F_(k+2)=   13  phi^k=  11.0902  OK
k=10  F_(k+2)=  144  phi^k= 122.9919  OK
k=14  F_(k+2)=  987  phi^k= 842.9988  OK
all hold: True
```

对 k = 0..14 逐一确认 F₍ₖ₊₂₎ ≥ φᵏ 成立。初学者易错点：φ ≈ 1.618，故 log_φ n ≈ 1.44·log₂ n，比二叉堆的 log₂ n 略大常数倍——Fibonacci 堆的优势不在这个对数常数上，而在把 DECREASE-KEY 从 O(log n) 降到 O(1)。

### 1.1.8 加速 Dijkstra 与 Prim 到 O(E + V log V)

Fibonacci 堆最著名的应用是把稠密图上的单源最短路（Dijkstra）与最小生成树（Prim）从二叉堆版的 O(E log V) 提速到

O(E + V log V)

其中 V、E 分别是顶点数与边数（Fredman–Tarjan 原论文的标题即为此，故成立性高度可靠；CLRS 第 22/21 章的 Dijkstra/Prim 分析）。

推导只需数清两类堆操作的次数。两个算法都恰好对每个顶点做一次 EXTRACT-MIN（共 V 次，每次 O(log V) 摊还 → V log V），并在每次松弛边时对邻接顶点做一次 DECREASE-KEY（共至多 E 次，每次 O(1) 摊还 → E）。二叉堆里 DECREASE-KEY 要 O(log V)，于是被 E log V 主导；换成 Fibonacci 堆，减键这项塌缩成 O(E)，总量变为 O(E + V log V)。对稠密图（E ≈ V²）这是 O(V²) 对 O(V² log V) 的实质改进。初学者易错点：这只是**理论**渐进最优，实际中 Fibonacci 堆常数因子大、指针开销高、缓存不友好，工程实现往往仍用二叉堆或配对堆——但作为"摊还换更优图界"的样板，它是本大主题的核心范例。

## 1.2 Splay 树

### 1.2.1 是什么：自调整二叉搜索树

Splay 树是 Sleator 与 Tarjan 于 1985 年提出的一种**自调整**二叉搜索树：它不存任何平衡信息（无颜色、无高度、无平衡因子），而是在**每次访问**（查找、插入、删除）之后，通过一串旋转把被访问的节点一路"伸展"（splay）到根，靠这个动作在长程上自动保持近似平衡（Sleator–Tarjan 1985 §1–2）。它的界是纯摊还的

单次操作 = O(log n) 摊还

最坏单次操作仍可能是 O(n)（例如访问一条退化链的底端）。

理解 Splay 树的关键心智模型是"最近访问的东西会被搬到最容易再拿的地方"。它不追求任何时刻树都平衡，而是赌"访问有局部性"：刚访问过的节点很可能马上再被访问，把它转到根就让下次访问变快。因此它天然适配带访问局部性的负载（如缓存、LRU 场景）。初学者易错点：Splay 树的 O(log n) 是摊还而非最坏——单次访问可能很慢，但任意 m 次操作的总时间是 O(m log n)，不能拿它做实时系统里对单次延迟有硬上界的场合。

### 1.2.2 伸展操作：zig / zig-zig / zig-zag

把节点 x 伸展到根，是反复施加三种情形之一，直到 x 成为根（Sleator–Tarjan 1985 §2）。设 x 的父为 p、祖父为 g。

在 zig 情形（p 是根、x 无祖父）下，对 x 做一次单旋转，x 取代 p 成为根。

在 zig-zig 情形（x 与 p 同侧，即都是左孩子或都是右孩子）下，先旋转 p（上层）、再旋转 x，为两次同向旋转。

在 zig-zag 情形（x 与 p 异侧）下，先旋转 x、再旋转 x，为两次反向旋转（等价于对 x 做一次双旋转）。

关键、也是最容易被初学者写错的一点：zig-zig 情形**必须先转父节点 p、再转 x**，而不是像 AVL 那样连转两次 x。正是这个"先转 p"的顺序，让伸展在把 x 提到根的同时，把 x 原来所在的那条长路径"对折"变短（路径上节点的深度大致减半），从而产生自平衡效果；若改成朴素的"每次都单旋 x 到根"（move-to-root），则得不到 O(log n) 摊还界。zig 只在最后一步、x 距根仅一层时用到。直觉上，zig-zig 与 zig-zag 每处理一步就把一段路径长度砍半，这是摊还分析能出对数界的结构根源。

### 1.2.3 splay 之上的基本操作

有了"把任意节点伸展到根"这一原语，BST 的各操作都用它组合实现（Sleator–Tarjan 1985 §2）。查找 x：按 BST 规则下行找到 x（或其应在位置的前驱/后继），然后把该节点 splay 到根。插入 x：正常 BST 插入后把新节点 splay 到根。JOIN(A, B)（A 中所有键 < B）：把 A 的最大节点 splay 到 A 的根，它没有右孩子，直接把 B 挂上去。SPLIT(x)：把 x splay 到根后砍断，即得两棵子树。删除 x：把 x splay 到根，删去它，再 JOIN 左右两棵子树。

理解要点是"所有操作都以 splay 收尾"——正是这个统一动作让摊还分析可以只分析 splay 一件事。为什么每次都要 splay，哪怕只是查找？因为摊还信用是靠 splay 重构树形来"结算"的：不 splay 就攒不下把树揉平的信用，退化链会一直退化。初学者易错点：查找一个**不存在**的键时，也要把查找终止处的最后一个节点 splay 到根，否则针对同一段不存在键的重复查找会持续 O(n)。

### 1.2.4 势函数、访问引理与摊还 O(log n)

Splay 树的摊还界由如下势函数导出：给每个节点 x 赋权重 1，令 s(x) 为以 x 为根的子树的节点数，秩 r(x) = log₂ s(x)，势函数为（Sleator–Tarjan 1985 §2 的"access lemma"）

Φ = Σ_x r(x)

核心结论是一条**访问引理**——把节点 x 从根为 t 的树中伸展到根，其摊还代价至多

3(r(t) − r(x)) + 1 = 3·log₂(s(t)/s(x)) + 1 = O(log n)

由此每个基本操作都是 O(log n) 摊还。

访问引理的直觉在于，r(x) 大致是"x 子树的高度预算"，把小节点（s(x) 小、秩低）转到根位置，会大幅抬高它的秩、同时压低沿途大节点的秩，势的净变化被证明能盖住旋转的实际次数，只留下与 log(s(t)/s(x)) 同阶的余项。三种伸展情形里，zig-zig 与 zig-zag 每步都让势下降足够多，把"这一步做了两次旋转"的实际代价吸收掉——这再次说明 1.2.2 那个"先转 p"的顺序为何不可替换。本机用一个简易 Splay 树统计了随机访问的平均触达深度（Python 3.11.15 @2026-07-30，标准库）

```
n=   100  m=20000  avg touched depth/access =   3.58   log2 n =  6.64
n=  1000  m=20000  avg touched depth/access =   5.94   log2 n =  9.97
n= 10000  m=20000  avg touched depth/access =   8.36   log2 n = 13.29
```

平均触达深度随 n 呈对数增长（且落在 log₂ n 之内），与 O(log n) 摊还相符。这只是经验性佐证，不替代对访问引理的文本比对。初学者易错点：势函数用的是"子树节点数的对数"，与树的实际高度不是一回事；Splay 树可能一时很高，但势函数保证长程平均代价仍是对数。

### 1.2.5 静态最优性与相关定理

Splay 树最深刻的性质是它能**自动逼近为已知访问分布量身定制的最优静态树**，无需事先知道该分布。设一段有 m 次访问，元素 i 被访问 q_i ≥ 1 次，则 Splay 树处理整段序列的总时间为（Sleator–Tarjan 1985 §5，静态最优性定理）

O(m + Σ_i q_i · log₂(m/q_i))

而括号里的和式正是"最优静态 BST"总代价的下界量级（与信息熵同阶），故 Splay 树在常数因子内匹配最优静态树。此外还有静态指针定理、工作集定理等一族"竞争性"结论，说明它对局部性访问自适应地高效。

超越静态的**动态最优猜想**（dynamic optimality conjecture）由同一篇论文提出：Splay 树对**任意**访问序列的总代价，都在**离线最优 BST 算法**（可预知整段序列、可任意重构树）的常数倍以内。截至核实日期（2026-07-30）该猜想**仍未解决**；目前最好的在线 BST 是 Tango 树等，仅证到 O(log log n)-竞争（Demaine 等 2004），常数-竞争仍开放。

静态最优性的直觉在于，常被访问的元素会被反复 splay 到根附近，于是"热"元素浅、"冷"元素深，这自发形成的形状就接近按频率优化的最优静态树——而 Splay 树完全不看频率统计，纯靠"访问即上浮"就做到了。初学者易错点：静态最优是"与最优静态树比"（树形固定后不再变），已被证明；动态最优是"与能随时重构的最优算法比"，是更强的开放猜想，两者别混。这条主线也解释了为何 Splay 树能当 link-cut 树的零件（见 1.3）。

## 1.3 动态树（link-cut tree）

### 1.3.1 是什么：维护有根森林与路径操作

Link-cut 树（动态树）是 Sleator 与 Tarjan 于 1983 年提出的数据结构，用来维护一片**不断被加边/删边的有根树森林**，并支持沿"根到某节点"路径的聚合查询与更新，每个操作 O(log n) 摊还（Sleator–Tarjan 1983；O(log n) 摊还的 splay 实现见 1985 self-adjusting 论文）。典型操作集合包括：FIND-ROOT(v) 返回 v 所在树的根；LINK(v, w) 把树根 v 接到另一棵树的节点 w 之下（合并两棵树）；CUT(v) 切断 v 与其父的边（把一棵树分成两棵）；path-aggregate 对 v 到其树根路径上的边或点做聚合（如求最小、求和）与更新（如整条路径加常数）；可选的 EVERT(v) 把 v 变成其所在树的新根。

理解动态树要对比"静态树 vs 动态森林"。普通并查集能维护连通性但不支持删边、也不支持路径上的加权聚合；线段树/树链剖分能做路径查询但树结构一旦变化就得重建。Link-cut 树填的正是这个空档：**结构会变、还要沿路径快速聚合**。初学者易错点：它维护的是"根到节点"的路径，不是任意两点间路径——任意两点路径要先 EVERT 换根或做 LCA，再拼接，别默认它天生支持任意 u–v 路径。

### 1.3.2 实现：偏好路径分解 + Splay 树

Link-cut 树的标准实现把每棵真实树分解成若干条不相交的**偏好路径**（preferred path），每条偏好路径用一棵**Splay 树**按深度为序来维护（这正是 1.2 的 Splay 树作零件），路径之间用"path-parent"指针相连（Sleator–Tarjan 1983/1985；MIT 6.854 Lec 7–8）。核心原语是 ACCESS(v)：把从 v 到其真实树根的整条路径变成同一条偏好路径，并把 v splay 到这棵 Splay 树的根。其余操作都建立在 ACCESS 之上，摊还代价

每个操作 = O(log n) 摊还

理解要点是把它看成"两层树"——外层是真实的森林结构，内层是每条偏好路径的 Splay 平衡树；沿路径的聚合就变成在 Splay 树上的子树聚合。为什么能 O(log n) 摊还？因为 ACCESS 每次改变的偏好边数量，可用一个类似 Splay 势函数的记账证明其摊还为对数级（这里用到"重路径/轻边"变化次数的对数界论证）。初学者易错点：单次 ACCESS 可能改动很多条偏好路径、看起来很贵，但和 Fibonacci 堆一样，这是摊还——大量廉价 ACCESS 为偶尔昂贵的那次预付了信用。这也解释了为什么 1.2 的 Splay 树是本大主题的"公共零件"，而不仅是独立话题。

### 1.3.3 加速最大流：Dinic + 动态树

Link-cut 树最经典的应用是给 Dinic（Dinitz）最大流算法提速。朴素 Dinic 在一般图上是 O(V²E)：它分 O(V) 个阶段，每阶段在分层图上用 DFS 找**阻塞流**（blocking flow），单阶段 O(VE)。用动态树维护"当前增广路径"的剩余容量，可把单阶段阻塞流降到 O(E log V)，于是总时间（Sleator–Tarjan 1983；MIT 6.854 Lec 7–8）

O(VE log V)

即用摊还结构把网络流的界又推进一档。

提速点在于，阻塞流阶段里算法反复沿一条路径推流、并删掉饱和边，朴素做法每推一次要 O(V) 走一遍路径；用 link-cut 树把"当前路径"整条维护起来，"找路径上剩余容量最小的边""沿整条路径减去该流量""删掉饱和边（cut）"都变成 O(log V) 的路径操作，一个阶段里这类操作总数是 O(E)，故单阶段 O(E log V)。初学者易错点：这里 O(VE log V) 是把动态树套进 **Dinic** 的结果，别和 push-relabel 族的界（下游大主题02）混为一谈；同样，动态树的收益是渐进的，工程实现常数大，实际最大流常用 push-relabel 或 ISAP 等。这一节与 1.1.8 遥相呼应，共同构成本大主题"用摊还结构换更优图算法界"的两大样板。
