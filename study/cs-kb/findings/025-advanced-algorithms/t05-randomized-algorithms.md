## 5.1 Las Vegas 与 Monte Carlo

### 5.1.1 随机化算法与两类误差模型

随机化算法是在执行中可以"抛硬币"（读取随机比特）的算法，其运行时间或输出因此成为随机变量。按"随机性影响的是正确性还是时间"，Motwani–Raghavan 把随机化算法分成两大类：**Las Vegas 算法**永远输出正确答案，只有运行时间是随机的；**Monte Carlo 算法**运行时间有确定上界，但输出以某个可控的小概率出错（Motwani–Raghavan §1.2；Mitzenmacher–Upfal Ch1）。

初学者可以用一句话记住区别：Las Vegas 是"结果一定对，快慢看运气"，Monte Carlo 是"跑多久说得准，对不对看运气"。随机快排是典型的 Las Vegas——无论怎么抛硬币选主元，排出来的序列一定有序，只是期望时间 O(n log n)、最坏仍可能 O(n²)。Karger 最小割（5.2）则是典型的 Monte Carlo——它固定跑完就停，但可能返回一个不是最小的割。为什么要引入随机？因为它能把"最坏情形输入"的敌意化解掉：对确定性算法，敌手可以专门构造让你变慢或出错的输入；引入随机后，敌手无法预知你的硬币，坏输入的坏运气被摊到所有硬币结果上。

### 5.1.2 Las Vegas 算法

Las Vegas 算法的正确性是确定的（对任意输入、任意随机比特都给出正确答案），衡量它的指标是**期望运行时间**（有时也看运行时间的高概率上界）。一个 Las Vegas 算法可以看成"不断尝试直到成功、每次尝试都验证结果"的过程，因此它天然带一个"知道自己何时做对了"的自检环节。

理解要点在于"期望"二字。期望时间 O(f(n)) 不排除偶尔一次运行远超 f(n)，只保证长程平均在 f(n) 量级。一个最小的例子是"随机选一个满足条件的元素"：反复均匀随机取样并检验，若合格元素占比 p，则期望取样次数为 1/p 次（几何分布的期望）

E[尝试次数] = 1/p

初学者易错点：Las Vegas 算法必须能**验证**自己这次是否成功，否则无法决定要不要重试；这也是它与 Monte Carlo 的分水岭——Monte Carlo 往往无法在多项式时间内验证自己是否答对（否则就能转成 Las Vegas，见 5.1.5）。

### 5.1.3 Monte Carlo 算法与单侧/双侧误差

Monte Carlo 算法在固定（通常多项式）时间内停机，但输出可能错，错误概率有明确上界。按错误发生的方式再分两种：**单侧误差**（one-sided error）只在一个方向上会错，另一个方向的回答绝对可信；**双侧误差**（two-sided error）两个方向都可能错（Motwani–Raghavan §1.2、§1.5；Mitzenmacher–Upfal Ch1）。

单侧误差最好理解的例子是判定型算法：若它回答"是"必定为真，只有回答"否"时才可能漏判（对应复杂度类 RP），那么一旦某次回答"是"就可以放心相信。Freivalds 验矩阵乘（5.3.2）正是单侧的——它若报"不相等"必定不相等，只有对不相等的实例可能误报"相等"。双侧误差则两边都可能翻车，只保证正确概率严格大于 1/2（对应类 BPP）。

理解误差方向为何重要：它决定了"如何靠重复把错误压小"。单侧误差只需重复到"任一次给出可信方向的回答"即可（错误概率随重复次数指数下降），双侧误差则要靠**多数投票**并用 Chernoff 界（5.4.4）证明多数正确的概率高。初学者易错点：Monte Carlo 的"错误概率 ≤ 1/2"里的 1/2 不是魔法阈值——只要严格小于 1/2 且有常数间隔，就能通过重复放大到任意小；关键是这个间隔是常数（BPP 的定义），而不是随 n 消失。

### 5.1.4 概率放大：用独立重复压低错误

Monte Carlo 算法最重要的性质是错误概率可以**指数级放大**（amplify）压低：独立重复运行多次并按误差类型汇总，就能把错误概率降到任意小，代价只是运行时间线性倍增。

对单侧误差算法（设错误概率 ≤ p < 1，且只在"否"方向出错），独立重复 k 次、只要有一次给出可信的"是"就输出"是"，则 k 次全错的概率为

Pr[k 次全错] ≤ p^k

取 k = O(log(1/δ)) 即可把总错误压到 δ。对双侧误差算法（正确概率 ≥ 1/2 + ε），独立重复 k 次取**多数**，由 Chernoff 界（5.4.4）多数出错的概率随 k 指数衰减

Pr[多数错] ≤ e^(−2ε²k)

故 k = O(ε⁻² log(1/δ)) 次即可。

直觉上，一次出错像抛到一枚坏运气的硬币，独立重复就是让坏运气连续发生，其概率是各次相乘而指数消失。初学者易错点：放大**必须用独立的随机比特**重复，对**同一份**随机比特重复毫无意义（会得到完全相同的错误答案）；此外放大针对的是"每个固定输入"的错误概率，而不是对随机输入求平均。

### 5.1.5 两类的相互转化与复杂度类

Las Vegas 与 Monte Carlo 之间有清晰的转化关系，对应一族随机复杂度类（Motwani–Raghavan §1.5；Mitzenmacher–Upfal Ch1）。Las Vegas 转 Monte Carlo 总是可行：把 Las Vegas 算法运行到某个时间上限就强行停机、超时则乱猜一个答案，得到有界时间、小概率出错的 Monte Carlo 算法（超时概率由 Markov 不等式 5.4.2 控制）。反方向 Monte Carlo 转 Las Vegas 需要一个额外条件——答案**可高效验证**：反复跑 Monte Carlo 直到验证通过为止，就得到永远正确、期望时间有界的 Las Vegas 算法。

对应的判定问题复杂度类是：**RP**（单侧误差、"是"可信）、**co-RP**（单侧误差、"否"可信）、**ZPP**（零错误、期望多项式时间，即 Las Vegas 的判定版）、**BPP**（双侧误差、正确概率有常数间隔）。它们满足

ZPP = RP ∩ co-RP

RP ⊆ BPP，co-RP ⊆ BPP

理解这条等式：一个问题既能在"是"方向可信又能在"否"方向可信，就能反复跑到某一侧给出确定回答，从而零错误——这正是 ZPP（Las Vegas）。初学者易错点：这些是**判定问题**的类，刻画的是"能否用随机在多项式时间内以受控错误判定"；P ⊆ ZPP ⊆ RP ⊆ BPP 是已知的包含链，而 BPP 与 NP 的关系、以及 P = BPP 是否成立（去随机化猜想）截至核实日期（2026-07-30）仍是开放问题，不要误当已证。

## 5.2 Karger 最小割

### 5.2.1 最小割问题与随机边收缩

给定一个无向连通图 G=(V,E)，**全局最小割**是把顶点集划成两个非空部分、使跨越两部分的边数最少的那个划分（这里研究无权/单位权的边数最小割）。Karger 1993 年提出的**随机收缩算法**（contraction algorithm）出奇简单：反复**均匀随机地选一条边并把它的两个端点合并（收缩）成一个超级点**（合并时保留重边、删去自环），直到只剩 2 个超级点为止；此时这 2 个超级点各自代表的原始顶点集合，连同它们之间剩下的边，就是算法输出的割（Karger 1993；Motwani–Raghavan §1.1、§10.2）。

收缩一条边 (u,v) 的含义是"赌 u 和 v 落在最小割的同一侧"。为什么这个荒唐简单的过程能work？因为最小割的边数很少，随机抽一条边正好抽中割边（从而把最小割的两侧错误地并到一起）的概率就很低；只要一路上从没抽中任何一条割边，最后剩下的 2 个超级点划分恰好就是那个最小割。初学者易错点：这是**Monte Carlo** 算法——它每次都在固定步数内停机（收缩 n−2 次），但返回的割可能不是最小的；单跑一次远不可靠，价值全在下一节的成功概率与重复放大。另一个易错点：收缩要保留重边（用带权/多重边表示），否则概率分析不成立。

### 5.2.2 单次成功概率下界

设图有 n 个顶点，固定某个特定的最小割，其割边数为 k。随机收缩算法**单次运行**返回这个特定最小割的概率有下界（Karger 1993；Motwani–Raghavan 定理 §1.1/§10.2）

Pr[单次找到该最小割] ≥ 2 / (n(n−1)) = 1 / C(n,2)

即至少约 2/n²。

推导只用到一个反复出现的不等式。若最小割大小为 k，则图中每个顶点的度至少为 k（否则孤立那个低度点就得到更小的割），于是边数至少 nk/2。第 i 步收缩时图还剩 n−i+1 个点，此步抽中某条固定割边的概率至多 k / ((n−i+1)k/2) = 2/(n−i+1)，故"这一步不毁掉最小割"的概率至少 1 − 2/(n−i+1)。全程 n−2 步都不毁掉的概率是这些的连乘，望远镜式相消后正好得到 2/(n(n−1))。理解直觉：n 大时单次成功概率只有 ~2/n²，看起来极低，但它是**多项式**倒数而非指数倒数，所以下一节用多项式次重复就能救回来。初学者易错点：这个界是"找到某个**特定**最小割"的概率下界，不是"找到最小割值"的概率——两者的关系与最小割数目上界一起在 5.2.3 说清。

本机在一个"两个 4-团用 2 条桥边相连、最小割 = 2"的 8 点图上做了核验（Python 3.11.15 + numpy 2.4.6 @2026-07-30）

```
Karger: n=8, mincut=2, empirical P(find mincut)=0.2133, lower bound 2/(n(n-1))=0.0357
```

经验单次成功率 0.2133 确实不低于理论下界 0.0357（下界是最坏保证，具体图上可更高），与定理相符。

### 5.2.3 重复放大与最小割数目上界

单次成功概率虽低但为多项式倒数，故独立重复足够多次、取所有运行中最小的那个割即可高概率成功。独立重复

T = C(n,2) · ln n = (n(n−1)/2) · ln n 次

后，"每次都失败"的概率为

Pr[T 次全失败] ≤ (1 − 1/C(n,2))^T ≤ e^(−ln n) = 1/n

即高概率找到最小割（Karger 1993；Motwani–Raghavan §1.1）。这里用到 (1−x) ≤ e^(−x) 这个放大分析里的常用不等式（与 5.1.4 的独立重复思想一致）。

这条分析还顺带给出一个漂亮的**组合推论**：图中不同的最小割至多有

C(n,2) = n(n−1)/2 个

因为每个特定最小割被单次运行返回的概率 ≥ 1/C(n,2)，而不同最小割被返回是互斥事件，概率之和 ≤ 1，故最小割个数 ≤ C(n,2)。这是一个纯组合事实，却由随机算法的分析"免费"证出，是随机化方法威力的经典展示。

本机核验了重复放大（同上 8 点图，T=59）

```
Karger repeat T=59: empirical failure rate=0.0000, bound 1/n=0.1250
```

2000 次重复实验中失败率为 0，远低于理论上界 1/n = 0.125，与放大界相符。初学者易错点：T 次重复的总时间是单次的 T 倍；朴素单次收缩用邻接矩阵实现约 O(n²)，故朴素重复版总时间约 O(n²·n² log n) = O(n⁴ log n)，这正是 5.2.4 的 Karger–Stein 要改进的地方。

### 5.2.4 Karger–Stein 递归改进

朴素重复的浪费在于：收缩早期（点还多时）抽中割边的概率很低，几乎不会出错，真正危险的是收缩到只剩很少点的后期；却对每一次完整运行都从头重跑早期的"安全"阶段。Karger 与 Stein 1996 年的**递归收缩算法**据此改进：把图收缩到约 n/√2 个顶点（此阶段保住一个固定最小割的概率 ≥ 1/2），然后在收缩后的图上**递归地跑两次**、取较好者（Karger–Stein 1996；Motwani–Raghavan §10.3）。其时间满足递推

T(n) = 2·T(n/√2) + O(n²) = O(n² log n)

单次递归运行找到最小割的成功概率满足

P(n) = Ω(1 / log n)

于是再独立重复 Θ(log² n) 次即可把失败概率压到高概率（如 1/n），总时间

O(n² log³ n)

这比朴素版 O(n⁴ log n) 大幅改进，成为很长一段时间内全局最小割的最优随机算法之一。

理解收缩到 n/√2 的选择：这个比例恰好让"此段不毁掉最小割"的概率 ≥ 1/2，于是递归两次里"至少一支成功"的概率能维持在一个不随深度快速衰减的水平，解出 P(n) = Ω(1/log n)。初学者易错点：Karger–Stein 仍是 Monte Carlo（可能失败），O(n² log³ n) 是**高概率**下的时间界；此外这里的 polylog 指数（log³ n）依赖于把成功概率从 Ω(1/log n) 放大到高概率所需的重复次数，不同教材对常数与是否含额外 log 因子的记法略有出入，以 Karger–Stein 原文与 MR §10.3 的 O(n² log³ n) 高概率界为准。

## 5.3 指纹与验证

### 5.3.1 指纹法的通用思想

**指纹**（fingerprinting）是一族用"短哈希 + 随机"来快速验证等式的技术：与其直接比较两个庞大的对象（两个大数、两个矩阵乘积、两个字符串），不如各自算一个随机化的短"指纹"再比指纹。若两对象相等，指纹必然相等（永不误报不等）；若不等，指纹碰巧相等（漏报）的概率被随机选择压到很小——这是典型的**单侧误差 Monte Carlo**（Motwani–Raghavan Ch7）。

核心直觉是"把高维等式投影到随机的低维再核对"。相等的东西投到哪都相等，不等的东西只在极少数"倒霉"的投影方向上才会重合，随机挑一个方向撞上倒霉方向的概率就很低。指纹法的两大好处是**快**（比指纹远快于比原对象）和**省通信**（远程比对只需传短指纹）。初学者易错点：误差是单侧的——"指纹不同"是铁证（对象一定不同），"指纹相同"才是概率判断（对象很可能相同但可能碰撞）；因此指纹法适合"快速排除不同"，确认相同要靠重复把碰撞概率压低。

### 5.3.2 Freivalds 验矩阵乘

Freivalds 1977 年的算法解决"验证矩阵乘积"：给定 n×n 矩阵 A、B、C，判断是否 A·B = C，而**不必真的重算矩阵乘法**。做法是随机取一个向量 r ∈ {0,1}ⁿ（每个分量独立等概率取 0 或 1），核对

A·(B·r) 是否等于 C·r

三次都是矩阵乘向量、各 O(n²)，故总时间 O(n²)，远快于已知最快矩阵乘的 O(n^ω)（ω < 2.372…）。若 A·B = C 则等式恒成立（永不误报不等）；若 A·B ≠ C 则

Pr[A·(B·r) = C·r] ≤ 1/2

独立重复 k 次可把漏报概率压到 ≤ 2^(−k)（Freivalds 1977；Motwani–Raghavan §7.1）。

为什么错误概率 ≤ 1/2？令 D = AB − C，则 D ≠ 0（至少有一个非零元，设在第 i 行）。算法出错当且仅当 D·r = 0，即随机向量 r 落在 D 的零空间里。用"延迟决定"的技巧：固定 D 第 i 行中某个非零元对应的坐标 r_j 最后再定，其余坐标定完后，使 (D·r) 第 i 分量为 0 的 r_j 取值至多只有一个，而 r_j 有两种等概率取值，故命中概率 ≤ 1/2。初学者易错点：一定要按 A·(B·r) 的**从右往左**顺序算（先算 B·r 得向量、再 A 乘向量），这样每步都是 O(n²)；若先算 A·B 就退化成做矩阵乘法、失去全部意义。

本机在 50×50 整数矩阵上核验（Python 3.11.15 + numpy 2.4.6 @2026-07-30，把正确乘积单个元素 +1 制造错误 C）

```
Freivalds: correct product always accepted=True; single-check detection rate on wrong product=0.5013 (>=0.5 expected)
```

正确乘积 1000 次全部接受（零误报不等），错误乘积单次检出率 0.5013 ≥ 1/2，与理论相符。

### 5.3.3 Rabin 指纹与字符串等式

Rabin 指纹用"对随机素数取模"给大对象算指纹，典型用于字符串/大整数的等式判定与子串匹配。把长度为 n 的比特串 x 看成一个 n 位整数，其指纹定义为对一个随机选取的素数 p 取模

F_p(x) = x mod p

比较两串 a、b 只需比 F_p(a) 与 F_p(b)（各只有 O(log p) 比特）。若 a = b 指纹必然相等；若 a ≠ b，则 F_p(a) = F_p(b) 当且仅当 p 整除 |a − b|，而 |a − b| < 2ⁿ 至多有 n 个不同素因子，故在从 {2,…,τ} 中均匀选素数时（Motwani–Raghavan §7.4）

Pr[a ≠ b 却指纹相同] ≤ n / π(τ)

其中 π(τ) 是 ≤ τ 的素数个数。取 τ 使 π(τ) ≥ n²（约 τ = O(n² log n)）即可把误差压到 ≤ 1/n，而指纹只需 O(log n) 比特。

这套思想的滑动窗口版就是 **Rabin–Karp 字符串匹配**：文本上长度为 m 的每个窗口算一个模 p 指纹，与模式串指纹比对，指纹不同必不匹配、相同再做一次逐字符确认；利用"多项式滚动哈希"每滑动一位只需 O(1) 更新指纹，全文匹配期望 O(n + m)。初学者易错点：素数模的选择要随机，否则敌手可构造让某固定 p 大量碰撞的输入（把 Monte Carlo 的"每输入小概率出错"退化成"对坏输入必错"）；另外指纹相等时若要零错误就必须再逐字符确认（这就把 Monte Carlo 转成了 Las Vegas，呼应 5.1.5）。

#### 来源与时效

- 一手：Freivalds《Probabilistic Machines Can Use Less Running Time》(IFIP Congress 1977)——O(n²) 验矩阵乘、错误概率 ≤ 1/2。核实 2026-07-30。
- 一手教材：Motwani–Raghavan《Randomized Algorithms》(1995) Ch7（§7.1 Freivalds、§7.4 指纹与模式匹配）——两类指纹的统一处理与误差界 n/π(τ)。核实 2026-07-30。
- 交叉核对：MR §7.1 与 Freivalds 原文对 ≤ 1/2 单次错误、2^(−k) 放大一致；Rabin–Karp 的滚动哈希与期望 O(n+m) 与 CLRS 字符串匹配章表述一致，无冲突。
- 待核：Rabin 指纹误差界的精确常数（取 τ 使 π(τ) ≥ tn 得误差 ≤ 1/t）各版本记法略异；本报告采用 MR §7.4 的 n/π(τ) 形式，具体常数以该节为准。

## 5.4 集中不等式

### 5.4.1 为什么需要集中不等式

集中不等式（concentration inequalities，又称尾界 tail bounds）回答一个反复出现的问题：一个随机变量偏离其期望值多远的概率有多大？它们是分析随机化算法的**主力工具**——5.1.4 的双侧放大、5.2.3 的重复成功、随机负载均衡的最大负载等，都归结为"证明某个随机量高概率靠近其期望"（Motwani–Raghavan Ch3–4；Mitzenmacher–Upfal Ch3–4）。三件核心工具按"要求的信息越多、给出的界越强"排成阶梯：Markov（只需期望）、Chebyshev（需方差）、Chernoff（需独立性/矩母函数）。

初学者先建立总图景：这些不等式都在给"尾巴"（概率分布远离中心的那部分）一个上界。为什么随机算法分析离不开它们？因为随机算法的性能常是许多随机小量之和（比较次数、命中次数、负载……），我们想说"这个和几乎总是接近它该有的平均值"，而"几乎总是"和"接近"正是尾界在量化。易错点：Markov/Chebyshev 对**任意**分布都成立（很通用但很松），Chernoff 只对**独立**随机变量之和成立（很紧但有前提）——用错前提是最常见的坑。

### 5.4.2 Markov 不等式

Markov 不等式是最基本的尾界，只要求随机变量**非负**、且期望存在。对非负随机变量 X 与任意 a > 0

Pr[X ≥ a] ≤ E[X] / a

等价地，对任意 t > 1

Pr[X ≥ t · E[X]] ≤ 1/t

它的证明一行：因为 X ≥ 0，E[X] ≥ E[X·𝟙(X≥a)] ≥ a·Pr[X ≥ a]，移项即得（Motwani–Raghavan §3.2；Mitzenmacher–Upfal §3.1）。

直觉是"平均值有限，就不可能有太多质量堆在远处"：若超过 2 倍均值的概率超过 1/2，光这部分贡献的期望就超过均值了，矛盾。Markov 的优点是几乎不需要任何信息（只要非负和期望），缺点是**非常松**——它只给出 1/t 这种多项式衰减，且只能约束上尾。初学者易错点：X 必须非负，对可正可负的量不能直接用 Markov（要先取绝对值或平方，那就进入 Chebyshev 了）；另外它只管"超过 a"这一侧，不给下尾信息。Markov 也是导出更强不等式的基石——Chebyshev 是对 (X−μ)² 用 Markov，Chernoff 是对 e^(tX) 用 Markov。

### 5.4.3 Chebyshev 不等式

Chebyshev 不等式在已知**方差** Var(X) = σ² 时，双侧地约束 X 偏离其期望 μ 的概率。对任意 a > 0

Pr[|X − μ| ≥ a] ≤ Var(X) / a²

等价地，以标准差 σ 为尺度，对任意 k > 0

Pr[|X − μ| ≥ k·σ] ≤ 1/k²

它由对非负量 (X−μ)² 施用 Markov 立得（Motwani–Raghavan §3.3；Mitzenmacher–Upfal §3.3）。

直觉是"方差衡量分散程度，越集中（方差越小）越难远离均值"。相比 Markov，Chebyshev 用上了二阶矩，因此给出 1/k² 的衰减（比 Markov 的 1/t 更快）、且是**双侧**的（能同时约束高于和低于均值两侧）。一个经典用途是证明"独立同分布样本的均值集中"：n 个独立同分布、方差 σ² 的变量取平均，其方差降为 σ²/n，代入 Chebyshev 就得到"样本均值以高概率接近真均值"——这是弱大数定律的定量版。初学者易错点：Chebyshev 只需方差存在（不要求独立），但对"许多独立变量之和"它给的界仍偏松（只有 1/k² 多项式衰减）；当变量独立且想要**指数级**衰减时，必须换 Chernoff。

### 5.4.4 Chernoff 界

Chernoff 界针对**独立**随机变量之和给出**指数级**尾界，是随机算法分析中最锋利的工具。设 X = X₁ + … + X_n 为独立的 {0,1}（伯努利/泊松试验）变量之和，μ = E[X]。上尾方向对任意 δ > 0 有

Pr[X ≥ (1+δ)μ] ≤ ( e^δ / (1+δ)^(1+δ) )^μ

下尾方向对 0 < δ < 1 有

Pr[X ≤ (1−δ)μ] ≤ e^(−μδ²/2)

上尾还有一个 0 < δ < 1 下常用的简化形式

Pr[X ≥ (1+δ)μ] ≤ e^(−μδ²/3)

其证明是对 e^(tX) 用 Markov（矩母函数法）、利用独立性把 E[e^(tX)] 拆成乘积、再优化参数 t（Motwani–Raghavan §4.1；Mitzenmacher–Upfal §4.2）。

理解 Chernoff 的威力：它给的是随 μ **指数下降**的界，远强于 Chebyshev 的 1/k²。直觉上，独立性让"很多变量同时往一个方向偏"变得指数级罕见——每多一个独立变量，同向偏离就再乘一个小于 1 的因子。这正是 5.1.4 双侧放大"重复 O(log(1/δ)) 次即可"的理论根据。初学者易错点：Chernoff **必须**要求各项独立（或负相关等特定条件），对相关变量直接套用会得出错误结论；此外市面上 Chernoff 界有多个版本（不同 δ 区间、加性 Hoeffding 形式等），系数各异，用时要认准前提与形式，不要混记。

本机对比了 100 枚公平硬币之和（μ=50）的经验上尾概率与两种 Chernoff 界（Python 3.11.15 + numpy 2.4.6 @2026-07-30）

```
Chernoff up: delta=0.2: empirical P[X>=(1+d)mu]=0.02863, classic bound=0.39090, e^(-mu d^2/3)=0.51342
Chernoff up: delta=0.4: empirical P[X>=(1+d)mu]=0.00004, classic bound=0.02864, e^(-mu d^2/3)=0.06948
Chernoff up: delta=0.6: empirical P[X>=(1+d)mu]=0.00000, classic bound=0.00050, e^(-mu d^2/3)=0.00248
```

经验尾概率始终落在两个界之内，且经典形式 e^δ/(1+δ)^(1+δ) 比简化形式 e^(−μδ²/3) 更紧——这说明两者都是合法上界、经典形式更接近真实，与理论一致。

### 5.4.5 三者对比与选用

三条不等式构成一个"信息换强度"的阶梯，给同一个尾事件的界越来越紧（Motwani–Raghavan Ch3–4；Mitzenmacher–Upfal Ch3–4）。以"n 个独立公平硬币之和偏离均值 n/2 达 εn"为例，三者给出的量级依次递紧，Markov（仅上尾）约为常数级、几乎无用，Chebyshev 给出约 1/(ε²n) 的多项式衰减，而 Chernoff 给出约 e^(−Θ(ε²n)) 的指数衰减

e^(−Θ(ε²n)) ≪ 1/(ε²n)

所需前提也随之依次加重，Markov 只要非负，Chebyshev 要方差，Chernoff 要独立性。

选用口诀是"能用 Chernoff 就用 Chernoff（前提是独立且要指数界），只有方差可算而独立性不明时退回 Chebyshev，什么都不知道只有非负均值时才用 Markov"。为什么不总用最强的？因为 Chernoff 的独立性前提常不满足；而 Markov 虽松，却是唯一"零前提"的工具，还是推导另两者的跳板。初学者易错点：三者不是互相替代而是覆盖不同信息场景；同一个问题里可能先用 Markov 快速估一步、再对独立部分用 Chernoff 收紧。把握这条阶梯，就掌握了随机算法误差分析的主干。
