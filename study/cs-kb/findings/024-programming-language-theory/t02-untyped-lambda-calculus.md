## T2.1 无类型算术表达式

### T2.1.1 项的语法与归纳定义

TAPL 用一个不含变量、不含 λ 的最小语言开场，先把操作语义的机器练熟（TAPL §3.1，加入数字后见 §3.2）。这个语言的**项**（term）由如下文法归纳生成

t ::= true | false | if t then t else t | 0 | succ t | pred t | iszero t

其中 true、false、0 是常量，if-then-else、succ（后继）、pred（前驱）、iszero（判零）是构造子。项的集合是**满足这些形成规则的最小集合**——这正是 T1 归纳定义的直接应用：先放入常量，再对已有的项套构造子，闭包封顶。

初学者要抓住的是"这是一个玩具语言，但麻雀虽小五脏俱全"。它没有函数、没有循环，却已经能演示后面 λ 演算和带类型系统里所有关键概念：什么是语法、什么是"能算一步"、什么算"算完了"、什么叫"算卡住了"。TAPL 特意先在这里把这套词汇立起来，等 T2.2 引入 λ 时就只需替换文法、复用同一套框架。一个易错点：`succ`、`pred` 作用的是"项"而不是"数"，所以 `succ true` 在语法上是**合法的项**（能写出来），只是求值时会卡住——语法合法 ≠ 求值有意义，这个区分是可靠性讨论的起点。

### T2.1.2 值与数值

**值**（value）是"求值已经完成、可作为最终结果"的项的子集（TAPL §3.2，Fig 3-2）。这个语言的值由下面两条文法给出

v ::= true | false | nv

nv ::= 0 | succ nv

其中 nv 是**数值**（numeric value）：0，或者把 succ 套在数值上（succ 0 表示 1、succ (succ 0) 表示 2……）。true 和 false 也是值。

理解要点是"值是语法上就能识别的一类项，不需要再算"。为什么把 `succ nv` 而不是 `succ t` 算作值？因为 `succ (pred 0)` 里面的 `pred 0` 还能算，所以整体还没算完；只有当 succ 里面已经是纯粹的数值堆叠时，才真正是一个"数"。这解释了后面 E-Succ 规则为什么允许对 succ 的参数继续求值。初学者常把"值"和"常量"混同——0 是值也是常量，但 `succ 0` 是值却不是单个常量，它是一个已求值完毕的复合项。

### T2.1.3 单步求值关系与求值规则

**求值关系**（evaluation relation）t → t′ 读作"t 一步归约到 t′"，是本语言语义的核心，用一组**推导规则**（inference rules）归纳定义（TAPL Fig 3-1 布尔部分 + Fig 3-2 数字部分）。计算规则（公理，无前提）为

if true then t₂ else t₃ → t₂　　(E-IfTrue)

if false then t₂ else t₃ → t₃　　(E-IfFalse)

pred 0 → 0　　(E-PredZero)

pred (succ nv₁) → nv₁　　(E-PredSucc)

iszero 0 → true　　(E-IszeroZero)

iszero (succ nv₁) → false　　(E-IszeroSucc)

同余规则（有前提，负责把求值"钻"进子项）为

t₁ → t₁′ ⟹ if t₁ then t₂ else t₃ → if t₁′ then t₂ else t₃　　(E-If)

t₁ → t₁′ ⟹ succ t₁ → succ t₁′　　(E-Succ)

t₁ → t₁′ ⟹ pred t₁ → pred t₁′　　(E-Pred)

t₁ → t₁′ ⟹ iszero t₁ → iszero t₁′　　(E-Iszero)

理解这套规则的关键是分清两类规则的分工：计算规则是"真正干活的一步"（if 挑分支、pred 剥一层 succ），同余规则只是"决定下一步在哪个位置算"——它们规定了**求值顺序**。例如 `if (iszero 0) then …` 里，E-If 要求先把条件 `iszero 0` 用 E-IszeroZero 算成 true，才能用 E-IfTrue 挑分支。这就是**小步语义**：每次只走一小步，`→` 关系精确刻画"下一步能变成什么"。

初学者要注意 E-PredSucc 的前提是 `succ nv₁` 而不是 `succ t₁`：`pred (succ (pred 0))` 不能直接剥，必须先把内层 `pred 0` 算成 0、变成 `pred (succ 0)`，才轮到 E-PredSucc。规则里出现 nv、v 这类**元变量**（metavariable）是在限定"只有当子项已是某种形状时才触发"，这是操作语义里控制求值时机的标准手法。

### T2.1.4 正规形式、值与二者关系

一个项 t 是**正规形式**（normal form），当且仅当不存在任何 t′ 使得 t → t′，即"再也走不动一步"（TAPL Def 3.5.6）。

关键定理有两条方向相反的命题。每个值都是正规形式（TAPL Def 3.5.7）

若 t 是值，则 t 是正规形式。

但反过来**不成立**：在含数字的这个语言里，存在既非值、又是正规形式的项（下一节的卡住项）。相较之下，若语言只含布尔部分（无数字），则正规形式恰好等于值（TAPL Def 3.5.8）。

这条"值 ⊆ 正规形式，但正规形式 ⊄ 值"是理解**类型安全为什么有意义**的种子。一个正规形式无非两种下场：要么它是值（皆大欢喜，算出了合法结果），要么它不是值却也动不了（卡住了，即出错）。类型系统（本课 T3）的全部目的，就是保证"良类型的项永不落到第二种下场"。初学者在这里先建立直觉即可：正规形式 = 停机状态，值 = 好的停机状态，卡住 = 坏的停机状态。

### T2.1.5 卡住项与运行时错误的建模

一个闭项称为**卡住**（stuck），当且仅当它是正规形式但不是值（TAPL Def 3.5.15）。典型卡住项如

if 0 then true else false　（条件不是布尔）

succ true　（对布尔取后继）

pred false

iszero true

这些项语法合法、却没有任何求值规则能匹配它们的当前形状，于是既算不下去、又不是合法结果——这正是无类型语言里"运行时类型错误"的形式化模型。

理解要点是"卡住 = 该语言表达无意义计算的方式"。在真实语言里这类情形对应"把布尔当数字加""调用一个非函数"等崩溃；TAPL 用"卡住"这个纯语法概念把它精确化，不引入任何异常机制就能谈论"出错"。这是**可靠性（soundness）的预演**：类型安全定理最终会说"良类型项不会卡住"，也就是 Progress（不是值就还能走一步）+ Preservation（走一步后仍良类型）联合排除卡住状态（本课 T3.3）。初学者要区分"卡住"和"发散/不停机"：卡住是**停下来但停错了**，发散是**永远停不下来**；本算术语言必停（下条），所以这里只有卡住这一种"坏结局"，到了 λ 演算才会出现发散。

### T2.1.6 求值的确定性与可终止性

本语言的求值有两条元性质，均可对求值规则做归纳证明（TAPL）。**确定性**（determinacy of one-step evaluation, Theorem 3.5.4）

若 t → t′ 且 t → t″，则 t′ = t″。

即每个项下一步最多只有一种走法，`→` 实际上是个（部分）函数。**可终止性**（termination / normalization, Theorem 3.5.11 及后续编号视版本）

对任意项 t，存在正规形式 t′ 使得 t →* t′（即求值必在有限步内停机）。

其中 →* 是 → 的**自反传递闭包**，表示"零步或多步归约到"。

确定性意味着"小步 vs 大步无歧义、结果唯一"，这是把语言实现成一个求值器的前提。可终止性的证明思路是给每个项定义一个"规模"（如项中构造子个数），并证明每走一步规模严格下降，而自然数不能无限下降——这是典型的**良基归纳/终止性度量**（承 T1.3）。初学者要记住：**可终止性是这个玩具算术语言的特权**，一旦进入 T2.2 的 λ 演算（图灵完备）就必然丧失（如下面的 Ω 项永远归约不停），因为图灵完备等价于停机不可判定。

## T2.2 λ 语法与 α/β

### T2.2.1 λ 项的语法：变量、抽象、应用

**无类型 λ 演算**只有三种项（TAPL §5.1，Def 5.3.1）

t ::= x | λx.t | t t

分别是**变量** x、**抽象**（abstraction）λx.t（"以 x 为参数、体为 t 的匿名函数"）、**应用**（application）t t（"把左边的函数作用到右边的参数"）。就这三条，别无其他——数、布尔、加法全靠它们编出来（T2.3）。

阅读约定必须先立清楚，否则会看错括号（TAPL §5.1）。应用**左结合**

s t u 读作 (s t) u

抽象体**尽量向右延伸**

λx. λy. x y z 读作 λx. (λy. ((x y) z))

即 λ 的"身体"一直吃到遇到没被括号挡住的边界为止。初学者最常犯的错就是把 `λx. x y` 误读成 `(λx. x) y`——实际上 y 在 λ 体内部，整个是一个抽象。养成"先按约定补全括号再动手"的习惯能免掉大半错误。

### T2.2.2 自由变量与绑定变量、闭项

抽象 λx.t 中的 x 是**绑定变量**（bound variable），它**绑定**（binds）t 中所有对应的 x 出现；不被任何 λ 绑定的变量出现叫**自由变量**（free variable）。项 t 的自由变量集 FV(t) 归纳定义为（TAPL Def 5.3.2）

FV(x) = {x}

FV(λx.t₁) = FV(t₁) ∖ {x}

FV(t₁ t₂) = FV(t₁) ∪ FV(t₂)

不含自由变量（FV(t) = ∅）的项称为**闭项**（closed term），也叫**组合子**（combinator）。

理解要点是"绑定变量的名字只是占位符，作用域局部"——就像数学里 ∫f(x)dx 和 ∫f(y)dy 是同一积分。在 `(λx. x) x` 里，前一个 x（λ 体内）是绑定的，最后那个 x 是自由的，两者虽同名却是**不同的东西**。同一个变量名可以在一处绑定、别处自由，甚至被内层 λ **遮蔽**（shadowing），如 `λx. λx. x` 里内层 x 遮住外层。初学者要训练"顺着 λ 的作用域判断每个变量出现是自由还是绑定"，这是后面代换和 α 等价不出错的基础。

### T2.2.3 α 等价（改名）

**α 等价**（alpha equivalence / alpha conversion）规定"只改绑定变量的名字、不改结构"的两个项视为相同（TAPL §5.3 注记；Barendregt §2.1 α-conversion）

λx. x  ≡α  λy. y

λx. λy. x  ≡α  λa. λb. a

改名时**不得把自由变量误绑进来**：λx. y 不能改成 λy. y（原来的自由 y 被抓成绑定了）。

λ 演算的"官方对象"其实是**α 等价类**，而不是带具体名字的项——名字只是书写工具。这就是为什么我们可以随意给绑定变量换个新鲜名字来避免冲突。α 等价存在的根本原因是"变量捕获"这个坑（下条）：做代换前常需先 α-改名，把要代入位置的绑定变量换成全新名字，才能安全代入。TAPL 在纸面上默认"隐式 α-改名"（Barendregt 变量约定：绑定变量总取得与自由变量都不同），而 T2.5 的 de Bruijn 表示则用编号彻底消灭名字、让 α 等价的项在语法上**字面相等**。

### T2.2.4 代换与变量捕获

计算的引擎是**代换**（substitution）[x↦s]t，读作"把 t 中自由出现的 x 全部换成 s"。为避免捕获，须用**避免捕获的代换**（capture-avoiding substitution, TAPL Def 5.3.5）

[x↦s]x = s

[x↦s]y = y　　(y ≠ x)

[x↦s](λy.t₁) = λy. [x↦s]t₁　　(y ≠ x 且 y ∉ FV(s))

[x↦s](t₁ t₂) = ([x↦s]t₁) ([x↦s]t₂)

抽象那条的旁条件 `y ∉ FV(s)` 是防捕获的关键；若不满足，先把 λy 的 y α-改名成一个既不等于 x、也不在 FV(s) 里的新名字，再代换。

**变量捕获**（variable capture）是初学者头号陷阱。设想直接、不设旁条件地算

[x↦y](λy. x)　误算成　λy. y

左边本意是"一个忽略参数、返回自由变量 y 的函数"，右边却变成了恒等函数——自由的 y 被 λy 抓住了，语义完全变味。正确做法是先把 λy 改名，如改成 λz：

[x↦y](λz. x) = λz. y

**代换必须尊重作用域，代入的自由变量不能被内层绑定意外捕获**。这个坑正是 α 等价和 de Bruijn 索引存在的理由。

### T2.2.5 β 归约

**β 归约**（beta reduction）是 λ 演算唯一的计算规则：把一个函数应用到实参，就用实参代换函数体里的形参（TAPL §5.3）

(λx. t₁₂) t₂ → [x↦t₂] t₁₂

形如 (λx. t₁₂) t₂ 的项（一个抽象紧跟一个参数）叫**可约式**（redex, reducible expression），代换后的结果 [x↦t₂]t₁₂ 叫**收缩项**（contractum）。

理解要点是"β 归约 = 函数调用的数学本质"，整个 λ 演算的计算力全部来自反复找 redex、做代换。最小例子

(λx. x) y → y

(λx. λy. x) a b → (λy. a) b → a

第二例展示了**柯里化**（currying）：多参函数其实是"返回函数的函数"，`(λx.λy.x) a b` 先吃 a 得到 `λy.a`，再吃 b 得到 a。相关的还有 **η 归约**（eta reduction）λx. (t x) → t（当 x ∉ FV(t)），表达"外延性/无用包装"，Barendregt §2.1 与 Hindley–Seldin 均单列，TAPL 提及但不作为核心求值规则。初学者要注意 β 归约本身**不指定先约化哪个 redex**——一个项可能有多个 redex，先约谁由"求值策略"决定（下条），而"无论怎么约、只要都约到底，结果一致"由合流性保证（T2.4）。

### T2.2.6 求值策略：正规序、值调用等

一个项常含多个 redex，**求值策略**（evaluation strategy）规定"下一个约化哪一个"。主流策略有（TAPL §5.1；Barendregt/Hindley–Seldin 术语）

**完全 β 归约**（full beta-reduction）：任意 redex 都可约，不限次序。

**正规序**（normal order）：总约**最左最外**的 redex。

**传名调用**（call-by-name, CBN）：类似正规序，但不进入抽象体内部约化（不约 λ 下面的 redex）。

**传值调用**（call-by-value, CBV）：只有当**参数已求值为值**时才约外层 redex，且同样不进入抽象体。

TAPL 正文采用 **call-by-value**，其小步规则为（TAPL Fig 5-3）

t₁ → t₁′ ⟹ t₁ t₂ → t₁′ t₂　　(E-App1)

t₂ → t₂′ ⟹ v₁ t₂ → v₁ t₂′　　(E-App2)

(λx. t₁₂) v₂ → [x↦v₂] t₁₂　　(E-AppAbs)

其中 v 表示值（在纯 λ 里，值 = 抽象 λx.t）。E-App1/E-App2 规定"先把函数位算成 λ、再把参数位算成值、最后才 β"，是**从左到右、传值**的求值顺序。

理解策略差异的关键在于"约化次序影响能否停机与效率，但（对纯 λ）不影响最终范式是否存在"。经典对比：`(λx. λy. y) Ω`，其中 Ω 是永不停机的发散项（见 T2.3）。正规序/CBN 先把外层函数应用了、直接丢掉没用的参数 x，得到 `λy.y` 停机；而 CBV 坚持先把参数 Ω 求值，于是永远卡在求 Ω 上、发散。这说明**CBN/正规序更"惰性"、更容易停机，CBV 更"急切"但实现简单、且与副作用配合可预测**——这是 Haskell（惰性）与 OCaml/大多数语言（传值）的分野之源。初学者要记住：TAPL 及绝大多数真实语言取 CBV，本报告后文 Church 编码的正确性也在 CBV 下用 Python 高阶函数佐证。

## T2.3 编程于 λ

### T2.3.1 Church 布尔值与逻辑运算

只有函数，怎么表示"真/假"？**Church 布尔**（Church booleans）把真假编码成"二选一"的函数（TAPL §5.2）

tru = λt. λf. t

fls = λt. λf. f

即 tru 拿到两个参数返回第一个，fls 返回第二个。条件表达式与逻辑运算随之定义

test = λl. λm. λn. l m n

and = λb. λc. b c fls

理解要点是"布尔值 = 一个会替你做选择的函数"。`test b m n` 把 b 作用到 m、n 上：若 b = tru 就选出 m，若 b = fls 就选出 n——分支逻辑内建在数据里。验证 `and tru fls`：

and tru fls → tru fls fls → (λt.λf.t) fls fls → fls

得到 fls，符合真值表。本机用 Python 高阶函数模拟（元层 β 归约）实跑得 `and tru tru -> true`、`and tru fls -> false`，与手算一致。初学者易错点：这套编码**依赖惰性直觉**——`test` 在真实 CBV 里会把 m、n 都作为参数求值，而语言中真正的 if 应短路；所以 Church 编码演示的是"可编码性"，不等于高效或与副作用兼容的实现。

### T2.3.2 序对与投影

**序对**（pair）同样用函数编码——把两个分量"存"进一个等待"选择器"的函数里（TAPL §5.2）

pair = λf. λs. λb. b f s

fst = λp. p tru

snd = λp. p fls

pair f s 记住 f 和 s，等一个布尔 b 来决定交出哪个；fst 送进 tru 取第一个，snd 送进 fls 取第二个。

验证 `fst (pair v w)`：

fst (pair v w) → (pair v w) tru → tru v w → v

本机 Python 佐证：`fst(pair 1 3) -> 1`、`snd -> 3`。理解要点是"数据结构 = 把数据装进闭包、用函数取出"——这与真实语言里"用闭包捕获状态"是同一思想的源头。初学者可把 pair 想成"暂存两样东西、凭一张布尔票据取货"的柜台。

### T2.3.3 Church 数字与算术

自然数编码为"把函数 s 迭代作用于 z 的次数"（**Church 数字**，Church numerals, TAPL §5.2）

c₀ = λs. λz. z

c₁ = λs. λz. s z

c₂ = λs. λz. s (s z)

即 c_n 表示"s 迭代 n 次"。后继与加乘定义为

scc = λn. λs. λz. s (n s z)

plus = λm. λn. λs. λz. m s (n s z)

times = λm. λn. m (plus n) c₀

判零用"迭代一个恒返回 fls 的函数：迭代 0 次仍是 tru"

iszro = λm. m (λx. fls) tru

数字 n 被编码成"对任意东西重复 n 次"的能力，scc 就是"在原有 n 次之上再套一次 s"，plus m n 就是"先迭代 n 次、再迭代 m 次 = 迭代 m+n 次"。本机 Python 佐证（把 s 取为 +1、z 取为 0 还原自然数）：`plus c2 c3 -> 5`、`times c2 c3 -> 6`、`iszro` 及数字 0/1/2/3 还原正确。

初学者最大的坑是**前驱 pred**：λ 里做减法远比加法难，Church 原始方案要靠"序对滑动"技巧（维护 (n-1, n) 一对、每步右移），TAPL §5.2 给出的 prd 就用了 pair/fst/snd。直觉上"数字只记得怎么往上数、不记得怎么往下退"，所以 pred 必须迂回构造。这也预告了：λ 演算表达力足够（图灵完备），但很多操作"能编但不自然"。

### T2.3.4 发散项 Ω 与递归的困难

在无类型 λ 里，有的项**永远归约不停**，最小的例子是**发散项**（divergent term）

omega = (λx. x x) (λx. x x)

对它做 β 归约

(λx. x x) (λx. x x) → (λx. x x) (λx. x x) → …

一步归约回自身，永不到达范式。

Ω 的存在证明了"无类型 λ 演算不满足可终止性"——与 T2.1 那个必停的算术语言形成鲜明对照，这正是图灵完备（能表达任意可计算函数、含不停机）的代价。子式 `λx. x x` 叫**自应用**（self-application），把参数作用到它自己身上，是制造循环的原材料。初学者要理解：正是"能把函数喂给它自己"这一点，让无类型 λ 既获得了递归能力，又失去了保证停机的能力；而后面加类型系统（T3）会禁掉 `x x` 这种自应用，从而换回强可终止性——**表达力与可终止性的取舍**是整个类型理论的核心张力。

### T2.3.5 不动点组合子 Y / fix 与递归

λ 演算里没有"函数名"可供自我引用，递归靠**不动点组合子**（fixed-point combinator）实现——它能为任意"生成器" F 找到一个 g 使得 g = F g（TAPL §5.2 给出 CBV 版 fix；经典 Y 见 Barendregt §6.1、§6.5）。经典 **Y 组合子**为

Y = λf. (λx. f (x x)) (λx. f (x x))

它满足不动点性质 Y F  =β  F (Y F)。但在 **call-by-value** 下 Y F 会立刻发散（参数 `x x` 被急切求值），故 TAPL 用 η-展开过的 **CBV 不动点组合子**

fix = λf. (λx. f (λy. x x y)) (λx. f (λy. x x y))

用法是把待递归函数写成"以自身为首参"的生成器，再喂给 fix。以阶乘为例，生成器

g = λfct. λn. if iszro n then c₁ else times n (fct (prd n))

则 `factorial = fix g` 即所求递归函数。

"不动点"就是方程 g = F g 的解——把"递归定义"看成一个关于函数自身的方程，Y/fix 负责把它解出来，从而在没有命名递归的语言里实现递归。为什么 CBV 要用 fix 而非 Y？因为 `λy. x x y` 这个 η-包装把危险的自应用 `x x` 藏在一个抽象后面（值，不再立即求值），推迟到真正需要时才展开，避免了无参数的即时发散。本机 Python 佐证：用 CBV 风格的 Z 组合子（fix 的等价物）实现的阶乘 `fact(5) -> 120`，验证了"不动点驱动递归"确实可行。初学者只需先抓直觉：**递归 = 解一个"函数等于它自身某种变换"的方程，不动点组合子是通用解法器**；细节推导留给专门读物。

## T2.4 Church-Rosser 与合流

### T2.4.1 合流性（confluence）与菱形性质

**合流性**（confluence）刻画"归约怎么分岔，最终都能再汇合"。归约关系 → 是合流的，当且仅当（Barendregt §3.1，Def 3.1.11；Hindley–Seldin Ch.1）

若 t →* t₁ 且 t →* t₂，则存在 t₃ 使得 t₁ →* t₃ 且 t₂ →* t₃。

这里 →* 是 β 归约的自反传递闭包。合流也叫**Church–Rosser 性质**（Church–Rosser property, CR）。一个更强的单步版本叫**菱形性质**（diamond property）：把上式里的 →* 换成单步 →。

理解要点是"殊途同归"：从同一个项出发，先约这个 redex 还是先约那个 redex 会走到不同中间项，但合流保证它们**总能再各走若干步碰头**。画成图就是一个菱形——上顶点分岔、下顶点汇合，故名。初学者要特别当心一个易错点：**β 归约本身不满足单步菱形性质**（约一个 redex 可能复制出多个新 redex，导致一步对不齐），它满足的是"多步"意义下的合流。证明 Church–Rosser 的经典手法（Tait–Martin-Löf 平行归约）正是为绕开这个"单步对不齐"而设计——本报告按 v3 只讲结论与直觉，不铺证明。

### T2.4.2 Church–Rosser 定理与范式唯一

**Church–Rosser 定理**（TAPL §5.3 结尾注记提及；Barendregt Theorem 3.2.8；Hindley–Seldin Ch.1 定理）陈述

无类型 λ 演算的 β 归约是合流的。

一条直接且极重要的推论是**范式唯一性**（uniqueness of normal form）

若一个项有范式，则该范式在 α 等价意义下唯一。

其中**范式**（normal form）指不含任何 redex、再也约不动的项。

范式唯一意味着"一个 λ 项如果算得出结果，那个结果与你选的约化次序无关"——这正是把 λ 演算当作确定性"计算模型"的合法性根基。证明思路：若 t 有两个范式 u、v，由合流性它们能汇合到某 t₃；但 u、v 已是范式（约不动），故 u →* t₃ 只能零步，即 u = t₃ = v（模 α）。初学者要抓住两个层次的结论区别：合流性说的是"能汇合"，范式唯一是它的推论；而"结果是否存在（是否有范式）"是另一回事——见下条。

### T2.4.3 范式的存在性与归约策略

合流性只保证"范式若存在则唯一"，**不保证范式一定存在**（TAPL §5.3；Barendregt §13 归约策略）。关键事实有三条

有的项根本没有范式（如 T2.3 的 Ω = (λx.x x)(λx.x x)，永远归约不停）。

有的项有范式，但**某些**归约策略找不到它（急切策略可能先陷入一个可丢弃的发散子项）。

**正规序**（最左最外）是**归约完全的**（normalizing）：只要一个项有范式，正规序归约必定到达它（标准化定理 / standardization theorem，Barendregt §11、§13）。

"存不存在范式"（可能不存在）、"哪种策略能保证找到"（正规序能，CBV/急切不一定能）、"找到的是不是唯一"（由合流性，是）。经典例子 `(λx. λy. y) Ω`：正规序先应用外层函数、把发散的 Ω 当作没用的参数 x 丢掉，得到范式 λy.y；而 CBV 坚持先求 Ω 而永远卡住。这与 T2.2.6 求值策略的停机差异是同一现象的两种说法。

**合流性负责"结果唯一、与路径无关"这一好性质，归约策略负责"能不能走到那个结果"**；无类型 λ 因图灵完备，"有没有结果"本身不可判定，所以才需要正规序这样的"只要有解就一定找得到"的策略保证。本小主题为纯理论命题，未做本机实证（合流性/标准化定理属证明论结果，Python 不足以佐证，如实标注）。

## T2.5 无名表示与实现

### T2.5.1 de Bruijn 索引：消灭变量名

要让机器真正跑 λ 演算，"变量名 + α 等价 + 避免捕获"这套麻烦必须处理掉。**de Bruijn 索引**（de Bruijn indices，TAPL §6.1）用一个自然数替代每个变量名：该数字表示"从这个变量出发，向外数到绑定它的那个 λ，中间隔了多少层 λ"（从 0 起数）。语法变为**无名项**（nameless terms）

t ::= k | λ. t | t t　　（k 为自然数索引，λ 不再带参数名）

例如

λx. x　写成　λ. 0

λx. λy. x (y x)　写成　λ. λ. 1 (0 1)

λx. λy. x　写成　λ. λ. 1

理解要点是"索引 = 到绑定者的距离"。在 `λ. λ. 1 (0 1)` 里：最内层 body 中的 `1` 跳过 1 层（内层 λ）指向外层 λ 绑定的变量（原 x），`0` 指向最内层 λ 绑定的变量（原 y）。最大好处是 **α 等价的项在无名表示下字面相等**——λx.x 和 λy.y 都是 λ.0，改名问题被彻底消除，机器比较两项是否 α 等价只需逐字符比对。初学者最容易错的是**数错层数**和忘记"从 0 起数"；另外，自由变量需要一个**命名上下文**（naming context）Γ 把它们映射到"外层假想的 λ 层数"，否则孤立的索引 k（k 超出当前 λ 嵌套深度）指向谁无从谈起。

### T2.5.2 移位（shifting）

代换会把一个项 s 搬进更深的 λ 嵌套里，s 中指向"外部"的自由索引必须相应**增大**才能继续指对原绑定者——这个调整叫**移位**（shifting，TAPL Def 6.2.1）。d 层移位、截断点 c 的定义为

↑ᵈ_c(k) = k　　(k < c)

↑ᵈ_c(k) = k + d　　(k ≥ c)

↑ᵈ_c(λ. t₁) = λ. ↑ᵈ_{c+1}(t₁)

↑ᵈ_c(t₁ t₂) = (↑ᵈ_c t₁) (↑ᵈ_c t₂)

其中 c 记录"当前钻进了几层 λ"，初始为 0；只有 ≥ c 的索引（自由索引）才 +d，< c 的（在 s 内部就被绑定的）保持不变。

移位区分"相对 s 而言的自由索引"和"内部绑定索引"，只给前者加偏移。截断点 c 每进入一层 λ 就 +1，正是为了动态跟踪"哪些索引才算自由"。最小例子：把 `λ. 0 1`（自由索引 1 指外部第 0 层）整体移入一层 λ 之下，需 `↑¹_0`，结果 `λ. 0 2`——内部的 0（被自己那层 λ 绑定）不动，自由的 1 变 2。初学者要记住：移位不是"所有数字统统加"，而是**只调整那些指向外界的索引**，这就是 c 存在的全部意义。

### T2.5.3 无名项上的代换与 β 归约

有了移位就能定义无名项的**代换** [j↦s]t（把索引 j 替换为 s，TAPL Def 6.2.4）

[j↦s]k = s　　(k = j)

[j↦s]k = k　　(k ≠ j)

[j↦s](λ. t₁) = λ. [j+1 ↦ ↑¹_0(s)] t₁

[j↦s](t₁ t₂) = ([j↦s]t₁) ([j↦s]t₂)

进入一层 λ 时，目标索引 j 要 +1（因为多了一层绑定），且被代入的 s 要先 ↑¹_0 移位一层（它现在处于更深的嵌套里）。β 归约规则随之写成（TAPL §6.3）

(λ. t₁₂) v₂ → ↑⁻¹_0 ([0 ↦ ↑¹_0(v₂)] t₁₂)

即：把参数 v₂ 先上移一层代入索引 0，代换后外层那个 λ 消失、整体再**下移一层** ↑⁻¹_0 把腾出的空缺补回。

这套定义把 T2.2 里"α-改名 + 避免捕获"的全部麻烦，机械化成"索引加减 + 移位"的纯算术操作——不再需要生成新鲜变量名，完全确定、可直接编码。β 规则里"先上移 v₂、代入、再整体下移"这一进一出，正是在维护"消掉一层 λ 后各索引仍指对绑定者"这一不变式。初学者不必背下每个 +1/−1 的来龙去脉，先抓住直觉：**de Bruijn 把"作用域"从名字变成了距离，于是代换变成了对距离的重新记账**。

### T2.5.4 λ 演算的实现要点

TAPL Ch.7 给出上述理论的可执行 ML 实现，工程要点为（TAPL §7.1–§7.3；PFPL 对照）

项数据类型用无名表示：`TmVar of index`、`TmAbs of name×term`、`TmApp of term×term`（name 仅供打印，语义由 index 决定）。

上下文 `context` 记录自由变量名，用于**打印**时把索引还原成可读名字（求值本身不需要名字）。

求值器实现单步 `eval1` + 反复迭代到范式的 `eval`，采用 call-by-value；核心操作是 `termShift`（移位）与 `termSubstTop`（顶层代换，即上面 β 规则右端）。

真实实现里"名字"只在**解析（外→内）与打印（内→外）**两端出现，中间一律用 de Bruijn 索引运算，从而免疫改名/捕获错误。这解释了为什么 `TmAbs` 还保留一个 name 字段——它纯粹是"打印提示"，对计算无影响。初学者可以把整条工具链记成：源码文本 → 带名字 AST → 转成 de Bruijn 无名项（去名）→ 求值（纯索引运算）→ 借上下文把结果还原成带名字项打印。本小主题的移位/代换定义可用 Python 直接实现验证（TAPL 有对应 OCaml），本报告未单独实跑该实现（属可选实证，标注为文本比对为准）。
