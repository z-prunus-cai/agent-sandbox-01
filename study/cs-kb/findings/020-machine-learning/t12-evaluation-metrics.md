## 12.1 混淆矩阵与准确率陷阱

### 12.1.1 混淆矩阵：四格的定义与布局

混淆矩阵（confusion matrix）是把分类器的**预测标签**与**真实标签**交叉制成的一张计数表。对二分类，它是一个 2×2 表，四个格子按"真实为正/负"与"预测为正/负"的组合分别记数，标准命名为真正例 TP、假正例 FP、假负例 FN、真负例 TN：

TP = 真实为正且预测为正的样本数

FP = 真实为负但预测为正的样本数（"误报""第一类错误"）

FN = 真实为正但预测为负的样本数（"漏报""第二类错误"）

TN = 真实为负且预测为负的样本数

它是本大主题后面几乎所有分类度量（准确率、精确率、召回、F1、TPR、FPR、特异度）的**共同原材料**——那些度量都只是这四个数的不同比值。

初学者最容易被"哪个是行哪个是列、正类放哪"绊住，而这里**没有统一约定**，是一个真实的来源分歧点，必须显式记牢。ISL Ch4 与很多教科书把**预测**放在行、**真实**放在列，且常把正类（如"患病""违约"）放在第一行/列；而 scikit-learn 的 `confusion_matrix(y_true, y_pred)` 约定**行是真实、列是预测**，且标签按数值/字典序升序排列——对 0/1 标签，就是 `[[TN, FP], [FN, TP]]`，因此官方推荐用 `cm.ravel()` 解包为 `tn, fp, fn, tp`（本次实证已坐实这个顺序）。所以看任何一张混淆矩阵前，第一件事是确认它的行列方向和正类位置，否则精确率和召回会算反。记忆四格的窍门：第二个字母是**预测**（P=预测正、N=预测负），第一个字母是**预测对不对**（T=对、F=错）——"FN"就是"预测为负、但预测错了"，即漏掉的正例。

### 12.1.2 从四格派生的基础率

固定混淆矩阵后，沿不同方向做归一化就得到一组有名字的比率，它们是后三节度量的桥梁。沿"真实为正"这一行归一化得到真正例率，沿"真实为负"归一化得到假正例率与真负例率：

真正例率 TPR = 召回 = 敏感度 = TP / (TP + FN)

假正例率 FPR = FP / (FP + TN)

真负例率 TNR = 特异度 = TN / (TN + FP) = 1 − FPR

阳性预测值 PPV = 精确率 = TP / (TP + FP)

流行率（先验）prevalence = (TP + FN) / N

关键区分是**按行还是按列**归一化。TPR/召回/敏感度是在"所有真实正例"里查回了多少（按真实正例这一行），特异度是在"所有真实负例"里正确排除了多少——这两个是 ROC 的两根轴（12.3），且**不随类别比例变化**，因为它们各自只在一类内部算。而精确率是按"所有被预测为正"这一列算的，**会随流行率变化**（正类越稀有、同样的模型精确率越低）。这个"行 vs 列"的差别正是 12.3 为什么 ROC 在不平衡下会给人虚高印象、而 PR 曲线更敏感的根源。同一个 TP 数，除以行和（TP+FN）得召回、除以列和（TP+FP）得精确率——初学者把这两个分母记清，后面 P/R/F1 就不会乱。

### 12.1.3 准确率的定义与类不平衡陷阱

准确率（accuracy）是最直觉的度量——预测对的样本占全部样本的比例：

accuracy = (TP + TN) / (TP + TN + FP + FN)

它的致命弱点是**对类别不平衡极不敏感、会被多数类主导**。当正类稀有时，一个完全不学习、"永远预测多数类"的退化模型也能拿到接近多数类占比的高准确率，看上去很美，实则毫无价值。

1000 个样本里 990 个负类、10 个正类（比如 1% 患病率的疾病筛查）。一个"无脑全判负"的模型，TP=0、TN=990、FP=0、FN=10，准确率 =(0+990)/1000=**0.99**——看起来 99% 的高分，但它对真正需要识别的 10 个病人**一个都没查出来**，正类召回为 0。本次实证正是这个设定，`accuracy_score` 返回 0.99、正类 `recall_score` 返回 0.0。这说明：在不平衡任务里，准确率是一个**危险的单一数字**，必须换用对正类敏感的度量（召回、精确率、F1、PR-AUC）或平衡化的准确率。初学者的正确反应是——看到准确率先问一句"类别比例是多少"，若严重不平衡，准确率基本作废。

### 12.1.4 多分类混淆矩阵与 micro / macro / weighted 平均

对 K 类问题，混淆矩阵是 K×K 表，格 (i, j) 记"真实为类 i、预测为类 j"的样本数，对角线是各类分对的数。要把每类的精确率/召回/F1 汇总成一个数，有三种平均方式，语义不同，选错会误导：

micro 平均——把所有类的 TP、FP、FN 分别求和后再算比率，等价于"按样本"统计，多分类里 micro-精确率=micro-召回=micro-F1=整体准确率。

macro 平均——先算每类的度量，再**不加权**取算术平均，每个类权重相等，稀有类和常见类同等重要。

weighted 平均——先算每类度量，再按各类真实样本数加权平均，大类主导，接近但不等于准确率。

从实践含义上看，如果你**关心稀有类**（如少数族群、罕见故障），用 **macro**——它不让大类的漂亮成绩掩盖小类的糟糕表现；如果你只关心"总体判对率"、各类重要性与其频率成正比，用 micro/weighted。scikit-learn 的 `f1_score`/`precision_score`/`recall_score` 用 `average=` 参数选择（`'micro'`/`'macro'`/`'weighted'`/`None`），`classification_report` 会同时打印 macro avg 与 weighted avg 两行。一个常见误区是不指定 `average` 就用于多分类导致报错或误解——多分类下必须显式选平均口径，且要在报告里写清用了哪个。

### 12.1.5 平衡准确率、Cohen's κ 与 MCC

针对准确率在不平衡下失效，有几个更稳健的单一汇总量，作为准确率的替代登记于此。平衡准确率是各类召回的算术平均，把"全判多数类"的分数拉回随机水平：

balanced accuracy = (TPR + TNR) / 2

马修斯相关系数 MCC 把混淆矩阵四格综合成一个 [−1, 1] 的相关系数，被公认为不平衡二分类下最稳健的单一度量之一：

MCC = (TP·TN − FP·FN) / sqrt((TP+FP)(TP+FN)(TN+FP)(TN+FN))

Cohen's κ 衡量"实际一致度"相对"随机一致度"的提升，用于校正凭运气蒙对的部分：

κ = (p_o − p_e) / (1 − p_e)

其中 p_o 是观测一致率（=准确率），p_e 是在各自边缘分布下随机预测的期望一致率。

这几个量的共同思路是**扣掉"靠猜多数类白得的分"**。对前面 99% 准确率的废模型，平衡准确率 =(0+1)/2=0.5（等于随机），MCC=0（分子 TP·TN−FP·FN 在 TP=FP=0 时为 0），κ≈0——它们都诚实地把废模型打回原形。初学者不必记死 MCC 的公式，但要记住结论：**报告不平衡分类结果时，除了 P/R/F1，附一个 balanced accuracy 或 MCC，比单看准确率诚实得多**。sklearn 提供 `balanced_accuracy_score`、`matthews_corrcoef`、`cohen_kappa_score`。

## 12.2 精确率/召回/F1

### 12.2.1 精确率与召回的定义

精确率（precision）和召回（recall）把混淆矩阵按两个正交方向拆开，专门刻画模型在**正类**上的表现，是不平衡任务里取代准确率的主力：

precision = TP / (TP + FP)

recall = TP / (TP + FN)

精确率回答"**模型说是正的，有多少真是正的**"（预测为正的可信度，分母是被预测为正的总数）；召回回答"**真正的正例，模型查回了多少**"（正例的覆盖率，分母是真实正例总数，等于 12.1.2 的 TPR/敏感度）。

用一个搜索/筛查的比方最好懂：你在一堆文件里搜"相关文档"。精确率高=你捞上来的基本都相关（不掺垃圾）；召回高=真正相关的基本都被你捞到了（不漏网）。二者关注不同的错误：精确率惩罚 **FP（误报，捞错了）**，召回惩罚 **FN（漏报，漏掉了）**。哪个更重要取决于错误代价——垃圾邮件过滤器把正常邮件误判为垃圾（FP）代价很高，重精确率；癌症筛查漏掉一个病人（FN）代价极高，重召回。初学者要把两个分母刻进脑子：精确率除以"预测为正的列和"，召回除以"真实为正的行和"。

### 12.2.2 精确率-召回权衡与阈值依赖

精确率和召回通常**此消彼长**，且都不是模型的固有常数，而是**随决策阈值 `t` 变化**的函数。模型输出连续分数 `s(x)`，用 `s(x) ≥ t` 判正。把阈值调低——判正更宽松，捞回更多正例（召回↑），但也混进更多误报（精确率↓）；把阈值调高——判正更严格，捞上来的更纯（精确率↑），但漏掉更多正例（召回↓）。

这个权衡的根源是"一个旋钮控制两个方向"。想象把所有样本按分数从高到低排队，阈值就是队伍里的一道横线，线以上判正。横线往下移，正例区变大：新纳入的样本里有真正例（召回涨）也有假正例（精确率可能跌）。因此报告"精确率=0.9"而不说阈值是**没有意义**的——同一个模型换个阈值就是另一组数字。一个常见初学者错误是拿两个模型在**各自默认阈值**（比如都用 0.5）下的单点 P/R 直接比高下——这不公平，因为 0.5 对不同模型对应的严格程度不同，正确做法是比较整条曲线（12.2.4）或在同一目标召回下比精确率。

### 12.2.3 F1 与 F-beta

当需要把精确率和召回压成**一个数**便于排序模型时，用它们的**调和平均**，即 F1 分数：

F1 = 2 · (precision · recall) / (precision + recall)

更一般地，F_beta 用参数 β 调节召回相对精确率的权重（β>1 偏重召回，β<1 偏重精确率）：

F_beta = (1 + β²) · (precision · recall) / (β² · precision + recall)

用调和平均而非算术平均，是为了**惩罚极端不均衡**——只有当精确率和召回**都**高时 F1 才高。举例：精确率 1.0、召回 0.01（只敢判一个最有把握的正例）的模型，算术平均是 0.505 看着还行，但 F1 = 2·(1·0.01)/(1.01) ≈ 0.02，如实反映它几乎没用。β 的取法：F2（β=2）把召回看得比精确率重（筛查场景），F0.5 反之（推荐/检索里重精确率）。初学者要记住 F1 的两个隐含前提：它**仍然依赖阈值**（因为 P、R 依赖阈值），且它**完全不看 TN**——所以 F1 天然聚焦正类、适合不平衡任务，但也意味着"负类判得多好"不进 F1。

### 12.2.4 PR 曲线与平均精确率 AP

要摆脱单一阈值，把阈值从高到低扫一遍，每个阈值算一对 (recall, precision) 并连成线，就是**精确率-召回曲线（PR 曲线）**。横轴召回、纵轴精确率，曲线越靠右上越好。把曲线下面积汇总成一个阈值无关的数，sklearn 用**平均精确率 AP**（average precision）：

AP = Σₙ (Rₙ − Rₙ₋₁) · Pₙ

即以召回的增量为权、对精确率做加权求和（一种数值稳健的曲线下面积，避免了梯形插值的乐观偏差）。

PR 曲线的关键性质是它的"随机基线"**等于正类流行率**——一个瞎猜的模型，AP≈正类占比。本次实证里正类占比 0.10、随机基线就是 0.10，而模型 AP=0.607，明显高于基线。这正是 PR 曲线在**极度不平衡**下比 ROC 更有信息量的原因（详见 12.3.3）：当负类海量时，ROC 的横轴 FPR 分母（TN+FP）巨大，少量 FP 几乎不改变 FPR，ROC 看着仍很漂亮；而 PR 的精确率分母是 TP+FP，少量 FP 就会明显拉低精确率，忠实暴露"捞上来一堆假正例"的问题。初学者选择口诀：**正类稀有且你在乎正类，优先看 PR 曲线/AP；类别大致平衡，ROC/AUC 也够用**。注意 AP 与另一个历史指标"11 点插值 AP"数值上不同，报告时应说明用的是哪种。

### 12.2.5 阈值不是模型的一部分——选阈值的纪律

**决策阈值是部署时的业务选择，不是模型训练出来的**。模型学的是分数 `s(x)`，把分数切成类别的阈值 `t` 应当根据业务的误报/漏报代价、或目标召回/精确率，在**验证集**上单独选定，绝不能在测试集上调阈值再用测试集报成绩（那是泄漏，见 12.5）。

很多库/教程默认阈值 0.5，这只在**类别平衡且概率已校准**时才是合理默认；不平衡或未校准时，0.5 往往不是好切点。正确流程是：在验证集上画 PR 曲线或算不同阈值的代价，选出满足业务约束（如"召回≥0.9 的前提下精确率最高"）的阈值，固定下来，再到测试集报这个固定阈值下的 P/R/F1。初学者最常见的错就是把"选阈值"和"报成绩"用了同一批数据，导致乐观偏差。

### 12.2.6 classification_report 的读法

scikit-learn 的 `classification_report(y_true, y_pred)` 是实践里最常用的一屏汇总，把每个类的精确率、召回、F1、支持数（该类真实样本数 support），以及 accuracy、macro avg、weighted avg 一次列出。它是 12.1–12.2 度量的实现载体，读它时套用前面的语义即可。

每一行是"把该类当正类"算出的 P/R/F1；`support` 让你一眼看出类别是否不平衡；底部 `accuracy` 是整体判对率（多分类下等于 micro 平均），`macro avg` 各类等权（关心稀有类看这行）、`weighted avg` 按 support 加权（接近 accuracy）。它默认在**你已经选定的阈值**（`predict` 的硬标签）下计算，所以换阈值要先自己二值化再传入。`⚙演进快·锚版本 sklearn 1.9.0`——参数默认（如 `zero_division` 的默认行为）属实现细节，跨版本可能微调，以当前版本文档为准。

## 12.3 ROC / AUC

### 12.3.1 ROC 曲线：TPR 对 FPR

受试者工作特征曲线（ROC curve）也是"扫过所有阈值"的曲线，但两根轴换成**真正例率 TPR（=召回/敏感度）**与**假正例率 FPR（=1−特异度）**：

TPR = TP / (TP + FN)

FPR = FP / (FP + TN)

横轴 FPR、纵轴 TPR，每个阈值对应曲线上一点。左下角 (0,0) 是"阈值极高、全判负"，右上角 (1,1) 是"阈值极低、全判正"，曲线越贴近**左上角**越好，对角线 y=x 是随机猜测。

ROC 的直觉：调低阈值时，你同时抓回更多真正例（TPR 涨）和误伤更多真负例（FPR 涨），曲线就是这两者随阈值联动的轨迹。一个完美模型能在 FPR=0 时就把 TPR 拉到 1（曲线经过左上角）；随机模型的 TPR 和 FPR 同步上涨（贴着对角线）。要点是 ROC 的**两根轴各自在一类内部归一化**（TPR 只看真实正例、FPR 只看真实负例），所以 ROC 曲线本身**不随类别比例变化**——同一个模型，把负类样本复制十倍，ROC 曲线不动。这既是它的优点（对先验鲁棒），也是 12.3.3 要讲的陷阱来源。

### 12.3.2 AUC 的定义与排序解释

把 ROC 曲线下的面积汇总成一个数就是 **AUC**（Area Under the ROC Curve），范围 [0,1]，0.5=随机、1=完美。AUC 有一个极其重要且优美的概率解释——它等于"**随机抽一个正例和一个负例，模型给正例打的分高于负例**"的概率：

AUC = P( s(x⁺) > s(x⁻) )

其中 x⁺ 是随机正例、x⁻ 是随机负例（并列时算 0.5）。这个恒等式使 AUC 等价于 Mann-Whitney U 统计量 / Wilcoxon 秩和的归一化形式。

这个解释把 AUC 的本质讲透了：**AUC 度量的是排序质量，而非某个阈值下的判对率**。它只关心模型有没有把正例排在负例前面，完全不管你最终把阈值切在哪、也不管分数的绝对数值对不对（只看相对顺序）。本次实证同时用 `roc_auc_score`（沿曲线积分）和"直接数正例分>负例分的比例"（Mann-Whitney 方式）两条独立路径，都得到 0.902，互相印证了这个恒等式。初学者据此可以记住：**AUC 高 = 模型排序好 = 存在某个阈值能同时兼顾 TPR 和 FPR**；但 AUC 高**不**保证默认阈值 0.5 好用，也**不**保证概率数值可信（那是校准，12.4）。

### 12.3.3 阈值无关性与 ROC vs PR 的选择

ROC/AUC 最大的卖点是**阈值无关**——你不必预设阈值就能比较模型的整体排序能力，这在"阈值待定"或"只想比模型好坏"时非常方便。但正因为它对类别比例鲁棒，在**极度不平衡**任务里 ROC 会给出**过于乐观**的印象，这是一个必须显式记住的分歧/陷阱。

原因在分母。FPR = FP/(TN+FP)，当负类海量（TN 极大）时，哪怕模型产生了成百上千个假正例，FPR 的分母被巨大的 TN 稀释，FPR 几乎不涨，ROC 曲线看起来仍紧贴左上、AUC 仍很高。可从用户视角看，"捞上来的正例里混了大量假正例"是致命的——而这恰恰被 PR 曲线的精确率 =TP/(TP+FP) 忠实捕捉（分母不含 TN）。所以在正类稀有、且你关心正类质量的场景（欺诈、罕见病、信息检索），**PR 曲线/AP 比 ROC/AUC 更有区分力**（Saito & Rehmsmeier 2015、Davis & Goadrich 2006 是这一主张的代表）。反过来，类别大致平衡、或你同等关心两类错误时，ROC/AUC 是合适且解释性好的默认选择。口诀：**平衡看 ROC，稀有正类看 PR**。

### 12.3.4 AUC 的陷阱与变体

除了不平衡下的乐观印象，AUC 还有几个初学者需知的边界。第一，AUC 只看**排序**、完全不看**校准**——两个模型可以 AUC 相同，但一个概率数值可信、一个系统性过度自信，AUC 对此毫无察觉（12.4 专治）。第二，AUC 是一个把整条曲线压成一个数的**汇总量**，可能掩盖曲线形状差异——两条相交的 ROC 曲线可以有几乎相同的 AUC，但在你实际关心的 FPR 区间（比如"只容忍 FPR≤1%"）表现天差地别，此时应看**部分 AUC（partial AUC）**或直接看目标工作区间的那段曲线。第三，多分类的 AUC 需指定 One-vs-Rest 或 One-vs-One 并选平均口径（sklearn `roc_auc_score` 的 `multi_class=` 与 `average=`），语义随选择变化。

实践建议是把 AUC 当"体检指标之一"而非唯一裁判：报告 AUC 的同时，给出你实际部署工作点（选定阈值）下的 P/R/F1，并单独检查校准。`⚙演进快·锚版本 sklearn 1.9.0`——多分类 AUC 的默认平均等 API 细节以当前版本文档为准。

## 12.4 概率校准

### 12.4.1 什么是校准——区分度 ≠ 校准

校准（calibration）关心的是模型输出的概率**数值本身是否可信**，与前面所有度量正交。一个模型是良好校准的，若"它说 70% 的那批样本里，确实约 70% 是正例"。形式上，对模型给出概率 p 的样本子集，其真实正例频率应≈p：

P( y = 1 | s(x) = p ) ≈ p，对所有 p

区分度（discrimination，即 AUC/排序）和校准是**两个独立的维度**：模型可以排序完美（AUC=1）却概率全错（比如把所有正例判 0.51、负例判 0.49，排序对但数值离谱），也可以排序平庸却校准良好。

为什么这很重要？很多下游决策直接**用概率数值**做算术——期望收益 = 概率 × 收益、按风险概率排优先级、给多个模型的概率做加权融合、设定"概率>0.8 才自动放行"的业务阈值。这些都要求概率**当真**，而不只是排序对。一个 AUC 很高但系统性高估的模型，会让所有基于概率的期望计算偏乐观。初学者要建立的核心认知：**AUC 高不代表概率能直接用**——想用数值，必须单独检查并可能修正校准。

### 12.4.2 可靠性图（reliability diagram）

诊断校准的标准工具是**可靠性图**（reliability diagram / calibration curve）。做法：把预测概率分成若干箱（如 [0,0.1),[0.1,0.2),…），每箱内算"平均预测概率"（横轴）与"实际正例频率"（纵轴），连点成线。完美校准的线落在对角线 y=x 上；线在对角线**下方**说明模型**过度自信**（预测概率比真实频率高），在**上方**说明**信心不足**。

本次实证的 5 分箱可靠性表（预测均值 → 实际频率）为约 0.097→0.010、0.298→0.020、0.490→0.116、0.680→0.471、0.889→0.875，可见中低段预测明显高于实际（该模型在中段偏过度自信），高段较贴合——这就是可靠性图要暴露的信息。初学者要注意两个实操点：分箱数是超参（太少看不出形状、太多每箱噪声大），且**等宽分箱**在概率分布不均时某些箱样本极少、频率估计不稳，sklearn `calibration_curve` 提供 `strategy='quantile'`（等频分箱）作为更稳的替代。可靠性图是"看"校准，下一节的 Brier/ECE 是"量化"校准。

### 12.4.3 校准指标：Brier 分数与 ECE

把校准好坏压成一个数，最常用 **Brier 分数**——预测概率与 0/1 真值的均方误差：

Brier = (1/N) Σ (pᵢ − yᵢ)²

Brier 越小越好，且可分解为"校准项 − 精细度项 + 不可约项"（Murphy 分解），因此它**同时**惩罚校准差和区分度差，是一个综合的概率评分（严格适当评分规则 proper scoring rule）。另一个直接量化校准的是**期望校准误差 ECE**——可靠性图里各箱"预测均值与实际频率之差"按样本量加权求和：

ECE = Σ_b (n_b / N) · | acc(b) − conf(b) |

其中 acc(b) 是箱 b 的实际正例频率、conf(b) 是箱 b 的平均预测概率。

这里要把两者辨析清楚。Brier 是**适当评分规则**——只有当你报告真实概率时它才最小，因此可直接作为训练/选型目标；但 Brier 混合了校准与区分度，Brier 低不能单独归因于校准好。ECE 更"纯"地只测校准，但它**依赖分箱**（箱数/箱边界一变数值就变），且对区分度完全不敏感（一个把所有样本都判成全局正类比例的"废但校准"模型 ECE 可以为 0）。所以实践里两者配合：用可靠性图看形状、Brier 看综合、ECE 看纯校准偏差。本次实证 Brier≈0.128（该合成任务）。`⚙演进快`——ECE 的具体估计方式（等宽/等频、箱数）在文献里不统一，报告时须写清。

### 12.4.4 Platt scaling（sigmoid 校准）

当诊断出模型未校准，用**事后校准**在不重训主模型的前提下修正概率。**Platt scaling**（sklearn 里 `method='sigmoid'`）假设"真实概率是模型分数经过一个 logistic sigmoid 变换得到"，在一个独立的校准集上拟合两个标量参数 A、B：

p_calibrated = 1 / (1 + exp(A · s(x) + B))

它本质是在模型原始分数 `s(x)` 上再套一层一维逻辑回归，把分数单调地压/拉到校准的概率。

Platt scaling 的特点是**参数少（仅 2 个）、抗过拟合、样本需求小**，因此在校准数据有限时是稳妥默认；代价是它假设了 sigmoid 形状的失真，若真实校准误差不是这个形状则修正不彻底。它最初为 SVM 输出（无概率含义的间隔分数）设计，现广泛用于任何输出未校准分数的模型。初学者记住定位：Platt = 参数化、平滑、数据省、但形状受限。

### 12.4.5 Isotonic regression（保序回归校准）

另一条路是**保序回归校准**（sklearn `method='isotonic'`），它不假设任何函数形状，只要求校准映射是**单调不减**的，然后拟合一个分段常数的单调阶梯函数，把原始分数映射到校准概率。它求解的是在单调约束下的最小二乘：

minimize Σ (yᵢ − f(sᵢ))²，subject to f 单调不减

用 PAV（pool adjacent violators）算法求解。

isotonic 比 Platt **更灵活**（能修正任意单调形状的失真），因此在数据充足时校准更准；但正因灵活，它在**小样本上容易过拟合**校准集、且只能输出阶梯状概率（分辨率受箱限制）。经验法则（sklearn 文档与 Niculescu-Mizil & Caruana 2005）：**校准样本少（约 <1000）用 Platt/sigmoid，样本充足用 isotonic**。本次实证在 4000 样本任务上二者 Brier 均≈0.061、旗鼓相当——说明样本够时两法都行、差异不大，差异主要在小样本或强非 sigmoid 失真时显现。

### 12.4.6 校准的纪律——独立校准集与防泄漏

校准的最大陷阱是**在训练模型的同一批数据上拟合校准映射**——这会乐观，因为模型在训练数据上的分数分布与它在新数据上的不同（尤其过拟合模型）。正确做法是校准参数在**独立的校准集**（或用交叉验证方式）上拟合。scikit-learn 的 `CalibratedClassifierCV` 正是为此设计：用 `cv=` 折交叉方式，在每折的一部分训练基模型、另一部分拟合校准，避免用同批数据既训练又校准。

一个必须记的时效性 API 变化：`⚙演进快·锚版本 sklearn 1.9.0`——`SVC(probability=True)` 的内置 Platt 校准参数在 1.9 已**弃用**，官方推荐改用 `CalibratedClassifierCV(SVC(), ensemble=False)`（本次实证时确实收到该 FutureWarning，将于 1.11 移除）。这类默认与 API 属实现细节、跨版本会变，以当前版本文档为准、不凭记忆填。

关于现代深度网络的补锚 `⚙演进快·锚 2017 论文时点`：Guo et al. 2017 系统发现现代深度神经网络（尤其高准确率的大模型）**系统性地过度自信**——预测概率显著高于实际正确率，且比老式浅网络更严重；他们提出**温度缩放**（temperature scaling，Platt 的单参数简化，用一个标量 T 除 logits 再 softmax）作为极简有效的事后校准。这是一个仍在演进的活跃议题（大模型、分布漂移下的校准），结论不宜当定论，深度学习语境归 L6-03。

## 12.5 数据泄漏与划分纪律

### 12.5.1 什么是数据泄漏

数据泄漏（data leakage）指**训练过程中用到了在真实预测时刻不该拥有的信息**，导致评估分数系统性偏高、模型上线后性能骤降。它是本大主题的效力前提：前四节所有度量，只有在"评估数据对模型完全陌生"时才作数；一旦泄漏，AUC=0.99 也可能是幻觉。

泄漏的本质是**信息从测试/未来/标签渗进了训练或预处理**。它比"选错度量"更隐蔽、更危险——选错度量至少数字是真的，泄漏则让数字本身是假的。初学者要建立的第一直觉是：任何在**看到测试数据/未来数据/标签之后**才能得到的东西，都不许喂给模型或用于特征构造。评估要模拟的是"模型面对一个它此前完全没见过的新样本"这一真实处境。

### 12.5.2 泄漏来源清单

泄漏有若干典型来源，广度上应列全：

预处理泄漏——在划分**之前**对全量数据做标准化、缺失值填补、PCA、特征选择等，使训练侧偷看了测试侧的统计量（均值/方差/被选特征）。

目标泄漏（target leakage）——特征里混入了"只有知道标签才能得到"的信息，例如用"是否已理赔"预测"是否出险"、用就诊后才录入的字段预测入院诊断、用未来才发生的事件当特征。

时间泄漏——时间序列里用未来信息预测过去，或随机洗牌打乱了时序，使训练集含有测试期之后的数据。

分组泄漏——同一实体（同一病人、同一用户、同一句子的多帧）的样本被随机拆到训练和测试两侧，模型靠"认出这个实体"而非泛化取巧。

重复/近重复泄漏——数据集里有重复或近重复样本被分到两侧（网页去重不彻底、数据增强后原图与增强图分离）。

多次窥探测试集——反复用测试集调参/选模型，等于把测试集的信息一点点"训练"进你的决策，测试集不再无偏（"多重比较/测试集过拟合"）。

这些的共同点都是**信息越界**。目标泄漏最难查、危害最大，因为它藏在特征语义里、指标看着完美，需要对每个特征追问"这个值在预测时刻真的能拿到吗、它是不是标签的下游产物"。

### 12.5.3 预处理泄漏与 Pipeline 防线

最常见也最容易犯的是预处理泄漏——初学者习惯"先把整个数据集标准化/填补/降维，再划分训练测试"，这就让标准化用的均值方差、填补用的中位数、PCA 的主成分、特征选择选中的列，全都**吸收了测试集的信息**。正确顺序永远是**先划分，再在训练集上 `fit` 预处理器，然后只 `transform` 测试集**。

scikit-learn 的防线是 `Pipeline`：把预处理器和模型串成一个整体，`fit` 时预处理只在训练侧学参数、`predict` 时对测试侧只做变换。在交叉验证里，`Pipeline` 保证每一折的预处理都**只在该折的训练部分**拟合——这是防止"交叉验证中预处理泄漏"的关键机制（12.5.6 用实证坐实其威力）。ESL §7.10.2 专门用"错误的交叉验证方式"讲了这个陷阱：先在全量数据上按与标签的相关性选特征、再交叉验证，会得到严重乐观（甚至在纯噪声上也很高）的估计。记住口诀：**任何 `fit` 只能看训练数据；测试数据只准被 `transform`，永远不参与学任何参数**。

### 12.5.4 划分纪律——随机 / 分层 / 分组 / 时间序列

划分方式必须匹配数据结构，选错就是泄漏或估计偏差的温床：

普通随机划分/KFold——假设样本独立同分布、可交换，适合无结构的表格数据。

分层划分 StratifiedKFold——按类别比例分层，保证每折的正负类比例与整体一致；**不平衡分类必须用分层**，否则某折可能几乎没有正类，度量剧烈波动甚至无法计算。

分组划分 GroupKFold——按"组"（病人 ID、用户 ID、文档 ID）划分，保证同一组的样本不跨越训练/测试边界，专治分组泄漏。

时间序列划分 TimeSeriesSplit——训练集永远在测试集之前（前向滚动），绝不用未来预测过去，专治时间泄漏；时间序列**禁止**随机洗牌划分。

选择的判据是问"我的样本之间有没有结构"：有类别不平衡→分层；有实体重复→分组；有时间顺序→时序划分；三者可能叠加（如按病人分组且保持时序）。初学者最常见的错是对不平衡数据用普通随机划分、对时间序列用随机划分——前者让度量方差大、后者直接泄漏未来。sklearn 提供对应的 `StratifiedKFold`/`GroupKFold`/`StratifiedGroupKFold`/`TimeSeriesSplit`。

### 12.5.5 三路划分、嵌套交叉验证与"只碰一次"的测试集

超参选择也会泄漏。若用同一份验证集**反复**调超参并选最优，验证集就被"训练"进了超参选择，验证分数变得乐观。规范做法是**三路划分**——训练集（学参数）、验证集（选超参/选模型/选阈值）、测试集（最后一次性报告泛化）；测试集应当**只在全部决策定稿后碰一次**，用完不再回头调整。

当数据不足以三分、或要同时做超参搜索又要无偏估计泛化时，用**嵌套交叉验证**：外层 CV 估计泛化性能，内层 CV 在外层每折的训练部分独立做超参搜索——内外层的数据严格隔离，使"选超参"和"估性能"不共享数据。它比单层 CV 计算贵，但给出的泛化估计才是诚实的。初学者的底线纪律：**测试集是一次性资源**，任何"看了测试分数不满意就回去改模型/改特征/改阈值"的循环，都在把测试集变成第二个验证集，最终报告的数字会系统性偏高（这也是 12.5.2 的"多次窥探"泄漏）。

### 12.5.6 交叉验证中的泄漏——特征选择、重采样、标准化的位置

交叉验证里最隐蔽的泄漏是把某些步骤放在了循环**外面**。三个高发点：特征选择（在全量数据上选特征再 CV）、重采样（在划分前对全量做 SMOTE/过采样，使合成样本的"近邻"跨越训练测试边界）、标准化/填补（在全量上 fit）。它们的共同错误是让某个步骤看到了本折测试部分的信息。正确做法是把每一个"从数据学东西"的步骤都塞进 `Pipeline`，让它们在每折的训练侧独立执行。

本次实证把这个陷阱做成了最有冲击力的对照：造一份 **200 样本 × 10000 特征的纯噪声**数据（标签与所有特征完全无关，真实泛化准确率必然≈0.5）。做法 A（泄漏）先在全量数据上 `SelectKBest` 挑出与标签"最相关"的 20 个特征、再做 5 折 CV——得到 **0.825** 的准确率，一个天大的假象，因为"最相关的 20 个特征"是利用了包括测试折在内的全部标签挑出来的。做法 B（正确）把 `SelectKBest` 放进 `Pipeline`、让特征选择在每折训练侧独立进行——准确率回落到 **0.475**（≈随机），如实反映"纯噪声无可学"。0.825 vs 0.475 的鸿沟，正是 ESL §7.10.2 警告的"错误的交叉验证方式"，也是初学者最该刻进肌肉记忆的一课：**先划分，任何学习性步骤只在训练侧发生，交叉验证里也不例外**。
