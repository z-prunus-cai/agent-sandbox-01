## 6.1 注意力机制（加性 vs 点积）

### 6.1.1 注意力要解决的问题

注意力是一种"按相关性加权求和"的机制：给定一个查询（query），它去和一组键（key）逐一比相关性，得到一组权重，再用这组权重对相应的值（value）做加权平均，输出一个上下文向量。核心一句话——输出是"值的加权平均，权重由查询和键的匹配度决定"。

它最早是为序列到序列翻译提出的（Bahdanau 等人 2015）。在此之前，编码器要把整个源句压进一个固定长度向量再交给解码器，长句信息被挤压丢失。注意力让解码器在生成每个目标词时，都能"回头看"源句所有位置、动态地聚焦到最相关的几个词上，从而绕开固定瓶颈。这也是"注意力"这个名字的直觉来源：像人读句子时视线在关键词上停留。

翻译"猫 坐 在 垫子 上"到英文，生成 "mat" 时，注意力权重应当集中在源端"垫子"上，其余词权重接近 0；生成 "cat" 时权重转移到"猫"。权重是软的（softmax 归一化、和为 1），不是硬性只选一个，所以叫"软注意力"。

### 6.1.2 加性注意力（Bahdanau 型）

加性注意力用一个带 tanh 的小前馈网络来算查询与键的匹配分数。若查询为 q、键为 k，则打分函数形如

score(q, k) = vᵀ · tanh(W_q · q + W_k · k)

其中 W_q、W_k、v 都是可学习参数。把 q 和 k 先各自线性变换、相加、过 tanh、再投影到标量，得到一个分数；对所有键的分数做 softmax 得权重。

它叫"加性"是因为 q 和 k 是相加后再喂进非线性，而不是直接相乘。好处是 q 与 k 的维度可以不同（各自有投影矩阵去对齐），且非线性打分表达力略强；代价是每一对 (q, k) 都要过一次小网络，无法直接用一个大矩阵乘法批量算，在长序列上慢、占显存。

### 6.1.3 点积注意力（Luong 型）与两者取舍

点积注意力直接用查询和键的内积当匹配分数

score(q, k) = qᵀ · k

内积天然衡量两个向量的"方向一致性"：越同向、内积越大、越相关。它没有额外参数，且一整批查询对一整批键的所有分数可以写成一次矩阵乘法 Q·Kᵀ，能吃满 GPU 的矩阵乘加速。

两种打分在理论表达力上接近，但工程差异巨大：原论文明确指出，点积注意力"在实践中快得多、省内存得多，因为可用高度优化的矩阵乘法实现"，这正是 Transformer 选点积而非加性的直接理由。分歧点在小维度下：当维度 d_k 较小时，加性注意力效果略优于未缩放的点积；但当 d_k 变大，点积数值会膨胀（见 6.2），需要加缩放来救，缩放后点积在大维度下反而更好、且更快。这就引出了下一节的"缩放点积注意力"。

不要把"点积注意力"和"自注意力"混为一谈。点积/加性说的是"怎么打分"，自注意力说的是"Q、K、V 从哪来"（都来自同一序列自身）。二者是正交的两个维度。

## 6.2 缩放点积注意力（QKV）

### 6.2.1 QKV 三元组的角色

自注意力把每个输入向量投影成三份：查询 Q、键 K、值 V，各由一个可学习矩阵得到

Q = X·W_Q,  K = X·W_K,  V = X·W_V

其中 X 是输入（形如 序列长度 × d_model 的矩阵）。同一个词既是别人的"被查对象"（提供 K、V），也主动去查别人（提供 Q）。把 Q、K、V 分开，是为了让"用什么来匹配（K）"和"匹配上之后取回什么（V）"解耦——检索键和检索内容可以不一样，表达更灵活。

打个数据库检索的比方：Q 是你的查询词，K 是每条记录的索引标签，V 是记录的实际内容。注意力就是"软检索"：不是精确命中一条，而是按查询与各标签的相似度，把所有内容按权重混合返回。

### 6.2.2 核心公式与 √d 缩放

缩放点积注意力的完整公式独占一行：

Attention(Q, K, V) = softmax( Q·Kᵀ / √d_k ) · V

先算 Q·Kᵀ 得到 序列长 × 序列长 的分数矩阵（第 i 行第 j 列 = 第 i 个查询与第 j 个键的内积），除以 √d_k 缩放，对每一行做 softmax 得到权重（每行和为 1），再乘 V 得到每个位置的上下文输出。这里 d_k 是每个头里键向量的维度。

为什么要除 √d_k：当 d_k 较大时，两个向量的内积是 d_k 个乘积之和，其数值方差随 d_k 线性增长、量级变大。过大的分数喂进 softmax，会把权重推到接近 one-hot 的极端（一个接近 1、其余接近 0），此时 softmax 的梯度几乎为 0，反传时梯度消失、训练卡住。除以 √d_k 把分数方差拉回大约 1 的量级，让 softmax 停在梯度健康的区间。原论文正是以"抵消大 d_k 下点积增大、避免 softmax 落入小梯度区"来解释这个缩放因子的。

设 q、k 的各分量独立、均值 0、方差 1，则 qᵀk 的方差约为 d_k；除以 √d_k 后标准差回到约 1。这就是为什么缩放因子取 √d_k 而不是别的数。

softmax 是"按行"做的，不是对整个矩阵拉平做；缩放是除以 √d_k（键/查询维度的平方根），不是除以序列长度，也不是除以 d_model。

### 6.2.3 自注意力 vs 交叉注意力

当 Q、K、V 都来自同一个序列，叫自注意力（self-attention），序列内每个位置互相看，这是 Transformer 编码器和解码器第一层注意力的形态。当 Q 来自一个序列、K/V 来自另一个序列，叫交叉注意力（cross-attention），典型用在编码-解码结构里：解码器用自己的状态作 Q，去查编码器输出的 K/V，从而"读源句"。

自注意力让 Transformer 能一步到位建立任意两个位置间的直接联系（路径长度 O(1)），这与 RNN 必须逐步传递（路径长度 O(序列长)）形成对比，也是它更擅长长依赖、更易并行的根源。代价是分数矩阵是 序列长 × 序列长，计算和显存随序列长度平方增长（O(n²)），长上下文时这成为主要瓶颈——后续大量注意力变体都在攻这个平方复杂度。

## 6.3 多头注意力

### 6.3.1 多头的动机与结构

多头注意力把注意力并行做多次（多个"头"），每个头在一个较低维的子空间里独立算一遍缩放点积注意力，最后把所有头的输出拼接、再过一个线性层融合。结构写成

head_i = Attention(Q·W_Q^i, K·W_K^i, V·W_V^i)

MultiHead(Q, K, V) = Concat(head_1, …, head_h) · W_O

每个头有自己的一套投影矩阵 W_Q^i、W_K^i、W_V^i，把输入投到维度 d_k = d_model / h 的子空间；h 个头各输出一个 d_k 维向量，拼起来恰好回到 d_model 维，再乘输出投影 W_O。

直觉是"分工看不同关系"：一个头可能专注句法上的主谓关系，另一个专注指代（代词指向谁），再一个专注局部相邻词。单个注意力只能算一种加权平均、容易把不同关系平均糊在一起；多头让模型在多个表示子空间里并行地关注不同位置的不同信息，然后汇总。

### 6.3.2 维度守恒与原论文取值

关键的工程约定是"总维度守恒"：单头维度 d_k 取 d_model / h，所以 h 个头拼起来仍是 d_model，多头的总计算量与一个 d_model 维单头大致相当，不额外变贵。原论文取 d_model = 512、h = 8、每头 d_k = d_v = 64（512 / 8 = 64）。这些是原论文基础模型的取值，现代模型的 d_model、头数、每头维度按规模各异，不应把 512/8/64 当成通用默认——具体数值随模型而定，此处只锚 2017 原版。⚙演进快·锚版本·随时变 @2026-08-01

多头不是"把注意力算 h 遍再平均"，而是每个头在不同子空间、拼接后经 W_O 融合；W_O 这一步不可省，它负责把各头的信息重新混合回 d_model 空间。另一个常见误解是"头越多越好"——头数与每头维度是此消彼长的权衡（总维度固定），过多头会让每头维度过小、单头表达力下降。

## 6.4 位置编码

### 6.4.1 为什么需要位置编码

自注意力本身对位置"无感"：它把输入当成一个集合，打乱输入顺序、输出也只是相应打乱，不改变每个词算出的表示（这叫排列等变）。但语言里"猫追狗"和"狗追猫"意思相反，顺序至关重要。位置编码就是把每个位置的顺序信息显式注入进去，让模型能区分"第几个词"。

这与 RNN 形成鲜明对比：RNN 逐步处理、顺序天然编码在递推里；Transformer 为了并行放弃了递推，就必须另外补上位置信息。

### 6.4.2 正弦位置编码（原论文）

原论文用固定的正弦/余弦函数生成位置编码，加到词嵌入上。对位置 pos、维度下标 i，公式独占行：

PE(pos, 2i)   = sin( pos / 10000^(2i / d_model) )

PE(pos, 2i+1) = cos( pos / 10000^(2i / d_model) )

即偶数维用 sin、奇数维用 cos，不同维度对应不同波长的正弦波，波长从短到长构成一个谱（低维变化快、高维变化慢），像多位数的"时钟表盘"。常数 10000 决定最长波长。这个编码是固定的、无需学习。

它的巧妙之处是便于表达相对位置：任意两个位置的编码之间存在固定的线性变换关系（可由三角恒等式推出），模型据此较容易学会"相隔 k 个位置"这类相对关系。另一个好处是它对训练时没见过的更长序列有一定外推能力（因为是连续函数，可直接算任意 pos）。

正弦位置编码是加到词嵌入上（相加），不是拼接；且它作用在输入端一次，不是每层都重新加。

### 6.4.3 可学习位置编码与现代做法（RoPE 等）

除了固定正弦编码，另一条路线是可学习绝对位置编码：给每个位置一个可训练的向量，随模型一起学（BERT、原始 GPT 系采用）。原论文也做过对照，报告固定正弦与可学习两种效果相近，因其简洁且可能利于外推而选了正弦。这是原论文内部的一个明确对照点。

⚙演进快·锚版本·随时变 @2026-08-01：位置编码是 Transformer 演进最活跃的部件之一，现代主流已从"加在输入端的绝对编码"转向"注入进注意力打分的相对编码"。当前被广泛采用的是旋转位置编码 RoPE（Su et al. 2021, RoFormer）：它不给嵌入加向量，而是按位置把查询和键向量在成对坐标上旋转一个与位置成正比的角度，使注意力分数只依赖两个位置之差（相对位置），且不引入可学习参数。据多篇 2025 综述，RoPE 已成为 Llama、Mistral、PaLM、GLM 等主流大模型的默认位置方案，因其参数量为零、天然相对、且配合角度缩放能把训练时的短上下文外推到长得多的推理上下文。另有 ALiBi 等相对偏置方案。这些具体方案的相对优劣随任务和规模而变，此处只登记机制、不排名、不作定论；原论文正弦编码与现代 RoPE 分账记录，二者不是同一时代的同一方案。

## 6.5 掩码（因果 vs 双向）

### 6.5.1 掩码的作用机制

掩码是在 softmax 之前，把注意力分数矩阵中"不允许看的位置"设成负无穷（−∞），这样经过 softmax 后这些位置的权重变成 0，等于让当前位置"看不见"被掩的位置。写成一行：

masked_score = score + M,  其中被禁位置 M = −∞、允许位置 M = 0

因为 exp(−∞) = 0，被掩位置在加权和里彻底不贡献。掩码是控制"谁能注意到谁"的开关。

### 6.5.2 因果掩码（解码器）

因果掩码（也叫前瞻掩码）让每个位置只能注意到自己及其左边（更早）的位置，看不见右边（未来）的位置。分数矩阵被掩成下三角形状：第 i 行只保留第 1..i 列。这用于自回归生成——模型逐个 token 预测下一个词，训练时若能偷看未来词就等于抄答案、学不到真本事；因果掩码保证第 i 个位置的预测只依赖前 i 个词，与推理时"还没生成未来词"的条件一致。GPT 类解码器结构全程使用因果掩码。

一个可自证的最小实验：搭一个小 self-attention，加因果掩码，改动某个靠后位置的输入，检查靠前位置的输出是否完全不变——若不变，说明未来信息确实没泄露到过去，掩码正确。（本机 numpy 可就地验证，属可选加固，不替代来源比对。）

### 6.5.3 双向（编码器）与填充掩码

双向注意力不加因果掩码，每个位置能同时看左右全部位置，适合"理解"类任务（如给整句做分类、抽取），因为理解时整句已知、没有"未来"之说。BERT 类编码器采用双向注意力。这与因果的分歧点在任务性质：生成需因果（防泄露未来）、理解可双向（信息越全越好）。

除因果/双向外还有一种正交的填充掩码（padding mask）：一批序列长度不同、短的补 pad 占位，填充掩码把 pad 位置屏蔽掉，防止真实 token 去注意无意义的填充符。填充掩码和因果掩码可以叠加使用（解码器训练时两者都在）。

因果掩码是"能否看到未来"的问题，填充掩码是"能否看到补位"的问题，二者不同、常同时存在；别把序列变长导致的 pad 屏蔽和自回归的前瞻屏蔽混淆。

## 6.6 Transformer 块（残差 + LN + FFN 组装）

### 6.6.1 一个块的组成

一个 Transformer 块由两个子层堆叠而成：一个多头（自）注意力子层，一个逐位置前馈网络（FFN）子层。每个子层外面都包一层残差连接和层归一化（LayerNorm）。原论文的组装方式（Post-LN）每个子层写成一行：

output = LayerNorm( x + Sublayer(x) )

即先算子层（注意力或 FFN）、把结果加回输入（残差），再做 LayerNorm。两个子层依次串起来就是一个块；把 N 个块堆叠就得到编码器或解码器（原论文 N = 6，编码器解码器各 6 层）。解码器的块多一个交叉注意力子层（查编码器输出），且其自注意力带因果掩码。

### 6.6.2 逐位置前馈网络 FFN

FFN 是一个两层的全连接网络，对序列里每个位置独立、且共享同一套权重地施加。公式独占行：

FFN(x) = W_2 · activation( W_1 · x + b_1 ) + b_2

它先把维度从 d_model 升到一个更大的中间维 d_ff、过一个非线性激活、再降回 d_model。原论文取 d_model = 512、d_ff = 2048（4 倍扩张），激活用 ReLU。直觉是：注意力子层负责"跨位置混信息"，FFN 子层负责"对每个位置的信息做逐点的非线性加工与变换"——一个管交流、一个管深加工，交替进行。⚙注：现代模型 d_ff 倍数、激活函数（如 GELU、SwiGLU）常与原版不同，属演进项，具体取值随模型而定、不作通用定论。⚙演进快·锚版本·随时变 @2026-08-01

### 6.6.3 残差、归一化与其现代变体

残差连接（x + Sublayer(x)）给梯度一条"高速公路"直通底层，缓解深层网络的梯度消失，使堆叠很多层可训（这与大主题3 残差连接的动机一脉相承）。LayerNorm 对每个位置的特征向量做归一化（减均值除标准差再缩放平移），稳定各层输入分布、加速收敛。

一个重要的演进分歧要分账记录：原论文是 Post-LN（LayerNorm 加在残差相加之后，即 LayerNorm(x + Sublayer(x)））。而现代大模型几乎普遍改用 Pre-LN（LayerNorm 加在子层之前，残差路径保持"干净"的恒等通路），写成

output = x + Sublayer( LayerNorm(x) )

Pre-LN 训练更稳、能用更大学习率、对 warmup 依赖更小，因此成为深层大模型的主流；代价是最终性能有时略逊，需在末尾补一个 LayerNorm。此外许多现代模型用 RMSNorm（只按均方根缩放、省去去均值步骤）替代 LayerNorm 以提效。这些是 2017 之后的做法：Post-LN 是原版定论，Pre-LN / RMSNorm 属现代主流但仍在演进，两边都记、以锚定版本为准、不给绝对排名。⚙演进快·锚版本·随时变 @2026-08-01

### 6.6.4 编码器-解码器整体与"就是要跑的那个 model"

把 6.1–6.6 拼起来：输入 token 先过词嵌入 + 位置编码，进入 N 个块堆叠。纯编码器（BERT 式，双向、无因果掩码）擅理解；纯解码器（GPT 式，因果掩码、自回归）擅生成，是当今大语言模型的主流骨架；编码器-解码器（原论文机器翻译式）解码端用交叉注意力读编码端。无论哪种，基本积木都是这里的"多头注意力 + FFN + 残差 + 归一化"块——这正是下游系统课要在硬件上榨性能去跑的那个模型。理解到"块=注意力混信息 + FFN 深加工 + 残差/归一化保训练"，就抓住了主线。

别把"编码器/解码器"与"注意力有没有掩码"割裂看——解码器之所以叫解码器，关键就在自注意力戴了因果掩码；也别以为只有编码-解码结构才配叫 Transformer，纯解码器（GPT 式）同样是 Transformer。
