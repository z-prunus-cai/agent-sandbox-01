## 11.1 视觉任务：检测 / 分割 / 关键点谱系

### 11.1.1 视觉任务谱系的组织逻辑

计算机视觉的核心任务可以按"输出的空间粒度"排成一条谱系：从"整张图给一个标签"（图像分类），到"给出物体的框"（检测），再到"逐像素给标签"（分割），最后到"给出结构化的点/骨架"（关键点）。粒度越细，模型要回答的问题越具体，标注成本也越高。

把它想成回答关于一张图的不同问题会更直观。图像分类回答"这张图里主要是什么"（一个类别）；目标检测回答"有哪些东西、分别在哪"（类别 + 位置框）；分割回答"每个像素属于什么"；关键点估计回答"这个物体的结构点在哪"（例如人体的关节）。同一张街景照片，分类说"街道"，检测框出每辆车和每个行人，分割把路面、天空、车辆逐像素染色，姿态估计给出每个行人的骨架。这条从粗到细的谱系是理解后面所有具体任务的骨架，初学者只要抓住"输出粒度"这一根线，就不会把任务搞混。

### 11.1.2 图像分类（谱系起点）

图像分类是给整张图（或一个图像区域）预测一个类别标签的任务，是视觉任务谱系里输出粒度最粗的一档，也是很多更复杂任务的骨干网络（backbone）预训练来源。

它之所以是"起点"，是因为检测、分割等任务的特征提取部分，通常直接复用在分类任务（如 ImageNet）上预训练好的卷积网络或 ViT，再接不同的"任务头"。也就是说，学会认"整张图是什么"得到的特征，被迁移去解"物体在哪""每个像素是什么"。这正好呼应前面表示学习与迁移学习的主线：分类预训练学到的层次特征是下游视觉任务的通用底座。易错点是把"分类"误当成只是简单任务——实际上它承担了整条谱系的特征供给角色。

### 11.1.3 目标检测（bounding box）

目标检测要同时输出图中每个目标的类别和位置，位置通常用一个轴对齐的矩形框（bounding box）表示，所以一张图的输出是"若干个（类别 + 框）"的可变长集合。

难点在于"数量不定"和"定位 + 分类要同时做"。经典思路分两大流派：两阶段法先生成候选区域再逐个分类回归（R-CNN 系列，如 Faster R-CNN，以精度见长）；单阶段法直接在整图上一次性预测框和类别（YOLO 系列，以速度见长）。更近的一条线是 DETR，把检测重述成"集合预测"问题，用 Transformer 的注意力直接输出一组框，省掉了手工设计的候选框/后处理环节。

一个常见易错点是把"检测"和"分类"混为一谈：检测的输出是带定位的集合，需要额外的定位误差度量（如框的交并比 IoU），评价指标也不同（常用 mAP），这些和纯分类的准确率不是一回事。此处只做谱系登记，具体指标细节属评估主题，不在此展开。

### 11.1.4 语义分割（逐像素分类）

语义分割为图中每个像素预测一个类别标签，把"这张图是什么"细化成"每个像素是什么"，但它不区分同类的不同个体——三个并排的人会被染成同一种"人"的颜色，彼此不分。

直觉上它就是"逐像素的分类"。典型做法用编码器把图下采样成语义特征、再用解码器上采样回原分辨率逐像素打标签（编码器-解码器结构，如 FCN、U-Net 一脉）。它适合关心"区域构成"的场景，例如自动驾驶里分出可行驶路面、人行道、天空。要点是它只回答"类别"，不回答"这是第几个物体"，这正是下一档任务要补的。

### 11.1.5 实例分割（区分个体的逐像素）

实例分割在逐像素给类别的基础上，进一步区分同类的不同个体，为每个物体实例给出独立的像素掩码；通常只关注前景可数物体，对天空、路面这类不可数背景一般不处理。

它可以理解成"检测 + 分割"的结合：既要框出/找出每个物体实例，又要给出该实例精确到像素的轮廓。代表方法 Mask R-CNN 就是在检测框架 Faster R-CNN 上加一个预测掩码的分支。和语义分割对比记忆最省力：语义分割把三个人染成一团，实例分割把三个人染成三种不同颜色并各自给轮廓。

### 11.1.6 全景分割（语义 + 实例统一）

全景分割把语义分割和实例分割统一进一个任务：图中每个像素都要同时得到一个类别标签和一个实例 ID，其中可数物体（如车、人，称 things）区分个体，不可数背景（如天空、道路，称 stuff）只给类别。

它的动机是"不留死角"——语义分割不分个体、实例分割一般丢背景，全景分割要求每个像素都被解释且该分个体的地方分到个体。一种朴素实现是把一个语义分割子网和一个实例分割子网的结果融合，但也有单一网络统一输出的做法。初学者只需记住它是"语义 + 实例"的合集，是这条分割谱系里覆盖最全的一档。

### 11.1.7 关键点 / 姿态估计

关键点估计要在图中定位一组预先定义的结构点，最典型的是人体姿态估计——找出关节点（肩、肘、腕、膝等）的坐标，再按人体拓扑把它们连成骨架；也用于人脸关键点、手部关键点等。

它的输出不是框也不是掩码，而是一组带语义的点坐标（外加它们的连接关系），所以是谱系里"结构化输出"的一档。常见做法是为每个关键点预测一张热力图（heatmap），峰值位置即该点坐标，这样把"回归坐标"转成了"逐像素定位"，训练更稳。多人场景还要额外解决"哪个点属于哪个人"的分组问题。这一档说明视觉任务的输出形态可以非常多样，不止分类/框/掩码。

### 11.1.8 代表模型谱系（演进快，只登记不排名）

⚙演进快·锚版本·随时变（核实 2026-08-01）。视觉任务的代表模型近年迭代很快，此处只登记机制脉络、不排名、不作 SOTA 定论。检测上有从两阶段（R-CNN → Faster R-CNN）到单阶段（YOLO 系列，已多代迭代）再到基于 Transformer 的集合预测（DETR 系）的脉络；分割上除 Mask R-CNN 外，出现了可提示的分割基础模型 Segment Anything（SAM，Meta 2023），用点/框/掩码作提示输出通用掩码，其后续版本（据来源已到 SAM 3，加入文本/概念级提示，2025 年）把分割推向"开放概念"，具体版本能力随时变、以官方发布为准。

这里给初学者的关键心智模型是：视觉领域正从"每个任务一个专用模型"走向"一个可提示的基础模型覆盖多任务"，且越来越多地用 Transformer/注意力替代或补充纯卷积。具体哪个模型现在最强不是本总览要下的结论——凡涉及排名或最新版本能力，都以当期官方文档/论文为准，本报告标"待核"，不据记忆填。

## 11.2 NLP 任务谱系：分类 / 序列标注 / 生成 / QA

### 11.2.1 NLP 任务谱系的组织逻辑

自然语言处理的任务，一种常见组织方式是按"输出结构"分类：整段文本给一个标签（分类）、给每个词/token 一个标签（序列标注）、输出一段新文本（生成），以及更复杂的结构化预测（如问答里输出一个答案片段、翻译里输出对齐的另一种语言序列）。

用"输出形态"这根线去归类最省力：输出是一个标签、还是一串逐词标签、还是一段文本、还是文中的一个片段。抓住这条线，后面的具体任务就都能对号入座。这和视觉那条"输出粒度"的线是同一种思路——先看模型要吐出什么形状的东西。

### 11.2.2 文本分类

文本分类（又称文本归类）给一整段文本预测一个（或多个）预定义类别，是 NLP 里最基础的任务之一，覆盖情感分析、主题分类、垃圾邮件过滤、自然语言推理（判断两句是蕴含/矛盾/中立）等一大类问题。

它的输出是"整段 → 一个标签"，粒度最粗。典型做法是用一个编码器（现代多为预训练 Transformer，如 BERT 一类）把整段文本编码成一个向量，再接一个分类头输出类别概率。这正好复用前面预训练-微调范式的主线：拿预训练好的语言表示，加一个小分类层微调即可。易错点是别把"多类"（互斥选一个）和"多标签"（可同时属多个类）搞混，二者的损失和输出层设计不同。

### 11.2.3 序列标注（NER / 词性标注）

序列标注给输入序列中的每个词/token 都预测一个标签，典型任务是命名实体识别（NER，标出人名、地名、机构、日期等实体）和词性标注（POS，标出名词/动词等），也用于抽取文中的片段。

和文本分类最大的区别在于：分类是"一段一个标签"，序列标注是"每个 token 一个标签"，输出长度随输入变化。为了标出"连续的实体片段"，常用 BIO 之类的标注方案（B 开头、I 内部、O 无关），把"找片段"转成"逐 token 分类"。它是信息抽取、知识图谱构建、问答等下游应用的基础构件。初学者容易忽略"边界"问题——实体是由连续多个 token 组成的片段，标注方案正是为解决片段边界而设计。

### 11.2.4 文本生成

文本生成是根据给定输入或提示产生一段自然语言文本的任务，输出是"一段新文本"而非固定标签，涵盖机器翻译、摘要、对话、续写等。

逐个 token 地预测下一个词，把已生成的部分回喂作为条件，这与前面注意力/Transformer 及自回归生成的内容一脉相承。生成任务的评价比分类难得多——同一个意思有很多种正确说法，所以既有基于重叠的自动指标（如 BLEU、ROUGE，用于翻译/摘要），也越来越依赖人类或模型评审。要点是：生成任务没有唯一正确答案，这决定了它的建模和评估都与分类/标注不同。

### 11.2.5 问答（QA：抽取式 vs 生成式）

问答任务给定问题（有时附一段材料），要求给出答案。经典的抽取式问答（如 SQuAD 风格）把答案限定为材料中的一个连续片段，模型输出该片段的起止位置（一对 token 下标）；生成式问答则直接生成答案文本，不要求答案原样出现在材料里。

两种形式对应两种输出形态：抽取式输出"文中的一个 span（两个下标）"，本质接近序列标注/定位；生成式输出"一段文本"，本质是文本生成。现代大模型多用生成式（配合检索到的材料），但抽取式在需要可溯源、答案必须出自原文的场景仍有价值。初学者要留意这条分界，因为它决定了任务用什么指标评（片段匹配 vs 生成质量）以及答案能否越出原文。

### 11.2.6 其他结构化预测（翻译 / 摘要 / NLI 等）

除上述四大类，还有一批"结构化预测"任务，输出比单标签复杂、又不完全是自由生成：机器翻译（序列到序列，输出另一种语言的对齐序列）、自动摘要（长文 → 短文）、自然语言推理 NLI（句对 → 蕴含/矛盾/中立，常归入分类）、句法/依存分析（输出树结构）等。

把它们单列，是为了提醒初学者 NLP 任务不止"分类/标注/生成/QA"四格——很多任务是这几类的组合或结构化变体。序列到序列（seq2seq）框架是其中的通用骨架：一个编码器读输入、一个解码器生成输出，翻译和摘要都能套进去。这条也呼应前面 seq2seq / 编码-解码的内容。

### 11.2.7 现代趋势：任务统一为"生成/指令"（演进快）

⚙演进快·锚版本·随时变（核实 2026-08-01）。近年 NLP 的一个明显趋势是把传统上分立的任务统一到一个生成式/指令式框架下：不再为每个任务训一个专用模型，而是用一个大语言模型，通过不同的提示（prompt）或指令，把分类、抽取、翻译、摘要、问答都表述成"输入文本 → 输出文本"来解。

一个足够大的预训练生成模型，加上指令微调和上下文学习，就能零样本/少样本地覆盖大量任务，省去为每个任务单独建模。这与前面预训练-微调范式、提示/上下文学习是同一条线的应用落地。给初学者的提醒是：本小节讲的"四大类任务谱系"仍是理解 NLP 的骨架（它刻画了任务本身的输入输出结构），而"用什么模型解"这一层正快速向统一生成范式收敛——具体哪种范式、哪个模型当前最优属演进快内容，本报告不作定论、以当期课程/论文为准。

## 11.3 多模态融合：图文 / 跨模态对齐（CLIP 类）

⚙演进快·锚版本·随时变（本小主题整体标此记号，核实 2026-08-01；多模态方法为 2016 后现代方法、迭代活跃，只讲机制不作定论）。

### 11.3.1 多模态与跨模态对齐（概念）

多模态学习指同时处理并整合来自多种模态的数据——最常见的是图像 + 文本，也扩展到音频、视频等。其核心难题是"跨模态对齐"：让不同模态的表示落到可以互相比较/关联的同一语义空间里，例如让"一张狗的照片"和"a photo of a dog"这句话的向量彼此靠近。

图像和文字本来是两套完全不同的信号（像素 vs 符号），要让机器"看图说话"或"按文字找图"，就得先有一座桥把两边的表示对齐到一起。对齐做好了，很多任务（图文检索、看图问答、按文字生成图）才有共同的地基。这条正是前面表示学习/嵌入主线在跨模态场景的延伸。

### 11.3.2 对比式对齐：CLIP

CLIP（Contrastive Language-Image Pre-training，Radford et al. 2021）用一个图像编码器（ResNet 或 ViT）和一个文本编码器（Transformer），在海量"图-文配对"上用对比损失联合训练：让配对的图和文在嵌入空间里相似度高、不配对的相似度低。据原论文，训练数据为 4 亿（图,文）对。

一个批次里，配对的图文当正样本、其余交叉组合当负样本；训练目标是拉近正样本、推远负样本的相似度（相似度用归一化向量的点积，即余弦相似度）。用符号表示，一张图向量 I 与一段文本向量 T 的匹配打分为

sim(I, T) = (I · T) / (‖I‖ · ‖T‖)

训练最大化正确图文对的该打分、压低错误对的打分。

CLIP 最有名的能力是零样本分类：把候选类别名套进模板句（如 "a photo of a {class}"）过文本编码器得到每类的文本向量，再把待分类图片过图像编码器得到图像向量，取相似度最高的类作为预测——整个过程不需要在目标数据集上再训练。据原论文，其最佳模型（ViT-L/14）在 ImageNet 上达到约 76.2% 的零样本 top-1 准确率。关于"匹配哪个监督基线"，来源存在分歧：原论文的标志性表述是"零样本匹配 original ResNet-50"，部分二手转述则写作"匹配 ResNet-101"——两边都记，以原论文（Radford et al. 2021）的 ResNet-50 表述为准，ResNet-101 说法存疑。初学者最该记住的是机制（对比对齐 + 用文本当"可变的分类器"），而非具体数值；数值随模型版本变，以原论文为准。

### 11.3.3 融合策略：早融合 / 晚融合 / 交叉注意力

多模态模型把不同模态的信息合到一起，大致有几种融合位置。晚融合（late fusion，也叫双塔/对齐式）让各模态各自编码成向量、最后只在向量层面比相似度——CLIP 就是这一路，适合检索/对齐。早融合（early fusion）在较早的层就把模态拼到一起进同一个网络联合处理，适合需要细粒度交互的任务。交叉注意力（cross-attention）则让一个模态去"注意"另一个模态的特征（如让文本 token 去注意图像特征），是很多图文模型做深度交互的手段。

用检索 vs 问答对比最好懂：图文检索只需判断"这张图和这句话配不配"，各自编码再比相似度（晚融合）就够；而看图回答一个具体问题，往往需要文字和图像在网络内部反复交互（交叉注意力/早融合）才答得准。选哪种融合，取决于任务需要多深的跨模态交互。易错点是以为"融合越早越好"——晚融合的双塔结构在大规模检索里因为可离线预存向量而效率极高，各有适用场景。

### 11.3.4 多模态大模型（LLaVA / GPT-4V 类，演进快）

⚙演进快·锚版本·随时变（核实 2026-08-01）。近年主流做法是把一个预训练大语言模型当"主干"，前面接一个视觉编码器（常用 CLIP 的图像编码器），中间用一个投影模块把图像特征映射进语言模型的词嵌入空间，于是图像被当成一串"视觉 token"喂给 LLM，让它像处理文字一样处理图像——LLaVA、GPT-4V（GPT-4 的视觉版）是这一路的代表。据来源，LLaVA-1.5 用 CLIP-ViT-L 作视觉编码器、Vicuna 作语言解码器，中间用一个可训练的 MLP 投影层连接，分"对齐预训练 + 指令微调"两阶段训练。

这类模型 = "会看图的 LLM"，靠"视觉编码器 + 投影桥 + 语言模型"三件套，把图像翻译成语言模型能读的 token，从而支持看图对话、视觉问答、图像描述。据来源，2025–2026 一代出现了不再用"桥接适配器"、而把各模态在单个 Transformer 里早融合的趋势（原生多模态）——但这属活跃演进内容，具体架构、能力、哪家最强随时变，本报告只登记机制、不排名、不作定论；涉及具体模型能力/版本一律标"待核"、以当期官方为准。

### 11.3.5 典型多模态任务

图文检索（给图找文或给文找图，CLIP 类对齐模型的主场）、图像描述生成（image captioning，看图产出一句话）、视觉问答（VQA，就一张图回答自然语言问题）、以及文生图（按文字提示生成图像，属生成模型分支）等。

把它们和前面的融合策略连起来看：检索靠晚融合的对齐（比相似度）；captioning 和 VQA 需要更深的图文交互（交叉注意力/多模态 LLM）；文生图则跨到生成模型（如扩散模型）的地盘。这一小节意在给初学者一张"多模态能干什么"的任务地图，具体每个任务的 SOTA 方法演进快，不在此总览里追最新。

## 11.4 分界：系统化跑起来归 AI/LLM 系统课（本条只做总览）

### 11.4.1 本主题的边界：谱系总览 vs 工程系统化

本大主题（视觉 / NLP / 多模态分支落地）刻意只做"应用分支总览"：讲清各领域有哪些任务、任务的输入输出结构、大致对应哪些深度学习构件。它回答的是"深度学习能往哪落地、每处要解的是什么问题"。

要把这句话讲透，关键是分清两个层次。一层是"任务与模型机制"——本主题覆盖的：检测/分割是什么、CLIP 怎么对齐、多模态 LLM 靠什么三件套。另一层是"把它高效、可靠地跑起来"——例如怎么在有限显存里训练一个大模型、怎么做并行、怎么高吞吐地服务推理、怎么算成本。后者是独立的一大门系统课题，不在本总览里。初学者要建立的边界感是：懂了机制不等于能把它跑在生产系统上，二者是不同层次的知识。

### 11.4.2 划归说明：工程系统化归后续系统课

凡属"系统化跑起来"的内容——显存预算、张量/流水线/数据并行、kernel 优化与 FlashAttention、KV cache 与推理服务、量化、缩放定律、训练后与对齐流水线等——本报告不展开，统一归属后续的 AI/LLM 系统课程去讲。同理，多模态/LLM 在应用层的编排（如检索增强、智能体）也不在本课，归相应的应用课程。

这样切分是为了避免主题膨胀、职责重叠：本主题把"有哪些分支、每支解什么任务、靠什么机制"这张地图画全画清，就完成了它作为总览的使命；"怎么把这些模型真正高效跑起来"是另一门课的主战场。给初学者的收尾提醒：读完本主题你应能对着一个视觉/NLP/多模态需求，说出它属于哪类任务、大致用什么构件——至于把模型高效落地运行的工程栈，请到系统课继续。
