## 3.1 算法概念与伪码

### 3.1.1 算法的定义与基本性质

算法（algorithm）是为完成某项计算或解决某类问题而给出的一个有限、精确的指令序列。Rosen §3.1 给出的定义强调它是「a finite sequence of precise instructions for performing a computation or for solving a problem」。教材进一步列出一个良定义算法通常应满足的若干性质：

- 输入（input）：从一个指定集合接收输入值；
- 输出（output）：对每组输入产生来自指定集合的输出值，即问题的解；
- 确定性（definiteness）：每一步都被精确、无歧义地规定；
- 正确性（correctness）：对每组输入都产生正确的输出；
- 有限性（finiteness）：对任意输入都在有限步后产生输出；
- 有效性（effectiveness）：每一步都能在有限时间内精确执行；
- 通用性（generality）：适用于该问题所有满足输入要求的实例，而非只对某一个特例有效。

初学者最容易忽略的是「有限性」和「有效性」这两条。它们把算法和「一段可能永远跑不完、或者含有无法真正执行的步骤的描述」区分开来。一个直观例子：把「列出所有正整数再从中挑出最大的」当作求最大值的方法就违反了有限性——正整数没有最大值，这段描述永远停不下来，因此不是算法。

「通用性」也常被低估。写出「1+1=2」不是算法，因为它只解决一个特例；而「输入两个整数、输出其和」才是算法，因为它对所有整数对都给出解。判断一段描述是不是算法时，可逐条对照上面的性质。

这些性质是「教辅级别」的判据，不同教材在措辞和条目数上略有出入（见本节末来源比对）；但输入 / 输出 / 确定性 / 有限性 / 有效性这几条几乎是所有版本的共识。

### 3.1.2 伪码约定

伪码（pseudocode）是介于自然语言和真实编程语言之间的一种半形式化描述方式，用来表达算法的逻辑而不纠缠于某一门语言的语法细节。Rosen 在书末附录（Appendix 3）规定了一套自己的伪码约定；MIT 6.042J 与 CLRS 各有一套相近但不完全相同的约定。它们的共同点是：都用赋值、条件（if/else）、循环（for/while）、以及 procedure（过程 / 函数）定义等基本结构，靠缩进或关键字划分语句块。

为什么要用伪码而不是直接写代码？因为算法研究关心的是「解决问题的思路和步骤」，而不是「某门语言里分号该不该加」。伪码剥掉了语言特有的噪声，让不同背景的读者都能读懂同一个算法，也便于做正确性论证和复杂度分析。

一个最小例子（求有限整数序列 a₁,…,aₙ 中的最大值），用与 Rosen 风格一致的伪码写成：

```
procedure max(a1, a2, ..., an: integers)
    m := a1
    for i := 2 to n
        if ai > m then m := ai
    return m   {m is the largest element}
```

初学者的常见误区是把伪码当成「随便写写、看得懂就行」的草稿。恰恰相反：好的伪码在关键处必须和真实代码一样精确（哪个变量被赋什么值、循环边界是闭区间还是开区间），只是省略了与思路无关的语法细节。另一个易错点是不同教材约定不同——例如数组下标从 0 还是 1 开始、赋值用 `:=` 还是 `←`——读一本书的伪码时要先看清它自己的约定，不要跨书混用。

### 3.1.3 示例算法之一：线性搜索

线性搜索（linear search，又称顺序搜索）是最基础的搜索算法：在一个序列中从头到尾逐个比较，直到找到目标元素或走到末尾。它的输出通常是目标元素的位置下标（找不到时约定返回 0 或某个哨兵值）。

```
procedure linear_search(x: integer, a1, a2, ..., an: distinct integers)
    i := 1
    while (i <= n and x != ai)
        i := i + 1
    if i <= n then location := i
    else location := 0
    return location
```

线性搜索的价值在于它「什么前提都不要」：序列不必有序，就能用。它的直觉就是人找东西时最朴素的办法——一个一个看过去。

初学者要留意循环条件里 `i <= n and x != ai` 的短路求值顺序：必须先判断 `i <= n` 再访问 `ai`，否则当 `i` 越过末尾时会去访问不存在的元素。这也是「伪码要精确」的一个具体体现。线性搜索在 3.3 会作为「最坏情形需要 n 次比较」的量级例子再次出现。

### 3.1.4 示例算法之二：二分搜索

二分搜索（binary search）用于**已排序**序列：每一步把待查区间对半砍掉一半，比较目标与区间中点，据此丢弃不可能含有目标的那一半。

```
procedure binary_search(x: integer, a1, a2, ..., an: increasing integers)
    i := 1          {i is left endpoint of search interval}
    j := n          {j is right endpoint of search interval}
    while i < j
        m := floor((i + j) / 2)
        if x > am then i := m + 1
        else j := m
    if x = ai then location := i
    else location := 0
    return location
```

二分搜索比线性搜索快得多，代价是要求输入必须有序。直觉是「每问一个问题就把可能性砍半」：n 个元素最多问约 log₂ n 次就能定位，因为把 n 连续对半砍到 1 所需的次数就是 log₂ n（向上取整）。这正是「猜数字游戏」里每次猜中点的最优策略。

最典型的易错点在于区间边界与中点取整：中点用 floor 还是 ceil、砍半时区间端点更新成 `m` 还是 `m+1`、循环条件用 `<` 还是 `<=`，任何一处不一致都可能造成漏查或死循环。这也是为什么二分搜索虽然思路简单，却是出了名地「容易写错」。它的 log 级量级会在 3.2 的增长层次和 3.3 的复杂度类里反复出现。

### 3.1.5 示例算法之三：排序（冒泡与插入）

排序（sorting）是把序列按某种次序重排的问题，Rosen §3.1 用冒泡排序和插入排序作为示例。

冒泡排序（bubble sort）反复扫描序列，把相邻的逆序对交换，让较大的元素像气泡一样逐趟「浮」到末尾：

```
procedure bubble_sort(a1, ..., an: real numbers with n >= 2)
    for i := 1 to n - 1
        for j := 1 to n - i
            if aj > aj+1 then interchange aj and aj+1
    {a1, ..., an is now in increasing order}
```

插入排序（insertion sort）则像整理手中的扑克牌：依次取出每张牌，把它插入到前面已经排好序的部分中的正确位置。

排序作为示例的意义在于：它是「同一个问题、多种算法、量级各不相同」的最好教具。冒泡排序和插入排序都用了两层嵌套循环，最坏情形的比较 / 交换次数是 n(n−1)/2 这一量级，也就是 3.2 里的 n² 级；而更聪明的排序（如归并、快排）可以做到 n log n。本课只到「用它们示范算法的写法与量级」为止，具体的排序算法分析与下界属 L3-01。

初学者容易把「排序方法多」误当成「随便哪种都差不多」。恰恰相反，量级差异（n² 对 n log n）在数据规模一大时是天壤之别，这正是 3.2 要建立的量级敏感度。

### 3.1.6 贪心算法与停机问题（点到即止）

Rosen §3.1 末尾还引入了两个「拓宽视野」的话题，本课只作导论性提及：

- 贪心算法（greedy algorithm）：一种在每一步都做「当前看起来最优」的局部选择、寄希望于得到全局最优解的算法设计范式。经典例子是找零钱问题（用尽量少的硬币凑出指定金额）。贪心有时能给出最优解、有时不能，判断它对某问题是否最优需要额外证明——这类证明与最优性分析归 L3-01，本课只需知道「贪心 = 每步取局部最优」这个概念。
- 停机问题（halting problem）：是否存在一个算法，能对任意程序及其输入判断该程序会不会停机？答案是**不存在**——这是一个可证明无解（unsolvable）的问题，由图灵给出。它的意义在于告诉初学者：不是所有精确描述的问题都有算法解，「有没有算法」本身是一个深刻的问题。停机问题的完整论证归本课大主题12（计算模型导论）与 L3-05，本节只作一句话指路。

## 3.2 函数的增长

### 3.2.1 大 O 的定义与见证常数

大 O 记号（big-O notation）用来给一个函数的增长速度设一个**上界**。Rosen §3.2 的定义是：设 f 和 g 是从整数集或实数集到实数集的函数，若存在常数 C 和 k，使得

|f(x)| ≤ C · |g(x)|，只要 x > k

就称 f(x) 是 O(g(x))（读作「f 是大 O 的 g」）。这里的两个常数 C 和 k 称为**见证常数**（witnesses），因为它们「见证」了这一大 O 关系的成立。

直觉是：大 O 说的是「当 x 足够大（大过某个门槛 k）之后，f 的绝对值最多是 g 的绝对值的某个固定倍数（C 倍）」。它只关心**增长的量级**，不关心小规模时的具体表现，也不关心常数因子——所以它是一种「粗粒度」的比较工具，正好适合刻画算法在大规模输入下的表现。

一个关键的教学要点是：**见证常数不唯一**。如果 (C, k) 是一对见证，那么任何 C′ ≥ C、k′ ≥ k 都同样是见证。找到一对即可证明大 O 关系成立，不必找「最小」的那一对。

Rosen 的经典最小例子：证明 f(x) = x² + 2x + 1 是 O(x²)。当 x > 1 时，有 x < x² 且 1 < x²，于是

x² + 2x + 1 ≤ x² + 2x² + x² = 4x²

因此可取见证常数 C = 4、k = 1。

可选数值示意（numpy 2.4.6，Linux 6.18.5，对应基线串）验证这对见证：取若干 x > 1，逐点检查 x²+2x+1 ≤ 4x²。

```python
import numpy as np
x = np.array([1.0001, 2, 5, 10, 100, 1000])
lhs = x**2 + 2*x + 1
rhs = 4 * x**2
print(bool(np.all(lhs <= rhs)))     # True
print(lhs[0], rhs[0])               # 4.0004... 4.0008...
```

真实输出为 `True`，以及在 x=1.0001 处 `4.000400... 4.000800...`（不等式在门槛 k=1 附近就已成立且趋于贴紧）。这只是加固直觉的数值检查，证明本身靠上面的代数放缩。

初学者最常见的误区是把 O 当成「等于」或「精确量级」。O 只是**上界**：说 f(x) 是 O(x²) 完全允许 f 实际上长得慢得多（例如 f(x)=x 也是 O(x²)）。第二个误区是漏掉「x > k 之后」这个限定——大 O 是关于「充分大的 x」的渐近命题，小 x 处 f 比 C·g 大并不违反定义。

### 3.2.2 常见增长量级与增长层次

在算法分析中反复出现的一批「参照函数」按增长由慢到快排成一条层次链。忽略常数因子后，常见量级的排序是：

1 ≺ log n ≺ n ≺ n log n ≺ n² ≺ n³ ≺ … ≺ 2ⁿ ≺ n! ≺ nⁿ

（这里 ≺ 表示「增长严格慢于」，即左边是右边的 O 但右边不是左边的 O。）

直觉上：常数量级（1）不随规模变化；对数量级（log n）增长极慢（规模翻倍只多一个常数）；线性（n）随规模成比例；n log n 略快于线性；多项式（n²、n³…）随幂次拉开；指数（2ⁿ）和阶乘（n!）则「爆炸式」增长，规模稍大就完全不可承受。

可选数值示意直观展示这条链条拉开的速度（numpy，对应基线串），列出各函数在 n = 1,2,4,8,16,32,64 处的值：

```
n            :          1           2           4           8          16          32          64
1            :          1           1           1           1           1           1           1
log2 n       :          0           1           2           3           4           5           6
n            :          1           2           4           8          16          32          64
n log2 n     :          0           2           8          24          64         160         384
n^2          :          1           4          16          64         256    1.02e+03     4.1e+03
2^n          :          2           4          16         256    6.55e+04    4.29e+09    1.84e+19
n!           :          1           2          24    4.03e+04    2.09e+13    2.63e+35    1.27e+89
```

上表是本机真实输出。可以肉眼看到：到 n=64 时，n² 才四千出头，而 2ⁿ 已是 1.8×10¹⁹、n! 更是 10⁸⁹ 量级——这就是为什么「指数 / 阶乘算法在实践中几乎不可用」。

初学者要建立的核心敏感度是：**当规模变大，唯一真正重要的是量级，不是常数**。一个 100n 的算法在 n 足够大时一定优于一个 n² 的算法，哪怕后者常数只有 1。这也解释了 3.2.1 里「大 O 忽略常数」为何是合理的抽象。易错点：log 的底数在大 O 里不重要（换底只差一个常数因子），所以常直接写 O(log n) 不标底。

### 3.2.3 多项式的大 O 定理

一个反复使用的现成结论（Rosen §3.2 定理）：设

f(x) = aₙxⁿ + aₙ₋₁xⁿ⁻¹ + … + a₁x + a₀

其中 a₀, a₁, …, aₙ 都是实数，则 f(x) 是 O(xⁿ)。

也就是说，**一个多项式的大 O 量级由它的最高次项决定**，低次项和所有系数都可以丢掉。例如 3x⁵ + 100x³ + 7 是 O(x⁵)。

当 x 足够大时，最高次项 xⁿ 完全「压制」了所有低次项，低次项相对它可以忽略。这条定理让我们不必每次都重新做放缩，看一眼最高次即可报出量级。它也是 3.2.1 那个 x²+2x+1 = O(x²) 例子的一般化。

易错点：这条定理是关于**多项式**的，对含指数 / 对数 / 阶乘的函数不适用（不能简单「取最高次项」）。另外，取最高次得到的是最紧的多项式上界，但同一个函数仍然是任何更高次幂的 O（x⁵ 也是 O(x⁶)），因为 O 只是上界。

### 3.2.4 大 O 的组合规则（和与积）

估计复杂函数时，两条组合规则（Rosen §3.2）很实用。设 f₁(x) 是 O(g₁(x))、f₂(x) 是 O(g₂(x))，则：

和规则：(f₁ + f₂)(x) 是 O( max(|g₁(x)|, |g₂(x)|) )

积规则：(f₁ · f₂)(x) 是 O( g₁(x) · g₂(x) )

和规则的直觉：两段代码顺序执行，总量级由**较慢的那段**决定（较快的那段被吸收）。积规则的直觉：两层嵌套循环，总量级是两层量级的**乘积**。

一个最小例子：估计 f(x) = (x + 1)·log(x + 1) + 3x²。前一项 (x+1)log(x+1) 由积规则是 O(x log x)；后一项 3x² 是 O(x²)；两项相加由和规则取较大者，得 f(x) 是 O(x²)。

初学者用和规则时的常见错误是「把两个量级相加」写成 O(g₁ + g₂)。虽然 O(g₁+g₂) 与 O(max(g₁,g₂)) 在 g 非负时其实等价，但教材标准写法是取 max，更能体现「慢的那个说了算」的直觉。用积规则时的易错点是嵌套与顺序的区分：嵌套循环用积（相乘），顺序代码段用和（取 max），两者不能混。

### 3.2.5 大 Ω（下界）

大 Ω 记号（big-Omega）与大 O 对偶，给增长速度设一个**下界**。Rosen §3.2 的定义：存在正常数 C 和常数 k，使得

|f(x)| ≥ C · |g(x)|，只要 x > k

则称 f(x) 是 Ω(g(x))。同样，C 和 k 是见证常数（此处 C 要求为正）。

大 Ω 说「当 x 足够大之后，f 至少是 g 的某个固定正倍数」，即 f 增长得**不慢于** g。它和大 O 恰好是一枚硬币的两面——有一个便利的对偶关系：

f(x) 是 Ω(g(x)) 当且仅当 g(x) 是 O(f(x))

例子：f(x) = 8x³ + 5x² + 7 是 Ω(x³)，因为当 x > 0 时 8x³ + 5x² + 7 ≥ 8x³，可取 C = 8、k = 0（这里 k 甚至可取 0，因为对所有正 x 都成立）。

初学者最容易混淆 O 与 Ω 的方向：O 是「最多这么快」（上界，刻画最坏不超过多少），Ω 是「至少这么快」（下界，刻画再好也快不过多少）。在算法里，O 常用来给最坏情形上界，Ω 常用来说明某个问题「无论多聪明都至少要这么多代价」。

### 3.2.6 大 Θ（紧确界）

大 Θ 记号（big-Theta）表示「量级上下都卡住」，是**紧确的量级刻画**。Rosen §3.2 的定义：若 f(x) 既是 O(g(x)) 又是 Ω(g(x))，则称 f(x) 是 Θ(g(x))，也说 f 与 g 是**同阶的**（f is of order g）。

等价地：f(x) 是 Θ(g(x)) 当且仅当存在正常数 C₁、C₂ 和常数 k，使得

C₁ · |g(x)| ≤ |f(x)| ≤ C₂ · |g(x)|，只要 x > k

Θ 说的是「f 和 g 增长得一样快（相差不超过常数因子）」。这是三种记号里最强、最精确的一种——说 f 是 Θ(g) 意味着 g 既是 f 的上界又是 f 的下界的量级。

例子：任何 n 次多项式 f(x) = aₙxⁿ + … + a₀（aₙ > 0）都是 Θ(xⁿ)：上界来自 3.2.3 的多项式定理，下界因为最高次项主导。所以 3x² + 5x + 1 是 Θ(x²)，而不仅仅是 O(x²)。

初学者要建立的判据是：**要报 Θ，必须同时验证 O（上界）和 Ω（下界）**。只证了上界就写 Θ 是最常见的错误。日常口语里人们常把「最坏情形是 n²」笼统说成「O(n²)」或「Θ(n²)」，但严格地讲，能写 Θ 的前提是上下界同阶——写 O 更保守、更安全。

### 3.2.7 记号使用的易错点与规范

关于这套记号，有几个反复出现的坑值得单列：

第一，「f(x) 是 O(g(x))」中的「是」不是等号。严格地讲 O(g) 是一个**函数集合**，f ∈ O(g) 才是本义；很多书（包括 CLRS）沿用 `f(x) = O(g(x))` 的传统写法，但这个「=」是单向的、不能反读，也不能两边消去。Rosen 刻意用「is」（是）而不用「=」，正是为了避免这个误解。

第二，O / Ω / Θ 都是**渐近**（asymptotic）陈述，只关心 x → ∞ 的行为，与小 x 处无关，也与常数因子无关。因此「O(2n) 和 O(n) 一样」「O(log₂n) 和 O(log₁₀n) 一样」都是对的。

第三，上界要报「有意义的最紧上界」。虽然「n 是 O(n²)」在技术上成立，但如果实际就是线性，报 O(n²) 虽不错但不够有用；实践中我们追求尽量紧的界。

## 3.3 算法复杂度

### 3.3.1 时间复杂度与基本运算计数

一个算法的**时间复杂度**（time complexity）刻画它所需的运算次数如何随输入规模增长。Rosen §3.3 的做法是：选定一种「基本运算」（如比较、加法、乘法），数出算法在规模为 n 的输入上执行了多少次这种运算，再用 3.2 的大 O / Θ 记号报出其量级。

这里的关键抽象是：**我们数的不是真实秒数，而是基本运算的次数的量级**。为什么？因为真实运行时间依赖于机器速度、编译器、缓存等无数硬件 / 实现细节，无法在算法层面比较；而「运算次数随 n 如何增长」是算法本身的、与机器无关的性质，正是我们想比较的东西。

最小例子：3.1.3 的线性搜索，基本运算取「x 与 aᵢ 的比较」。在长度 n 的序列上，最坏情形（目标不在序列中或在末尾）要比较 n 次，所以线性搜索的最坏情形时间复杂度是 Θ(n)。再如 3.1.5 的冒泡排序，两层循环使比较次数约为 n(n−1)/2 次，量级为 Θ(n²)。

初学者的常见误解是「复杂度 = 运行时间（秒）」。不是——复杂度是运算次数的**增长量级**，是一条关于「规模变大时会怎样」的趋势判断。两个都是 O(n) 的算法在同一台机器上跑，秒数可以差好几倍（常数不同），但当 n 足够大时，O(n) 一定最终优于 O(n²)。

### 3.3.2 空间复杂度

**空间复杂度**（space complexity）刻画算法运行时所需的**存储空间**如何随输入规模增长，同样用大 O / Θ 记号表示。它与时间复杂度并列，是衡量算法资源消耗的另一维度。

有些算法用「额外空间换时间」，有些反之，二者常有权衡（trade-off）。例如就地（in-place）排序几乎不用额外空间（O(1) 辅助空间），而某些排序需要与输入等量的辅助数组（O(n) 额外空间）。

初学者要注意区分「输入本身占的空间」和「算法额外使用的空间」——通常空间复杂度指的是后者（辅助空间）。本课只需建立「空间也是一种要度量的资源、也用同一套量级语言」这个认识；具体算法的空间分析归 L3-01。

### 3.3.3 最坏情形、平均情形与最好情形

同一个算法在不同输入上运算次数可能不同，因此复杂度分析要指明是哪一种「情形」：

- 最坏情形（worst-case）：在所有规模为 n 的输入中，运算次数最多的那种。它给出「保证不超过」的上界，是最常用、最保守的度量。
- 平均情形（average-case）：在某种输入分布假设下运算次数的期望值。它更贴近「典型表现」，但需要对输入分布做假设，分析也更难。
- 最好情形（best-case）：运算次数最少的那种输入，实践意义较小（不能靠运气）。

例子：线性搜索最好情形是目标恰在第一个位置（1 次比较，Θ(1)），最坏情形是目标不在或在末尾（n 次比较，Θ(n)）；其平均情形在「目标等概率出现在各位置」假设下约为 n/2 次，仍是 Θ(n)。

初学者最需要记住的是：**默认说的复杂度通常指最坏情形**，因为它提供「无论输入多坏都不会更糟」的保证。谈平均情形时一定要交代「在什么输入分布假设下」——脱离分布谈平均情形是没有意义的。

### 3.3.4 常见复杂度类与术语（P / 可解 / 难解导论）

把常见量级配上名字，就得到一张「复杂度类」速查表（Rosen §3.3）：

- Θ(1)：常数（constant）复杂度；
- Θ(log n)：对数（logarithmic）复杂度；
- Θ(n)：线性（linear）复杂度；
- Θ(n log n)：线性对数（linearithmic / 「n log n」）复杂度；
- Θ(nᵇ)（b ≥ 1 常数）：多项式（polynomial）复杂度；
- Θ(bⁿ)（b > 1 常数）：指数（exponential）复杂度；
- Θ(n!)：阶乘（factorial）复杂度。

在此基础上引入两个导论性术语：一个问题若存在最坏情形为**多项式时间**的算法求解，就称它是**易解的 / 可行的**（tractable），这类问题构成复杂度类 **P**；若可证明不存在多项式时间算法，则称为**难解的**（intractable）。此外还有一批问题（如停机问题）根本不存在任何算法，称为**不可解的 / 不可判定的**（unsolvable）。

Rosen §3.3 还点到复杂度类 **NP** 与 **NP 完全**（NP-complete）问题，以及著名的悬而未决的 P 对 NP 问题（P = NP?），但这些只作一句话导论——它们的正式定义、归约与理论深挖归本课大主题12（计算模型导论）与 L3-05，本课不展开。

直觉上这张表把 3.2.2 的增长层次「翻译」成了工程判断：多项式及以下（含 log、线性、n log n）一般被认为「可实际计算」，指数和阶乘则「规模稍大就不可承受」。初学者要建立的核心分界线正是「多项式 vs 指数」——这是「能不能真正跑得动」的粗略分水岭，也是 P、NP 等理论概念的直觉起点。

易错点：「多项式时间 = 快」只是一个粗略约定，n¹⁰⁰ 在理论上是多项式但实践中极慢；「指数 = 一定不能用」也不绝对，小规模输入上指数算法照样能跑。这条分界线是理论上的粗分类，不是逐案的性能判断。
