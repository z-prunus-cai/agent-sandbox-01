## 5.1 数组与 C 字符串

### 5.1.1 定长数组（fixed-size array）

C 的数组是**同一类型的元素在内存里连续排布**的一段区域，声明时给定固定长度，长度是类型的一部分，运行期不可增长。

    int a[5];        // 5 个连续的 int，下标 0..4
    a[0] = 10;       // 用下标访问

核心直觉：数组名 `a` 代表这段连续内存的起点，`a[i]` 就是"从起点往后数第 i 个元素"。因为元素等宽、连续排列，所以按下标访问是"一步到位"的（编译器用 起点 + i×元素大小 直接算出地址），这也是数组"随机访问快"的根源（代价画像与其它结构的对比深挖归 L2-01）。

初学者最需要绷紧的一根弦：**C 数组不做边界检查**。写 `a[5]` 或 `a[100]` 编译器不会拦你，运行期会读写到数组之外的内存——轻则拿到垃圾值，重则崩溃或被利用（越界深挖归大主题6）。数组长度必须自己另外记着（常用 `sizeof(a)/sizeof(a[0])` 在"数组还没退化成指针"的作用域里算元素个数）。另一个易错点：数组不能整体用 `=` 赋值或比较（`a = b`、`a == b` 非法），要逐元素处理或用 `memcpy`。

### 5.1.2 以 `'\0'` 结尾的 C 字符串

C 没有独立的字符串类型：**字符串就是一个 `char` 数组，用一个值为 0 的字符 `'\0'`（空字符）标记结尾**。字符串字面量 `"Hi"` 在内存里其实是 3 个字节 `'H'`、`'i'`、`'\0'`。

实测（基线 Py3.11.15/np2.4.6/gcc13.3 @2026-07-25，`gcc -std=c11 -Wall`）——用 `char s[] = "Hi";`：

    sizeof("Hi" array)=3  strlen=2
    bytes: [0]=72('H') [1]=105('i') [2]=0('0')
    manual count until NUL = 2

关键对照：**`sizeof(s)` 是 3（含结尾 `'\0'`），`strlen(s)` 是 2（不含 `'\0'`，只数到终止符前）**。这是初学者第一大坑：给字符串分配空间时永远要多留 1 字节放 `'\0'`（存 `n` 个字符的字符串要 `char buf[n+1]`），否则字符串函数会一直读到内存里下一个恰好为 0 的字节才停，造成越界。

字符数组遍历的惯用法就是"走到 `'\0'` 为止"：

    for (char *p = s; *p != '\0'; ++p) { /* 处理 *p */ }

`*p` 为 0 时循环自然结束——因为 `'\0'` 的整数值就是 0，作条件即为假。这也解释了为什么 `strlen`、`strcpy` 这类函数不需要额外传长度：长度信息"藏在"终止符里。代价是求长度是 O(n)（要扫到终止符），且忘了终止符就是灾难。Python 的字符串则自带长度、没有终止符约定，`len(s)` 是 O(1)，不存在这个坑。

#### 来源与时效（本小主题末集中列）
- 一手锚点：K&R 2nd ed(C89) Ch1 §1.6「Arrays」、Ch5 §5.3「Pointers and Arrays」、§5.5「Character Pointers and Functions」（数组连续布局、字符串以 `'\0'` 结尾、`strlen`/遍历惯用法）。ISO/IEC 9899:2011 (C11) §6.2.5p20（数组类型）、§6.7.9p14（字符数组由字符串字面量初始化、含终止空字符）、§7.24「String handling <string.h>」（`strlen` 定义为不含终止空字符的长度）。核实 2026-07-26。
- 比对结论一致：K&R（教材）与 C11（规范）对"字符串=以 `'\0'` 结尾的 char 数组"、`strlen` 不含终止符完全一致；C11 措辞更严格地把"字符串字面量含终止空字符"写死。
- 实测坐实：`sizeof("Hi" 数组)=3`、`strlen=2`、字节 `[2]=0`——本机真实输出，印证 `sizeof`（含 `'\0'`）vs `strlen`（不含）的差 1。

## 5.2 Python 序列容器

### 5.2.1 list / tuple / range 三种序列

Python 把"按位置有序排列的一串元素"统一抽象成**序列（sequence）**，最常用的三种是 `list`、`tuple`、`range`。它们共享一套"序列协议"：都能用 `len()` 取长度、用 `s[i]` 按下标取元素、用 `for x in s` 遍历、用切片截取。

三者的关键区别是**可变性与用途**：

    list  = [1, 2, 3]     # 可变：能增删改元素，方括号
    tup   = (1, 2, 3)     # 不可变：定长、内容不可改，圆括号
    r     = range(0, 10, 2)  # 惰性整数序列，不真正存所有元素

`list` 是"可增删的动态列表"，日常最常用；`tuple` 是"定死的一组值"，常用于返回多个值、作字典键、表示"不该被改"的记录；`range` 是个"按需生成整数"的惰性对象（不预先把 0..N 全存进内存），常配 `for i in range(n)` 用。实测：

    range(0,10,2) -> [0, 2, 4, 6, 8]

初学者易错点：`(1)` 不是元组而是加了括号的整数 1，单元素元组要写 `(1,)`（靠逗号，不是括号，定义元组）。另外 `list` 因为可变，**不能**作字典键或放进 `set`；`tuple`（元素也都不可变时）可以。

### 5.2.2 索引与切片语义

索引用 `s[i]` 取单个元素，**支持负索引**：`s[-1]` 是最后一个、`s[-2]` 是倒数第二个。切片 `s[start:stop:step]` 取一段**子序列**，遵循**左闭右开**（含 `start`、不含 `stop`）：

    s[start:stop:step]   # 含下标 start，不含 stop，步长 step

实测（基线 Py3.11.15，`a = [0,1,2,3,4,5]`）：

    a[1:4] = [1, 2, 3]
    a[:3] = [0, 1, 2] | a[3:] = [3, 4, 5]
    a[::2] = [0, 2, 4] | a[::-1] = [5, 4, 3, 2, 1, 0]
    a[1:100] = [1, 2, 3, 4, 5]   (over-range slice: no error)

要建立的直觉：**省略端点表示"到头/从头"**（`a[:3]` 从头到下标 3 前、`a[3:]` 从下标 3 到末尾）；`step` 为负表示反向，`a[::-1]` 是反转序列的惯用法；`a[::2]` 隔一个取一个。一个和 C 数组截然不同、初学者常惊讶的点：**切片的上界越界不报错，会被"截断"到合法范围**（`a[1:100]` 安全返回 `[1,2,3,4,5]`）——但**单个索引越界（如 `a[100]`）会抛 `IndexError`**。切片是"温柔"的，单点索引是"严格"的。

另一要点：**对 list 切片会返回一个新的 list（浅拷贝）**，`b = a[:]` 是复制列表的常用写法；这与 5.5 的"可变性/别名"直接相关——`b = a` 是别名（同一对象），`b = a[:]` 是新对象。左闭右开的一个副作用好处：`a[:k]` 和 `a[k:]` 恰好把序列不重不漏地切成两半，长度分别是 `k` 和 `len(a)-k`。

#### 来源与时效（本小主题末集中列）
- 一手锚点：Python 3.11 Language Reference §3.2「The standard type hierarchy」（Sequences：可变/不可变序列，list/tuple/range 分类）、§6.3.2「Subscriptions」、§6.3.3「Slicings」（索引与切片语法语义）。Python 官方文档「Built-in Types · Sequence Types — list, tuple, range」（切片 `s[i:j:k]`、负索引、越界切片被截断的语义；单元素元组需逗号）。Berkeley CS61A（Sequences 讲次，cs61a.org，核实 2026-07-25 为 Summer 2026 学期）——序列/切片教学。核实 2026-07-26。

- 实测坐实：`a[1:4]`、`a[::-1]`、`a[1:100]` 不报错等均本机真实输出，印证左闭右开与"切片温柔、索引严格"。

## 5.3 集合与映射入门

### 5.3.1 set：无序、去重的集合

`set` 是一组**互不相同、无序**的元素的容器。它天然去重、且成员判断（`x in s`）很快（背后是哈希，实现与复杂度深挖归 L2-01）。

    s = {1, 2, 3}          # 集合字面量（注意：{} 是空 dict，不是空 set）
    empty = set()          # 空集合要用 set()

实测——把有重复的列表丢进 `set` 即去重：

    set from list: [1, 2, 3]      # set([3,1,2,2,3,1]) 去重后

初学者要点：**set 无序**（不保证遍历顺序、也不能用下标 `s[0]`）；空集合必须写 `set()`，因为 `{}` 被占用为"空字典"。set 支持并 `|`、交 `&`、差 `-` 等数学集合运算，做"去重 / 判成员 / 求交并差"时比用 list 又快又清楚。限制：**只能装可哈希（通常即不可变）的元素**——能放 `int`/`str`/`tuple`，不能放 `list`/`dict`（它们可变、不可哈希）。

### 5.3.2 dict：键到值的映射

`dict` 是**键（key）到值（value）的映射**，用键直接查值，是 Python 最核心的数据结构之一。

    d = {"a": 1, "b": 2}
    d["a"]           # 取值 -> 1
    d["c"] = 3       # 新增/更新键

核心直觉：dict 像"可以用任意（可哈希）键当下标的表"。查、插、删都很快（哈希，深挖归 L2-01）。键必须**唯一且可哈希**；值任意。

### 5.3.3 键的唯一性与去重

**同一个键在 dict 里只保留一份**——重复赋值是覆盖而非新增。实测：

    dict key dedup: {'a':1 then 'a':2} -> {'a': 2}

更微妙的一条（初学者常被绕）：**dict/set 判"同一个键"用的是"相等 `==` + 哈希"，而不是"类型相同"或"是同一对象"**。因此值相等的不同类型数值会被当成同一个键：

    dict.fromkeys([1,1.0,True]) -> {1: None}   (1==1.0==True same key)

`1`、`1.0`、`True` 因为 `1 == 1.0 == True` 且哈希相同，被折叠成同一个键（保留最先插入的键对象 `1`）。这正呼应大主题1：`bool` 是 `int` 的子类、`True == 1`。

关于顺序：**从 Python 3.7 起，dict 保证按插入顺序遍历**（这是语言层面的正式保证，不再是实现细节）。实测：

    dict preserves insertion order: {'z': None, 'a': None, 'm': None}

但 **set 不保证任何顺序**——别把 dict 的"记住插入序"想当然套到 set 上。需要"有序去重"时，惯用法是 `list(dict.fromkeys(seq))`（借 dict 键去重又保序）。

#### 来源与时效（本小主题末集中列）
- 一手锚点：Python 3.11 Language Reference §3.2「The standard type hierarchy」（Set types set/frozenset：无序、元素须可哈希；Mapping types dict：键须可哈希、`d[k]` 语义）。Python 官方文档「Built-in Types · Set Types」「Built-in Types · Mapping Types — dict」（去重、集合运算、键唯一、可哈希要求）。Python 官方文档「What's New in Python 3.7」（dict 保持插入顺序成为语言保证）。Berkeley CS61A（Dictionaries 相关讲次，cs61a.org，核实 2026-07-25）。核实 2026-07-26。
- 比对结论一致：Language Reference 与 Built-in Types 对"set 无序去重、dict 键唯一可哈希"一致；"dict 保序"由官方 What's New 3.7 明文确立（早于 3.7 仅 CPython 3.6 实现细节，3.7 起为语言保证），本机 3.11 已是保证。
- 实测坐实：list→set 去重、`{'a':1→2}` 覆盖、`fromkeys([1,1.0,True])` 折叠为单键、dict 保序——均本机真实输出。
- 冲突/易混点：`{}` 是空 dict 非空 set（易混，语言约定）；`1/1.0/True` 同键源自 `==`+哈希相等（呼应 bool 是 int 子类），非分歧；set 无序 vs dict 保序需分清，非来源冲突。

## 5.4 C 结构体与聚合数据

### 5.4.1 struct 定义与成员访问

C 的**结构体 `struct` 把不同类型的成员聚合成一个新的复合类型**——数组是"同类型元素的序列"，结构体是"异类型成员的记录"。

    struct Point { int x; int y; };   // 定义一个含两个 int 成员的类型
    struct Point p;                    // 声明一个该类型的变量
    p.x = 3; p.y = 4;                  // 用点号访问成员

核心直觉：结构体让你把"逻辑上属于一体的一组数据"（一个点的 x、y；一个学生的姓名、学号、成绩）打包成一个能整体命名、整体传递、整体赋值的东西。访问成员：变量用 `.`（`p.x`），指向结构体的指针用 `->`（`ptr->x`，等价于 `(*ptr).x`）。与数组不同，**结构体可以整体用 `=` 赋值/拷贝、也能整体作参数传值或作返回值**（按值拷贝所有成员）——数组做不到这些。

### 5.4.2 内存对齐与填充（只给直觉）

结构体在内存里**不一定是各成员大小的简单相加**：编译器为了让每个成员落在其"对齐要求"的地址上，会在成员之间或末尾插入**填充字节（padding）**。

直觉上为什么：CPU 访问一个 `int`（4 字节）时，若它的地址是 4 的倍数会更高效（甚至某些架构上强制要求对齐），所以编译器会把成员"推"到合适的边界，空出来的缝隙用填充补齐。规则的入门直觉是——**每个成员的偏移量要能被它自身的对齐值整除；整个结构体的大小要能被其最大成员的对齐值整除**（好让数组里相邻结构体的成员也都对齐）。

实测（基线 Py3.11.15/np2.4.6/gcc13.3 @2026-07-25，x86-64 System V ABI，`gcc -std=c11 -Wall`，`_Alignof`/`offsetof`）：

    sizeof(struct A{char;int})=8 align=4  offset c=0 i=4
    sizeof(struct B{int;char})=8 align=4  offset i=0 c=4
    sizeof(struct C{3 char})=3 align=1
    sizeof(struct D{double;char;int})=16 align=8  off d=0 c=8 i=12

读这几个数就懂了：`struct A{char c; int i;}` 里 `char` 占偏移 0，但 `int` 要对齐到 4 的倍数，于是 `c` 后面填 3 字节，`i` 落在偏移 4，总大小 8（不是 1+4=5）。`struct B{int i; char c;}` 里 `i` 在 0、`c` 在 4，但总大小要是最大对齐值 4 的倍数，故末尾再填 3 字节凑到 8。`struct C{char,char,char}` 全是 1 字节对齐，大小恰好 3、无填充。`struct D` 因含 `double`（8 字节对齐），整体对齐值 8、大小 16。

初学者要建立的直觉，而**不是背数字**：(1) 结构体大小 ≥ 成员大小之和，多出来的是填充；(2) **成员声明顺序会影响大小**（把大的、对齐要求高的成员放前面往往更省——但这属优化，入门不必纠结）；(3) **这些具体数值依赖 ABI**，本机是 x86-64 System V，换平台可能不同，所以谈具体字节数必须锚定 ABI。对齐/填充的位级与硬件层深挖归 L3-02（组成原理）/L2-01，本处只给"为什么有填充、大小为何不等于成员之和"的直觉。

#### 来源与时效（本小主题末集中列）
- 一手锚点：K&R 2nd ed(C89) Ch6「Structures」§6.1–6.2（struct 定义、`.`/`->` 成员访问、结构体可整体赋值/传参/返回；§6.7 提及编译器可能因对齐留"洞"）。ISO/IEC 9899:2011 (C11) §6.7.2.1「Structure and union specifiers」（成员按声明顺序、地址递增，允许成员间与末尾填充；§6.7.2.1p15「there may be unnamed padding within a structure object, but not at its beginning」）、§6.5.3.4/§6.2.8「Alignment of objects」（对齐要求）。System V AMD64 ABI（x86-64）——各基本类型对齐值与结构体布局规则（本 KB 指定 ABI）。核实 2026-07-26。
- 比对结论一致：K&R（"编译器可能为对齐插入洞"）与 C11 §6.7.2.1（允许填充、成员地址递增、不在开头填充）一致；具体填充**数值**由 System V AMD64 ABI 决定，非 C 标准强制（标准只规定"可以有填充、成员顺序递增"）。
- 实测坐实：`struct A/B/C/D` 的 `sizeof`/`_Alignof`/`offsetof` 均本机真实输出（x86-64 System V），印证"大小含填充、成员顺序影响布局、整体大小为最大对齐值倍数"。
- 冲突/易混点：**规范 vs 实现分账**——C11 只保证"成员按序、可有填充"，**确切填充字节数是 ABI/实现事实**（本机 System V AMD64），跨平台可变，须锚 ABI，不可当作标准承诺；深挖归 L3-02。

## 5.5 可变性与数据抽象入门

### 5.5.1 可变 vs 不可变容器对照

Python 的容器分两类：**可变（mutable）**的能就地增删改（`list`/`dict`/`set`），**不可变（immutable）**的一经创建内容就固定（`tuple`/`str`/`frozenset`，以及 `int`/`float` 这些标量）。

核心直觉与 5.2/大主题1 的别名一脉相承：**"修改一个可变对象"改的是那唯一的对象本身，所有指向它的名字都会看到变化；"修改一个不可变对象"其实是造了个新对象、再让名字改指向**。实测：

    mutable shared: [1, 2, 3] ref is lst -> True
    immutable rebind: s1= hi s2= hi!

`ref = lst; ref.append(3)` 后 `lst` 也变成 `[1,2,3]`（同一列表对象，`ref is lst` 为 `True`）——这是别名共享。而 `s2 = s1; s2 = s2 + "!"` 后 `s1` 仍是 `"hi"`——因为字符串不可变，`s2 + "!"` 造了个新字符串、`s2` 改指向它，没动到 `s1` 指的原对象。

给初学者的实用规则：**要多个地方共享同一份可改数据，用可变容器；要"值一旦定下就别被谁悄悄改"或要当 dict 键/放进 set，用不可变的**。这也解释了为什么函数里对可变参数原地修改会"泄漏"到调用方（呼应大主题3 传参），以及为什么 `tuple` 能当字典键而 `list` 不能。

### 5.5.2 构造器 / 选择器与抽象屏障（数据抽象雏形）

**数据抽象**的核心思想：**把"怎么用一个数据"和"这个数据内部怎么表示"分开**。使用者只通过一组**构造器（constructor，造出数据）**和**选择器（selector，从数据里取出部件）**来打交道，不直接碰内部表示——两者之间那道"只许通过接口访问"的界线，叫**抽象屏障（abstraction barrier）**。

以"有理数"为例（CS61A/SICP 经典入门例），先只定接口：

    def make_rat(n, d):   return (n, d)   # 构造器：造一个有理数
    def numer(r):         return r[0]     # 选择器：取分子
    def denom(r):         return r[1]     # 选择器：取分母

关键直觉：只要 `make_rat`/`numer`/`denom` 这组接口不变，**上层代码（如有理数加法）完全不需要知道内部是用元组、还是用 list、还是用字典存的**。哪天想把内部表示从 `(n, d)` 换成别的，只要改这三个函数，所有上层代码一行都不用动——这就是抽象屏障的价值：**隔离变化、降低耦合**。初学者常犯的错是"绕过接口直接摸内部"（比如到处写 `r[0]` 而不调 `numer`），一旦内部表示改了就全线崩——数据抽象正是要用纪律避免这件事。

### 5.5.3 C 侧的对照：struct 作构造、成员作选择

C 里同样能实践数据抽象雏形：用 `struct` 聚合内部表示，用一个"造结构体"的函数当构造器、用访问成员的小函数当选择器。

    struct Rat { int n, d; };
    struct Rat make_rat(int n, int d){ struct Rat r = {n, d}; return r; }
    int numer(struct Rat r){ return r.n; }
    int denom(struct Rat r){ return r.d; }

对照直觉：C 和 Python 用**不同的复合数据机制**（C 用 struct/数组，Python 用 tuple/list/dict）承载同一个"构造器 + 选择器 + 抽象屏障"的思想。区别在可变性默认——C 结构体是"有类型的内存"，赋值/传参是按值拷贝（改副本不影响原件，呼应大主题1/3）；Python 容器多为引用共享（可变的会被别名波及）。数据抽象是**跨语言的设计思想**，不依赖某种具体容器；把它当成本大主题（复合数据）通向后续课程（L3-04 面向对象/ADT）的桥。更完整的抽象屏障、信息隐藏、表示不变式深挖归 L3-04。
