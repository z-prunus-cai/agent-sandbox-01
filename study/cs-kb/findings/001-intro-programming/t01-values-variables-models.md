## 1.1 字面量与基本类型

### 1.1.1 字面量（literal）是什么

字面量是源代码里"直接写出值"的记号：写 `42` 就得到整数四十二，写 `3.14` 就得到一个浮点数，写 `'A'` 就得到一个字符。编译器/解释器读到字面量时，直接据其**词法形式**决定它的值和类型，不需要任何变量或运算。

对初学者最容易忽略的一点是：**字面量本身是有类型的**，而类型由写法决定，不是由你"心里想的"决定。在 C 里 `42` 是 `int`、`42L` 是 `long`、`42U` 是 `unsigned int`、`3.14` 是 `double`（不是 `float`！），`3.14f` 才是 `float`。在 Python 里 `42` 是 `int`、`3.14` 是 `float`、`True`/`False` 是 `bool`。写错后缀或小数点，会悄悄改变类型，进而影响后续运算（尤其在 C 的整数除法里，`3/2` 得 `1` 而 `3.0/2` 得 `1.5`）。

一个 C 专属的经典坑：**字符字面量 `'A'` 在 C 中的类型是 `int`，不是 `char`**（C11 §6.4.4.4「整数字符常量的类型是 int」）。所以 `sizeof('A')` 在 C 里等于 `sizeof(int)`（本机为 4），这与 C++ 不同（C++ 里 `'A'` 是 `char`）。Python 则根本没有独立的字符类型，单个字符就是长度为 1 的字符串 `str`。

### 1.1.2 C 的静态类型分类

C 是**静态类型**语言：每个变量在声明时就固定了类型，编译期确定，运行期不变。C 的基本算术类型分两大族——

整数族（按典型大小递增）：

    char, short, int, long, long long

每个整数类型又有有符号/无符号两种（`signed`/`unsigned`），如 `unsigned int`。浮点族：

    float, double, long double

初学者最需要记住的直觉：**C 标准只规定各类型大小的"下限"和相对关系，不规定确切字节数**。标准保证 `sizeof(char)==1`（且 `char` 至少 8 位，见 C11 §5.2.4.2.1 `CHAR_BIT`），并保证

    1 == sizeof(char) <= sizeof(short) <= sizeof(int) <= sizeof(long) <= sizeof(long long)

但"`int` 到底几字节"取决于平台/编译器（实现定义）。所以谈具体字节数必须锚定平台。本机（x86-64 System V，LP64 模型，gcc 13.3）实测：

命令与真实输出（基线 Py3.11.15/np2.4.6/gcc13.3 @2026-07-25，`gcc -std=c11 -Wall sizes.c`）：

    char=1 short=2 int=4 long=8 longlong=8
    float=4 double=8 longdouble=16
    CHAR_BIT=8 INT_MAX=2147483647 INT_MIN=-2147483648
    UINT_MAX=4294967295

即本机 `int` 为 4 字节、`long` 为 8 字节（LP64 的标志：`long` 和指针都是 64 位；注意 Windows 的 LLP64 下 `long` 只有 4 字节，故不可跨平台照搬）。有符号 32 位 `int` 的取值范围是

    -2147483648 .. 2147483647

即 −2³¹ .. 2³¹−1（补码表示，深挖归大主题7/L3-02，这里只给"位宽决定范围"的直觉）。

### 1.1.3 Python 的动态类型

Python 是**动态类型**语言：类型属于**对象**，不属于变量名。同一个名字这一行绑着 `int`、下一行可以绑着 `str`，完全合法。你不需要（也不能）在赋值时声明类型。

对初学者最反直觉、也最省心的一点：**Python 的 `int` 是任意精度的**（"大整数"），不会像 C 的 `int` 那样溢出。`2**100` 在 Python 里是一个精确的大整数；在 C 里 `int` 早就溢出了（有符号溢出还是未定义行为，见大主题2）。代价是 Python `int` 是堆上的对象、比 C 机器整数慢且占内存多——但入门阶段先享受"不溢出"的便利即可。

Python 内置的基本数值/标量类型：`int`（任意精度）、`float`（就是 C 的 `double`，即 IEEE 754 双精度 64 位）、`bool`（是 `int` 的子类型，`True==1`、`False==0`）、`complex`（复数）、`str`（文本）。注意 `bool` 是 `int` 的子类这一点偶尔会咬人：`True + True == 2` 是成立的。

## 1.2 表达式、运算符、优先级与结合性

### 1.2.1 表达式与运算符分类

表达式是"能求出一个值的代码片段"：字面量、变量、以及用运算符把它们组合起来的东西都是表达式。运算符按功能分几族——

算术：

    +  -  *  /  %

关系（结果是真/假）：

    <  <=  >  >=  ==  !=

逻辑：

    &&  ||  !        (C)
    and  or  not     (Python)

位运算（按二进制位操作）：

    &  |  ^  ~  <<  >>

初学者要建立的直觉：**每个表达式都有"值"和"类型"两个属性**。`3 + 4` 的值是 7、类型是 `int`；`3 < 4` 在 C 里值是 1、类型是 `int`（C 用 int 的 0/1 表示真假），在 Python 里值是 `True`、类型是 `bool`。易错点：C 的 `/` 对两个整数做**整数除法**（`7/2==3`，向零截断），要得到小数必须让至少一个操作数是浮点（`7.0/2==3.5`）；Python 里 `/` 永远是真除法得 `float`（`7/2==3.5`），整除要用 `//`（`7//2==3`）。`%` 是取余。

### 1.2.2 优先级与结合性

当一个表达式里有多个运算符，**优先级（precedence）**决定"先算谁"，**结合性（associativity）**决定"同优先级时从左还是从右"。例如 `2 + 3 * 4`，因为 `*` 优先级高于 `+`，等价于

    2 + (3 * 4)

同优先级的减法从左结合，`10 - 3 - 2` 等价于

    (10 - 3) - 2

大多数二元运算符是**左结合**；少数是**右结合**，最重要的两类是赋值 `=`（`a = b = c` 即 `a = (b = c)`）和一元运算符（如 `!x`、`-x`）。Python 的幂运算 `**` 也是右结合：`2 ** 3 ** 2` 等于 `2 ** (3 ** 2) == 512`，不是 `(2**3)**2==64`——这是 Python 初学者常踩的点。

### 1.2.3 优先级踩坑：位运算与比较

一个 C/Python 都存在、极隐蔽的经典坑：**比较运算符 `==` 的优先级高于位运算 `&`**。所以

    x & 1 == 0

不是"x 的最低位是不是 0"，而是被解析成

    x & (1 == 0)

即 `x & 0`（因为 `1==0` 为假=0），结果恒为 0。正确写法要显式加括号：

    (x & 1) == 0

记不住整张优先级表没关系，入门期的安全习惯是：**混用不同族运算符时主动加括号**，既防错又提高可读性。K&R 明确建议"拿不准就加括号"。

### 1.2.4 求值顺序：优先级 ≠ 计算先后

初学者最容易把"优先级"和"操作数的求值顺序"混为一谈，其实是两回事。优先级只决定"谁和谁结合"（语法树形状），**不决定各操作数在运行时谁先被算出来**。在 C 里，绝大多数运算符的两个操作数的**求值顺序是未指定的**（unspecified），并且在同一表达式里对同一变量既读又写而无中间序列点会导致未定义行为。所以像

    i = i++ + 1;

或

    a[i] = i++;

这类代码在 C 里是坑（未定义/未指定行为，深挖归大主题2）。给初学者的规则很简单：**一条语句里不要对同一个变量既改又用**。Python 没有这类未定义行为（求值顺序有明确规定，总体从左到右），但把复杂副作用挤进一行同样有害可读性。

#### 来源与时效（本小主题末集中列）
- 一手锚点：K&R 2nd ed Ch2 §2.5「Arithmetic Operators」、§2.6「Relational and Logical Operators」、§2.9「Bitwise Operators」、§2.12「Precedence and Order of Evaluation」及 Appendix A §A.7（运算符优先级表）。C11 §6.5「Expressions」（优先级由语法给出；§6.5 明确多数运算符操作数求值顺序未指定）。Python 3.11 Language Reference §6.16「Operator precedence」（含 `**` 右结合、比较可链式 `a<b<c`）、§6.5「The power operator」。核实 2026-07-26。
- 比对结论：K&R 与 C11 对优先级/结合性完全一致；C11 额外把"求值顺序未指定"讲死（K&R 只提醒"顺序未定义，别依赖"）。Python 与 C 的优先级大体同构，差异在 `**` 右结合与比较链式（Python 特有）。
- 冲突/易混点：`&` 低于 `==` 是 C 和 Python 共同的历史遗留坑（两边一致，非分歧）；整数除法 `/` 语义 C（截断）vs Python（真除法）不同——语言差异，非来源冲突。

## 1.3 类型转换与提升

### 1.3.1 C 的整型提升（integer promotion）

C 在做算术前，会先把"比 `int` 窄"的整数类型（如 `char`、`short`、位域）**自动提升为 `int`**（若 `int` 装不下则为 `unsigned int`）。这叫整型提升，是自动发生、初学者看不见的。

直觉上为什么要这样：C 的算术运算是以"机器自然字长"（历史上即 `int`）为单位进行的，所以窄类型先被"抬"到 `int` 再运算。一个可观察的后果：

    char a = 10, b = 20;
    // a + b 的类型是 int，不是 char

也因此 `sizeof('A')` 是 4（`'A'` 本就是 int，见 1.1.1），以及对 `char` 做运算时不必担心它按 8 位溢出——它在运算中已是 int。

### 1.3.2 C 的常用算术转换（usual arithmetic conversions）

当二元算术运算的两个操作数类型不同（且都已完成整型提升）时，C 会把它们转换到一个"共同类型"再运算，规则叫"常用算术转换"（C11 §6.3.1.8）。粗略直觉的优先级链是：

    long double > double > float > (更宽/无符号的整数类型) > int

即"往更宽、更能表示的类型靠拢"。所以 `1 + 2.0` 里 `1` 先转成 `double` 再相加，结果是 `double` 的 `3.0`。

这里藏着 C 最著名的坑之一——**有符号与无符号混合运算**。当一个 `int` 和一个 `unsigned int` 相加/比较时，`int` 会被转成 `unsigned`，负数会变成一个很大的正数。经典陷阱：

    int i = -1;
    unsigned u = 1;
    // (i < u) 结果为“假”！因为 -1 被转成 4294967295，比 1 大

初学者规则：**尽量别把有符号和无符号混着比较/运算**（gcc 的 `-Wsign-compare`/`-Wconversion` 能帮你发现）。

### 1.3.3 C 的显式强制转换（cast）

除了自动转换，C 允许显式写 `(类型)表达式` 强转。最常见用途是把整数除法变成浮点除法：

    int a = 7, b = 2;
    double r = (double)a / b;   // 3.5，而不是 3

注意 `(double)a / b` 里 `a` 先转 `double`，再触发常用算术转换把 `b` 也变 `double`。强转也可能丢信息：`(int)3.9` 得 `3`（向零截断，不是四舍五入），窄化 `(char)300` 会溢出/实现定义。

### 1.3.4 Python：没有隐式数值窄化

Python 也做**混合数值的隐式加宽**：`int` 与 `float` 混合运算时，`int` 自动变 `float`（`1 + 2.0 == 3.0`）。但 Python **不做隐式窄化、也不会把数值悄悄截断成整数**——想从 `float` 得 `int` 必须显式调用 `int(3.9)`（结果 `3`，向零截断），想从字符串得数必须显式 `int("42")`/`float("3.14")`。而且 Python 不同类型间不会像 C 那样"静默按位重新解释"。

给初学者的对照直觉：**C 的转换更"激进"且大多沉默（含有符号/无符号这种危险的沉默转换）；Python 的转换更"克制"，加宽自动、窄化必须你亲手写**。这也是 Python 更适合入门的原因之一——少了很多沉默的数值陷阱。另外 Python 里 `int` 任意精度，根本不存在 C 那种"运算中溢出"的隐式转换需求。

## 1.4 变量与赋值语义

### 1.4.1 C 模型：变量是有类型的内存位置

在 C 里，声明一个变量就是**向编译器申请一块有确定类型、确定大小的内存位置（对象 object）**，并给它起个名字。

    int x;        // 划出一块 4 字节的内存，命名为 x
    x = 5;        // 把整数 5 的位模式写进这块内存
    x = 6;        // 覆盖：把 6 的位模式写进同一块内存

关键直觉：**变量名 `x` 永久绑定那块固定的内存**（在其生命周期内），赋值 `x = 6` 是"往盒子里写新内容"，盒子本身没变、地址没变。类型 `int` 是这块内存的属性——它规定了盒子多大、里面的位如何解释。所以 C 里"变量有类型"是字面意义的：类型长在那块内存上。

这套"命名的盒子"模型能直接解释很多 C 行为：为什么能对变量取地址 `&x`（盒子有地址）、为什么类型不能中途改变（盒子大小固定）、为什么未初始化的变量里是"垃圾值"（盒子刚划出来、没人写过，里面是残留位模式，读它是未定义行为，见大主题2）。

### 1.4.2 Python 模型：名字绑定对象

Python 的模型完全不同，也是初学者最需要"换脑"的地方：**值（对象）活在内存里、自带类型；变量名只是贴在对象上的标签（引用）**。赋值

    n = 10

不是"把 10 放进名为 n 的盒子"，而是"先有一个整数对象 10，再让名字 `n` 指向它"。名字本身没有类型、没有固定的存储，它只是个指向对象的引用。

因此**再赋值是"改指向"，不是"改内容"**：

    n = 10
    n = n + 1   # 先算出新对象 11，再让 n 改指向 11；原来的 10 对象没被修改

实测观察（`python3`，基线 Py3.11.15/np2.4.6/gcc13.3 @2026-07-25）——`id()` 返回对象身份（CPython 里即其内存地址）：

    id before: 10666504
    id after rebind (n=11): 10666536 -> value 11

`id` 变了，说明 `n` 指向的是**另一个对象**，不是"同一个盒子里的值被改了"。这与 C 的"覆盖同一地址"形成鲜明对比。CS61A 用"环境（environment）+ 帧（frame）"图示这套模型：一个帧里放的是"名字→对象"的箭头，赋值就是画/改箭头。

### 1.4.3 赋值到底改了什么：一句话对照

把两套模型并排记住，就抓住了本大主题的核心：

    C:      x = v   →  把 v 的位模式【写入】名字 x 所绑定的固定内存位置
    Python: x = v   →  把名字 x【重新指向】对象 v（不复制、不改动任何已有对象）

由此推出的两个初学者常问："Python 赋值会不会拷贝数据？"——**不会**，只是多贴一个标签（下一节 1.5 的别名就源于此）。"C 赋值会不会拷贝？"——对基本类型和结构体，`=` 是**按位复制值**到目标内存（C 传值/赋值是拷贝语义）。这个差异是后面"函数传参"（大主题3）和"别名陷阱"（1.5）的总源头。

## 1.5 别名与身份陷阱

### 1.5.1 Python `is` vs `==`

`==` 比较**值是否相等**（调用对象的相等逻辑）；`is` 比较**是否是同一个对象**（身份，等价于 `id(a) == id(b)`）。二者常常一致但绝不等同。

初学者规则：**比较值一律用 `==`；`is` 只用于和单例比较**，最典型的是

    x is None

因为 `None` 全局只有一个对象，用 `is` 判断既快又准。反过来，**不要用 `is` 比较数值或字符串是否相等**——那要用 `==`。原因见下一条的"小整数缓存"坑。

### 1.5.2 身份陷阱：小整数缓存

CPython 出于优化，会**缓存（intern）一小段常用整数对象**（实现细节：范围为 −5 到 256），这段范围内相等的整数是同一个对象，`is` 会意外地返回 `True`；超出这段则不保证。实测（`python3`，为绕开同一行的常量折叠，用 `int("...")` 在运行时构造）：

    256 case: a == b -> True | a is b -> True
    x == y -> True | x is y -> False      # x=257, y=int("257")

可见 `257 is int("257")` 是 `False`——两个值相等但不是同一对象。**结论：判断数值相等永远用 `==`；`is` 得到的 `True`/`False` 依赖实现，不可依赖**。这个坑几乎每个 Python 初学者都会撞一次（"为什么 `a == b` 是 True 但 `a is b` 有时 True 有时 False？"）。

### 1.5.3 可变对象的共享（别名）

因为 Python 赋值只是"多贴一个标签"（1.4.2），把一个**可变对象**（如 `list`、`dict`、`set`）赋给另一个名字，两个名字指向的是**同一个对象**——这叫别名（alias）。通过任一名字修改它，另一名字"看到"的也变了。实测：

    alias is lst -> True | == -> True
    after alias.append(4), lst = [1, 2, 3, 4]

`alias = lst` 没有复制列表，`alias.append(4)` 改的是那唯一的列表对象，所以 `lst` 也变成 `[1,2,3,4]`。同理链式赋值：

    p = q = []
    p.append(1)
    # 结果 q = [1]

实测输出 `p=q=[]; p.append(1) -> q = [1]`——`p` 和 `q` 是同一个空列表的两个标签。想要独立副本必须显式拷贝（`lst.copy()`、`list(lst)` 或 `copy` 模块）。

一个由此派生的著名坑（点到即止，深挖归 L3-04）：**可变默认参数**

    def f(item, bucket=[]):   # 默认列表只创建一次，被所有调用共享——危险

对可变对象要格外警惕"是共享还是独立"。反之，**不可变对象**（`int`/`str`/`tuple`）没有这个问题：它们不能被原地修改，"修改"只能产生新对象、再改名字指向，别名之间互不影响。这就是为什么初学者感觉"数字和字符串很安全，列表和字典很危险"。

### 1.5.4 C 的对照：同一地址的多个名字

C 里也有别名，但机制不同：C 通过**指针/引用让多个名字指向同一块内存**。例如

    int a = 5;
    int *p = &a;   // p 指向 a 的地址
    *p = 9;        // 通过 p 修改，a 也变成 9

此时 `a` 和 `*p` 是同一块内存的两个访问路径——这是 C 版的别名。与 Python 的差异在于：**Python 的别名是"多个名字→同一对象"（默认、隐式，赋值即可能产生）；C 的别名是"多个指针→同一地址"（显式，你得亲手取地址/传指针）**。C 里普通的 `int b = a;` 是**拷贝**（把 a 的位复制给 b 的独立内存），改 `b` 不影响 `a`——这恰与 Python 可变对象赋值相反，是初学者跨语言时最易混的点。指针别名的机制细节归大主题6，此处只需建立"C 别名靠显式指针、Python 别名靠隐式共享引用"的对照直觉。

- 一手锚点：Python 3.11 Language Reference §3.1「Objects, values and types」（身份 identity、`id()`、`is` 比较身份）、§6.10.3「Identity comparisons」（`is`/`is not`）、§6.10「Comparisons」（`==` 比较值）。Python 官方文档「Built-in Functions · id()」（身份，CPython 中为地址）；关于小整数缓存为 CPython 实现细节（官方多处注明 `is` 用于身份、不应用于值判等）。K&R 2nd ed Ch5「Pointers and Arrays」§5.1–5.2（`&`/`*`、通过指针别名同一对象）；C11 §6.5.16.1（简单赋值为按值拷贝到左值对象）。核实 2026-07-26。
- 比对结论：`is`（身份）vs `==`（值）在 Python Reference §3.1 与 §6.10 一致，且与实测（`id`/`is`）互证。C 指针别名 K&R §5.1 与 C11 §6.5.3.2（一元 `&`/`*`）一致。
- 实测坐实：小整数缓存 256（`is True`）vs 257（`is False`）、列表别名 `alias.append` 影响 `lst`、`p=q=[]` 共享——均本机真实输出（基线串见正文）。
- 冲突/易混点：小整数 `is` 的结果（256 True / 257 False）是 **CPython 实现细节**，非语言规范承诺，硬标"依赖实现、勿依赖"。同一行 `x=257; y=257` 因常量折叠可能 `is True`，故实测特意用 `int("257")` 在运行时构造以暴露真相——这本身也是"别用 `is` 判值"的佐证。
