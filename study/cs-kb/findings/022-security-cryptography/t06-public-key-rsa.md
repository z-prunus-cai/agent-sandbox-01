## 6.1 公钥革命动机

### 6.1.1 密钥分发问题与 O(n²) 密钥爆炸

在公钥密码出现之前，所有加密都是**对称的**：通信双方必须先共享同一把秘密密钥。这带来一个根本困境——两个素未谋面的人，如何在一条可能被窃听的信道上，商定出一把只有他们俩知道的密钥？这就是**密钥分发问题（key-distribution problem）**。

在一个 N 人的网络里，若要求任意两人都能私密通信，每一对都要一把独立的对称密钥，总数是

C(N, 2) = N·(N−1)/2

这个数量随人数平方增长，N=1000 人就需要约 50 万把密钥，且每个人要安全保管 N−1 把。密钥的产生、分发、更新、撤销都成了运维噩梦。历史上的解法是设一个在线**密钥分发中心（KDC）**替大家中转密钥，但 KDC 成了单点故障与单点信任——它能读所有人的通信，一旦被攻破全网沦陷。

初学者可以这样体会问题的本质：对称加密像一把物理的锁和唯一的钥匙，你要先把钥匙的复制品**安全地**送到对方手里，可送钥匙本身又需要一条安全信道——这就成了"先有鸡还是先有蛋"。公钥密码的革命性正在于打破这个循环：让加密和解密用**不同**的密钥，加密密钥可以大大方方公开。

### 6.1.2 公钥革命：Diffie–Hellman 1976

1976 年 Whitfield Diffie 与 Martin Hellman 在《New Directions in Cryptography》中提出**公钥（非对称）密码**的设想：每个用户持有一对密钥，一把**公钥 pk** 任意公开，一把**私钥 sk** 严格保密；任何人都能用 Alice 的公钥加密并只有 Alice 能用私钥解密。于是要给 Alice 发密信，不再需要事先与她共享秘密，只要查到她公开的 pk 即可。

在 N 人网络里，公钥密码把密钥总量从 O(N²) 降到 O(N)——每人只保管自己的一把私钥，公钥登记在公开目录里。密钥分发问题被转化为"如何确认某把公钥确实属于 Alice"的**认证**问题（由后续大主题 09 的 PKI/证书解决），而不再是"如何秘密传送密钥"的机密性问题。

对初学者，最容易混淆的一点是"公钥加密"与"密钥交换"是两件相关但不同的事。Diffie–Hellman 论文里既提出了公钥加密的**思想**，也给出了具体的 DH **密钥交换**协议（本课大主题 07 详述）——DH 让双方协商出一把共享对称密钥；而公钥**加密**（RSA、El Gamal）让人直接用对方公钥加密消息。二者都属于"非对称"世界，但一个交换密钥、一个直接加密。RSA（1977，Rivest–Shamir–Adleman）是第一个同时能做加密和签名的具体公钥方案。

### 6.1.3 陷门单向置换的思想

公钥加密要能成立，需要一种特殊函数：**陷门单向置换（trapdoor one-way permutation）**。它是一族置换 f，满足三条——正向 f(x) 容易算；没有陷门时由 f(x) 反求 x 在计算上不可行（单向）；但持有陷门信息 td 的人能高效求逆。

把它对应到公钥加密：公钥 pk 描述正向函数 f（谁都能加密），私钥 sk 就是陷门 td（只有持有者能解密）。RSA 里的 f 是模幂

f(x) = x^e mod n

它在 Z_n* 上是一个置换；陷门是 n 的分解（等价地，解密指数 d）。反过来"不知分解就求 e 次方根"被相信是难的，这就是后面 6.2 要正式陈述的 RSA 假设。

为什么强调是"置换"而不是一般的单向函数？因为加密要求可逆——每个密文必须唯一对应一个明文，解密才不会歧义。单向**置换**恰好保证 f 是双射，加密不丢信息、解密结果唯一。一个直觉比喻：陷门函数像一把带暗锁的挂锁，任何人都能"啪"地一按锁上（正向易算），但没有钥匙谁也打不开（单向），只有持钥匙的人一转即开（陷门求逆）。需要提醒的是，"陷门置换 ⇒ 直接拿来加密就安全"是错觉——6.3 会说明为什么裸用陷门置换会出大问题。

## 6.2 教科书 RSA

### 6.2.1 密钥生成

教科书（"plain"/"textbook"）RSA 的密钥生成如下。取两个大素数 p、q（各约 1024 比特以给出 2048 比特模数），令

n = p · q

φ(n) = (p − 1)(q − 1)

选公开指数 e，要求 e 与 φ(n) 互素

gcd(e, φ(n)) = 1

再用扩展欧几里得算出 e 关于模 φ(n) 的逆元 d（私有指数）

d = e⁻¹ mod φ(n)

即 e·d ≡ 1 (mod φ(n))。公钥是 (n, e)，私钥是 (n, d)，而 p、q、φ(n) 用完须销毁或严加保密。

这里每个量的角色要分清：n 是公开的**模数**，它的比特长度决定安全强度，但它的**分解** p、q 是最高机密——谁知道 p、q 就能算出 φ(n) 从而算出 d。e 常取固定小值 **65537 = 2¹⁶ + 1 = 0x10001**，因为它是素数且二进制只有两个 1，模幂时平方-乘法步数最少、加密最快；用 e=3 也可以但更易踩小指数攻击的坑（见 6.3）。d 一般是与 n 同长的大数，解密因此比加密慢得多。初学者常问"为什么用 φ(n)"：因为 e 次方在 Z_n* 上要可逆，恰好需要 e 与群阶相关量互素，而欧拉定理里控制指数的正是 φ(n)（部分教材/实现改用卡迈克尔函数 λ(n)=lcm(p−1,q−1) 得到更小的 d，二者都满足正确性，RFC 8017 允许两种约定，见本节末）。

### 6.2.2 加密与解密

明文先编码为整数 m，满足 0 ≤ m < n。加密就是用公钥做一次模幂

c = mᵉ mod n

解密用私钥再做一次模幂

m = cᵈ mod n

加解密是同一台"模幂机器"，只是换了指数 e 与 d。

对初学者，关键直觉是"e 和 d 在指数上互相抵消"。因为 e·d ≡ 1 (mod φ(n))，把 c=mᵉ 再取 d 次方得到 m^(ed)，而 ed 比 φ(n) 的倍数多 1，凭欧拉定理这个"多出来的 1 次方"正好把 m 原样吐回。需要强调 m 必须 < n：RSA 一次只能加密一个小于模数的整数，真实消息（可能很长）不能直接塞进来——这正是 6.6 混合加密要解决的问题。另一个易错点：加解密都在模 n 下进行，中间结果绝不允许"溢出到普通整数"，必须每步取模（快速幂天然做到）。

### 6.2.3 陷门置换与正确性证明

RSA 的核心是：映射

f(x) = xᵉ mod n

在 Z_n*（乃至整个 Z_n）上是一个**置换**，其逆映射是 x ↦ xᵈ mod n，陷门就是 d（等价地 n 的分解）。正确性即要证对所有 0 ≤ m < n 都有

m^(ed) ≡ m (mod n)

证明分两步。由 e·d ≡ 1 (mod φ(n)) 可写 ed = 1 + k·φ(n)。当 gcd(m, n)=1 时，欧拉定理给出 m^φ(n) ≡ 1 (mod n)，于是

m^(ed) = m^(1 + k·φ(n)) = m · (m^φ(n))^k ≡ m · 1 ≡ m (mod n)

当 gcd(m, n) ≠ 1（m 是 p 或 q 的倍数，概率极小）时改用中国剩余定理：分别验证模 p 与模 q 都有 m^(ed) ≡ m（用费马小定理），再由 CRT 合并得模 n 也成立。两步合起来说明对**任意** m 正确性都成立。

为什么"知道分解就能求逆"是陷门？因为求 d 需要 φ(n)=(p−1)(q−1)，而算 φ(n) 需要 p、q。攻击者只有公开的 n，若能分解 n 就破了 RSA；反过来目前也没有已知的、不分解 n 就能普遍求 e 次方根的高效方法。把"给定 (n, e, c) 求 m 使 mᵉ ≡ c"的困难性单独抽象出来，就是 **RSA 假设/RSA 问题**——它不强于分解假设（能分解就能破 RSA），是否严格等价仍是开放问题。这解释了安全参数的选取：2020 年代主流要求 n ≥ 2048 比特（约 112 比特安全强度），因为已公开分解的最大 RSA 数为 RSA-250（829 比特，2020 年分解）——具体记录随算力演进，属"⚙参数随时变"。

### 6.2.4 CRT 解密加速

实际实现几乎都用中国剩余定理加速解密。私钥额外预存

dP = d mod (p − 1)

dQ = d mod (q − 1)

qInv = q⁻¹ mod p

解密时分别在模 p、模 q 下做小指数模幂，再合并

m₁ = c^dP mod p

m₂ = c^dQ mod q

h = (qInv · (m₁ − m₂)) mod p

m = m₂ + h · q

结果与直接 cᵈ mod n 相同，但快约 3–4 倍。

道理在于：模幂的开销随模数比特数超线性增长，把一次 2048 比特模数下的幂运算，拆成两次 1024 比特模数下的幂运算，单次便宜得多，两次相加仍划算；且 dP、dQ 比 d 短一半，指数也更短。RFC 8017 §3.2 正式定义了 dP、dQ、qInv 这三个 CRT 参数（分别是 e·dP ≡ 1 mod (p−1)、e·dQ ≡ 1 mod (q−1)、q·qInv ≡ 1 mod p）。一个重要的安全警告：CRT 解密对**故障注入攻击**敏感——若 m₁ 或 m₂ 计算中出错，攻击者可由错误签名/解密结果通过一次 gcd 直接分解 n（Boneh–DeMillo–Lipton 攻击），所以实现必须校验结果。

本机验证（纯 Python + sympy 1.14.0，仓库外 scratchpad 跑完即清）：随机取两个 64 比特素数生成 (n,e,d)，对同一密文分别用直接解密与 CRT 解密，并检查 e·d ≡ 1 (mod φ)。真实输出：

full-flow decrypt ok: True

CRT decrypt ok: True

e*d mod phi == 1: True

## 6.3 教科书 RSA 的不安全性

### 6.3.1 确定性导致不满足语义安全（IND-CPA）

教科书 RSA 是**确定性**的：同一明文 m 用同一公钥加密永远得到同一密文 c=mᵉ mod n。任何确定性加密都不可能达到现代要求的**语义安全 / 选择明文攻击下不可区分性（IND-CPA）**。

原因很直接：IND-CPA 游戏里攻击者提交两个明文 m₀、m₁，收到其中之一的加密，要猜是哪个。对确定性方案，攻击者只要自己把 m₀ 用公钥加密一遍（公钥人人可用！），比对密文是否相等就 100% 猜中。更实际的场景是**消息空间小**时的穷举：若已知密文加密的是"yes"或"no"、某个人名、某个 PIN，攻击者把所有候选逐一加密比对，立即还原明文。初学者要记住的口诀是——**公钥加密必须随机化**，否则加密函数对攻击者完全"透明"。教科书 RSA 缺的正是这份随机性。

### 6.3.2 可乘同态导致可锻性与 CCA 攻破

RSA 的模幂天然满足**可乘同态**：两个密文相乘，解密后等于两个明文相乘。设 c₁=m₁ᵉ、c₂=m₂ᵉ，则

c₁ · c₂ mod n = (m₁ · m₂)ᵉ mod n

即 Enc(m₁)·Enc(m₂) = Enc(m₁·m₂ mod n)。这使 RSA 是**可锻的（malleable）**——不解密就能有意义地篡改密文，直接违反选择密文攻击下的安全（CCA）。

一个经典的 CCA 攻破：攻击者截获目标密文 c=mᵉ，想知道 m 但解密预言机拒绝对 c 本身解密。他挑一个随机 r，构造 c′ = c·rᵉ mod n 送去解密，得到 m′ = m·r mod n，再乘以 r⁻¹ 就还原出 m。因为 c′ 看似一个全新密文，预言机不会拒绝。这说明"陷门置换直接当加密"远不够——可乘结构被当作武器。辅助理解：同态性在别的场合（如同态加密投票）是优点，但对追求 CCA 安全的通用加密，它是致命的可锻性。

本机验证（同前环境）：随机 (n,e,d) 下，取 m_a=7、m_b=9，检验 Enc(7)·Enc(9) 解密是否等于 63。真实输出：

Enc(a)*Enc(b) decrypts to a*b: True 63 63

### 6.3.3 小指数与小明文攻击

用小公开指数（尤其 e=3）而不填充时，若明文太小使得 mᵉ < n，则 c=mᵉ 根本没发生模约简，攻击者对密文直接开 e 次整数方根就得到 m：

若 mᵉ < n，则 m = c^(1/e)（普通整数开根）

更进一步是 **Håstad 广播攻击**：同一消息 m 用 e=3 发给至少 3 个不同模数 n₁,n₂,n₃ 的收件人（三个密文 c_i=m³ mod n_i），攻击者用 CRT 把三式合并得到 m³ mod (n₁n₂n₃)，因 m³ < n₁n₂n₃ 而直接开立方根还原 m。相关的还有 **Coppersmith 攻击**（已知明文高位或低指数下的部分信息可多项式时间求解）与 **Franklin–Reiter 相关消息攻击**。

这些攻击的共同教训是：小 e 本身不是漏洞（e=65537 很常用且快），漏洞在于**不填充**——没有随机填充时，消息的代数结构（太小、线性相关、跨模数相同）被攻击者利用。填充的作用之一就是把 m 撑大到接近模数长度并注入随机性，破坏这些结构。初学者不必记住每种攻击的细节，只需记住结论：**任何真实系统都绝不能用教科书 RSA，必须加规范化的随机填充（OAEP）或改用混合加密**。

## 6.4 RSA-OAEP 与 PKCS#1

### 6.4.1 填充为什么必要、OAEP 是什么

要把 RSA 变成安全加密，必须在模幂前对消息做**随机化填充**。当前标准做法是 **RSA-OAEP（Optimal Asymmetric Encryption Padding，Bellare–Rogaway 1994）**，即先用 OAEP 把消息编码成一个与模数等长、含随机种子的整数块 EM，再对 EM 做 RSA 模幂。OAEP 在**随机预言模型（ROM）**下、基于 RSA 假设可证明达到 **IND-CCA 安全**——这正是教科书 RSA 缺的两条（随机化 + 抗 CCA）。

直觉上 OAEP 做两件事：注入随机种子让加密不再确定（挡住 6.3.1 的问题），并把消息经两轮"哈希掩码"彻底打散、绑上冗余校验（挡住 6.3.2/6.3.3 的代数结构攻击）。它像一个双向的搅拌器（Feistel 式两轮）：解密方只有先解出全部再逐层"解搅拌"才能拿到消息与校验值，任何对密文的局部篡改都会让解出的块变成一堆随机噪声、校验失败，从而消除可锻性。

### 6.4.2 OAEP 编码步骤（RFC 8017 §7.1）

设哈希输出长 hLen，RSA 模数字节长 k，标签 L（默认空）。OAEP 编码（EME-OAEP，RFC 8017 §7.1.1）如下：

lHash = Hash(L)

PS = k − mLen − 2·hLen − 2 个 0x00 字节（填充串）

DB = lHash ‖ PS ‖ 0x01 ‖ M

seed = 随机 hLen 字节

dbMask = MGF(seed, k − hLen − 1)

maskedDB = DB ⊕ dbMask

seedMask = MGF(maskedDB, hLen)

maskedSeed = seed ⊕ seedMask

EM = 0x00 ‖ maskedSeed ‖ maskedDB

最后对 EM 转成整数做 RSA 加密 c = EM^e mod n。其中 MGF 是掩码生成函数（MGF1，基于哈希，见 RFC 8017 §B.2.1）。解密时反向：RSA 解出 EM，用 maskedDB 恢复 seedMask 得 seed，再恢复 DB，核对 lHash 与 0x01 分隔符正确后取出 M。

对初学者，几个要点：seed 是每次加密新取的随机数，保证同一 M 每次密文都不同（随机化）；lHash 与 0x01 分隔符是**冗余校验**，解密方靠它判断填充是否合法，非法即拒绝——这份冗余就是抗 CCA 的关键；两次 MGF 掩码构成一个两轮 Feistel，使 seed 与 DB 互相"锁死"，改动任一部分都会雪崩式破坏另一部分。实现上必须小心 OAEP 解码错误也可能成为侧信道（Manger 攻击针对不规范实现），错误处理需常时且不区分错因。

### 6.4.3 PKCS#1 v1.5 与 Bleichenbacher 隐患

在 OAEP（PKCS#1 v2.x）之前，广泛部署的是 **PKCS#1 v1.5** 填充（RFC 8017 §7.2 仍收录为 RSAES-PKCS1-v1_5）。它把消息填成 `0x00 ‖ 0x02 ‖ PS(非零随机) ‖ 0x00 ‖ M`，虽然有随机 PS，但**没有可证明的 CCA 安全**，且解密方需要检查格式是否以 `00 02` 开头。

1998 年 **Bleichenbacher 攻击**利用了这个格式检查：若服务器对"填充是否合法"给出可区分的响应（一个**填充预言机 padding oracle**），攻击者反复构造 c·sᵉ mod n 送去、观察是否"填充合法"，用自适应选择密文逐步逼近，约百万次查询即可解出任意密文对应的明文——史称"百万消息攻击"。它是一次实打实的自适应 CCA。2017 年的 **ROBOT** 研究表明大量 TLS 实现二十年后仍存在此类可利用的预言机变体。

这段历史的教训对初学者很重要：不要自己发明填充；新系统一律用 OAEP（加密）而非 v1.5，或直接走 KEM/DEM（6.6）。TLS 也因此在 1.3 版彻底删除了 RSA 密钥传输（RSA key transport），改用（EC）DHE。需要标注版本：RFC 8017 = **PKCS#1 v2.2（2016-11）**，是当前 PKCS#1 主规范，同时收录 OAEP（推荐）与 v1.5（仅为兼容，附安全警告）。TLS 1.3 见 RFC 8446（2018）。

## 6.5 El Gamal 加密

### 6.5.1 构造：基于离散对数的随机化加密

El Gamal（1985）是另一条路线的公钥加密，安全性基于**离散对数 / 判定性 Diffie–Hellman（DDH）**假设，而非分解。工作在一个阶为素数 q 的循环群 G 中，生成元 g（如 Z_p* 的大素数阶子群，或椭圆曲线群）。密钥生成取随机私钥 x 并公开

h = gˣ

公钥是 (G, q, g, h)，私钥是 x。加密消息 m（须是群元素）时，每次取**新的随机数** y，输出一对

c₁ = gʸ

c₂ = m · hʸ

解密用私钥 x 恢复共享掩码并去除

m = c₂ · (c₁ˣ)⁻¹ = c₂ · c₁^(−x)

正确性显然：c₁ˣ = gˣʸ = hʸ，正是加密时乘上的掩码，除掉即得 m。

直觉是"一次性 DH 掩码"：c₁=gʸ 是发送方的临时 DH 公钥，c₁ˣ=hʸ=gˣʸ 是发送方与收件人之间**当场算出的一次性 DH 共享值**，用它当掩码把 m 乘起来。收件人用自己的私钥 x 重算同一个共享值即可解掩。因为每次 y 都重取，同一 m 每次密文都不同——El Gamal 天生随机化，直接满足 IND-CPA（在 DDH 假设下），补上了 RSA 靠填充才有的随机性。密文是明文的两倍长（两个群元素），这是它的代价。

### 6.5.2 同态性、可锻性与安全边界

El Gamal 也是**可乘同态**的：两个密文逐分量相乘

(c₁, c₂) · (c₁′, c₂′) = (c₁·c₁′, c₂·c₂′)

解密得到 m·m′。因此和裸 RSA 一样是**可锻的**，只满足 IND-CPA 而**不满足 IND-CCA**——要 CCA 安全需改造（如 Cramer–Shoup，或经 Fujisaki–Okamoto 变换、或放进 KEM/DEM 框架）。

其一，明文必须先**编码为群元素**（不能是任意比特串），这在实践中很别扭，是 El Gamal 直接加密少见、而其 KEM 形态（DHIES/ECIES）常见的原因（见 6.6）。其二，随机数 y **绝不可复用**：两条消息用同一 y，则 c₂/c₂′ = m/m′ 直接泄露明文比值，与 OTP 密钥重用同类灾难。其三，安全假设分层——IND-CPA 需要 DDH（判定版）成立；若群选得不好（如整个 Z_p* 而非素数阶子群）DDH 可能不成立，须用素数阶子群。El Gamal 的现代形态几乎都在椭圆曲线群上（ECC，见大主题 07），因为同等安全下密钥更短。

### 6.5.3 与 RSA 的对照

El Gamal 与 RSA 是两大公钥家族的代表，值得并置理解。RSA 基于分解、加密确定（需 OAEP 填充才随机化与 CCA 安全）、密文与模数等长、加密快（小 e）解密慢；El Gamal 基于离散对数/DDH、天生随机化、密文是明文两倍长、加解密都是若干次群幂。签名侧二者也各有对应（RSA 签名 / DSA、Schnorr，见大主题 08）。

两者都可以纳入"陷门 + 掩码"框架——RSA 的陷门是分解、掩码是模幂置换；El Gamal 的陷门是私钥 x、掩码是一次性 DH 值。它们各自的裸形态都不够安全（RSA 可锻、El Gamal 可锻），现代实践都倾向把它们降格为**只负责传递一把随机密钥**的 KEM，再交给对称加密处理真正的数据——这就引出 6.6。

## 6.6 KEM/DEM 混合加密

### 6.6.1 混合加密：为什么不直接用公钥加密数据

公钥加密（RSA、El Gamal）有两大实用限制：慢（模幂比对称加密慢几个数量级）、且一次只能加密一个小于模数/群阶的短块。因此真实系统几乎从不直接用公钥加密长消息，而用**混合加密（hybrid encryption）**：用公钥只加密一把随机的**对称会话密钥 k**，再用快速的对称加密（AES-GCM 等 AEAD）加密真正的数据。

**KEM/DEM** 是混合加密的标准抽象（Cramer–Shoup 提出）。它把过程拆成两个模块：

KEM（Key Encapsulation Mechanism，密钥封装）：Encaps(pk) → (c, k)，输出一个封装密文 c 与一把随机对称密钥 k；Decaps(sk, c) → k 用私钥恢复 k。

DEM（Data Encapsulation Mechanism，数据封装）：用对称密钥 k 加密数据，Enc_k(m)（通常是一次性安全的 AEAD）。

完整密文是 (c, Enc_k(m))：收件人先 Decaps 得 k，再对称解密得 m。

关键差别在于 KEM **不加密外部给定的消息**，而是**自己内部生成**一把随机密钥并封装它——这比"用公钥加密一个我选定的 k"更容易做到 CCA 安全，也回避了 El Gamal"明文须为群元素"、RSA"须填充"的编码麻烦。以 RSA-KEM（RFC 5990 / ISO 18033-2）为例：取随机整数 r ∈ [0, n)，令 c = rᵉ mod n，密钥 k = KDF(r)。没有可锻性可利用的明文结构，简洁而稳健。

### 6.6.2 CCA 组合定理

KEM/DEM 之所以是主流范式，是因为有干净的**组合定理**：

若 KEM 是 IND-CCA 安全的，且 DEM 是（一次性）CCA/AEAD 安全的，则由二者拼成的混合加密方案是 IND-CCA 安全的。

也就是说，只要分别把两块做对，整体的 CCA 安全自动成立。这把"设计一个能加密任意长消息的 CCA 安全公钥方案"这个难题，分解为两个更小、更好分析的子问题。

对初学者，几点收束：其一，每条消息用**全新随机**会话密钥 k，所以对称层只需"一次性"安全，DEM 常直接用 AES-GCM 这类 AEAD，天然带认证、抗篡改。其二，KDF/哈希把封装出的原始秘密（RSA 的 r、DH 的 gˣʸ）派生成定长对称密钥，顺带在随机预言模型里帮助达成 CCA。其三，这套范式统一了不同公钥原语：DH/ECDH 封装 → DHIES/ECIES；RSA 封装 → RSA-KEM；后量子 → ML-KEM（FIPS 203，见大主题 11）都用同一 KEM/DEM 骨架。理解了它，TLS 1.3、加密邮件、混合 PQC 迁移就都是同一个模式的实例。

现代实践几乎一律采用混合/KEM-DEM：TLS 1.3（RFC 8446, 2018）用 (EC)DHE 做密钥交换 + AEAD；而 NIST 后量子标准 ML-KEM 也正是一个 KEM，要配对称 DEM 使用——KEM/DEM 已是公钥加密的事实默认形态。
