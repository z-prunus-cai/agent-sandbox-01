## 8.1 签名安全定义

### 8.1.1 数字签名方案的三个算法

一个数字签名方案由三个算法组成：密钥生成 Gen、签名 Sign、验证 Vrfy。Gen 输出一对密钥——私钥（签名密钥）sk 和公钥（验证密钥）pk；持私钥者对消息 m 计算签名

σ ← Sign(sk, m)

任何持公钥者用

Vrfy(pk, m, σ) ∈ {1（接受）, 0（拒绝）}

判定这条签名是否对这条消息合法。正确性要求：诚实产生的签名总能通过验证，即对所有合法密钥对与消息 m 有 Vrfy(pk, m, Sign(sk, m)) = 1。

初学者要先抓住"非对称"这个和 MAC 最大的差别。MAC 里签和验用同一把对称密钥；签名里签用私钥、验用公钥，两把不同，且公钥可以公开发布给全世界。这带来一个关键后果：验证方**不需要**持有任何秘密——它只拿公开信息就能验，这正是签名能面向"任意第三方"建立信任的根本原因。

签名保护的是"完整性 + 来源认证 + 不可否认"，**不是机密性**。签名不加密消息，m 通常与 σ 一起明文传输；想同时保密要另外加密（或用签名加密的组合）。把"签名"想成盖在文件末尾的公开印章，而非把文件锁进保险箱。

### 8.1.2 EUF-CMA：存在性不可伪造（选择消息攻击下）

签名安全的标准定义是 EUF-CMA（Existential Unforgeability under Chosen-Message Attack，选择消息攻击下的存在性不可伪造）。它用一个攻击者与挑战者之间的游戏刻画：

攻击者拿到公钥 pk，并可以自适应地向一个签名预言机查询任意多条它选定的消息 m₁, m₂, … 得到对应签名 σ₁, σ₂, …

攻击者最后输出一对 (m*, σ*)，若满足

Vrfy(pk, m*, σ*) = 1 且 m* 从未被查询过

则攻击者获胜。方案是 EUF-CMA 安全，当且仅当任何高效（多项式时间）攻击者获胜的概率都可忽略。

逐词拆开这个定义能帮你理解它为什么"苛刻到刚刚好"。"选择消息攻击"（CMA）指攻击者能让持私钥者对**任意它挑的消息**签名——这是最强的攻击能力，模拟现实中攻击者可以诱导服务器签各种数据。"存在性不可伪造"（EUF）指哪怕攻击者只造出**某一条**（哪怕是无意义的乱码）新消息的合法签名就算破防——门槛压到最低。合起来就是"即使给你最强的能力，你连一条新签名都造不出"，这才是够强的安全保证。

初学者常有一个困惑——为什么"从未被查询过"这条限制是必要的？因为如果 m* 允许等于查询过的消息，攻击者直接把预言机给它的 σ 原样交回就"赢"了，那根本不算伪造。所以获胜条件必须排除"重放旧签名"。更强的变体叫 sEUF-CMA（强不可伪造）：连"对已查询消息造出一条**不同**的新签名"都不允许——这对区块链等场景（签名可锻造性会导致交易 malleability）很重要，Ed25519 在规范约束 S 范围后可达此性质。

### 8.1.3 签名 vs MAC：不可否认性的根本区别

签名和 MAC 都提供消息完整性与来源认证，但只有签名提供**不可否认性**（non-repudiation）：签名者事后无法抵赖"这条消息不是我签的"。MAC 做不到，因为 MAC 的验证方也持有同一把对称密钥、同样能造出合法标签——所以一个合法 MAC 只能向"共享密钥的双方内部"证明来源，无法向第三方（如法官）证明"是对方而非验证方自己造的"。

Alice 用私钥签了一份合同发给 Bob。日后 Alice 抵赖，Bob 可以把 (合同, 签名) 连同 Alice 的公钥交给任何仲裁者——仲裁者验证通过就知道"只有持 Alice 私钥的人能签出它"，Alice 赖不掉。换成 MAC：Alice 和 Bob 共享密钥 k，Bob 手里的合法标签既可能是 Alice 造的、也可能是 Bob 自己造的（他也有 k），仲裁者无从区分，于是不可否认性荡然无存。

MAC = 完整性 + 来源认证（对称、双方内部、**可否认**、快）；签名 = 完整性 + 来源认证 + **不可否认**（非对称、面向第三方、公开可验、慢）。另一个实践含义是**分发成本**：n 方两两通信用 MAC 需要 O(n²) 把共享密钥，用签名每方只需一对密钥、公钥公开发布即可，这也是签名成为 PKI/TLS 认证基石的原因。代价是签名的公钥运算比对称 MAC 慢几个数量级，所以实际协议里常"签一次哈希 + 后续用对称保护"。

## 8.2 RSA 签名与 PSS

### 8.2.1 教科书 RSA 签名及其缺陷

RSA 签名沿用 RSA 陷门置换（G11-06）：公钥 (n, e)、私钥 d，满足 ed ≡ 1 (mod φ(n))。最朴素（"教科书"）的做法是把消息 m 当作 Zₙ 中的元素，签名与验证为

σ = mᵈ mod n

m ?= σᵉ mod n（验证时用公钥还原，比对是否等于原消息）

它数学上对称于 RSA 加密（签名 = 用私钥"解密"，验证 = 用公钥"加密"），但直接这样用是**不安全**的，绝不能在生产中使用。

第一个致命缺陷是**可乘同态导致的伪造**。RSA 满足 (m₁m₂)ᵈ ≡ m₁ᵈ · m₂ᵈ (mod n)，即两条消息签名的乘积正好是它们乘积的签名。攻击者拿到 m₁、m₂ 的签名 σ₁、σ₂，不需要私钥就能算出 σ₁σ₂ mod n，它是新消息 m₁m₂ mod n 的合法签名——这直接违反 EUF-CMA。更极端地，攻击者甚至能**不查询任何签名**就伪造：随便挑一个 σ，声称它是消息 m = σᵉ mod n 的签名，验证必然通过（虽然 m 是"垃圾消息"，但按 EUF-CMA 存在性伪造已算破防）。

第二个问题是**没有绑定哈希、无法处理长消息**：教科书 RSA 只能签小于 n 的整数。正确的现代做法是先用抗碰撞哈希把任意长消息压成固定长摘要 H(m)（这也是抗碰撞性对签名至关重要的原因，见 G11-05），再对经过**结构化填充**的摘要做私钥运算。填充的作用正是破坏上面的可乘结构、注入冗余，让"随便挑 σ 反推 m"落到合法编码之外。下面两节就是两种填充方案。

### 8.2.2 RSASSA-PKCS1-v1_5：确定性填充

PKCS#1 v1.5 签名填充（RFC 8017 记为 RSASSA-PKCS1-v1_5）是把摘要包进一个固定结构的编码消息 EM 再做私钥幂运算。编码结构为

EM = 0x00 ‖ 0x01 ‖ PS ‖ 0x00 ‖ T

其中 PS 是一串填满的 0xFF 字节（保证 EM 长度等于模长），T 是一个 DER 编码的结构，里面含"哈希算法标识符 + 摘要 H(m)"。签名与验证仍是

σ = EM(m)ᵈ mod n

验证时，由 σᵉ mod n 还原出 EM′，再**重新独立计算** EM(m)，逐字节比对二者是否相等。

它是**确定性**的：同一条消息、同一密钥永远得到同一个签名（因为没有随机成分）。这一点和下面的 PSS 形成对照。其中 0xFF 填充和固定前缀 0x00 0x01 引入了大量冗余结构，破坏了教科书 RSA 的可乘同态、堵住了 8.2.1 的存在性伪造。

初学者需要知道现状——RFC 8017 明确"没有已知针对 RSASSA-PKCS1-v1_5 的攻击"，它在 TLS 证书、老系统里仍大量使用；但它**缺乏可证明安全性归约**，且历史上实现层面反复出问题——最著名的是验证方偷懒不"重新计算 + 严格比对"而是宽松地在 EM 里"找"摘要，导致 Bleichenbacher 的 e=3 签名伪造。因此 RFC 8017 建议**新应用改用 RSA-PSS**。要区分两个 Bleichenbacher 攻击：这里的是**签名伪造**（宽松验证），G11-06 里的是针对 PKCS#1 v1.5 **加密**的 padding oracle，两者同名不同事。

### 8.2.3 RSASSA-PSS：概率填充与可证明安全

RSA-PSS（Probabilistic Signature Scheme，RFC 8017 记为 RSASSA-PSS）是带随机盐的概率填充方案，在随机预言模型下有紧的安全性归约到 RSA 问题，是 RFC 8017 为新应用推荐的方案。它的编码（EMSA-PSS）核心步骤为：

mHash = Hash(M)

M′ = (0x)00 00 00 00 00 00 00 00 ‖ mHash ‖ salt

H = Hash(M′)

DB = PS ‖ 0x01 ‖ salt

maskedDB = DB ⊕ MGF(H)

EM = maskedDB ‖ H ‖ 0xbc

其中 salt 是每次签名新抽的随机盐，PS 为零填充，MGF 是基于哈希的掩码生成函数。之后同样 σ = EM ᵈ mod n。

它是**概率性**的：同一条消息每次签出的签名都不同（因为盐随机）。这与 PKCS1-v1.5 的确定性相反——初学者常问"签名不唯一会不会有问题"，答案是不会，验证方不需要重算出同一个 σ，而是从 σᵉ mod n 还原 EM 后**恢复出盐、重算 H 并比对**，任何合法盐都能通过。随机盐 + 哈希掩码把摘要彻底打散，使得攻击者既无法利用可乘结构，也无法把 σ 反推到某个合法 EM，这正是它能被严格归约证明安全的关键。

在版本与时效上，RSA-PSS 与 PKCS1-v1.5 均定义在 **RFC 8017（PKCS#1 v2.2，2016-11）**，也被 FIPS 186-5（2023）纳为批准的 RSA 签名方案。记忆口诀——**PSS 概率、可证明安全、新应用首选；v1.5 确定性、无归约、legacy 兼容仍在用**。

## 8.3 DSA/ECDSA

### 8.3.1 基于离散对数的签名思想

DSA（Digital Signature Algorithm）与 ECDSA（Elliptic Curve DSA）的安全性建立在离散对数难题上（G11-07）：给定循环群里的生成元 G 与公钥点/元素 Q = [x]G，从 Q 反求私钥 x 是困难的。DSA 工作在素数域乘法子群 Zₚ* 中，ECDSA 工作在椭圆曲线点群中；两者代数结构同构，ECDSA 只是把"模幂 gᵏ"换成"标量乘 [k]G"，因此在同等安全强度下密钥/签名短得多（256 位 ECDSA ≈ 3072 位 DSA）。

对初学者，先建立与 RSA 的对照：RSA 靠"分解难"，(EC)DSA 靠"离散对数难"，是**两个不同的困难假设**族。RSA 签名可以从公钥"还原"出被签的编码消息；而 (EC)DSA 签名**不可还原消息**——验证是"重算一个量、看它是否等于签名里的分量"，这是离散对数类签名的通用形态（Schnorr 也是，见 8.5）。

还有一个统摄性的观察——DSA/ECDSA 每次签名都要抽一个**一次性随机数 k**（称 nonce 或 per-message secret），签名的两个分量都由它派生。这个 k 是整个方案最脆弱的地方——8.3.3 会看到它一旦泄露或复用就直接暴露私钥。

### 8.3.2 ECDSA 签名与验证步骤

设域阶（子群阶）为 n，私钥 x，公钥 Q = [x]G，消息摘要 e = Hash(m)（取其最左若干位以匹配 n 的比特长）。签名步骤为：

抽随机 k ∈ [1, n−1]

计算点 (x₁, y₁) = [k]G

r = x₁ mod n （若 r = 0 重抽 k）

s = k⁻¹ · (e + r·x) mod n （若 s = 0 重抽 k）

签名 σ = (r, s)。

验证（用公钥 Q、消息摘要 e）步骤为：

检查 r, s ∈ [1, n−1]

w = s⁻¹ mod n

u₁ = e·w mod n，u₂ = r·w mod n

计算点 (x₁, y₁) = [u₁]G + [u₂]Q

接受当且仅当 r ≡ x₁ (mod n)

验证为什么成立，值得一走代数（帮助理解 nonce 的角色）：由 s = k⁻¹(e + rx) 得 k = s⁻¹(e + rx) = w·e + w·r·x = u₁ + u₂·x。于是 [u₁]G + [u₂]Q = [u₁]G + [u₂x]G = [u₁ + u₂x]G = [k]G，其 x 坐标正是 r，验证通过。初学者可以只记结论：验证方在不知 k、不知 x 的情况下，靠公钥把 [k]G 重建出来并核对 r。

还有几个要点值得强调。e 是摘要不是原消息，取"最左 n 比特"而非取模，这是 FIPS 186-5 的规定（易错点）；r 只取点的 x 坐标 mod n，所以 ECDSA 天然存在签名可锻造性——(r, s) 与 (r, −s mod n) 都是合法签名（low-s 规范化用于消除，比特币等强制）。ECDSA 使用的曲线在 FIPS 186-5 中为 P-256/P-384/P-521（二进制域曲线已弃用）。

### 8.3.3 nonce 泄露或复用的致命性

(EC)DSA 的头号杀手是 nonce k：它必须每次唯一且完全保密。**任一条件被破坏都直接泄露私钥。**

先看复用的情形——两条不同消息用了同一个 k。设 σ₁ = (r, s₁) 对应摘要 e₁、σ₂ = (r, s₂) 对应摘要 e₂（同 k 使 r 相同，一眼可辨）。由两式相减 k 可解出

k = (e₁ − e₂) · (s₁ − s₂)⁻¹ mod n

再回代任一式解出私钥

x = (s₁·k − e₁) · r⁻¹ mod n

于是攻击者仅凭两条公开签名就恢复了完整私钥。

再看部分泄露的情形——即便只泄露 k 的少数比特（例如通过侧信道拿到每次 nonce 的几个高位），跨多条签名用格归约（Hidden Number Problem / LLL）也能重建私钥。这就是为什么 nonce 生成的质量是 (EC)DSA 安全的命门。历史真实案例：2010 年 Sony PlayStation 3 因对所有游戏签名复用同一个固定 k 被 fail0verflow 直接算出主签名私钥；多起比特币盗币源于钱包 RNG 弱导致 nonce 碰撞。

现代缓解是**确定性 nonce**：不再依赖随机数发生器，而是把 k 由私钥和消息一起用 HMAC 派生出来——RFC 6979 定义了确定性 ECDSA，FIPS 186-5（2023）也批准了这一变体。它保证同一 (私钥, 消息) 恒得同一 k、不同消息几乎不可能撞 k，从根上消除"坏 RNG 导致复用"。这正是下一节 EdDSA 的核心设计理念。（本项的 nonce 复用恢复私钥代数关系可用小素数群在 scratchpad 教学级实证；本次未逐条落地运行，代数推导已由 Katz §13.5 与 FIPS 186-5 两源核对，标此实证为可选未取。）

在时效上还要记住 DSA 的退役状态。FIPS 186-5（2023-02-03 生效）中，**DSA 已被移除为签名生成的批准算法，仅保留用于验证既有签名**——理由是产业使用有限且实现易受攻击。新系统应使用 ECDSA 或 EdDSA。

#### 来源与时效（本小主题末集中列，不逐项脚注）
- 锚点：NIST FIPS 186-5（2023-02-03 生效）§6（ECDSA：签名生成/验证步骤、批准曲线 P-256/384/521）、§3（DSA 退役为"仅验签"）、§6.3（RFC 6979 确定性 ECDSA 变体获批），本次经 WebSearch 核对 nvlpubs.nist.gov 与 Federal Register 公告，核实 2026-07-30。
- 锚点：Katz & Lindell 3rd ed. §13.5（DSA/ECDSA 构造、离散对数签名范式、nonce 唯一性要求与复用泄露私钥），核实 2026-07-30。
- 锚点：IETF RFC 6979（Deterministic Usage of DSA and ECDSA, 2013-08）§1–§3（确定性 nonce 派生动机与构造），核实 2026-07-30。
- 交叉核对：ECDSA 签名/验证公式在 FIPS 186-5 §6 与 Katz §13.5 一致；nonce 复用 k=(e₁−e₂)(s₁−s₂)⁻¹、x=(s₁k−e₁)r⁻¹ 的代数推导两源一致。DSA 退役状态以 FIPS 186-5（2023）与 NIST/Federal Register 公告双源坐实，非记忆。

## 8.4 EdDSA/Ed25519

### 8.4.1 EdDSA 的设计动机

EdDSA（Edwards-Curve Digital Signature Algorithm）是基于 Schnorr 签名（8.5）、工作在扭曲爱德华兹（twisted Edwards）曲线上的现代签名族，两个具名实例是 **Ed25519**（用 Curve25519 对应的 edwards25519 曲线 + SHA-512）与 **Ed448**（用 edwards448 + SHAKE256）。它由 RFC 8032 标准化，并被 FIPS 186-5（2023）首次纳入 NIST 批准算法。设计目标是"默认就安全、又快"：消除 (EC)DSA 的 nonce 陷阱、抵抗侧信道、给出高性能实现。

对初学者，把 EdDSA 理解为"修好了所有 ECDSA 坑的离散对数签名"最合适。它相对 ECDSA 的四个主要改良：nonce 确定性派生（8.4.2）、选用完备加法公式的 Edwards 曲线（8.4.3）、签名对整条 (R‖A‖M) 而非仅摘要哈希、以及规范化编码。它已成为 SSH、TLS 1.3、Signal、众多区块链的默认签名。

### 8.4.2 确定性 nonce：从根上消除随机数陷阱

EdDSA 的招牌特征是 nonce **完全确定性**：不使用任何随机数发生器，而是把 nonce r 由私钥派生的"prefix"和消息一起哈希出来。密钥派生与签名的核心步骤（Ed25519）为：

先对 32 字节私钥做 SHA-512，得 64 字节摘要 h；低半 h[0..31] 经"修剪"（clamp）成标量 a，高半 h[32..63] 记为 prefix

公钥 A = 编码([a]B)，B 是标准基点

签名时先确定性派生 nonce r，其中 L 为群阶

r = SHA-512(prefix ‖ M) mod L

R = 编码([r]B)

k = SHA-512(R ‖ A ‖ M) mod L

S = (r + k·a) mod L

签名 σ = R ‖ S（Ed25519 共 64 字节：R 占 32、S 占 32）。

这里的关键是 nonce r 只由 (prefix, M) 决定：同一私钥对同一消息永远得同一签名，不同消息几乎不可能撞 nonce，且 prefix 从私钥哈希而来、对外保密。于是 8.3.3 里"坏 RNG 导致 nonce 复用/泄露 → 私钥全丢"的整类灾难被**结构性地根除**——EdDSA 不给随机数留任何位置。初学者要注意 clamp（修剪）那步不是花架子：清零低 3 位保证标量是 8（余因子）的倍数以防小子群攻击，设定最高位附近的比特保证标量足够大、且让蒙哥马利阶梯常时执行。

### 8.4.3 Edwards 曲线与验证等式

Ed25519 用扭曲爱德华兹曲线，其加法公式是**完备的**（对曲线上任意两点——包括相等点、含无穷远点——同一套公式都成立，无需分类讨论）。这既简化了实现、又天然抵抗因分支带来的侧信道，是它比 ECDSA 所用 Weierstrass 曲线更"防呆"的重要原因。验证步骤为：

把 σ 拆成 R（前 32 字节，解码为点）和 S（后 32 字节，解码为整数，须满足 0 ≤ S < L）；解码公钥 A 为点

k = SHA-512(R ‖ A ‖ M) mod L

接受当且仅当群等式成立：

[8][S]B = [8]R + [8][k]A

验证等式为何成立：由 S = r + k·a，[S]B = [r]B + [k][a]B = R + [k]A，两边乘余因子 8 即得。RFC 8032 说明"检查带 8（余因子）的等式充分但非必需，也可直接检查 [S]B = R + [k]A"——乘 8 的版本能兼容不同实现对小子群点的处理，是"批量验证/宽松验证"的一个已知歧义点。

初学者对照 ECDSA 记两个差别：其一，EdDSA 的挑战 k 把 **R、公钥 A、消息 M 全都哈希进去**（ECDSA 只哈希消息），这带来更强的绑定与 sEUF 友好性；其二，验证是加法群里的线性等式核对，没有求逆、没有取 x 坐标 mod n 的可锻造问题。要求 0 ≤ S < L 这条范围检查若被省略会引入签名可锻造，是实现层面反复出现的坑（RFC 8032 与后续勘误强调必须做）。

在时效上，Ed25519/Ed448 由 **RFC 8032（2017-01）** 标准化，并由 **FIPS 186-5（2023）** 正式纳入 NIST 批准算法——这是 EdDSA 从"广泛部署但非 FIPS"到"合规可用"的关键节点，需注意此前的 FIPS 186-4 并不含 EdDSA。

#### 来源与时效（本小主题末集中列，不逐项脚注）
- 锚点：IETF RFC 8032（EdDSA, 2017-01）§5.1.5（密钥生成、clamp）、§5.1.6（签名步骤：r = H(prefix‖M)、R=[r]B、k=H(R‖A‖M)、S=r+k·a）、§5.1.7（验证等式 [8][S]B=[8]R+[8][k]A 及"充分非必需"说明），本次经 WebFetch 核对 rfc-editor.org 原文，核实 2026-07-30。
- 锚点：NIST FIPS 186-5（2023）§7（EdDSA：Ed25519/Ed448 获批，引用 RFC 8032），本次经 WebSearch 核对，核实 2026-07-30。
- 锚点：Katz & Lindell 3rd ed. §13.5–§13.6（Schnorr/EdDSA 作为离散对数签名，确定性 nonce 的动机），核实 2026-07-30。
- 交叉核对：Ed25519 签名/验证等式在 RFC 8032 与 FIPS 186-5（引用 RFC）一致；"确定性 nonce 消除 RNG 陷阱"在 RFC 8032 §8.5（安全考量）与 Katz §13.5 一致。EdDSA 加入 FIPS 的时点以 FIPS 186-5 vs 186-4 双版本对比坐实。

## 8.5 Fiat–Shamir 与 Schnorr

### 8.5.1 识别协议与 Sigma 协议

要理解 Schnorr 签名和 EdDSA 的来历，先看它们的源头——识别协议（identification protocol）中的三步（Sigma）结构。以证明"我知道公钥 Q=[x]G 对应的私钥 x"为例，证明者 P 与验证者 V 交互三步：

P 抽随机 k，发送承诺 R = [k]G

V 抽随机挑战 c 发给 P

P 计算响应 s = k + c·x（mod 群阶），发给 V

V 验证 [s]G ?= R + [c]Q

这套"承诺（commit）→ 挑战（challenge）→ 响应（response）"的三步式称为 Sigma 协议，是 Schnorr 识别协议的形态。

它为什么能证明"P 知道 x"而又"不泄露 x"？验证等式 [s]G = [k+cx]G = [k]G + [cx]G = R + [c]Q 恒成立，所以诚实的 P 总能通过。而 P 不知道 x 时无法对随机挑战 c 应答（可靠性/soundness）；同时因为 R 是随机的、s 被 k 完全掩盖，V 学不到关于 x 的任何信息（零知识/honest-verifier ZK）。初学者只需记住这是一个"交互式的知识证明"，承诺里的随机 k 起到一次性掩码作用——这个 k 就是后面签名里 nonce 的前身。

### 8.5.2 Fiat–Shamir 变换：从交互协议到签名

Fiat–Shamir 变换（Fiat–Shamir heuristic）把一个交互式 Sigma 协议变成一个**非交互**的签名方案，核心动作只有一句：**把验证者原本随机抛的挑战 c，替换成对"承诺（以及要签的消息）"做哈希的结果**。即令

c = H(R ‖ m)

而不再由验证者交互提供。这样证明者一个人就能生成完整的 (R, s)，谁都能用同一个哈希重算 c 来验证，交互被彻底去掉。

这个变换背后的直觉是，交互协议里验证者随机抛 c 是为了防止作弊者"先知道 c 再倒推承诺"。用一个安全哈希算 c 达到同样效果——因为哈希不可预测且依赖 R，作弊者必须先定 R 才能得到 c，无法逆序作弊。把消息 m 一并喂进哈希，就把"证明我知道私钥"绑定到了"对这条 m 的证明"，识别协议就变成了对 m 的签名。这个变换是随机预言模型下可证明安全的（把 H 理想化为随机预言机），是构造离散对数类签名的通用配方，也是它常在 ROM 下证安全的原因。

初学者常有一个疑问——为什么算 c 时一定要把 R 放进哈希？因为 c 必须"锁死"承诺 R——如果 c 不依赖 R，作弊者就能挑好 c 再反算 R 蒙混。把 R 哈希进去，等于让承诺先于挑战被固定，复刻了交互中"先承诺、后挑战"的时序。

### 8.5.3 Schnorr 签名

对 Schnorr 识别协议施加 Fiat–Shamir 变换，就得到 Schnorr 签名。密钥：私钥 x、公钥 Q = [x]G。签名步骤为：

抽 nonce k，计算承诺 R = [k]G

计算挑战 c = H(R ‖ m)

计算响应 s = k + c·x（mod 群阶）

签名 σ = (R, s)（也可传 (c, s) 变体）。

验证步骤为：

重算 c = H(R ‖ m)

接受当且仅当

[s]G = R + [c]Q

它是所有离散对数签名里结构最干净的：验证就是一条线性群等式，无求逆（对比 ECDSA 需要 s⁻¹）。EdDSA/Ed25519（8.4）本质上就是 Schnorr 签名的一个具体实例——把 nonce k 换成确定性派生的 r、挑战哈希进 A、选 Edwards 曲线。理解了 Schnorr，就理解了 EdDSA 的骨架。

初学者要注意 Schnorr 同样**对 nonce k 极度敏感**：和 (EC)DSA 一样，复用 k 会让 s₁−s₂ = c₁·x − c₂·x 直接解出私钥 x = (s₁−s₂)(c₁−c₂)⁻¹，泄露 k 也是。这正是 EdDSA 用确定性 nonce 的原因。时效补记：Schnorr 签名的原始专利已于 2008 年到期，这解锁了它的广泛采用；比特币 2021 年 Taproot 升级（BIP-340）采用 Schnorr 签名以支持密钥聚合。Schnorr 的线性结构还是门限签名/多签（MuSig）的基础，这是它相对 ECDSA 的一大工程优势。（本项 Schnorr 签名/验证可用小素数群在 scratchpad 教学级实证；本次未逐条落地运行，签名/验证等式与 nonce 复用关系已由 Katz §12–13 与 RFC 8032 背景两源核对，标此实证为可选未取。）
