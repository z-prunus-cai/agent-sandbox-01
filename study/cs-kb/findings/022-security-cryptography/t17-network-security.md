**互联网的核心协议（以太网/ARP、IP、TCP、DNS、BGP）几乎都诞生在一个"默认互信"的年代，安全是事后补丁**。它们大多不认证来源、不校验完整性，于是攻击的通用套路就是"冒充"——冒充别的主机（欺骗）、冒充连接的对端（注入）、冒充域名的权威（投毒）、冒充路由的源头（劫持）；防御的通用套路则是"补上认证与完整性"（DNSSEC、RPKI、TCP 序列号随机化）或"补上过滤与冗余"（入口过滤、限速、IDS）。读本主题的关键是随时问两个问题：这个攻击者站在哪里（能不能看到流量），以及被攻击的协议缺了哪一味安全属性。

## 17.1 低层网络攻击：嗅探、欺骗与敌手模型

### 17.1.1 敌手模型：on-path、off-path、in-path

网络安全的一切分析都从"攻击者站在哪里、能做什么"开始。CS161 把网络敌手按能力分成三档：

on-path（在路径上）敌手能**看到**受害者之间往来的数据包，但不能阻止原包送达；它能抢在真包之前伪造回包（因为它看得到序列号等所有字段），是"窃听 + 抢答"。

off-path（不在路径上）敌手**看不到**流量，只能向网络注入伪造源地址的包；它要成功就必须**猜**出连接里的秘密字段（如 TCP 序列号、DNS 事务 ID），是"盲打"。

in-path / man-in-the-middle（在路径中间，中间人）敌手不但能看，还能**修改、丢弃、延迟**数据包，能力最强，等价于完全控制这段信道。

区分这三档是全大主题的地基。很多攻击（17.2 的 RST 注入、17.3 的 DNS 投毒）都有"on-path 版（容易）"和"off-path 版（要靠猜、要靠概率）"两个变体，难度天差地别。一个常见误区是把"能嗅探"和"能篡改"混为一谈：交换式以太网里一个旁观主机默认只是 on-path 甚至更弱，要升级成中间人往往需要额外一步（如 ARP 欺骗，见 17.1.3），把流量真正引到自己这里来。判断一个防御是否够用，也要看它挡的是哪一档敌手——例如只做序列号随机化只能挡 off-path，挡不了 on-path。

### 17.1.2 嗅探（sniffing / eavesdropping）

嗅探是被动读取经过的网络流量。网卡平时只收发给自己 MAC 地址的帧，但置于**混杂模式（promiscuous mode）**后会把所有听到的帧都交给上层，配合 `tcpdump`/Wireshark/`libpcap` 即可抓包分析。在**共享介质**（早期集线器 hub、无线 WiFi、同一广播域）上，攻击者天然能听到别人的流量；在**交换式以太网**里，交换机按 MAC 地址只把帧转给目标端口，旁观者默认听不到——除非用 MAC 泛洪（MAC flooding，灌满交换机的 CAM 表逼它退化成 hub 广播）或 ARP 欺骗把流量引过来。

嗅探之所以是"万恶之源"，是因为很多老协议**明文**传输：HTTP、Telnet、FTP、早期 SMTP、未加密的 DNS 查询里，账号口令、Cookie、查询内容都一览无余。这解释了为什么"全网 HTTPS 化"是过去十年最重要的安全工程——加密（TLS，见大主题10）把嗅探的收益从"读到明文"降为"只知道你在和谁通信、包多大"。对初学者，记住一条定位：嗅探是**机密性**攻击，本身不改数据；它常常是更强攻击的第一步（先偷到序列号/Cookie/口令，再去注入或冒充）。无线场景尤其要警惕——WiFi 是共享广播介质，未加密热点上任何人都能被动收听。

### 17.1.3 ARP 欺骗（ARP spoofing / ARP poisoning）

ARP（地址解析协议）负责在局域网内把 IP 地址解析成 MAC 地址：主机广播"谁是 10.0.0.1？"，持有者回一个"我是，我的 MAC 是 …"。ARP **无任何认证**，且多数实现会无条件接受甚至主动缓存收到的 ARP 应答（包括没人问就发的"免费 ARP"gratuitous ARP）。攻击者据此不断向受害者宣告"网关 10.0.0.1 的 MAC 是我"，向网关宣告"受害者的 MAC 是我"，两边的 ARP 缓存都被投毒，于是双向流量都先经过攻击者——一个纯 on-path 的旁观者就此**升级成中间人**。

ARP 欺骗是把"只能嗅探"变成"能篡改"的经典跳板，也是本地网络里最实用的攻击之一。它的前提是攻击者与受害者在**同一二层广播域**（同一交换机/同一 WiFi），跨不出子网。防御手段包括：静态 ARP 表（把网关 MAC 写死，不随应答变）、交换机的 Dynamic ARP Inspection（DAI，校验 ARP 应答与 DHCP 绑定表是否一致）、以及端到端加密——即便中间人接管了流量，TLS 也让它读不懂、改不了（只能丢弃）。初学者要抓住的直觉：ARP 欺骗攻击的是"IP↔MAC 映射"这个信任缺口，它不需要猜任何秘密，因为局域网里根本没设防，这也是为什么"内网不可信"是现代零信任的出发点。

### 17.1.4 IP 欺骗（IP spoofing）

IP 欺骗指攻击者伪造数据包的**源 IP 地址**。IP 头里的源地址字段完全由发送方填写、路径上一般不校验，所以伪造源 IP 在技术上轻而易举。它的后果分两类：

一是**单向攻击/反射**——攻击者不在乎收不到回包，只想让回包发去别处或隐藏自己，这是 DoS 反射放大攻击（17.4）的基础：伪造成受害者的 IP 去请求放大器，回包全砸向受害者。

二是**冒充可信来源**——若某服务只按源 IP 做鉴权（如老式 rlogin 的 IP 白名单），攻击者伪造白名单内的 IP 就可能被信任；但这类攻击若需要完成 TCP 握手就退化成 off-path 难题，因为攻击者收不到 SYN-ACK，必须猜出序列号（见 17.2.1）。

IP 欺骗对**只发不收**的场景（UDP 反射）几乎零成本，对**需要双向**的场景（TCP 会话）则受序列号这道盲猜门槛限制。最有效的网络级防御是**入口过滤（ingress filtering，BCP 38 / RFC 2827）**：ISP 在网络边界丢弃源地址不属于本网段的出站包，从源头掐断伪造。可惜 BCP 38 部署并不完全，这正是反射放大攻击至今仍然猖獗的根因。

## 17.2 TCP 与 BGP 攻击：注入与劫持

### 17.2.1 TCP 序列号预测

TCP 用一对 32 位序列号（seq/ack）来编号字节流、拒收不在窗口内的数据。要往一条已建立的 TCP 连接里注入或伪造数据，攻击者必须提供**落在接收窗口内的序列号**。对 on-path 敌手这不是问题（它能看到当前序列号）；对 off-path 敌手，这是一道盲猜门槛——早期系统的初始序列号（ISN）用简单可预测的递增规则生成，攻击者能据此推算，这就是 1994–95 年著名的 **Mitnick 攻击**（用 IP 欺骗 + 序列号预测冒充可信主机建立 TCP 连接）。

三次握手与序列号的关系可写成：

```
客户端 → 服务器:  SYN,  seq = x
服务器 → 客户端:  SYN-ACK, seq = y, ack = x+1
客户端 → 服务器:  ACK,  ack = y+1
```

off-path 攻击者伪造第一步很容易（源 IP 随便填），但收不到第二步里的 `y`，于是无法给出正确的 `ack = y+1` 完成握手——除非它能预测 `y`。防御正是**初始序列号随机化（RFC 6528）**：把 ISN 用一个基于连接四元组的密钥化随机函数生成，让 off-path 攻击者无从预测，从而把 TCP 会话伪造挡在门外。初学者要记住：序列号随机化只对 **off-path** 有效——它增加的是"猜中的难度"；面对能直接看到序列号的 on-path/中间人，它毫无作用，那种场景只能靠 TLS 之类的端到端加密认证。

### 17.2.2 RST 注入与连接重置

TCP 用 RST（reset）标志强制立即终止连接。如果攻击者能发出一个**四元组匹配、序列号在窗口内**的 RST 包，就能让通信一方误以为对端要断开，从而中断连接。on-path 敌手轻松做到（看得到序列号），off-path 敌手则要盲猜序列号——但由于接收窗口有一定宽度，攻击者可以**在整个序列号空间里按窗口大小步进地喷 RST 包**来提高命中概率，这类"盲窗内攻击"是真实威胁。

RST 注入的现实用例很有名：一些网络中间设备（运营商、审查系统）用伪造 RST 来**主动切断特定连接**——历史上 Comcast 曾用 RST 注入干扰 BitTorrent，防火长城也被广泛记录用 RST 注入阻断连接。针对盲注入，IETF 出了 **RFC 5961「Improving TCP's Robustness to Blind In-Window Attacks」**：收紧对 RST/SYN 的接受条件（要求序列号精确匹配下一个期望值、否则回一个 challenge ACK 让对端确认），大幅抬高 off-path 盲打成本。关键定位：RST 注入是**可用性/完整性**攻击（断连或插入数据），其难度同样由攻击者是 on-path 还是 off-path 决定；根治之道仍是端到端加密（TLS 之上的应用不会被伪造明文欺骗，但连接层的 RST 断连仍可发生——所以还需要 QUIC 这类把传输层也加密认证的协议来抵抗连接重置）。

### 17.2.3 BGP 劫持（prefix hijacking） ⚙演进快·锚 2026-07-30

BGP（边界网关协议）是自治系统（AS）之间交换"我能到达哪些 IP 前缀、路径是什么"的域间路由协议。原始 BGP **不认证路由通告**：任何 AS 都可以宣告"我拥有前缀 1.2.3.0/24"，邻居默认相信。BGP 劫持就是恶意或误配的 AS 宣告了不属于自己的前缀，把本该流向真正持有者的流量吸引过来。它有两种形态：

```
精确前缀劫持：宣告与合法方完全相同的前缀 1.2.3.0/24，与真源竞争，靠 AS 路径更短等取胜
子前缀劫持：宣告更具体的 1.2.3.128/25，因路由器按"最长前缀匹配"优先，几乎必然全胜且更隐蔽
```

经典事件是 2008 年 **Pakistan Telecom 误劫持 YouTube**（本想在国内封锁，却把 YouTube 的前缀通告泄漏到全球，导致 YouTube 全球短暂不可达）。劫持可用于流量拦截、窃听、发垃圾邮件、乃至配合发放假证书。

防御正在从"事后监测"转向"密码学验证"，但仍在演进：**RPKI（RFC 6480）**让前缀持有者签发 **ROA（Route Origin Authorization，路由源授权）**，声明"只有 AS X 可以宣告我这个前缀、最长到 /Y"；开启 **ROV（Route Origin Validation，路由源验证）**的路由器据此把 origin 对不上的通告标为 invalid 并丢弃。据 NIST RPKI 监测，截至 2025-04 已有超过 55% 的前缀被 RPKI 认证、约 30% 的网络做 ROV 校验（数值 ⚙演进快，随时变）。局限在于 ROV 只验证"起源 AS 对不对"，**验证不了整条 AS 路径**——路径伪造（把自己插进一条看似合法的路径中间）仍能绕过；解决路径认证的 **BGPsec（RFC 8205）** 需要逐跳签名、对路由器软硬件要求高，截至 2025 年几乎无生产部署（五大 RIR 的 RPKI 仓库当时尚不支持发布 BGPsec 路由器证书）。ASPA（Autonomous System Provider Authorization）等"后 ROV"路径防御处于标准化推进中。对初学者：BGP 安全的现状是"起源验证已初步铺开、路径验证仍是开放难题"，这也是本节硬标演进快的原因。

## 17.3 DNS 与 DNSSEC：缓存投毒与签名链

### 17.3.1 DNS 缓存投毒（cache poisoning）

DNS 把域名解析成 IP。递归解析器（resolver）代客户端向权威服务器逐级查询并**缓存**结果。经典 DNS 用 **UDP**、靠一个 **16 位事务 ID（TXID）** 来把应答和查询配对，且**不做任何来源认证**：只要一个应答的四元组和 TXID 对得上、抢在真应答之前到达，解析器就采信并缓存。off-path 攻击者据此伪造应答——把某域名指向攻击者控制的 IP，一旦投毒成功且被缓存，此后所有查该域名的用户都被导向恶意地址（机密性、完整性、可用性全线失守）。

真正让世界重视这个问题的是 2008 年的 **Kaminsky 攻击**：Dan Kaminsky 发现即便随机化了 TXID，攻击者也能通过**不断查询同一域名的随机子域**制造大量并发查询、并针对每个查询喷大量伪造应答（把恶意记录塞进应答的 Additional/Authority 区去投毒父域的 NS），从而绕过"缓存命中就不再查询"的限制，把成功概率从"偶尔"提升到"很快必中"。因为只有 16 位 TXID（约 6.5 万种），盲猜本就不算难。

打补丁的应对（RFC 5452「DNS Resilience against Forged Answers」）核心是**加大攻击者要猜的熵**：在 TXID 之外再**随机化源端口**，把可猜空间从 16 位提到约 32 位；此外还有 0x20 大小写随机化等技巧。这些是"抬高门槛"而非"根治"——真正的根治是给 DNS 加密码学认证，即 DNSSEC。初学者要记住的定位：DNS 投毒的本质是"应答无认证 + 熵太少"，补丁加熵是治标，DNSSEC 加签名是治本。

### 17.3.2 DNSSEC 签名链（chain of trust）

DNSSEC（DNS Security Extensions，RFC 4033/4034/4035）给 DNS 记录加**数字签名**，让解析器能验证应答确实来自该域的权威、且未被篡改。它**不加密**（DNS 内容仍是公开的），只提供**来源认证 + 完整性**。它新增几类记录：

```
DNSKEY ：区的公钥。通常分两把——KSK（密钥签名密钥）与 ZSK（区签名密钥）
RRSIG  ：对某个 RRset（同名同类型的记录集合）的数字签名
DS     ：Delegation Signer，父区里存放的、对子区 KSK 的哈希，作为向下委派的信任桥
NSEC/NSEC3：对"不存在"做认证应答（防止攻击者伪造否定回答），NSEC3 用哈希防区枚举
```

验证沿 DNS 层级自顶向下形成一条**信任链**：

```
根区公钥（信任锚，浏览器/解析器内置）
   → 根用其 KSK 签名 .com 的 DS 记录
   → .com 的 DNSKEY 经其 DS 哈希核对无误后，用它验证 example.com 的 DS
   → example.com 的 DNSKEY 经其 DS 核对后，验证该区里 A/AAAA 等记录的 RRSIG
```

每一层都用"父区签名的 DS = 子区 KSK 的哈希"把上一环的信任传递下来，最终锚定在全球公开、定期轮换的**根信任锚（root trust anchor / root KSK）**。只要根公钥可信、且每层签名与 DS 校验都通过，解析器就确信这条记录未被投毒——即便应答被 off-path 攻击者伪造，签名也验不过。

对初学者，抓住两个类比：DS 记录像"父母给孩子的介绍信"（父区替子区的公钥背书），RRSIG 像"文件上的公证章"（证明这组记录没被改）。KSK/ZSK 分工是运维考量——ZSK 短、轮换勤（日常签记录），KSK 长、轮换慢（只签 DNSKEY 集合、且要通知父区更新 DS，代价大）。常见易错点：DNSSEC 只保证"记录真实完整"，不保证"记录内容保密"（用 `dig +dnssec` 仍能看到明文），DNS 的机密性要靠另一条线的 DoT/DoH（DNS over TLS/HTTPS）。另一个部署痛点是 NSEC 的**区枚举**问题——认证否定应答时会泄露相邻域名，NSEC3 用哈希缓解但不能完全消除。教学级可用 `dig +dnssec example.com` 与 `dig DS`/`dig DNSKEY` 观察 RRSIG/DS/DNSKEY（仓库外，未逐项实测则如实标注）。

## 17.4 DoS/DDoS 与防御

### 17.4.1 DoS vs DDoS 与攻击分类

拒绝服务（Denial of Service, DoS）攻击的目标是**可用性**——耗尽受害者的某种有限资源，让正常用户用不了服务。当攻击由大量分布在各处的机器（通常是被 Mirai 之类僵尸网络控制的失陷设备）协同发起时，就是**分布式拒绝服务（DDoS）**。DoS 大体分两类：

```
资源耗尽 / 协议型：钻协议状态机的空子，用少量流量占住大量服务端资源（如 SYN flood）
带宽淹没 / 容量型：用海量流量塞满受害者的网络管道（如反射放大攻击）
```

理解 DoS 的关键是"**不对称**"——攻击者花的代价远小于受害者被迫承担的代价，这个放大比越大，攻击越划算。防御的通用思路则是反过来消除不对称：要么让服务端处理单个恶意请求几乎不耗资源（SYN cookies），要么在攻击流量到达受害者之前把它挡在上游（清洗、限速、过滤）。SYN flood 与放大攻击分别是这两类的教科书代表，下面分别看。

### 17.4.2 SYN flood 与 SYN cookies

SYN flood 是协议型 DoS 的典型。TCP 三次握手中，服务器收到 SYN 后要分配一个"半开连接"控制块（记住序列号等状态）并回 SYN-ACK，等客户端的最终 ACK。攻击者只发大量 SYN（常配伪造源 IP）、**从不回最终 ACK**，服务器的半开连接表被迅速填满，无法再接受正常连接。它耗的不是带宽，而是服务器的连接状态内存。

防御的巧解是 **SYN cookies**：服务器收到 SYN 时**不分配任何状态**，而是把连接信息（时间戳、MSS、四元组的哈希）编码进它回给客户端的初始序列号 `y` 里；只有当客户端回来的 ACK 携带 `y+1`、服务器能校验出这个 cookie 合法时，才真正建立连接并分配状态。这样"半开连接"不再占内存，攻击者不完成握手就什么也占不到。写成一句话：

```
y = SYN cookie = 密钥化哈希(源IP, 源端口, 目的IP, 目的端口, 粗粒度时间戳) 编码进 32 位 ISN
```

初学者要抓住这里的精妙之处：SYN cookies 把"记住状态的责任"从服务器**转嫁回客户端**（状态编码在客户端必须原样回带的 ack 里），用一点点计算换掉了整张半开连接表——正是"消除不对称"思想的漂亮实例。代价是丢失了一些 TCP 选项信息，通常只在检测到 SYN flood 时才启用。

### 17.4.3 反射与放大攻击（reflection & amplification）

带宽型 DDoS 最狠的一招是**反射放大**。攻击者向大量开放的 UDP 服务（DNS、NTP、memcached 等）发请求，但把源 IP **伪造成受害者**；这些服务器把（远大于请求的）应答统统发给受害者。它同时利用了两点：IP 欺骗（17.1.4，让回包发去受害者、隐藏攻击者）和**放大**（一个小请求换一个大应答）。放大能力用**带宽放大因子（BAF）**衡量：

```
BAF = 应答 UDP 载荷字节数 / 请求 UDP 载荷字节数
DNS（含 EDNS/DNSSEC 大应答）：约 28 – 54 倍
NTP（monlist 命令）：约 556 倍
memcached（UDP 11211）：约 10,000 – 51,000 倍
```

memcached 的惊人放大造就了 2018 年针对 GitHub 的 **1.3 Tbps** 攻击（当时的纪录级容量型攻击）。反射攻击对攻击者的两大好处：隐藏真实来源（受害者只看到反射服务器的 IP），以及以小博大（几十兆上行换来几百 G 下行砸向受害者）。

根治反射攻击最有效的是网络层的**入口过滤（BCP 38 / RFC 2827）**——ISP 丢弃源地址伪造的出站包，让"冒充受害者去请求"这一步根本发不出去；可惜全网部署不全，所以放大攻击至今未绝。次一级的缓解是关闭/限制这些 UDP 服务的开放递归与危险命令（如禁用 NTP monlist、DNS 关开放递归）。初学者记住：放大攻击的三要素是"UDP 无握手 + 可伪造源 IP + 应答远大于请求"，缺一不可——这也解释了为什么 TCP 服务难被反射放大（三次握手挡住了伪造源 IP）。

### 17.4.4 防御手段：防火墙、限速、清洗与过滤

DoS 没有单一银弹，实战靠一套纵深防御叠加。

**防火墙（firewall）**在网络边界按规则放行/丢弃流量。无状态包过滤（stateless）只看单包的五元组（源/目的 IP、端口、协议）；有状态防火墙（stateful）跟踪连接状态（如只放行属于已建立连接的包），能挡掉大量不合法握手。防火墙是"设定允许的最小面"，把攻击面收窄。

**限速（rate limiting）**对单来源/单类请求设速率上限，超额丢弃或排队，防止任一来源打爆资源——但对**分布式**攻击效果打折（每个僵尸机各自都在限额内）。

**流量清洗（scrubbing）与 Anycast 稀释**是大规模 DDoS 的主力：把流量引到有巨大冗余带宽的清洗中心（如 CDN/抗 D 服务），在那里滤掉攻击流量、只把干净流量回源；Anycast 用同一 IP 在全球多节点宣告，把攻击流量**地理上分摊**到各节点分而治之。

**入口过滤（BCP 38）**如前所述从源头掐断源 IP 伪造，是治本但需全网协作的一环。

协议型攻击靠"让单请求不耗资源"（SYN cookies、有状态过滤）来防；容量型攻击靠"比攻击者有更多带宽 + 提前清洗"（CDN/scrubbing/Anycast）来防；而伪造源 IP 这个共性弱点靠入口过滤来治本。没有哪一层能独当一面，可用性防御本质是"用冗余和过滤对冲不对称"。

## 17.5 IDS/IPS：入侵检测与防御

### 17.5.1 IDS vs IPS、NIDS vs HIDS

入侵检测系统（IDS，Intrusion Detection System）监控流量或主机活动、发现可疑行为并**告警**；入侵防御系统（IPS，Intrusion Prevention System）在此之上还能**主动阻断**（丢包、断连、封 IP）。二者的核心区别是部署位置与权限：

```
IDS：多为旁路（out-of-band），镜像/抓取流量做分析，只观察与告警，不影响转发
IPS：多为串接（in-line），流量必须穿过它，可实时拦截；但它本身成了单点/时延来源
```

按监控对象又分**网络型（NIDS）**（在网络节点看流量，如 Snort/Suricata/Zeek）与**主机型（HIDS）**（在单机看系统调用、日志、文件完整性，如 OSSEC）。初学者的定位：IDS 是"监控摄像头 + 报警器"，IPS 是"摄像头 + 自动上锁的门"。IPS 阻断能力强但代价也大——一次误判（false positive）就可能把正常业务掐断，所以很多组织宁可用 IDS 告警 + 人工研判，或让 IPS 只对高置信度规则做阻断。

### 17.5.2 签名检测 vs 异常检测

IDS/IPS 有两条根本不同的检测路线。

**签名检测（signature-based / misuse detection）**把流量与一个**已知攻击特征库**逐条比对，命中就告警。Snort、Suricata 就是签名引擎的代表，规则形如"匹配某端口 + 某载荷字节模式 + 某协议状态"。优点是对已知攻击又快又准、误报可控、可解释；致命短板是**对没进库的新攻击/变种结构性失明**（零日、多态变形都能绕过），且规则库要不断更新。

**异常检测（anomaly-based）**先在训练期学出一套"正常行为"的基线模型，运行时把偏离基线的行为标为可疑。优点是**有望发现从未见过的新攻击**；短板是"什么算正常"极难界定，**误报率天然偏高**，且模型本身可能被"投毒"或被精心构造成"看起来正常"的攻击绕过（呼应 17.6）。

```
签名检测：低误报、高漏报（挡不住新攻击）    ——"认识的坏人才拦"
异常检测：低漏报（潜力）、高误报           ——"不像好人的都疑"
```

现实系统（如 Snort/Suricata）往往**两者混用**，再叠加协议解析。初学者要抓住这条主线：这是"精确 vs 泛化"的经典张力——签名精确但不泛化，异常泛化但不精确，没有免费午餐。

### 17.5.3 误报/漏报与基率谬误（base-rate fallacy）

评价 IDS 绕不开两类错误：**误报（false positive，把正常当攻击）**与**漏报（false negative，把攻击当正常）**。二者此消彼长——把阈值调敏感会少漏报但多误报，调迟钝则反之。

一个初学者极易忽视、却决定 IDS 实用性的现象是**基率谬误**：真实网络里绝大多数流量是良性的（攻击事件是极小概率），此时即便检测器的准确率看起来很高，**告警里仍可能绝大多数是误报**。直觉例子：若一百万条流量里只有 100 条是攻击，检测器漏报率极低但误报率哪怕只有 1%，也会产生约 1 万条误报——真攻击被淹没在误报海里，运维根本看不过来。这正是 Axelsson 在 1999 年对 IDS 的经典批评：限制 IDS 实际效果的不是检测率，而是**在极低攻击基率下把误报率压到足够低有多难**。

IDS 的价值不在"能不能发现攻击"，而在"告警能不能被人消化"——一个天天喊狼来了的系统会被运维直接忽略。这也解释了为什么实战里签名检测（误报低）仍是主力，异常检测更多作为补充，以及为什么"告警降噪 / 关联分析"是 SOC 的核心工作。

## 17.6 AI/ML 安全 ⚙演进快·锚 2026-07-30

> 本小主题为前沿领域，攻防与标准仍快速演进；以下概念与分类以 **NIST AI 100-2e2025**（2025-03 发布的最终版对抗性机器学习分类）为主锚，具体攻击效果/防御强度数值多为研究结论、随时变，均硬标演进快、不作定论。

### 17.6.1 为什么 ML 模型是新的攻击面

传统安全护的是代码与协议；当系统里嵌入了机器学习模型（图像识别、垃圾邮件过滤、风控、乃至大语言模型），**模型本身**成了新攻击面。原因是 ML 模型的行为由训练数据与学习到的统计规律决定，而非人写死的规则——攻击者可以操纵输入、操纵训练数据、或反复查询来偷取/破坏模型，这些是传统防火墙/IDS 看不见的攻击。

NIST AI 100-2e2025 把对抗性机器学习按**攻击者目标**分为三大类（作用于三种安全属性），并区分**预测型 AI（PredAI）**与**生成式 AI（GenAI）**：

```
完整性（integrity）攻击：让模型输出错误 —— 逃逸/对抗样本、投毒后门
可用性（availability）攻击：让模型对正常输入也失效 —— 可用性投毒
隐私（privacy/confidentiality）攻击：窃取模型或训练数据 —— 模型窃取、成员推断、数据提取
```

这仍是那套 CIA 三性（完整性/可用性/机密性）框架，只不过对象从"代码和数据"换成了"模型和训练集"。下面按攻击发生的阶段（推理时 vs 训练时 vs 查询时）看具体几类。

### 17.6.2 对抗样本（adversarial examples / evasion）

对抗样本是**推理阶段**的完整性攻击：给一个正常输入加上人眼几乎察觉不到的微小扰动，就能让模型给出完全错误的判断（经典例子：一张熊猫图加上精心计算的噪声，模型以高置信度识别成长臂猿；给停车标贴几张小贴纸，自动驾驶识别成限速牌）。它利用的是高维模型决策边界的脆弱性——在人看来"没变"的输入，在模型的特征空间里已越过了边界。

生成对抗扰动的思路是沿"让损失变大"的方向对输入求梯度并微调，最简形式是 FGSM（快速梯度符号法）：

```
x_adv = x + ε · sign(∇_x L(θ, x, y))
```

其中 `x` 是原输入、`L` 是模型损失、`ε` 控制扰动幅度（越小越隐蔽）。攻击按攻击者知识分**白盒**（知道模型参数、可直接算梯度）与**黑盒**（只能查询输出，靠迁移性或估计梯度）。防御研究里**对抗训练**（把对抗样本加进训练集一起训）是当前最主流也相对有效的加固，但没有已知的完美防御，攻防持续拉锯（⚙演进快）。初学者记住定位：对抗样本不改模型、不改训练数据，只在**输入端**做手脚，却能系统性地骗过模型——这暴露了"高准确率"与"鲁棒性"是两回事。

### 17.6.3 数据投毒与后门（poisoning & backdoor）

投毒是**训练阶段**的攻击：攻击者往训练数据里掺入恶意样本，从而破坏训练出来的模型。它分两种意图——**可用性投毒**让模型整体性能下降（把它训坏）；**后门/木马投毒（backdoor）**更隐蔽：模型在正常输入上表现完全正常，但一旦输入里出现攻击者预设的**触发器（trigger，如某个特定像素块或词语）**就会输出攻击者指定的错误结果，相当于给模型埋了一个"暗号后门"。

投毒的现实入口是训练数据的来源不可控——很多模型用网络爬取的公开数据、第三方标注、或用户上传内容训练，攻击者只要污染其中一小部分就可能生效。对 GenAI/LLM，NIST 2025 版特别列出了**RAG 知识库投毒**（污染被检索增强的外部知识源）和**供应链攻击**（污染预训练模型/数据集/依赖）。防御方向包括训练数据来源审计与清洗、异常样本检测、鲁棒训练等，但同样无完美解（⚙演进快）。初学者对照记忆：对抗样本是"考试时作弊"（推理期改输入），投毒是"篡改教材"（训练期改数据），后门是"教材里埋了只有暗号才触发的错误答案"。

### 17.6.4 模型窃取与隐私攻击（extraction / privacy）

这一类是**查询阶段**的机密性攻击，把矛头对准模型和它的训练数据本身，主要有三种。模型窃取/提取（model extraction/stealing）指攻击者仅通过大量查询目标模型的 API、拿输入-输出对去训练一个"仿制模型"，从而复制其功能——绕过高昂的训练成本，也可能进一步窃取知识产权或为后续白盒攻击做准备。成员推断（membership inference）是判断"某条特定数据是否在训练集里"，可能泄露隐私（如某人是否在某疾病数据集里）。训练数据提取/记忆（data extraction）则诱导模型（尤其大语言模型）吐出它记住的训练数据原文，可能包含个人信息、密钥等敏感内容。

对 GenAI 还有一类突出的新型攻击——**提示注入（prompt injection）**，尤其是**间接提示注入**：把恶意指令藏在模型会读到的外部内容（网页、文档、邮件）里，劫持模型去执行攻击者的意图；NIST 2025 版把直接/间接提示注入、以及多智能体系统里的"提示蠕虫"传播都纳入了 GenAI 攻击分类。防御含查询限速与异常检测（抗窃取）、差分隐私训练（抗成员推断，见大主题18）、输入输出过滤与权限隔离（抗提示注入）等，均在快速演进（⚙演进快）。

AI/ML 安全把攻击面从"程序"扩展到了"数据与模型"，但用的仍是老框架（CIA 三性 + 攻击者能力分级）；它之所以硬标演进快，是因为标准（NIST AI 100-2 才在 2025-03 出最终版）、攻击手法（尤其 GenAI/LLM 方向）和防御都远未定型，任何具体的"最优防御 / 攻击成功率"结论都应视为随时会变，不作定论。

#### 来源与时效（本小主题末集中列，不逐项脚注）
