## 7.1 Diffie–Hellman 密钥交换

### 7.1.1 协议动机：不传密钥而"约定"出密钥

Diffie–Hellman（DH，1976）解决的是对称加密时代最尖锐的难题——通信双方要用同一把对称密钥，可这把密钥怎么在一条被窃听的信道上先商定出来。DH 的答案是：双方各自保留一个私密数，只在公开信道上交换由私密数算出的"公开值"，再各自把对方的公开值和自己的私密数一混合，双方就得到同一个只有他们才算得出的共享秘密，而全程窃听者也拼不出它。

这就是"公钥革命"的起点：在 DH 之前，密钥必须靠可信信使或事先见面来分发；DH 第一次让两个素未谋面的人在完全公开的对话中"凭空"约定出一把共享密钥。它交换出来的是一个**共享秘密**，不是直接加密消息——它是密钥协商（key agreement），不是加密方案。初学者要区分：DH 本身只产密钥，真正加密还要把这把密钥喂给对称加密（如 AES-GCM）。

### 7.1.2 协议流程（有限域乘法群版）

设有一个公开的循环群参数：大素数 p、以及 Z_p* 中一个生成元 g（阶为大素数 q）。这些参数公开、可被所有人（含攻击者）看到。

Alice 选私钥 x（1 ≤ x ≤ q−1），计算并发送

A = g^x mod p

Bob 选私钥 y（1 ≤ y ≤ q−1），计算并发送

B = g^y mod p

Alice 收到 B 后计算

B^x mod p = (g^y)^x mod p = g^(xy) mod p

Bob 收到 A 后计算

A^y mod p = (g^x)^y mod p = g^(xy) mod p

两人得到同一个共享秘密

K = g^(xy) mod p

窃听者看得到 p、g、A = g^x、B = g^y，却要从中算出 g^(xy)——这正是下一节的计算性 DH 问题，被认为极难。

关键直觉是"指数在混合时可交换"：(g^x)^y 和 (g^y)^x 都等于 g^(xy)，所以双方从不同方向出发却落到同一点。攻击者手里只有 g^x 和 g^y，而 g^x · g^y = g^(x+y) 给出的是"和"不是"积"的指数——他没有任何公开的、能把两个指数相乘的运算，除非先把 x 或 y 从指数上"取下来"（即解离散对数），而这被假设做不到。一个常见误解是以为攻击者能"相乘 A·B 得到答案"，其实那只给 g^(x+y)，与 g^(xy) 毫无关系。

### 7.1.3 共享密钥的后处理：KDF 而非直接当密钥

DH 算出的原始共享秘密 K = g^(xy) mod p 是群里的一个元素（几百比特的大整数），它**不能直接当对称密钥用**。原因有二：一是它的比特分布并不均匀（是群元素而非均匀随机串），二是实际协议往往还要从一次交换派生多把密钥。标准做法是把 K 送进一个密钥派生函数（KDF，如 HKDF）：

k_sym = KDF(K, 上下文信息)

得到定长、看起来均匀随机的对称密钥。

初学者容易直接把那个大整数截断当 AES 密钥，这是典型错误。DDH 假设（见 7.2）保证的是"K 与随机群元素不可区分"，而对称密钥需要的是"均匀比特串"，中间必须由 KDF 桥接。实际协议（TLS 1.3 等）都在 DH/ECDH 之后紧跟一个 HKDF 步骤，本知识库的 TLS 大主题会展开。

### 7.1.4 本机实证：小素数群跑通 DH

用一个玩具群 p = 23、g = 5 演示流程可复现（仅教学，真实参数需数千比特）。Alice 私钥 x = 6，Bob 私钥 y = 15：

A = 5^6 mod 23 = 8

B = 5^15 mod 23 = 19

Alice 算 B^x = 19^6 mod 23 = 2；Bob 算 A^y = 8^15 mod 23 = 2

本机真实输出（纯 Python `pow(g,x,p)`）：`toy DH: A=8 B=19  sA=2 sB=2`，双方共享秘密均为 2，吻合。这条最小例子把"双方从不同公开值出发得到同一秘密"坐实了；把 23 换成 RFC 3526 的 2048 位素数、把私钥换成随机大数，就是生产用的有限域 DH。

## 7.2 DL / CDH / DDH 困难假设

### 7.2.1 离散对数问题（DL）

在循环群 G = ⟨g⟩（阶为 q）中，给定 g 和一个元素 h = g^x，求出指数 x 的问题，就是**离散对数问题**（Discrete Logarithm, DL）：

已知 g、h = g^x，求 x

离散对数假设是说：当群选得好、q 足够大时，不存在概率多项式时间算法能以不可忽略的概率解出 x。

"离散"是相对于实数对数而言的：在实数里由 h 求 x = log_g h 用连续函数很容易；但在有限循环群里，指数一大 g^x 就"绕圈"（模 p 回卷），没有连续性可利用，只能像大海捞针一样搜。要注意 DL 难不难**取决于群**：在 (Z_n, +) 这种加法群里"离散对数"其实就是模逆除法，很容易；密码学专挑那些 DL 确实难的群（Z_p* 的大素数阶子群、椭圆曲线群）。

### 7.2.2 计算性 DH 假设（CDH）

计算性 Diffie–Hellman 问题（Computational DH, CDH）：给定 g、g^x、g^y（但不给 x、y），求 g^(xy)。

已知 g、g^x、g^y，求 g^(xy)

CDH 假设是说该问题对多项式时间攻击者不可解。这正是 7.1 里窃听者面对的问题——他有全部公开值，要的就是共享秘密 g^(xy)。

CDH 与 DL 的关系：能解 DL 就一定能解 CDH（先由 g^x 解出 x，再算 (g^y)^x = g^(xy)），所以 **CDH 不比 DL 难**，DL 难是 CDH 难的前提。反方向（能解 CDH 是否就能解 DL）在一般群里未知、被认为大体等价但无普遍证明。初学者记一句话即可：DH 密钥交换的"能不能被算出来"押在 CDH 上，而 CDH 站在 DL 的肩膀上。

### 7.2.3 判定性 DH 假设（DDH）

判定性 Diffie–Hellman 问题（Decisional DH, DDH）：给定 g、g^x、g^y 和第四个元素 Z，判断 Z 是真正的 g^(xy) 还是一个随机群元素。DDH 假设是说这两种情形对攻击者**不可区分**：

(g, g^x, g^y, g^(xy)) 与 (g, g^x, g^y, g^r) 计算不可区分（r 随机）

DDH 比 CDH 更强的要求：不仅算不出 g^(xy)，连"这个东西是不是 g^(xy)"都看不出来。它是很多方案（ElGamal 加密的语义安全、DH 派生密钥可当随机串用）能证明安全的基础。

三者难度关系是一条链：

解 DDH ≤ 解 CDH ≤ 解 DL

即 DDH 最"容易"被攻破（假设最强/最容易不成立），DL 最难被攻破（假设最弱/最保险）。关键陷阱：**DDH 在某些群里是假的**——在整个 Z_p* 上，用勒让德符号（判断是否二次剩余）就能区分，所以 DDH 会失败；必须把群限制到 Z_p* 的大素数阶子群（q | p−1，且用阶为 q 的生成元），或用素数阶椭圆曲线群，DDH 才成立。这解释了 7.3 为什么强调"安全素数/素数阶子群"，而不是随便一个 Z_p*。

## 7.3 DH 群参数与中间人风险

### 7.3.1 安全素数与素数阶子群

DH 的安全强烈依赖群参数选得对。工程上常用**安全素数**（safe prime）：形如

p = 2q + 1，其中 q 也是素数

此时 Z_p* 的阶为 p−1 = 2q，存在一个阶为 q 的大素数阶子群，在这个子群里工作能保证 DDH 成立、且没有"小子群"可供攻击者把秘密困在里面。

为什么不能随便挑 p？若 p−1 含很多小素因子，Pohlig–Hellman 算法能把离散对数拆到各小素数阶子群上分别求解，再用 CRT 拼起来，整体难度骤降到"最大素因子那一档"。安全素数让 p−1 = 2q 只有因子 2 和大素数 q，堵死了这条路。初学者只需记住：DH 的群不是"任意大素数就行"，还要求 p−1 有大素因子（最好就是安全素数），并把运算限制在阶为 q 的子群、用小余因子做剔除。

### 7.3.2 RFC 3526 MODP 群

为免每个人自造参数出错，IETF 把一批经过审查的固定 DH 群写进标准。RFC 3526（2003）定义了一组 **MODP 群**，其素数与生成元如下要点（本机核对 RFC 原文）：

它定义的群及比特长度：Group 5 = 1536 位、Group 14 = 2048 位、Group 15 = 3072 位、Group 16 = 4096 位、Group 17 = 6144 位、Group 18 = 8192 位。

所有群的生成元都是

g = 2

每个素数都是安全素数（p = 2q + 1，q 也素），由 π 的高精度值构造，形如

p = 2^b − 2^(b−64) − 1 + 2^64 · { ⌊2^(b−130) · π⌋ + offset }

其中 b 是比特长度、offset 是使 p 成为安全素数的一个小整数（各群不同，如 2048 位群 offset = 124476、8192 位群 offset = 4743158）。

用 π 的位来"造"常数是一种**nothing-up-my-sleeve**（袖里无物）设计：π 是公认的自然常数，用它的数位当参数能向所有人证明"作者没有偷偷埋后门"，因为参数不是随手挑的可疑数。这些群里 2048 位（Group 14）是长期主力。注意时效：这些是有限域 DH 群；现代协议（TLS 1.3）已基本弃用有限域 DH、改用椭圆曲线 ECDHE（见 7.5），MODP 群更多见于 IKE/IPsec 与遗留系统。1536 位（Group 5）按今天标准偏弱、不建议新用。

### 7.3.3 无认证 DH 的中间人攻击

裸 DH 有一个致命短板：它不认证对方身份。攻击者 Mallory 站在 Alice 与 Bob 中间，可以分别与两人各做一次 DH：

Alice ↔ Mallory 得共享密钥 K1；Mallory ↔ Bob 得共享密钥 K2

Alice 以为在跟 Bob 说话（实际用 K1 与 Mallory 加密），Bob 以为在跟 Alice 说话（实际用 K2 与 Mallory 加密），Mallory 居中解密、看完、再重新加密转发，双方毫无察觉。这就是**中间人攻击**（Man-in-the-Middle, MITM）。

根因在于 DH 只保证"我和某人共享了密钥"，不保证"那个某人就是 Bob"。修复办法是给 DH 加认证：用数字签名签自己的 DH 公开值（TLS 用证书+签名认证服务器）、或用双方预共享的口令/密钥做认证（PAKE），把公开值和身份绑定。初学者要牢记一句话：**DH 抵御被动窃听（CDH 保证），但对主动的中间人无能为力，必须靠认证补上**。这也是 PKI/证书与签名在后续大主题里存在的核心动机。

## 7.4 椭圆曲线直觉

### 7.4.1 从"数的群"到"点的群"

椭圆曲线密码（ECC）的核心一步，是把 DH 舞台上的群从 Z_p* 换成**椭圆曲线上的点集**。定义在有限域 F_p（p 为大素数）上的短 Weierstrass 形式椭圆曲线是满足下式的点 (x, y) 的集合，再加一个特殊的"无穷远点" O：

y^2 = x^3 + a·x + b （mod p）

其中系数满足非奇异条件 4a^3 + 27b^2 ≠ 0（保证曲线无尖点/自交）。这些点配上一种叫"点加法"的运算，构成一个**可交换群**，O 充当群的单位元（零元）。

初学者要跨过的第一个坎是"点怎么能相加"。这里的"加"不是坐标各自相加，而是一条几何规则（下节）；一旦定义好，它就满足群公理（有单位元 O、有逆元、可结合、可交换），于是 7.1–7.2 关于"群上离散对数难"的整套故事可以原样搬过来，只是把"乘法群里求指数"换成"点群里求标量"。为什么用椭圆曲线？因为在这个群上，最好的离散对数攻击（ECDLP）只有**指数级**算法，而 Z_p* 上有更快的**亚指数**算法（指数演算），所以同等安全下椭圆曲线的参数短得多（7.6 量化）。

### 7.4.2 点加法的群律（几何直觉）

两个不同点 P、Q 相加的几何规则是：过 P、Q 作一条直线，它必与曲线再交于第三个点 R'，把 R' 关于 x 轴对称（y 取负）得到的点就是 P + Q。

P + Q = −R'（R' 为直线 PQ 与曲线的第三个交点）

若一条竖直线只交曲线于两点（P 和 −P），则规定它们的和是无穷远点：

P + (−P) = O

这套"弦与切线"规则正是群运算，O 是把所有竖直线交汇的"天上一点"。

直觉上把 O 想成"竖直方向的无穷远处"：任何竖直线都过它，所以互为镜像的 P 和 −P 相加落到 O（即加了个零）。这解释了为什么单位元是那个看不见的无穷远点，而不是原点 (0,0)。可交换是显然的（直线 PQ 与直线 QP 是同一条），结合律 (P+Q)+S = P+(Q+S) 几何上不显然但可代数验证——初学者接受结论即可，不必自证。

### 7.4.3 点加与倍点的代数公式

把几何规则翻译成 F_p 上的坐标公式。对 P = (x1, y1)、Q = (x2, y2) 且 P ≠ ±Q，令斜率

λ = (y2 − y1) · (x2 − x1)^(−1) mod p

则 P + Q = (x3, y3)：

x3 = λ^2 − x1 − x2 mod p

y3 = λ·(x1 − x3) − y1 mod p

当 P = Q（**倍点**，doubling，即 P + P = 2P），切线斜率改用微分给出：

λ = (3·x1^2 + a) · (2·y1)^(−1) mod p

x3、y3 公式同上（代入 x2 = x1）。

这里的"除法"都是模逆（乘以模 p 的逆元，见 G11-02），所以要求被除量与 p 互素——在素数域上除 0 外都可逆。初学者最容易忽略的是"点加"和"倍点"是两条不同公式（分母一个是 x2−x1、一个是 2y1），实现时必须分情况；把它们混用是常见 bug。真正加密里不会手算这些，而是靠下面的标量乘一层层调用点加/倍点。

### 7.4.4 标量乘与 ECDLP

椭圆曲线上对应"乘法群求幂 g^x"的运算是**标量乘**：把点 P 自加 k 次，记作

[k]P = P + P + … + P（k 个 P 相加）

用"倍加法"（double-and-add，与快速幂同构）可在 O(log k) 次点运算内算完。椭圆曲线离散对数问题（ECDLP）就是它的逆：

已知 P 和 Q = [k]P，求标量 k

ECDLP 假设是说：在选得好的曲线上，这个问题没有多项式（甚至亚指数）时间算法。

ECC 的全部安全都押在 ECDLP 上，正如经典 DH 押在 Z_p* 的 DL 上。关键区别再强调一次：Z_p* 上有指数演算（index calculus）这类亚指数算法，而一般椭圆曲线上最好的通用攻击是 Pollard's rho，复杂度约 √n（n 为群阶），是**纯指数级**——这就是"256 位椭圆曲线 ≈ 3072 位 RSA/DH"的根源（7.6）。标量乘的 double-and-add 与 7.1 里模幂的 square-and-multiply 是同一个算法骨架，只是"平方/乘"换成了"倍点/点加"，初学者可对照记忆。

#### 来源与时效（本小主题末集中列）
- 一手锚点：Katz-Lindell 3rd ed. §9.3.4 及椭圆曲线群小节（曲线群、点加群律、ECDLP 与相较 Z_p* 无亚指数攻击）。核实 2026-07-30。
- 交叉源：HAC 1996 §6.2 与 Ch3（椭圆曲线点加/倍点代数公式、ECDLP、Pollard rho √n）；RFC 7748 §4-5（曲线定义与群运算，蒙哥马利形式对照）。核实 2026-07-30。
- 冲突项：无。曲线写法有短 Weierstrass（本节）与蒙哥马利形式（7.5 X25519 用）之分，两者等价、按用途分账，非分歧。

## 7.5 ECDH 与 X25519

### 7.5.1 ECDH：把 DH 搬到曲线上

椭圆曲线 Diffie–Hellman（ECDH）就是 7.1 的 DH 换成椭圆曲线点群：公开参数是曲线、素数 p 和一个基点 G（阶为大素数 n）。Alice 选私钥 a，公钥为 [a]G；Bob 选私钥 b，公钥为 [b]G。双方交换公钥后各自算标量乘：

Alice 算 [a]([b]G) = [ab]G

Bob 算 [b]([a]G) = [ab]G

共享秘密

K = [ab]G

通常取 K 的 x 坐标再经 KDF 得对称密钥。

和经典 DH 一一对应："g^x" 变 "[a]G"，"g^(xy)" 变 "[ab]G"，安全从 CDH 变 ECDH 版 CDH（押 ECDLP）。用临时（每次会话新生成）私钥的 ECDH 记作 **ECDHE**，提供前向保密——即使长期密钥日后泄露，也解不开过去会话，这是 TLS 1.3 的默认密钥协商，后续 TLS 大主题展开。

### 7.5.2 Curve25519 参数

X25519 是在 Bernstein 设计的 **Curve25519** 上做 ECDH 的具体函数，写进 RFC 7748。它用**蒙哥马利形式**曲线而非短 Weierstrass，定义在素数域

p = 2^255 − 19

曲线方程（u、v 为蒙哥马利坐标）

v^2 = u^3 + 486662·u^2 + u

基点的 u 坐标为

u = 9

余因子 cofactor = 8，基点阶为素数

n = 2^252 + 0x14def9dea2f79cd65812631a5cf5d3ed

选 2^255−19 这个素数是为了让模约减极快（接近 2 的幂），486662 是精心挑的系数让曲线既安全又高效。X25519 的一大工程优点是**只用 u 坐标**（x 坐标）运算、不碰 y，公钥就是 32 字节的 u 坐标，实现更简单也更省。"25519" 就来自素数 2^255−19。

### 7.5.3 标量钳制（clamping）

X25519 在使用私钥前先对 32 字节标量做固定的位操作，称为 clamping（decodeScalar25519）：把最低字节的最低 3 比特清零、把最高字节的最高位清零、把最高字节的次高位置 1。等价地按小端整数看，钳制后的标量形如

2^254 + 8·{0 … 2^251−1}

也就是说，低 3 位清零使标量成为 8 的倍数（乘掉余因子 8，避免小子群攻击），最高位固定为 2^254 使标量落在固定高位区间（抵抗某些侧信道/时序、保证阶梯步数固定）。

初学者不必背这些位，但要理解动机："清低 3 位"是把私钥变成余因子 8 的倍数，使得任何小阶点被乘成无穷远点、堵死小子群攻击；"定最高位"让所有私钥的比特长度一致，配合下面的蒙哥马利阶梯做到运算步数与私钥无关（常数时间）。这是 Curve25519 "误用友好"设计哲学的典型：把安全隐患在算法内部消化掉，不指望调用者做对。

### 7.5.4 蒙哥马利阶梯（Montgomery ladder）

X25519 的标量乘用**蒙哥马利阶梯**实现——一种每处理标量一个比特就做固定一次"倍点+差分加"、且两个分支工作量相同的算法，天然常数时间、抗时序侧信道。其骨架（RFC 7748 伪码，k 为钳制后标量，共 255 比特）：

x1 = u；x2 = 1, z2 = 0；x3 = u, z3 = 1；swap = 0

for t 从 254 downto 0：

　k_t = (k >> t) & 1

　swap ^= k_t

　(x2, x3) = cswap(swap, x2, x3)；(z2, z3) = cswap(swap, z2, z3)

　swap = k_t

　（一组固定的域加减乘：由 (x2,z2) 与 (x3,z3) 算出新的倍点与差分加）

结束后 (x2, x3) = cswap(swap, x2, x3)；返回

x2 · z2^(p−2) mod p

其中 z2^(p−2) 由费马小定理给出 z2 的模逆（把投影坐标 X/Z 还原成仿射 u）。cswap 是常数时间条件交换：

cswap(swap, a, b)：dummy = mask(swap) & (a ^ b)；a ^= dummy；b ^= dummy

一是每个比特都执行**完全相同**的运算序列，不因比特是 0 还是 1 而走不同分支，所以运行时间不泄露私钥；二是用 cswap（掩码异或）而非 `if` 来做条件交换，避免分支预测泄露。这就是"常数时间实现"的样板。初学者只需抓住"阶梯 = 每比特固定步、无数据依赖分支"这一点，逐行域运算不必手推。

## 7.6 ECC vs RSA 密钥长度对标

### 7.6.1 为什么 ECC 密钥能短得多

ECC 与 RSA/有限域 DH 提供同等"安全强度"时，ECC 需要的密钥长度显著更短。根源在最优攻击算法的复杂度不同：攻破 RSA 靠整数分解、攻破有限域 DH 靠指数演算，两者都有**亚指数**算法，随模数增大安全增长较慢；而攻破一般椭圆曲线的 ECDLP 只有 Pollard rho 这类**纯指数级**（约 √n）通用算法，安全随比特数增长快得多。

安全强度（security strength）以"比特"计，指攻破需约 2^s 次操作。一句话直觉：因为椭圆曲线没有亚指数捷径，256 位的椭圆曲线群就能顶得上 3072 位的 RSA 模数——所以 ECC 密钥更短、运算更快、带宽更省，这是它在 TLS、移动端、区块链里全面取代 RSA 的直接原因。

### 7.6.2 NIST SP 800-57 可比强度表（Table 2）

NIST SP 800-57 Part 1 Rev. 5（2020）Table 2 给出各安全强度下的对应参数（本机核对 NIST PDF 原文，逐行摘录）：

| 安全强度(bit) | 对称(Symmetric) | FFC 有限域 DH/DSA (L, N) | IFC RSA 模数 k | ECC 密钥 f 范围 |
|---|---|---|---|---|
| ≤ 80 | 2TDEA | L=1024, N=160 | k=1024 | f = 160–223 |
| 112 | 3TDEA | L=2048, N=224 | k=2048 | f = 224–255 |
| 128 | AES-128 | L=3072, N=256 | k=3072 | f = 256–383 |
| 192 | AES-192 | L=7680, N=384 | k=7680 | f = 384–511 |
| 256 | AES-256 | L=15360, N=512 | k=15360 | f = 512+ |

表中 L 是有限域 DH 公钥（素数 p）比特数、N 是私钥/子群阶比特数；k 是 RSA 模数 n 的比特数；f 是椭圆曲线群阶 n 的比特数（≈ 私钥/坐标比特数）。

读表时务必只看**同一行**才是"等价安全"。128 位安全这一行——最常见的现代目标——对应 AES-128、RSA-3072、ECC 256–383 位；也就是 P-256（256 位椭圆曲线，f=256）或 Curve25519（≈252 位阶）大致落在 128 位安全档。对比最刺眼的是 256 位安全：RSA 要 15360 位模数（几乎没人用，慢到不切实际），而 ECC 只要 512+ 位——ECC 的长度优势随安全等级拉高而急剧放大。初学者别把不同行的数字混比（如拿 RSA-2048 对 ECC-256），要对齐"安全强度"列看。

### 7.6.3 时效与边界

这张对标表是**基于当前已知经典攻击**的估计，NIST 在文中明确声明：分解算法、离散对数算法的进步，以及量子计算成为现实时，这些强度估计会显著改变（表中 IFC/ECC 行带星号注明"量子计算实用化时将严重受影响"）。

这里要硬标两点。其一，Rev. 5 发布于 2020 年，表值稳定但"某长度还能安全用多少年"要参照 SP 800-57 的时限指引与 SP 800-131A 的过渡规定（80 位已不再批准用于保护、112 位 3TDEA 亦已弃用），具体年限随修订更新，本报告不外推、以 Table 2 结构值为准。其二，量子计算下 Shor 算法会同时击垮 RSA 与 ECC（对 ECDLP 亦有效），届时"ECC 比 RSA 短"这条经典对标整体失效，需转向后量子密码——这是本课后量子大主题（G11-11）的内容，此表仅刻画**经典**攻击下的对标。任何具体"哪年必须弃用某长度"的结论若无 SP 800-131A 对应条目支撑，标「待核」，不凭记忆填。
