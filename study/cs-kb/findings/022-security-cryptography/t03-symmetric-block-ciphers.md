## 3.1 伪随机性原语

### 3.1.1 伪随机生成器（PRG）

伪随机生成器（Pseudorandom Generator, PRG）是一个确定性、可高效计算的函数 G，它把一段短的随机种子拉伸成一段更长的输出，且这段输出对任何高效算法而言都"看起来像"真正的随机比特串。形式化地，G 把 n 比特种子映射到 ℓ(n) 比特（ℓ(n) > n 为拉伸量），安全性要求任何概率多项式时间（PPT）区分器 D 分辨"G(种子) 的输出"与"等长的真随机串"的能力可忽略：

|Pr[D(G(s)) = 1] − Pr[D(r) = 1]| ≤ negl(n)

其中 s 均匀取自 {0,1}^n，r 均匀取自 {0,1}^{ℓ(n)}，negl(n) 是可忽略函数（比任何 1/多项式 都小）。

真正的随机需要"每一比特都花一比特真随机来买"，代价高昂；PRG 的意义是"用少量真随机（种子）撬动大量以假乱真的随机"。关键词是"以假乱真"——G 的输出当然不是真随机（它完全由种子决定，只有 2^n 种可能，远少于 2^{ℓ(n)} 种等长串），但只要没人能在多项式时间内**抓住**这个破绽，在密码学里它就和真随机一样好用。一个易错点：PRG 必须是确定性的（同一种子必给同一输出，否则收发双方对不上），"随机"体现在种子上，不在函数里。PRG 直接给出了流密码的骨架——把种子当密钥，用 G 拉出一条长长的密钥流，逐比特异或到明文上。

### 3.1.2 伪随机函数（PRF）

伪随机函数（Pseudorandom Function, PRF）把"看起来随机"从一条输出串升级到一整张函数表。它是一个带密钥的函数 F，固定密钥 k 后得到一个从 n 比特到 n 比特的具体函数 F_k；安全性要求：随机选一个密钥 k 得到的 F_k，与"从所有 n 比特到 n 比特函数中均匀随机抽一个函数 f"，对任何只能查询有限次的 PPT 区分器 D 都不可分辨：

|Pr[D^{F_k}(1^n) = 1] − Pr[D^{f}(1^n) = 1]| ≤ negl(n)

这里 D 只能通过"喂输入、看输出"的方式**黑盒查询**这个函数（记号 D^{F_k} 表示 D 可以访问 F_k 这个预言机），k 均匀随机，f 从全体函数中均匀随机抽取。

理解 PRF 的关键是想象两个黑盒子：一个盒子里装着 F_k（一把随机密钥选出的函数），另一个盒子里装着一张"真正随机填出来的巨大对照表"f。你可以对盒子随便输入、观察输出，任务是猜自己面对的是哪个盒子——PRF 安全就是说你猜不中（成功率仅比抛硬币多一个可忽略量）。为什么这比 PRG 强？因为 PRG 只保证"一条固定的长输出"随机，而 PRF 保证"整张函数的每个输入-输出对应关系"都随机，是随机访问、可任意点查的。那张真随机对照表大到无法存储（n=128 时有 2^128 个条目、每条 128 比特），PRF 的魔力正是**用一把 128 比特的密钥，冒充出一张天文数字大的随机表**。PRF 是构造 CPA 安全加密与 MAC 的核心积木。

### 3.1.3 伪随机置换（PRP）与分组密码模型

伪随机置换（Pseudorandom Permutation, PRP）是 PRF 加上"每个 F_k 都是双射（置换）"的要求：对固定的 k，F_k 是 {0,1}^n 到自身的一一对应，因而**可逆**（存在 F_k^{-1}）。它的安全性要求随机密钥选出的置换 F_k 与"从全体 n 比特置换中均匀随机抽一个置换"不可区分。若连"同时黑盒查询正向 F_k 和逆向 F_k^{-1}"都无法把它与随机置换区分开，则称为强 PRP（strong PRP）。

一个分组密码（block cipher）就是 PRP 的工程实现：它有固定的分组长度（block size，AES 为 128 比特）和密钥长度，加密 E_k 是置换、解密 D_k 是其逆。理论上我们**把分组密码当作（强）PRP 来分析和使用**。

初学者要抓住 PRP 与 PRF 的唯一区别——可逆性。加密必须能解密，所以加密函数必须是置换（一一对应），不能把两个不同明文映到同一密文，否则收方无法还原。为什么可逆的 PRP 和不可逆的 PRF 在实践中几乎可以互换着用？因为有一条"PRP/PRF 转换引理"：当分组长度 n 足够大时，一个 PRP 和一个 PRF 在多项式次查询下差别可忽略（区别只在生日界 2^{n/2} 附近才显现，n=128 时约 2^64 次查询才开始暴露"置换无碰撞"这个破绽）。所以设计协议时常按 PRF 来推理，实现时用 AES 这样的 PRP 来落地。要强调的是：分组密码"是 PRP"是一个**没有被证明、但被密码学界广泛相信**的假设——我们无法从更基本的假设证明 AES 是 PRP，只能靠多年公开密码分析没找到区分器来支撑这份信心。

## 3.2 计算安全与 CPA

### 3.2.1 计算不可区分

计算不可区分（computational indistinguishability）是现代密码学"安全"一词的通用度量。两个概率分布（或分布族）被称为计算不可区分，是指任何 PPT 区分器 D 从其中一个采样后判断"这是哪个分布"的优势可忽略：

|Pr[D(X) = 1] − Pr[D(Y) = 1]| ≤ negl(n)

它把"安全"从"绝对无法泄露任何信息"（信息论安全，如一次性密码本）**放松**为"在有限（多项式）计算资源下无法察觉差别"。

这是从大主题01/02 的完美保密走向实用密码学的关键一跳，初学者务必理解这次"放松"为何必要且值得。Shannon 定理说完美保密要求密钥至少和明文一样长（见大主题01），这在现实中不可用。计算安全的思路是：我们不追求"密文绝对不含明文信息"（它当然含——密钥比明文短，信息论上明文就藏在密文里），而只要求"没有任何现实计算能力能把这点信息**提取**出来"。就像一个上了复杂锁的保险箱，钥匙齿形信息其实全刻在锁芯里，但撬开它需要的时间超过宇宙年龄——于是它"实际上"是安全的。三个限定词要记牢：对手是**多项式时间**的（算力有界）、成功概率是**可忽略**的（比如 2^{-128}）、这一切建立在某个**未被证明的困难假设**上（如 PRF 存在）。

### 3.2.2 语义安全

语义安全（semantic security）是"密文不泄露明文任何部分信息"的直觉的形式化：对手在看到密文后，能计算出关于明文的任何函数的能力，与它压根没看到密文时相比没有实质提升。一个与之等价、更好操作的表述是**不可区分性**（IND）：对手自己挑两条等长明文 m_0、m_1 交给挑战者，挑战者随机加密其中一条返回密文，对手猜是哪条的成功率不超过

Pr[猜对] ≤ 1/2 + negl(n)

Katz-Lindell 证明了"语义安全 ⇔ 不可区分安全"，因此实践中一律用更简洁的不可区分实验来定义和证明。

初学者可以把不可区分实验想成一个游戏：你（对手）精心挑两条最想区分的消息，比如 m_0 = "进攻" 与 m_1 = "撤退"，对方掷硬币加密一条给你，你盯着密文猜。如果对任何你能想出的两条消息，你的胜率都压不过掷硬币（1/2），那这个加密方案就没漏任何可利用的信息。为什么用"挑两条自选消息"这么强的设定？因为它涵盖了最坏情况——连"对手完全知道明文只可能是这两者之一"这种极端先验都防住了，弱一点的场景自然也防住。一个直接推论：语义安全的加密**必须是随机化的**（或带 nonce/IV），因为确定性加密下同一条消息永远给同一密文，对手把 m_0 加密一次比对即可，胜率 100%。

### 3.2.3 CPA 安全定义

选择明文攻击（Chosen-Plaintext Attack, CPA）下的安全，是把 3.2.2 的不可区分游戏加强：允许对手在挑战前后**任意查询加密预言机**——即对手可以让系统加密任意多条它选的明文并看到对应密文，然后仍要在挑战密文上猜不中。用实验 PrivK^{cpa}_{A,Π}(n) 表示对手 A 对方案 Π 的这个游戏，CPA 安全定义为

Pr[PrivK^{cpa}_{A,Π}(n) = 1] ≤ 1/2 + negl(n)

游戏流程分步是：

1. 挑战者生成密钥 k

2. 对手 A 可多次向加密预言机 Enc_k(·) 提交任意明文，收到密文

3. A 输出两条等长明文 m_0、m_1

4. 挑战者掷硬币 b∈{0,1}，返回挑战密文 c* = Enc_k(m_b)

5. A 可继续查询加密预言机，最后输出猜测 b′；当 b′ = b 时 A 获胜

CPA 安全是对称加密的**基准安全目标**，初学者要理解"允许对手点加密"为什么是合理且必要的门槛。现实中攻击者常常能诱使系统加密它选的内容——比如让服务器加密一段攻击者提交的表单、或在 WEP/TLS 里注入已知明文。若一个方案在这种能力下就崩溃，它在现实里就不安全。CPA 安全的一个决定性后果，也是它区别于完美保密的地方：**CPA 安全的加密必然是随机化或带状态（nonce）的**，因为确定性加密在这个游戏里必输——对手在第 2 步先加密 m_0 拿到密文，第 4 步比对挑战密文即可。这正是后续大主题04 里所有工作模式都要引入 IV/nonce 的根本原因。比 CPA 更强的还有 CCA（选择密文攻击，对手还能查询解密预言机），对应认证加密，留待大主题04。

## 3.3 规约证明范式

### 3.3.1 归约论证的结构

可证明安全的核心手段是归约（reduction）：要证明"方案 Π 在假设 X 成立时是安全的"，不是直接证明没人能攻破 Π，而是**反证**——假设存在一个能以不可忽略优势攻破 Π 的高效对手 A，就用 A 当子程序构造出一个高效算法 B 去攻破被广泛相信为困难的问题 X（例如"区分 PRF 与随机函数""分解大整数"）。由于 X 被假设为困难，这样的 B 不该存在，因此这样的 A 也不该存在，矛盾。逻辑骨架分步是：

1. 假设敌手 A 能以优势 ε(n)（不可忽略）攻破方案 Π

2. 构造规约算法 B，B 内部把 A 当黑盒调用，并把 A 期待看到的输入"模拟"得与真实攻击环境不可区分

3. 当 A 成功攻破模拟环境时，B 相应地解决了底层困难问题 X

4. 推出 B 以与 ε(n) 相关的不可忽略优势解决了 X，与"X 困难"矛盾

5. 故不存在这样的 A，Π 安全

这个"用矛盾把安全性甩锅给一个公认难题"的思路，是初学者最需要转过来的弯。密码学几乎无法证明任何方案"绝对安全"（那要求证明 P≠NP 之类的世界级难题），能做的是把新方案的安全性**归约到少数几个久经考验的困难假设**上——相当于说"要攻破我的加密，你就得先解决那个几十年没人解开的老大难问题"。这里的技术核心是第 2 步的**模拟**：B 手里没有真实密钥，却要让 A 觉得自己在正常攻击真实方案，B 靠精心构造输入把这场戏演得天衣无缝。规约的"紧致性"也有讲究——B 解决 X 的优势和调用 A 的次数越接近，安全性越强，但按本报告广度定位不深入展开。

### 3.3.2 一个具体归约：PRF 直接给出 CPA 安全加密

把抽象骨架落到一个课本级实例。用一个 PRF F 构造如下加密方案：加密 m 时随机选一个 n 比特随机数 r，输出

c = ⟨ r , F_k(r) ⊕ m ⟩

解密时收方用同样的 k 算 F_k(r)，再异或回来得到 m。可以证明：若 F 是安全的 PRF，则该方案是 CPA 安全的。

归约的思路是这样的——假设有对手 A 能攻破这个加密方案的 CPA 安全，就构造 B 去区分"F_k 是真 PRF"还是"随机函数 f"。B 用自己手上的函数预言机来回答 A 的所有加密查询和挑战。如果 B 手上是真正的随机函数 f，那么只要每次用的随机数 r 不重复，F_k(r) 就是一串全新的随机比特，异或到明文上等同于一次性密码本，A 面对的密文与明文完全无关、胜率只能是 1/2；反过来，如果 A 真能在这个游戏里赢，那 B 手上的函数一定不是随机函数（否则 A 赢不了），于是 B 就区分出了 PRF 与随机函数，攻破了 PRF 假设。

这个例子让初学者一次看清三件事如何咬合：PRF（3.1）提供"随机的密钥流"，CPA 安全（3.2）是要达成的目标，归约（3.3）是把二者连起来的桥。它也暴露了唯一的隐患——**随机数 r 绝不能重复**：一旦两次加密撞用同一个 r，两条密文异或就消掉了 F_k(r)，直接泄露两条明文的异或（c_1 ⊕ c_2 中的密文部分 = m_1 ⊕ m_2），这正是大主题04 里 nonce/IV 复用灾难的雏形。

## 3.4 Feistel 与 DES 史

### 3.4.1 Feistel 网络结构

Feistel 网络是构造分组密码的一种通用框架：它把每个数据块对半劈成左右两半 (L, R)，反复迭代若干"轮"，每轮只对一半施加一个轮函数 F 再与另一半异或，然后左右交换。设第 i 轮输入为 (L_{i−1}, R_{i−1})、轮密钥为 k_i，则

L_i = R_{i−1}

R_i = L_{i−1} ⊕ F(R_{i−1}, k_i)

Feistel 结构最大的工程优点是**加密与解密用同一套电路/代码**：解密只需把轮密钥反序使用、并按下式反推（同一个 F，无需 F 可逆）：

R_{i−1} = L_i

L_{i−1} = R_i ⊕ F(L_i, k_i)

Feistel 的妙处，是它让设计者**不必操心轮函数 F 本身是否可逆**——不管 F 多复杂、多不可逆，整个 Feistel 变换永远是可逆的置换。初学者可以这样验证反推：加密时 R_i = L_{i−1} ⊕ F(R_{i−1}, k_i)，而 L_i = R_{i−1}，所以解密方拿到 (L_i, R_i) 后，用 L_i（就是 R_{i−1}）算出 F(L_i, k_i)，再异或掉 R_i 就还原出 L_{i−1}。异或的自反性（a⊕b⊕b=a）是这套可逆魔法的关键。这解放了设计者：可以把 F 做得极度混乱、充满查表和非线性，而不用付出"保证它可逆"的代价。有一个漂亮的理论结果（Luby–Rackoff 定理）：若轮函数 F 是安全 PRF，则三轮 Feistel 即为 PRP、四轮即为强 PRP——这为"用弱原语迭代出强置换"提供了理论背书。DES 是 Feistel 结构最著名的实例；相对地，AES 走的是另一条 SPN 路线（3.5）。

### 3.4.2 DES 概况

数据加密标准（Data Encryption Standard, DES）是 1977 年由美国国家标准局（NBS，今 NIST）颁布的分组密码，采用 16 轮 Feistel 结构，分组长度 64 比特，密钥名义上 64 比特但其中 8 位是奇偶校验位，**有效密钥长度仅 56 比特**。

对 DES 只需记住两个数和它的历史地位。两个数是：分组 64 比特、有效密钥 56 比特。历史地位是：它是第一个被公开、被全世界密码学界围攻研究的商用分组密码，催生了差分/线性密码分析等整套现代分析工具，AES 的许多设计取舍都是对 DES 教训的回应。DES 的算法本身（16 轮、S 盒扩散）经受住了几十年密码分析——它的致命伤不在算法而在**密钥太短**。56 比特意味着密钥空间只有 2^56 ≈ 7.2×10^16 种，这在今天可被暴力穷举（见 3.4.3）。

### 3.4.3 DES 退役与 3DES

56 比特密钥的 DES 早已被穷举攻破：1998 年 EFF 用约 25 万美元造的专用机器 "Deep Crack" 在数天内暴力破解 DES，1999 年配合分布式网络将时间压到约 22 小时，宣告单重 DES 的死亡。作为过渡方案，业界改用三重 DES（Triple DES / TDEA / 3DES），即用三把密钥连做"加密-解密-加密"：

C = E_{k3}( D_{k2}( E_{k1}(P) ) )

三密钥 3DES 名义密钥 168 比特，但因**中间相遇攻击**（meet-in-the-middle），其实际安全强度只有约 112 比特（NIST SP 800-57 认定为 112 位）。

3DES 如今也已进入退役程序，初学者应记住这条明确的时间线以免误用：按 NIST SP 800-131A Rev.2，三密钥 TDEA 用于加密在 2023-12-31 前为"弃用（deprecated）"、**2023 年后被"禁止（disallowed）"用于新应用的加密**（旧数据的解密仍允许作遗留用途），相关 FIPS 验证模块自 2024 年起移入历史列表。为什么名义 168 比特只值 112 比特？中间相遇攻击的思路是：把三段拆成"前一次 E_{k1}"和"后两次 D_{k2}·E_{k3}"，攻击者对已知明密文对，正向枚举 k1 建一张中间值表，反向枚举 (k2,k3) 去查表碰撞，用空间换时间把 3×56=168 的穷举降到约 2×56=112 量级。3DES 还有一个短板：分组仍是 64 比特，在大数据量下容易触及生日界碰撞。今天的正确选择是直接用 AES，3DES 仅存在于遗留系统兼容语境。

## 3.5 AES 内部结构

### 3.5.1 SPN 与 AES 概况

高级加密标准（Advanced Encryption Standard, AES）是 NIST 于 2001 年在 FIPS 197 中标准化的分组密码，其算法即比利时密码学家 Daemen 与 Rijmen 设计的 Rijndael（限定分组为 128 比特的版本）。AES 走的不是 Feistel 而是**代换-置换网络（Substitution-Permutation Network, SPN）**：每一轮对**整个**数据块施加"代换（打乱字节值）+ 置换/扩散（打乱字节位置与线性混合）+ 轮密钥异或"三类操作，层层叠加实现 Shannon 提出的混淆（confusion）与扩散（diffusion）。

AES 分组长度固定 128 比特，支持三种密钥长度 128/192/256 比特，对应 AES-128/AES-192/AES-256。内部把 128 比特（16 字节）的块排成一个 4×4 的字节矩阵，称为**状态（State）**，所有轮变换都作用在这个状态上。

SPN 与 Feistel 的直觉差别值得初学者对照记忆：Feistel 每轮只动一半数据、靠迭代和交换让改动扩散过去，好处是加解密对称、F 不必可逆；SPN 每轮就把整块一起变换，扩散更快，但每个组成操作都必须可逆（否则无法解密），所以 AES 的 S 盒、行移位、列混淆全部设计成可逆映射，解密时逐一用其逆变换、并把轮密钥反序。"混淆"指让密文与密钥的关系尽可能复杂（AES 靠 S 盒的非线性实现），"扩散"指让每一个明文比特尽快影响到尽可能多的密文比特（AES 靠行移位+列混淆实现，理论上两轮内一个字节的改变即扩散到全部 16 字节）。

### 3.5.2 四个轮变换

AES 的每一轮（末轮略有不同）由固定的四个步骤组成，全部作用在 4×4 字节状态上。

字节代换 SubBytes：对状态里**每个字节**独立地过同一张 8→8 比特的非线性代换表（S 盒），提供混淆。S 盒在数学上定义为"该字节在有限域 GF(2^8) 中的乘法逆元，再接一个固定的仿射变换"，其底层有限域用约化多项式

m(x) = x^8 + x^4 + x^3 + x + 1

行移位 ShiftRows：把状态矩阵的第 0 行不动、第 1 行循环左移 1 字节、第 2 行左移 2 字节、第 3 行左移 3 字节，提供跨列的扩散。

列混淆 MixColumns：把状态的**每一列**（4 字节）视为 GF(2^8) 上的一个多项式，乘以一个固定多项式并模 x^4+1，实现列内 4 字节的线性混合扩散（末轮省略此步）。

轮密钥加 AddRoundKey：把当前状态与本轮的 128 比特轮密钥逐字节异或。

初学者可以把一轮想成"炒菜四步"：SubBytes 是把每颗食材单独换味（非线性、防线性分析），ShiftRows 是把食材在盘子里横向挪位，MixColumns 是把每列食材搅拌融合，AddRoundKey 是撒上这一轮专属的密钥调料。前三步只负责"搅匀"（与密钥无关、公开可算），真正注入秘密的是第四步的异或。为什么末轮去掉 MixColumns？是为了让加密和解密流程在结构上对齐、便于实现，去掉它不影响安全性（末轮之后紧跟输出，再混合没有密码学收益）。这四步都可逆：解密时用逆 S 盒、反向行移位、逆列混淆矩阵，配合反序轮密钥即可还原。

### 3.5.3 轮结构与轮数

AES 的整体流程是"一次初始轮密钥加 + (Nr−1) 个完整轮 + 1 个末轮（无 MixColumns）"，轮数 Nr 取决于密钥长度：

AES-128 → Nr = 10 轮

AES-192 → Nr = 12 轮

AES-256 → Nr = 14 轮

这些轮数是 FIPS 197 规定的固定值，不可改动；三者分组长度都是 128 比特，只是密钥越长、轮数越多。

初学者常问"为什么不多加几轮更安全"——轮数是安全裕度与性能的平衡点。设计者根据当时最好的密码分析（差分/线性攻击能穿透的轮数）留出足够安全余量后定死轮数；轮数越多越慢，AES-256 比 AES-128 慢约 40%（多 4 轮）正是这个代价。要澄清一个常见误解：AES-256 的"更安全"主要来自更长的密钥（抗穷举，见 3.6），而非仅仅多几轮；实际上针对 AES-256 密钥编排还发现过一些相关密钥攻击（不影响正常单密钥使用），所以"256 一定处处强于 128"要谨慎表述——在标准单密钥场景两者都远超实用安全门槛。

### 3.5.4 密钥编排（Key Expansion）

密钥编排（key schedule / key expansion）把用户的原始密钥扩展成每一轮都要用的一串轮密钥。AES 用参数 Nk 表示原始密钥的 32 比特字数：

AES-128 → Nk = 4（4 字 = 128 比特），共需 11 个 128 比特轮密钥（初始 1 + 10 轮）

AES-192 → Nk = 6，共需 13 个轮密钥

AES-256 → Nk = 8，共需 15 个轮密钥

扩展过程以字（32 比特）为单位递推：每个新字一般等于它前一个字与 Nk 个位置之前的字的异或；在每 Nk 个字的边界处，先对前一个字做一次"字循环 RotWord + 字节代换 SubWord + 异或轮常数 Rcon"再参与异或，以打破对称性（AES-256 在中途还额外插一次 SubWord）。轮密钥总数为 4×(Nr+1) 个字。

密钥编排的作用是给每一轮都发一把"不同的、由主密钥派生的子钥"，避免所有轮共用同一密钥带来的规律性。初学者不需要背下递推的每个位运算，抓住三点即可：一是轮常数 Rcon 每轮不同，专门用来打破各轮之间的对称、防止滑动攻击（slide attack）；二是编排是可逆/确定的，收方用同一主密钥能算出完全相同的轮密钥序列；三是编排本身相对"轻"（主要是异或和查表），所以 AES 换密钥的开销不大。需要提醒的是，AES 的密钥编排被认为是其相对薄弱的一环（AES-256 的相关密钥攻击即源于此），但在规范的、每次随机独立选密钥的使用方式下不构成实际威胁。

## 3.6 密钥长度与安全对标

### 3.6.1 穷举搜索成本

对一个设计良好、无结构性弱点的分组密码，最好的通用攻击就是**暴力穷举密钥**（brute-force / exhaustive key search）：逐一试遍所有可能密钥直到解出正确明文。密钥长度为 k 比特时，密钥空间大小为

2^k

平均需要尝试约 2^{k−1} 次即可命中（期望在遍历一半时找到）。因此"密钥有效长度"直接决定了穷举下限，这也是 DES 的 56 比特（2^56 ≈ 7.2×10^16）在今天不安全、而 128 比特被认为安全的根本原因。

初学者要建立对这些指数数量级的体感。2^56 大约是 7 亿亿，专用硬件或大型集群数小时到数天可穷尽（1998 年就做到了）。每增加 1 比特，穷举代价翻一倍；从 56 到 128 是多了 72 个比特，代价是原来的 2^72 ≈ 4.7×10^21 倍。一个常被引用的量级估计：即使动用地球上全部计算力、跑到宇宙年龄那么久，也遍历不完 2^128 个密钥——这就是"128 比特对称密钥在经典计算下实际不可穷举"的直觉来源。要强调：这条推理只对"没有比穷举更好的攻击"的密码成立，AES 之所以敢把安全性押在密钥长度上，前提是几十年公开分析没找到显著优于穷举的捷径。

### 3.6.2 对称密钥强度对标（128/256）

NIST SP 800-57 Part 1 用"安全强度（security strength）"这一统一尺度衡量各算法：一个算法有 s 比特安全强度，意味着攻破它的最好已知攻击代价约为 2^s 次操作。对称算法的对标是直接的——密钥无结构性弱点时，安全强度约等于有效密钥长度：

AES-128 → 128 位安全强度

AES-192 → 192 位安全强度

AES-256 → 256 位安全强度

三密钥 3DES → 112 位安全强度（受中间相遇攻击限制，见 3.4.3）

作为跨体制的直觉参照，达到同等安全强度所需的密钥长度在不同体制间差异巨大：128 位对称安全强度大致对应 RSA-3072 或 256 位椭圆曲线（数值随算力演进，详见大主题06/07，此处仅作对标提示）。

初学者由此可得到清晰的选型口径：**通用场景选 AES-128 就已远超实用安全门槛**（112 位是 NIST 认可的最低可接受强度，128 位有充分裕度）；需要更长防护期或抵御未来（含量子）风险时选 AES-256。要点是"更长密钥买的是更高的穷举门槛，不是更复杂的算法"——AES-128 与 AES-256 用的是同一套轮变换，差别只在密钥长度与轮数。也要避免一个误区：对称密钥长度不能与公钥（RSA/ECC）密钥长度直接比大小，128 位 AES 远强于 128 位 RSA（后者几乎瞬间可破），必须通过"安全强度"这个共同尺子换算。

### 3.6.3 量子冲击（Grover）与选型

量子计算对**对称**密码的冲击相对温和且已被量化：Grover 搜索算法能把穷举 2^k 个密钥的代价降到约

2^{k/2}

即把有效安全强度**减半**（这与 Shor 算法对 RSA/DH 的毁灭性多项式时间破解截然不同，后者见大主题11）。因此在量子威胁模型下，AES-128 的等效强度降到约 64 位（偏弱），而 AES-256 仍保有约 128 位强度。

这解释了当前"对称密码抗量子"的主流建议，初学者可直接记结论：**面向长期/抗量子场景，对称加密选 AES-256**，它在 Grover 下仍留约 128 位强度、被认为足够。要点在于对称与公钥受量子冲击的性质完全不同——Grover 只提供平方根级加速（把 k 位削成 k/2 位，靠加倍密钥长度即可补回），所以对称密码"加长密钥就能续命"；而 Shor 直接在多项式时间内解掉大整数分解和离散对数，使 RSA/ECC 无论加长到多少位都从根上失效，只能整体换成后量子算法。这也是为什么后量子迁移（大主题11）主要是换公钥体制，而对称侧基本只需从 AES-128 升到 AES-256。需注意 Grover 加速在现实中还受量子电路深度、纠错开销等制约，实际"减半"是理论上界，且大规模容错量子计算机尚未到来（前沿演进，标"随技术演进"）。
