## 18.1 匿名与抗审查：混淆网络与 Tor 洋葱路由

### 18.1.1 匿名的目标：保护元数据而非内容

匿名通信要保护的不是消息**内容**（那是加密的活，见大主题10 TLS），而是**通信关系**这一元数据——谁在什么时候和谁通信、通信量多大。即使内容全程加密，一个能观察网络的敌手只要看到"A 的包总是紧接着流向 B"就能推断出关系，而关系本身往往就是敏感信息（记者联系了哪个线人、谁访问了某个政治/医疗网站）。

初学者常把"加密"和"匿名"当成一回事，这是本主题第一个要破除的误区。加密隐藏"说了什么"，匿名隐藏"谁在说、跟谁说"。HTTPS 让窃听者读不到你的网页内容，但它照样知道你连的是哪个 IP、哪个域名（SNI）。匿名系统的核心指标是**匿名集（anonymity set）**——一条消息可能来自的人的集合有多大；集合越大，把消息归到某个具体个体的概率越低。所以匿名从来不是一个人能实现的，它本质上需要"一群人共用一条通道，互相打掩护"。

### 18.1.2 混淆网络（mix network，Chaum 1981）

混淆网络是匿名通信的理论鼻祖，由 David Chaum 于 1981 年提出。它由一串"混淆节点（mix）"组成：每个 mix 收集**一批（batch）**来自不同发送者的消息，对每条消息用自己的公钥剥掉一层加密，然后**重新排序（reorder）**、可能加入延迟后再统一转发出去。因为进入 mix 的顺序和离开的顺序被打乱、每条消息的外观（长度、加密层）也被改变，观察者无法把某个流出的包和某个流入的包对应起来。

理解 mix 的关键在于"批处理 + 重排"这一对操作专门用来打断**时序关联（timing correlation）**。设想没有重排：包一进一出，第 3 个进的就是第 3 个出的，匿名立刻失效。mix 靠"攒一批再乱序放出"制造混淆，代价是**高延迟**（要等凑够一批）。层层公钥加密的写法可类比套娃——发送者用路径上各 mix 的公钥自内向外逐层加密，每个 mix 只能解开属于自己的那层、看到"下一跳是谁"，看不到最终目的地也看不到真正的源。这个"层层加密、逐跳剥离"的思想正是"洋葱路由"名字的来源，也是 Tor 的直接祖先；区别在于 Tor 为了可用性放弃了 mix 的批处理与延迟（见 18.1.4）。

### 18.1.3 Tor 洋葱路由：电路与分层加密

Tor（The Onion Router）是当今部署最广的匿名网络，其设计见 Dingledine-Mathewson-Syverson 2004 论文。客户端从数千个志愿者中继（relay）中挑选，默认构建一条**三跳电路（circuit）**：入口守卫（guard/entry）、中间中继（middle）、出口中继（exit）。客户端与三个中继各自用 Diffie-Hellman 协商一把独立的对称密钥（大主题07），然后把数据**层层加密**——最内层用出口密钥、中间层用中间密钥、最外层用守卫密钥。数据沿电路前进时每经过一跳就被剥掉一层，如同剥洋葱。

这套设计的安全核心是一条不变式：**没有任何单个中继同时知道"源"和"目的地"**。守卫知道你是谁但只看到加密数据和"下一跳是中间中继"，看不到你最终访问哪里；出口知道你访问哪里但只看到流量来自中间中继，不知道你是谁；中间中继两头都不知道。攻击者要还原完整路径，必须同时控制守卫和出口。选"三跳"是安全与性能的折中：一跳等于没有中间人遮挡，两跳则守卫和出口直接相邻更易被同一方掌握，三跳用中间中继把两端隔开，再多则徒增延迟收益递减。为什么固定用少量长期"守卫"而非每次随机换入口？因为若每条电路都随机选入口，长期使用后你迟早会某次选中攻击者控制的入口+出口组合而暴露；固定守卫把"是否踩雷"变成一次性赌注而非反复抽签，降低长期被去匿名的概率。

### 18.1.4 Tor 的威胁模型与端到端关联攻击

Tor 明确是一个**低延迟（low-latency）**匿名网络——为了能刷网页、看视频，它**不做** mix 那样的批处理和延迟。这个可用性取舍带来一个已知且未解的弱点：面对能同时观测入口和出口流量的**全局被动敌手（global passive adversary）**，Tor 无法抵御**端到端流量关联（end-to-end traffic correlation / confirmation）**攻击——敌手不需要解密，只要比对入口侧和出口侧的数据包时序和大小模式，就能以高置信度确认"这个用户在访问那个站点"。

要记住的一点是，Tor 的设计文档本身就声明**不**在威胁模型内防御全局观测者，这不是 bug 而是明确的范围界定。它防的是局部敌手（单个中继、单个 ISP、访问的目标网站），靠"没有单点同时知道两端"来保护。区分 Tor（低延迟、防局部敌手、不防时序关联）与经典 mixnet（高延迟、通过批处理试图防时序关联）是本小主题最重要的辨析点。

### 18.1.5 抗审查：网桥与可插拔传输

匿名和抗审查是相关但不同的目标：匿名要隐藏"你是谁"，抗审查要突破"不让你连上 Tor"。审查者常用两招——封锁公开的 Tor 中继 IP 列表，以及用深度包检测（DPI）识别 Tor 流量特征后阻断。Tor 的对策是**网桥（bridge）**（不公开列出的入口中继，审查者拿不到完整封锁列表）加**可插拔传输（pluggable transport）**（如 obfs4、meek，把 Tor 流量伪装成随机字节流或普通 HTTPS，让 DPI 认不出来）。

从直觉上看，抗审查是一场"看起来不像 Tor"的伪装竞赛，和匿名的"藏进人群"是两条不同的防线。一个用户可能需要匿名但不需要抗审查（所在地不封 Tor），也可能两者都要（封锁环境下的记者）。把这两个目标分开，才能理解为什么 Tor 既有洋葱路由（匿名）又有网桥/混淆层（抗审查）这两套相对独立的机制。

## 18.2 (ε,δ)-差分隐私的定义

### 18.2.1 相邻数据集与差分隐私的直觉

差分隐私（DP）刻画一个随机算法（机制 M）的性质：**在数据集里加入或移除任何单一个体的记录，M 的输出分布几乎不变**。两个只差一条记录的数据集称为**相邻（adjacent / neighboring）**数据集，记作 D 和 D'。"几乎不变"意味着：无论你事后拿到什么输出，你都无法据此判断某个特定个体到底在不在数据集里——因为在与不在给出的输出分布长得几乎一样。

这个定义的巧妙之处在于它保护的是**个体的存在性/参与**，而且是最坏情况下的保证：对任意个体、任意先验知识、任意输出都成立。初学者要抓住的核心承诺是"合情合理的否认（plausible deniability）"——参与数据集的人可以声称"任何关于我的推断，就算我没参与也会得出同样的结论"，因为我的加入几乎不改变结果。这也解释了为什么 DP 是**机制的性质**而不是**数据/输出的性质**：同一个输出既可能来自 D 也可能来自 D'，谈"这个输出私不私"没有意义，只能谈"产生它的算法私不私"。

### 18.2.2 ε-差分隐私（纯 DP）的定义式

一个随机机制 M 满足 ε-差分隐私（pure DP），当且仅当对所有相邻数据集 D、D'，以及 M 输出空间的所有可测子集 S，都有

Pr[M(D) ∈ S] ≤ e^ε · Pr[M(D') ∈ S]

其中参数 ε ≥ 0 称为**隐私损失参数（privacy budget / privacy loss）**。ε 越小，两个分布被约束得越接近，隐私越强；ε = 0 意味着输出完全不依赖数据（绝对私密但毫无用处）。

这里为什么用 e^ε 这个乘性因子而不是加性差？因为概率有大有小，乘性约束对"极小概率事件"也同样有力——它禁止任何输出在 D 上比在 D' 上"概率暴涨"。把不等式两边取对数，e^ε 就变成"对数似然比至多相差 ε"，这正是下一项"隐私损失"的来源。一个常见误区是把 ε 当百分比或概率来读；ε 是一个无量纲的对数尺度参数，ε=1 对应 e≈2.72 倍的概率差，ε=0.1 对应约 1.1 倍，ε=ln2≈0.69 对应 2 倍。所以 ε 从 1 降到 0.1 不是"隐私强 10%"，而是把最坏情况的分布差异从 2.72 倍压到 1.1 倍，是数量级的收紧。

### 18.2.3 隐私损失随机变量

对某个具体输出 o，**隐私损失（privacy loss）**定义为在 D 与 D' 下观测到 o 的概率的对数比：

L = ln ( Pr[M(D) = o] / Pr[M(D') = o] )

ε-DP 等价于要求这个损失对所有相邻 D、D' 和所有输出都满足绝对值上界 |L| ≤ ε 恒成立。

把隐私损失看成一个随机变量（因为 o 是 M 随机产生的）是理解后面"近似 DP"和"高级组合"的钥匙。纯 DP 要求这个随机变量被 ε **硬性封顶**、一个反例都不许有；这非常强，也非常苛刻。现实中很多好用的机制（尤其高斯机制）会有极小概率产生一个损失超过 ε 的"坏输出"。与其为了封住这罕见尾巴而付出巨大噪声代价，不如允许一个小概率 δ 的例外——这就自然引出了 (ε,δ)-DP。

### 18.2.4 (ε,δ)-近似差分隐私的定义式

一个机制 M 满足 (ε,δ)-差分隐私（approximate DP），当且仅当对所有相邻数据集 D、D' 和所有可测子集 S，

Pr[M(D) ∈ S] ≤ e^ε · Pr[M(D') ∈ S] + δ

当 δ = 0 时退化为纯 ε-DP。δ 是一个"允许纯 DP 保证被打破"的小概率松弛项，通常要求 δ 远小于数据集规模 n 的倒数（δ ≪ 1/n），常取如 10⁻⁵ 这一量级。

理解 δ 的正确心智模型：δ 是"隐私彻底失守的概率上界"。一个直观（但要小心的）解读是——机制以至多 δ 的概率可能输出某种严重泄露个体信息的结果，其余至少 1−δ 的概率下仍满足 ε-DP。这就是为什么 δ 绝不能取大：若 δ = 1/n，一个"每次随机挑一条真实记录直接公开"的机制在技术上也能满足 (0, 1/n)-DP，却显然毫无隐私——所以实践中 δ 必须**密码学级地小**（远小于 1/n），把这种灾难概率压到可忽略。区分两者的定位：纯 DP（δ=0）是"绝对没有坏情况"，近似 DP（δ>0）是"坏情况的概率被 δ 封住"；高斯机制天然只能给近似 DP，拉普拉斯机制能给纯 DP，这是 18.3 选机制的关键分野。

## 18.3 全局敏感度与基本机制

### 18.3.1 全局敏感度

要给一个数值查询 f 加噪以满足 DP，先得知道"改动一个人最多能让 f 变多少"。函数 f 的**全局敏感度（global sensitivity）**是它在任意一对相邻数据集上输出差的最大范数。用 L1 范数（拉普拉斯机制用）时记作

Δ₁f = max over adjacent D, D' of ‖f(D) − f(D')‖₁

用 L2 范数（高斯机制用）时记作

Δ₂f = max over adjacent D, D' of ‖f(D) − f(D')‖₂

敏感度是"该加多少噪声"的标尺：变化范围越大，要盖住这个变化就得加越多噪声。最好记的例子是**计数查询**（"有多少人满足某条件"）：加或减一个人最多让计数变 1，所以计数的全局敏感度 Δf = 1。求和查询若每个人的贡献被裁剪到区间 [0, C]，则敏感度是 C。均值、直方图等都可类似推。一个初学者易错点：全局敏感度取的是**所有可能相邻对上的最大值**，与你手头这份具体数据无关——它是最坏情况的属性，正因如此它不会泄露关于真实数据的信息，可以放心公开用来定噪声量。（另有依赖具体数据的"局部敏感度"，但直接用它定噪声会泄露信息，属进阶话题，此处不展开。）

### 18.3.2 拉普拉斯机制

拉普拉斯机制对数值查询 f 的每个输出坐标加入独立的拉普拉斯噪声，噪声尺度由敏感度和 ε 决定：

M(D) = f(D) + Lap(Δ₁f / ε)

其中 Lap(b) 是尺度参数为 b、均值为 0 的拉普拉斯分布，其概率密度为

p(x) = (1 / 2b) · exp( − |x| / b )

拉普拉斯机制满足**纯 ε-DP**（δ = 0）。

为什么恰好是拉普拉斯分布而不是别的？因为它的密度里有 |x|（绝对值），取两个相邻输入下密度的比值时，指数上出现 |f(D)−x| − |f(D')−x|，由三角不等式这个差被 ‖f(D)−f(D')‖₁ ≤ Δ₁f 控住，于是似然比恰好被 e^(Δf/b) 封顶——令 b = Δf/ε 就得到 e^ε。噪声尺度 b = Δf/ε 蕴含两条直觉：敏感度越大要加越多噪声（分子），ε 越小（要越私）也要加越多噪声（分母）。对计数查询（Δf=1），加的噪声就是 Lap(1/ε)，其标准差约为 √2 / ε——ε=0.1 时标准差约 14，ε=1 时约 1.4，直观显示"更私 = 更吵"。numpy 教学级实证可选：`numpy.random.laplace(0, 1/eps, size)` 对计数加噪并统计经验分布，本次未落地，如实标注。

### 18.3.3 高斯机制

高斯机制改加正态噪声，尺度由 L2 敏感度、ε 和 δ 共同决定：

M(D) = f(D) + N(0, σ²)

在经典分析（Dwork-Roth 附录 A，要求 0 < ε < 1）下，取

σ ≥ (Δ₂f / ε) · √( 2 · ln(1.25 / δ) )

即可满足 (ε, δ)-DP。高斯机制**只能给近似 DP**（δ > 0），换来的好处是它按 L2 敏感度而非 L1 敏感度加噪。

为什么要用高斯而不总用拉普拉斯？关键在高维。当 f 输出一个 d 维向量（如一批查询、一个梯度），L1 敏感度往往随维度线性增长，而 L2 敏感度只按 √d 增长；在高维下高斯机制加的总噪声量常常更省。代价是高斯分布的密度里是 x²（不是 |x|），似然比无法被硬性封顶——总有极小概率的尾部事件打破 ε 约束，这就是它必须带一个 δ、只能是近似 DP 的根本原因。这也正好呼应 18.2.3：δ 就是用来"赦免"这条罕见尾巴的。注意上式是经典（较松）的界；近年"解析高斯机制（analytic Gaussian mechanism, Balle & Wang 2018）"给出更紧的 σ，且不再受 ε<1 限制，实务与库中常用后者——此处只登记，具体系数以所用库文档为准，标⚙。

### 18.3.4 敏感度决定机制、机制决定 DP 类型

把三者串起来看，整条流水线是先算查询的敏感度（L1 还是 L2，取决于打算用哪种机制），再据敏感度和隐私参数定噪声尺度，最后机制类型决定你拿到纯 DP 还是近似 DP。拉普拉斯配 L1 敏感度、给纯 ε-DP；高斯配 L2 敏感度、给 (ε,δ)-DP。

初学者可把这条流水线记成"敏感度是输入、噪声是旋钮、DP 保证是输出"。同一个查询，选拉普拉斯还是高斯不是随意的：低维、要纯 DP、无法容忍任何 δ 松弛时选拉普拉斯；高维（尤其机器学习梯度）、能接受一个极小 δ、想省噪声时选高斯。这个选择直接决定 18.4 组合时用哪套定理、18.6 的 DP-SGD 为何清一色用高斯机制。

## 18.4 组合定理与隐私预算

### 18.4.1 隐私预算的概念

现实里同一份数据往往要回答**多个**查询，每个查询都消耗一点隐私。DP 的组合定理告诉你多次访问后总的隐私损失是多少——这个总量就是**隐私预算（privacy budget）**。实务做法是先给整个数据集分配一个总预算 ε_total，每个查询从中扣除一份，用完为止；这把"隐私"变成了一种可核算、可分配的稀缺资源。

这是 DP 相对早期匿名化技术（k-匿名等）的决定性优势：它能**跨多次发布、可加地**追踪隐私损失，而不是每次单独评估、无法累计。初学者要建立的直觉是"隐私会累积泄露"——问一个人 10 个略带噪声的问题，把答案凑起来能比问 1 个泄露得多。组合定理就是量化这种累积的工具，隐私预算就是给累积设的天花板。

### 18.4.2 顺序组合

若机制 M₁, …, M_k 分别满足 (ε₁,δ₁)-DP, …, (ε_k,δ_k)-DP，且都作用在**同一份数据**上，则它们的组合满足

( Σᵢ εᵢ , Σᵢ δᵢ )-DP

即隐私参数**逐项相加**。纯 DP 是其特例：k 个 εᵢ-DP 机制顺序组合得 (Σεᵢ)-DP。

顺序组合是隐私预算"花钱"的基本记账规则：每问一次，就从总预算里扣掉这次的 ε。它的证明直觉是隐私损失随机变量可加——两次独立机制的对数似然比相加，最坏情况就是各自上界之和。要点在于这个界对**自适应**查询也成立（下一个查询可以依赖上一个的带噪输出），这正是它实用的原因。易错点：顺序组合的相加是**最坏情况**的界，往往偏保守；当 k 很大时，逐项相加会让预算飞快耗尽，这就是需要 18.4.4 高级组合的动机。

### 18.4.3 并行组合

若把数据集划分成**互不相交（disjoint）**的若干块，对每块分别施加一个 εᵢ-DP 机制，则整体只满足

( maxᵢ εᵢ )-DP

即取最大值而非求和。

从直觉上讲，任何一个个体只落在**一个**分块里，只被那一块的机制"碰到"一次，所以它承受的隐私损失就是那一块的 ε，而不是所有块之和。最典型的应用是**直方图**——把人群按互斥的桶（年龄段、地区）分开计数，每桶加独立噪声，整个直方图的隐私代价只是单桶的 ε，而不是桶数乘以 ε。区分顺序与并行是本小主题最关键的辨析：查询**重复触碰同一批人**用顺序组合（相加），查询**切分到互斥人群**用并行组合（取 max）。注意并行组合的经典表述来自 McSherry 的 PINQ (2009)，Dwork-Roth 专著以顺序组合与高级组合为主线，二者不冲突、各有出处。

### 18.4.4 高级组合与隐私预算的次线性增长

顺序组合让 ε 线性累加（k 次 → kε），k 大时预算爆炸。**高级组合定理（advanced composition）**给出更省的界：k 个 (ε, δ) 机制的组合，对任意 δ' > 0，满足 (ε', kδ + δ')-DP，其中

ε' = √( 2 k · ln(1 / δ') ) · ε + k · ε · (e^ε − 1)

当 ε 很小时第二项可忽略，ε' 主要按 √k 增长，即

ε' ≈ √( 2 k · ln(1 / δ') ) · ε

高级组合的意义在于把总隐私损失从"线性 kε"改善到"约 √k · ε"，代价是引入一个额外的 δ'（从纯 DP 滑向近似 DP）。为什么能省？因为 k 次损失里有的偏高、有的偏低，会**相互抵消**——像 k 步随机游走的净位移只有 √k 而不是 k。这正是训练成千上万步的 DP-SGD（18.6）能活下来的数学基础：若按线性组合，几万步早把预算烧光了。近年更进一步用 **Rényi DP / 零集中 DP（zCDP）** 或数值化的"矩会计（moments accountant）"给出比高级组合还紧的界，是当前实务主流（⚙演进快，此处只登记名称，具体常数以所用会计器文档为准）。

- 一手：NIST SP 800-226 (Final, 2025-03-06) §2.3 / §3——顺序组合可加、并行组合取 max、高级组合的 √k 改善、隐私预算记账，核实 2026-07-30。

## 18.5 隐私-效用权衡与 ε 的选择

### 18.5.1 噪声-精度的基本权衡

DP 的免费午餐并不存在：隐私靠加噪买来，而噪声必然损害**效用（utility / accuracy）**。对拉普拉斯机制，单次查询加的噪声标准差正比于 Δf/ε，所以

误差（噪声标准差）∝ Δf / ε

在给定敏感度下，ε 越小（越私）→ 噪声越大 → 答案越不准；ε 越大（越不私）→ 噪声越小 → 答案越准。

这条反比关系是整个 DP 工程决策的核心张力。初学者可以记一个具体感受：计数查询（Δf=1）用拉普拉斯，ε=1 时误差标准差约 1.4，ε=0.1 时约 14，ε=0.01 时约 140。对一个真实值几百万的人口计数，±14 的噪声无关痛痒；但对一个真实值只有个位数的稀有子群计数，±14 的噪声足以把信号完全淹没。所以"ε 够不够用"从来不能脱离**查询规模和数据规模**孤立地谈。numpy 教学级实证可选：扫描一组 ε 值、对固定真值反复加拉普拉斯噪声、绘制均方误差随 ε 的曲线，本次未落地，如实标注。

### 18.5.2 样本量如何缓解权衡

同样的 ε，数据集越大，DP 的相对损害越小。因为很多统计量（如均值、比例）本身的抽样标准误差按 1/√n 缩小，而 DP 噪声对**归一化后**的统计量的影响也随 n 增大而相对变小——当 n 足够大，DP 噪声会被淹没在本就存在的抽样波动里。

这解释了一个反直觉但重要的事实：DP 更适合**大规模**数据发布（人口普查、大平台遥测），在小数据/稀有子群上则代价高昂。给初学者的定位：不要孤立地问"ε=1 私不私、准不准"，要问"在这个 n 和这个查询下，ε=1 加的噪声相对信号是大是小"。同一个 ε 在十亿级数据上几乎无损，在几十人的敏感子群上可能让结果完全不可用——这也是稀有群体在 DP 发布中反而更容易被牺牲的原因，是一个公平性层面的已知隐忧。

### 18.5.3 ε 的选择：没有普适阈值

ε 该取多少没有一劳永逸的标准答案。DP 文献早期常把 ε ≤ 1（有时到 ln2 或 ln3）视作"强隐私"的经验区间，但真实部署里 ε 的取值范围很宽：美国 2020 年人口普查等大型项目使用的总 ε 明显大于 1（分配到大量查询后每项很小），因此**脱离上下文比较两个系统的 ε 数值是没有意义的**。NIST SP 800-226 的立场是不给硬性阈值，而是要求把 ε 连同粒度单位（保护的是一条记录还是一个用户）、δ、组合后的总预算一起披露和评估。

初学者最该带走的判断纪律是：一个 ε 数字单独拎出来无法判定好坏，必须问清四件事——(1) **相邻的定义**（改一条记录 vs 改一个用户的全部记录，后者严格得多）；(2) δ 取了多大；(3) 这是**单次查询**的 ε 还是**组合后总**预算；(4) 数据和查询的规模。忽略其中任何一条去比 ε，都会得出错误结论。这也是为什么监管和评估越来越强调"报告完整的隐私会计"而非只报一个 ε。

### 18.5.4 中心化 DP 与本地化 DP 的权衡

DP 有两种部署模型，效用差异巨大。**中心化 DP（central DP）**假设有一个可信的数据聚合方，先收集所有人的原始数据、再对**聚合结果**加一次噪声；**本地化 DP（local DP, LDP）**不信任聚合方，每个用户在**自己设备上**先给自己的数据加噪再上传。

两者的权衡一目了然：本地 DP 信任假设更弱（连收集方都不用信，隐私更硬），但每个用户各加一份噪声，聚合后噪声按用户数累积，**效用差得多**，通常需要海量用户才能得到有用的统计。中心化 DP 只在最终结果上加一次噪声，效用高得多，但要求你信任那个持有全部原始数据的聚合方。经典部署对照：苹果、谷歌的一些遥测采集用本地 DP（随机响应类），美国人口普查用中心化 DP。理解这条分野能解释很多"为什么某系统的 ε 看起来很大却仍被接受"——本地 DP 因噪声累积往往被迫用大得多的 ε。

- 一手：NIST SP 800-226 (Final, 2025-03-06) §2.4 / §5——ε 无普适阈值、须连同粒度/δ/总预算披露、中心 vs 本地 DP、样本量对效用的影响，核实 2026-07-30。

## 18.6 隐私保护机器学习（PPML）与机密计算

### 18.6.1 DP-SGD：把差分隐私搬进模型训练

DP-SGD（差分隐私随机梯度下降，Abadi et al. 2016）是训练带 DP 保证的神经网络的主力方法。它在普通 SGD 的每一步上加两道工序：先对**每个样本单独**计算梯度并把其 L2 范数**裁剪（clip）**到一个上限 C（把单样本敏感度硬性限制为 C），再对这一批裁剪后梯度的和加**高斯噪声**，最后用带噪梯度更新参数。整个训练过程的总隐私损失用一个"会计器（accountant）"跨所有步累计。

理解 DP-SGD 只需扣住 18.3–18.4 两块拼图：梯度裁剪是**制造有界敏感度**的手段（原始梯度范数无上界，无法定噪声，裁剪后敏感度就是 C），高斯加噪把每步变成一个 (ε,δ) 机制，跨步用**高级组合/矩会计**把成千上万步的总预算控制在 √(步数) 量级而非线性。这就是 18.4.4 说"高级组合是 DP-SGD 的数学基础"的含义。代价是双重的：裁剪+噪声都损害精度，DP 模型通常比非私有模型精度低，且隐私预算越紧、掉点越多——这是 18.5 噪声-效用权衡在深度学习里的具体化。此处涉及的具体噪声乘子、裁剪阈值、会计器实现随库（如 Opacus / TF-Privacy）与年份演进，标⚙，不给固定数值。

### 18.6.2 联邦学习：把数据留在本地

联邦学习（federated learning, McMahan et al. 2017 的 FedAvg）让多个客户端（手机、机构）各自在**本地数据**上训练，只把模型更新（梯度/权重）上传给服务器聚合，原始数据从不离开本地。它的动机是数据最小化与合规——数据不集中，泄露面更小。

这里有一个初学者最常踩的误区——**联邦学习本身不等于隐私保护**。上传的梯度并非无害，研究已表明可从梯度**反演（gradient inversion）**出训练样本。所以实践中联邦学习要真正保护隐私，通常还要叠加两样东西——**DP**（对上传的更新加噪，给出形式化保证）和/或**安全聚合（secure aggregation）**（用密码学让服务器只看到所有更新的和、看不到任何单个客户端的更新）。把"联邦学习=数据不出门"和"DP=形式化隐私保证"分开理解很重要：前者是系统架构层面的数据最小化，后者才是可量化的隐私承诺，二者常组合但解决的是不同问题。

### 18.6.3 机密计算与可信执行环境（TEE）· ⚙未定型，只登记不作结论

机密计算（confidential computing）指用硬件**可信执行环境（TEE）**——如 Intel SGX、Intel TDX、AMD SEV-SNP、ARM CCA/TrustZone——在**使用中（in-use）**保护数据：把代码和数据放进一块由 CPU 硬件隔离、加密的"飞地（enclave）"里，即使操作系统、虚拟机管理程序乃至云服务商都无法读取或篡改其中内容，并可通过**远程证明（remote attestation）**向外部证明"我确实在一个未被篡改的 enclave 里运行指定代码"。它与 DP 是**正交**的隐私手段：DP 限制"输出泄露多少"，TEE 保护"计算过程中数据不被旁人看到"。

本项按 prompt 要求**硬标未定型、只登记不作结论**。原因是 TEE 的安全边界在实践中并不稳固：SGX 等 enclave 多年来被一系列微架构侧信道攻击（Foreshadow/L1TF、Plundervolt、SGAxe、ÆPIC Leak、各类瞬态执行泄露，参见大主题14）反复攻破，厂商以微码/固件更新与硬件迭代持续修补，攻防仍在拉锯；不同厂商方案（SGX/TDX/SEV-SNP/CCA）的威胁模型、证明机制、可用性状态各异且快速演进。因此本报告只登记 TEE 作为 PPML 的一类硬件路径及其"保护使用中数据 + 远程证明"的核心定位，具体某方案在某时点"是否安全、防住哪些侧信道、生产可用到什么程度"不作结论，须以厂商与学界在核实时点（⚙锚 2026-07-30，随时变）的最新公告为准。
