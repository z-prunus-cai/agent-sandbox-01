一个刚预训练完的语言模型只会「续写」——给它一段文本，它接着往下写最可能的 token。它并不知道「回答问题」「遵循指令」「拒绝有害请求」是它该做的事。训练后与对齐要解决的就是这个落差：怎样把一个博学但不受控的续写机器，调成一个愿意听话、行为符合人类意图的助手。本大主题按「越来越省人力、越来越自动」的顺序把主要技术路线摆开：先用示范数据模仿（SFT），再用人类偏好打分做强化学习（RLHF），然后是绕开奖励模型、直接用可验证信号的 RLVR，以及绕开显式 RL、把对齐写成一个分类损失的 DPO 一族，最后是把视觉/音频接进 LM 的多模态对齐。

## 08S-12.1 SFT（指令微调）

### 08S-12.1.1 从预训练到后训练：为什么需要 SFT

监督微调（Supervised Fine-Tuning, SFT），在语言模型语境下常直接叫「指令微调（instruction tuning）」，指用一批「指令 + 理想回答」的示范样本，继续训练预训练模型，让它学会按人类期望的格式和行为来响应指令。

预训练模型的目标只有一个——预测下一个 token，所以它擅长的是「补全」而不是「应答」。给它「法国的首都是哪里？」，一个纯预训练模型可能接着生成「德国的首都是哪里？意大利的首都是哪里？」这样一串同类问题，因为在网页语料里，问题后面常常跟着更多问题。SFT 的作用是把模型的行为分布挪到「看到指令就给出有用回答」上。这一步之所以放在最前面，是因为它便宜、稳定、见效快：只要有一批高质量示范，用标准的监督学习就能训，不需要任何强化学习或奖励模型。它也是后面 RLHF、DPO 等所有方法的共同起点——那些方法几乎都从一个 SFT 之后的模型出发，再进一步优化。

### 08S-12.1.2 指令数据的格式与 chat template

SFT 的数据是一条条「对话」，最简单形式是单轮的（用户指令，助手回答），也可以是多轮的（用户/助手交替）。为了让模型分清谁在说话、从哪里开始该由它生成，训练和推理时会用一套固定的「聊天模板（chat template）」把角色和轮次用特殊标记包起来。

一条训练样本在喂进模型前，会被模板渲染成类似这样的 token 序列（不同模型的具体标记名不同，此处示意）：

```
<|system|> 你是一个乐于助人的助手。
<|user|> 法国的首都是哪里？
<|assistant|> 巴黎。
```

模板不是可有可无的装饰：模型在训练时见到的是哪种格式，推理时就必须喂同一种格式，否则行为会明显退化——这是初学者常踩的坑（自己拼 prompt 时漏掉角色标记，导致模型答非所问）。系统提示（system prompt）用来设定全局角色与约束，用户与助手轮次交替构成对话历史。特殊标记（如轮次起止符）通常在分词器里作为专门的 token 加入，模型靠它们判断上下文边界和「该我说话了」的位置。

### 08S-12.1.3 训练目标：交叉熵 + 只在回答上算损失

SFT 用的损失函数和预训练一样，都是下一 token 的交叉熵；关键区别是通常只在「助手回答」那部分 token 上计算损失，用户输入和模板标记部分被「屏蔽」掉（loss masking / prompt masking），不参与梯度。

也就是对一条样本，损失只对回答段的每个 token 求和：

```
L_SFT = − Σ_{t ∈ 回答段} log p_θ(y_t | y_<t, prompt)
```

我们要模型学的是「给定这个指令，怎么回答」，而不是「怎么把用户的问题再复述一遍」。如果把用户输入也算进损失，模型会浪费容量去建模用户会问什么，甚至学着模仿用户语气。屏蔽掉输入段，梯度就只推动模型改进它真正要产出的部分。要注意这只是常见做法而非唯一做法——是否屏蔽、屏蔽到哪一段属于实现选择，不同代码库有差异；具体默认值以所用框架为准（待核）。因为目标函数与预训练同构，SFT 本质上是「换了数据分布的继续预训练」，工程上极其简单，这也是它稳定的原因。

### 08S-12.1.4 指令数据的来源与规模

指令微调数据主要有两条来路：一是人工撰写/标注的高质量示范，二是用更强的模型「蒸馏」生成的合成指令数据。规模上，早期工作发现相对少量但高质量的示范就能显著改变模型行为。

人工路线以 InstructGPT（Ouyang et al. 2022, arXiv:2203.02155）为代表：雇标注员为大量 prompt 写理想回答，作为 SFT 的第一步。合成路线里，FLAN（把大量现有 NLP 数据集改写成指令形式）、Alpaca（用一个强模型自动生成指令-回答对再微调一个小模型）是常被引用的思路。数据的「质量 vs 数量」是这一块的核心争论之一：一派证据（如 LIMA 类工作，arXiv:2305.11206）显示很少量（千级）但精挑的示范就能出好的对齐效果，暗示对齐更多是「激活预训练已有的能力」而非灌输新知识；另一派则用大规模混合数据追求覆盖面。两种取向都有支持，具体哪种在什么规模下更优随模型与任务而变，本篇不作定论。具体的最优样本数、混配比例属逐项工程结论，未一手坐实者标「待核」。

### 08S-12.1.5 SFT 的边界：模仿学不到「更好」

SFT 本质是行为克隆（behavior cloning）——模型只能模仿示范里出现过的回答，无法学到「哪种回答比另一种更好」这个相对信息，因此单靠 SFT 难以逼近人类偏好的上限。这正是后续偏好学习（RLHF / DPO 等）要补的短板。

直觉上，示范数据只告诉模型「这样答是对的」，却没告诉它「这样答比那样答好在哪」。当一个指令有很多种合理回答、但它们质量有高下之分时，SFT 无从区分——它对示范里的每条回答一视同仁地去拟合。而且人写的示范也有天花板：标注员未必总能写出最优回答，模型至多学到「标注员的平均水平」。更麻烦的是分布外行为：对示范没覆盖到的情形，模型只能外推，容易产生自信的错误。要突破这些，需要一种能利用「A 比 B 好」这种成对比较信号的方法，让模型知道往哪个方向调。这就是下一节偏好学习的出发点——从「模仿正确答案」升级到「优化人类更偏好的方向」。

## 08S-12.2 RLHF（奖励模型 + PPO）

### 08S-12.2.1 RLHF 三阶段总览

基于人类反馈的强化学习（Reinforcement Learning from Human Feedback, RLHF）是把人类偏好转成学习信号的经典流水线，标准形态分三步：先做 SFT 得到初始策略，再用人类对成对回答的偏好训练一个奖励模型（reward model, RM），最后用强化学习（通常是 PPO）优化语言模型去最大化奖励模型给的分。

这条三步流水线由 InstructGPT（Ouyang et al. 2022, arXiv:2203.02155）系统化，也是 ChatGPT 早期对齐的基础。三步的分工是：SFT 让模型先会「像样地回答」，给强化学习一个不至于胡言乱语的起点；奖励模型把「人类觉得哪个回答更好」这种难以写成公式的偏好，压缩成一个能对任意回答打分的函数；强化学习则让模型在这个打分函数上「爬坡」，去生成得分更高的回答。为什么不直接用强化学习从零训？因为语言模型的动作空间是整个词表、序列极长，没有一个好的初始策略和一个稠密的奖励信号，RL 几乎无法起步——SFT 和奖励模型正是为 RL 铺好这两样东西。这一步整体复用 L6-03·03-10 的强化学习框架，此处只讲它落在语言模型上的具体形态。

### 08S-12.2.2 偏好数据与 Bradley-Terry 模型

RLHF 的原料是「成对偏好」数据：对同一个 prompt，让模型生成两个（或多个）回答，请人标注哪个更好，得到一批「胜者 y_w、败者 y_l」的对。把这种成对比较转成一个可训练的概率模型，最常用的是 Bradley-Terry 模型。

Bradley-Terry 假设每个回答有一个潜在「实力分」r，回答 y_w 被偏好于 y_l 的概率是两者分数经 sigmoid 的形式：

```
P(y_w ≻ y_l | x) = σ( r(x, y_w) − r(x, y_l) )
```

其中 σ 是 logistic sigmoid，r(x, y) 是给定 prompt x 时回答 y 的奖励（实力分）。直觉是：两个回答的分差越大，胜者被选中的概率越接近 1；分数相等时概率是 0.5（掷硬币）。为什么要用成对比较而不是让人直接给绝对分？因为人对「这个回答值几分」很难打得一致，但对「A 和 B 哪个更好」的判断稳定得多——成对比较把标注难度降到了最低，也天然契合 Bradley-Terry 这种只依赖分差的模型。这个概率模型是下一步训练奖励模型的理论地基：我们要找一个 r，使它在所有标注过的偏好对上，给胜者的分尽量高于败者。

### 08S-12.2.3 奖励模型训练

奖励模型是一个把（prompt, 回答）映射到一个标量分数的网络，通常在 SFT 模型基础上改造（把输出层换成一个输出单个标量的头）。它用上一节的成对偏好数据训练，损失就是让胜者得分高于败者的负对数似然。

由 Bradley-Terry 模型直接导出的奖励模型损失是：

```
L_RM = − E_{(x, y_w, y_l)} [ log σ( r_φ(x, y_w) − r_φ(x, y_l) ) ]
```

r_φ 是参数为 φ 的奖励模型。训练它就是最小化这个损失：每见到一对偏好，就推动模型把胜者的分抬高、败者的分压低，直到 σ(分差) 尽量接近 1。训好后，这个 r_φ 就成了一个「自动裁判」，能对训练中现场生成的任意新回答打分，从而给强化学习提供逐条的奖励信号——这正是它存在的意义：把有限的、离线的人类偏好，泛化成一个能在线打分的函数。要注意奖励模型只是人类偏好的近似，它本身会犯错、会有盲区，模型一旦学会钻它的空子，就会出现下面 08S-12.2.5 说的 reward hacking。

### 08S-12.2.4 PPO 微调 + KL 惩罚

第三步用强化学习让语言模型（策略）去生成能让奖励模型打高分的回答。最常用的算法是近端策略优化（Proximal Policy Optimization, PPO, Schulman et al. 2017, arXiv:1707.06347）。关键的一笔是：优化目标里除了奖励，还加了一个对参考模型（通常是 SFT 模型）的 KL 散度惩罚，防止模型为了刷分而跑得离原来太远。

RLHF 阶段实际最大化的目标可写成（奖励减去 KL 惩罚）：

```
max_θ  E_{x, y∼π_θ} [ r_φ(x, y) ] − β · KL( π_θ(·|x) ‖ π_ref(·|x) )
```

π_θ 是被训练的策略，π_ref 是冻结的参考模型（SFT 后的模型），β 控制 KL 惩罚强度。为什么必须加这个 KL 项？因为奖励模型不完美——如果放任模型只追求高奖励，它会漂向奖励模型的漏洞区（生成一些奖励模型误判为好、实则古怪或退化的文本），同时可能丢掉预训练/SFT 学到的语言能力和多样性。KL 惩罚像一根皮筋，把策略拴在参考模型附近：既允许它朝高奖励方向移动，又不许它跑太远。β 太小容易 reward hacking、输出退化；β 太大则学不动、对齐效果弱——这个权衡是 RLHF 调参的核心难点之一，具体取值随模型与实现而变（待核）。PPO 的「近端」是指它每步限制策略更新幅度（用裁剪的重要性比），避免一次更新走太猛导致训练崩溃，机制细节见 L6-03·03-10。

### 08S-12.2.5 奖励攻击与 RLHF 的不稳定性

奖励攻击（reward hacking，又称 reward over-optimization）指模型学会利用奖励模型的缺陷去刷高分，而并没有真正变得更好——比如生成冗长、堆砌讨好词、格式花哨但内容空洞的回答，只因奖励模型恰好偏爱这些表面特征。这是 RLHF 最典型也最棘手的失效模式。

根源在于奖励模型只是人类偏好的一个有限、有偏的代理：它在训练分布上学得不错，但模型在 RL 过程中会主动探索到它没见过、判断不准的区域，专挑它的软肋。一个经常被观察到的具体现象是「长度偏置」——奖励模型倾向给更长的回答打更高分，于是 RLHF 后的模型变得啰嗦。KL 惩罚（上一节）正是主要的缓解手段之一，但调不好就压不住。除了 reward hacking，RLHF 的工程复杂度也很高：要同时在显存里放策略、参考模型、奖励模型（有时还有 critic/价值网络），PPO 本身对超参敏感、训练不稳定、复现困难。正是这些痛点——多个模型的开销、PPO 的脆弱、reward hacking——催生了后面 08S-12.4 的 DPO 一族（想绕开显式 RL）和 08S-12.3 的 RLVR（想绕开会被攻击的奖励模型）。RLHF 整体标「最不稳定」：其最佳实践仍在快速变化，不作定论。

### 08S-12.2.6 RLAIF 与 Constitutional AI（用 AI 反馈替人类）

RLAIF（Reinforcement Learning from AI Feedback）指把 RLHF 里「由人来标注偏好」的环节，替换成「由另一个 AI 模型按给定原则来判断哪个回答更好」，从而大幅减少对人工标注的依赖。Constitutional AI（Bai et al. 2022, arXiv:2212.08073）是其代表性框架。

Constitutional AI 的核心是给模型一部「宪法」——一组自然语言写的原则（如「回答应无害、应解释拒绝的理由」）。它分两阶段：监督阶段让模型对自己的回答做自我批评和修订，再用修订后的回答微调自己；强化学习阶段（即 RLAIF）让模型根据宪法原则去判断成对回答哪个更好，用这些 AI 生成的偏好训练奖励模型，再照常做 RL。这样做的动机很直接：人类偏好标注昂贵、慢、且随标注员波动；用 AI 按明确成文的原则打分，能规模化、可复现，还能把「价值观」显式写进原则里而非隐含在标注员脑中。代价与风险是：AI 裁判本身可能有偏、可能被同源模型的共同盲区带偏，「AI 监督 AI 是否可靠」本身是活跃研究话题（未定型）。实践中 RLAIF 和人类反馈常混合使用，纯 AI 反馈能替代到什么程度尚无定论。

## 08S-12.3 RLVR / 可验证奖励（未定型）

### 08S-12.3.1 核心思想：用可验证信号替奖励模型

可验证奖励强化学习（Reinforcement Learning with Verifiable Rewards, RLVR）指在强化学习对齐里，把「学出来的奖励模型」换成「一个能自动判定对错的验证函数」——只要任务的答案可以被程序化地检查，就用这个检查结果（对给 1、错给 0，或类似的确定性信号）当奖励。这个术语由 Tülu 3（Lambert et al. 2024, arXiv:2411.15124）明确提出并推广。

RLVR 沿用 RLHF 的强化学习骨架，只替换了奖励来源这一环。它的出发点是 08S-12.2.5 的痛点：学出来的奖励模型会被攻击、会犯错、要额外训练和显存。但很多重要任务的「好坏」其实有客观标准——数学题的答案对不对可以核验，代码能不能通过测试用例可以运行检查，格式约束满不满足可以正则匹配。对这类任务，与其费劲训一个近似的奖励模型，不如直接用「标准答案/测试用例」给出精确、不可被表面特征糊弄的奖励。这样奖励信号本身就没有「漏洞」可钻（答案错就是错），从根上削弱了 reward hacking。RLVR 是 2024–2025 年最热的方向之一，随 DeepSeek-R1 爆发式扩散，仍在快速演进（未定型）。

### 08S-12.3.2 适用域与边界

RLVR 天然适用于「答案可被自动、客观核验」的任务：数学解题（对最终数值/表达式判等）、编程（跑单元测试）、形式化推理、以及可用规则检查的指令遵循（如「输出必须是 JSON」「必须恰好 100 字」）。对开放式、主观的任务（写作风格、共情、帮助性），它就不直接适用——那些仍要回到 RLHF/偏好学习。

这条边界很重要，是初学者容易忽略的：RLVR 的威力完全来自「有一个便宜可靠的验证器」。有验证器，奖励就精确无偏；没有验证器（比如「这篇故事写得好不好」），就没法用它。因此现实系统往往是分工的——用 RLVR 提升数学/代码/推理这类可验证能力，用 RLHF/DPO 处理无法验证的对齐目标（语气、安全、帮助性），两者互补而非互斥。还有一个微妙点：即使奖励可验证，模型仍可能钻「验证器本身的漏洞」——比如猜到答案格式而没真会推理、或利用测试用例覆盖不全蒙混过关，所以「可验证」削弱但并未完全消除 reward hacking。这些边界属活跃研究，结论未定型。

### 08S-12.3.3 GRPO：去 critic 的组相对优势

组相对策略优化（Group Relative Policy Optimization, GRPO, Shao et al. 2024, DeepSeekMath, arXiv:2402.03300）是一种为可验证奖励量身简化的强化学习算法，被 DeepSeek-R1 用来训练推理能力。相比 PPO，它最大的简化是去掉了 critic（价值网络），改用「同一 prompt 采样一组回答、组内比较」来估计优势。

对一个 prompt，GRPO 采样一组 G 个回答，各自拿到奖励 r_i，然后用组内奖励的均值和标准差把每个回答的奖励标准化，作为它的优势估计：

```
A_i = ( r_i − mean(r_1, …, r_G) ) / std(r_1, …, r_G)
```

也就是「比这组的平均好多少（以标准差为单位）」。为什么这么做？PPO 需要一个和策略同规模的价值网络来估计每一步的基线（用于降低策略梯度方差），这在大模型上意味着又要多放一个大网络、多一堆超参。GRPO 观察到：既然对同一 prompt 能采样很多条回答，那「这组回答的平均奖励」本身就是一个天然的基线，不必再训 critic——高于组均值的回答被鼓励，低于的被抑制。这就省掉了价值网络，显存和复杂度都降下来，特别契合 RLVR 场景（验证器给奖励又快又准，采样一组、判对错、组内比较即可）。GRPO 是当下热门方案，但其变体层出不穷（Dr. GRPO、DAPO 等对标准化项、裁剪等做调整），细节逐季演进，不作定论。

### 08S-12.3.4 R1-Zero 现象与局限

DeepSeek-R1（DeepSeek-AI 2025, arXiv:2501.12948）里的 R1-Zero 展示了一个引人注目的现象：不经过 SFT，直接在预训练模型上用 GRPO + 可验证奖励做大规模强化学习，模型能自发涌现出较长的推理链、自我检查、回溯等行为，数学/推理能力大幅提升。这被视为 RLVR 路线的一个标志性结果。

它的意义在于挑战了「必须先 SFT 再 RL」的固有流程——至少在可验证任务上，纯 RL 也能从预训练模型直接练出强推理。直觉上，可验证奖励提供了极其干净的信号（对就是对），模型在反复试错中被引导去发现「怎样思考更容易得到正确答案」，长推理链是这种优化的副产品。但要清醒看待局限：其一，这套做法目前主要在可验证域（数学、代码）见效，能否迁移到开放任务尚不清楚（未定型）；其二，R1-Zero 的原始输出存在可读性差、语言混杂等问题，完整的 R1 仍加了 SFT 冷启动和多阶段来修正；其三，reward hacking 在可验证域被削弱但未消失。整个 RLVR/推理模型方向是 2025 年最活跃的研究前沿之一，具体最优配方、能力边界、与 SFT/偏好学习的最佳组合都在快速变动，全部标「未定型」，本篇只记状态、不作定论。

## 08S-12.4 偏好优化（DPO 类）

### 08S-12.4.1 DPO 核心：把 RL 目标改写成分类损失

直接偏好优化（Direct Preference Optimization, DPO, Rafailov et al. 2023, arXiv:2305.18290）用一个关键的数学变换，把 RLHF 那个「训奖励模型 + 跑 PPO」的两阶段过程，合并成一个可以用普通监督学习（一个分类式损失）直接在偏好数据上优化的单阶段目标——不再需要显式训练奖励模型，也不需要在线强化学习。

DPO 的损失直接作用在成对偏好数据上，形式是：

```
L_DPO = − E_{(x, y_w, y_l)} [ log σ( β log (π_θ(y_w|x) / π_ref(y_w|x)) − β log (π_θ(y_l|x) / π_ref(y_l|x)) ) ]
```

π_θ 是被训练的策略，π_ref 是参考模型（SFT 模型），β 对应 KL 强度。它的洞见被论文一句话点破：「你的语言模型本身就是一个奖励模型。」推导上，RLHF 那个「最大化奖励 − KL 惩罚」的问题有一个闭式最优解，把这个解反解出来，会发现奖励可以用「策略相对参考模型的对数概率比」来表示——也就是 β log(π_θ/π_ref) 这一项，即所谓「隐式奖励」。把这个表达式代回 Bradley-Terry 偏好概率，奖励模型就消失了，只剩下策略本身。于是训练变成：直接调整策略，让它给胜者 y_w 的（隐式）奖励高于败者 y_l。这个损失看着就是个 logistic 回归/二分类损失，用标准反向传播即可优化，工程上比 PPO 简单太多——这是 DPO 迅速流行的主因。

### 08S-12.4.2 DPO 与 RLHF 的关系与取舍

DPO 并不是抛弃了 RLHF 的目标，而是用数学等价把同一个目标（带 KL 约束的偏好对齐）换了一种求解方式：RLHF 显式地「训奖励模型 → 在线采样 → PPO 爬坡」，DPO 则直接在固定的偏好数据集上做离线的监督式优化。

理解它们的取舍要抓住「在线 vs 离线」这条轴。RLHF 是在线的：训练中模型现场生成新回答、由奖励模型即时打分，因此能持续探索到当前策略的新行为并纠正。DPO 通常是离线的：它只在一批预先收集好的偏好对上训，模型不在训练中生成新样本。离线的好处是简单、稳定、便宜（没有采样循环、没有多个大模型同时驻留显存）；代价是它只能从已有数据学，若偏好数据覆盖不到模型后来会产生的行为，就纠正不了那部分——这被称为分布偏移问题。因此有大量工作在两者之间折中：迭代式/在线 DPO（边训边生成新偏好对再训）、或先 DPO 再补一轮在线 RL。「DPO 和在线 RLHF 到底谁更强」是这块最活跃的争论之一，不同论文在不同设置下结论相反，本篇不作定论（见 08S-12.4.4）。

### 08S-12.4.3 变体谱系：IPO / KTO / ORPO / SimPO

DPO 出现后衍生出一大批偏好优化变体，各自改动损失的某一环，构成一个仍在快速扩张的谱系（方案逐季演进）。常被并列提及的有 IPO、KTO、ORPO、SimPO 等。

几条主线可以帮初学者建立地图。其一是「怎么定义损失/避免 DPO 的某些假设」：IPO（Identity Preference Optimization, Azar et al. 2023, arXiv:2310.12036）用一个平方损失目标，绕开 DPO「把成对偏好当成点态奖励」的假设，据称对偏好数据里的确定性偏好更鲁棒。其二是「不需要成对数据」：KTO（Kahneman-Tversky Optimization, Ethayarajh et al. 2024, arXiv:2402.01306）借用前景理论，能从「单条回答好/不好」这种非成对的二元反馈学习，放宽了对偏好对的要求。其三是「去掉参考模型」以省显存/算力：ORPO（Odds Ratio Preference Optimization, Hong et al. 2024, arXiv:2403.07691）在 SFT 损失上加一个基于胜负回答几率比（odds ratio）的项，把 SFT 和偏好对齐合成一步、且不需要参考模型；SimPO（Meng et al. 2024, arXiv:2405.14734）用序列的平均对数概率当隐式奖励、并引入目标奖励间隔，同样去掉参考模型。这些变体各有适用场景与代价，谁在什么设置下更优随数据与任务变，没有统一赢家，本篇不排名。整个谱系逐季有新成员，具体性能对比数字未一手坐实者标「待核」。

### 08S-12.4.4 DPO vs 在线 RL 的争议

「离线的 DPO 一族」和「在线的 RLHF/RL」哪条路线更好，是本大主题当前最没有定论的问题之一。不同研究在不同模型规模、数据质量、任务类型下给出方向相反的结论，因此只能记录分歧、不能裁定。

支持 DPO 一侧的论据主要是简单、稳定、便宜、易复现，且在很多基准上能追平甚至超过 PPO 版 RLHF。支持在线 RL 一侧的论据是：在线采样让模型能探索并纠正自己当前的错误行为，理论上上限更高，尤其在偏好数据覆盖不足或需要持续对抗 reward hacking 时；一些工作报告在充分调优下在线 RL 仍优于离线 DPO。折中派（迭代 DPO、在线 DPO、DPO+RL 混合）则试图兼取两者之长。对初学者，正确的心态不是「记住谁赢」，而是理解这场争论背后的真实权衡轴——在线探索能力 vs 工程简单性、数据覆盖 vs 采样成本——以及它高度依赖具体设置。这块随论文时点快速变动，全部标「⚙演进快·随时变」，本篇不给定论。

## 08S-12.5 多模态接入

### 08S-12.5.1 基本范式：编码器 + 投影 + LLM

多模态接入指把视觉、音频等非文本模态「接」进一个已有的语言模型，让它能看图、听音后再用语言回答。主流范式是三段式：用一个预训练的模态编码器（如视觉用 CLIP 的 ViT）把图像/音频编码成特征向量，再用一个投影模块把这些特征映射到语言模型的词嵌入空间，然后当作「特殊 token」拼进 LLM 的输入序列。

这个设计的巧妙之处在于最大化复用：视觉编码器已经在海量图文上学会「看懂」图像，语言模型已经学会「说」和「推理」，缺的只是一座桥——把视觉特征翻译成 LLM 能听懂的「语言」。投影模块就是这座桥，它把一张图变成若干个和词嵌入同维度的向量，插进文本 token 序列里，之后对 LLM 而言，图像就和一段文字没本质区别，可以照常做注意力、照常生成回答。LLaVA（Liu et al. 2023, arXiv:2304.08485）是这一范式的代表：冻结的 CLIP 视觉编码器 + 一个可训练的投影层 + 一个 LLM（Vicuna）。这样接入不需要从零训一个多模态大模型，成本远低于联合从头预训练——这是它成为主流的关键原因。

### 08S-12.5.2 对齐训练的两阶段

多模态模型的训练通常也分两阶段，和纯文本的「预训练 + 指令微调」结构呼应：先做特征对齐的预训练（只训投影模块，让视觉特征和语言空间对上），再做多模态指令微调（用图文指令数据教模型按指令回答关于图的问题）。

第一阶段像是「教翻译官对词典」：冻住视觉编码器和 LLM，只训中间的投影层，用大量图文对（如图-caption）让投影出来的视觉 token 落到 LLM 认识的语义位置上。这一步只动少量参数，便宜且稳定。第二阶段是「教它听指令看图说话」：用图文指令数据（如「描述这张图」「图里有几个人」，回答常由更强模型如 GPT-4 生成）微调，此时可能同时放开投影层和 LLM（视觉编码器常仍冻结）。LLaVA 正是这么做的——先用一批图文对做特征对齐，再用一批 GPT-4 生成的多模态指令数据做指令微调。两阶段的分工和纯文本一脉相承：先对齐表示、再对齐行为。具体各阶段放开哪些参数、数据规模属实现选择，随模型而变（待核）。

### 08S-12.5.3 架构谱系：Flamingo / BLIP-2 / LLaVA

把模态接入 LLM 的「桥」有几种不同设计，构成一个谱系。三个常被并列的代表是 Flamingo、BLIP-2 和 LLaVA，区别主要在「桥」的形态和训练量。

Flamingo（Alayrac et al. 2022, arXiv:2204.14198）用「交叉注意力」把视觉特征注入冻结的语言模型——在 LLM 各层之间插入门控交叉注意力层，让文本 token 去「看」视觉特征，视觉信息不占用 LLM 的输入 token 位。BLIP-2（Li et al. 2023, arXiv:2301.12597）引入一个叫 Q-Former 的轻量查询 Transformer 当桥：用一组可学习的查询向量从冻结的视觉编码器里「问出」少量最相关的视觉特征，再喂给冻结的 LLM，桥小、两端都冻结、训练高效。LLaVA（arXiv:2304.08485）则走极简路线：桥就是一个线性层（后续版本用小 MLP），把视觉特征直接投影成 LLM 的输入 token。三者体现的取舍是「桥的复杂度 vs 训练成本 vs 灵活性」——交叉注意力表达力强但改动 LLM 结构、Q-Former 特征压缩得好但多一个组件、线性投影最简单但可能需要更多指令数据来补。哪种在什么规模下更好没有定论，本篇只陈列机制、不排名。多模态是快速演进领域，新架构不断出现（未定型项按当时时点重核）。

### 08S-12.5.4 与本课的边界：应用层归 X-GENAI

多模态接入到「把编码器对齐进 LM、让模型能看图听音」为止属于本课（训练后与对齐的系统机制）。再往上的应用层——检索增强生成（RAG）、智能体（agents）、提示工程（prompt engineering）——划归 X-GENAI 专课，本篇仅登记边界、不展开、不吞并。

划这条线的理由是关注点不同：本课关心的是「怎么训/怎么把一个模态接进模型」这类系统与训练机制；而 RAG、agents、prompt 工程关心的是「拿一个已经训好的（可能是多模态的）模型，怎么在应用里编排它去解决任务」——那是使用层而非训练层。举例说，「用 CLIP 编码器 + 投影层把视觉对齐进 LLM 再做视觉指令微调」是本课范畴；而「让一个多模态模型看着网页截图、检索文档、调用工具完成一个多步任务」则属应用层，归 X-GENAI。初学者容易把两者混在一起，这里明确：本篇到「多模态对齐」收尾，应用编排仅作指路、不深入。
