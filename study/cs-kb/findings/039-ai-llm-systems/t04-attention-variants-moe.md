标准全注意力（L6-03·03-6）的代价是随序列长度 n 平方增长的计算与显存。本大主题把「怎么把这个平方项压下去」的各条技术路线摆在一起：限制注意范围的稀疏注意力、用核技巧改写的线性注意力、干脆换掉注意力的状态空间模型，以及从「压计算量」转向「压激活参数量」的另一条正交路线——混合专家 MoE。它们各自解决的瓶颈不完全相同（有的压 O(n²) 计算、有的压 KV cache 显存、有的压每 token 激活参数），读的时候要分清各自针对的是哪一堵墙。

## 08S-4.1 稀疏 / 局部 / 滑窗注意力

### 08S-4.1.1 全注意力的 O(n²) 瓶颈（问题背景）

标准自注意力让序列里每个位置都去看其它所有位置，注意力分数矩阵是一个 n×n 的方阵（n 是序列长度）。因此计算量和存这张矩阵的显存都随 n 平方增长。

对每个 query，注意力要算它和全部 n 个 key 的相似度：

```
scores = Q @ K^T        # 形状 (n, n)，需要 O(n^2 · d) 次乘加
attn   = softmax(scores) @ V
```

这就是所有「效率注意力」要打的靶子。直觉上，序列翻倍，计算和显存要变 4 倍——当 n 从几千涨到几万、几十万时（长文档、长上下文、代码库级输入），这张 n×n 矩阵会先把显存撑爆，即使算得动也存不下。稀疏注意力的思路很朴素：既然不是每对位置都同等重要，那就只让每个位置看「一部分」位置，把稠密的 n×n 矩阵变成稀疏的，从而把复杂度从 O(n²) 降下来。这里要区分两堵不同的墙：稀疏/线性注意力压的是训练期与 prefill 期的 O(n²) 计算与显存；而下文 08S-4.1.5 的 MQA/GQA 压的是自回归解码期的 KV cache 显存带宽，是另一条正交的轴，别混为一谈。

### 08S-4.1.2 局部 / 滑窗注意力

滑窗注意力（sliding window attention, SWA）让每个位置只注意它前后固定宽度 w 的一个窗口内的位置，而不是整条序列。

如果窗口半径是 w，那么每个 query 只和大约 2w+1 个 key 交互，总计算量从 O(n²) 降到 O(n·w)。当 w 是一个远小于 n 的常数时，复杂度对 n 就是线性的。

这背后的直觉是语言里的依赖大多是局部的：一个词的含义主要由它附近的词决定。堆叠多层滑窗注意力后，感受野会随层数线性扩大——第 1 层看 ±w，第 2 层能间接看到 ±2w，就像卷积网络靠层数叠加扩大感受野一样，所以深层网络仍能捕捉到较远的依赖。易错点是：单层滑窗看不到窗口外的信息，需要靠「多层堆叠」或下面的「全局 token」来补长程依赖，不能指望一层就解决。滑窗是很多长上下文模型的骨架组件，Longformer 就以它为主干。

### 08S-4.1.3 全局 + 窗口 + 随机的组合（Longformer / BigBird）

纯滑窗丢掉了长程连接，实用系统通常在局部窗口之外再加少量「全局注意力」位置（这些位置能看到所有人、也被所有人看到），甚至加一点随机连接，用很小的额外代价补回全局信息流。Longformer（Beltagy et al. 2020, arXiv:2004.05150）= 滑窗 + 任务驱动的全局 token；BigBird（Zaheer et al. 2020, arXiv:2007.14062）= 滑窗 + 全局 token + 随机注意，两者都把复杂度降到 O(n)。

直觉上可以类比社交网络里的「小世界」结构：大多数人只认识身边的人（局部窗口），但只要有少数几个「枢纽」认识所有人（全局 token），加上一点随机的远距离连接，整个网络里任意两点之间的信息就能在很少的跳数内传到。BigBird 的作者进一步论证这种稀疏模式仍是序列函数的通用逼近器、且图灵完备，理论上保留了全注意力的表达力。要注意这些是「近似」全注意力：全局/随机 token 具体怎么选、放几个是任务相关的设计选择，不同实现差别很大；哪种稀疏模式在通用大模型上最优，属活跃研究、尚无定论（未定型）。

### 08S-4.1.4 固定 / 跨步稀疏模式（Sparse Transformers）

Sparse Transformers（Child et al. 2019, arXiv:1904.10509）用固定的稀疏因子分解模式（如「跨步 strided」和「固定 fixed」两种）代替稠密注意力，把复杂度降到 O(n·√n)。

注意这里是 O(n√n) 而不是 O(n)——它把一次全注意力拆成两次稀疏注意力（一次沿局部、一次沿跨步方向），两者组合起来覆盖全序列，代价是介于线性与平方之间。

直觉是把序列想成一个二维网格：一个 head 专门看「同一行内的邻居」（局部），另一个 head 看「不同行的同一列」（跨步、抓周期性/远距离结构），两类组合就能让信息在两步内从任意位置传到任意位置。这类固定模式的好处是稀疏结构是预先定死的、对硬件友好（可以写高效 kernel）；代价是模式是人工设计的、不随内容自适应。它是「稀疏注意力」这条线最早的代表作之一，后来的 Longformer/BigBird 可以看作在稀疏模式设计上的不同取舍。

### 08S-4.1.5 MQA / GQA：压 KV cache 的注意力变体（另一条轴）

多查询注意力（Multi-Query Attention, MQA；Shazeer 2019, arXiv:1911.02150）让所有 query head 共享同一份 key/value 投影；分组查询注意力（Grouped-Query Attention, GQA；Ainslie et al. 2023, arXiv:2305.13245）折中——把 query head 分成若干组，每组共享一份 key/value。

标准多头注意力（MHA）里每个 head 都有自己独立的 K、V。设 head 数为 h：MHA 有 h 组 KV，MQA 只有 1 组 KV，GQA 有 g 组（1 < g < h）。三者可以看成同一根轴上的三个点：

```
MHA : h 组 KV   ── 质量最好、KV cache 最大
GQA : g 组 KV   ── 折中（1 < g < h）
MQA : 1 组 KV   ── KV cache 最小、可能掉质量
```

这一项和前面的稀疏/线性注意力压的不是同一堵墙。自回归解码时要缓存历史所有位置的 K、V（KV cache，见 08S-9），逐 token 解码是访存受限（memory-bound）的，瓶颈在于每步都要把整个 KV cache 从显存读进来。MQA 把 KV head 从 h 份压到 1 份，KV cache 直接缩小到约 1/h，解码时要搬运的数据量大幅下降，因此解码更快。代价是共享 KV 可能损失一点质量，GQA 就是为了把这点质量找回来——用 g 组 KV 取得「接近 MHA 的质量 + 接近 MQA 的速度」。Shazeer 最初的洞见正是：现代加速器上，增量解码的瓶颈是加载 KV cache 的内存带宽，而不是算力。GQA 已被许多开源大模型采用为默认，但 g 取多少是随模型而定的工程选择，不作定论。

## 08S-4.2 线性注意力

### 08S-4.2.1 核化改写：去掉 softmax 换特征映射 φ

线性注意力的核心手法是把 softmax 换成一个可分解的核（kernel）：用一个特征映射 φ 把 Q、K 各自变换一下，用 φ(Q) 和 φ(K) 的内积来近似原来 softmax(QKᵀ) 的作用。

标准注意力对第 i 个位置的输出可写成对所有 j 的加权和，权重是 exp(qᵢ·kⱼ)：

```
标准:  outᵢ = Σⱼ [ exp(qᵢ·kⱼ) / Σⱼ' exp(qᵢ·kⱼ') ] · vⱼ
线性:  outᵢ = Σⱼ [ φ(qᵢ)·φ(kⱼ) / Σⱼ' φ(qᵢ)·φ(kⱼ') ] · vⱼ
```

softmax 里的 exp(qᵢ·kⱼ) 是「先算内积再取指数」，这个非线性没法拆开，逼得你必须先把整张 n×n 分数矩阵算出来。而 φ(qᵢ)·φ(kⱼ) 是两个向量的内积，是「可分解」的——φ(q) 和 φ(k) 各自独立算，这就为下一步换序创造了条件。φ 的选择有多种：Katharopoulos et al. 2020（「Transformers are RNNs」, PMLR 119）用简单的 φ(x)=elu(x)+1 这类固定正映射；Performer 用随机特征去逼近真正的 softmax 核（见 08S-4.2.4）。

### 08S-4.2.2 结合律换序把 O(n²)→O(n)

一旦分数是内积形式，就能用矩阵乘法的结合律改变计算顺序：不先算 φ(Q)φ(K)ᵀ（会得到 n×n），而是先算 φ(K)ᵀV，把它变成一个 d×d 的小矩阵，再让 φ(Q) 去乘它。

```
避免:  (φ(Q) φ(K)^T) V        # 中间量 n×n，O(n^2 d)
改成:  φ(Q) (φ(K)^T V)        # 中间量 d×d，O(n d^2)
```

当特征维度 d 远小于序列长度 n 时，O(n·d²) 就是关于 n 的线性复杂度——这是线性注意力名字的由来。直觉是：φ(K)ᵀV 把「所有历史 key-value 对」压缩成了一个固定大小 d×d 的「摘要矩阵」，跟序列多长无关；每个 query 只要去查这个固定大小的摘要，不用再和每个历史位置逐一交互。易错点：这个换序只在去掉 softmax 之后才成立，标准 softmax 注意力做不到，因为 exp 不能拆进内积里。

### 08S-4.2.3 因果 / 自回归的递推（RNN 视角）

在因果（自回归）设定下，线性注意力可以写成一个随时间步递推的状态更新——这正是「Transformers are RNNs」标题的含义：线性注意力本质上是一个带矩阵状态的 RNN。

维护一个累积状态 S（d×d 矩阵）和归一化项 z，每来一个新 token 就增量更新：

```
Sₜ = Sₜ₋₁ + φ(kₜ) vₜ^T
zₜ = zₜ₋₁ + φ(kₜ)
outₜ = φ(qₜ)^T Sₜ / (φ(qₜ)^T zₜ)
```

这意味着自回归生成时不需要保存越来越长的 KV cache，只需保存一个固定大小的状态 Sₜ，每步是常数时间、常数显存。对比标准注意力解码时 KV cache 随生成长度线性增长，这是线性注意力最诱人的地方。作者也正是靠这个递推形式，在超长序列的自回归生成上报告了数量级的加速（具体倍数随设置而变，标「待核」）。这个「固定大小状态 + 增量更新」的思路，也正是下一节状态空间模型的共同点。

### 08S-4.2.4 随机特征近似 softmax（Performer）

Performer（Choromanski et al. 2020/2021, arXiv:2009.14794）用一种叫 FAVOR+ 的方法，通过随机正交特征来无偏地逼近真正的 softmax 注意力核，而不是换成一个完全不同的核。

前面 Katharopoulos 的做法是直接用一个简单 φ 换掉 softmax（改变了模型），Performer 则想「保住 softmax 的行为、只是用线性成本算出来」。它构造一组随机特征映射，使得 φ(q)·φ(k) 在期望意义上等于 exp(q·k)，从而既拿到线性复杂度、又逼近原始 softmax 注意力，且论文给出可证明的逼近精度。直觉上像蒙特卡洛：用一批随机投影去估计一个本来要精确算的量，特征数越多估得越准。代价是它是「近似」，随机特征数少了会有估计噪声。Performer 不依赖稀疏或低秩先验，这是它区别于稀疏注意力的地方。

### 08S-4.2.5 代价：近似误差与检索能力下降

线性注意力虽然拿到了 O(n) 复杂度，但把「摘要成固定大小状态」是有信息损失的，尤其在需要精确长程检索（从很远处精确调出某个具体 token）的任务上，质量往往不如全注意力。

这是线性注意力至今没有全面取代 softmax 注意力的关键原因。直觉：全注意力保留了每一对位置的精确交互，而线性注意力把所有历史压进一个固定 d×d 的状态里，容量有限——当你要「大海捞针」式地精确回忆很久以前的某个细节时，固定大小的状态就成了信息瓶颈。这类「哪种线性/次二次注意力能既省又不掉检索能力」是当前非常活跃的研究方向，各种改进（门控、增量、更好的特征映射等）层出不穷，尚无公认赢家（未定型）。因此实践中线性注意力更多出现在对长序列吞吐敏感、且不强依赖精确长程检索的场景，或与全注意力混合使用。

## 08S-4.3 状态空间模型（Mamba 类）

### 08S-4.3.1 SSM 基本形式（连续 → 离散）

状态空间模型（SSM）源自控制理论：用一个隐藏状态 h 随时间演化来建模序列，输入 x 驱动状态、状态再产生输出 y。它天生是序列模型，且可以做到随序列长度线性扩展。

连续时间的 SSM 由一组线性常微分方程刻画，离散化后（用步长 Δ）变成一个可在序列上跑的递推：

```
连续:  h'(t) = A h(t) + B x(t) ,   y(t) = C h(t)
离散:  hₜ = Ā hₜ₋₁ + B̄ xₜ ,       yₜ = C hₜ
```

直觉上这和 RNN 很像——都是「用一个隐藏状态承载历史、逐步更新」。区别在于经典 SSM 的转移是线性的、且参数（A、B、C）不随输入变化，这带来了一个巨大好处：整个序列的输出可以等价地写成一次卷积，从而在训练时并行计算（不像 RNN 必须逐步串行）。这就是 SSM 「训练像卷积能并行、推理像 RNN 状态固定」双视角的来源。A 的结构化设计（如何初始化、如何保证能记住长程信息）是这条线的技术核心。

### 08S-4.3.2 S4：结构化 SSM 与卷积 / 递推双视角

S4（Structured State Space，Gu, Goel, Ré 2021, arXiv:2111.00396）给 SSM 的状态矩阵 A 设计了一种特殊（结构化）的参数化，使它既能高效计算、又能在超长序列上保住长程记忆，在长序列基准上取得了强结果。

S4 的贡献是把「SSM 理论上能线性建模长序列」变成「实际能高效算、且真的记得住」。它利用特定结构的 A 矩阵（基于 HiPPO 理论，让状态成为对历史的最优压缩），并把训练期的计算转化为可并行的卷积核。直觉：S4 相当于给模型一套「怎么把无限长历史压进固定大小状态而尽量不丢信息」的数学配方。S4 报告在生成上比 Transformer 快得多（论文称约 60×，随设置而变，标「待核」）且大幅缩小长序列建模差距。它是 Mamba 的直接前身，但有个关键局限——参数不随输入变，见下一节。

### 08S-4.3.3 选择性 SSM（S6 / Mamba）：输入相关参数

Mamba（Gu & Dao 2023, arXiv:2312.00752）在 S4 基础上引入「选择性」机制（称 S6）：让 SSM 的参数（B、C、Δ）随输入变化，从而模型能根据内容选择性地记住或忘记信息。

S4 的 A、B、C 是固定的（对每个位置一视同仁），这让它没法做「基于内容的推理」——比如根据当前 token 决定该不该把某段信息存进状态。Mamba 把 B、C、Δ 变成输入 xₜ 的函数：

```
Bₜ, Cₜ, Δₜ = f(xₜ)      # 参数随输入 token 变化（选择性）
hₜ = Āₜ hₜ₋₁ + B̄ₜ xₜ ,   yₜ = Cₜ hₜ
```

这一步让模型能「看情况」调整状态更新——重要的信息多记、无关的跳过，类似注意力「按内容加权」的能力，但仍保持随序列线性、且推理时状态固定大小。代价是：一旦参数随输入变，就不能再写成一次固定卷积了（卷积核依赖内容），失去了 S4 的并行卷积捷径。Mamba 用一个硬件感知的并行扫描算法把这个损失补回来（见下节）。Mamba 报告吞吐约为同规模 Transformer 的数倍（论文称约 5×，随设置而变，标「待核」）。

### 08S-4.3.4 硬件感知的并行扫描

因为选择性 SSM 不能再用卷积并行，Mamba 改用「并行前缀扫描」（parallel scan）算法在 GPU 上并行地算这个递推，并且做了访存优化：只在 GPU 内快而小的 SRAM 里展开扩张后的状态，避免把大中间量反复写回慢而大的 HBM。

递推 hₜ = Āₜhₜ₋₁ + B̄ₜxₜ 表面看是串行的（每步依赖上一步），但它是一种可结合的运算，能用扫描算法在 O(log n) 的并行深度内算完，就像把「逐个累加」改成「两两合并的树形累加」。这一步是纯工程但至关重要——没有它，选择性 SSM 会因为丢了卷积并行而训练很慢。Mamba 明确说这套设计是「FlashAttention 精神」的延续：核心瓶颈是显存层次间的搬运，优化点在于减少 HBM 读写、把中间状态留在 SRAM（呼应 08S-5 内存层次、08S-6 IO 感知 kernel）。

### 08S-4.3.5 与注意力的关系与状态

SSM 类模型（Mamba 及其后续）被视为注意力的一条「非注意力」替代路线：它们抛弃了 n×n 注意力矩阵，用固定大小的循环状态换取随序列长度线性的计算与常数的推理显存。但它们是否能在所有任务上匹敌注意力、尤其是精确长程检索类任务，仍无定论。

线性注意力、SSM 其实共享同一个骨架——「固定大小状态 + 增量更新」，学界越来越把它们放在统一框架下比较。SSM 的短板和线性注意力类似：固定大小状态在「精确回忆很久以前某个具体 token」这类任务上弱于全注意力。因此一个活跃方向是「混合架构」——大部分层用 Mamba/SSM 省算力，少数层插入全注意力补检索能力。这一整片（纯 SSM vs 混合 vs 改进注意力）是当前最热、翻新最快的研究区，本篇只登记机制与状态，绝不排名、不下定论（未定型）。

## 08S-4.4 混合专家 MoE

### 08S-4.4.1 稀疏激活的基本思想（解耦参数量与计算量）

混合专家（Mixture of Experts, MoE）把 Transformer 里的前馈层（FFN）换成许多个并列的 FFN「专家」，每个 token 只被路由到其中少数几个专家去计算。这样模型总参数量可以做得很大，但每个 token 实际激活（参与计算）的参数只有一小部分——把「模型容量」和「单 token 计算量」解耦开。

前面几节都在压 O(n²) 计算，MoE 走的是完全正交的另一条路：它不动注意力，而是让 FFN 变「稀疏激活」。直觉：与其让每个 token 都过一个巨大的稠密 FFN，不如养一批各有专长的小 FFN，每个 token 只找最合适的一两个去处理。这样参数总量（=知识容量）可以随专家数线性扩，但每 token 的计算量（=FLOP）几乎不变。典型例子 Mixtral 8x7B（见下）总参数约 46.7B，但每 token 只激活约 12.9B。关键收益是：在「每 token 计算预算」固定时，MoE 能塞进远多于稠密模型的参数/知识。代价是总显存要装下所有专家（哪怕大多数时候不激活），以及路由和跨设备通信的复杂度。

### 08S-4.4.2 门控路由与 top-k（Shazeer 2017）

稀疏门控 MoE（Shazeer et al. 2017, arXiv:1701.06538「Outrageously Large Neural Networks」）用一个可学习的门控网络（router）给每个 token 打分，选出得分最高的 top-k 个专家，只让这几个专家参与计算，输出按门控权重加权求和。

门控通常是一个小线性层 + softmax，对第 t 个 token：

```
g = softmax(W_router · xₜ)          # 每个专家一个分数
选出 top-k 个专家 E, 权重 gₑ
outₜ = Σ_{e∈top-k} gₑ · FFNₑ(xₜ)
```

直觉是「让模型自己学会派活」：router 学着把某类 token（比如代码、比如某种语言）送给擅长它的专家。为什么必须是稀疏 top-k 而不是全用？因为只有稀疏才省计算——若每个 token 都过所有专家就退化成稠密大模型、没有省 FLOP 的意义。易错点/难点：top-k 里那个「选出最高的 k 个」是离散操作、不可导，router 只能通过被选中专家的加权输出间接学到梯度；而且天然会出现「马太效应」——少数专家被选爆、其它专家饿死，这就引出了下面的负载均衡问题。

### 08S-4.4.3 Switch（top-1）与 Mixtral（top-2）

Switch Transformer（Fedus et al. 2022, arXiv:2101.03961）把路由简化到极致——每个 token 只选 top-1 个专家；Mixtral 8x7B（Mistral AI 2024, arXiv:2401.04088）用 8 个专家、每 token 选 top-2。

k 取多少是核心设计旋钮。Switch 论证 top-1 已足够、且最省：每 token 只过一个专家，通信和计算最少，作者据此把模型扩到极大参数量。Mixtral 是解码器-only 的稀疏 MoE，32 层、每层 8 个专家替换 FFN，router 每 token 选 2 个专家。直觉上 k 越大越接近稠密（质量可能更稳、但更费算力和通信），k 越小越省（但对路由质量更敏感）。这里必须强调：Switch 的 top-1 与 Mixtral 的 top-2 是不同设计点、各有取舍，本篇不裁定谁更优（未定型；k 的最优值随规模/任务/系统约束而变）。

### 08S-4.4.4 负载均衡：辅助损失

因为 router 会倾向于反复选少数几个专家，导致负载不均（有的专家过载、有的闲置），经典做法是在训练损失里加一个辅助的负载均衡损失（load balancing auxiliary loss），鼓励 token 尽量均匀地分到各专家。

负载不均有两个坏处：一是浪费——闲置专家的参数白占显存却学不到东西；二是在多设备部署时（每个专家常放在不同 GPU 上）过载专家会成为吞吐瓶颈，拖慢整体。Shazeer 2017 最初用了两个辅助损失（一个鼓励各专家「重要性」均衡、一个鼓励「负载」均衡）；Switch 把它简化成一个可微的负载均衡损失。这个损失通常构造成「专家被选中的比例」和「router 分给它的平均概率」的乘积和，当分配越均匀时越小。易错点：辅助损失是加在主任务损失之外的一个正则项，权重要调——太小压不住不均衡，太大会干扰主任务、拖累模型质量，这个副作用正是下面「无辅助损失」方案想避开的。

### 08S-4.4.5 容量因子与 token 丢弃

实现上，每个专家有一个固定的「容量」（一个 batch 里它最多处理多少 token），由容量因子（capacity factor）控制；超出容量的 token 会被「丢弃」（不经该专家、通常靠残差直连跳过）。

为什么要设容量上限？因为在硬件上要把张量做成规整的固定形状才能高效并行——不能让某个专家这一批处理 3 个 token、下一批处理 3000 个。容量因子就是给「平均每专家应得的 token 数」乘上的一个余量系数：

```
每专家容量 ≈ capacity_factor · (batch 内 token 总数 / 专家数)
```

容量因子 > 1 留出缓冲以容纳分配不均，代价是显存和计算的浪费；容量因子太小则会丢弃更多 token，损失信息。这是一个吞吐-质量的权衡旋钮。易错点：token 被丢弃不等于报错，模型靠残差连接让被丢的 token 直接跳过该 MoE 层，训练仍能进行，但丢太多会掉质量。具体容量因子取值随实现/框架而变，标「待核」。

### 08S-4.4.6 无辅助损失负载均衡（DeepSeek 偏置法）

一条较新的路线是不用辅助损失来均衡负载，而是给每个专家的路由分数加一个可调的偏置项，根据近期各专家的负载动态调整这个偏置，把 token 往欠载的专家轻推——从而在不往训练里注入额外梯度的前提下实现均衡。

DeepSeek 提出的无辅助损失负载均衡（auxiliary-loss-free load balancing；arXiv:2408.15664，并用于 DeepSeek-V3 技术报告 arXiv:2412.19437）给每个专家维护一个偏置 bₑ，只用它来影响「选哪些专家」的排序，但不参与最终输出权重的计算：

```
选择时用:  score'ₑ = gₑ + bₑ      # 偏置只改路由排序
过载专家:  bₑ ← bₑ - γ            # 下调，少接 token
欠载专家:  bₑ ← bₑ + γ            # 上调，多接 token
```

传统辅助损失会在训练里额外引入梯度，为了均衡而干扰主任务、可能损害模型质量。偏置法把「均衡」这件事从梯度里剥离出来，做成一个每步常数时间的启发式调整，因此不干扰主任务梯度。DeepSeek 报告这样既能更好均衡、又能拿到更好的模型质量。这是活跃演进中的方案（未定型）；偏置更新速度 γ 等超参随实现而变，标「待核」。

### 08S-4.4.7 共享专家 / 细粒度专家（DeepSeekMoE）

另一种结构上的变体是把专家分成两类：少数「共享专家」（shared experts，对每个 token 都激活、承载通用知识），和多数「路由专家」（routed experts，仍走 top-k 稀疏选择、承载专门知识）；同时把专家切得更细粒度（更多、更小的专家）。

Mixtral 式的标准 MoE 里所有专家都受 router 的 top-k 支配；DeepSeekMoE 式结构则让共享专家绕过路由、始终参与，只对路由专家做稀疏选择。直觉：通用能力（每个 token 都用得上的基础知识）没必要每次都靠路由去抢，干脆固定几个专家常驻；把稀疏预算省下来留给专门化的路由专家，并通过「更多更小的专家」让每个专家的专长更聚焦、组合更灵活。这是对 08S-4.4.1 基本 MoE 的结构改良，属活跃设计空间（未定型），共享/路由专家的具体数目配比随模型而变，标「待核」。

### 08S-4.4.8 专家并行与系统开销

MoE 在多卡部署时通常把不同专家放到不同 GPU 上（专家并行, expert parallelism）；于是每个 token 被路由到哪个专家，就意味着要把它的激活「发送」到对应 GPU、算完再「收回」，这带来大量 all-to-all 通信开销。

这解释了为什么 MoE 虽然省 FLOP，却不是免费的午餐：省下的计算可能被通信吃掉一部分，而且负载不均会让某些 GPU 空等（呼应 08S-4.4.4 为何要均衡、08S-7 并行策略）。直觉：MoE 把「计算问题」部分转化成了「通信与调度问题」——token 在设备间搬运的 all-to-all、专家负载是否均匀、容量是否够，共同决定实际吞吐。因此 MoE 的收益高度依赖系统实现（通信-计算重叠、路由效率、均衡质量），具体加速比/通信量随集群与框架差异极大，一律标「待核」，本篇不给基准数字、不排名框架。
