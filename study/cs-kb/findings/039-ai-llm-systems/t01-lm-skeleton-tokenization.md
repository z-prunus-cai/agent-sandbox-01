这份报告回答一个很具体的问题：不用现成的大框架黑盒，怎么从最底层把一个语言模型（LM）从零"跑起来"。它由四步串成一条最小可用的流水线——先把文本变成整数（分词），再把整数喂给 Transformer 算出下一个词的概率（前向），再用数据反复调参数（训练循环），最后让训好的模型自己吐字（采样解码）。Transformer 内部结构本身在 03-6 已讲透，这里当既定物拼装，重点在"系统骨架"而非"建模机制"。

## 08S-1.1 BPE 分词

### 分词在整条流水线里的位置

分词（tokenization）是把原始文本字符串切成一串离散单元、再把每个单元映射成一个整数 ID 的过程；这串整数才是模型真正读到的输入。它是 LM 流水线的第一道关，也是唯一直接接触"人类可读文本"的一环——之后所有环节看到的都只是整数张量。

模型本身不认识字母或汉字，它只认识"词表（vocabulary）"里第 0 号到第 V-1 号这些整数。分词器（tokenizer）就是文本与整数之间的双向翻译词典，必须能 encode（文本→整数）也能 decode（整数→文本），且理想情况下 decode(encode(x)) == x（无损可逆）。分词器是独立于模型单独"训练"出来的，训练语料决定了它把哪些字符片段当成一个 token；一旦定死，模型训练和推理全程都用同一套，中途不能换。

CS336 L1 把这一步放在整门课最前面，正是因为词表大小 V 直接决定了模型嵌入层和输出层的规模，也决定了同一段文本被压成多长的整数序列——这两点会一路影响后面每一章的显存和算力账。

### 粒度谱系：字符级 / 字节级 / 词级 / 子词级

给定一段文本，切分粒度有几种极端选择，各有硬伤，BPE 是对这些极端的折中。

字符级把每个字符当一个 token，词表极小（几十到几千），永远不会遇到"没见过的词"，但序列变得极长（一个英文单词就是好几个 token），模型要在很长的距离上才能建立语义关联，效率低。

词级（word-level）以空格或分词规则切成整词，序列短、语义单元完整，但词表会爆炸（自然语言的词是开放集合），而且一定会遇到训练时没见过的词，只能塞给一个 `<unk>`（unknown）占位符，信息就丢了。

字节级（byte-level）把文本先编码成 UTF-8 字节流，每个字节（0–255）是一个基本单元，词表基座恰好 256 个，任何语言、任何符号、任何 emoji 都能表示，永不 `<unk>`，代价同样是序列偏长。

子词级（subword）是主流折中：常见词保持成一个 token，罕见词拆成若干有意义的片段（如 "encoding" → "encod" + "ing"）。BPE 属于子词级，兼顾了"词表可控"与"永不 unk"（尤其字节级 BPE）。CS336 L1 明确把 BPE 讲成"从字节起步、逐步合并"的子词方案。

### BPE 合并训练算法

BPE（Byte-Pair Encoding）的训练是一个纯统计的贪心过程：从最细粒度单元（字符或字节）出发，反复找出当前语料里出现频率最高的相邻单元对（pair），把它合并成一个新单元，记录这条合并规则，直到词表达到预设大小。

一次训练的骨架是：

```
初始化：把每个词切成基本单元序列（字节/字符），并记录词频
重复 直到 词表大小达到目标 V：
    统计所有相邻 pair 在语料中的总出现次数
    选出出现次数最高的 pair (a, b)
    把语料中所有 (a, b) 合并成新符号 ab
    把合并规则 (a, b) -> ab 追加到"合并表"（有序）
```

关键点在于合并表是有序的——第 k 条规则依赖前 k-1 条已经合并出的中间符号。词表最终大小 = 基座符号数 + 合并次数（+ 特殊 token）。所以你想要多大的词表，就做多少次合并。

用一份玩具语料本机跑通可以直观看到这个过程。对 `"low low low low low lower lower newest newest widest widest widest"`（把字符当基本单元、词尾加 `</w>` 标记），numpy/collections 实现的 BPE 前 4 条合并规则真实输出为：

```
第1条  ('l','o')  出现 7 次  -> lo
第2条  ('lo','w') 出现 7 次  -> low
第3条  ('low','</w>') 出现 5 次 -> low</w>
第4条  ('e','s')  出现 5 次  -> es
```

可以看到 "low" 因为反复出现被优先合并成一个整块，而低频组合留在细粒度——这正是 BPE"高频成块、低频留碎"的直觉。

BPE 合并的是"频率最高的对"，不是"最长的词"；它完全数据驱动，没有任何语言学规则，所以切出来的片段常常不符合人的直觉（如把 "ing" 单切出来）。这不是 bug，而是它靠统计规律让模型反复见到同一片段、从而更好泛化的机制。

### 编码（encode）：用合并表切新文本

训练得到的产物有两个：一个把符号映射到整数 ID 的词表，一个有序的合并表。encode 一段新文本时，先把它拆成基本单元，然后按合并表的顺序逐条尝试应用合并（贪心地把能合并的相邻对合起来），直到没有规则可用，最后查词表得到整数序列。

沿用上面的玩具合并表，对训练时没出现过的新词 `"lowest"` 做 encode，本机真实输出为：

```
['low', 'es', 't', '</w>']
```

"low" 和 "es" 是训练学到的块，"t" 没能进一步合并就留成单字符——这演示了 BPE 对未见词的优雅降级：不 unk，而是拆成已知片段的组合。

合并必须严格按训练时的规则顺序应用，顺序错了切分结果就变了；这也是为什么分词器文件要同时保存词表和有序合并表，两者缺一不可。

### 解码（decode）：整数还原文本

decode 是 encode 的逆：把整数序列查词表还原成符号片段，再把片段拼接起来。字符/子词级下拼接需要处理词边界标记（如 `</w>` 或 GPT-2 用来表示空格的特殊字符）；字节级下则是把 token 对应的字节拼回字节流、再按 UTF-8 解码成字符串。

单个 token 在字节级 BPE 下可能只对应"半个多字节字符"（比如一个中文字是 3 个 UTF-8 字节，可能被切在两个 token 里）。所以逐 token 解码再拼字符串可能中途出现无法解码的字节片段，正确做法是先把所有 token 的字节拼全、最后统一按 UTF-8 解码。这也是流式输出时"中文/emoji 偶尔要等下一个 token 才显示"的原因。

### 字节级 BPE（GPT-2 路线）

GPT-2（Radford et al. 2019）把 BPE 建立在 UTF-8 字节之上，而不是 Unicode 字符之上：基座固定 256 个字节，再在其上做合并。好处是任何输入都能表示、永远不需要 `<unk>`，且对任何语言脚本天然通用（script-agnostic）。

GPT-2 分词器的词表大小是 50257，其构成是 256 个字节基座 + 50000 次合并产生的新 token + 1 个特殊 token `<|endoftext|>`（多来源一致确认此拆分）。

一个实现细节：GPT-2 在真正 BPE 之前，先把 256 个原始字节双射到一批"可打印 Unicode 字符"上（避免控制字符/空格在处理中出问题），BPE 在这套可打印表示上进行，decode 时再映射回字节。初学者不必背这套映射，但要知道"字节级"不等于"直接对生字节做合并"，中间有一层可打印化处理。CS336 L1 与 HuggingFace tokenizers 文档对这一路线的描述一致。

### 正则预分词（pre-tokenization）

现代 BPE 实现在合并前通常先用一个正则表达式把文本粗切成块（如按空格、标点、数字分组），BPE 只在每个块内部做合并、绝不跨块合并。这一步叫预分词。

它的作用是防止合并出跨越语义边界的怪异 token（例如把 "dog." 里的 "g." 合成一个 token），也让"词 + 前导空格"成为常见 token 形态。OpenAI 的 tiktoken 就为每套编码定义了一个正则 `pat_str` 做预分词；不同编码用不同正则。初学者理解到"预分词=先划好不许跨越的栅栏，再在栅栏内合并"即可。

### 特殊 token

除了从语料学来的普通 token，分词器还会保留少数人为定义的特殊 token，最常见的是文档结束符（GPT-2 的 `<|endoftext|>`）。它们不参与 BPE 合并，而是直接占据固定 ID，用来标记序列边界、拼接多篇文档、或（在后续对齐阶段）标记对话角色。

特殊 token 必须在切分时被"整体识别"，绝不能被 BPE 拆开；实现上通常在预分词阶段就把它们从文本里抠出来单独处理。数量和含义随模型/训练阶段变化，具体某模型用了哪些属「待核」，要查该模型的分词器配置。

### 词表大小的系统权衡

词表大小 V 是一个要在训练前定死的关键超参，它同时牵动两笔账：V 越大，同一段文本被压得越短（序列更短、算注意力更省），但嵌入矩阵和输出投影矩阵（都是 V × d 量级）越大、越占显存，且极罕见 token 训练不充分。V 越小则相反。

这就是为什么主流词表落在几万到二十万的区间：GPT-2 用 50257，OpenAI 后续 tiktoken 的 cl100k_base 约 10 万、o200k_base 约 20 万（GPT-4o 系用）。这些具体数字随模型代际演进（⚙演进快），不构成"应该用多少"的定论——CS336 L1 把词表大小讲成一个需要按语料和预算权衡的旋钮，而非固定答案。

## 08S-1.2 Transformer 前向组装

### 从 token 序列到 logits 的整体数据流

前向组装就是把 03-6 已讲清的 Transformer 块拼成一个能算"下一个 token 概率"的解码器（decoder-only）语言模型。整体数据流是：一批整数 token → 查嵌入表变成向量 → 加位置信息 → 过 N 个相同结构的 Transformer 块 → 最终归一化 → 线性投影回词表维度，得到每个位置对下一个 token 的打分（logits）。

把它想成一条装配线：分词把文本变成"零件编号序列"，嵌入层按编号取出"零件的向量画像"，Transformer 块层层加工让每个位置吸收上下文信息，最后 LM head 把加工后的向量翻译成"下一个零件是词表中每个候选的可能性"。本篇不重讲注意力内部（那在 03-6），只讲怎么把块拼成完整 LM。

CS336 作业 1 要求学生亲手实现的正是这套 decoder-only 骨架，与 nanoGPT 的 `model.py` 结构一致。

### 输入嵌入与形状约定

第一层是嵌入（embedding）：一个形状为 V × d 的可学习矩阵（V 是词表大小，d 是隐藏维/模型维度），把每个整数 token 查成一个 d 维向量。一批数据的张量形状约定通常是 (B, T)（B=批大小 batch，T=序列长度），经嵌入后变成 (B, T, d)，之后一路保持 (B, T, d) 直到最后一层。

嵌入表就是"每个 token 一行的可训练查找表"，训练会让语义相近的 token 学到相近的向量。形状 (B, T, d) 会贯穿全模型，记住它能帮你读懂后面每一步在对哪个维度操作——注意力在 T 维上做交互，FFN 和 LayerNorm 在 d 维上做变换。

### 位置信息注入

自注意力本身对 token 顺序是"无感"的（打乱输入顺序，注意力的计算是对称的），所以必须显式告诉模型每个 token 的位置。做法是给嵌入向量叠加位置信息：原始 Transformer 用固定的正弦位置编码，GPT-2 类用可学习的位置嵌入表，更现代的做法（RoPE/ALiBi）把位置信息注入到注意力内部——后者是 08S-3 的内容，这里只需知道"必须有一处注入位置"。

初学者常以为注意力"自然知道"顺序，其实不然；忘了加位置信息，模型会把句子当成一个无序词袋。具体用哪种位置方案属架构选择（⚙演进快），本节不裁定优劣。

### 复用 03-6 的 Transformer 块

模型主体是 N 个结构完全相同、参数各自独立的 Transformer 块堆叠。每个块（在 decoder-only LM 里）的经典组成是：一个带因果掩码的多头自注意力子层 + 一个前馈网络（FFN）子层，两个子层各自配残差连接和层归一化（LayerNorm）。这正是 03-6.6 讲的"残差 + LN + FFN"组装，此处当既定物直接堆叠。

残差连接（把子层输入直接加到子层输出上）是能训练很深网络的关键——它给梯度一条"高速公路"，缓解深层梯度消失（呼应 03-3.6）。LayerNorm 的放置位置（子层前 Pre-LN 还是子层后 Post-LN）会显著影响训练稳定性，这是 08S-3.1 的话题；现代实现多用 Pre-LN，但本篇不作定论。

### 因果掩码：语言模型不能偷看未来

语言模型的训练目标是"根据前文预测下一个 token"，所以位置 t 只能看到位置 0..t，绝不能看到 t 之后的内容，否则就是"抄答案"。实现上是在注意力打分矩阵里，把每个位置对其未来位置的打分置成负无穷，softmax 后这些位置权重就归零。这就是因果（causal）掩码，也叫下三角掩码。

这与 03-6.5 讲的"因果 vs 双向掩码"一致：编码器（BERT 式）用双向、能看全句，解码器（GPT 式）用因果、只能看左边。初学者最致命的 bug 就是掩码写错导致信息泄露——训练 loss 会低得离谱、但一到自回归生成就崩，因为生成时根本没有"未来"可看。验证方法很简单：改动某个未来位置的输入，当前位置的输出不应有任何变化。

### 最终归一化与 LM head（含权重共享）

堆叠完 N 个块后，通常再过一层最终 LayerNorm，然后接 LM head——一个把 d 维向量投影回 V 维的线性层，输出每个位置对下一个 token 的 logits，形状 (B, T, V)。

一个常见且省参数的技巧是权重共享（weight tying）：让输出投影矩阵直接复用输入嵌入矩阵的转置（两者都是 V × d 量级）。这既省下一大块参数（当 V 大时嵌入层占总参数比例很高），也有"输入输出共享同一套 token 表示"的直觉。是否 tie 属实现选择，nanoGPT 与多数 GPT 类实现默认开启；具体某模型是否 tie 属「待核」。

### 前向输出即 logits，尚未归一化

前向的终点是 logits，不是概率。logits 是任意实数打分；要变成概率需再过一次 softmax，但训练时算交叉熵损失的函数（如 PyTorch 的 `cross_entropy`）内部会自己做 softmax，所以模型前向通常直接吐 logits、不提前 softmax。

训练时又手动 softmax 一遍（等于做了两次、数值和梯度都错），或推理采样时忘了 softmax（直接拿 logits 当概率）。记住分工：前向出 logits；损失函数吃 logits；采样时才显式 softmax（见 08S-1.4）。这一 logits→概率的边界是整条流水线里最容易接错的接口之一。

## 08S-1.3 训练循环

### 训练循环的整体骨架

训练循环是让模型"从数据里学"的引擎：反复地取一批数据 → 前向算出 logits → 与真实答案比较算出损失（loss）→ 反向传播算梯度 → 优化器按梯度更新参数 → 清空梯度，如此循环成千上万步。语言模型的"真实答案"来自数据本身——用序列里第 t+1 个 token 当第 t 个位置的标签，这叫下一 token 预测（next-token prediction），是一种自监督（无需人工标注）。

一步训练的最小骨架：

```
for step in 训练步数:
    x, y = 取一个 batch          # y 是 x 右移一位
    logits = model(x)            # (B, T, V)
    loss = cross_entropy(logits, y)
    loss.backward()              # 反向传播，累出梯度
    optimizer.step()             # 按梯度更新参数
    optimizer.zero_grad()        # 清空梯度，准备下一步
```

每一步就是"考一次试、对答案、按错误调整、准备下一次"。数据的 x 和 y 只差一位（y 是 x 整体右移一格），因为"预测下一个"就是"用第 t 个位置去猜第 t+1 个 token"。CS336 作业 1 要求实现的正是这一整套 loss/优化器/训练循环栈。

### 交叉熵损失

语言模型的损失几乎总是交叉熵（cross-entropy）：对每个位置，模型输出一个 V 维概率分布，损失衡量"真实的下一个 token"在这个分布里被赋予的概率有多低。单个位置的交叉熵是：

```
loss = -log( p_model[正确的下一个 token] )
```

整段序列/整批的损失是所有位置该值的平均。模型预测得越准（给正确 token 的概率越接近 1），-log 越接近 0；预测越离谱，损失越大。

交叉熵损失取指数就是困惑度（perplexity, PPL = exp(loss)），这是 LM 最常用的评估指标，可粗略理解为"模型在每一步平均在多少个候选之间纠结"。易错点：交叉熵要吃 logits（内部自带 softmax），别自己先 softmax；标签要对齐成"右移一位"，错位一格是常见 bug，会让 loss 卡在无意义的高位。

### 优化器：AdamW

更新参数用的优化器，LM 训练里事实上的默认是 AdamW——Adam（自适应学习率，见 03-3.3）加上"解耦的权重衰减（decoupled weight decay）"。Adam 为每个参数维护梯度的一阶矩（动量）和二阶矩（梯度平方的滑动平均）两组统计量，据此给每个参数自适应地缩放步长；权重衰减则是一种正则，AdamW 的贡献是把它从梯度里解耦出来、单独作用于参数，效果比原始 Adam 里混在一起更好。

AdamW 因为每个参数要多存两组状态（一阶矩、二阶矩），显存开销是参数本身的数倍（这笔账在 08S-2 显存预算里细算）。具体的 β1/β2/权重衰减系数/学习率是随模型和语料调的超参，任何"标准值"都属「待核」、不宜凭记忆填。AdamW 出自 Loshchilov & Hutter 的 Decoupled Weight Decay 工作，被 GPT 类训练与 nanoGPT 广泛采用。

### 学习率调度与 warmup

学习率（步长）通常不是恒定的，而是按一条调度曲线变化：典型做法是先 warmup（从很小线性升到峰值，头几百到几千步），再按余弦或线性衰减到很低。warmup 的作用是训练初期参数和优化器的矩估计都还不稳，先小步走避免一上来就发散。

刚开始像刚学开车，先慢慢给油（warmup），上路稳了再提速，快到终点再减速精调（衰减）。这解决了初学者的一个困惑——"为什么 loss 前几百步不怎么降甚至抖动"，那常常正是 warmup 阶段。具体 warmup 步数和峰值学习率属「待核」的调参量。

### 梯度裁剪

反向传播偶尔会产生异常大的梯度（梯度爆炸，尤其序列模型里，呼应 03-5.3），一步过大的更新能把训练毁掉。梯度裁剪（gradient clipping）在更新前把梯度的整体范数限制在一个阈值内：若超过就等比例缩小，方向不变、幅度封顶。

这是 LM 训练里近乎标配的稳定手段，实现上是在 `loss.backward()` 之后、`optimizer.step()` 之前插一步裁剪。初学者把它理解成"给每一步的更新幅度装个保险丝"即可。常用阈值（如 1.0 量级）属经验值、随设置变，具体数字「待核」。

### 梯度累积

当显存装不下想要的大 batch 时，用梯度累积（gradient accumulation）在小显存上"模拟"大 batch：连续跑若干个小 batch（micro-batch），每个都 backward 让梯度累加进同一处，但不立即 step；累够 K 个 micro-batch 后才 step 一次、再清零。这样一次真正的参数更新看到的等效 batch = micro-batch × K。

关键机制在于 PyTorch 里梯度默认是累加的（每次 backward 加到 `.grad` 上，不覆盖），所以只要 K 步内不清零，就自然累加；配合损失除以 K 来保持尺度一致。

一步骨架：

```
for i, (x, y) in enumerate(batches):
    loss = cross_entropy(model(x), y) / K
    loss.backward()                 # 梯度累加，不清零
    if (i + 1) % K == 0:
        optimizer.step()
        optimizer.zero_grad()
```

梯度累积用"时间换空间"——多花几倍前向反向时间，换来"大 batch"的稳定训练效果，几乎不占额外显存（除了梯度本身）。易错点：忘了把 loss 除以 K 会让等效学习率放大 K 倍；忘了在 step 后 zero_grad 会让梯度无限累加。

### 混合精度训练

为省显存和提速，现代训练常用混合精度（mixed precision）：大部分计算用 16 位浮点（fp16 或 bf16），但关键处（如损失累加、优化器状态）保留 32 位。bf16 因为动态范围和 fp32 一样大、更不易溢出，在 LM 训练里越来越常见（需硬件支持）。

初学者理解到"用低精度换显存和速度、但要防数值下溢/上溢"即可。fp16 通常要配 loss scaling（把 loss 放大再缩回）防梯度下溢，bf16 一般不需要。本机无 GPU，此项概念讲清、不实证；具体哪种精度、是否 loss scaling 随硬件和框架版本变（⚙演进快）。

### 检查点

训练动辄几天，必须定期把"训练现场"存盘，这叫检查点（checkpoint）。要存的不只是模型参数，还包括优化器状态（Adam 的一阶/二阶矩）、当前步数、学习率调度状态、数据读取位置等——只有这些齐全，才能在中断后精确续训（resume）而不是从头再来。

只存了模型权重、没存优化器状态，续训时 Adam 的动量归零，等于优化过程被"重置"，loss 会短暂反弹。检查点也用于事后挑选最优模型、以及在不同阶段（如后续微调）作为起点。存盘频率是省算力与抗故障之间的权衡。

## 08S-1.4 采样解码

### 自回归解码总览

训练好的模型只会做一件事：给定前文，输出下一个 token 的概率分布。生成一段文本靠自回归（autoregressive）循环：喂入前文 → 取最后一个位置的 logits → 按某种策略从中挑一个 token → 把它接到序列末尾 → 再喂回去，如此逐个 token 生成，直到遇到结束符或达到长度上限。

"采样解码"讨论的就是"按什么策略从概率分布里挑 token"。这决定了生成文本的确定性、多样性和质量。它与 03-9.5 的自回归生成一脉相承，是把训练好的 LM 真正用起来的最后一环。CS336 与各解码论文都把它归为独立于训练的推理期选择——同一个模型换不同解码策略，输出风格可以天差地别。

采样时才需要显式 softmax 把 logits 变概率（训练时是损失函数内部做的，见 08S-1.2）。另外每生成一个 token 就要重跑一次前向，朴素实现会重复计算前文——这引出 KV cache 等推理优化（归 08S-9，本篇不展开）。

### 贪心解码

最简单的策略：每步直接选概率最高的那个 token（argmax），完全确定、无随机性。

贪心快且可复现，但对开放式生成（写故事、聊天）有个著名毛病：容易陷入重复循环、产出乏味文本（Holtzman et al. 2020 的"神经文本退化"正是批评这类最大化解码）。直觉上，每步都挑"最稳的"会让文本越来越保守、失去多样性；而且局部最优不等于整句最优（贪心不回头）。对有唯一正确答案的任务（如某些抽取式问答）贪心尚可，对创造性生成则通常太死板。

### 温度

温度（temperature, T）是在 softmax 之前把 logits 除以 T，用来调节分布的"尖锐/平坦"：

```
p_i = softmax(logits / T)
```

T < 1 让分布更尖（高概率 token 更突出，输出更保守确定）；T > 1 让分布更平（低概率 token 有更多机会，输出更随机多样）；T → 0 退化成贪心；T = 1 是模型原始分布。

本机对固定 logits 向量 `[2.0, 1.0, 0.5, 0.1, -1.0, -3.0]` 算不同温度下的概率，真实输出：

```
T=0.5:  [0.826 0.112 0.041 0.018 0.002 0.000]
T=1.0:  [0.556 0.205 0.124 0.083 0.028 0.004]
T=2.0:  [0.361 0.219 0.170 0.140 0.081 0.030]
```

可直观看到：T=0.5 时最高概率 token 独占 0.826（接近贪心），T=2.0 时概率被明显摊平、尾部 token 也拿到可观份额。这就是"调温度=调创造性"的机械原理。易错点：温度是除在 logits 上、不是除在概率上；T=0 不能直接算（除零），实现上等价于取 argmax。

### top-k 采样

top-k（Fan et al. 2018）只在概率最高的 k 个 token 里采样：先按概率排序，保留前 k 个，把其余置零，重新归一化后再随机抽。它切掉了长尾里那些低质、离谱的候选，同时保留头部的多样性。

沿用上面的分布（T=1），top-k=2 的真实输出：

```
只保留前 2 个 token，重归一化 -> [0.731 0.269 0.000 0.000 0.000 0.000]
```

从"最靠谱的 k 个候选"里掷骰子，既不像贪心那样死板，又不至于抽到荒唐 token。GPT-2 生成常用 k=40 量级。易错点在于 k 是固定的，不管当前分布是"胸有成竹"（概率集中在一两个）还是"举棋不定"（概率很分散）都切一样多——分布很尖时 k 太大会放进噪声，分布很平时 k 太小又扼杀了合理多样性。这个缺陷正是 top-p 要解决的。

### top-p（核）采样

top-p / 核采样（nucleus sampling，Holtzman et al. 2020）改成按累积概率动态选集合：从高到低累加概率，直到累积和刚超过阈值 p，就在这个最小集合（"核"）里重新归一化后采样。集合大小随分布形状自适应——分布尖时可能只留一两个，分布平时可能留很多个。

同一分布下 top-p=0.8 的真实输出：

```
保留累积达 0.8 的最小集合（索引 0,1,2），重归一化 -> [0.629 0.231 0.140 0.000 0.000 0.000]
```

对比同一分布 top-k=2 只留 2 个、top-p=0.8 留了 3 个，可见 top-p 的集合是随分布自适应决定的，这正是它相对 top-k 的核心改进：模型确信时收窄、犹豫时放宽，切尾更合理。Holtzman 论文的动机正是最大化解码（贪心/beam search）会退化，而截断不可靠的长尾能显著提质。

### 组合使用与实践直觉

这些策略不是互斥的，实践中常组合：先温度调整分布，再 top-k 或 top-p 截断，最后采样；top-k 与 top-p 也可叠用（先 k 后 p）。参数越"收紧"（低温、小 k、小 p）越确定保守，越"放开"越多样但风险越高。

贪心是 top-k=1 的极限；温度调分布形状；top-k 按固定个数切尾；top-p 按累积概率自适应切尾。没有"最好"的一套参数——这是随任务和模型调的推理期旋钮，且各家默认值随版本演进（⚙演进快），具体默认数值属「待核」。还有 beam search（保留多条候选束、偏向高似然）等策略更适合翻译等有参考答案的任务，在开放式生成中已较少单独使用，本篇仅登记不展开。
