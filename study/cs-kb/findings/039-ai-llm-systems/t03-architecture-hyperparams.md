## 08S-3.1 归一化位置与类型：Pre-LN vs Post-LN、RMSNorm

### Post-LN：原始 Transformer 的归一化位置

原始 Transformer（Vaswani et al. 2017）把层归一化放在残差相加之后，即每个子层的输出先与输入相加，再对相加结果做归一化。这种写法记作 Post-LN（post-normalization）。

一个子层的计算顺序是：

x_out = LayerNorm(x + Sublayer(x))

这里 Sublayer 是自注意力或前馈网络。关键在于归一化"套在"残差连接的外面，残差通路本身也被归一化重新缩放了。

对初学者来说，先要理解残差连接的作用：它给梯度提供一条"高速公路"，让梯度可以几乎不衰减地从深层流回浅层，这是能训很深网络的前提。Post-LN 把归一化压在这条高速公路的出口，等于每过一层就把这条通路重新缩放一次。这在浅层网络里没问题，但层数一多，靠近输出的层在初始化时会累积出很大的梯度，训练一开始就容易发散。

### Post-LN 的梯度不稳定与 warmup 依赖

「On Layer Normalization in the Transformer Architecture」（Xiong et al., ICML 2020, arXiv:2002.04745）用理论分析指出：Post-LN 结构在初始化时，靠近输出层的参数期望梯度很大，因此几乎必须配合学习率 warmup（先用很小的学习率、再逐步升到目标值）才能稳定训练。

warmup 是一段"热身"调度：训练最初的若干步把学习率从接近 0 线性抬到峰值，之后再按正常调度衰减。它之所以对 Post-LN 是刚需，是因为如果一开始就用大学习率，那些初始梯度本就偏大的输出层参数会被一步推得太远，把模型带到坏区域。warmup 相当于在梯度还没被网络"驯服"前先小步慢走。

warmup 本身要调超参（热身步数、峰值），调不好训练就崩，等于给工程增加了一个脆弱的旋钮。这正是后来大家想绕开 Post-LN 的动机之一。

### Pre-LN：把归一化移进残差通路

Pre-LN（pre-normalization）把层归一化移到子层的输入端，即先归一化、再进子层，子层输出直接加回未归一化的残差通路：

x_out = x + Sublayer(LayerNorm(x))

同一篇 On-LN 论文证明：这样残差高速公路上不再被反复缩放，梯度在初始化时就"表现良好"，可以去掉 warmup 直接训练，收敛更快（论文在 BERT 预训练上报告了约 40% 的加速，此数值锚该论文设置）。

直觉上，Pre-LN 让残差通路成为一条干净的恒等映射，每个子层只是往这条通路上"加"一个被归一化过的增量。梯度回传时能沿恒等通路无损流回，因此深层也稳。CS336 Spring 2026 L3 的说法是：几乎所有现代 LM 都用 pre-norm，因为它"训练稳定得多"。

要给初学者补两个容易混的点。第一，Pre-LN 不是没有代价：因为残差通路上的量会随层数线性累积（每层都往上加东西），到最后一层数值会偏大，所以 Pre-LN 结构通常在最后再补一个归一化（final norm）。第二，"更稳"不等于"最终质量一定更高"——存在文献分歧。

### Post-LN 与 Pre-LN 的分歧与再平衡

来源在"谁最终质量更好"上并不一致，这里两边都记。On-LN 论文和 CS336 的立场是 Pre-LN 更稳、是现代默认；但另有工作指出 Post-LN 在能训稳的前提下最终表示能力/质量可能更高，只是难训——例如通过更谨慎的初始化让很深的 Post-LN 也能训起来（如 DeepNet 一类工作，锚其各自论文时点，具体增益「待核」）。

现代大模型压倒性地选 Pre-LN，主要买的是"训练稳定、可去 warmup、少一个崩溃点"这份工程确定性，而不是断言它建模上一定占优。这类选择随代际演进，属 ⚙演进快，不作定论。

### RMSNorm：去掉再中心化只留缩放

RMSNorm（Root Mean Square Layer Normalization, Zhang & Sennrich, arXiv:1910.07467, 2019）是对标准 LayerNorm 的简化：它假设 LayerNorm 里"减均值再中心化"这一步是可有可无的，只保留按均方根（RMS）做缩放。

标准 LayerNorm 对一个 d 维向量 x 先减均值再除以标准差；RMSNorm 直接用 RMS 归一，公式为：

RMSNorm(x)_i = x_i / RMS(x) · g_i,  其中 RMS(x) = sqrt( (1/d) · Σ_{j=1..d} x_j² )

g 是可学习的逐维缩放增益（gain），d 是向量维度。注意分母里没有减均值那一项。

LayerNorm 做两件事——把一批激活的均值拉到 0（re-centering，再中心化）、把幅度归一（re-scaling，再缩放）。RMSNorm 的主张是只有"再缩放"对 Transformer 是重要的，"再中心化"可以扔掉。扔掉之后要算的统计量更少（不用先算均值再算方差，只算一个平方和），所以更快。论文报告在不同模型上运行时间减少约 7%–64%（此区间锚该论文），效果与 LayerNorm 相当。

RMSNorm 每层都要跑，归一化虽算力占比不高，却是逐元素、访存密集的操作，省掉一遍均值计算能实打实降低这部分开销；参数也更少（通常连 bias 一起省掉）。CS336 L3 的观察是现代模型"几乎都用 RMSNorm"，理由正是"更快且一样好"。这仍属演进选择，不作优劣定论。

### 去掉偏置项（bias-free）

与归一化一起被现代架构清理掉的还有各线性层的偏置项（bias）。CS336 L3 指出多数现代 Transformer 不再给线性层和归一化层加 bias。

偏置项就是线性变换 y = Wx + b 里的那个加性常量 b。去掉它后变成纯 y = Wx。这样做省下少量参数和一次加法，更重要的是被报告有利于优化稳定性；配合 RMSNorm（本就不需要 bias）一起，整套归一化/线性栈更干净。对初学者这是个"减法优化"的例子：不是加东西提性能，而是删掉被验证为冗余的部件来换取速度与稳定。具体收益随模型而异，属 ⚙演进快。

## 08S-3.2 激活选择：GeLU / SwiGLU 对吞吐-收敛的影响

### 前馈子层与激活函数的角色

Transformer 每个块里除了注意力，还有一个逐位置的前馈网络（FFN），它由两个线性层夹一个非线性激活组成：

FFN(x) = W2 · φ(W1 · x)

φ 是激活函数，W1 把维度从 d_model 升到中间维 d_ff（通常放大），W2 再降回 d_model。这个 FFN 是模型里参数量和算力的大头之一。

注意力负责"在序列里混合信息"，FFN 负责"对每个位置各自做一次非线性变换"，两者交替。激活函数 φ 提供非线性——没有它，两个线性层会塌成一个线性层，模型就没有表达力了。所以选哪个 φ 既影响拟合能力（收敛），也影响这一大块的计算成本（吞吐）。

### GeLU：平滑的门控式激活

早期大模型（如 GPT、BERT 家族）常用 GeLU（Gaussian Error Linear Unit）替代 ReLU。ReLU 是硬截断（负的全归零），GeLU 是它的平滑版：按输入自身的大小、用标准正态分布的累积函数 Φ 做一个平滑的"软门"：

GeLU(x) = x · Φ(x)

Φ(x) 是标准正态分布的累积分布函数，取值在 0 到 1 之间。

直觉上，GeLU 对很负的输入几乎压到 0、对很正的输入几乎原样通过，中间是平滑过渡，而不是 ReLU 那样在 0 处有个折角。平滑意味着梯度处处存在，训练时更少出现"死神经元"（ReLU 负区梯度恒为 0 导致神经元不再更新）。代价是要算一个 Φ（或其近似），比 ReLU 一次比较略贵，但在整体开销里可忽略。

### GLU 门控与 SwiGLU

「GLU Variants Improve Transformer」（Shazeer, arXiv:2002.05202, 2020）提出把 FFN 的第一层换成门控线性单元（GLU）的变体。GLU 的思路是：不用单一激活，而是用两条并行的线性投影，一条过激活当"门"，另一条当"内容"，两者逐元素相乘。SwiGLU 用 Swish（也叫 SiLU）当门：

SwiGLU(x) = ( Swish(x·W) ⊙ (x·V) ) · W2,  其中 Swish(z) = z · sigmoid(z)

这里 W、V 是两个并行的输入投影，⊙ 是逐元素相乘，W2 是输出投影。注意这比普通 FFN 多了一个矩阵（W 和 V 两个输入投影，而普通 FFN 只有一个 W1）。

门控的直觉是"让网络自己学会哪些通道该放行、哪些该抑制"——门那一支（过 Swish）输出接近 0 就关掉对应内容通道，接近 1 就放行。相比固定形状的 GeLU，门是数据依赖的，表达更灵活。论文的经验结论是 GEGLU / SwiGLU 这类门控变体在困惑度上系统性优于原始 FFN（结论锚该论文），SwiGLU 随后被 PaLM、LLaMA 等广泛采用，也是 Llama 3、Qwen 3、DeepSeek 等现代开源模型的常见选择。

### 参数量对齐：4×d_model 与 8/3×d_model

因为 SwiGLU 用了三个矩阵（W、V、W2）而普通 FFN 只有两个（W1、W2），若中间维 d_ff 不变，SwiGLU 的 FFN 参数会多出约 50%。为公平比较、保持参数量与算力持平，现代做法是把 SwiGLU 的中间维缩小。

标准 GeLU/ReLU FFN 的经验默认是：

d_ff = 4 × d_model

换成 SwiGLU 后为保持参数量不变，把系数从 4 降到 8/3：

d_ff = (8/3) × d_model ≈ 2.66 × d_model

CS336 L3 指出这个"约 2.66"的比例在 PaLM、Mistral、Llama、Qwen、DeepSeek、T5 等模型上被反复观察到；同时引 Kaplan 等的缩放律分析说 d_ff/d_model 的最优区间其实是一个"很宽的盆地"，大致 1 到 10 之间都不算差，所以 4 或 8/3 都落在合理区（个别例外如 T5-11B 用过极大的 d_ff，属特例，锚其论文）。

为什么要专门做这个对齐，对初学者很关键：如果换激活的同时又偷偷加了参数，那"性能变好"就分不清是激活的功劳还是参数变多的功劳。把参数量钉死再比，才是干净的对照。这也是"系统取舍"的核心——同样的参数预算下换个结构能不能更划算。

### 吞吐-收敛的系统取舍

从系统成本看，门控变体多一个输入投影矩阵，意味着这一支的矩阵乘法数量增加，kernel 调度也更碎；但通过 8/3 缩窄 d_ff 把总 FLOP 和参数拉回持平后，实测吞吐差异不大，换来的是收敛/困惑度上的经验增益。

这些是"在该锚点下的经验观察"，不是定理。激活选择随代际演进（属 ⚙演进快），不同规模、不同数据下增益幅度不同，无一手坐实的具体加速比/困惑度差在此标「待核」，本篇不排名、不裁定 GeLU 与 SwiGLU 谁绝对更优。

## 08S-3.3 位置编码变体：RoPE / ALiBi 的外推性

### 为什么需要位置编码

自注意力本身对输入顺序是"置换不变"的：如果不额外告诉它每个 token 在第几位，把句子里的词打乱，注意力算出来的结果集合是一样的。语言显然依赖顺序，所以必须往模型里注入位置信息。原始 Transformer 用固定的正弦/余弦函数给每个位置生成一个向量，加到词嵌入上（绝对位置编码）。

注意力靠 Q·K 的点积衡量"谁该关注谁"，这个点积只看内容不看位置。位置编码就是给内容里掺进"我在哪"的信号，让点积能间接感知距离。绝对正弦编码的问题是它编的是"绝对位置第几位"，而语言里更重要的往往是"相对距离多远"，且推理时若序列比训练时长，超出的绝对位置模型没见过，容易失效——这就引出"外推性"（extrapolation，测试序列比训练更长时还能不能用）这个系统关注点。

### RoPE：旋转位置编码

RoPE（Rotary Position Embedding，出自 RoFormer, Su et al., arXiv:2104.09864, 2021）不再往嵌入上"加"位置向量，而是在注意力层里把 Q 和 K 向量按其位置"旋转"一个角度，且旋转角与位置成正比。

把 Q/K 的维度两两配对成一个个二维平面，位置 m 处的向量在第 i 对平面上旋转角度 m·θ_i：

RoPE(x, m) 在第 i 对分量上 = [ x · cos(m·θ_i) − x' · sin(m·θ_i), x · sin(m·θ_i) + x' · cos(m·θ_i) ]

其中 θ_i 是随维度对递减的一组频率。关键性质是：两个位置 m、n 的 Q、K 做点积时，结果只依赖它们的相对位置差 m−n，而不依赖绝对位置——旋转把"相对距离"自然编进了点积里。

想象每个 token 的 Q/K 是钟表指针，位置越靠后指针转得越多。两根指针做点积（相当于看夹角）时，夹角只取决于两者转动量之差，也就是相对距离。这样模型天然学到的是相对关系，且距离越远相关性自然衰减。CS336 L3 指出现代模型"基本都用 RoPE"，且强调它作用在注意力层（对每层的 Q/K 施加），而不是像绝对编码那样只在嵌入层加一次。

RoPE 的外推性是"有限的好"：它比绝对编码更能处理没见过的长度，但当推理长度远超训练长度时仍会退化，因此衍生出一批"外推增强"方法（如位置插值等，锚各自论文时点，具体做法「待核」）。

### ALiBi：注意力线性偏置

ALiBi（Attention with Linear Biases, Press et al., arXiv:2108.12409, 2022）走另一条路：完全不改 Q/K，而是在注意力分数矩阵上直接减去一个与相对距离成正比的惩罚项，距离越远惩罚越大。

对位置 i（query）和 j（key），注意力打分为：

score(i, j) = q_i · k_j + m · (−(i − j))

其中 m 是每个注意力头固定的斜率（不同头用不同斜率，是超参而非学习量）。相当于给"看得越远"的注意力施加一个线性递增的负偏置。

ALiBi 的思想极简——不给模型编"我在第几位"，只告诉它"越远越该少关注"。因为这个偏置是纯粹按相对距离算的公式、和序列长度无关，所以训练时用短序列、推理时换更长序列，公式照用不误，外推性因此很好。这是 ALiBi 论文的主打卖点：在短序列上训练、外推到长序列时困惑度仍稳。

ALiBi 的斜率是启发式设定的（不是学出来的），且它的"远处衰减"是强制单调的线性惩罚，灵活性不如 RoPE 的旋转；有工作指出这种启发式设计对某些分布不一定最优（锚相关论文）。

### 外推性对比与取舍

把两者并排看：RoPE 通过旋转把相对位置编进 Q/K 的内容里，表达灵活、被现代主流广泛采用，但原生外推有限，需要配合插值等技巧才能大幅拉长上下文；ALiBi 通过在打分上加固定的距离惩罚，天生对长度不敏感、外推稳，但机制更"硬"、灵活性较低。

RoPE 每层要对 Q/K 做旋转（逐元素乘加，开销小且可融合进 kernel）；ALiBi 只是在打分矩阵上加一个可预计算的偏置，几乎零额外参数。二者都比"存一张可学习位置表"更省参数、更易扩展序列长度。

这里必须两边都记、不作定论：不同来源对"谁外推更好"结论不一致——ALiBi 论文主打其外推优势，而实践中 RoPE（尤其配合插值/基频调整后）成为长上下文模型的事实主流。这属活跃演进（⚙演进快），谁更优随任务、序列长度、后续改法而变，具体外推质量数值「待核」。

## 08S-3.4 宽深比与规模权衡：层数/隐藏维/头数的系统成本

### 宽度、深度与残差流

给定参数预算，模型可以做得"深"（更多层 n_layers）或"宽"（更大的隐藏维 d_model）。d_model 是残差流（residual stream）的维度，它一处放大几乎会同时放大模型里所有操作的规模——注意力投影、FFN、归一化都以它为基准维度。

把网络想成一条主干管道（残差流），每一层往管道里读写。管道有多粗（d_model）决定每层能处理多少信息、算力多大；管道有多长（n_layers）决定信息要经过多少次变换。同样的参数量，可以摊成"又粗又短"或"又细又长"，这就是宽深比（aspect ratio）问题。

### 宽深比（aspect ratio）的甜点

宽深比通常定义为每层分到的隐藏维，即 d_model 除以 n_layers。CS336 L3 给出的经验甜点是约 128：

aspect ratio = d_model / n_layers ≈ 128

CS336 同时引 Kaplan 等缩放律的结果：损失对这个比值的最小值大约落在比值为 100 附近，且曲线在甜点附近相当平坦（比值在较宽范围内损失差别不大）。换句话说，只要不太极端地偏宽或偏深，最终质量对宽深比不敏感。

这条经验的用处是"定完总参数量后，怎么在深和宽之间分配"有个默认起点——每层大约 100–128 维 d_model。为什么不能一味加深？因为太深会让优化更难（梯度路径长、Pre-LN 也只能缓解而非消除），也更难并行；太宽则单层矩阵巨大、显存和单步算力吃紧。甜点是这两难之间的经验平衡（具体最优随规模变，属 ⚙演进快）。

### 宽深比的系统成本差异

宽和深虽然参数量可以相同，系统开销却不同，这是"系统取舍"的关键。

更深（更多层）意味着前向/反向必须逐层串行走完，层与层之间有依赖，难以在时间上并行；在多卡场景下深模型更适合按层切开做流水线并行，但会引入流水线气泡（等待）开销。更宽（更大 d_model / d_ff）意味着单层的矩阵乘法更大，更容易被 GPU 的大矩阵乘吃满、算术强度更高，也更适合按维度切开做张量并行，但单层的激活和权重显存峰值更高。

同样多的参数，深模型是"很多小步、步步等前一步"，宽模型是"少数大步、每步很重"。GPU 擅长大矩阵，所以适当偏宽往往吞吐更友好；但太宽会撞显存墙。这解释了为什么实际模型的宽深比落在一个中间甜点，而不是走极端。

### 头数、头维度与 KV cache（MHA / MQA / GQA）

多头注意力把 d_model 切成 n_heads 个头，每个头维度 d_head。CS336 L3 的常规做法是加头时保持 d_head 固定（典型 64–128），并让 d_model 与 n_heads×d_head 大致相等（比值约 1）：

d_model ≈ n_heads × d_head

头数还牵动一个重要的系统成本——推理时的 KV cache。自回归生成时每个 token 的 K、V 要缓存下来复用，缓存大小正比于 KV 头的数量。为压缩这块显存，出现了共享 KV 头的变体：

MQA（Multi-Query Attention, Shazeer, arXiv:1911.02150, 2019）让所有 query 头共享同一份 K、V；GQA（Grouped-Query Attention, Ainslie et al., arXiv:2305.13245, 2023）介于两者之间——把 query 头分成若干组，每组共享一份 K、V。

标准多头注意力（MHA）每个 query 头都配自己的 K、V 头，表达最全但 KV cache 最大；MQA 只留一份 K、V，cache 最小但可能损失质量；GQA 取折中，例如 16 个 query 头配 8 个 KV 头（每 2 个 query 共享一份），既大幅缩小 cache 又比 MQA 保留更多灵活性。GQA 论文报告其质量接近 MHA、速度接近 MQA（结论锚该论文）。这纯粹是"推理显存/吞吐"驱动的系统取舍，不改变建模的基本形式。

### 词表大小的系统成本

词表大小（vocabulary size）决定嵌入矩阵和输出投影（softmax 前的线性层）的规模，这两块参数量都正比于词表大小×d_model。CS336 L3 给的经验范围：早期单语模型约 30k–50k（如早期 GPT、Llama），现代多语/生产系统约 100k–250k，常见参考约 100k–200k。

词表越大，单个 token 平均能覆盖更长的文本片段（编码更"省 token"，序列更短、推理更快），但嵌入和输出层的参数与算力（尤其最后一层 softmax）随之膨胀，训练时这一层的显存和计算都不小。词表大小因此是"序列长度效率"与"嵌入/输出层成本"之间的权衡，落点随语言覆盖面和部署需求变（属 ⚙演进快，具体最优「待核」）。

### 系统成本视角的总括

宽深比决定串行 vs 并行、显存峰值 vs 吞吐的取舍；头数/头维度决定注意力的并行度与推理 KV cache（MHA/MQA/GQA 是这条线上的选择）；词表大小决定嵌入/输出层成本与序列效率。这些超参彼此不独立，且都随代际和硬件演进而调整。本篇只给"在该锚点下"的经验默认与机制取舍，不裁定具体配置的优劣，无一手坐实的数值一律标「待核」。
