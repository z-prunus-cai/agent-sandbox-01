本报告讲"把原始文本变成能喂进语言模型的训练语料"这条前置流水线：从哪里采数据、怎么去掉低质、怎么去掉重复、各来源按什么比例混、以及能不能用模型自己生成的数据回喂。它紧邻通用数据管线课（L6-04/L6-05）但视角不同——这里关心的是"数据配方如何影响一个具体 LM 的最终能力"，而不是通用 ETL 工程。

现代预训练数据不是"一份现成语料"，而是一条多级流水线的产物，每一级（采集 → 抽取 → 过滤 → 去重 → 混配 →（可选）合成）都是可调的设计选择，且这些选择随季度快速演进、各家配方多不公开。因此下面所有具体阈值、比例、权重都锚到某篇论文的某个时点，不作跨代际的定论；无一手来源坐实的数字标「待核」。

## 08S-11.1 数据源与采集

### 08S-11.1.1 来源谱：网页 / 代码 / 书籍 / 百科 / 学术

预训练语料的"来源谱"指训练文本从哪些渠道来：开放网页抓取（Common Crawl 及其衍生）、代码（GitHub 等）、书籍（Books/Gutenberg）、百科（Wikipedia）、学术（arXiv、PubMed）、问答与论坛、法律/专利文本等。

不同来源贡献不同能力，代码给逻辑与结构、书籍给长程连贯与知识、百科给事实密度、网页给规模与话题广度。可以把来源谱理解成一张"营养表"，每类来源是一种养分，最终模型的能力谱取决于喂了哪些、各喂多少。哪些来源按什么比例，正是后面 08S-11.4 混配要调的东西，本节先把"有哪些来源、怎么把它们变成文本"讲清。

### 08S-11.1.2 Common Crawl 与 WARC / WET 归档

网页数据的主入口是 Common Crawl，它每月对可爬网络做一次快照并公开发布，有两种存档格式：WARC 保存完整 HTTP 响应（含原始 HTML），WET 保存已抽取的纯文本。大规模网页语料几乎都从这里起步。

网页数据不是"直接下载一堆 .txt"，这是初学者最容易误解的一点。原始快照极脏，导航栏、广告、样板文字、乱码、非目标语言混杂，所以"采集"其实一大半工作量在抽取与清洗上，而不是"下载"本身。很多高质数据集宁可从 WARC 重新抽正文，也不用现成的 WET，因为专用抽取器质量更高。

### 08S-11.1.3 正文抽取与语言识别

从原始网页到干净文本，要过三道常见工序：从 HTML 抽正文、判语言只留目标语言、用 URL 黑名单挡掉成人/垃圾站点。FineWeb 用 `trafilatura` 库从 WARC 抽正文；语言识别常用 fastText 语言分类器打分后按阈值保留；URL 层面先过一遍黑名单。

这一步决定了进入后续流水线的原料质量。抽取器若把导航栏、页脚当正文留下，后面所有过滤都要替它补救；语言判错会让非目标语言混进语料。所以业界把"抽正文用什么工具"当成一个会显著影响最终模型的设计选择，而不是无关紧要的预处理。

### 08S-11.1.4 两条路线：多源策划 vs 纯网页规模优先

数据集在"来源结构"上走了两条对照路线。一条是多源人工策划，The Pile 把 22 个精选来源（Pile-CC、PubMed、arXiv、GitHub、Wikipedia、Gutenberg 书籍、FreeLaw、Stack Exchange 等）拼在一起，强调来源多样性与质量。另一条是纯网页规模优先，RefinedWeb（Falcon 用）主张"只用 Common Crawl、只要过滤去重做得足够狠，就能超过人工策划语料"，FineWeb（2024）同走纯网页路线，从 2013–2024 的 96 个 Common Crawl 快照产出约 15T token。

这两条路线结论相反，是记忆本主题的好抓手。The Pile 说"多源策划才够好"，RefinedWeb 说"纯网页足矣，关键在清洗"，它们的分歧至今没有被一锤定音，两边都要记、不裁定谁更优。趋势上，随着 08S-8 缩放定律把"要多少数据"抬到与参数量同量级，纯网页 + 强清洗这条更易上量的路线越来越主流。

### 08S-11.1.5 规模代际与量级

来源谱的量级在快速演进，早期学术/策划语料（The Pile 约 825GB 级）→ 网页规模语料（RefinedWeb 公开约 600B token、FineWeb 约 15T token）→ 更大的开放语料（Dolma 约 3T token、RedPajama-v2 号称约 30T token）。

这个膨胀直接呼应 08S-8，Chinchilla 类结论要求数据量随参数量同步放大，倒逼语料从"GB 级策划"迈向"万亿 token 级网页 + 清洗"。只需把握"数量级三连跳"这个趋势，具体 token 数按数据集论文时点锚定，博客口径（如 RedPajama-v2 的约 30T）标「待核」。

## 08S-11.2 质量过滤

### 08S-11.2.1 启发式规则过滤

启发式规则过滤用一批人写死的统计判据剔掉明显不像自然语言的页面。最常被复用的一套是 Gopher（MassiveText）规则，例如文档词数落在某区间、平均词长在合理范围、符号与词的比例不过高、以省略号结尾的行占比不过高、含足够多的常用停用词等，C4 还贡献了"删掉不以标点结尾的段落"这类规则。

这类规则便宜、可大规模并行，是过滤的第一道粗筛。它们都是代理指标（proxy），判的是"统计上像不像正常文本"而不是"内容好不好"，因此会误杀合法但风格特殊的文本，列表、代码、表格常中招。具体阈值（词数下限、符号比例上限等）各家不一且随代际改，属要锚论文的量，凭记忆填不可取。

### 08S-11.2.2 困惑度过滤

困惑度过滤源自 CCNet，用在高质量语料（通常是 Wikipedia）上训练的 n-gram 语言模型（KenLM）给每个文档打困惑度，困惑度太高（"不像 Wikipedia"）的判为低质删掉，直觉是"越像干净参考语料越可能高质"。

易错点正在这里，这类过滤对参考语料的风格有强偏置。以 Wikipedia 为参考时，流畅的废话能得高分，而代码、口语对话、技术写作等有价值但风格不同的文本会被冤枉。规范上要把困惑度理解为"与参考语料的风格相似度"，而不是"真实质量"，这是最该纠正的直觉。

### 08S-11.2.3 分类器过滤

分类器过滤训练一个二分类器区分"高质/低质"，用它给全量文档打分并按阈值保留。GPT-3 与 RefinedWeb 都用过"以策划语料（如 Wikipedia、被点赞的网页链接）为正例、随机网页为负例"训练的质量分类器。FineWeb-Edu 更进一步，用一个 LLM 给网页的"教育价值"打分、再训一个模型去复现该打分，从 FineWeb 里筛出约 1.3T token 的教育向子集，在 MMLU/ARC 等知识推理基准上显著更好。

分类器过滤把"什么算好"外包给了正例的选择，这是理解它的钥匙。正例偏 Wikipedia，就会系统性偏向 Wikipedia 风格，这既是它的力量（能精准提纯某类内容）也是它的偏置来源。保留比例（分类器阈值卡在哪个分位）各家不一，无一手坐实处标「待核」。

### 08S-11.2.4 过滤的偏置与统一心智模型

三档手段（启发式规则、困惑度、分类器）常叠加使用，但要建立一个统一心智模型，质量过滤不是"客观删垃圾"，而是"按某个质量代理重塑数据分布"。

因此过滤必然与下游目标耦合，并落在一个权衡上，过滤越狠语料越干净但越窄（丢失多样性），过滤太松则噪声多。困惑度与分类器路线都偏 Wikipedia 风格、会误伤代码/对话/技术文本，这类批评在多篇工作中反复出现，两边都记。没有"最优阈值"的普适答案，具体值随论文时点变，标「待核」。

## 08S-11.3 去重

### 08S-11.3.1 为什么要去重

去重指删除语料里重复或近重复的内容。网页里同一段文字会被无数站点转载、模板会重复上万次，一个被广泛引用的例子是 C4 里有一句 61 词的英文句子重复了 6 万多次。去重被反复证明能提升表现、减少对训练数据的逐字记忆（从而降低隐私/版权风险、改善泛化），是数据工程里承重的一步。

不去重，模型会把算力浪费在背诵高频重复上，还更容易逐字吐出训练文本。Lee et al. 2021 量化了收益，去重后模型逐字记忆减少约 10 倍，并能用更少步数达到同等或更好精度。去重分"精确"与"近似"两类，下面分别讲。

### 08S-11.3.2 精确去重（文档级 / 子串级）

精确去重删完全相同的内容，有两种粒度。文档级对整篇算一个哈希，哈希撞了就当重复删掉，快但只能抓"一字不差的整篇"。子串级用后缀数组（suffix array）找出所有超过某长度阈值（如 50 token）的完全相同子串并删除，能抓到"文档里嵌了一大段别处也有的文字"这种局部重复，后者正是 Lee et al. 2021 的 ExactSubstr 工具做的事。

要记住"整篇撞哈希"与"长子串撞"的分工，前者漏掉"改了开头结尾、中间大段照抄"的情形，后者专治这种局部抄袭。但两者都只认"一字不差"，改几个字就骗过去了，这正是需要近似去重的原因。

### 08S-11.3.3 Jaccard 相似度与 shingle

近似去重要估计两文档有多相似，做法是把文档表示为它的 n-gram（称 shingle）集合，再用 Jaccard 相似度衡量两个集合的重叠：

J(A, B) = |A ∩ B| / |A ∪ B|

取值 0（完全不相交）到 1（完全相同）。把文档切成 shingle 集合，是为了让"顺序略变、加删个别词"的两篇仍有高重叠。直接两两算 Jaccard 是平方级、在万亿 token 上不可行，所以需要下面的 MinHash + LSH 两级近似。

### 08S-11.3.4 MinHash 签名与无偏估计

MinHash（Broder 1997）把"比整集合"压成"比短签名"。对集合里每个元素用同一个哈希函数 h 求哈希、取最小值 min h(·) 作为一个签名分量，关键性质是两个集合的最小哈希相等的概率恰好等于它们的 Jaccard 相似度：

P[ min h(A) = min h(B) ] = J(A, B)

用 k 个独立哈希函数得到长度 k 的签名，两签名逐位相等的比例就是 J 的无偏估计。

min-hash 相当于"随机挑一个元素看两集合是否都含它"，而重叠越大越容易挑中共有元素，所以"签名撞的比例"自然逼近 Jaccard。签名把每篇文档压成几百个整数，比较成本大降，但两两比签名仍是平方级，需要下一步 LSH。

### 08S-11.3.5 LSH 分带与 S 曲线

LSH（局部敏感哈希）的分带（banding）法把候选相似对快速筛出来，避免两两比较。把长度 k 的签名切成 b 个带、每带 r 行（k = b·r），只要有任意一带完全相同就当候选重复对。两个相似度为 s 的文档至少落进同一桶（成为候选）的概率是

P(候选) = 1 − (1 − s^r)^b

这条曲线关于 s 是一条 S 形，相似度高的对几乎必被选中，低的几乎被跳过，拐点（近似阈值）约在

s* ≈ (1/b)^(1/r)

调 b 与 r 就能把"判为重复"的相似度阈值挪到想要的位置，从而把近重复检测从平方级降到接近线性，可在万亿 token 规模跑通。

这条 S 曲线可以这样理解，把签名切成很多带、只要一带全等就算候选，等于给"高相似"开了很多道过关机会，给"低相似"几乎堵死，于是判定在阈值附近迅速从"几乎不选"翻到"几乎必选"。b 越多阈值越低（更宽松、查全高但查准低），r 越大阈值越高（更严格）。

### 08S-11.3.6 参数权衡与去重强度

shingle 的 n、签名长度 k、以及 (b, r) 的选择共同决定"多相似算重复"和查准/查全的权衡，各家取值不同且随规模调，属要锚论文的参数，不要凭记忆填。去重还有"跨快照 vs 快照内""全局 vs 分片"的工程选择。

一个反直觉的经验是 FineWeb 报告的，过度全局去重未必更好，说明去重强度本身也是要消融的超参，不是越狠越好。应把去重看成"一个有最优点的旋钮"，而非"能删就删"。具体阈值、去重比例无一手坐实处标「待核」。

## 08S-11.4 领域混配

### 08S-11.4.1 混配是什么、为何是关键超参

领域混配（data mixture / domain reweighting）指决定各来源在最终训练语料里各占多大采样比例。同样一堆来源，权重不同训出的模型能力谱就不同，多给代码则编码强、多给网页则通用广。

因此混配权重是直接影响下游能力的关键超参，而不是随便按数据量摊。最该纠正的直觉是"哪个来源数据多就给它高权重"，恰恰相反，稀缺但高价值的来源（书籍、代码、精选百科）常被上采样、重复训多轮。

### 08S-11.4.2 手工权重与上采样（The Pile）

最朴素的做法是手工设定权重，The Pile 给每个来源一个人工设的采样权重，有的来源会被上采样重复多轮（如 Wikipedia/书籍的权重高于其自然占比）。

"上采样"这个操作的含义是，某来源真实体量小但价值高，就在训练时多采几遍，让它在有效语料里占比抬高。问题是手工权重靠经验、未必最优，且随目标任务变，这促成了下面自动优化混配的方法。

### 08S-11.4.3 DoReMi：代理模型自动定权

DoReMi（Domain Reweighting with Minimax Optimization）先用一个小"代理模型"（如 280M）在各领域上跑分布鲁棒优化（Group DRO），学出一组让"最差领域损失"尽量小的领域权重，再用这组权重重采样去训真正的大模型。

原论文报告，在 The Pile 上，用 280M 代理定出的权重去训 8B 模型（约 30× 大），平均少样本下游精度比用 The Pile 默认权重高约 6.5 个百分点，并能用约 2.6× 更少的步数达到基线精度。核心洞见是权重可迁移，小模型学的权重能用到大得多的模型上，因此定权成本很低。以上数值为该论文口径，随代际可变。

### 08S-11.4.4 DSIR / DoGE：面向目标分布的选择

另一支方法面向"想要的目标分布"。DSIR（Data Selection via Importance Resampling）给定一批目标样本（如某下游任务文本），在一个降维特征空间里估计每条原始数据相对目标分布的重要性权重，再按权重重采样，使被选子集逼近目标分布，解决"我知道想要什么样的数据，怎么从海量原始池捞出匹配的"。DoGE 则用代理训练时的领域梯度来估计各领域对泛化的贡献并据此重配权重。

把这两支和 DoReMi 分开记，DoReMi/DoGE 是"自动定各领域的比例"，DSIR 是"按一个目标分布挑样本"。不同方法给出的"最优配比"结论可能不一致，冲突处两边都记，不作定论。

### 08S-11.4.5 广度 vs 专精的心智模型

混配就是在"广度（覆盖多领域、通用性强）"和"专精（某领域权重高、该领域强）"之间调一个分布，且这个分布最好按下游目标来定，而非按原始数据量来定。

还要记一条与 08S-8 的联系，混配与缩放定律耦合，固定算力下配比不同会改变"参数 vs 数据"的最优点。具体各来源权重、上采样轮数、DoReMi/DSIR 的超参各家不一且随代际改，无一手坐实处标「待核」。

## 08S-11.5 合成数据 `⚙锚 CS336 Sp26·未定型`

### 08S-11.5.1 合成数据是什么、动机

合成数据指用（通常更强的）模型生成文本，再把这些生成文本喂回训练流程，作为真实爬取数据的补充或替代。动机是真实高质文本有限、且可定向生成"教材式"高信息密度内容。

这是数据工程里最活跃、最未定型的一块，什么时候有用、用多少、会不会导致退化都还在快速演化、无定论，本节只讲机制与已知边界，不作结论，整节硬标「未定型」。

### 08S-11.5.2 教材式合成与改写网页（Phi / WRAP）

代表性正面证据有两支。Phi 系列的"教材式合成数据"路线（《Textbooks Are All You Need》，Phi-1，2023）用大量合成的"教科书质量"代码/解释文本预训练一个 1.3B 小模型，在编码基准上追平体量约 10× 的模型，核心主张不是"数据量"而是"数据质量与结构"。另一支是"改写网页"（Rephrasing the Web / WRAP，2024），用模型把已有网页改写成更规整的风格再训练，报告能提升算力与数据效率。

两者共同的洞见是，合成数据的价值来自"提纯/重构"而非凭空造，把已有信息重新组织成每 token 信息量更高的形式。以上体量/加速数字为各论文口径，随代际可变。

### 08S-11.5.3 模型崩溃

最重要的风险是模型崩溃（model collapse）。如果反复用"上一代模型生成的数据"训练下一代，分布会一代代退化，先丢掉分布尾部（罕见但真实的模式），最终收敛到贫乏、重复的输出，Shumailov et al.（Nature 2024）在递归训练设定下给出了这一现象。

直觉上，模型采样天然偏向高概率区域，用自己的采样再训自己，就像反复复印复印件，细节一代代丢失，这是"合成数据不是免费午餐"的核心警示。

### 08S-11.5.4 替换 vs 累积、验证筛选

崩溃是否必然，取决于一个关键区分，替换 vs 累积。若每代都用合成数据替换真实数据，崩溃会发生；若把合成数据累积到（而非替换掉）真实数据之上，多项研究发现崩溃可被显著缓解甚至避免。相关实证还给出经验性配比迹象（例如某些设定下约 30% 高质改写合成 + 70% 真实数据在可见规模内不退化）。

这些具体比例高度依赖设定、属未定型区，务必标「待核」，不可当通用结论。另一条缓解线是验证/筛选，只把通过某种正确性或质量校验的合成样本留下，能减轻退化。

### 08S-11.5.5 收束与边界

把合成数据当"受控的数据增强"而非"免费的数据来源"来理解，它能定向补足稀缺高质内容（尤其代码、推理、教材式解释），但必须与真实数据混合、并配去重与质量校验，否则有分布退化风险。

因为本小主题随季度翻新极快，凡具体配比、代际稳定性、哪种校验最有效，均无跨代定论，硬标「未定型」，无一手坐实的数值标「待核」。
