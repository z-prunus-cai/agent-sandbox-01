本报告讲"把原始文本变成能喂进语言模型的训练语料"这条前置流水线：从哪里采数据、怎么去掉低质、怎么去掉重复、各来源按什么比例混、以及能不能用模型自己生成的数据回喂。它紧邻通用数据管线课（L6-04/L6-05）但视角不同——这里关心的是"数据配方如何影响一个具体 LM 的最终能力"，而不是通用 ETL 工程。

现代预训练数据不是"一份现成语料"，而是一条多级流水线的产物，每一级（采集 → 抽取 → 过滤 → 去重 → 混配 →（可选）合成）都是可调的设计选择，且这些选择随季度快速演进、各家配方多不公开。因此下面所有具体阈值、比例、权重都锚到某篇论文的某个时点，不作跨代际的定论；无一手来源坐实的数字标「待核」。

## 08S-11.1 数据源与采集

预训练语料的"来源谱"指训练文本从哪些渠道来：开放网页抓取（Common Crawl 及其衍生）、代码（GitHub 等）、书籍（Books/Gutenberg）、百科（Wikipedia）、学术（arXiv、PubMed）、问答与论坛、法律/专利文本等。采集要解决两件事：拿到原始字节（网页抓取存为 WARC/WET 归档），以及把它转成干净纯文本（从 HTML 抽正文、判语言、去掉明显非自然语言的页面）。

网页数据不是"直接下载一堆 .txt"。Common Crawl 是每月对整个可爬网络的快照，存成 WARC（含完整 HTTP 响应）或 WET（已抽的纯文本）格式。原始快照极脏——导航栏、广告、样板文字、乱码、非目标语言混杂。所以"采集"其实一大半工作量在抽取与清洗上。

不同数据集在"来源结构"上走了两条对照路线，值得对比记忆。一条是多源人工策划：The Pile 把 22 个精选来源（Pile-CC、PubMed、arXiv、GitHub、Wikipedia、Gutenberg 书籍、FreeLaw、Stack Exchange 等）拼在一起，强调来源多样性与质量。另一条是纯网页规模优先：RefinedWeb（Falcon 用）主张"只用 Common Crawl、只要过滤去重做得足够狠，就能超过人工策划语料"，其公开部分约 600B token（管线可产出更大规模）。FineWeb（2024）走的也是纯网页路线，从 2013 到 2024 年的 96 个 Common Crawl 快照产出约 15T token，并公开了每一步过滤/去重的消融实验。

从 HTML 抽正文的工具是一个具体且重要的环节。FineWeb 用 `trafilatura` 库从 WARC 抽正文（而不是直接用 Common Crawl 预抽的 WET），因为专门的正文抽取器质量更高。语言识别通常用 fastText 语言分类器打分并按阈值保留目标语言。URL 层面还会先用黑名单挡掉成人/垃圾站点。这些步骤共同构成"采集+抽取"这一级。

要点是记住来源谱的量级差异与代际趋势：早期学术语料（The Pile 约 800GB 级）→ 网页规模语料（RefinedWeb/FineWeb 到万亿 token 级）→ 更大的开放语料（Dolma 约 3T token、RedPajama-v2 号称约 30T token）。数据规模的膨胀直接呼应 08S-8 的缩放定律：Chinchilla 类结论把"要多少数据"抬到与参数量同量级，倒逼了这条从"策划"转向"网页规模 + 强清洗"的路线。具体各来源在最终配比中的权重见 08S-11.4；这里只确立"有哪些来源、怎么拿到、怎么抽成文本"。

## 08S-11.2 质量过滤

质量过滤指在抽出纯文本后，用规则或模型把"低质"文档删掉或降权。主流有三类手段：启发式规则过滤、基于语言模型困惑度的过滤、以及基于分类器的过滤。三者常叠加使用，目标是提高保留文本的"平均有用度"，但每一类都有自己的偏置，会误伤某些合法文本。

启发式规则过滤是最直接的一档：用一批人写死的统计判据剔掉明显不像自然语言的页面。最常被复用的一套是 Gopher（MassiveText）规则——例如文档词数落在某区间、平均词长在合理范围、符号与词的比例不过高、以省略号结尾的行占比不过高、含足够多的常用停用词等；C4 还贡献了"删掉不以标点结尾的段落"这类规则。这些判据便宜、可大规模并行，但都是代理指标（proxy），会误杀合法但风格特殊的文本（如列表、代码、表格）。

第二档是困惑度过滤，源自 CCNet：用在高质量语料（通常是 Wikipedia）上训练的 n-gram 语言模型（KenLM）给每个文档打困惑度，困惑度太高（"不像 Wikipedia"）的判为低质。它的直觉是"越像干净参考语料越可能高质"。易错点也在此：这类过滤对 Wikipedia 风格有强偏置——流畅的废话能得高分，而代码、口语对话、技术写作等有价值但风格不同的文本会被冤枉。规范上要把它当"风格相似度"而非"真实质量"来理解。

第三档是分类器过滤：训练一个二分类器区分"高质/低质"，用它给全量文档打分并按阈值保留。GPT-3 与 RefinedWeb 都用过"以策划语料（如 Wikipedia、被点赞的网页链接）为正例、随机网页为负例"训练的质量分类器。FineWeb-Edu 更进一步，用一个 LLM 给网页的"教育价值"打分、再训一个回归/分类器去复现该打分，从 FineWeb 里筛出约 1.3T token 的教育向子集，在 MMLU/ARC 等知识推理基准上显著更好。要点是：分类器过滤把"什么算好"外包给了正例的选择——正例偏 Wikipedia，就会系统性偏向 Wikipedia 风格，这既是它的力量也是它的偏置来源。

质量过滤不是"客观删垃圾"，而是"按某个质量代理重塑数据分布"。因此它必然和下游目标耦合——过滤越狠，语料越干净但越窄；过滤太松则噪声多。具体阈值（词数下限、困惑度分位、分类器保留比例）各家不一且随代际变，属于要按论文时点锚定的量，凭记忆填某个数值不可取，无一手坐实处标「待核」。

## 08S-11.3 去重

去重指删除语料里的重复或近重复内容，分精确去重与近似去重两类。精确去重删完全相同的文档或长的完全相同子串；近似去重删"高度相似但不完全一样"的文档，工业上主要用 MinHash + LSH。去重被反复证明能提升模型表现、减少对训练数据的逐字记忆（从而降低隐私/版权风险并改善泛化），是数据工程里承重的一步。

先说为什么必须去重。网页里同一段文字会被无数站点转载、模板会重复上万次。一个被广泛引用的例子：C4 里有一句 61 词的英文句子重复了 6 万多次。若不去重，模型会把算力浪费在背诵这些高频重复上，还更容易逐字吐出训练文本。Lee et al. 2021 证明去重后模型逐字记忆减少约 10 倍，并能用更少步数达到同等或更好精度。

精确去重有两种粒度。文档级：对整篇算一个哈希，哈希撞了就当重复删掉——快但只能抓"一字不差的整篇"。子串级：用后缀数组（suffix array）找出所有超过某长度阈值（如 50 token）的完全相同子串并删除，能抓到"文档里嵌了一大段别处也有的文字"这种局部重复。后者正是 Lee et al. 2021 的 ExactSubstr 工具做的事。

近似去重要解决"改了几个字、加了标点就骗过精确匹配"的问题，核心是估计两文档的 Jaccard 相似度。把文档表示为其 n-gram（shingle）集合 A、B，Jaccard 相似度定义为

J(A, B) = |A ∩ B| / |A ∪ B|

直接两两算 Jaccard 是平方级、不可行。MinHash（Broder 1997）给出一个无偏估计：对集合里每个元素用同一个哈希函数 h 求哈希，取最小值 min h(·) 作为一个"最小哈希签名"。关键性质是两个集合的最小哈希相等的概率恰好等于它们的 Jaccard 相似度：

P[ min h(A) = min h(B) ] = J(A, B)

用 k 个独立哈希函数得到长度 k 的签名，两签名逐位相等的比例就是 J 的无偏估计——把"比对整集合"压缩成"比对短签名"。

即便有了签名，签名两两比较仍是平方级，于是用 LSH（局部敏感哈希）的分带（banding）法把候选对筛出来：把长度 k 的签名切成 b 个带、每带 r 行（k = b·r），只要有任意一带完全相同就当候选重复对。两个相似度为 s 的文档至少落进同一桶（成为候选）的概率是

P(候选) = 1 − (1 − s^r)^b

这条曲线关于 s 是一条 S 形：相似度高的对几乎必被选中，低的几乎被跳过，拐点（近似阈值）约在

s* ≈ (1/b)^(1/r)

调 b 与 r 就能把"判为重复"的相似度阈值调到想要的位置。这样近重复检测从平方级降到接近线性，可在万亿 token 规模上跑通。

n-gram 的 n、签名长度 k、以及 (b, r) 的选择共同决定"多相似算重复"和查准/查全的权衡，各家取值不同且随规模调，属要锚论文的参数，不要凭记忆填。去重还有"跨快照 vs 快照内""全局 vs 分片"的工程选择——FineWeb 的一个反直觉发现是"过度全局去重"未必更好，说明去重强度本身也是要消融的超参，不是越狠越好。具体阈值/去重比例无一手坐实处标「待核」。

## 08S-11.4 领域混配

领域混配（data mixture / domain reweighting）指决定各来源（网页、代码、书籍、百科、学术……）在最终训练语料里各占多大采样比例。同样一堆来源，权重不同训出的模型能力谱就不同——多给代码则编码强、多给网页则通用广。因此混配权重是一个直接影响下游能力的关键超参，而不是随便按数据量摊。

最朴素的做法是手工设定权重：The Pile 就给每个来源一个人工设的采样权重（有的来源会被上采样重复多轮，如 Wikipedia/书籍权重高于其自然占比）。问题是手工权重靠经验、未必最优，且随目标任务变。于是出现了自动优化混配的方法。

DoReMi（Domain Reweighting with Minimax Optimization）是代表性一支：先用一个小"代理模型"（如 280M）在各领域上跑分布鲁棒优化（Group DRO），学出一组让"最差领域损失"尽量小的领域权重，再用这组权重重采样去训真正的大模型。原论文报告：在 The Pile 上，用 280M 代理定出的权重去训 8B 模型（约 30× 大），平均少样本下游精度比用 The Pile 默认权重高约 6.5 个百分点，并能用约 2.6× 更少的步数达到基线精度。关键点是权重可迁移——小模型学的权重能用到大得多的模型上。

另一支是面向目标分布的选择，代表是 DSIR（Data Selection via Importance Resampling）：给定一批"想要的目标样本"（如某下游任务的文本），在一个降维特征空间里估计每条原始数据相对目标分布的重要性权重，再按权重重采样，使被选子集的分布逼近目标。它解决的是"我知道想要什么样的数据，怎么从海量原始池里捞出匹配的"。相关的还有 DoGE（用代理训练时的领域梯度来估计各领域对泛化的贡献并据此重配权重）。

混配就是在"广度（覆盖多领域、通用性强）"和"专精（某领域权重高、该领域强）"之间调一个分布，且这个分布最好按下游目标来定，而非按原始数据量来定。一个易错点是把"某来源数据多"直接当成"该给它高权重"——恰恰相反，稀缺但高价值的来源（如书籍、代码、精选百科）常被上采样。另一个要记的联系：混配与 08S-8 缩放定律耦合——固定算力下，配比不同会改变"参数 vs 数据"的最优点。具体各来源权重、上采样轮数、DoReMi/DSIR 的超参各家不一且随代际改，属要锚论文时点的量，无一手坐实处标「待核」；DoReMi 与 DoGE 等不同方法给出的最优配比结论也可能不一致，冲突处两边都记。

## 08S-11.5 合成数据

`⚙锚 CS336 Sp26·未定型` 合成数据指用（通常更强的）模型生成文本，再把这些生成文本喂回训练流程，作为真实爬取数据的补充或替代。动机是真实高质文本有限、且可定向生成"教材式"高信息密度内容。这是数据工程里最活跃、最未定型的一块——什么时候有用、用多少、会不会导致退化，都还在快速演化、无定论，本节只讲机制与已知边界，不作结论。

代表性的正面证据是 Phi 系列的"教材式合成数据"路线：论文《Textbooks Are All You Need》（Phi-1，2023）用大量合成的"教科书质量"代码/解释文本预训练一个 1.3B 小模型，在编码基准上追平体量大约 10× 的模型。核心主张不是"数据量"而是"数据质量与结构"——精心生成的高密度文本每 token 信息量更高。另一支是"改写网页"（Rephrasing the Web / WRAP，2024）：用模型把已有网页改写成更规整的风格再训练，报告能提升算力与数据效率。两者共同的洞见是：合成数据的价值来自"提纯/重构"，而非凭空造。

最重要的风险是模型崩溃（model collapse）：如果反复用"上一代模型生成的数据"训练下一代，分布会一代代退化——先丢掉分布尾部（罕见但真实的模式），最终收敛到贫乏、重复的输出。Shumailov et al.（Nature 2024）在递归训练设定下给出了这一现象。给初学者的直觉：模型采样天然偏向高概率区域，用自己的采样再训自己，就像反复复印复印件，细节一代代丢失。

但"崩溃是否必然"取决于一个关键区分：替换 vs 累积。若每代都用合成数据替换真实数据，崩溃会发生；若把合成数据累积到（而非替换掉）真实数据之上，多项研究发现崩溃可被显著缓解甚至避免。相关实证还给出经验性配比迹象（例如某些设定下约 30% 高质改写合成 + 70% 真实数据在可见规模内不退化）——但这类具体比例高度依赖设定、属未定型区，务必标「待核」，不可当通用结论。另一条缓解线是验证/筛选：只把通过某种正确性或质量校验的合成样本留下，能减轻退化。

把合成数据当"受控的数据增强"而非"免费的数据来源"来理解——它能定向补足稀缺高质内容（尤其代码、推理、教材式解释），但必须与真实数据混合、并配去重与质量校验，否则有分布退化风险。因为本小主题随季度翻新极快，凡具体配比、代际稳定性、哪种校验最有效，均无跨代定论，硬标「未定型」，无一手坐实的数值标「待核」。
