## 5.1 Moore vs Mealy

### 5.1.1 什么是同步有限状态机

有限状态机（finite state machine, FSM）是一类时序电路：它在任一时刻只处于有限个"状态"之一，每个时钟边沿根据"当前状态 + 当前输入"跳到"下一个状态"，并对外给出"输出"。硬件里的标准同步 FSM 由三块拼成——一组存放当前状态的触发器（状态寄存器）、一块算下一状态的组合逻辑（次态逻辑）、一块算输出的组合逻辑（输出逻辑）：

```
        ┌──────────┐        ┌───────────┐ 次态 S'  ┌──────────┐
输入 X ─▶│ 次态逻辑  │──────▶│ 状态寄存器 │────┬────▶│ 输出逻辑  │──▶ 输出 Y
     ┌─▶│ (组合)    │        │ (触发器)   │    │     │ (组合)    │
     │  └──────────┘        └───────────┘    │     └──────────┘
     │        ▲    当前状态 S                  │           ▲
     └────────┴──────────────────────────────┘           │(Mealy 时 X 也接到这里)
              clk 每个上升沿把 S' 锁进寄存器成为新的 S      
```

初学者可以把 FSM 想成"带记忆的规则表"：组合电路（DL-2、DL-3）只看当前输入、没有记忆；而 FSM 靠状态寄存器记住"走到哪一步了"，于是同样的输入在不同状态下能产生不同反应。这正是它能做计数器、序列检测器、交通灯控制器、CPU 控制器的原因。

为什么必须是"有限"个状态？因为状态用固定位数的触发器存储，k 个触发器只能表示 2^k 种状态，天然有限。为什么强调"同步"？因为所有触发器共用一个时钟，状态只在时钟边沿整齐地更新一次，两次边沿之间电路是稳定的——这把"什么时候变"这件事从连续时间简化成一拍一拍的离散步进，是数字设计能大规模可靠工作的关键（与 DL-4.5/DL-6 的时序约束呼应）。

一个 FSM 要完整定义，需要给出：状态集合、初始（复位）状态、输入、输出、次态函数、输出函数。硬件 FSM 上电后必须能被复位信号强制回到已知初始状态，否则一开机状态随机、行为不可预测——这是易错点，实作中"忘了接复位"是常见 bug。

### 5.1.2 Moore 型：输出仅依赖当前状态

Moore 型状态机的输出只是"当前状态"的函数，与当前输入无关：

```
Moore:  Y = g(S)          （输出只看状态）
        S' = f(S, X)       （次态看状态 + 输入）
```

直觉：在 Moore 机里，"我现在处于哪个状态"就唯一决定了"我现在输出什么"。要改变输出，必须先经过一个时钟边沿跳到别的状态。可以把每个状态想象成挂了一块固定的输出牌子，走进这个状态就亮这块牌子。

用贯穿全篇的「检测 101」例子：Moore 版需要 4 个状态——S0（还没有有用前缀）、S1（刚收到 `1`）、S2（收到 `10`）、S3（收到 `101`，在此状态输出 1）。只有走到 S3 这个状态时输出才为 1，输出牌子挂在 S3 上，和"这一拍输入是什么"无关。

Moore 输出的一个重要特性是它"跟随时钟、干净稳定"：因为输出只在状态改变（即时钟边沿）之后才变，一个时钟周期内输出保持不变，不会因输入在周期中途抖动而抖动。代价是它通常要更多状态、且输出比输入晚一拍才反应（见 5.1.4）。

### 5.1.3 Mealy 型：输出依赖当前状态 + 输入

Mealy 型状态机的输出是"当前状态"和"当前输入"共同的函数：

```
Mealy:  Y = g(S, X)        （输出看状态 + 输入）
        S' = f(S, X)       （次态看状态 + 输入）
```

直觉：Mealy 机的输出牌子不是挂在状态上，而是挂在"状态之间的箭头（转移）"上——走哪条箭头，就给哪个输出。因为输出直接看当前输入，它能在同一拍内、不等下一个时钟边沿就对输入作出反应。

同样是检测 101，Mealy 版只需要 3 个状态——S0、S1（收到 `1`）、S2（收到 `10`）。当处于 S2 且当前输入为 `1` 时，就在这条转移上立即输出 1，而不必再花一个状态去"停靠"。这就是 Mealy 常比 Moore 少用状态的原因：它把"识别成功"这件事放在转移上表达，省去一个专门的输出状态。

Mealy 的代价是输出可能不稳定：由于输出随输入组合变化，输入在时钟周期内的任何毛刺（glitch，见 DL-3.6）都可能直接透传到输出，输出也可能在一个周期内变化。因此对时序敏感、需要干净输出的场合更偏好 Moore；追求少状态、快一拍响应时用 Mealy。

### 5.1.4 二者对比：时序、状态数、毛刺

Moore 与 Mealy 描述的是同一类计算能力（都能识别正则语言，见跨课孪生 L3-05），可相互转换，差别只在"输出接在哪"，带来三点工程差异：

```
              Moore                          Mealy
输出函数      Y = g(S)                        Y = g(S, X)
状态数        通常更多（需专门的输出状态）      通常更少
输出时序      与时钟同步、整周期稳定、晚一拍     组合响应、快一拍、可能随输入抖动
对输入毛刺    不敏感（输出只在边沿后变）          敏感（输入毛刺可透传到输出）
```

关键辨析——"晚一拍"到底指什么：在 Moore 机里，要让输出反映"刚发生的输入"，得等这个输入把状态推到新状态、经过时钟边沿之后，输出才在下一拍体现；Mealy 机则在当拍就能通过输入直接影响输出。所以同一个识别任务，Mealy 的"检测到"信号通常比 Moore 早一个时钟周期出现。这是初学者最容易混淆的点：不是谁对谁错，而是输出的时间对齐方式不同。

本篇 5.3.6 的 Python 逐拍仿真同时跑了这个 101 检测器的 Moore（4 态）与 Mealy（3 态）两版，并与一个独立的"重叠子串计数"参照比对，二者对同一输入串给出的"检测点"完全一致，实证了两种机型识别同一模式、可互相实现。

选择建议（教辅层）：需要输出稳定、便于后级再采样、或输出要驱动别的时序逻辑时选 Moore；需要省状态、要求对输入即时反应时选 Mealy；很多实际控制器是两者混用的。

#### 来源与时效
- 主锚：Harris & Harris《DDCA》RISC-V ed, 1st (2021), ch3 §3.4.3 *Moore and Mealy Machines*、§3.4 FSM 结构图（状态寄存器 + 次态逻辑 + 输出逻辑）。核实 2026-07-26。
- 交叉源①：Wakerly《Digital Design: Principles and Practices》（Moore 输出仅依赖状态、Mealy 依赖状态+输入、Mealy 输出可随输入变化并可能含毛刺、Mealy 常用更少状态）——与 H&H 定义一致。
- 交叉源②（本机 Python 3.11.15 实测，见 5.3.6）：101 检测器 Moore(4 态)/Mealy(3 态) 与重叠计数参照三方一致，佐证两机型等价可互换。
- 无冲突项。术语提示：Mealy 输出"快一拍"是相对同一识别任务而言的常见结论，非绝对定律；具体差异取决于状态划分方式，两源均以"输出接线位置不同"为本质，一致。

## 5.2 状态编码

### 5.2.1 状态编码问题：把抽象状态映射成 0/1

状态图里的状态是抽象名字（S0、S1…），但触发器只存 0/1，所以设计时必须给每个状态分配一串二进制码，这叫状态编码（state encoding）。用 k 位编码 N 个状态，只需满足能一一区分：

```
二进制编码所需触发器数：  k = ⌈log₂ N⌉
```

同一个状态图，选不同的编码方案会得到完全不同的次态/输出方程，从而影响电路的触发器数量、组合逻辑复杂度、速度和功耗。也就是说，编码是一个设计自由度，不唯一。初学者要建立的核心认识是：状态的"名字"无所谓，重要的是分配的"码"如何让后续的布尔方程更简单或更快。

### 5.2.2 二进制编码（binary / 顺序编码）

二进制编码把 N 个状态按普通二进制数依次编号：状态 0=`00…0`、状态 1=`00…1`……用 ⌈log₂ N⌉ 个触发器即可，是触发器数最少的方案。

例如 4 个状态只需 2 个触发器：

```
S0=00  S1=01  S2=10  S3=11
```

优点是触发器省——状态多时优势明显（如 16 状态只要 4 个触发器，而独热要 16 个）。缺点是次态译码逻辑往往较复杂：因为每次转移可能同时翻转多个状态位，次态方程要综合所有位来判断"现在在哪个状态"，组合逻辑较深。初学者常默认"编码当然用二进制"，但在触发器便宜、追求速度的工艺（尤其 FPGA）里，未必最优（见 5.2.4）。

### 5.2.3 独热编码（one-hot）

独热编码给每个状态分配一个专用触发器，任一时刻恰好有一个触发器为 1、其余全为 0（"one hot"＝只有一位是热的）。N 个状态就用 N 个触发器：

```
N=4 状态的独热编码：
S0=0001  S1=0010  S2=0100  S3=1000
所需触发器数 = N（每状态一个）
```

代价是触发器多（状态多时急剧增加），好处是次态与输出逻辑极简：判断"是否处于某状态"只要看那一位触发器，无须译码；很多次态方程退化成几个信号的与/或，组合逻辑浅、速度快。这在 FPGA 上尤其划算——FPGA 里触发器是现成、几乎免费的资源，而组合逻辑深度（查找表级数）才是速度瓶颈，所以工具常默认把 FSM 综合成独热。

易错点：独热编码上电后若不复位，可能落在"非法码"（如两位同时为 1 或全 0），这些非法状态若不处理可能死锁，因此独热 FSM 更依赖可靠复位。

### 5.2.4 格雷编码与编码权衡

格雷编码（Gray code）是一种相邻码字只差 1 位的编码。若把它用于状态转移大体沿单一方向推进的 FSM（如计数器、顺序前进的控制器），可使每次转移只翻转一个状态位：

```
3 位格雷序列：000 → 001 → 011 → 010 → 110 → 111 → 101 → 100
相邻两码仅 1 位不同
```

一次只翻一位带来两个好处：一是切换时的动态功耗和开关噪声更小；二是减少了"多位同时翻转、但因路径延迟不齐而中途经过错误组合"导致的输出毛刺（与 DL-3.6 的竞争-冒险同源）。但格雷编码只在状态转移接近线性顺序时才对得上，对转移四通八达的一般 FSM 未必有优势。

三种编码没有绝对优劣，权衡如下：

```
方案       触发器数        组合逻辑        典型适用
二进制     最少 ⌈log₂N⌉    可能较复杂       状态多、触发器紧张（ASIC 面积敏感）
独热       最多 N           最简、最快       状态适中、触发器便宜（FPGA 首选）
格雷       ⌈log₂N⌉         视转移而定       顺序推进的状态序列、低功耗/低噪声
```

核心结论：编码选择本质是"触发器面积 ↔ 组合逻辑复杂度/速度/功耗"的折中，取决于目标工艺与状态图形状。教辅层记住"二进制省触发器、独热省逻辑且快、格雷省翻转"即可，不需要背某个具体门数。

#### 来源与时效
- 主锚：Harris & Harris《DDCA》RISC-V ed, 1st (2021), ch3 §3.4.2 *State Encodings*（二进制 vs 独热，k=⌈log₂N⌉ 触发器 vs N 触发器，独热省次态逻辑、FPGA 常用）。核实 2026-07-26。
- 交叉源①：Wakerly《Digital Design: Principles and Practices》（状态分配影响电路成本、one-hot 用 N 个触发器且逻辑简单、格雷/相邻分配减少输出毛刺与切换）——与 H&H 一致，并补充格雷/毛刺论点。
- 交叉源②：Mano & Ciletti《Digital Design》（状态分配是设计自由度，不同分配得不同电路成本）——与上一致。
- 无公式冲突；⌈log₂N⌉ 与 one-hot=N 触发器三源一致。格雷编码的"低功耗/少毛刺"收益依赖转移是否顺序，属条件性结论，已在正文点明，非绝对。

## 5.3 FSM 设计流程

### 5.3.1 总览：从问题到门电路的五步

把一个用自然语言描述的时序任务变成实际电路，标准流程是五步，环环相扣：

```
① 画状态图      （识别需要哪些状态、状态间怎么转移、每态/每转移的输出）
② 列状态转移表   （把状态图翻成表：当前状态 + 输入 → 次态 + 输出）
③ 选状态编码     （给每个状态分配二进制码，见 5.2）
④ 写激励/输出方程 （由编码后的表，用卡诺图/化简得次态方程与输出方程，见 DL-2）
⑤ 门级实现       （触发器存状态 + 组合门实现方程，接成 5.1.1 的三块结构）
```

直觉：前两步是"想清楚要做什么"（与具体电路无关，纯逻辑），第三步是"选一种落地方式"，后两步是"变成真门电路"。初学者最容易在第①步偷懒——状态图错了，后面再化简都是错的；也容易忘记复位状态（每个 FSM 都要指定上电初始状态）。下面用检测重叠模式 `101` 的 Moore 机走完全程。

### 5.3.2 步骤 1–2：状态图与状态转移表

先想清楚要"记住"什么。检测 `101` 时，我们需要记住"已经匹配到模式的前几个字符"，于是有 4 个状态：S0（无有用前缀）、S1（已收 `1`）、S2（已收 `10`）、S3（已收 `101`，输出 1）。因为要检测"重叠"出现，匹配成功后不能清零，而要保留可复用的后缀。状态转移表（Moore，输出只标在状态上）：

```
当前状态  输入X  次态    | Moore输出Y(在当前状态)
  S0       0     S0     |
  S0       1     S1     |  S0:Y=0
  S1       0     S2     |
  S1       1     S1     |  S1:Y=0
  S2       0     S0     |
  S2       1     S3     |  S2:Y=0
  S3       0     S2     |
  S3       1     S1     |  S3:Y=1
```

理解转移的关键是"匹配失败时退到最长可复用后缀"，不是一律退回 S0。例如在 S3（刚见 `101`）又来 `0`，此时尾巴是 `1010` 的后两位 `10`，已是通往下一个 `101` 的有效前缀，所以退到 S2 而非 S0；在 S3 又来 `1`，尾巴 `1011` 的有效前缀是 `1`，退到 S1。这种"重叠复用"是序列检测器的常见易错点——初学者常错误地在匹配后无脑回到起点，漏掉重叠出现的模式。

### 5.3.3 步骤 3：状态编码

采用二进制编码（5.2.2），2 个触发器即可，状态位记为 (Q1,Q0)：

```
S0=00  S1=01  S2=10  S3=11
```

换一种编码（如独热用 4 个触发器）会得到不同的方程，但状态图与转移表不变——这体现了 5.2.1 的"编码是自由度"。

### 5.3.4 步骤 4：激励方程与输出方程

把编码代入转移表，得到以 (Q1,Q0,X) 为输入、以次态位 (Q1',Q0') 与输出 Y 为输出的真值表，再用布尔化简（DL-2.3 卡诺图）得到方程。对 D 触发器，"激励方程"就是次态方程本身（D 输入 = 次态）。化简结果：

```
Q1' = Q0·X' + Q1·Q0'·X
Q0' = X
Y   = Q1·Q0            （Moore 输出，只看状态，与 X 无关）
```

这些方程不是凭记忆写的，而是本机用 sympy 从转移真值表化简得到并核对（见 5.3.6 真实输出）。可以直观验证 `Q0' = X`：看步骤 2 的表，次态低位 Q0' 恰好在输入 X=1 的所有行为 1、X=0 的行为 0，所以 Q0' 就等于 X。输出 `Y = Q1·Q0` 也一望即知——只有 S3=`11` 两位皆 1 时 Y 才为 1。

易错点：D 触发器时激励方程＝次态方程，直接实现即可；但若用 JK 或 T 触发器，还要经过"激励表"把次态换算成 J/K 或 T 的输入，多一层转换（见 DL-4.2）。入门用 D 触发器最省心。

### 5.3.5 步骤 5：门级实现

最后按 5.1.1 的三块结构接线：2 个 D 触发器存 (Q1,Q0)（共用时钟与复位，复位到 S0=00）；一块组合逻辑按上面的次态方程算出 (Q1',Q0') 接到两个 D 输入；一块组合逻辑按 Y=Q1·Q0（一个与门）算输出：

```
Q0':  X ──────────────────────▶ D0 ─┐
                                     │ [FF0] ─┬─▶ Q0
Q1':  (Q0·X') + (Q1·Q0'·X) ────▶ D1 ─┐       │
                                     │ [FF1] ─┼─▶ Q1
                                     │        │
Y = Q1·Q0  ──(AND)────────────────────────────▶ Y
clk ─▶ 两个 FF 的时钟端；reset ─▶ 两个 FF 异步/同步清 0（初始 S0）
```

到这一步，抽象的"检测 101"就变成了确定的触发器 + 门电路，可以交给工艺实现。回顾全程会发现：设计的"思考"集中在前两步（状态图/表），后面都是机械的编码 + 化简 + 连线——这正是 FSM 方法论把复杂时序问题工程化的价值。

## 5.4 状态化简与分解

### 5.4.1 等价状态与状态化简

状态化简（state reduction / minimization）指在不改变外部输入-输出行为的前提下，合并"等价状态"以减少状态总数。两个状态等价的判据：

```
状态 P 与 Q 等价 ⇔ 对任意输入序列，从 P 出发与从 Q 出发
                    产生的输出序列完全相同
等价的充要条件（可迭代判定）：
  ① 对每个输入，P 与 Q 给出相同输出，且
  ② 对每个输入，P 与 Q 的次态也两两等价
```

直觉：如果从两个状态出发，外界无论喂什么输入都永远分不出差别，那它们对外就是"同一个状态"，留一个即可。状态少了，编码位数（⌈log₂N⌉）可能下降、触发器和组合逻辑随之变省，这是化简的动机。

常用手工方法是"隐含表 / 蕴含图"（implication chart）：把所有状态两两配对，先划掉输出就不同的对，再迭代划掉"其次态对已被划掉"的对，最后剩下的对即等价、可合并。教辅层不必掌握完整算法细节，理解"等价＝对外不可区分、可合并"这一核心即可。

易错点：Mealy 与 Moore 的等价判据略有措辞差异（Mealy 要比对"每个输入下的输出"，Moore 直接比"状态输出"），但本质都是"输出序列不可区分"。另外，"无关/未用状态"是另一回事——它是编码后多出来的非法码，靠指定复位和安全次态处理，不属于状态化简。

来源覆盖差异（据实记，非冲突）：正式的等价状态判据与隐含表算法在 Mano、Wakerly、Katz 等教材中系统讲解；本大主题主锚 Harris & Harris ch3 侧重 FSM 的设计与分解，对形式化状态最小化着墨较少，更强调"想清楚就用最少的必要状态"。因此本节的化简判据以 Mano/Wakerly 为主源、H&H 为背景。

### 5.4.2 FSM 分解（factoring）

FSM 分解（factoring state machines）指把一个庞大、状态爆炸的状态机，拆成多个较小的、相互协作（一个的输出作另一个的输入）的状态机。核心思想：

```
单个大 FSM（状态数 = 各子功能状态数的乘积，易爆炸）
        ↓ 分解为
多个小 FSM 协作（总状态数 ≈ 各子功能状态数之和，且各自更易设计）
```

直觉与最小例子：一个"带节日模式的交通灯控制器"若揉成一个 FSM，要为"每种灯态 × 是否节日模式 × 计时阶段"的每种组合各设一个状态，组合起来数量很大；分解成"模式 FSM（管普通/节日切换）"和"灯序 FSM（管红黄绿循环）"两个小机器、让模式 FSM 的输出去控制灯序 FSM，各自都简单清晰，状态从"相乘"降到"相加"。这正是 Harris & Harris ch3 用交通灯例子讲分解的动机。

为什么分解有用：一是抑制状态爆炸（状态数从乘积级降到求和级），二是提高可读性与可复用性（每个小 FSM 职责单一、可单独验证），三是便于团队分工。代价是要额外设计 FSM 之间的接口信号与握手，且要保证协作时序正确。

易错点：分解不是随便切，必须沿"功能上相对独立、耦合少"的边界切，否则子机之间信号来回纠缠反而更复杂。关联：这与软件工程里的"模块化/关注点分离"是同一种思想在硬件上的体现；再往上，多周期/微程序 CPU 控制器（跨课 →L3-02）就是大型 FSM，常按"取指/译码/执行阶段"分解思路来组织。

#### 来源与时效
- 主锚：Harris & Harris《DDCA》RISC-V ed, 1st (2021), ch3 §3.4.4 *Factoring State Machines*（把大 FSM 分解为协作的小 FSM，交通灯 + 模式控制器例子；分解降低复杂度）。核实 2026-07-26。
- 交叉源①：Mano & Ciletti《Digital Design》 / Wakerly《Digital Design: Principles and Practices》（等价状态定义、隐含表/蕴含图法做状态最小化、状态数减少降低成本）——提供 H&H 着墨较少的形式化状态化简判据。
- 交叉源②：Katz & Borriello《Contemporary Logic Design》（状态最小化的行匹配/隐含表方法、FSM 分解思想）——与上一致。
- 覆盖差异（非冲突）：形式化"状态最小化算法"主要在 Mano/Wakerly/Katz；H&H 更强调"分解"与"用够用的状态"。两条路线互补，均以"减少状态/复杂度而不改变外部行为"为目标，无语义分歧。
