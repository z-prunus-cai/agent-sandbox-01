## 6.1 关键路径与 Fmax

### 6.1.1 同步时序电路的心智模型

绝大多数数字系统是**同步时序电路**：所有状态元件（触发器/寄存器）由同一个时钟统一驱动，每个上升沿"拍一下"，把组合逻辑算好的结果锁进寄存器，作为下一拍的输入。整个电路因此像一台按节拍前进的机器，一个节拍就是一个**时钟周期** T_c。

理解时序分析，先建立这个画面：一段信号的旅程总是「从一个寄存器的输出 Q 出发 → 穿过一片组合逻辑 → 到达下一个寄存器的输入 D」。这一段叫**寄存器到寄存器路径**（register-to-register path）。同步电路的全部时序问题，都是在问"这趟旅程在一个时钟周期里跑得完吗？会不会跑得太快反而闯祸？"——前者是建立时间约束（6.2），后者是保持时间约束（6.2）。

为什么要用同一个时钟统一节拍？因为这样设计者只需保证"每段路径在一拍内稳定"，就能推理整个系统的正确性，而不必追踪每根信号的绝对时刻。这种"用离散节拍把连续的电压变化驯服成一步步状态转移"的抽象，是数字系统能做大的根本原因，也是 DL-4「时序逻辑」与本大主题的连接点。

时序分析只关心**寄存器之间**的组合路径，不关心组合逻辑内部某根线什么时候变——只要它在下一个时钟沿到来前稳定即可。初学者常误以为要算每个门的绝对时刻，其实只需算路径两端之间的总延迟。

### 6.1.2 关键路径与传播延迟

一片组合逻辑里，从任一输入到任一输出往往有多条通路，每条通路上的门延迟累加起来不一样。其中**延迟最大的那条通路**叫**关键路径**（critical path），它决定了这片组合逻辑的**传播延迟** t_pd（propagation delay，输入最后一次变化到输出最终稳定的最长时间）。

t_pd = 关键路径（延迟最长的输入→输出通路）上各级传播延迟之和

关键路径为什么重要？因为一个时钟周期必须长到足够让**最慢**的那条路径也算完；只要有一条路径没稳定，锁进寄存器的值就可能是错的。所以关键路径像木桶最短的那块板——它一个人决定了整块电路能跑多快。

一个 4 位行波进位加法器（DL-3.1），进位要从最低位一级一级"波"到最高位，关键路径就是这条进位链，逻辑深度随位宽线性增长；这正是 DL-3.2 超前进位（CLA）想缩短的那条路径。可见"化简/换结构缩短关键路径"（DL-2、DL-3）和"时序分析算关键路径"是同一枚硬币的两面：前者改电路，后者算后果。

关键路径不一定是"门最多"的路径，而是"延迟累加最大"的路径——不同门、不同扇出、不同连线的延迟不同，数门的个数只是粗略近似。另外，关键路径是针对 t_pd（最大延迟）说的；与之相对还有一条**最短路径**决定污染延迟 t_cd（见 6.2 保持约束），两者不要混。

### 6.1.3 逻辑深度与 Fmax

"逻辑深度"（logic depth）指关键路径上串联的门级数，是 t_pd 的一个直观代理量：逻辑越深、串联门越多，t_pd 越大，可达到的时钟频率越低。系统能稳定运行的**最高时钟频率** F_max 是最小时钟周期的倒数：

F_max = 1 / T_c(min)

而 T_c(min) 由建立时间约束给出（下一节 6.2 推导），它正比于 t_pcq + t_pd + t_setup。因此在其他量固定时：

关键路径 t_pd 越长 → T_c(min) 越大 → F_max 越低

这就是"关键路径/逻辑深度决定最高时钟频率"这句话的完整含义。想让芯片跑得更快（提高 F_max），本质上只有两条路：要么**缩短关键路径**（换更快的结构、减少串联门级，如 CLA、逻辑化简），要么**切分关键路径**（流水化，见 6.4）。

F_max 不是由"平均路径"或"门总数"决定的，只由**那一条最长路径**决定。哪怕全芯片只有一条路径慢，整块也得迁就它。这也解释了为什么工程上做时序收敛（timing closure）时总是盯着"最差路径"（worst negative slack）反复优化。

## 6.2 时序约束核算

### 6.2.1 建立时间约束（最大延迟约束，决定 Fmax）

寄存器要正确锁存，数据必须在时钟上升沿到来**之前**至少稳定 t_setup（建立时间）。把一趟寄存器到寄存器旅程的耗时算清楚：发送寄存器在时钟沿后经 t_pcq（clock-to-Q 传播延迟）才把新值送出，再经组合逻辑最长延迟 t_pd 到达接收寄存器的 D 端，且必须比下一个时钟沿早 t_setup 稳定。于是一个周期 T_c 必须满足：

T_c ≥ t_pcq + t_pd + t_setup

等价地，留给组合逻辑的时间上限为：

t_pd ≤ T_c − (t_pcq + t_setup)

这称为**建立时间约束**，又叫**最大延迟约束**（max-delay constraint），因为它对组合逻辑的最长延迟 t_pd 设了上限。它决定了最小周期 T_c(min) = t_pcq + t_pd + t_setup，从而决定 F_max（6.1.3）。

其中 t_pcq 是寄存器的时钟到 Q 传播延迟，t_setup 是接收寄存器的建立时间，两者都是器件（工艺库）给定的参数。

一个周期的"预算"被三块吃掉——寄存器把值送出去要花 t_pcq，组合逻辑算要花 t_pd，接收方提前锁好要留 t_setup。三块加起来不能超过周期长度，否则数据来不及稳定就被拍进去，锁到错值。

### 6.2.2 时序开销（sequencing overhead）

上式里 t_pcq + t_setup 这两项与"有用计算"无关，纯粹是寄存器自身占用的时间，称为**时序开销**（sequencing overhead）：

时序开销 = t_pcq + t_setup

理想情况下整个周期都该留给组合逻辑做有用的活，但时序开销先切走了一块。于是每个周期真正能用于组合计算的时间只有：

t_pd(可用) = T_c − (t_pcq + t_setup)

这个概念在 6.4 流水化时至关重要：把一条长关键路径切成 N 段、周期缩短，可以提高吞吐率，但**每一段都要重新付一份时序开销**，所以流水级数不是越多越好——切得太细时，时序开销会吃掉切分带来的收益。

时序开销是"每个流水寄存器界面各付一份"的固定成本，与组合逻辑多复杂无关；初学者容易忽略它，误以为把周期无限切小就能无限提频。

### 6.2.3 保持时间约束（最小延迟约束）

寄存器要正确锁存，数据还必须在时钟沿**之后**保持稳定至少 t_hold（保持时间）不变。危险来自"跑得太快"的信号：本拍时钟沿刚过，发送寄存器又太快地送出了**新**值，这个新值若在接收寄存器还没锁完旧值的 t_hold 窗口内就窜到了接收端 D，就会把本该锁的旧值冲掉。为避免这种竞争，最短那条路径的延迟必须够长：

t_ccq + t_cd ≥ t_hold

即对组合逻辑的**最短路径**延迟（污染延迟）设下限：

t_cd ≥ t_hold − t_ccq

这称为**保持时间约束**，又叫**最小延迟约束**（min-delay constraint）。其中 t_ccq 是发送寄存器的**污染延迟**（contamination delay，clock-to-Q 的最小延迟，即最快多久输出**开始**变化），t_cd 是组合逻辑的污染延迟（最短路径延迟）。

保持约束里**没有 T_c**——它与时钟周期无关！这是初学者最容易栽的地方。把时钟调慢（加大 T_c）能救建立时间违例，但**对保持违例毫无帮助**，因为保持约束两边都不含 T_c。保持违例只能靠改电路修（在太短的路径上故意插缓冲/延迟单元，增大 t_cd），否则芯片在任何频率下都错——这类芯片是废的。

建立约束防"太慢"（数据没及时到），靠加长周期或缩短 t_pd 解决；保持约束防"太快"（新数据抢跑冲掉旧数据），靠加长最短路径 t_cd 解决。两者一个管 max、一个管 min，方向相反，必须同时满足。

### 6.2.4 一个假想数值的算术核对（本机实测）

下面用一组**明确标注为假想**的教学数值（单位 ns，非任何真实器件参数）跑通上面的公式，验证算术自洽——周期怎样换算成频率、裕量正负怎样判定。真实输出如下（Python 3.11.15 @ Linux 6.18.5，基线串见抬头）：

```
sequencing overhead = 0.50 ns
Tc_min (no skew)    = 3.00 ns  -> Fmax = 333.3 MHz
Tc_min (skew 0.1)   = 3.10 ns  -> Fmax = 322.6 MHz
hold slack (no skew) = 0.45 ns  pass=True
hold slack (skew)    = 0.35 ns  pass=True
```

假想输入为 t_pcq=0.30、t_setup=0.20、t_hold=0.10、t_ccq=0.15、t_pd=2.50、t_cd=0.40、t_skew=0.10（ns）。可以核对：时序开销 0.30+0.20=0.50；T_c(min)=0.30+2.50+0.20=3.00 ns，对应 F_max=1/3.00 ns≈333.3 MHz；保持裕量 (t_ccq+t_cd)−t_hold=0.15+0.40−0.10=0.45 ns（>0，通过）。加入 skew 后（见 6.3）建立侧周期变长、保持侧裕量缩小，与公式一致。

这些数字只用来演示公式怎么用，不是任何芯片的实测规格；真实参数须查工艺库/数据手册，不得凭记忆填（brief §3 红线）。

## 6.3 时钟偏斜与抖动

### 6.3.1 时钟偏斜（clock skew）

理想中同一个时钟沿"同时"到达所有寄存器，但时钟要经过一张时钟分配网络（clock distribution network）传播，连线长度、缓冲级数、负载不同，导致不同寄存器实际收到时钟沿的时刻有差异。这个**同一时钟沿到达不同寄存器的最大时刻差**就是**时钟偏斜**（clock skew）t_skew。

skew 是**空间差异、静态的**（对给定布局大体固定，取最坏情况值）。它的坏处是同时侵蚀建立和保持两个方向的裕量。保守分析中，把 skew 加进两条约束：

T_c ≥ t_pcq + t_pd + t_setup + t_skew        （建立约束，skew 恶化）

t_ccq + t_cd ≥ t_hold + t_skew               （保持约束，skew 恶化）

接收寄存器的时钟**早到**（相对发送方），留给数据传播的窗口就变短，等效于建立时间变严；而接收时钟**晚到**又会让"新数据抢跑冲掉旧值"更容易发生，等效于保持时间变严。由于设计者事先不知道具体哪端早哪端晚，保守起见把 t_skew 同时算进两条约束的"更难"一侧。结论：**skew 加大了时序开销，两头都吃裕量**。

skew 恶化保持约束这一点尤其危险——如 6.2.3 所述保持违例调频率救不了，若 skew 又把保持约束推到违例，芯片直接报废。这正是为什么时钟树综合（clock tree synthesis）要极力压低 skew。

### 6.3.2 时钟抖动（clock jitter）

**时钟抖动**（clock jitter）指时钟沿在**时间上的随机波动**——同一个时钟输出，每一拍的周期长度并非恒定，围绕标称值上下抖动，源于时钟源（PLL/振荡器）噪声、电源噪声等。

skew 与 jitter 的关键区别：skew 是**不同寄存器之间**的**空间**差异（静态），jitter 是**同一时钟随时间**的**时序**随机波动（动态）。工程上常把 jitter（有时与 skew 合并为一个"时序不确定性"项 t_jitter/t_uncertainty）也保守地从可用周期里扣掉，主要收紧建立约束：

T_c ≥ t_pcq + t_pd + t_setup + t_skew + t_jitter   （把不确定性一并扣除的保守式）

如果这一拍时钟提前结束（周期偶尔偏短），组合逻辑可用的时间就临时变少，为保证最坏一拍也不违例，就得把这份最坏抖动预留出来，代价是可用于计算的时间进一步被压缩、F_max 进一步下降。

skew 与 jitter 容易被初学者混为一谈。记法：**skew 看"哪里"（不同点），jitter 看"何时"（不同拍）**。两者都缩小时序裕量，但来源和治理手段不同（skew 靠平衡时钟树，jitter 靠更干净的时钟源/电源）。另外 jitter 的具体分解（周期抖动、周期间抖动、长期抖动）属专家纵深，入门知道"它是时钟沿的随机时间波动、要保守从裕量里扣"即可。

## 6.4 流水化提频动机

### 6.4.1 关键路径卡住频率时怎么办

当关键路径 t_pd 已经很难再缩短、F_max 被 T_c(min)=t_pcq+t_pd+t_setup 卡死时，还想提频，可以**把长的组合关键路径切成若干段，在每段之间插入寄存器**，让信号分多个时钟周期、每周期只穿过一小段逻辑走完全程。这就是**流水化**（pipelining）。

把一条延迟为 t_pd 的关键路径切成 N 段、每段延迟约 t_pd/N，则每段的建立约束只需容纳 t_pd/N，最小周期近似降到：

T_c(min) ≈ t_pd/N + (t_pcq + t_setup)

于是 F_max 近似提高到约 N 倍（在时序开销可忽略的理想极限下）。注意周期里那份时序开销 (t_pcq + t_setup) 不随 N 缩小，是每段都要付的固定成本。

### 6.4.2 提的是吞吐率，不是单次延迟

流水化提高的是**吞吐率**（throughput，单位时间完成多少个任务），而**不是单个任务的端到端延迟**（latency）。一个具体输入仍要走完全部 N 段、花 N 个（更短的）周期才出结果，其总延迟甚至因为多插了 N−1 组寄存器的时序开销而**略有增加**；但因为各段可以像流水线工人一样**同时**处理不同的输入，稳态下每个周期都能吐出一个结果，单位时间产量随频率提升而提升。

最小例子（洗衣类比）：洗、烘、叠三步串行做，一批衣服要等三步全完；改成流水线——第一批在烘时第二批已在洗——单批总时间没变（甚至因交接略增），但单位时间"完成的批数"翻了几倍。数字流水线同理：切段=分工序，插寄存器=工序间的暂存台。

### 6.4.3 代价与边界（为 L3-02 CO-5 埋伏笔）

流水化不是免费午餐，入门需知三点代价：

其一，每增加一级流水寄存器，就多付一份时序开销 t_pcq + t_setup（还要加上 skew/jitter 的裕量，6.3）。当 t_pd/N 已经和时序开销同量级时，再切段收益递减甚至转负——所以流水级数有实际上限。

其二，流水化引入**冒险**（hazards）：数据冒险（后一条指令要用前一条还没写回的结果）、控制冒险（分支要等结果才知道跳不跳）。这些是 L3-02 CO-5（处理器流水线）的核心议题，硬件上要靠转发/前推、停顿（stall）、分支预测处理。本大主题只需知道"切分关键路径能提频，但会带来跨段依赖问题"这一动机与代价，具体机制留给 CO-5。

其三，多段间要保证功能等价，切分点要选在合适的信号边界上，控制逻辑也随之复杂化。

DL-6 从"关键路径决定 F_max"出发，最终把"想提频→切关键路径→流水化"这条动机链交给 L3-02——CPU 之所以要做流水线，根子就在本大主题的时序分析里。
