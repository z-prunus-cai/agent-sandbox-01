# L2-02·DL-4 时序逻辑基础

> 基线 Py3.11.15/np2.4.6/gcc13.3 @2026-07-25 ｜ 核实：2026-07-26 ｜ 先修：DL-1 数制编码、DL-2 布尔代数、DL-3 组合电路构件 ｜ 一手锚点：Harris & Harris《Digital Design and Computer Architecture》RISC-V ed, 1st, 2021, ch3 Sequential Logic Design ｜ 成熟度：GA（数字逻辑基础，几十年稳定）

时序逻辑（sequential logic）与组合逻辑最根本的区别是：组合逻辑的输出只由当前输入决定，而时序逻辑的输出还取决于**过去**的输入——也就是说它有"记忆"。这份记忆存放在**状态元件**（state element）里，靠电路的输出反馈回输入来保住。本章从最小的记忆单元（锁存器）一路搭到寄存器堆，再讲清楚"什么时候采样才安全"（时序参数）以及"采样出错会怎样"（亚稳态）。

## DL-4.1 锁存器

### 双稳态电路：记忆的物理根源

把两个反相器首尾相接（I1 的输出接 I2 的输入，I2 的输出接回 I1 的输入），就得到一个**双稳态电路**（bistable circuit）：它有两个输出 Q 和 Q̄、没有任何输入，却能稳定地记住 1 bit。

分析很简单，只有两种自洽的情况：

```
Q = 0  →  Q̄ = 1  →  逼着 Q = 0   （自洽）
Q = 1  →  Q̄ = 0  →  逼着 Q = 1   （自洽）
```

这两种状态各自稳定、互不跳变，所以叫"双稳态"。它是一切锁存器/触发器的核心：**记忆 = 交叉反馈**。

它的问题也很直白：没有输入，你没法控制它记的是 0 还是 1，只能"出厂随缘"。接下来的 SR 锁存器就是给它装上控制开关。

初学者常问"为什么两个反相器就能记住"。直觉是：每个反相器都在"复读"对方给它的相反值，两人互相印证，谁也不肯先松口，于是当前值被"锁"住了。这也是"latch（门闩）"这个名字的来历。

### SR 锁存器

SR 锁存器（Set/Reset latch）用两个交叉耦合的 **NOR 门** N1、N2 搭成，把双稳态电路加上两个控制输入 S（置位）和 R（复位），从而能主动写入。H&H 用 N1、N2 标注这两个 NOR 门，其真值行为如下：

| S | R | Q（下一态） | 含义 |
|---|---|-------------|------|
| 0 | 0 | Q_prev | 保持（记住旧值） |
| 0 | 1 | 0 | 复位（Reset，输出清 0） |
| 1 | 0 | 1 | 置位（Set，输出置 1） |
| 1 | 1 | 0（且 Q̄ = 0） | 非法/禁止 |

关键结论：S=1 把 Q 置 1，R=1 把 Q 清 0，S=R=0 时保持记忆，而 **S=R=1 是禁止状态**。

为什么 S=R=1 非法？此时两个 NOR 门的输出都被强拉到 0，于是 Q=0 且 Q̄=0——这违背了"Q 和 Q̄ 互补"的约定。更糟的是，如果 S、R 同时从 1 撤回到 0，两个门会同时试图翻转、竞争谁先稳定下来，最终落到哪个状态是不确定的（取决于两条路径的微小延迟差）。所以设计上要坚决避免 S=R=1。

SR 锁存器是理解一切状态元件的起点，但它有两处不好用：一是有非法输入组合要人为回避，二是它是"输入一变、输出立即跟着变"，没有一个统一的时间基准。D 锁存器就是来修掉这两个毛病的。

### D 锁存器

D 锁存器（D latch，也叫透明锁存器/电平敏感锁存器）在 SR 锁存器前面加一层逻辑，把两个输入合并成一个数据输入 D 和一个时钟/使能输入 CLK，从内部保证永远不会出现 S=R=1 的非法情况。它的行为是：

```
CLK = 1 : Q = D          （D 直接"穿过"到 Q，锁存器透明 transparent）
CLK = 0 : Q = Q_prev     （Q 保持不变，锁存器不透明 opaque）
```

也就是说，只要 CLK 为高电平，输出就实时跟随输入变化——所以它叫**电平敏感**（level-sensitive）；CLK 一旦拉低，最后那一刻的 D 值就被冻结保存。

直觉上可以把 CLK=1 想成"门开着，水（数据）自由流过"，CLK=0 想成"门关上，水被截在里面"。"透明"这个词就是说：门开着的时候你从输出端能直接"看穿"到输入。

内部实现：D 和 CLK 经过一小片组合逻辑产生 S、R 送给 SR 锁存器。当 CLK=0 时强制 S=R=0（保持）；当 CLK=1 时让 S=D、R=D̄，于是 Q 跟随 D。因为 S、R 由同一个 D 派生，永远互补，天然规避了 S=R=1。

D 锁存器最大的陷阱是它的透明性：在 CLK=1 的**整段时间**里，输入的任何抖动都会立刻传到输出。如果一个反馈系统里用 D 锁存器当状态元件，CLK 高电平期间数据可能"绕一圈又跑回来"，一个时钟脉冲里状态变了好几次，行为无法预测。要根治这一点，需要把"更新时刻"压缩成一个瞬间——这就引出边沿触发器。

## DL-4.2 边沿触发器

### D 触发器：只在时钟边沿采样

D 触发器（D flip-flop）与 D 锁存器输入相同（CLK、D），但行为关键不同：它只在 **CLK 的上升沿**（从 0 跳到 1 的那一瞬间）采样 D，把该值送到 Q 并保持整个周期；边沿之外无论 D 怎么变，Q 都不动。因为它由"边沿"激活，所以称为**边沿触发**（edge-triggered）器件。

一句话对比：D 锁存器是"CLK 高电平期间一直透明"，D 触发器是"只在 CLK 上升沿那一刻拍一张快照"。H&H 用"照相"打比方：快门只在边沿按下一次，D 必须在那一瞬间稳定。

这个"瞬间采样"正是同步数字系统的基石：全系统所有触发器共用同一个时钟，于是所有状态在同一时刻整齐更新，两次更新之间留出整段时间给组合逻辑安心计算，行为完全可预测。

### 主从结构：两个背靠背的 D 锁存器

D 触发器的经典内部实现是**主从结构**（master-slave）：两个 D 锁存器 L1（主）、L2（从）串联，由**互补时钟**控制（L1 用 CLK，L2 用 CLK̄）。

```
CLK = 0 : L1 透明、L2 不透明 → D 进入 L1，存到内部节点 N1（从级封锁，Q 不变）
CLK = 1 : L1 不透明、L2 透明 → N1 送到 L2 输出 Q（主级封锁，不再收新 D）
```

于是在 CLK 由 0 变 1 的那一刻，D 被"接力"送到 Q，而其余时间总有一级是封锁的，D 到 Q 的通路永远不会全程打开——这正好把 D 锁存器"整段透明"压缩成了"边沿瞬间导通"。

为什么必须两级、且时钟互补？因为任一时刻只允许一级透明，才能杜绝数据"一穿到底"。互补时钟保证 L1、L2 的透明窗口首尾相接但绝不重叠，数据每个周期只前进一站。

下面是本机对"D 锁存器（电平敏感）"与"主从 D 触发器（边沿触发）"的逐拍仿真，可直观看出两者区别（基线 Py3.11.15，仅内置逻辑）：

```
t   : [0, 1, 2, 3, 4, 5, 6, 7]
CLK : [0, 1, 1, 0, 0, 1, 1, 0]
D   : [1, 1, 0, 0, 1, 1, 0, 0]
Qlat: [0, 1, 0, 0, 0, 1, 0, 0]   ← CLK=1 期间实时跟随 D（如 t=2：D 变 0，Qlat 立刻变 0）
Qff : [0, 1, 1, 1, 1, 1, 1, 1]   ← 仅在 CLK 0→1 更新后保持（t=2 D 变 0 但 Qff 不动）
```

注意 t=2：CLK 仍为高，D 从 1 变 0，锁存器输出 Qlat 立刻跟着变 0（透明），而触发器输出 Qff 纹丝不动——这就是"电平敏感 vs 边沿触发"的分水岭。

### 触发器 vs 锁存器（易混辨析）

核心区别一句话：**锁存器电平敏感（CLK 高电平期间透明），触发器边沿敏感（只在时钟边沿更新一次）**。

初学者最容易把两者混为一谈，甚至把 "latch" 和 "flip-flop" 当同义词，这在做时序设计时会酿成大错。判据：问"CLK 保持高电平不变时，输入变了输出会不会跟着变？"——会跟（透明），是锁存器；不会跟，是触发器。现代同步设计几乎清一色用边沿触发器做状态元件，正因为它把状态更新钉死在一个可预测的瞬间；锁存器多用于对面积/功耗敏感或特定异步场合。

### 带使能触发器

带使能触发器（enabled flip-flop）多一个使能输入 EN，只有 EN=1 时才在时钟边沿装入新数据，EN=0 时无视时钟、保持旧值。

```
EN = 1 : 时钟边沿到来时 Q ← D
EN = 0 : Q 保持，忽略时钟边沿
```

它非常实用：想让某个寄存器"这一拍先别更新、等信号来了再更新"，就用 EN 控制。最简单的实现是在 D 前放一个二选一多路选择器（MUX）：EN=1 选 D，EN=0 选 Q 的反馈（把旧值又喂回去）。切记不要靠"关掉时钟"（clock gating）来实现使能——那会引入时钟毛刺和偏斜问题，初学阶段一律用数据回环的方式做使能。

### 带复位/置位触发器：同步 vs 异步

带复位触发器（resettable flip-flop）多一个 Reset 输入，Reset=1 时把 Q 强制清 0，Reset=0 时表现为普通 D 触发器。带置位触发器（settable）类似，只是把 Q 强制置 1。它们让系统上电或复位时能进入一个确定的已知状态。

复位分两种，务必分清：

```
同步复位（synchronous） : 只在时钟边沿生效——Reset=1 时下一个上升沿把 Q 清 0
异步复位（asynchronous）: 立即生效——Reset=1 一到，不等时钟就把 Q 清 0
```

同步复位的实现是在 D 前加逻辑（Reset=1 时把送入的 D 强制为 0），需要改动触发器的输入逻辑；异步复位则直接作用在触发器内部、优先级最高。选择权衡：同步复位对时序分析友好、不易受复位信号毛刺影响，但复位信号本身也要满足建立时间且时钟必须在跑；异步复位能在时钟未启动时也让电路归位，但释放（deassert）时若撞上时钟边沿可能引发亚稳态，需要专门的"异步置位/同步释放"处理。

### JK 触发器与 T 触发器

除了 D 触发器，经典教材还讲 JK 触发器和 T 触发器（在 H&H 的 RISC-V 设计方法里已很少用，但作为基础概念仍需知道）。

JK 触发器有 J、K 两个输入，其特性表为：

| J | K | Q（下一态） | 含义 |
|---|---|-------------|------|
| 0 | 0 | Q | 保持 |
| 0 | 1 | 0 | 复位 |
| 1 | 0 | 1 | 置位 |
| 1 | 1 | Q̄ | 翻转（toggle） |

JK 相当于修好了 SR "11 禁止"的版本：把 SR 的非法组合 11 重新定义成"翻转"。

T 触发器（Toggle）只有一个输入 T，可看成把 JK 的 J、K 短接在一起。它的次态方程独占一行：

```
Q(t+1) = T ⊕ Q(t)
```

即 T=0 时保持、T=1 时每个时钟边沿翻转一次。T 触发器天生适合做计数器（每来一个脉冲翻一下，就是二进制计数的最低位）。

为什么现代设计偏爱 D 而冷落 JK/T？因为 D 触发器的次态方程最简单——Q(t+1)=D，"想让下一拍等于什么，就把什么接到 D"，配合 HDL 综合最直接；JK/T 在手工搭计数器时省门，但在标准单元 + 综合流程里优势不再。任何 JK/T 触发器都能用一个 D 触发器加少量组合逻辑等价实现（例如 T 触发器：令 D = T ⊕ Q）。

## DL-4.3 寄存器与寄存器堆

### 多位寄存器

一个 N 位寄存器（register）就是 **N 个共用同一时钟的 D 触发器并排放在一起**：D₃:₀ 四根输入线各接一个触发器的 D，Q₃:₀ 各接其 Q，所有触发器同一个 CLK。每个上升沿它们一起把 N 位数据整体锁存。

这一步的思想很朴素：单个 D 触发器只记 1 bit，要记一个字节/一个字，就并联多个、共享时钟让它们"步调一致"。它是 CPU 里程序计数器、指令寄存器、流水线段寄存器等一切"多位状态"的通用积木。原理图上常用一个带斜杠标注位宽（如 /4）的方块表示，省去画 N 个触发器。

### 寄存器堆：多读单写结构

寄存器堆（register file）是把一组寄存器组织成可按地址随机访问的小型存储阵列，配上专门的读口和写口。处理器里最常见的是**两读一写**（2 read, 1 write）结构，例如 RISC-V 的 32 个通用寄存器：一次能同时读出两个操作数、写回一个结果。

结构拆成两部分理解：

```
写口：写地址 → 译码器（decoder，N→one-hot）→ 选中唯一一个寄存器的使能端
      再配合写使能 WE，在时钟边沿把写数据装入被选中的寄存器
读口：每个读口 = 一个多路选择器（MUX），读地址作为 log2(寄存器数) 位选择信号
      从所有寄存器的输出里选出目标寄存器的值送到读数据线
```

为什么读口用 MUX、写口用译码器？因为"读"是从多选一（多个寄存器里挑一个输出→MUX 天然合适），"写"是把一个使能信号"派发"给指定的那一个寄存器（一对多的地址解码→译码器天然合适）。想要两个读口就放两个独立的 MUX，各自用各自的读地址——这正是为什么一条指令能同时取到 rs1 和 rs2 两个源操作数。

读口通常是**组合式**的（给地址就立刻出数据，不等时钟），写口是**时序式**的（在时钟边沿才真正写入）。一个常见易错点：同一拍里对某寄存器又读又写时，读到的是旧值还是新值取决于实现约定（例如很多设计约定"先写后读"或在流水线里靠转发解决），初学时要留意这个读写冲突问题。此外 RISC-V 的 x0 恒为 0，是寄存器堆的一个特例（读恒得 0、写被丢弃），并非普通寄存器。

#### 来源与时效
- 一手锚点：Harris & Harris《DDCA》ch3「Registers（N 个共享时钟的 D 触发器）」；寄存器堆的多读单写组织见《DDCA》ch5 Digital Building Blocks（Register Files）及 RISC-V 数据通路章节。核实 2026-07-26。
- 交叉核对（独立源）：Patterson & Hennessy《COD》RISC-V ed 数据通路章 + 附录（寄存器堆 = 译码器写口 + 多路选择器读口，2 读 1 写）；Wikipedia「Register file」对"读口用 MUX、写口用译码器 + 写使能、各端口带地址输入"的描述一致。

## DL-4.4 亚稳态与同步器

### 亚稳态：双稳态之间的"第三态"

任何双稳态器件除了两个稳定态（0 和 1），中间还存在一个**亚稳态**（metastable state）。H&H 用"山谷—山顶—山谷"作比：两个山谷是稳定态，山顶是亚稳态；小球停在山顶理论上平衡，但只要有一丝扰动就会滚向某一侧，而且**停在山顶的时间不确定**。

触发器若在采样瞬间输入正在跳变（违反建立/保持时间，见 DL-4.5），输出 Q 就可能落到既非 0 也非 1 的中间电平——即进入亚稳态，并可能维持一段不确定的时间才最终解析（resolve）到某一轨。

为什么会解析回来？因为触发器内部是交叉耦合的正反馈（回看 DL-4.1 的双稳态），只要 Q 稍微偏离山顶，反馈就会把它越推越远、最终推到 0 或 1 那一轨。麻烦在于"多久推到"是概率性的、无上界的——这就是亚稳态危险的本质：它不是必然出错，而是让"何时给出确定值"变得不可保证。

### 分辨时间与解析概率公式

如果触发器在随机时刻采样了一个正在跳变的输入，那么**等待时间 t 之后输出 Q 仍处于亚稳态**的概率为（公式独占行）：

```
P(t_res > t) = (T0 / Tc) · e^(−t/τ)
```

其中 t_res 是解析到 0 或 1 所需的时间，Tc 是时钟周期，T0 与 τ 是该触发器电路的固有参数。

直觉拆解 H&H 给的两项：T0/Tc 表示"输入恰好在坏时刻（孔径时间内）跳变"的概率——时钟越快（Tc 越小）撞上坏时刻的机会越大；e^(−t/τ) 表示"给定已进入亚稳态，等 t 之后仍未解析"的概率，τ 是刻画触发器脱离亚稳态快慢的时间常数（与内部交叉耦合门的延迟相关）。合起来一句话：**只要你肯等（t 足够大），输出解析成 0/1 的概率就指数级趋近 1**——但永远不等于 100%。

不要凭记忆去背 T0、τ 的具体数值：它们是器件/工艺相关参数，须查具体触发器的数据手册，教材里的数字只是示例。

### 双触发器同步器

异步输入（按键、跨时钟域信号等）无法保证满足建立/保持时间，必然偶尔触发亚稳态。**同步器**（synchronizer）的目标是把"输出仍亚稳"的失效概率压到足够低——注意它**不能把失效概率降到 0**，只能降低。

最常用的是**双触发器同步器**：两个背靠背触发器 F1、F2 串联，同用目标时钟域的时钟。异步输入先进 F1；就算 F1 采样时进了亚稳态，其内部信号 D2 还有近乎一整个时钟周期（Tc − tsetup）的时间去解析，等到 F2 采样时大概率已经稳定，于是 F2 输出一个干净的 0/1。

```
异步 D → [F1] →(D2, 有 Tc − tsetup 时间解析)→ [F2] → 干净的同步输出 Q
```

直觉：给亚稳态"多留一拍时间自己滚下山顶"。代价是同步器引入一拍（或多拍）延迟；要更低失效率就再加第三级触发器。核心记忆点：跨时钟域/异步输入进入同步系统前，必须过同步器，否则亚稳态会随机地把错误值传遍全系统。

### MTBF：平均无故障时间

把每次采样的失效概率乘上单位时间的采样/输入跳变次数，就得到失效率，其倒数即**平均无故障时间**（Mean Time Between Failures, MTBF）。对双触发器同步器，H&H 给出（公式独占行）：

```
P(failure)/sample  = (T0 / Tc) · e^(−(Tc − t_setup)/τ)
P(failure)/second  = (N · T0 / Tc) · e^(−(Tc − t_setup)/τ)
MTBF = 1 / [P(failure)/second] = (Tc / (N · T0)) · e^((Tc − t_setup)/τ)
```

其中 N 是异步输入每秒跳变次数。这里的分辨时间是 t_res = Tc − t_setup（一拍里扣掉第二级建立时间后，留给 D2 解析的时间）。

要读懂这个式子只需抓住指数项：MTBF 随 (Tc − t_setup)/τ **指数增长**。这意味着——只要给亚稳态多一点解析时间（提高 Tc、加同步级数增大有效解析时间），MTBF 就能从"几秒"暴涨到"远超宇宙年龄"。这就是为什么加一级触发器（多等一拍）如此有效。

本机代入 H&H 教材例子核对（基线 Py3.11.15）：Tc=2 ns、τ=200 ps、T0=150 ps、t_setup=100 ps、N=10/s，真实计算输出：

```
tres = Tc - tsetup = 1.90 ns
P(failure)/sample = 5.614e-06     （H&H 教材：5.6e-6，吻合）
P(failure)/second = 5.614e-05     （H&H 教材：5.6e-5/s，吻合）
MTBF = 17813 s = 4.95 hours       （H&H 教材：约 5 小时，吻合）
```

复现命令：将上述 5 个参数代入 `MTBF = (Tc/(N*T0))*math.exp((Tc-tsetup)/tau)`，`python3` 运行即得 17813 s。

一处独立源的记号差异（点明、不和稀泥）：FPGA/工程文献（如 Intel/Altera 白皮书、Ginosar 的 IEEE 教程）常写成

```
MTBF = e^(t_r / τ) / (T0 · f_clk · f_data)
```

形式看似不同，其实与 H&H 的式子**代数等价**：令 f_clk = 1/Tc、f_data = N、t_r = Tc − t_setup 代入即两式相同（本机核对：两种写法算出的 MTBF 同为 4.95 小时）。差别只在把哪些量记成频率、以及 T0 是否已把"孔径窗口"折进常数里——数值结论一致。

## DL-4.5 时序参数

### 建立时间、保持时间与孔径时间

触发器要正确采样，输入 D 必须在时钟边沿"前后一小段时间"内保持稳定。这段要求由三个参数刻画：

```
建立时间 t_setup : 时钟边沿之前，D 必须已稳定的时长
保持时间 t_hold  : 时钟边沿之后，D 必须继续稳定的时长
孔径时间 t_a     : 边沿前后 D 必须稳定的总窗口，t_a = t_setup + t_hold
```

这三条合称**动态纪律**（dynamic discipline）：只要输入在孔径窗口内稳定，触发器就保证不进亚稳态、正确采样。

H&H 的"照相"比喻在这里最贴切：拍照时被摄物体必须在快门开合的那一小段里别动，否则照片糊掉（进亚稳态）。t_setup 是"按下快门前要先站好"，t_hold 是"快门响完再多站一会儿"。违反动态纪律正是 DL-4.4 亚稳态的来源。

### 时钟-Q 传播延迟与污染延迟

输出侧也有两个时间参数，描述时钟边沿之后 Q 何时开始动、何时稳定：

```
传播延迟 t_pcq (clock-to-Q propagation) : 边沿之后，Q 保证已稳定（停止变化）的时刻
污染延迟 t_ccq (clock-to-Q contamination): 边沿之后，Q 可能开始变化（最早动）的时刻
```

必然有 t_ccq ≤ t_pcq：Q 最早在 t_ccq 开始动，最迟在 t_pcq 之前稳定下来，中间是它"正在变"的模糊区间。

初学者常把这两个和建立/保持搞混。记法：带 "q"（clock-to-Q）的是**输出**参数（触发器边沿后多久给出结果），setup/hold 是**输入**参数（边沿前后输入要稳多久）。t_pcq 决定"这一级触发器多晚才把数据交给下一级组合逻辑"，t_ccq 决定"数据最早多快就冲出来"——后者在保持时间约束里是主角。

### 建立时间约束（决定最高时钟频率）

考虑两个寄存器 R1、R2 之间夹一块组合逻辑（传播延迟 t_pd）。要让 R2 在下一个边沿正确采样，数据必须走完"R1 输出 + 组合逻辑"后，还赶在 R2 的建立时间之前稳定。由此得**建立时间约束**（公式独占行）：

```
Tc ≥ t_pcq + t_pd + t_setup
```

等价地，组合逻辑的最大延迟受限于：

```
t_pd ≤ Tc − (t_pcq + t_setup)
```

其中 (t_pcq + t_setup) 称为**时序开销**（sequencing overhead）。

这条约束是整个数字系统性能的命门：它给时钟周期 Tc 设了下限，也就等于给最高时钟频率 f_max = 1/Tc 设了上限。想让芯片跑得更快（Tc 更小），要么减小时序开销，要么缩短组合逻辑的最长路径 t_pd（即"关键路径"，见 DL-6）。它盯的是**最长路径 / 最坏情况**，因为最慢的那条路径决定了整块电路能多快。

### 保持时间约束（与频率无关）

保持时间约束管的是另一头：数据不能"跑得太快"，以免在 R2 还没过完保持时间时就把它的输入改掉了。用组合逻辑的**最小**延迟（污染延迟 t_cd）来写（公式独占行）：

```
t_hold < t_ccq + t_cd
```

即：

```
t_cd > t_hold − t_ccq
```

这里没有 Tc——**保持时间约束与时钟频率无关**，把时钟调慢也救不了它。这是初学者最反直觉的一点：建立时间违例可以靠"降频"解决，保持时间违例只能靠"往太短的路径上加缓冲器（buffer）增大 t_cd"来修。H&H 的例子里，一条过短路径违反 t_hold，做法就是插入缓冲器把 t_cd 从 25 ps 提到 50 ps。

### 时钟偏斜对约束的修正

真实系统里时钟到达不同寄存器有时间差，称为**时钟偏斜**（clock skew，t_skew）。做最坏情况分析时，它会同时侵蚀两条约束（公式独占行）：

```
建立（最坏 CLK2 早到）: Tc ≥ t_pcq + t_pd + t_setup + t_skew
保持（最坏 CLK2 晚到）: t_cd > t_hold + t_skew − t_ccq
```

直觉：偏斜是不确定的"时间误差预算"，无论建立还是保持，都得把它当额外裕量扣掉，让约束更苛刻。所以时钟树设计要尽量压低 skew。本条为 DL-6（时序分析与时钟）埋下伏笔，那里会把关键路径、Fmax、偏斜/抖动展开。
