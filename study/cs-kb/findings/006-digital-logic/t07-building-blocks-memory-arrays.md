## 7.1 移位器

### 7.1.1 三种移位：逻辑移位、算术移位、循环移位

移位器（shifter）把一个 N 位字整体向左或向右挪动若干位，空出来的位按"移位类型"填充。三种标准移位的区别只在**移出的位怎么处理、空位填什么**：

    逻辑左移 SLL x<<k ：低位补 0，高位移出丢弃
    逻辑右移 SRL x>>k ：高位补 0，低位移出丢弃
    算术左移 SLA       ：同逻辑左移，低位补 0（左移两者一致）
    算术右移 SRA x>>k ：高位补"符号位的复制"，低位移出丢弃
    循环左移 ROL       ：从高位移出的位绕回填入低位（不丢）
    循环右移 ROR       ：从低位移出的位绕回填入高位（不丢）

**逻辑移位空位一律补 0；算术右移空位补符号位（保号）；循环移位不丢位、移出的绕回来**。

为什么算术右移要补符号位？因为它要保持"移位 = 除以 2 的幂并向下取整"这个算术含义（DL-1.2 补码）。对补码负数，右移若补 0 会把符号位冲掉、数变成正的错值；补符号位才能让 −8>>1 = −4 成立。左移则逻辑/算术一致（都补 0），因为左移是乘 2，低位天然补 0。循环移位不改变位的总数、只是转圈，常用于密码学、CRC、位域旋转。

下面用 8 位真实枚举坐实"移位的算术含义"与各类型填充规则（基线 Py3.11.15 @2026-07-26，代码在 scratchpad，仅贴输出）：

    7.1 x=10110001 (unsigned=177, signed=-79)
    7.1 SLL by 2 = 11000100
    7.1 SRL by 2 = 00101100
    7.1 SRA by 2 = 11101100  (sign bit 1 replicated in from left)
    7.1 ROL by 3 = 10001101
    7.1 ROR by 3 = 00110110
    7.1 SLL(x,k)==x*2^k mod 2^8 for all x,k: True
    7.1 SRA==floor(signed/2^k) for all x,k: True

（1）算术左移几乎无人特意区分——因为它和逻辑左移完全相同，很多 ISA（含 RISC-V）干脆不设算术左移指令。（2）"逻辑右移当除法"只对**无符号数**成立；有符号数除以 2 的幂必须用算术右移，且对负奇数会得到"向下取整（往 −∞）"而非"向零取整"的结果（如 −79>>2 得 −20 而非 −19），这与 C 语言整数除法的"向零取整"不一致，是高频坑。（3）移位量 k 通常只取 0..N−1，超出范围的行为由具体 ISA 定义（有的取模 N），不要想当然。

### 7.1.2 桶形移位器：一拍完成任意位数移位的 MUX 阵列

桶形移位器（barrel shifter）是能在**一级组合逻辑（一个时钟周期内、无迭代）**把输入移动任意位数的电路。朴素的"移一位的移位寄存器"要移 k 位就得走 k 拍；桶形移位器把移位摊平成一张 MUX 网络，任意移位量都是纯组合、一次算出。

它的标准结构是**对数级联的 MUX 层**：按移位量的二进制位分层，第 j 层用一排 2:1 MUX 决定"是否移动 2^j 位"。移 N 位宽、最多移 N−1 位，需要：

    log2(N) 层，每层 N 个 2:1 MUX  ⇒  约 N·log2(N) 个 2:1 MUX

例如 8 位桶形移位器分 3 层：第 0 层由移位量最低位控制"移 0 或 1 位"，第 1 层控制"移 0 或 2 位"，第 2 层控制"移 0 或 4 位"，三层叠加就能实现 0..7 位任意移位。

把"移 5 位"拆成二进制 101 = 移 4 + 移 1，分别由第 2 层和第 0 层各自"接通"，第 1 层直通。这正是"用 log N 层解决 N 种情况"的分治思想，和 DL-3.2 超前进位把线性链改成对数深度是同一路数——**规整、对数深度、面积换速度**。为什么不用简单的循环移位寄存器？因为那要 k 拍、且拍数随数据变化，破坏定时；桶形移位器延迟固定（约 log N 级门），是流水线数据通路里做移位/对齐（如浮点尾数对齐、位提取）的标配。易错点：桶形移位器"层数 = log2(N)"是延迟量级，不是精确门延迟；具体皮秒依工艺，本报告不给数值（不编造）。

## 7.2 乘除法器

### 7.2.1 阵列乘法器：部分积的加法器阵列

阵列乘法器（array multiplier）把小学竖式乘法直接"硬件化"：两个 N 位数相乘，先生成 N 行部分积（partial products），每行是"被乘数 A 与乘数某一位 b_i 的与，再左移 i 位"，最后把这些错位的部分积全部相加，得到 2N 位积。

    P = Σ_{i=0}^{N-1} (b_i · A) << i        （b_i 是乘数第 i 位）

每个部分积位 = a_j · b_i（一个与门），把它们按错位排成一个二维阵列，用一片全加器阵列（DL-3.1）逐层累加进位，就是"阵列乘法器"——它是纯组合电路，规整得像一块方阵。

用 4×4 穷举坐实"移位部分积求和 = 真实乘积"（基线 Py3.11.15 @2026-07-26）：

    7.2 4x4 array multiplier (sum of shifted partial products)==a*b for all a,b in 0..15: True

乘法就是"移位加"——乘数某位是 1 就把被乘数移到对应权重上加进来，是 0 就跳过。硬件把"逐位判断再加"全部铺开成并行阵列，一次算完。为什么叫阵列？因为 N×N 个部分积与门 + 一片全加器构成规整的二维网格，非常适合 VLSI 平铺。它的延迟随 N 增长（进位要穿过阵列），大型乘法器会用更快的结构（如 Wallace 树、Booth 编码减少部分积行数）——这些属专家纵深，本报告只点名不展开。易错点：（1）N 位乘 N 位结果是 **2N 位**，截断成 N 位会丢高位（无符号溢出）；（2）有符号（补码）乘法不能直接套无符号阵列——高位部分积的符号扩展要特殊处理，或改用 Booth 算法，初学者常忽略这一点。

### 7.2.2 移位相减除法器：迭代的"试减—回复"

除法比乘法难，硬件最基础的做法是**恢复余数除法（restoring division）**：把长除法逐位硬件化。它维护一个余数寄存器 R 和商寄存器 Q，从被除数最高位起，每拍做三件事——余数左移一位并吸入被除数下一位、试着减去除数、根据够不够减决定商位与是否"回复"：

    每一拍（共 N 拍，i 从高位到低位）：
      1. R ← (R << 1) | 被除数第 i 位
      2. R ← R − 除数
      3. 若 R ≥ 0：  商第 i 位 = 1（保留这次减法）
         若 R < 0：  商第 i 位 = 0，并 R ← R + 除数（回复到减之前）

用 8 位穷举坐实商与余数（基线 Py3.11.15 @2026-07-26）：

    7.2 8-bit restoring divider (shift-subtract)==(a//b,a%b) for all a in 0..255,b in 1..15: True

这就是"你每一步都试着把除数减掉——减得动就记商 1、减不动就退回去记商 0"，和手算长除法一模一样，只是二进制里每步商只能是 0 或 1，判断"够不够减"只需看减完的符号。为什么叫"移位相减"？因为核心操作就是余数左移 + 相减。它是迭代结构：N 位除法要 N 拍（时序，不是一拍组合），这与阵列乘法器的"一拍组合"形成对比——乘法天然并行、除法天然串行。改进版"不恢复余数除法（non-restoring）"省掉回复步、用加减交替，稍快，属细节不展开。易错点：（1）除数为 0 要单独判、硬件会置异常标志（本节验证跳过 b=0）；（2）有符号除法要先取绝对值再修正商/余数符号，且"余数符号跟谁"各语言约定不同（C 是跟被除数），是坑；（3）除法延迟远高于乘法，这也是为什么高性能代码尽量避免除法、编译器把"除以常数"换成乘 + 移位（指向 L3-03 汇编优化）。

## 7.3 存储阵列单元

### 7.3.1 存储阵列的总体组织：位单元 + 行译码 + 列读出

存储阵列（memory array）把大量一位存储单元（bit cell）排成二维网格：地址的高位经**行译码器**（DL-3.4）选中一整行（字线 wordline 拉高），地址的低位经**列多路选择/读出电路**（DL-3.3）从被激活的行里选出要读写的那几位（位线 bitline）。一个 2^N × M 的阵列表示 2^N 个字、每字 M 位。

    容量（bit）= 行数 × 每行位数 = 2^(行地址位数) × 每行字数 × 字宽
    读一个字：行地址 → 行译码器 → 激活一条字线 → 该行各位驱动位线 → 列选出目标字

**所有半导体存储（SRAM/DRAM/ROM/Flash）都共用"二维阵列 + 行列译码"这个骨架**，区别只在"一个 bit 单元用什么器件存"。这就是为什么把它们放在一起讲。

把存储想成一栋大楼，行译码器是"选楼层"（字线），列电路是"选房间"（位线），地址就是门牌号。为什么要二维而不是一维长条？因为 2^N 个字若用一维译码需要 2^N 条选择线、译码器巨大；折成近似方形的二维阵列（比如行列各 √(2^N)）能让译码器规模和布线大幅下降，这是"面积/延迟"的工程折中。这个骨架直接就是 L3-02 CO-6 里 cache/主存"按地址取一行/一个块"的物理来源。

### 7.3.2 SRAM 单元（6T）：交叉耦合反相器锁存

静态随机存取存储器（SRAM）的标准位单元用 **6 个晶体管（6T）**：两个反相器交叉耦合成一个锁存（4 个晶体管，DL-4.1 的双稳态结构），外加 2 个访问晶体管（access transistor）把内部节点连到一对互补位线，由字线控制通断。

    6T = 交叉耦合反相器（4T，存 1 bit，双稳态）+ 2 个访问管（读写通路）

"静态"（static）指：只要供电，交叉耦合反相器会一直把状态顶住、**无需刷新**。读时字线打开、内部值把位线拉向对应电平；写时用较强的驱动强行翻转内部节点。

交叉耦合反相器是"两个人互相说对方是对的"的正反馈，一旦定下 0/1 就自锁，非常稳、访问快——这就是 SRAM 快的原因，也是它做 cache（CO-6）的原因。代价是每位要 6 个晶体管，面积大、密度低、成本高，所以只用在容量小但要极快的地方（寄存器堆、cache）。易错点：SRAM 是**易失（volatile）**的——断电即丢；"静态"不等于"非易失"，静态只是相对 DRAM 的"不用刷新"。

### 7.3.3 DRAM 单元（1T1C）：一个电容存电荷

动态随机存取存储器（DRAM）的位单元只用 **1 个晶体管 + 1 个电容（1T1C）**：电容存电荷代表 0/1，晶体管作为访问开关连到位线，由字线控制。

    1T1C = 1 个存储电容（存电荷 = 存 1 bit）+ 1 个访问晶体管

"动态"（dynamic）指：电容会通过漏电慢慢失去电荷，必须**周期性刷新（refresh）**——定时读出再写回——否则数据丢失。而且 DRAM 的读是**破坏性的**（读会把电容电荷放掉），读完必须立即写回。

DRAM 用一个电容顶替了 SRAM 那 6 个晶体管，所以密度极高、每位成本低——这正是主存（CO-6）用 DRAM、能做到 GB 级的原因。代价是慢（要充放电、要感测微弱电荷、要刷新）、且需要刷新逻辑与破坏性读写回。对比记忆：**SRAM 快而贵（6T、不刷新、易失）；DRAM 密而慢（1T1C、要刷新、易失、破坏性读）**——两者都易失，非易失是 ROM/Flash 的事。易错点：初学者常把"动态"误解为"断电能存"，恰恰相反，动态指"电荷会漏、要不断刷新"，仍是易失的。

### 7.3.4 ROM 单元与阵列：按连接与否编码固定值

只读存储器（ROM）在阵列的行列交叉点上"有没有器件连接"来编码固定的 0/1：某交叉点有连接（如一个晶体管把位线在字线选中时拉到某电平）就是一个固定位值，没有就是另一个。掩膜 ROM 在制造时就把内容"焊死"，是**非易失（non-volatile）**的——断电内容不丢。

    ROM 内容 = 交叉点连接图案（制造时固定）
    读：选中字线 → 该行各交叉点按"连/不连"驱动位线 → 读出固定字

**ROM 本质是一张固化的真值表 / 查找表**——地址是输入、每个字是对应输出，因此 ROM 可以直接实现任意组合逻辑函数（把真值表烧进去），这也是它和"可编程逻辑"（7.4）、FPGA 的 LUT 相通的地方。ROM 家族按可编程性演进：掩膜 ROM（出厂固定）→ PROM（一次可编程）→ EPROM/EEPROM（可擦写）→ Flash（块擦写，今天 SSD/固件的主力）。这些具体器件的擦写机制、耐久度属演进快的工程细节，本报告只列谱系、不给具体数值（不编造）。

ROM 像"一本印好的书"，DRAM/SRAM 像"可反复擦写的白板"；ROM 用来放开机固件、常量表。易错点：现代"ROM"多已是可多次擦写的 Flash，"只读"是历史命名，实际能写，但写得慢、按块擦——名字和现状有偏差，属**演进快·命名滞后**项。

## 7.4 可编程逻辑

### 7.4.1 PLA 与 PAL：可编程的与-或阵列

可编程逻辑阵列（PLA）和可编程阵列逻辑（PAL）都基于"任意布尔函数 = 积之和（SOP，DL-2.2）"这一事实，用两级阵列实现——一个**与阵列（AND plane）**生成需要的乘积项、一个**或阵列（OR plane）**把乘积项或成各输出。二者区别只在哪一级可编程：

    PLA：与阵列可编程 + 或阵列可编程   （最灵活，乘积项可被多个输出共享）
    PAL：与阵列可编程 + 或阵列固定     （每个输出的乘积项数固定，较快较便宜）

**PLA/PAL 是"把 SOP 直接做成可配置硬件"**——用户通过编程"接通/断开"阵列交叉点，把真值表化简出的乘积项烧进去，就得到想要的组合函数。

回忆 DL-2.5"真值表→SOP→与或门图"，PLA 就是把那张"与门层 + 或门层"的通用骨架做成一块芯片，交叉点是否连接由你编程决定。为什么 PLA 比 PAL 灵活？因为 PLA 的或阵列也可编程，一个乘积项能喂给多个输出、共享省面积；PAL 或阵列固定、每输出乘积项数受限，但结构简单更快、更便宜，历史上更流行。易错点：PLA/PAL 是"两级 SOP"结构，只擅长乘积项不太多的组合函数；乘积项爆炸的函数或时序逻辑要靠下面的 FPGA。它们是可编程逻辑的早期形态，今天多被 CPLD/FPGA 取代，属**演进快**的谱系起点。

### 7.4.2 FPGA：LUT + 触发器的可重构阵列

现场可编程门阵列（FPGA）是今天主流的可重构逻辑器件，核心是海量**可配置逻辑块（CLB / logic element）**排成阵列，块与块之间由**可编程互连（布线开关）**连接。每个逻辑块的两大件是：

    · 查找表 LUT（Look-Up Table）：实现任意组合函数
    · 触发器 FF（flip-flop，DL-4.2）：实现时序/状态存储

一个 N 输入 LUT 本质就是**一块 2^N 位的小 SRAM + 一个 2^N:1 MUX**（DL-3.3 用 MUX 实现任意函数）：把真值表的输出列写进 SRAM，N 个输入当选择线，就能实现该 N 变量的任意布尔函数。

    N 输入 LUT = 2^N 个 SRAM 配置位 + 2^N:1 MUX  →  可实现任意 N 变量布尔函数

**FPGA = "LUT 造任意组合逻辑 + 触发器造时序 + 可编程互连接线"，因此几乎能配置成任意数字电路**。这是把 7.3 的 SRAM 阵列（存 LUT 内容与互连配置）和 DL-4 的触发器组织成"可重构织物"的产物——正好收束本大主题。

ASIC 是"一次性焊死的电路"，FPGA 是"用 SRAM 配置、可反复重写的电路"——同一块芯片今天配成 CPU、明天配成图像滤波器。为什么用 LUT 而不用固定门？因为 LUT 用"查表"取代"算逻辑"，任意 N 变量函数都统一成一次查表，规整、可配置。触发器数量与 LUT 一一配套，是为了让每个逻辑块既能做组合又能做一位状态，方便实现流水线/FSM（DL-5）。易错点与**演进快标注**：现代商用 FPGA 的 LUT 输入数（常见 **4 到 6 输入**，具体依厂商/代际）、每块 LUT/FF 配比、以及专用块（DSP/RAM 块）都是**⚙演进快·厂商相关**参数——本报告给"LUT+FF+互连"的原理骨架与"LUT=SRAM+MUX"的等价，不锚定某厂商某代的具体数字（不编造）。FPGA 配置本身多存在 SRAM 里，故上电要从外部 Flash 重新加载配置，这也是易失配置的一个后果。

## 7.5 HDL 建模入门（SystemVerilog）

### 7.5.1 用 HDL 描述组合与时序，而非画门图

硬件描述语言（HDL）——业界两大主流是 SystemVerilog 与 VHDL——让工程师用**代码描述硬件的行为/结构**，再由综合工具（synthesis）自动映射成门级网表，而不是手画原理图。它是描述本大主题全部构件（移位器/乘除/存储/FPGA 配置）的实际工程手段。

SystemVerilog 里区分两类核心建模写法：

    组合逻辑：连续赋值 assign，或 always_comb（输出随输入即时变化，无记忆）
    时序逻辑：always_ff @(posedge clk)（在时钟边沿更新，用非阻塞赋值 <= ，有记忆）

**HDL 不是"编程"而是"描述电路"**——`always_ff @(posedge clk)` 综合出的是触发器（DL-4.2），`assign` 综合出的是组合门（DL-2）；写 HDL 时脑子里要始终是"这会变成什么硬件"，而不是"这段代码顺序执行"。

`assign y = a & b;` 就是一个与门；`always_ff @(posedge clk) q <= d;` 就是一个 D 触发器。为什么时序逻辑用非阻塞赋值 `<=`？因为它模拟"所有触发器在同一个时钟沿同时采样旧值再一起更新"，与真实硬件并行更新一致；组合逻辑用阻塞赋值 `=`。这是 HDL 初学者最大的坑：**用错赋值类型会综合出错误的硬件（意外的锁存器或竞争）**。另一个坑是"HDL 看着像 C，但它描述的是并行硬件"——所有 always 块是并发的，不是自上而下顺序执行的程序。

### 7.5.2 本机仿真坐实（Icarus Verilog 12.0）

prompt 把"仿真器是否可本机装"标为【待核】。**已坐实：可装可跑**。本机基线（Linux 6.18.5）用 `apt-get install iverilog` 安装了 Icarus Verilog 12.0 (stable)，编译并仿真了一段 SystemVerilog——一个带同步复位与使能的 4 位计数器（`always_ff` 时序 + `assign` 组合输出 `is_max`），验证计数、到 15 时 `is_max` 拉高、以及回绕：

    工具：Icarus Verilog 12.0 (stable) ｜ iverilog -g2012 ｜ 核实 2026-07-26
    DL-7.5 cycle 0: q=0 is_max=0
    DL-7.5 cycle 1: q=1 is_max=0
    ...（逐拍递增，此处略中间）...
    DL-7.5 cycle 14: q=14 is_max=0
    DL-7.5 cycle 15: q=15 is_max=1
    DL-7.5 cycle 16: q=0 is_max=0      ← 4 位计数器回绕 15→0
    DL-7.5 cycle 17: q=1 is_max=0

这段真实输出印证了 7.5.1 的两点：`always_ff` 建出的寄存器逐时钟沿保持并递增（有记忆）、`assign is_max=(q==4'hF)` 是随 q 即时变化的组合输出，且 4 位计数器在 15 之后自然回绕到 0（对应 DL-1 的模 2^N 回绕）。

需要点明的**规范与工具分账**：Icarus Verilog 是**仿真器**（验证行为对不对），不是**综合器**——它不把代码映射成真实门/FPGA 比特流。"这段 HDL 能综合成什么硬件"要靠综合工具（如 Yosys、厂商工具），本机未验证综合结果，故上述仅坐实"语言语义 + 仿真行为"，不作"综合出的门级实现"的结论。SystemVerilog 的语言语义以 IEEE Std 1800 为准（本机用 iverilog 的 `-g2012` 对应 2012 版子集，非全量支持）——工具对标准的覆盖度属**⚙演进快**，个别高级语法 iverilog 未必支持，须以所用工具版本为准。
