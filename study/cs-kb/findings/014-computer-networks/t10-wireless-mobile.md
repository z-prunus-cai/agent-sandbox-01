## N10.1 无线链路特性与 CSMA/CA

### N10.1.1 无线链路为什么比有线链路难

无线链路把比特承载在自由空间传播的电磁波上，这带来几个有线链路几乎没有的困难。Kurose-Ross 归纳的主要特征包括：**信号强度随距离衰减（path loss / 路径损耗）**，电磁波扩散和被障碍物吸收使功率随传播距离迅速下降；**来自其他源的干扰（interference）**，同频段的其他设备（别的 Wi-Fi、蓝牙、微波炉）会叠加噪声；以及**多径传播（multipath propagation）**，信号经不同路径反射后在接收端错位叠加，造成信号模糊。

对初学者而言，最该建立的直觉是「无线的差错率天生比有线高，而且高得多、还随时间和位置剧烈变化」。有线链路的比特差错率（BER）可以低到 10⁻¹²量级，几乎可忽略；无线链路则常在 10⁻³甚至更高浮动。这解释了 N2 里那个悬念——为什么可靠交付（链路层确认/重传）在 WiFi 上常做、在以太网上常省：无线信道太不可靠，若不在链路层就地纠错，把错误一路带到传输层（TCP）再由端到端重传，代价大得多。

### N10.1.2 信噪比、误码率与速率的权衡

无线接收质量由**信噪比（SNR, Signal-to-Noise Ratio）** 刻画，即接收到的信号功率与背景噪声功率之比（通常以 dB 表示）。SNR 越高，接收方越容易把 0 和 1 分辨清楚，**误码率（BER, Bit Error Rate）** 就越低。

给定一种调制编码方式，SNR 与 BER 之间大致是「SNR 升高 → BER 下降」的关系。

SNR ↑ ⇒ BER ↓

无线系统据此做**自适应调制（adaptive modulation）**：SNR 高时切到高阶调制（每个符号携带更多比特，速率高但对噪声敏感），SNR 低时退回低阶调制（速率低但更抗错）。这就是为什么你离路由器越远、连接速率越低——不是路由器「限速」，而是 SNR 下降后设备主动选了更稳健、更慢的调制档，用速率换可靠性。初学者可把它理解成「信号差就说话说慢一点、重复多一点，以免对方听错」。

### N10.1.3 隐藏终端与暴露终端问题

无线共享介质上有两个有线以太网不会遇到的经典麻烦。**隐藏终端问题（hidden terminal problem）**：A 和 C 都想发给中间的 B，但 A 和 C 相距太远、彼此的信号到不了对方，于是 A 在发时「听不到」C 也在发，两者在 B 处相撞而双方都不自知。**暴露终端问题（exposed terminal problem）**：B 正在发给 A，附近的 C 听到 B 的信号就误以为介质忙而不敢发，其实 C 想发给的 D 在另一侧、根本不受 B 影响，这次「谦让」是多余的、白白浪费了本可并行的机会。

理解这两个问题的钥匙是「载波侦听（听介质忙不忙）是在发送方本地听的，但碰撞发生在接收方那里」。发送方听到的和接收方经历的不是同一处的电磁环境，所以「我这儿听着空闲」不等于「对方那儿收得干净」，「我这儿听着忙」也不等于「我发了就会干扰到别人的接收」。隐藏终端是「该避没避成」，暴露终端是「不必避却避了」——它们正是下面 RTS/CTS 机制要对付的核心场景。

### N10.1.4 为什么无线不能用 CSMA/CD，只能用 CSMA/CA

有线以太网用的是 **CSMA/CD（带碰撞检测的载波侦听多路访问）**：边发边听，一旦听到碰撞立即停发。无线做不到这一点，原因有二。其一，无线适配器**难以在发送的同时检测碰撞**——自己发出的信号功率远远压过远处传来的微弱信号，接收电路被自己「震聋」了，根本听不出有没有撞上别人。其二，就算能检测，也有隐藏终端问题（N10.1.3）使发送方本就侦听不到远处的竞争者。

因此 802.11 改用 **CSMA/CA（带碰撞避免的载波侦听多路访问）**：既然事后检测不了碰撞，就想办法在**事前尽量避免**碰撞。核心手法是「侦听到空闲后不立刻抢发，而是先随机退避一段时间再发」，把多个同时想发的节点在时间上错开，降低撞车概率；并配合链路层确认（收到完好帧就回 ACK）来确认到底有没有成功。初学者记住这组对照即可：有线是「撞了就停（Detection）」，无线是「尽量别撞（Avoidance）」，因为无线连「撞没撞」都当场看不清。

### N10.1.5 802.11 的 CSMA/CA 接入流程与帧间隔

CSMA/CA 的基本发送流程（Kurose-Ross 8E Ch7 描述）如下。发送方先侦听信道：若信道空闲持续一段固定的**DIFS（分布式帧间间隔，Distributed Inter-Frame Space）** 时间，则发送整帧（无碰撞检测、一发到底）；若信道忙，则选一个随机退避计数值，在信道空闲时递减、信道忙时冻结，减到 0 时才发送。接收方收到一个完好的帧后，等待一个更短的 **SIFS（短帧间间隔，Short Inter-Frame Space）** 就回送链路层 ACK。发送方在预期时间内没收到 ACK，就认为发生了碰撞/丢失，增大随机退避区间后重传。

各类帧间间隔的关键是它们的**长短次序**，而不是具体微秒值（微秒值随 PHY 不同，此处不逐一列，属待核 PHY 参数）：

SIFS < DIFS

SIFS 最短，是为了让「一次交互内的后续动作」（如回 ACK、RTS 之后的 CTS）享有最高优先级，抢在任何新发送之前完成，保证一问一答不被打断；DIFS 较长，是新的争用发送必须多等的时间。为什么无线要用链路层 ACK 而以太网不用？还是那句话——无线差错率高且发送方无法自行确认碰撞，只能靠接收方「收到了就吱一声」来闭环，这也是 N2 说的「可靠交付按链路差错率取舍」在无线上的落地。

### N10.1.6 RTS/CTS 信道预约（对付隐藏终端）

为缓解隐藏终端造成的长帧碰撞，802.11 提供可选的 **RTS/CTS 握手**。发送方在发数据前，先发一个短小的 **RTS（Request To Send，请求发送）** 帧给 AP/接收方，其中携带本次传输预计占用的时长；接收方回一个 **CTS（Clear To Send，允许发送）** 帧，同样广播这个时长。听到 CTS 的所有邻居（包括那些听不到原发送方的「隐藏」节点）都据此把自己的**网络分配向量（NAV, Network Allocation Vector）** 设为该时长，在这段时间内保持沉默。

这个设计的巧妙之处在于「用两个短帧的小碰撞风险，换一个长数据帧的免碰撞传输」。RTS 仍可能相撞，但它很短，撞了损失小、重来快；一旦 CTS 成功广播出去，接收方周围就被「清场」了，隐藏终端也会因为听到 CTS 而闭嘴，于是随后的长数据帧几乎稳赢。代价是每次传输多两次握手的开销，所以 RTS/CTS 通常只对超过某个长度阈值的大帧启用，小帧直接发更划算。初学者可类比会议室门口贴一张「本时段已被预约」的告示（CTS），连没看见预约人本尊、只看见告示的路人也不会闯进来。

## N10.2 802.11 WiFi 架构与帧

### N10.2.1 基本服务集（BSS）、AP 与两种组网模式

802.11 网络的基本构件是**基本服务集（BSS, Basic Service Set）**。在最常见的**基础设施模式（infrastructure mode）** 下，一个 BSS 由一个**接入点（AP, Access Point）** 加若干无线站点（station）组成，所有站点的流量都经由 AP 中转，AP 再通过有线接口把 BSS 接入更大的网络（家里/公司的以太网）。另一种是**自组织模式（ad hoc mode）**，站点之间不经 AP 直接互通，没有中心协调者。

每个 AP 用一个人类可读的名字 **SSID（Service Set Identifier）** 对外标识自己（就是你手机 WiFi 列表里看到的网络名），并有一个 MAC 地址 **BSSID**。初学者要抓住的定位是「AP 在无线世界里扮演的角色，相当于有线局域网里的交换机 + 网关」：它是本 BSS 内所有无线通信的必经枢纽，也是无线段与有线段之间的桥。绝大多数日常 WiFi 都是基础设施模式，ad hoc 模式了解概念即可。

### N10.2.2 信道与扫描：主动扫描 vs 被动扫描

Wi-Fi 工作在划分好的**频段与信道（channel）** 上（传统 2.4 GHz、5 GHz，Wi-Fi 6E/7 扩展到 6 GHz；具体信道划分随监管区域不同，属待核区域参数）。站点要加入网络，第一步是**扫描**发现周围有哪些 AP。**被动扫描（passive scanning）**：站点在各信道上守听 AP 周期性广播的**信标帧（beacon frame）**，信标里带 SSID 和 AP 的 MAC。**主动扫描（active scanning）**：站点自己广播**探测请求（probe request）**，收到请求的 AP 回**探测响应（probe response）**。

理解两者差别的关键是「谁先开口」。被动扫描省电、不打扰信道，但要等 AP 的信标到来（有间隔延迟）；主动扫描更快发现 AP，但要自己发帧、更耗电也更占信道。手机在锁屏时多用被动，在你主动点「搜索网络」时多用主动。扫描的产物是一张「候选 AP 列表 + 各自信号强度」，站点据此挑一个信号好的去关联。

### N10.2.3 关联与认证：加入一个 BSS 的握手

发现并选定 AP 后，站点要完成**关联（association）** 才能收发数据：它向目标 AP 发**关联请求（association request）**，AP 回**关联响应（association response）**。关联成功后，AP 通常会代表该站点向有线侧发一个 DHCP 请求，为它取得 IP 地址，此后 AP 就把发往该站点的帧接管过来转发。**认证（authentication）** 则决定「允不允许你连」：早期的开放系统/WEP 已被淘汰，现代主要是 WPA2/WPA3（承重的密码学原语属 g11/L5-04 范畴，本课只登记机制位置，不展开）。

对初学者，可把加入 WiFi 的完整链路串成一条：**扫描（找到 AP）→ 认证（证明有权限）→ 关联（登记到这个 AP）→ DHCP 取 IP（拿到网络层地址）→ 上网**。注意关联是「一对一独占」的——一个站点在同一时刻只关联到一个 AP，这一点在 N10.4 讲移动切换时很关键：从一个 AP 走到另一个 AP，本质就是「解除旧关联、建立新关联」。

### N10.2.4 802.11 帧格式

802.11 数据帧的字段布局如下（字节数据取自 Kurose-Ross 8E Ch7；载荷上限 2312 字节为 802.11 常引数值）：

```
+-----------+----------+---------+---------+---------+---------+---------+-------------+-------+
|  Frame    | Duration | Address | Address | Address |  Seq    | Address |   Payload   |  CRC  |
|  Control  |  / ID    |    1    |    2    |    3    | Control |    4    | (0..2312 B) |       |
+-----------+----------+---------+---------+---------+---------+---------+-------------+-------+
|    2 B    |   2 B    |   6 B   |   6 B   |   6 B   |   2 B   |   6 B   |   0..2312 B |  4 B  |
```

关键字段的语义如下。**Frame Control（2 字节）** 内含协议版本、类型/子类型（区分数据帧/控制帧/管理帧，RTS/CTS/ACK/信标都是其中某种）、以及 **To DS / From DS** 两个标志位（指示帧是发往还是来自「分布式系统 DS」即有线骨干），这两位决定了下面四个地址字段各自的含义。**Duration（2 字节）** 携带占用时长，正是 N10.1.6 里其他节点用来设置 NAV 的值。**Sequence Control（2 字节）** 给帧编号，用于接收方去重（因为链路层重传可能造成重复帧）。**CRC（4 字节）** 做差错检测（同 N2.2 的循环冗余校验思路）。

最需要专门讲的是**为什么有四个地址、以太网却只要两个**。以太网帧只需「源 MAC + 目的 MAC」；而 802.11 帧要区分「无线这一跳的收发双方」与「有线那头的最终源/目的」，所以地址被拆细：

Address 1 = 接收此帧的无线节点（如从站点到 AP 时，填 AP 的 MAC）
Address 2 = 发送此帧的无线节点（如站点自己的 MAC）
Address 3 = 与 AP 相连的路由器（网关）接口的 MAC，用于连接无线段与有线段
Address 4 = 仅在 ad hoc 自组织模式下用到

一个帧从「你的手机」发往「互联网上的某服务器」，在无线这一跳里，真正的收方是 AP（Address 1）、发方是手机（Address 2），但 AP 收下后还要知道该把它交给有线侧的哪个路由器接口（Address 3），才能接力送往服务器。以太网不需要这层区分，因为它没有「无线一跳」和「有线接力」的拼接问题。第四个地址平时用不上，只在没有 AP 的 ad hoc 模式里派上用场。

### N10.2.5 Wi-Fi 版本演进（Wi-Fi 4/5/6/6E/7）⚙演进快·锚版本

⚙演进快·锚版本（核实 2026-07-29）。802.11 通过一系列**修订（amendment）** 演进，Wi-Fi 联盟给主流修订起了「Wi-Fi 数字代号」以便消费者辨识：**Wi-Fi 4 = 802.11n**（引入 MIMO 多天线）；**Wi-Fi 5 = 802.11ac**（更宽信道、更高阶调制）；**Wi-Fi 6 = 802.11ax**（引入 OFDMA 子载波级多用户接入、1024-QAM，2019 年前后商用）；**Wi-Fi 6E** 是 Wi-Fi 6 向 6 GHz 新频段的扩展；**Wi-Fi 7 = 802.11be**（EHT, Extremely High Throughput）。

Wi-Fi 7 的时间线与关键特性需硬标版本：IEEE 于 **2024-09-26 批准** 802.11be，正式标准 **IEEE Std 802.11be-2024 于 2025-07-22 出版**；而 **Wi-Fi 联盟从 2024 年 1 月起开始认证（Wi-Fi CERTIFIED 7）设备**——即「产品先行、正式标准文本后至」是常态。Wi-Fi 7 的三个标志性特性是：**320 MHz 信道**（比 Wi-Fi 6 的 160 MHz 翻倍）、**4096-QAM（4K-QAM）** 每符号承载 12 比特（比 1024-QAM 的 10 比特多约 20% 数据）、以及**多链路操作（MLO, Multi-Link Operation）**——一个逻辑关联可同时横跨多个频段/信道收发，理论 PHY 峰值速率抬到约 46 Gbps。

初学者不必记牢每代的调制阶数，抓住「演进的两条主轴」即可：一是**把管道做宽做密**（更宽信道、更多空间流 MIMO、更高阶 QAM），二是**把一个信道更聪明地分给多用户**（Wi-Fi 6 的 OFDMA、Wi-Fi 7 的 MLO）。这些是标称峰值速率，实际吞吐远低于此，取决于距离、干扰与终端能力。由于此处版本与日期变化快，引用时务必以本节标注的核实日期为准。

## N10.3 蜂窝网络与 4G/5G

### N10.3.1 蜂窝架构：小区、基站与频率复用

蜂窝网络（cellular network）把地理区域切成许多**小区（cell）**，每个小区由一个**基站（base station）** 覆盖，用户设备（**UE, User Equipment**，即手机等终端）就近接入所在小区的基站。相邻小区使用不同的频率/编码以避免干扰，而相隔较远的小区可以**复用（frequency reuse）** 同一频率——这正是「蜂窝」命名的由来：像蜂巢一样用有限的频谱资源覆盖无限延展的区域。

初学者要抓住「为什么要分小区，而不是一个大天线覆盖全城」。核心是**频谱是稀缺且要复用的**：把区域切小、降低每个基站的发射功率，就能让远处的小区安全地重用同一段频率，从而在整片区域内同时服务的用户数远多于单基站方案。小区变小（微蜂窝/微微蜂窝）也让单位面积容量更高——这是 5G 用大量小基站（尤其毫米波下）密集组网的底层逻辑。蜂窝与 Wi-Fi 的根本分工在于：Wi-Fi 频段是**免许可、人人可用、自行避让**的，蜂窝频段是**运营商持牌、集中规划调度**的，所以蜂窝能提供更可控的覆盖与移动性。

### N10.3.2 无线接入网（RAN）与核心网（Core）的两分

蜂窝网络在架构上分成两大块。**无线接入网（RAN, Radio Access Network）** 负责「空中接口」——基站与 UE 之间的无线连接、无线资源调度；**核心网（Core Network）** 是运营商的「大脑与骨干」，负责用户鉴权、会话/连接管理、计费、以及把用户流量接入互联网（充当去往公网的网关）。UE 先经 RAN 接入，再由核心网托管其会话并转发至外部网络。

理解这个两分的意义在于「无线的归无线，管理的归管理」。RAN 处理瞬息万变的无线环境（信号、切换、调度），核心网处理相对稳定的会话状态与策略（你是谁、允不允许、流量往哪送、怎么计费）。这与 Wi-Fi 把很多职责压在单个 AP 上形成对比，也解释了蜂窝网络为什么能做无缝的大范围移动性——因为有一个集中的核心网在始终跟踪、管理每个用户的会话（详见 N10.4）。

### N10.3.3 从 4G LTE 到 5G NR 的组件对照

4G 与 5G 的架构组件有清晰的对应，Kurose-Ross 8E 用它们讲清「谁负责什么」。**4G LTE** 的接入网基站叫 **eNodeB（eNB）**，核心网叫 **EPC（Evolved Packet Core）**，其中关键网元有 **MME（移动性管理实体，负责鉴权与移动性/会话控制的信令面）**、**S-GW（服务网关）** 与 **P-GW（分组数据网网关，通往互联网的出口）**。**5G** 的接入网基站叫 **gNB（gNodeB）**，核心网叫 **5GC（5G Core）**，控制面与用户面进一步分离，关键网元有 **AMF（接入与移动性管理功能）**、**SMF（会话管理功能）**、**UPF（用户面功能，转发用户数据的出口）**。

对初学者，不必背全所有缩写，抓住一条对照即可：**信令/控制（谁能连、往哪走）与用户数据转发（真正的流量）在演进中被越拆越干净**。4G 已把控制面（MME 等信令）与用户面（S-GW/P-GW 转发）区分，5G 用「控制面/用户面分离（CUPS）」做得更彻底——AMF/SMF 管控制、UPF 专管转发。这样做的好处是可以把 UPF 下沉到离用户更近的边缘、降低时延，而控制面集中在云端，这是 5G 支持低时延应用的架构基础。

### N10.3.4 多址接入：FDMA / TDMA / CDMA / OFDMA

蜂窝系统怎么让一个小区里的多个用户共享同一段频谱？靠**多址接入（multiple access）** 技术，历代制式各有侧重：**FDMA（频分）** 给不同用户分不同频率；**TDMA（时分）** 分不同时隙；**CDMA（码分）** 让用户用不同的正交码同时同频发送、靠码字区分（3G 的核心）；**OFDMA（正交频分多址）** 把频带切成大量正交子载波、按子载波与时隙的二维网格灵活分配给用户（4G/5G 的核心，也是 Wi-Fi 6 借用的技术）。

这里的直觉可用「一间会议室多人说话」来类比：FDMA 是每人分一个隔音小房间（各占一条频率），TDMA 是大家轮流说、每人一个时间片，CDMA 是所有人同时在一个大厅说但各用一种「只有对应听者能解出」的编码语言，OFDMA 则是把大厅在「频率×时间」两个维度上切成很多小格子、按需把格子分给各用户。演进的方向是从「粗粒度独占」走向「细粒度、可动态调度的共享」，以榨出更高的频谱效率——这与 N10.2.5 里 Wi-Fi 的演进主轴是同一个道理。

### N10.3.5 5G 关键特性与演进（NR、频段、三大场景、5G-Advanced）⚙演进快·锚版本

⚙演进快·锚版本（核实 2026-07-29）。5G 的空口称 **5G NR（New Radio）**，工作频段分两大类：**sub-6 GHz（FR1）** 覆盖广、穿透好；**毫米波 mmWave（FR2，24 GHz 以上）** 带宽极大、速率高但覆盖近、易被遮挡。5G 定义了三大应用场景：**eMBB（增强移动宽带，追峰值速率）**、**URLLC（超可靠低时延通信，追低时延高可靠）**、**mMTC（海量机器类通信，追海量物联设备接入）**。**网络切片（network slicing）** 允许在同一物理网络上按场景切出多个逻辑「专网」，各自满足不同的速率/时延/可靠性目标。

3GPP 以「Release」推进标准，版本与冻结时间需硬标：**Release 15**（2018）是首个 5G 版本，含**非独立组网 NSA（借用 4G 核心网起步）** 与**独立组网 SA（用全新 5GC）**；**Release 16**（2020）、**Release 17**（2022）持续增强；**Release 18** 是 **5G-Advanced** 的首个版本，于 **2024 年 6 月冻结**；**Release 19** 是 5G-Advanced 的第二个版本，RAN1 功能冻结约在 **2025 年 6 月**、计划 2025 年底完成。「冻结（freeze）」指该版本技术内容定型、不再接受新的技术性变更。

其一，5G 不只是「更快」，它是**用三大场景 + 网络切片一张网服务差异极大的需求**（手机看视频、工厂机器人低时延控制、海量传感器）；其二，早期 5G 多为 NSA（先蹭 4G 核心网，只换空口）过渡，SA 才是完整的 5G；其三，本节所有版本号与日期变化极快，引用务必带核实日期，按锚版本对待。

## N10.4 移动管理与切换

### N10.4.1 移动性带来的核心难题：地址绑死在网络里

IP 地址天生**绑定在网络位置**上——一个地址属于某个子网/网络，路由器正是靠「地址前缀 → 网络」的对应把包送对地方（见 N3 的 CIDR 与最长前缀匹配）。这就和「终端会移动」直接冲突：当一台设备从它的**归属网络（home network）** 走到**被访网络（visited / foreign network）**，如果还用原地址，路由系统会把发给它的包送到原来的网络（它已经不在那儿了）；如果就地换一个新地址，那么正在进行的连接（比如一个 TCP 会话，四元组含原 IP）就会断掉。

理解这个两难是本小主题的钥匙：**移动管理要同时满足两个看似矛盾的目标——「让别人始终能用一个不变的名字/地址找到你」和「让数据实际送到你此刻真正所在的位置」。** Kurose-Ross 用两个地址来化解：**永久地址（permanent / home address）** 是移动节点的「不变身份」，别人永远用它来寻址；**转交地址（care-of address, COA）** 是它此刻在被访网络里的「当前位置」。剩下的全部机制，都是围绕「如何把发往永久地址的包，转送到当前的转交地址」展开。

### N10.4.2 归属代理、外地代理与间接路由

Kurose-Ross 讲的移动管理经典框架里有两个网络实体。**归属代理（home agent）** 位于归属网络，负责代表离家的移动节点「看家」——截获所有发往其永久地址的数据报。**外地代理（foreign agent）**（在 Mobile IPv4 中）位于被访网络，负责登记来访的移动节点、分配/代理转交地址。移动节点每到一个新网络，就要把自己的转交地址**注册（registration）** 给归属代理。

最基础的转发方式是**间接路由（indirect routing / triangle routing 三角路由）**：通信方（correspondent）把包发往移动节点的永久地址 → 包被路由到归属网络、由归属代理截获 → 归属代理通过**隧道（tunneling，把原包再套一层 IP 头封装）** 把包转发到当前的转交地址 → 被访网络把包交给移动节点。

Correspondent → Home Network（Home Agent 截获）→ 隧道 → Care-of Address（Visited Network）→ Mobile Node

初学者可用「邮件转寄」来理解：你搬家后在原地址（永久地址）设了转寄（归属代理），别人照旧寄到老地址，邮局自动把信重新装进一个写着你新地址（转交地址）的大信封（隧道）转投过去。它的缺点也一目了然——所有包都要先绕到归属网络再转出去，路径可能很绕（这就是「三角路由」低效之处）。**直接路由（direct routing）** 是一种优化：让通信方直接获知转交地址、绕过归属代理，但代价是通信方也要参与移动性管理、且切换时更复杂。

### N10.4.3 切换（handover / handoff）：换基站/AP 时不断线

**切换（handover，美式亦称 handoff）** 指移动节点在移动过程中，其无线接入点从一个基站/AP 转到另一个的过程。在蜂窝网络里，当 UE 从一个小区走向相邻小区、当前基站信号变弱而邻区变强时，网络（在核心网协调下）触发切换：把该 UE 的会话上下文从源基站转移到目标基站，并重定向其数据通路，力求**用户无感、正在进行的通话/会话不中断**。在 Wi-Fi 里，对应的是站点解除与旧 AP 的关联、与新 AP 重新关联（见 N10.2.3）。

理解切换的关键是「它是一个有状态迁移的过程，不是简单重连」。要保持会话不断，网络必须把「这个用户是谁、正在进行哪些连接、缓存了哪些未送达的数据」从旧接入点交接给新接入点，并在极短时间内切换数据转发路径。蜂窝网络因为有集中的核心网统一跟踪会话（N10.3.2），能做到比 Wi-Fi 平滑得多的切换——这也是你坐高铁刷视频不断线、而在两个 WiFi 间走动却常需重连的原因。切换决策要在「切早了（乒乓效应，来回反复切）」和「切晚了（信号太差掉线）」之间权衡。

### N10.4.4 Mobile IP：IPv4 与 IPv6 的标准化差异

**Mobile IP** 是把上述移动管理思想标准化的 IETF 协议族。**Mobile IPv4** 由 **RFC 5944（IP Mobility Support for IPv4, Revised）** 规定（它修订并取代了更早的 RFC 3344），定义了归属代理、外地代理、转交地址、注册与隧道转发这套机制。**Mobile IPv6** 由 **RFC 6275（Mobility Support in IPv6）** 规定。

两者一个值得记住的架构差异是：**Mobile IPv6 不再需要「外地代理」**——它利用 IPv6 本身的能力（如地址自动配置），移动节点在被访网络可自行获得转交地址、无需被访网络部署专门的外地代理路由器；而 Mobile IPv4 依赖被访网络里的外地代理。初学者可把它理解成「IPv6 把移动性做得更自给自足，少了对本地特殊路由器的依赖」。

Mobile IP 是**概念上重要、部署上有限**的协议。现实中的移动性绝大部分由**蜂窝网络自己的移动管理**（4G EPC / 5GC 内的机制，N10.3.3 的 MME/AMF 等）承担，而不是靠主机层面的 Mobile IP。所以本节的价值在于把「永久地址 + 转交地址 + 归属代理转发」这套通用心智模型讲清——它是理解一切移动性方案（包括蜂窝内部机制）的参照系，而非日常最常用的落地协议。
