时钟系统是整块芯片的「心跳源」：CPU 取指、总线传输、外设采样、通信波特率、延时长度，无一不是从某个时钟频率推算出来的。定时器（timer）则是把这个心跳「数出来」的硬件——它本质上是一个自动加一或减一的计数器，配合比较、捕获、中断，就能实现精确延时、周期任务、脉宽测量、以及最重要的一类输出：PWM（脉冲宽度调制），用一根数字引脚的「高电平占比」去近似模拟量，驱动电机、调光、发声。

本报告以参考板 TI EK-TM4C123GXL（Cortex-M4，TM4C123GH6PM）与 ARM Cortex-M 内核自带的 SysTick 为锚，讲清「时钟怎么来（时钟树 + PLL）→ 怎么数（SysTick 与通用定时器）→ 怎么用（输入捕获、输出比较、PWM）」这条主线。凡涉及具体频率、分频系数、寄存器位宽、定时器/PWM 数量的数值，均以锚平台手册为准并标注来源；换 SoC 或换 Cortex-M 型号，这些数值几乎一定不同，正文会在相应处提示。所有出现的频率与重载值都由公式加锚平台参数推出，并已在本机用 numpy 复核，不凭记忆填写。

## 6.1 系统时钟树与 PLL 配置

### 6.1.1 时钟源：内部 RC、外部晶振与主振荡器

一颗微控制器上电后必须先有一个时钟才能跑起来，这个最初的时钟来自「振荡器」。常见有两大类：芯片内部集成的 RC 振荡器（在 TM4C123 上是 16 MHz 的精密内部振荡器 PIOSC，以及一个约 30 kHz 的低频内部振荡器），和芯片外部接的晶体振荡器（主振荡器 MOSC，接一颗石英晶体，EK-TM4C123GXL 板载 16 MHz 晶体）。

内部 RC 振荡器的好处是「开箱即用、不占引脚、便宜」，缺点是频率精度和温漂较差，通常有百分之几的误差；外部晶振精度可到百万分之几（ppm 级），但要额外的晶体元件和两个引脚。做串口通信这类对时基精度敏感的场合，一般选外部晶振或经过校准的源；只做粗略延时、点灯，内部 RC 就够。初学者常见的误区是「以为芯片上电就跑在标称最高频率」——实际上多数 MCU 复位后默认跑在某个内部低速源上（TM4C123 复位默认用 PIOSC，且 PLL 不使能），要跑到高频必须由启动代码显式配置时钟树，这一步没做好，后面所有定时器、波特率算出来都是错的。

### 6.1.2 时钟树与 PLL 倍频

「时钟树（clock tree）」指的是：一个或几个振荡器作为根，经过选择器（MUX）、锁相环（PLL）、一级级分频器（divider）和门控开关，最终分发给 CPU 内核、各条总线、和每一个外设的这整张分发网络。之所以叫「树」，是因为同一个源会分叉出许多条频率各异的支路：CPU 想要尽量高的频率，而某个低速外设（如看门狗、RTC）只需要几十 kHz。

PLL（Phase-Locked Loop，锁相环）是时钟树里的「倍频器」：它能把一个较低的输入参考频率锁定并倍频到一个很高的内部频率（VCO 输出），再往下分频得到系统需要的各档时钟。这样做的价值在于——外部晶振通常只有十几 MHz（频率越高的晶振越贵、越难布线），而 CPU 想跑到几十甚至上百 MHz，PLL 就负责把这道「频率鸿沟」补上。

在锚平台 TM4C123 上，PLL 的输出频率固定为 400 MHz（这是 PLL 的 VCO 频率，与输入晶振频率无关——芯片内部会先把各种晶振频率折算到 PLL 需要的参考频率，晶振频率通过 RCC 寄存器的 XTAL 字段告知硬件）。这一点对初学者很反直觉：不是「16 MHz 晶振 × 某个倍数 = 目标频率」，而是「PLL 恒定产出 400 MHz，你再往下分频」。⚙演进快·锚平台 TM4C123·其它 SoC 的 PLL 结构（有无固定 VCO、倍频/分频字段划分）完全不同。

### 6.1.3 分频与系统时钟推导

得到 PLL 的高频输出后，要靠分频器把它降到系统实际使用的频率。系统时钟频率的一般关系是：

```
f_sys = f_源 / (divisor + 1)
```

在 TM4C123 上，使用 PLL 时的推导链是：PLL 输出 400 MHz，先被一个固定的 /2 预分频降到 200 MHz，再由 RCC/RCC2 寄存器里的 SYSDIV 字段做用户分频。因此常规路径下：

```
f_sys = 200 MHz / (SYSDIV2 + 1)
```

TM4C123 的最高系统时钟是 80 MHz。但 80 MHz 无法由 200 MHz 整除（200/80 = 2.5），所以芯片提供了一个特殊位 DIV400（RCC2 寄存器位 30）：置位后分频改为直接作用在 400 MHz 上、并把 SYSDIV2 与一个额外的最低位 SYSDIV2LSB 拼成更细的除数字段，于是：

```
f_sys = 400 MHz / (divisor + 1)
```

取 divisor = 4 即得 400 / 5 = 80 MHz——这正是 Valvano 教材与 TivaWare 里配置 80 MHz 系统时钟的做法。DIV400 与 SYSDIV2:SYSDIV2LSB 的具体位编码 ⚙演进快·锚平台 TM4C123·须查该型号 SoC Reference Manual 系统控制章·核实 2026-08-01。

本机用 numpy 复核了「最高频率对应的分频关系」这类算术（下一小节的 SysTick 重载值验证同源）：80 MHz 系统时钟意味着每个时钟周期 12.5 ns，是后面所有定时器/PWM 时间计算的基准。一个高频易错点：把系统时钟配错（比如以为是 50 MHz 实际是 80 MHz），会让你算出的所有延时、波特率、PWM 频率成比例偏移，且现象往往是「串口乱码 / 电机转速不对」，很难一眼看出根因在时钟。

### 6.1.4 外设时钟门控与多时钟域

时钟树的末端不是「一根线连到所有外设」，而是每个外设模块都有一个独立的时钟使能开关（门控，gating）。复位后大多数外设的时钟是关着的——这是为省电：不用的模块不给时钟就几乎不耗动态功耗。要用某个外设（GPIO 端口、某个定时器、UART……），必须先在系统控制寄存器里打开它对应的运行模式时钟门（TM4C123 上是 RCGCTIMER、RCGCGPIO、RCGCPWM 等 RCGCxxx 寄存器的对应位）。

对初学者，这是继「中断没使能」之后第二大「代码看着对但外设没反应」的陷阱：你配置了定时器寄存器，却忘了先给定时器上时钟，那么对定时器寄存器的写入要么无效、要么直接触发总线错误。正确顺序永远是「先开外设时钟门 → 等待几个周期让时钟稳定 → 再配置该外设寄存器」。此外，不同外设可能挂在不同频率的时钟域上（如某些定时器可选系统时钟或独立的低频时钟做 RTC），跨时钟域会带来同步开销，属于进阶话题，此处点到为止。

## 6.2 SysTick 周期节拍与延时

### 6.2.1 SysTick 是什么

SysTick 是 ARM Cortex-M 内核自带的一个 24 位递减计数器（down counter），几乎每颗 Cortex-M 芯片都有它（在 ARMv7-M 上是架构必备；在 Cortex-M0/M0+/M1/M23 等 ARMv6-M/v8-M Baseline 上是可选项，但实际几乎总会实现）。它的价值在于「可移植」：因为它属于内核而非某家厂商的外设，同一段 SysTick 延时/节拍代码几乎不用改就能在不同厂商的 Cortex-M 芯片间搬运——这与厂商专有的通用定时器（每家寄存器都不同）形成鲜明对比。

SysTick 的典型用途有两个：给操作系统提供周期性的「系统节拍（tick）」中断（RTOS 靠它推进调度，见大主题10），以及做简单的忙等延时（delay）。它的行为很纯粹：从一个「重载值」开始每个时钟周期减一，减到 0 后下一拍自动重新装入重载值，如此循环；到 0 的那一刻可选择产生一次 SysTick 异常。

### 6.2.2 四个寄存器与关键配置位

SysTick 由内核私有外设区（地址 0xE000E010 起）里的四个寄存器控制：

```
SYST_CSR   (0xE000E010) 控制与状态
    位0  ENABLE     计数器使能
    位1  TICKINT    到 0 时是否产生 SysTick 异常
    位2  CLKSOURCE  时钟源：1=处理器时钟, 0=外部参考时钟(实现相关)
    位16 COUNTFLAG  自上次读以来是否数到过 0(读清)
SYST_RVR   (0xE000E014) 重载值 RELOAD[23:0]，24 位
SYST_CVR   (0xE000E018) 当前计数值(写任意值会清零并清 COUNTFLAG)
SYST_CALIB (0xE000E01C) 校准值(TENMS 给出 10ms 参考, 可能无效需查 NOREF/SKEW)
```

由于是 24 位，RELOAD 的最大值是 0x00FFFFFF = 16777215（本机 numpy 核对：`0x00FFFFFF = 16777215`）。CLKSOURCE 选处理器时钟还是外部参考时钟，是各家实现差异点；在 TM4C123 上 SysTick 计数时钟可选系统时钟或系统时钟的 /4（属平台细节，⚙演进快·锚平台 TM4C123·核实 2026-08-01）。

### 6.2.3 重载值与节拍周期公式

要让 SysTick 每隔 N 个计数时钟周期产生一次事件，写入的重载值是 N−1，而不是 N。原因很直接：计数器从 RELOAD 一路减到 0 是包含 0 在内的，一共经历了 RELOAD+1 个时钟周期。因此：

```
经历周期数 N = RELOAD + 1
所以         RELOAD = N − 1
```

节拍时间周期与频率的关系为：

```
T_tick = (RELOAD + 1) / f_clk = N / f_clk
```

以锚平台 80 MHz 系统时钟、想要 1 ms 节拍为例，本机 numpy 推算：

```
f_sys   = 80_000_000 Hz
T       = 1e-3 s
N       = f_sys × T = 80000  个周期
RELOAD  = N − 1     = 79999  (0x1387F)
```

（真实输出：`SysTick 1ms tick: N cycles = 80000  RELOAD = 79999  (hex 0x1387f)`。）

24 位宽也给出了单次能计的最长间隔：RELOAD 拉满时

```
T_max = (0x00FFFFFF + 1) / f_sys = 16777216 / 80e6 ≈ 209.7 ms
```

（真实输出：`24-bit max RELOAD = 16777215 -> 最长间隔 = 209.7152 ms @80MHz`。）超过约 210 ms 的定时就不能靠单个 SysTick 周期实现，得在中断里软件累加计数（例如每 1 ms 中断一次、软件数到 1000 得 1 秒）。忘记「减一」是新手最典型的 off-by-one：写成 RELOAD = N 会让实际周期偏长一个时钟，1 ms 变成 1.0000125 ms，短期看不出、长期累积成明显时钟漂移。

### 6.2.4 忙等延时、中断节拍与 RTOS 时基

用 SysTick 做延时有两种范式。忙等（busy-wait）延时最简单：设好 RELOAD、清 CVR、轮询 CSR 的 COUNTFLAG 位直到它置 1，就过去了一个周期；但这期间 CPU 什么也干不了，纯烧时间，只适合极短或调试用途。更常用的是中断节拍：让 SysTick 周期性产生异常，每次中断把一个全局软件计数器加一，主程序或 RTOS 就以这个计数器为「系统时间」——延时变成「记下当前 tick，等到 tick 差达到目标」，等待期间 CPU 可以睡眠或做别的事。

这正是 SysTick 与 RTOS 的接口：绝大多数运行在 Cortex-M 上的 RTOS（如 FreeRTOS、Zephyr）默认就用 SysTick 作为调度时基，每个 tick 中断里检查是否有更高优先级任务就绪、是否有延时到期的任务要唤醒（本大主题只讲定时器本身，RTOS 调度见大主题10）。一个易错点：如果应用代码和 RTOS 都想用 SysTick，会冲突——用了 RTOS 就把 SysTick 交给内核管理，自己需要延时改用 RTOS 提供的 `vTaskDelay` 之类 API，而不要再直接碰 SysTick 寄存器。

## 6.3 通用定时器：输入捕获 / 输出比较

### 6.3.1 通用定时器结构与计数模式

「通用定时器（general-purpose timer）」是厂商在 SysTick 之外提供的、功能更丰富的外设定时器。它的核心还是一个计数器（可向上计数 count-up 或向下计数 count-down），但围绕计数器加了一圈可编程功能：装载/重载寄存器决定周期、匹配（match）寄存器用于比较、捕获（capture）寄存器用于记录事件时刻、预分频器（prescaler）用来把输入时钟先降速以延长可计时长。

最基础的两种工作模式是一次性（one-shot）和周期（periodic）：one-shot 数到边界就停、只触发一次，适合「延时 X 之后做一件事」；periodic 数到边界自动重载、循环触发，适合「每隔 X 做一次」。预分频器解决的是位宽不够的问题——一个 16 位定时器最多数 65536，直接用 80 MHz 时钟只能覆盖约 0.8 ms；先 /256 预分频再计数，同样 16 位就能覆盖上百毫秒。在锚平台 TM4C123 上，通用定时器还可拼成更宽的位宽（见 6.3.4）以进一步延长量程。

### 6.3.2 输入捕获

输入捕获（input capture）解决的问题是「测量外部信号的时间特征」：什么时候来了个边沿、两个边沿间隔多久、单位时间内来了几个脉冲。它的机制是——定时器计数器自由运行，当指定引脚上出现约定的边沿（上升沿/下降沿/双边沿）时，硬件自动把「此刻的计数值」抓拍进捕获寄存器，并可产生中断。软件读两次相邻抓拍值相减，就得到了这段时间对应的计数，再乘以每个计数的时长即得实际时间。

它的威力在于「时间戳由硬件精确记录，不受软件响应延迟影响」。如果改用软件轮询去测脉宽，你读到边沿的时刻已经比边沿真正发生晚了不确定的一段（受中断延迟、代码路径影响），测量必然带抖动；输入捕获把「记录时刻」这件事交给硬件在边沿发生的那一拍完成，软件晚点去读没关系，读到的仍是准确的抓拍值。典型应用：测量 PWM 输入的占空比/频率、测转速（数编码器脉冲）、超声波测距（测回波时间）、遥控信号解码。锚平台 TM4C123 的 GPTM 把这类模式细分为「边沿计数（edge-count，数脉冲个数）」与「边沿时间（edge-time，抓时间戳）」。

### 6.3.3 输出比较

输出比较（output compare）与输入捕获相对：不是「记录外部事件的时刻」，而是「在预定的时刻改变输出引脚」或产生中断。机制是——计数器自由运行，软件把一个目标值写进匹配寄存器；当计数值等于匹配值时，硬件自动翻转/置位/清零输出引脚，或产生一次中断。因为「到点动作」由硬件在匹配那一拍完成，输出的时序精度不受软件抖动影响。

输出比较是生成精确时序波形的基础：把匹配值和重载值配合调，就能控制输出电平在一个周期内何时翻转、翻转几次——这正是下一节 PWM 的底层原理（PWM 可以看成输出比较的一种特化、周期化用法）。它也可用来产生一次性精确延时后的信号沿、软件定时基准等。初学者容易混淆捕获与比较：一句话记忆——捕获是「信号进来、我记下时间」（输入），比较是「时间到了、我改变输出」（输出）；一个测量、一个生成。

### 6.3.4 锚平台 TM4C123 的 GPTM 概览

TM4C123GH6PM 的通用定时器资源相当丰富：六个 32 位通用定时器模块（每个可拆成两个独立的 16 位定时器 Timer A/Timer B，故最多十二个 16 位），外加六个「宽（wide）」64 位通用定时器（每个可拆成两个 32 位，故最多十二个 32 位）；此外还有两个符合 ARM FiRM 规范的看门狗定时器（看门狗见大主题12）。这套 GPTM（General-Purpose Timer Module）支持的模式包括：one-shot、periodic、实时时钟（RTC）、输入边沿计数、输入边沿时间（捕获）、以及 PWM。

对初学者，关键认识是「同一个定时器模块通过配置寄存器切换成很多种角色」——它不是六个只会数数的计数器，而是六套可编程时序引擎。每个模块由自己的运行模式时钟门（RCGCTIMER 对应位）供电，配置前必须先开门（回到 6.1.4 的陷阱）。⚙演进快·锚平台 TM4C123·核实 2026-08-01：定时器的个数、位宽、可拆分方式、支持模式高度平台相关，换 SoC（乃至换同系列不同型号）几乎一定不同，务必以该型号 SoC Reference Manual 的 GPTM 章为准。

#### 来源与时效
- 锚点：TM4C123GH6PM Datasheet / SoC Reference Manual「General-Purpose Timers (GPTM)」章（六个 32 位 + 六个宽 64 位定时器、可拆分位宽、one-shot/periodic/RTC/edge-count/edge-time/PWM 模式、预分频、捕获/匹配寄存器）@2026-08-01；TI 数据手册 https://www.ti.com/lit/ds/symlink/tm4c123gh6pm.pdf 「六个 32-bit + 六个 wide 64-bit general-purpose timers、两个 watchdog」经检索确认。

## 6.4 PWM 生成与占空比控制

### 6.4.1 PWM 与占空比

PWM（Pulse Width Modulation，脉冲宽度调制）是用一路「周期固定、高电平时间可调」的数字方波，去近似表达一个连续可变的模拟量。核心度量是占空比（duty cycle）：一个周期内高电平时间占整个周期的比例。

```
D = t_high / T_period      （0 ≤ D ≤ 1，常用百分数表示）
```

它为什么能「用数字近似模拟」？因为许多负载对高频方波的响应是「取平均」：LED 亮度、直流电机转速、加热功率，都近似正比于施加电压的时间平均值，而方波的时间平均值恰好等于 幅值 × 占空比。于是占空比 75% 的方波驱动 LED，人眼（因视觉暂留 + 足够高的频率）看到的就是约 75% 亮度。本机 numpy 生成一段占空比 0.75 的方波并求平均验证了这一点：

```
波形平均值(应≈D) = 0.75   目标D = 0.75
```

PWM 频率要足够高，高到负载/人眼来不及跟随单个脉冲的通断（LED 一般几百 Hz 到几 kHz 以上就不闪，电机、开关电源常用十几到几十 kHz 以上以避开可听噪声）。频率太低会看到闪烁或听到啸叫；这不是占空比的事，是周期的事，二者要分开调。

### 6.4.2 用定时器加比较器生成 PWM

PWM 在硬件上就是「一个计数器定义周期 + 一个比较器定义翻转点」的组合，本质是 6.3.3 输出比较的周期化特化。以向下计数为例：计数器从装载值 LOAD 一路减到 0（定义了一个周期），中途每当计数值等于比较值 COMP 时，输出引脚翻转一次电平。于是 LOAD 决定周期（频率），COMP 相对 LOAD 的位置决定占空比。软件只要改 COMP 就能实时调占空比，而 LOAD 一般设一次定死频率。

PWM 频率与装载值的关系（计数满一个周期需 LOAD+1 个计数时钟）：

```
f_PWM = f_pwmclk / (LOAD + 1)
```

其中 f_pwmclk 是喂给 PWM 计数器的时钟（可能是系统时钟，也可能经过 PWM 专用分频器）。占空比则由比较值与周期计数决定：

```
高电平计数 = D × (LOAD + 1)
```

本机 numpy 以锚平台 80 MHz、目标 20 kHz PWM 推算了一组真实值：

```
f_pwmclk = 80 MHz, f_PWM = 20 kHz
period_counts = f_pwmclk / f_PWM = 4000   (LOAD = 3999)
占空比 75% → 高电平计数 = 3000
```

（真实输出：`PWM 20kHz @80MHz: period_counts = 4000  LOAD = 3999`、`Duty 75%: high_counts = 3000`。）注意占空比的「高电平对应 COMP 高于还是低于阈值、向上还是向下计数」在不同芯片/模式下方向可能相反，具体以手册的波形定义为准——这是初学者调 PWM 时常把占空比调反的原因。

### 6.4.3 频率、分辨率与分频的权衡

PWM 的「分辨率」指占空比能被调到多细，取决于一个周期里有多少个计数步：

```
分辨率(bits) = log2(period_counts) = log2(f_pwmclk / f_PWM)
```

上面 20 kHz、period_counts=4000 的例子，本机算得约 11.97 bits（真实输出：`PWM 分辨率 ~ 11.97 bits`），意思是占空比大约能分成 4000 档。这里藏着一个核心权衡：在计数时钟固定时，PWM 频率越高，一个周期内的计数步就越少，分辨率越低——想要高频又要高分辨率，只能提高计数时钟（受芯片上限约束）。反过来想要极高分辨率就得压低频率或提高时钟。这是 PWM 设计的第一道取舍。

计数器位宽给出分辨率上限：TM4C123 的 PWM 计数器是 16 位，单周期最多 65536 个计数步，故最高约 16 位分辨率。当系统时钟太高、直接计数会让最低频率也偏高时，可用 PWM 专用分频器（TM4C123 在 RCC 寄存器里用 USEPWMDIV 位启用、PWMDIV 字段选 /2 到 /64）先把喂给 PWM 的时钟降下来，从而降低可达到的 PWM 频率下限、延长周期。分频用得越狠，频率越低但每步时间越长（分辨率不因分频改变，因为频率也同比降低，period_counts 不变）。

### 6.4.4 边沿对齐、中心对齐、死区与 TM4C123 PWM 模块

按波形形态，PWM 常分边沿对齐（edge-aligned）与中心对齐（center-aligned）。边沿对齐是每个周期的起点固定翻转、比较点决定另一次翻转，实现简单，是最常见的默认；中心对齐让脉冲关于周期中心对称（计数器先增后减），好处是多路 PWM 的开关时刻更分散、谐波特性更好，常用于电机三相驱动。

死区（dead-band / dead-time）是驱动半桥/全桥（如电机、逆变器）时的安全特性：一对互补 PWM 驱动上下两个开关管，绝不能同时导通（否则直通短路烧管）。死区在两路互补信号切换之间插入一小段两者都关断的间隙，给开关管留出关断时间。这是电力电子应用里 PWM 模块必备的一环，纯调光/调速的入门场景用不到，但要知道它存在。

锚平台 TM4C123GH6PM 有专门的 PWM 外设：共八个 PWM 生成器块（generator block，分布在两个 PWM 模块 M0/M1 中），每个生成器块含一个 16 位计数器、两个 PWM 比较器、一个信号生成器、一个死区生成器，以及一个中断/ADC 触发选择器；每个生成器可产出一对（互补的）PWM 信号。⚙演进快·锚平台 TM4C123·核实 2026-08-01：PWM 模块/生成器数量、计数器位宽、对齐模式、死区能力高度平台相关；此外许多 MCU 并无独立 PWM 外设，而是用通用定时器的 PWM 模式生成，换芯片务必以本型号 SoC Reference Manual 的 PWM 章为准。
