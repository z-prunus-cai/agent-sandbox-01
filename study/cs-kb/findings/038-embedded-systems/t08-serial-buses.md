嵌入式系统里，处理器要跟传感器、存储器、显示屏、其它芯片交换数据，绝大多数走的是「串行」总线：一次传一位、靠一到几根线搞定，而不是像并行总线那样一次几十根线。串行省引脚、省成本、抗干扰更容易做，代价是要靠协议把「一位一位」重新拼回字节。本报告按由简到繁覆盖片内/板级最常见的五种：UART（点对点异步）、SPI（同步高速）、I²C（两线多器件）、CAN（车载多主）、USB（主机外设）。

一个贯穿全篇的分类维度先摆在这里，后面每种总线都会落到它上面：

```
同步 vs 异步：是否有独立的时钟线随数据一起走
  同步：SPI、I²C（有 SCLK/SCL）——收发双方共享时钟，不必事先约定速率
  异步：UART（无时钟线）——双方各自用本地时钟，必须预先约定波特率

双工方式：
  全双工：收发各一根线，可同时收发（UART 的 TX/RX、SPI 的 MOSI/MISO）
  半双工：一根线分时收发（I²C 的 SDA、经典单线 CAN 的差分对）

主从/多主：
  单主：SPI、I²C 常见用法、USB（主机发起一切）
  多主：I²C 支持、CAN 天生多主（靠仲裁解决同时抢线）
```

一个尺度提醒，避免和网络课混淆：这些是「板级/片间」总线，距离从厘米到几十米（CAN 可到上千米但速率降低），关心的是电平、位时序、帧格式、仲裁；它们大多没有 IP/端口/路由这类概念。和 TCP/IP 的「协议分层」只是结构上的类比（物理层—链路层的味道），不要把网络层以上的东西套进来。

## 8.1 UART 异步帧、波特率、起/停/奇偶位

### 8.1.1 UART 是什么：无时钟线的异步全双工串口

UART（Universal Asynchronous Receiver/Transmitter，通用异步收发器）是一种点对点的异步串行接口，最少只用两根信号线：TX（发送）和 RX（接收），外加共地。它是全双工的——TX 和 RX 各一根线，收发可以同时进行。因为没有独立的时钟线，收发双方靠各自本地的时钟来采样数据，所以必须事先约定好速率（波特率）和帧格式，否则接收方会把位切错。

严格说，UART 是芯片里那个收发外设的名字；它输出的是逻辑电平信号，这套「起始位+数据位+校验+停止位」的信号约定常被叫作「异步串行」或口语里的「串口」。当它接上 RS-232 电平转换芯片就变成 PC 上那种 COM 口，接上 RS-485 收发器就能做多点长距离总线——但这些是电平/物理层的事，帧格式仍是同一套。初学者最容易混的一点是把「UART」和「RS-232」当同义词：UART 是控制器与帧协议，RS-232/RS-485/TTL 是电平标准，可以自由组合。

### 8.1.2 UART 帧结构：起始位、数据位、奇偶位、停止位

空闲时线路保持高电平。一帧从一个「起始位」（拉低一个位时间）开始，接着是数据位（通常 8 位，可配 5～9 位，最低位 LSB 先发），可选一个奇偶校验位，最后是一到两个「停止位」（高电平）。接收方检测到下降沿（起始位）就启动采样时钟，通常在每个位的中点采样以获得最大容错。

一帧的位序（以最常见的 8N1 = 8 数据位、无校验、1 停止位为例）：

```
空闲(高) │ 起始(低) │ D0 D1 D2 D3 D4 D5 D6 D7 │ 停止(高) │ 空闲(高)
          └一个位时间┘  ←—— LSB 先发，MSB 后发 ——→  └一个位时间┘
```

「8N1」这种写法读作「8 数据位 / No parity / 1 stop bit」；常见变体还有 8E1（偶校验）、8O1（奇校验）、8N2（2 停止位）。停止位其实就是保证帧与帧之间线路回到高电平至少一个位时间，好让下一帧的下降沿能被识别。易错点：两端的帧格式必须完全一致，哪怕波特率对了、但一端 8N1 另一端 8E1，接收方会把校验位当成数据或产生帧错误。

### 8.1.3 波特率与位时间：异步的核心约定

波特率（baud rate）是每秒传输的符号数；在 UART 这种每符号一位的场景里，它等于每秒比特数。位时间就是波特率的倒数。因为没有共享时钟，双方本地时钟的偏差必须小到在整帧内累积的采样点漂移不越过位边界——工程经验上通常要求两端波特率误差合起来在 ±2% 以内较稳妥（越靠近位中点采样越能容忍误差）。

位时间与帧时间的关系（本机 Python 核算，见本节末来源）：

```
位时间 = 1 / 波特率
9600 baud → 位时间 = 1/9600 s ≈ 104.17 µs
8N1 一帧 = 10 位（1 起始 + 8 数据 + 1 停止）
       帧时间 ≈ 10 × 104.17 µs ≈ 1.042 ms
       吞吐 ≈ 9600 / 10 = 960 字节/秒
8E1 一帧 = 11 位（多一个校验位）→ 吞吐 ≈ 9600 / 11 ≈ 872.7 字节/秒
```

直觉上，加校验位或加停止位都会「稀释」有效数据吞吐，因为帧里多了非数据的开销位。在锚平台 TM4C123 上，波特率由系统/外设时钟经过一个整数分频加小数分频（BRD 整数部分 + 小数部分）得到，具体寄存器（如 UARTIBRD/UARTFBRD）与分频公式属平台细节，⚙演进快·锚平台，其它 SoC 的分频器结构不同——但「波特率来自对某个时钟源做分频」这一点是通用的。

### 8.1.4 奇偶校验：最小的错误检测

奇偶校验位是一个附加位，使「数据位 + 校验位」里 1 的总个数为偶（偶校验 even）或为奇（奇校验 odd）。接收方重新数一遍，如果奇偶性不符就判定这一帧出错。它能检出任意奇数个位翻转，但检不出偶数个位同时翻转，也无法纠错——只能发现「这帧坏了」。

计算示例（本机核算）：

```
字节 0x41（'A'）= 0100 0001，含 2 个 1（偶数）
  偶校验位 = 0（凑成仍为偶数）；奇校验位 = 1（凑成奇数）
字节 0x37 = 0011 0111，含 5 个 1（奇数）
  偶校验位 = 1（凑成 6 个 1，偶数）
```

奇偶校验只是「聊胜于无」的检错手段，对突发多位错误几乎无力；要可靠得多的检错要上 CRC（见 CAN 一节）。因此现代协议里 UART 校验位常被关掉（用 8N1），把检错交给上层协议或干脆在受控环境里省掉。

### 8.1.5 常见误区与电平标准

UART 控制器输出的是单端逻辑电平（相对于地的高/低），常见的板内直连是 TTL/CMOS 电平（如 3.3V），空闲为高。RS-232 把它转换成正负电压且极性相反（空闲为负电平、逻辑 1 是负），RS-485 则用差分对做长距离多点。这些转换不改变帧格式，只改变电气特性和可达距离/抗干扰能力。

把两块板的 TX 直接对 TX（应该是 A 的 TX 接 B 的 RX，交叉连接）；忘记共地导致电平参考漂移；以及在没有电平转换的情况下把 3.3V 的 UART 直连到真正的 RS-232 口（电压不兼容会损坏引脚）。

## 8.2 SPI 主从、时钟极性/相位（CPOL/CPHA）

### 8.2.1 SPI 是什么：四线同步全双工主从总线

SPI（Serial Peripheral Interface）是同步串行总线：有一根专门的时钟线，主设备产生时钟，数据在时钟边沿上收发，所以双方不必事先约定速率。典型四根线：

```
SCLK  主 → 从   串行时钟（主设备产生）
MOSI  主 → 从   Master Out Slave In（主发从收）
MISO  从 → 主   Master In Slave Out（从发主收）
SS/CS 主 → 从   片选（Slave Select，低有效），每个从设备一根
```

SPI 是全双工的：每个时钟周期，MOSI 送出一位的同时 MISO 收回一位——本质是主从两个移位寄存器首尾相连组成一个环，转 N 个时钟就交换了 N 位。它没有寻址字段、没有应答位、没有起停条件，靠片选线选中目标；因此协议极简、速度可以很高（几十 MHz 常见），代价是每多一个从设备就多一根片选线，且没有内建的错误检测或流控。

### 8.2.2 CPOL/CPHA：四种模式

SPI 用两个参数定义时钟与采样的关系。CPOL（时钟极性）决定空闲时 SCLK 是低（0）还是高（1）。CPHA（时钟相位）决定在时钟的第一个边沿还是第二个边沿采样数据：CPHA=0 在每个位的「前沿（leading edge）」采样、后沿移位；CPHA=1 在「后沿（trailing edge）」采样、前沿移位。两两组合成四种模式：

```
模式  CPOL CPHA  空闲电平  采样边沿
  0     0    0    低        SCLK 第一个（前）边沿，上升沿采样
  1     0    1    低        SCLK 第二个（后）边沿，下降沿采样
  2     1    0    高        SCLK 第一个（前）边沿，下降沿采样
  3     1    1    高        SCLK 第二个（后）边沿，上升沿采样
```

CPOL 只是把整条时钟波形上下翻转；CPHA 决定「在边沿到来时是采样还是换数据」。主从两端必须用同一模式，否则会整体错位半个时钟，读到的全是错的。易错点：模式 0 和模式 3 都在上升沿采样，很多器件二选一支持，但空闲电平不同；数据手册通常直接给「支持 mode 0 和 mode 3」这类说明，照抄即可，不要凭「上升沿采样」就以为模式随便选。

一个「前沿采样」（CPHA=0）的时序直觉：

```
CPOL=0 空闲低：
SCLK  ___┌─┐_┌─┐_┌─┐___
数据线    X───X───X       数据在时钟前变好，主从在上升沿(前沿)采样
采样点    ↑   ↑   ↑
```

### 8.2.3 数据交换：移位寄存器环与片选

SPI 传输的心智模型是「两个 8 位（或 N 位）移位寄存器组成一个环」。主机每发一个时钟，两边的移位寄存器同步移一位，主机移出的位进从机、从机移出的位进主机。转满 8 个时钟，主从各自的一个字节就互相交换完毕。

一次字节交换的位移仿真（Python，MSB 先发的常见配置）：

```
主机待发 0xA5 = 1010 0101，从机待发 0x3C = 0011 1100
每拍：master_bit = MSB(master_reg)；slave_bit = MSB(slave_reg)
      两寄存器左移一位，master 低位补 slave_bit，slave 低位补 master_bit
8 拍后：主机收到 0x3C，从机收到 0xA5（完成互换）
```

这解释了为什么「只想读不想写」时，主机仍必须发出无意义的字节（常发 0x00 或 0xFF）来产生时钟、把从机的数据「摇」出来——因为时钟只由主机产生，没有时钟就没有任何数据移动。多从设备时，用独立片选（每从一根 SS）或菊花链（daisy-chain，前一个的 MISO 接后一个的 MOSI，串成一长条移位寄存器）两种拓扑。

### 8.2.4 SPI 的取舍与局限

SPI 的优点是简单、快、全双工、无协议开销；缺点是引脚随从设备数量线性增长（每从一根片选）、没有寻址、没有应答/流控、没有错误检测、也没有正式的多主机制。它是事实标准而非有中央机构维护的单一规范文档——各家 SoC 数据手册里的 SPI/SSI 外设描述就是权威来源，细节（如帧格式变体、TI SSI 模式、Microwire）各有差异。

不同厂商对片选的时序要求（片选拉低到第一个时钟的建立时间、字节间片选是否要拉高）不一样；以及位序（MSB first vs LSB first）也可配，两端必须一致。这些都要查具体器件手册，属 ⚙演进快·锚平台细节。

## 8.3 I²C 寻址、起停条件、ACK 与仲裁

### 8.3.1 I²C 是什么：两线、开漏、多主多从

I²C（Inter-Integrated Circuit，读作「I-squared-C」或「I-two-C」）是同步串行总线，只用两根线：SDA（串行数据）和 SCL（串行时钟），外加共地。它支持在同一对线上挂多个从设备（各有地址）甚至多个主设备。SDA 是半双工的（同一根线分时收发）。NXP 的 UM10204 是其权威规范（当前 rev.7.0，2021）。

两根线都是「开漏/开集」输出加上拉电阻——器件只能把线拉低（输出 0=dominant），松手时靠上拉电阻回到高（1=recessive）。多个器件并联在同一根线上，只要有一个拉低，整根线就是低，这叫「线与」（wired-AND）。这个特性是后面 ACK、时钟延展、多主仲裁三件事的物理基础，务必先理解：

```
SDA/SCL 都是开漏 + 上拉电阻 Rp 到 VCC
任一器件拉低 → 线为低(0)
所有器件松手 → 上拉拉高 → 线为高(1)
=> 线上电平 = 所有器件输出的「逻辑与」（有一个 0 就是 0）
```

### 8.3.2 起始、停止与重复起始条件

I²C 靠 SDA 在 SCL 为高期间的跳变来标记帧边界（数据位则规定只能在 SCL 为低时变化）：

```
起始条件 START (S)：SCL 保持高时，SDA 由高→低
停止条件 STOP  (P)：SCL 保持高时，SDA 由低→高
重复起始 Sr    ：不发 STOP 直接再发一次 START，用于「写地址→改读方向」而不释放总线
```

平时数据位只在 SCL 低电平时翻转，所以「SCL 高时 SDA 却动了」是一个特殊事件，用来当作不可能与数据混淆的分隔符。重复起始（Sr）很常见：比如读一个寄存器，先「写」告诉从机要读哪个寄存器地址，再用 Sr 切成「读」把数据取回，中间不放 STOP 以免总线被别的主机抢走。

### 8.3.3 寻址：7 位地址与 R/W 位（及 10 位扩展）

START 之后主机发的第一个字节 = 7 位从机地址 + 1 位方向位（R/W）。R/W=0 表示主机要写，R/W=1 表示主机要读。所以同一个 7 位地址会对应总线上两个「字节值」。

```
第一字节 = [A6 A5 A4 A3 A2 A1 A0] [R/W]
例：7 位地址 0x68，写 → (0x68<<1)|0 = 0xD0
                 读 → (0x68<<1)|1 = 0xD1
```

数据手册有时给「7 位地址 0x68」，有时给「写地址 0xD0/读地址 0xD1」，其实是同一器件——差一位移位，别当成两个不同地址。7 位地址空间理论 128 个，但有若干保留地址（如 0000 000 通用广播、以及高速模式主机码等），实际可用略少。地址不够时有 10 位寻址扩展：用两个字节，第一字节高 5 位是固定前缀 11110 加地址高 2 位，属规范里的可选机制。

### 8.3.4 ACK / NACK：每字节的应答

每传完 8 个数据位，发送方在第 9 个时钟释放 SDA，接收方把 SDA 拉低表示 ACK（应答，收到了），保持高表示 NACK（未应答）。这是 I²C 相对 SPI 多出来的「握手」——发送方能知道对方在不在、还要不要继续。

```
数据字节: bit7..bit0 (8 个时钟) │ 第 9 个时钟：接收方拉低 SDA = ACK，松手 = NACK
```

主机寻址后若无器件应答（NACK），说明地址上没挂器件；主机读多字节时，在最后一个字节故意回 NACK 告诉从机「够了，别再发」，随后发 STOP。易错点：ACK 由「接收方」给，方向随读写而变——写时从机 ACK，读时主机 ACK（最后一字节除外）。

### 8.3.5 时钟延展（clock stretching）

因为 SCL 也是开漏线与，从机在跟不上时可以把 SCL 按住在低电平，主机想拉高也拉不动（线与），于是被迫等待，直到从机松手。这叫时钟延展，是从机对主机做流控的唯一手段。

这正是 8.3.1 那个「有一个拉低就是低」特性的直接应用——从机用它「拖住」时钟争取处理时间。易错点：不是所有主机（尤其某些位操作模拟的软件 I²C 或部分硬件外设）都正确支持时钟延展，遇到慢从机可能通信失败；这是实际调试里常见的坑，属实现相关。

### 8.3.6 多主与非破坏性仲裁

I²C 允许多个主机。若两个主机几乎同时发起并发数据，靠 SDA 的线与特性做「非破坏性仲裁」：每个主机发出一位的同时回读 SDA 实际电平，如果自己发的是 1（松手）但读回来是 0（被别人拉低），说明输给了对方，立即退出、停止驱动，让赢的一方继续——数据没有被破坏，赢家完全不知道刚才有过竞争。

```
主机A 发 ...1... （松手，期望高）
主机B 发 ...0... （拉低）
线上实际 = 0（线与）
A 回读发现 期望1却是0 → A 输，退出；B 继续
=> 发送「0（拉低）」的一方胜出 = 数值较小的地址/数据胜出
```

这个「0 压过 1、输家无损退出」的思想和 CAN 的仲裁本质相同（见 8.4）。它保证总线上任一时刻最终只有一个主机在发，且不会因碰撞而损坏正在传的那帧。

### 8.3.7 速度模式

I²C 定义了若干标准速率档，随规范演进逐步增加：

```
标准模式 Standard-mode      100 kbit/s
快速模式 Fast-mode (Fm)     400 kbit/s
快速模式+ Fast-mode Plus     1 Mbit/s
高速模式 High-speed (Hs)    3.4 Mbit/s
超快速模式 Ultra Fast (UFm) 5 Mbit/s（单向，仅写，无 ACK/无仲裁，特殊子集）
```

速率不是随便设的，受上拉电阻和总线电容（走线长度、器件数量）限制——电容大、上拉弱会让上升沿变缓，跑不到高速。UFm 是一个只发不收的单向变体，和常规 I²C 不完全兼容，属规范里的特例。以上数值以 UM10204 rev.7.0 为准。

- 一手规范（主）：NXP UM10204《I²C-bus specification and user manual》rev.7.0（2021-10）——起停条件、7/10 位寻址、ACK、时钟延展、仲裁、速度模式均以此为锚 ｜核实 2026-08-01。

## 8.4 CAN 帧格式与非破坏性仲裁

### 8.4.1 CAN 是什么：差分、多主、面向消息

CAN（Controller Area Network）由 Bosch 提出（CAN 2.0 规范 1991），后标准化为 ISO 11898，最初为汽车而生，现广泛用于工业。它是多主、广播式、差分信号的串行总线：所有节点挂在同一对差分线（CAN_H/CAN_L）上，任何节点都能发，靠仲裁决定谁先发。

CAN 最反直觉的一点是「面向消息，而非面向地址」：帧里的标识符（ID）标记的是「这条消息是什么内容/优先级」，不是「发给谁」。所有节点都收到每一帧，各自根据 ID 用滤波器决定要不要处理。ID 同时兼任优先级——数值越小优先级越高（见仲裁）。

差分与「显性/隐性」是仲裁的物理基础：

```
显性位 dominant  = 逻辑 0 —— 主动驱动差分对，会「压过」隐性
隐性位 recessive = 逻辑 1 —— 不驱动（靠终端电阻回到隐性）
多个节点同时发：只要有一个发显性(0)，总线就是显性(0)
=> 与 I²C 的线与同构：0 压过 1
```

### 8.4.2 帧格式：标准帧与扩展帧

CAN 有多种帧类型（数据帧、远程帧、错误帧、过载帧），最常用是数据帧。数据帧有两种 ID 长度：

```
标准帧 (CAN 2.0A)：11 位标识符
扩展帧 (CAN 2.0B)：29 位标识符（11 位 base + 18 位 extension）

数据帧主要字段（简化）：
  SOF(起始1位) │ 仲裁场(ID + RTR) │ 控制场(含 DLC 数据长度码) │
  数据场(0~8 字节) │ CRC 场(15位CRC + 界定符) │ ACK 场 │ EOF(结束7位)
```

经典 CAN 数据场最多 8 字节，用 DLC（Data Length Code）标数据字节数。CRC 场用 15 位循环冗余校验做强错误检测（远强于 UART 的奇偶校验）。ACK 场里，正确收到帧的其它节点会一起发显性位应答，发送方据此确认「至少有一个节点收到了」——但这是总线级的应答，不针对特定接收者。

### 8.4.3 非破坏性逐位仲裁

多个节点同时开始发时，在「仲裁场」（ID）逐位竞争：每个节点发一位后回读总线，若自己发隐性(1)却读到显性(0)，说明有更高优先级的帧在发，立即退出改为接收；发显性的一方继续。因为退出发生在位级、且总线上始终是那个赢家的正确电平，正在传的帧不被破坏——这就是「非破坏性逐位仲裁」。

```
节点A ID: 0 0 1 0 0 ...   （某位发隐性1）
节点B ID: 0 0 0 ...       （同位发显性0）
总线:     0 0 0 ...       （显性压过隐性）
A 在第3位发1却读到0 → A 退出；B 赢，继续发完整帧
=> ID 数值最小者胜出（= 最高优先级）
```

结果：赢家不必重发、输家会在总线空闲后自动重试，仲裁不浪费带宽（不同于以太网的碰撞后退避重发）。这也解释了为什么低数值 ID 要留给高优先级消息。本机核算：三个 ID {0x123, 0x120, 0x0A0} 竞争，胜出者是 0x0A0（最小），与规则一致。

### 8.4.4 错误处理与 CAN FD 演进

CAN 内建多重错误检测（CRC、帧格式检查、位监视、位填充、ACK 检查）和错误帧机制，检出错误的节点会发错误帧强制全网丢弃并重传；节点还有错误计数器，故障节点会自动从「主动错误→被动错误→总线关闭」逐级退出，避免一个坏节点拖垮整条总线。这套健壮性是 CAN 用于安全关键场景的核心卖点。

CAN FD（CAN with Flexible Data-rate，Bosch 2012，后并入 ISO 11898-1:2015）是演进版：数据场可达 64 字节、且数据阶段可切到更高比特率（仲裁段仍用低速以保证仲裁正确），大幅提升吞吐。更新的 CAN XL 进一步扩展。这些属 ⚙演进快·标版本，具体控制器是否支持 FD/XL 看芯片型号。

#### 来源与时效

- 一手规范：Bosch CAN Specification 2.0（1991，Part A 标准帧 / Part B 扩展帧）与 ISO 11898-1（CAN 数据链路层）；CAN FD 见 ISO 11898-1:2015 ｜核实 2026-08-01。
- 副锚：Lee & Seshia 2nd ed Ch10（总线仲裁作为 I/O 与实时通信示例）。
- 本机实证：Python 核算逐位仲裁「最小 ID 胜出」（{0x123,0x120,0x0A0}→0x0A0），与规范一致。
- 分歧/待核：经典 CAN 数据场上限 8 字节、CAN FD 上限 64 字节两说并非冲突而是版本差异，正文已分账标版本；各控制器对 FD/XL 支持度属芯片相关，标「查芯片手册」。TM4C123 的 CAN 外设寄存器细节 ⚙演进快·锚平台，此处以协议为主未展开寄存器。

## 8.5 USB 枚举与传输类型概念

### 8.5.1 USB 是什么：主机中心的分层总线

USB（Universal Serial Bus）与前面几种最大的不同：它是严格「主机中心」的——总线上有且仅有一个主机（Host），所有传输都由主机发起、调度；外设（Device/Function）只能被动响应，不能主动发起传输。拓扑是以主机的根集线器为根、经集线器（Hub）逐层扩展的树。物理上用一对差分线（D+/D-，USB 2.0）传半双工数据；USB 3.x 另加了独立的高速差分对做全双工 SuperSpeed。

常见速率档（USB-IF 规范）：

```
Low-Speed        1.5 Mbit/s   (USB 1.x)
Full-Speed       12  Mbit/s   (USB 1.x/2.0)
High-Speed       480 Mbit/s   (USB 2.0)
SuperSpeed       5   Gbit/s   (USB 3.0 / 3.2 Gen1)
SuperSpeed+     10/20 Gbit/s  (USB 3.2 Gen2 / Gen2x2)
```

这里点到为止：嵌入式课里 USB 关心的是「枚举 + 传输类型」两个概念，深入的信令/链路层不展开（那是 USB-IF 大部头规范的内容）。

### 8.5.2 枚举（enumeration）

设备插入时，主机通过一套标准流程识别并配置它，叫枚举：主机检测到连接（靠 D+/D- 上拉判定速率）→复位设备→设备先用默认地址 0 响应→主机读取「设备描述符」→分配一个唯一地址→再读取配置/接口/端点等描述符→选择一个配置使设备进入就绪。整个过程走的是控制传输（见下）。

枚举就是「即插即用」背后的自我介绍——设备通过一层层「描述符」告诉主机「我是谁（VID/PID）、有几个功能、每个功能需要哪些端点、要多少带宽」，主机据此加载驱动、分配资源。易错点：地址 0 只是枚举初期的临时公共地址，枚举完每个设备有独立地址；描述符是分层的（设备→配置→接口→端点），初学者常把它们混为一谈。

### 8.5.3 四种传输类型

USB 端点按用途分四类传输，主机据此分配带宽与时序保证：

```
控制传输 Control        —— 配置/命令，枚举用它；有严格的请求-数据-状态阶段，可靠
批量传输 Bulk           —— 大块数据（U 盘、打印机），保证正确但不保证时延/带宽
中断传输 Interrupt      —— 小量、低时延、周期轮询（鼠标、键盘）；注意「主机轮询」而非设备主动中断
等时传输 Isochronous    —— 音视频流，保证固定带宽/时延，但不重传（丢了就丢了）
```

四类是在「可靠性」和「实时性」之间做不同取舍。Bulk 要正确可以慢、可以等空闲带宽；Isochronous 要准时可以错、丢帧也不回补；Control 是可靠的命令通道；Interrupt 名字有误导——USB 设备不能真的中断主机，是主机按约定周期来「问」有没有数据，所以叫轮询式的低时延小传输更准确。

### 8.5.4 端点、管道与描述符

设备侧的通信单元叫「端点（endpoint）」，每个端点是一个单向的数据缓冲，有编号和方向（IN=向主机 / OUT=离主机）。端点 0 是每个设备必有的双向控制端点，枚举就走它。主机侧与某端点建立的逻辑通道叫「管道（pipe）」。设备把自己有哪些端点、各是什么传输类型、要多大包/多快轮询，都写在「端点描述符」里，枚举时交给主机。

IN/OUT 的方向永远相对主机而言（IN=数据流入主机），别站在设备角度理解反了；端点 0 的控制通道和其它功能端点是分开的，一个再简单的设备也至少有端点 0。这一层是 USB「点到为止」的边界，够理解枚举与传输分类即可。
