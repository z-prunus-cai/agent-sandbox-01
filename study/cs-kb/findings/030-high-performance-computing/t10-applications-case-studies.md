## H-10.1 N-body 粒子仿真

### H-10.1.1 N-body 问题是什么：N 个粒子两两相互作用

N-body（多体）仿真模拟一群粒子在两两相互作用力（引力、库仑静电力等）下随时间演化的过程。最直接的做法是对每个粒子 i，把其他所有粒子 j 对它的作用力加起来，得到它受到的合力（或加速度），再用这个加速度推进它的位置和速度一小步，如此反复。以引力为例，粒子 i 的加速度是所有 j≠i 的贡献之和：

a_i = G · Σ_{j≠i} m_j · (r_j − r_i) / ‖r_j − r_i‖³

这里对每个 i 都要遍历所有 j，一次完整的力计算要做约 N×(N−1) 次两两运算，所以直接法（all-pairs / direct sum）的时间复杂度是：

work = O(N²) （每个时间步）

时间步之间是串行的（物理是因果的，下一步依赖上一步的全部位置），但**单个时间步内 N 个粒子的力计算彼此独立**——这就是并行的着力点：把 N 个粒子分给 N 个线程，每个线程独立算自己那一行的求和。

N-body 的瓶颈不是"步数多"而是"每步太贵"。N=100 万时每步就是 10¹² 量级的运算，哪怕只跑几千步也是天文数字。所以 N-body 一是靠并行硬扛（GPU 每步铺满上万线程），二是靠近似算法把 O(N²) 降下来（10.1.5）。第二个直觉：这个计算是**计算受限（compute-bound）**的典型——每读一个粒子坐标（几个浮点数）要做很多次乘除和平方根，算术强度高，正好适合 GPU 这种算力远大于访存带宽的设备（Roofline 视角见大主题2）。

### H-10.1.2 并行化：每个粒子一个线程，gather 所有其他粒子

直接法在 GPU 上的自然映射是"一个线程负责一个粒子"：线程 i 循环读入所有 j 的位置和质量，累加它们对 i 的力，最后写回 a_i。这是一个纯 **gather** 模式——线程只读别人、只写自己那一格，没有两个线程写同一个地址，因此**不需要原子操作、没有写冲突**，正确性最省心。

```
// 直接法 N-body 力计算，一线程一粒子（示意）
i = blockIdx.x * blockDim.x + threadIdx.x;
acc = (0,0,0);
for (j = 0; j < N; ++j) {
    d   = pos[j] - pos[i];          // 读别人
    r2  = dot(d,d) + softening;     // 软化，见 10.1.3
    inv = rsqrt(r2*r2*r2);          // 1/r^3
    acc += mass[j] * d * inv;       // 累加到本线程私有寄存器
}
a[i] = G * acc;                     // 只写自己
```

本机 numpy 实证（无 GPU，用广播模拟"每个 i 对所有 j 求和"）：对 N=5 个粒子，广播向量化算出的加速度矩阵与老老实实写双重 for 循环逐个累加的结果，最大逐元素差 4.4e-16（机器 epsilon 量级），确认这个求和形状本身是对的。这也顺带说明了并行版和串行版"应当"得到同一结果——差异只会来自浮点求和顺序（详见数值课），不来自算法。

这里"一线程一粒子"里线程还在一个 `for j` 里串行扫全部 N 个粒子，所以单线程的工作量仍是 O(N)、全体是 O(N²)，并行只是把 N 行分摊到 N 个线程同时做，把**墙钟时间**从 O(N²) 降到大约 O(N)（有 N 个线程时），并没有减少总运算量。要真正减少运算量得靠近似算法。

### H-10.1.3 软化（softening）：躲开 r→0 的数值爆炸

核心问题是分母里的 ‖r_j − r_i‖³：当两个粒子靠得很近（或数值上恰好重合、以及 j=i 自己对自己）时，r→0，力趋于无穷，一步就把粒子甩飞、仿真崩溃。标准做法是加一个小的**软化长度 ε**，把分母改成：

‖r_j − r_i‖² + ε²

再取 3/2 次方。ε 的物理含义是"把点粒子抹成一个小团"，避免近距离奇点；它是仿真的一个可调参数，太大丢失近距离物理、太小又不稳定。

忘了处理 j=i。如果不软化也不跳过自身，线程算到 j=i 时 r=0，得到 inf 或 NaN，一个坏值会顺着求和污染整行。实践中要么显式 `if (i==j) continue`，要么让软化项保证分母恒正（本机 demo 里对自作用项把 inv_r3 置 0）。这个"边界元素特判"是几乎所有 N-body 代码的第一个 bug 来源。

### H-10.1.4 共享内存 tiling：把重复读的粒子缓存到片上

⚙演进快·锚 CUDA Toolkit 13.x（本机无 GPU·文档腿）｜核实 2026-08-01

直接法里每个线程都要把全部 N 个粒子从全局内存读一遍，全体就是 N 个线程 × N 次读 = O(N²) 次全局访存——虽然计算受限，但这么读还是浪费带宽。GPU 优化的标准手法是 **tiling（分块）**：把一个 block 内的线程组织起来，分批（每批 P 个，P=block 大小）协作把 P 个粒子的坐标搬进**共享内存**，然后 block 内所有线程都从共享内存重复读这 P 个粒子来累加，读完一批再搬下一批。

```
// tiled N-body（示意）：每批把 P 个粒子搬进 shared，再 block 内共享
for (tile = 0; tile < N; tile += P) {
    shared[t] = pos[tile + t];   // 协作加载一批
    __syncthreads();
    for (k = 0; k < P; ++k) acc += interaction(myPos, shared[k]);
    __syncthreads();
}
```

这样每个粒子坐标从慢的全局内存只被搬 N/P 次（而不是 N 次），block 内的 P 个线程共享这一次搬运，全局访存量降到约 O(N²/P)。GPU Gems 3 的 CUDA N-body 一手实现正是这个结构，PMPP 也把它作为"tiling 复用数据"的通例。这里体现的普适教训：即便计算受限，减少慢速内存访问、把复用数据搬到片上（大主题6 的核心思想）几乎总是值得的。具体的占用率/tile 尺寸最优值依 GPU 型号而变，本机无 GPU，属文档腿·待核。

### H-10.1.5 近似算法直觉：Barnes-Hut O(N log N) 与 FMM O(N)

直接法 O(N²) 在大 N 下无论怎么并行都扛不住，真正的突破来自**把远处的粒子成团近似**。核心物理直觉：一群离你很远的粒子，对你的合力约等于把它们当成一个位于其质心、质量为总和的"等效大粒子"——远处的细节你根本感觉不到。

Barnes-Hut 算法（Barnes & Hut, Nature 1986）用一棵空间八叉树（2D 是四叉树）把空间递归分块，每个树节点存该区域的质心和总质量。算某粒子受力时从树根往下走：节点离得足够远（用"节点尺寸 / 距离 < θ 阈值"判定）就用它的质心近似、不再下钻；只有近处才递归到单个粒子。每个粒子只需访问约 O(log N) 个节点，总复杂度：

Barnes-Hut：work = O(N log N)

快速多极子法（FMM，Greengard & Rokhlin, J. Comput. Phys. 1987）更进一步，用多极展开同时处理"一团源对一团目标"的相互作用，把复杂度压到线性：

FMM：work = O(N)

CS267 的粒子方法（particle methods）单元正是以 Barnes-Hut / FMM 为主线，与两篇原始论文的复杂度界一致。给初学者的分寸感：这两个算法把运算量从 N² 砍到 N log N / N 是数量级的胜利，但代价是**并行难度大增**——树的构建、遍历带来不规则的内存访问和负载不均（有的区域粒子密、有的稀），需要空间填充曲线排序、动态负载均衡等技术（属通信/负载均衡专题）。所以工程上常是"小 N 或近程用直接法（好并行），大 N 远程用树法（省运算量）"的权衡，不是非此即彼。

## H-10.2 网格 / PDE（stencil）仿真

### H-10.2.1 从 PDE 到显式模板更新

大量科学问题（传热、流体、电磁、波传播）用偏微分方程（PDE）描述场量在空间和时间上的变化。数值求解的基本套路是**离散化**：把连续空间铺成一张规则网格，把导数用邻居差分近似，于是"某点下一时刻的值"变成"当前时刻它自己和几个邻居的加权组合"——这就是**模板（stencil）** 计算。以二维热传导方程为例：

∂u/∂t = D · (∂²u/∂x² + ∂²u/∂y²)

用显式时间推进 + 五点空间差分，格点 (i,j) 的更新是它自己加上四个邻居的拉普拉斯：

u_new[i,j] = u[i,j] + α · ( u[i−1,j] + u[i+1,j] + u[i,j−1] + u[i,j+1] − 4·u[i,j] )

其中 α = D·Δt/Δx²。这个"每个格点读固定几个邻居、算加权和"就是模板模式（大主题7 已讲其并行结构），N-body 是"每点读全部其他点"、模板是"每点只读近邻"——这是两类应用最根本的区别。

模板计算像"一张图片反复做模糊滤波"，每个像素变成它和周围像素的平均。空间局部性极好（只读近邻），所以并行时每个线程负责一个（或一块）格点、并行度等于格点数，非常自然。

### H-10.2.2 稳定性：显式格式的 CFL / von Neumann 条件

核心事实：显式时间推进不是想设多大步长都行——步长太大数值解会**指数爆炸**，与真实物理无关。对上面 2D 五点显式热方程，稳定的充分必要条件（von Neumann 稳定性分析给出）是：

α = D·Δt/Δx² ≤ 1/4 （二维五点显式）

一维同类格式的阈值是 1/2。直觉上这是说"一个时间步内热量扩散的距离不能超过一个网格间距"——这类"信息传播速度 × 时间步 ≤ 网格间距"的约束统称 CFL（Courant-Friedrichs-Lewy）条件。

2D 热方程 41×41 网格、顶边固定为 1，取 α=0.2（<1/4）跑 2000 步平稳收敛到稳态，稳态内部离散拉普拉斯的最大绝对值降到 3.6e-5（说明确实解出了 ∇²u≈0 的稳态）；把 α 改成 0.30（>1/4）只跑 200 步，场值就爆到 1.7e23。这正是初学者最容易踩的坑：代码逻辑完全正确，只因步长选大了就"跑出 NaN / inf"，误以为是 bug，其实是违反了稳定性条件。稳定性阈值把显式格式的时间步锁死得很小，这也是为什么大问题会转向隐式格式（每步解一个大线性系统，需要稀疏求解器，见大主题9）——隐式无条件稳定但每步更贵，又是一个权衡。

### H-10.2.3 域分解与 ghost cell（halo）交换

在分布式内存（MPI）上跑大网格，做法是把网格切成若干块、每个进程算一块（域分解，domain decomposition）。问题在于：块边界上的格点要读邻居块的数据。解决办法是每个块在四周多留一圈**幽灵格点（ghost cells / halo）**，每个时间步开始前，相邻进程互相把自己边界的一层值发给对方填进对方的 halo，之后各自独立更新内部格点。

```
每个时间步：
  1. 与上下左右邻居交换一层边界值（填各自 ghost cell）  // MPI 通信
  2. 用（含 ghost 的）本地数组做 stencil 更新           // 本地计算
```

ghost cell 就是"把邻居的边界抄一份放在自己家门口"，抄完就能当本地数据用，不必每算一个边界点都去问一次邻居。通信量正比于块的**表面**（边界一圈的格点数），计算量正比于块的**体积**（内部格点数）——块越大，通信/计算比越小、越划算，这是弱扩展（问题随进程数一起变大）表现好的原因（大主题2）。这里还能自然引出通信-计算重叠（大主题8）：先发起 halo 交换（非阻塞），趁通信在途先更新不依赖 halo 的内部格点，通信回来再更新边界格点，把通信时间藏到计算背后。

### H-10.2.4 stencil 的性能画像：带宽受限与 tiling

⚙演进快项标注：以下 GPU 具体带宽/占用率数值锚 CUDA Toolkit 13.x，本机无 GPU·文档腿·待核。

模板计算和 N-body 的性能画像正相反：模板每个格点只做几次加乘（算术强度低），却要从内存读好几个邻居，所以它通常是**带宽受限（memory-bound）**——瓶颈在把数据从内存搬进来的速度，不在算力。放到 Roofline 图（大主题2）上，模板点落在左侧的带宽斜坡上，优化方向是"减少访存、提高数据复用"而不是"堆算力"。

优化手法是 tiling / 分块：把一小块网格连同它的边界（halo）搬进片上快速内存（GPU 共享内存 / CPU cache），块内的更新都从快速内存读，减少对慢速主存的重复读取（一个格点会被它的 4 个邻居各读一次，tiling 让这些重复读命中片上）。相关的时间分块（temporal blocking，把连续几个时间步在片上一起做完再写回）是进阶手法。给初学者的落点：判断一个计算该往哪个方向优化，先问它是计算受限还是带宽受限——N-body 堆算力、stencil 省带宽，方向完全不同，这个判断比具体技巧更重要。

## H-10.3 深度学习并行（数据并行 / 模型并行直觉）

### H-10.3.1 为何深度学习是 HPC 问题：底层就是大矩阵乘

⚙演进快·深度学习框架与 GPU 库演进极快，锚 CUDA Toolkit 13.x｜本机无 GPU·文档腿｜核实 2026-08-01

深度学习训练之所以进 HPC 视野，是因为它的计算内核几乎全是**稠密矩阵乘（GEMM）和卷积**——全连接层是矩阵乘，卷积层可展开成矩阵乘（im2col）或用专门卷积核，注意力也是一串矩阵乘。这些恰好是 GPU 最擅长、优化库（cuBLAS/cuDNN）最成熟的计算（大主题9）。所以"训练一个大模型"本质是"把海量 GEMM 铺到成百上千块 GPU 上跑得又快又省"，这是彻头彻尾的并行计算问题。

一次训练迭代分三步——前向（一串矩阵乘算出预测和损失）、反向（再一串矩阵乘算出每个参数的梯度）、更新（用梯度改参数）。规模爆炸来自两个方向：数据多（要过很多 batch）和模型大（参数多到单卡装不下）。这两个方向分别对应下面两种并行策略。本报告只讲"怎么切到多设备"的并行直觉，模型结构与训练算法本身归 L5-02/L6-03。

### H-10.3.2 数据并行：复制模型、分批数据、allreduce 梯度

数据并行是最常用、最好懂的策略：把**同一个模型完整复制到每块 GPU**，把一个大 mini-batch 切成若干份、每块 GPU 拿一份数据独立做前向和反向，各自算出一份梯度。关键在于:每块只看了部分数据，梯度只是局部的，更新前必须把所有 GPU 的梯度**求平均**，让所有副本用同一个平均梯度更新、保持模型一致。这个"把各卡梯度加起来再分回去"正是 collective 里的 **allreduce**（大主题4）：

每步：各卡本地算梯度 g_k → allreduce 求 Σg_k / K → 各卡用同一平均梯度更新参数

数据并行像"K 个学生分头做同一套卷子的不同题，做完把答案汇总平均、统一订正"。它的好处是实现简单、扩展性好（加卡就多分数据）；代价是**每步都要一次全体梯度 allreduce**，通信量正比于模型参数量，卡越多、模型越大通信越吃紧——所以梯度通信与反向计算的重叠、梯度压缩等成为工程重点（通信优化，大主题8）。前提约束：模型必须能塞进单卡显存，否则数据并行无从谈起。

### H-10.3.3 模型并行：把一个装不下的模型切开

当模型大到单卡显存装不下，就得把**模型本身切开**放到多卡，这是模型并行。它有两种正交的切法。

张量并行（tensor / intra-layer parallelism）：把单个大层的权重矩阵按行或列切成几块分到多卡，一次矩阵乘由多卡各算一部分、再用 collective（如 allreduce）拼起来。像"一道超大的矩阵乘题，几个人各算一部分列，最后拼成完整结果"。

流水线并行（pipeline / inter-layer parallelism）：把网络按层分段，第 1 段的层放 GPU0、第 2 段放 GPU1……数据像流水线一样逐段前向。像"装配线，每个工位负责几道工序"。它的坑是**流水线气泡（bubble）**：开头 GPU1 得等 GPU0 出结果才能开工，结尾反过来空转，这段空闲就是浪费；对策是把 mini-batch 再切成 micro-batch 让流水线尽量填满。

三种并行常**组合使用**（数据并行 × 张量并行 × 流水线并行，即所谓 3D 并行）来训超大模型。本报告只给到"为什么要这样切、各自卡在哪"的直觉；具体框架 API、通信原语编排、显存/重计算权衡随框架与硬件快速演进（⚙演进快），且 LLM 推理系统的工程栈另立专题，此处不展开、不并入。

### H-10.3.4 推理与混合精度：另一类并行画像

⚙演进快·锚 CUDA Toolkit 13.x｜本机无 GPU·文档腿·待核｜核实 2026-08-01

训练之外，推理（用训练好的模型做预测）也是重要 HPC 负载，但画像不同：训练要存中间激活做反向、通信梯度；推理只前向、更看重延迟和吞吐，常用更激进的低精度（FP16/BF16/INT8 等）换速度和显存。**混合精度**训练用低精度做大部分矩阵乘（省显存、吃满 GPU 的低精度算力单元）、用高精度累加关键量保稳定，是现代训练的标配思路。

这里体现 HPC 的一条通用权衡——精度换性能。低精度让每次运算更快、数据更小（带宽更省），但要小心数值下溢/精度损失，需要 loss scaling 等技巧兜底。具体哪些算子用什么精度、支持哪些低精度格式，强依赖 GPU 型号与库版本，本机无 GPU，全部标文档腿·待核，不给具体数值。

## H-10.4 科学计算案例（静电势图 / MRI 重建）

### H-10.4.1 静电势图：电荷叠加与 gather vs scatter 的选择

静电势图（electrostatic potential map）计算一批点电荷在空间网格上每一点产生的电势，是分子建模等领域的常见步骤。物理上电势线性叠加：网格点 p 的电势是所有电荷贡献之和：

V(p) = Σ_i k · q_i / ‖p − r_i‖

这个计算形状和 N-body 是"近亲"——都是"每个输出点对所有源求和"，都是 O(网格点数 × 电荷数) 的两两求和、计算受限。但它引出一个并行设计的核心抉择：

gather（散射的反面）：一个线程负责一个**网格点**，循环读所有电荷、累加到自己这一点。只写自己、无冲突、无需原子操作。

scatter：一个线程负责一个**电荷**，把它的贡献散布加到所有网格点上。多个电荷线程会同时写同一个网格点，需要原子操作或私有化（大主题7）避免写冲突。

PMPP Ch18 的教学要点正是：这类问题**优先选 gather**——输出点驱动、每个线程独占输出、天然无竞争，比 scatter 好写好优化。本机 numpy 实证：对 2 个点电荷（一正一负）在 50×50 网格上，逐电荷累加（scatter 思路的串行版）与广播一次性对所有网格点求和（gather 思路）结果完全一致（allclose 通过，电势范围 −41.0～+41.0），确认两种视角算的是同一个量、差别只在并行时谁写谁。

这是贯穿本大主题的主线——**能用 gather 就别用 scatter**。gather 把"多写一处"的冲突从根上消掉了；只有当每个源影响的输出很局部、gather 反而要扫太多无关源时，scatter + 原子/私有化才更划算。

### H-10.4.2 迭代 MRI 重建：把成像变成反问题求解

⚙演进快项（GPU 落地）锚 CUDA Toolkit 13.x｜本机无 GPU·文档腿｜核实 2026-08-01

磁共振成像（MRI）扫描仪采集的不是图像本身，而是频域（k-space）的测量值；重建就是从这些测量反解出图像。笛卡尔均匀采样时可以直接用逆 FFT（大主题9），但为了加快扫描常采用**非笛卡尔采样**（螺旋/放射状轨迹），这时不能简单 FFT，得把重建写成一个**迭代优化问题**：反复"从当前图像估计正向生成测量、与真实测量比、按差异修正图像"，直到收敛。

PMPP Ch17 的并行要点是：迭代重建里最贵的一步涉及一个只依赖扫描轨迹、与具体图像无关的量（教材称 Q 矩阵 / FHF 类结构），可以**预先计算一次、之后每次迭代复用**——这是"把不变量提出循环外"的经典优化，且这一步本身是规则的两两求和（每个体素对所有 k-space 采样点求和），并行结构和静电势图/N-body 同族，同样用 gather + tiling 优化。

MRI 重建是"反问题"——正问题（有图像算测量）好算，反问题（有测量求图像）要迭代逼近。它把前面学的 FFT、迭代求解（大主题9）、gather 求和、tiling 全用上了，是"应用综合体"。具体的收敛步数、精度、GPU 加速比依数据和实现而定，本机无相关数据、无 GPU，标文档腿·待核，不给具体数值或收敛结论。

### H-10.4.3 贯穿案例的通用思维：计算形状 → 性能画像 → 并行选择

回看四个案例，能抽出一套可迁移的分析框架，这比记住任何单个案例都重要。

第一步认**计算形状**：是"每点对所有点求和"（N-body、静电势、MRI 那步——两两求和族），还是"每点对近邻求和"（stencil、卷积——近邻模板族），还是"大矩阵乘"（深度学习）。形状定了，能复用哪个并行算法模式（大主题7）就定了。

第二步判**性能画像**：算术强度高、算力吃紧的是计算受限（N-body、静电势、GEMM），优化靠堆算力和 tiling 复用；算术强度低、访存吃紧的是带宽受限（stencil），优化靠省访存、提局部性。用 Roofline（大主题2）一眼定方向。

第三步选**并行落地**：优先 gather（无写冲突）；必须 scatter 时上原子/私有化；分布式时按域分解 + halo 交换切数据，并做通信-计算重叠（大主题8）；训练类按数据/模型并行切。给初学者的收束：具体应用千千万，但"形状→画像→落地"这三问，加上前九个大主题的招式库，就能对一个新应用做出八九不离十的并行方案草图——这正是这门课的目的。
