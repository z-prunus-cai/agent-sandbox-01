**为什么今天几乎所有计算都要并行**，以及**并行机器和并行编程模型有哪几大类**。它是整门高性能计算的地基——后面所有的性能模型、OpenMP、MPI、GPU 编程，都建立在这里的动机（登纳德缩放终结）和分类（Flynn、共享/分布式内存、系统谱系）之上。这里只讲编程者需要建立的心智模型，不深入微架构（流水线细节、缓存协议状态机）的纵深，那属于体系结构课。

## 1.1 为何并行：功耗墙 / 频率墙 / 内存墙

### 1.1.1 摩尔定律与登纳德缩放是两件不同的事

摩尔定律（Moore's Law）说的是：集成电路上可容纳的晶体管数量大约每两年翻一番。这是一条关于**晶体管密度**的经验观察，Gordon Moore 于 1965 年提出、1975 年修正。到 2026 年它已明显放缓但尚未完全停止。登纳德缩放（Dennard Scaling，Robert Dennard 1974）说的是另一件事：当晶体管按比例缩小时，只要同步降低工作电压和电流，单位芯片面积上的**功率密度可以保持不变**。这意味着"晶体管更多、更小、更快，但每平方毫米发热不变"——这才是过去几十年主频能一路飙升的真正原因。

初学者常把这两条混为一谈，其实要分开记：摩尔定律给的是"更多晶体管"，登纳德缩放给的是"这些晶体管可以跑得更快而不烧毁"。关键转折在于——**摩尔定律还在（虽然变慢），但登纳德缩放在 2005 年前后失效了**。晶体管继续变多，却不能再一边变多一边免费提速。理解这门课后续一切动机，都要先抓住"这是两条独立的曲线、其中一条断了"这个事实。

### 1.1.2 频率墙与功耗墙：主频为什么停在几 GHz

芯片的动态功耗近似正比于电容、电压平方与频率的乘积：

P_dynamic ≈ α · C · V² · f

其中 α 是活动因子，C 是负载电容，V 是电源电压，f 是时钟频率。登纳德缩放能持续时，缩小尺寸会同步压低 V，于是即便 f 上升、总功率密度也稳住。一旦 V 降不下去（漏电流等物理限制使电压逼近下限），再拉高 f 就会让功率随之飙升、发热无法散出——这就是"功耗墙"。它的直接表现是"频率墙"：商用 CPU 主频大约在 2004–2005 年停在 3–4 GHz 量级，此后基本不再靠提主频前进（具体年份与 GHz 数各来源略有出入，属"大约在此区间"的共识，非精确常数）。

登纳德缩放像一台越做越小、却始终耗电不变的省电灯泡；它失效后，你想让灯更亮（更高主频）就只能更费电、更发热，房间受不了。工程上的出路不是"造一个更亮的灯"，而是"装很多个正常亮度的灯"——这正是从单核转向多核的物理逻辑。易错点：功耗墙不是说"频率不能再高"，而是说"再高在功耗/散热上不划算"，实验室超频仍可短时冲到更高。

### 1.1.3 ILP 墙：靠"单核变聪明"也走到头了

在多核之前，处理器还有另一条免费提速路线：指令级并行（ILP, Instruction-Level Parallelism）——用流水线、超标量、乱序执行、分支预测，让单个核在一个周期内并发处理多条指令。ILP 墙指的是这条路线的收益递减：程序里可挖掘的独立指令有限，再增加乱序窗口、预测器等硬件，性能提升越来越小，而这些复杂机构本身又很耗电、耗面积。

到 2005 年前后，"让一个核自动跑得更快"的三种手段——提主频（撞功耗墙）、缩晶体管免费提速（登纳德缩放终结）、加深 ILP（撞 ILP 墙）——同时失灵。于是硬件厂商把新增的晶体管预算从"让一个核更强"转向"放更多个核"，把提速的责任交给了软件——程序员必须显式写并行代码才能吃到新硬件的红利。这就是"免费午餐结束"的完整含义。

### 1.1.4 内存墙：算得快没用，喂不饱

内存墙（Memory Wall，Wulf & McKee 1995）指处理器速度与主存访问速度之间的差距长期拉大：CPU 的运算吞吐增长远快于 DRAM 延迟的改善，结果越来越多的时间花在"等数据从内存运过来"上，而不是真正计算。DRAM 延迟每年只改善个位数百分比，而算力增长快得多，差距逐年累积。

直觉上，这是"厨师切菜飞快、但食材从仓库送到案板很慢"的问题：无论刀工多好，产出被送菜速度卡住。现代硬件用多级缓存、预取、更宽的内存通道来缓解，但缓解不等于消除。它对并行计算有两个深远影响：其一，很多并行程序的真正瓶颈是**访存带宽而非算力**（后续 Roofline 模型、算术强度就是量化这件事）；其二，把更多核堆在一起会加剧对内存带宽的争抢——核多了，"送菜通道"反而更挤。这也是为什么 GPU 这类吞吐机器要配极高带宽的显存。

### 1.1.5 结论：并行是被逼出来的，不是锦上添花

综合前四节：晶体管还在变多（摩尔定律未死），但"让单核免费变快"的所有路子（主频、登纳德缩放、ILP）都撞了墙，同时内存墙让"喂数据"越来越贵。硬件厂商唯一能持续利用新增晶体管的方式，就是**在一块芯片上放更多核、并用向量/众核/加速器提高并行吞吐**。于是性能的增长从"硬件自动给"变成"必须靠软件显式并行去挣"。

这就是整门高性能计算存在的理由：并行不是为了炫技，而是 2005 年后**继续获得性能增长的唯一主流途径**。记住这个因果链——物理限制（功耗/内存）→ 架构转向（多核/众核/异构）→ 编程责任转移（程序员要写并行）——本报告后面的 Flynn 分类、内存架构、系统谱系，都是在回答"既然被逼并行了，那并行机器长什么样"。

## 1.2 Flynn 分类（SISD / SIMD / MIMD）与 SIMT 的位置

### 1.2.1 分类的两个维度：指令流 × 数据流

Flynn 分类（Michael Flynn 1966 / 1972）用两个正交维度给计算机架构分门别类：一个程序执行时同时有几条**指令流**（Instruction Stream），几条**数据流**（Data Stream）。两两组合出四类：SISD、SIMD、MISD、MIMD。这里"流"的意思是"独立推进的序列"——单指令流指所有执行单元在同一时刻做同一条指令，多指令流指各执行单元可各做各的指令。

它之所以是所有并行教材的开篇，是因为它给了初学者一张最简单的地图：任何并行硬件都能先粗粒度地归到这四格之一。要注意，这是一个**很粗**的分类，1966 年提出、面向当时的机器，现代硬件（尤其 GPU）常常是几类的混合，硬套会别扭——所以后面才有 SIMT、SPMD 这些补充术语。把它当"入门坐标系"用，而不是当"精确物种表"用。

### 1.2.2 SISD：经典串行机器

SISD（Single Instruction, Single Data）是一条指令流处理一条数据流的机器，也就是最经典的单核冯·诺依曼计算机：一次取一条指令、作用在一份数据上。历史上没有 ILP 的顺序处理器就是纯 SISD。

它是理解其余三类的基准：初学者可以把 SISD 想成"一个厨师、一次做一道菜的一步"。现代带流水线和超标量的单核严格说已经不是纯 SISD（内部有指令级并行），但在 Flynn 这张粗地图上通常仍归入 SISD——因为它对程序员呈现的是"单一指令流作用于单一数据流"的假象。这提醒我们分类是按"对外呈现的模型"而非"内部实现细节"来分的。

### 1.2.3 SIMD：一条指令同时算多份数据

SIMD（Single Instruction, Multiple Data）是一条指令流同时作用于多份数据：同一个操作（比如加法）被同时施加到一组数据元素上。典型代表有历史上的向量处理器，以及今天 CPU 里的向量指令扩展（Intel 的 SSE/AVX/AVX-512、ARM 的 NEON/SVE）。

直觉是"一声令下、全班同时做同一道题"：控制逻辑只有一套，数据通路有很多条，因此单位面积能塞进大量算力、能效高，非常适合规整的数据并行（数组逐元素运算、图像像素、矩阵）。它的天生弱点是**分支**：如果一组数据里有的要走 if、有的要走 else，SIMD 只能"先全体走一支、再全体走另一支、各自屏蔽掉不该动的通道"，效率下降。本机 `lscpu` 的 flags 含 `avx2` 与 `avx512`，就是这台 CPU 的 SIMD 能力——一条 AVX-512 指令最宽可同时处理 512 位数据（如 16 个 32 位浮点）。这类硬件通常由编译器自动向量化或用 intrinsics 显式调用，程序员不必手写并行线程也能吃到。

### 1.2.4 MISD：几乎没有主流实例

MISD（Multiple Instruction, Single Data）是多条指令流作用于同一份数据流。这一格在实践中几乎没有主流商用机器，是四类里最"空"的一格。教材通常举的勉强例子是容错系统（多个不同单元对同一数据做冗余计算、比对结果）或某些流水线/脉动阵列（systolic array）的解读，但这些归类本身就有争议。

对初学者，MISD 的主要价值是**让分类完整、并说明分类的局限**：一个 1966 年提出的 2×2 表格，必然有格子对应不到现实。遇到"MISD 到底是什么"的困惑时，正确的心态是"它基本是空的、别在它身上纠结"，把精力放在 SIMD 与 MIMD 这两类真正撑起并行世界的架构上。不同教材对 MISD 举的例子彼此不一致，本身就说明它没有公认代表。

### 1.2.5 MIMD：各核各干各的（含 SPMD 澄清）

MIMD（Multiple Instruction, Multiple Data）是多条指令流各自作用于各自的数据流：每个处理单元有独立的指令流，可以执行完全不同的程序、处理不同的数据。今天的多核 CPU、多路服务器、计算集群，本质上都是 MIMD——每个核/每个节点独立取指、独立执行。

这是最灵活、也最通用的一类。初学者常把它和一个相关但不同的词 **SPMD**（Single Program, Multiple Data）搞混：SPMD 不是 Flynn 的第五类，而是 MIMD 硬件上最常用的一种**编程风格**——所有进程/线程跑的是同一份程序代码，但通过各自的编号（rank/线程号）走不同分支、处理不同数据。MPI 程序就是典型 SPMD。要点是：MIMD 描述"硬件能力"（各单元可各行其是），SPMD 描述"我们通常怎么用它"（大家跑同一个程序、按 ID 分工）。这个区分在后面学 MPI 时会反复用到。

### 1.2.6 SIMT：GPU 落在哪一格

SIMT（Single Instruction, Multiple Thread）是 NVIDIA 为其 GPU 提出的术语（Lindholm et al., IEEE Micro 2008，Tesla 架构）。它不是 Flynn 的原生分类，而是 SIMD 与多线程的**混合**：硬件上，一组线程（NVIDIA 称一个 warp，固定 32 个线程 ⚙锚 CUDA Toolkit 13.x）在同一时刻执行同一条指令，很像 SIMD；但对程序员，每个线程有自己的寄存器、程序计数器（较新架构支持独立线程调度）和分支能力，写起来像一堆独立线程，很像 MIMD/SPMD。

所以 SIMT 的定位可以这样记：**它给程序员一个"多线程"的编程假象，底层却用"单指令多数据"的方式批量执行**，以此兼得 SIMD 的能效与线程模型的易用性。它的代价与 SIMD 同源——warp 内的线程若走不同分支（warp divergence，线程束分歧），硬件会串行执行各分支、屏蔽无关线程，性能下降；这是 GPU 性能优化的核心议题之一（后续 GPU 主题详述）。分歧点提示：SIMD 与 SIMT 的界线在教学上并不绝对，有人把 SIMT 视作 SIMD 的一种编程封装，有人强调其独立线程语义使二者本质不同；本报告采用"混合体、编程像 MIMD、执行像 SIMD"的主流折中说法，并注明 warp 大小 32 是 NVIDIA 的实现常数、可用 `warpSize` 查询，非 SIMT 定义的一部分。

## 1.3 共享内存 vs 分布式内存架构（含 UMA/NUMA）

### 1.3.1 共享内存：一个大家都能碰的地址空间

共享内存（shared memory）架构里，所有处理器/核共享**同一个物理地址空间**：任何核都能直接用普通的读写内存指令访问同一份数据。并行任务之间"通信"的方式，就是一个核写某个内存地址、另一个核读同一个地址——通信是"访问共享变量"的副产品，不需要显式发消息。OpenMP、pthreads 就是面向这类架构的编程模型。

对初学者，这像一间办公室里所有人共用一块大白板：谁都能写、谁都能看，交流成本低、上手快。代价是"共用"带来的麻烦：两个核同时写同一变量会产生数据竞争（race condition），需要锁、原子操作等同步手段来保证正确（正确性细节属并发课）；而且这种架构可扩展的处理器数量有限——因为让很多核同时高速访问同一份内存，内存和互连会成为瓶颈。所以纯共享内存通常止步于单机的几十到几百核规模。

### 1.3.2 分布式内存：各自有内存，靠发消息通信

分布式内存（distributed memory）架构里，每个处理器（节点）有**自己私有的内存**，一个节点**不能**直接用内存指令读另一个节点的内存。要交换数据，必须通过网络显式地"发消息"——一方 send、另一方 recv。MPI 就是面向这类架构的标准编程模型，计算集群、超算都属于此类。

直觉上这像一栋楼里每人一间独立办公室、各有自己的白板，要共享信息就得打电话或发邮件（走网络）。好处是**极强的可扩展性**：想要更大规模，加机器、加网络即可，理论上能扩到几十万核（超算），因为没有"所有人抢一块内存"的中心瓶颈。代价是编程更麻烦——程序员必须显式管理"哪份数据在哪个节点、什么时候发给谁"，通信延迟和带宽成为核心性能因素，且要小心 send/recv 配对不当导致的死锁（后续 MPI 主题详述）。共享内存的难点在"同步正确性"，分布式内存的难点在"显式通信与数据划分"，这是两类架构最根本的编程差异。

### 1.3.3 UMA / SMP：内存对每个核一样近

UMA（Uniform Memory Access，统一内存访问）是共享内存的一个子类：所有处理器访问主存的延迟和带宽**都相同**，没有"更近的内存"。经典的对称多处理（SMP, Symmetric Multiprocessing）系统就是 UMA——一组对等的核通过共享总线或交叉开关连到同一块内存，谁访问哪一块内存的代价都一样。

初学者可以把 UMA 想成"白板正好挂在房间正中央，每个人到白板的距离都相等"。它的编程心智最简单：不用操心数据放哪，反正访问哪都一样快。本机 `lscpu` 显示单 socket、`NUMA node(s): 1`，就是一个 UMA 系统——4 个核看到的是一整块等距内存，写这台机器上的并行程序不需要考虑内存亲和性。UMA 的局限是规模：核越多，"大家挤在一条总线上访问同一块内存"的争抢越严重，所以它主要出现在小规模（单 socket、有限核数）系统。

### 1.3.4 NUMA / ccNUMA：内存有远近之分

NUMA（Non-Uniform Memory Access，非统一内存访问）也是共享内存（仍是单一地址空间、可直接读写），但访问**不同位置的内存延迟不同**：每个处理器（通常每个 CPU socket）连着一块"本地内存"，访问本地内存快，访问挂在别的 socket 上的"远端内存"要经过处理器间互连（如 Intel UPI、AMD Infinity Fabric），更慢。多路服务器普遍是 NUMA。当系统还维护缓存一致性时，称为 ccNUMA（cache-coherent NUMA），是现代多路服务器的主流形态。

直觉是"办公室里每人桌上有个小白板（本地内存），中央还有别人的白板（远端内存）；用自己桌上的快，跑去看别人桌上的慢"。它带来一个共享内存下仍要操心的新问题——**内存亲和（affinity）**：让线程尽量访问它所在 socket 的本地内存，并把数据分配到会用它的那个 socket 上，否则大量远端访问会拖慢程序（后续 OpenMP 主题的 NUMA 亲和会细讲）。易错点：NUMA 仍是"共享内存、单地址空间"，不要与"分布式内存、需发消息"混淆——NUMA 下你依然能用普通指针访问远端内存，只是慢；分布式内存下你根本无法用指针访问别的节点。本机是单 NUMA 节点，无法实证远近差异，此处结论为文档腿。

### 1.3.5 缓存一致性与混合架构

在共享内存（尤其多核/多路）系统里，每个核有自己的缓存，同一份内存数据可能同时被多个核缓存了副本。缓存一致性（cache coherence）就是硬件保证"当一个核改了某数据，其他核看到的不会是过期副本"的机制（常见 MESI 类协议）。它对程序员基本透明——你按共享变量正常读写即可，硬件在背后维护一致——但它不是免费的：核间为维持一致而交换的一致性流量，是伪共享（false sharing）等性能问题的根源（属后续主题与并发课，此处只需知其存在）。

现实中的大型系统几乎都是**混合架构**：一个超算由很多节点组成（节点之间是分布式内存、走 MPI），而每个节点内部是多核共享内存、且往往是 NUMA（节点内用 OpenMP/线程），节点里还可能插着 GPU（又一层）。这就是为什么真实 HPC 代码常写成 "MPI + OpenMP + CUDA" 的多层组合——每一层对应架构的一个层级。初学者先牢牢分清"共享 vs 分布式"这条主线，再理解真实机器是这两者的层层嵌套，就能看懂后面所有并行编程模型的分工。

## 1.4 多核 / 众核 / 集群 / 异构系统谱系

### 1.4.1 多核：少量"胖"核，为延迟优化

多核（multicore）指在一块芯片上集成少量（今天量级约 2–64，具体随产品而变）功能完整、单核性能强的核心。这类核是"延迟优化"（latency-oriented）的：配大缓存、复杂的乱序执行与分支预测，目标是**把单个任务尽快做完**。今天的桌面/服务器 CPU 都是多核，本机就是 4 核的多核 CPU。

初学者可以把多核想成"几位经验丰富的全能厨师"：人数不多，但每个都能独立、快速地完成复杂菜品。它是 1.1 节"免费午餐结束"后的直接产物——既然单核不能免费变快，就放几个核让软件并行。它擅长通用任务、控制流复杂的程序；但因为每个核都很"重"（占面积、耗电），核数堆不了太多。这与下面的众核形成鲜明对比。

### 1.4.2 众核：大量"瘦"核，为吞吐优化

众核（manycore）指在一块芯片上集成大量（数百到数千甚至更多）结构简单、单核较弱的核心，为"吞吐优化"（throughput-oriented）：每个核不追求把单个任务做快，而是靠**海量核并行、并用大规模多线程隐藏访存延迟**，把总吞吐做到极致。GPU 是当今众核的代表（历史上还有 Intel Xeon Phi 等）。

直觉是"上千名只会做一道简单工序的流水线工人"：让任何一个人单独做一整桌菜会很慢，但一万份同样的简单菜同时开工，总产量惊人。众核适合数据并行、规整、算术密集的负载（矩阵、图像、深度学习），正是 SIMT（1.2.6）与 GPU 编程的用武之地。易错点：多核 vs 众核不是简单的"核多核少"，本质是**设计取向不同**——延迟优化（让一个任务快）对吞吐优化（让很多任务的总量大）；理解这个取向差异，才能理解为什么有的负载适合 CPU、有的适合 GPU。

### 1.4.3 集群：用网络把很多机器连成一台"超级计算机"

集群（cluster）指把许多台独立的计算机（节点，每台有自己的 CPU、内存，本身可能就是多核）用高速网络连接起来，协同完成一个大计算。集群是**分布式内存**架构（1.3.2）的物理载体：节点之间不共享内存，靠网络发消息（MPI）协作。世界上的超级计算机基本都是超大规模集群。

初学者可以把集群想成"很多间办公室（节点）用电话网连起来，一起做一个超大项目"。它的意义是突破单机的天花板：单台机器的核数、内存、算力都有物理上限，而集群通过"加机器"几乎可以无限扩展规模，这是解决超大科学计算（气候模拟、宇宙学、分子动力学）的唯一途径。它的核心挑战全在"跨节点"——网络延迟/带宽、数据如何划分到各节点、通信与计算如何重叠、如何负载均衡（后续多个主题专门讨论）。注意区分：集群的节点内部是共享内存（多核），节点之间是分布式内存，这正是 1.3.5 说的混合架构。

### 1.4.4 异构系统：CPU + 加速器各司其职

异构系统（heterogeneous system）指在同一台机器/节点里混用不同类型的计算单元——最典型是通用 CPU 搭配一个或多个加速器（accelerator），如 GPU、FPGA、TPU 等专用芯片。思路是"用对的工具做对的事"：CPU 负责复杂控制流、操作系统、串行部分和调度（延迟优化擅长的），加速器负责规整的大规模数据并行部分（吞吐优化擅长的）。今天几乎所有顶级超算和 AI 训练集群都是 CPU+GPU 的异构系统。

直觉是"一个统筹全局的主厨（CPU）指挥一支只做重复工序但人数极多的流水线队伍（GPU）"：主厨接单、分配、处理特殊情况，把批量重活丢给流水线。异构编程的核心难点也由此而来：CPU 和加速器通常有各自的内存，数据要在两者间来回搬运（H2D/D2H 传输），搬运开销常常主导性能，因此"少搬、搬得巧、算与搬重叠"是关键（后续 GPU 主题详述，统一内存 unified memory 等机制用来缓解）。这条谱系线——多核 → 众核 → 集群 → 异构——不是四选一，而是层层叠加：一台现代超算就是"由很多异构节点（多核 CPU + 众核 GPU）经网络连成的集群"。异构软件栈（CUDA/ROCm/oneAPI 等）⚙演进快，本报告只锚概念，具体 API 以对应官方文档当前版本为准（CUDA Toolkit 13.x，2026 年中；本机无 GPU，异构实证为文档腿）。
