## 13.1 多项式时间与类 P

### 13.1.1 判定问题、抽象问题与最优化问题

复杂度理论把研究对象统一成**判定问题（decision problem）**：输入一个实例，输出只有「是（1）」或「否（0）」两种。CLRS §34.1 把一个抽象问题（abstract problem）形式化为一个二元关系，把实例集合映到解集合；当解集合是 {0,1} 时就是判定问题。

核心说明：现实里我们常关心**最优化问题（optimization problem）**——「求最大团有多大」「求最短巡回路线的长度」。理论上会先把它改写成配套的判定问题，做法是给答案加一个阈值参数 k：「是否存在规模 ≥ k 的团？」「是否存在长度 ≤ k 的巡回？」这样最优化问题就变成了一族判定问题。

辅助说明：为什么非要转成判定问题？因为整套 NP 理论（验证、归约、完全性）都是围绕「是/否」语言建立的，判定版是最干净的载体。而且判定版**不比**最优化版容易——如果判定版难，最优化版至少一样难（能解最优化就能回答判定，反之要靠二分等手段）。所以「证明判定版是 NPC」足以说明「对应的最优化问题也难」，这正是我们要的结论。初学者只需记住：**谈难度时，一律先看判定版**。

一个判定问题可以等价地看成一个**语言（language）**：所有「答案为是」的实例编码组成的字符串集合 L ⊆ {0,1}*。于是「解一个判定问题」= 「判定一个串是否属于语言 L」。

### 13.1.2 编码与「多项式相关」

要谈「多项式时间」，必须先说清「输入规模 n 是什么」——而这取决于**编码（encoding）**：怎样把一个抽象对象（整数、图……）写成 0/1 串。

核心说明：CLRS §34.1 指出，只要两种编码是**多项式相关（polynomially related）**的（彼此能在多项式时间内互相转换、长度多项式相关），那么「在一种编码下多项式可解」就等价于「在另一种编码下多项式可解」。所以只要避开「病态编码」，多项式时间这个概念对合理编码是**稳健的**、与具体编码无关。

辅助说明：这里有一个经典陷阱——**一元 vs 二进制**。把整数 N 写成一元（N 个 1）需要 N 位，写成二进制只需约 log₂N 位，两者**不是**多项式相关的（一元长度是二进制长度的指数）。很多「看起来多项式」的算法其实是对一元输入而言的多项式，对二进制输入是指数——这叫**伪多项式（pseudo-polynomial）**，子集和的动态规划就是典型（见 13.5.5）。初学者要养成习惯：**输入规模按二进制位数算**，不要按「数值大小」算。

### 13.1.3 类 P 的定义

类 P 是「能被多项式时间算法判定的语言」的集合。

P = { L ⊆ {0,1}* ： 存在常数 k 与一个算法 A，A 在 O(nᵏ) 时间内判定 L }

其中 n 是输入串长度；「判定」指对 x∈L 输出 1、对 x∉L 输出 0，且总会停机。

核心说明：直觉上，**P = 「实践中算得动」的问题类**——排序、最短路、最大流、最小生成树、判素数等都在 P 里。多项式（n、n²、n³……）随规模温和增长，指数（2ⁿ）则很快爆炸到不可算。

辅助说明：为什么用「多项式」而不是「n²」这种更具体的界当分界线？因为多项式这个类**对合理的计算模型和编码都封闭、稳健**：多项式的和、积、复合仍是多项式；换一种合理机器模型（RAM ↔ 图灵机）运行时间也只差多项式因子。所以「多项式时间可解」是一个不依赖机器细节的、鲁棒的「易解」判据。这也是 Cobham–Edmonds 论题的内容。要注意这是**理论分界**：n¹⁰⁰ 也算多项式却毫不「实用」，但作为「易/难」的粗分类，多项式是公认最合适的一刀。

#### 来源与时效
- 锚点：CLRS 4th ed (2022) §34.1「Polynomial time」（抽象问题/判定问题/编码/多项式相关/类 P 定义），核实 2026-07-26。
- 交叉核对：MIT 6.046J syllabus「Complexity: P, NP…」模块把 P 定义为「多项式时间可判定」，与 CLRS 一致；一元/伪多项式陷阱在 CLRS §34.5.5 子集和处再次点明，两处相互印证。
- 无冲突项。

## 13.2 多项式时间验证与 NP

### 13.2.1 验证算法与证书

有些问题我们不知道怎么快速**求解**，但如果有人给出一个「答案的凭据」，我们能快速**核验**。这就是「验证」。

核心说明：CLRS §34.2 定义**验证算法（verification algorithm）**是一个两输入算法 A(x, y)：x 是原实例，y 是一段**证书（certificate，也叫见证 witness）**。A 验证语言 L 的含义是

L = { x ∈ {0,1}* ： 存在证书 y，|y| = O(|x|ᶜ)，使得 A(x, y) = 1 }

即：x 属于 L，当且仅当**存在**一个多项式长度的证书 y 让验证器接受；且验证器本身跑在多项式时间内。

辅助说明：用最小例子体会——哈密顿回路问题「图 G 有没有一条经过每个顶点恰一次的回路？」直接搜可能要试指数条路径；但如果有人给你一个顶点排列当证书 y，你只要 O(V) 检查「相邻两点在 G 里有边、且首尾相连、每点恰一次」就能确认，这是多项式的。**关键不对称**：证书难找，但一旦给了就好验。NP 抓的正是这种「验证比求解容易」的结构。注意「不存在证书」时不要求快速判否——NP 只关心「是」的一侧有短证书。

### 13.2.2 类 NP 的定义

类 NP 是「能被多项式时间验证算法验证的语言」的集合。

NP = { L ⊆ {0,1}* ： 存在多项式时间验证算法 A 与常数 c，使 L = { x ： ∃y, |y|=O(|x|ᶜ), A(x,y)=1 } }

核心说明：NP 里的 N 是 **Nondeterministic（非确定）**，不是「Non-polynomial」。等价的另一种定义是「能被非确定图灵机在多项式时间内判定」——非确定机可以「猜」一个证书再验证，这与「存在短证书 + 多项式验证器」是一回事（这条等价的严格证明属 L3-05）。

辅助说明：初学者最常见的误解就是把 NP 读成「非多项式/难解」。恰恰相反，NP 里包含大量简单问题。要记住 NP 的定义是关于**验证**的、不是关于求解难度的：一个问题在 NP 里只说明「它的『是』实例有短的、可快速核验的证书」，并不说明它难。

### 13.2.3 P ⊆ NP 与 P vs NP 未解问题

核心说明：显然有

P ⊆ NP

因为若 L∈P，有多项式算法直接判定它，那把证书设成空串、让验证器忽略 y 直接判定 x 即可——所以 P 里每个问题都平凡地在 NP 里。反过来是否成立，即

P = NP ？

是计算机科学头号未解问题。它问的是：「凡是答案能被快速**验证**的问题，是否也都能被快速**求解**？」

辅助说明：绝大多数研究者相信 P ≠ NP（即存在「好验证但难求解」的问题），但**至今没有证明**。该问题由 Clay 数学研究所列为千禧年七大难题之一（2000 年设立，悬赏 100 万美元），截至 **2026-07-26 仍未解**。本报告及全库凡涉及 P 与 NP 关系一律维持「未解」结论，不采信任何声称已解的说法。相关的还有 co-NP（「否」实例有短证书的语言类）与 P 是否等于 NP∩co-NP 等，同属未解，本课点名不展开（严格讨论归 L3-05）。

#### 来源与时效
- 锚点：CLRS 4th ed (2022) §34.2「Polynomial-time verification」（验证算法/证书/类 NP/P⊆NP），核实 2026-07-26。
- 交叉核对：MIT 6.046J syllabus 同一模块以「证书 + 多项式验证器」定义 NP，与 CLRS 一致；P vs NP 的「未解」现状据 Clay Mathematics Institute「P vs NP」官方页（2000 年设立、悬赏、截至 2025-11 仍确认未解）核对。
- 无实质冲突。术语提示：不同教材对 NP 有「非确定 TM」与「验证器」两套等价定义，本课用验证器定义、L3-05 用 TM 定义，非冲突而是两个视角。

## 13.3 NP完全性与多项式归约

### 13.3.1 多项式时间（映射）归约 ≤ₚ

「归约」是把一个问题转化为另一个问题，从而**搬运难度**的工具。

核心说明：CLRS §34.3 定义语言 L₁ **多项式时间可归约到** L₂（记作 L₁ ≤ₚ L₂），若存在一个多项式时间可计算的函数 f：{0,1}* → {0,1}*，使得对所有 x，

x ∈ L₁ ⟺ f(x) ∈ L₂

这里的 ≤ₚ 是**多项式时间映射归约（也叫多对一 / Karp 归约）**。函数 f 把 L₁ 的实例翻译成 L₂ 的实例，且翻译本身花的时间是多项式。

（归约方向记号，独占一行以免混淆）

L₁ ≤ₚ L₂ 读作「L₁ 不比 L₂ 难」

辅助说明：初学者最容易搞反方向。诀窍是把 ≤ₚ 当成「难度的小于等于号」：L₁ ≤ₚ L₂ 表示「解 L₂ 的能力足以解 L₁」，所以 L₂ **至少和** L₁ 一样难。翻译方向（把 L₁ 实例变成 L₂ 实例）和难度方向（L₂ 更难）是相反的，这点务必记牢。「多对一」指 f 可以把 L₁ 的多个实例映到 L₂ 的同一个实例，但每个 L₁ 实例只映到**一个** L₂ 实例、只调用 L₂ 判定器**一次**（对比更一般的图灵归约允许多次调用，那属 L3-05）。

### 13.3.2 归约如何传递「易」与「难」

核心说明：归约的全部威力来自下面这条引理（CLRS §34.3 引理 34.3）：

若 L₁ ≤ₚ L₂ 且 L₂ ∈ P，则 L₁ ∈ P

道理很直接：要判定 x∈L₁，先花多项式时间算 f(x)，再用 L₂ 的多项式算法判定 f(x)∈L₂；两个多项式相加复合仍是多项式，所以 L₁ 也在 P 里。

辅助说明：把这条引理取**逆否命题**，就是我们判难的主武器：

若 L₁ ≤ₚ L₂ 且 L₁ ∉ P，则 L₂ ∉ P

换句话说——**已知 L₁ 难，又能把 L₁ 归约到 L₂，则 L₂ 至少一样难**。这就是「用归约判难」的逻辑内核：想说明新问题 L₂ 难，不必从零证明，只要把一个**公认难**的问题 L₁ 归约进去。这也解释了 13.3.1 里方向为什么那样定——难度顺着 ≤ₚ 往右累积。一个常见错误是把归约方向做反（从新问题归约到已知难问题），那证明的是「新问题不比已知问题难」，对判难毫无用处。

### 13.3.3 NP-难与 NP-完全

核心说明：CLRS §34.3 定义：

语言 L 是 **NP-难（NP-hard）**：对每个 L′ ∈ NP，都有 L′ ≤ₚ L。

语言 L 是 **NP-完全（NP-complete，NPC）**：L ∈ NP 且 L 是 NP-难。

即 NPC = 「既在 NP 里，又是 NP 里最难的那一档」。NPC 问题彼此之间都能多项式互归约，构成 NP 中「难度封顶」的一族。

辅助说明：NP-难与 NP-完全的区别在**是否要求自己也在 NP 里**：NP-难只要求「NP 中所有问题都能归约到它」（它可以比 NP 还难，比如某些不可判定问题也算 NP-难）；NPC 额外要求「它自己也在 NP 里」，所以 NPC 恰好卡在 NP 的「天花板」。由 13.3.2 的引理可推出一条最重要的推论：

若某个 NPC 问题 ∈ P，则 P = NP；若某个 NPC 问题 ∉ P，则所有 NPC 问题都 ∉ P（即 P ≠ NP）

这就是 NPC 之所以重要的原因——**它把「上千个看似无关的难题」和「P vs NP 这一个未解问题」绑成了一个整体**：只要有人给任何一个 NPC 问题找到多项式算法，整座大厦（几千个 NPC 问题）就同时被攻破、P=NP；反过来只要有人证明任何一个 NPC 问题没有多项式算法，就同时证明了 P≠NP。因此对一个已证 NPC 的问题，实践中的正确态度是「别再找精确多项式算法了」，转而求近似（见大主题14）、启发式或对特殊输入求解。

### 13.3.4 电路可满足性 CIRCUIT-SAT：第一个 NPC 问题

核心说明：上面的定义有个「先有鸡还是先有蛋」的问题——要证某问题 NPC，得先有**已知的** NPC 问题去归约；那第一个从哪来？CLRS §34.3 给出答案：**电路可满足性问题 CIRCUIT-SAT**（给定一个布尔组合电路，问是否存在一组输入使输出为 1）是第一个被证明的 NPC 问题。它的 NP-难性不能靠归约别人，而是**直接**证明——说明「任何 NP 问题的多项式时间验证算法都能被一个多项式规模的布尔电路模拟」，于是每个 NP 问题都能归约到 CIRCUIT-SAT。

辅助说明：这条「第一个 NPC 从验证器构造电路」的思想，正是 **Cook–Levin 定理**的核心（Cook 1971 与 Levin 独立得到）。**其完整、严格的构造（把图灵机的计算历史逐格编码成公式/电路）属 L3-05 #08（锚 Sipser 3e §7.4），本课不做严格构造**——CLRS 4e 在此也只给「电路模拟验证器」的直觉论证而非机器级全证。本课要掌握的是它的**用途**：CIRCUIT-SAT 一旦坐实，就成了归约链的「火种」，后面所有 NPC 都由它一路归约点燃（见 13.4–13.5）。历史上 Cook 1971（STOC，pp.151–158）先立此柱，Karp 1972 随即用它证明了 21 个组合问题 NPC，NPC 理论就此铺开。

#### 来源与时效
- 锚点：CLRS 4th ed (2022) §34.3「NP-completeness and reducibility」（≤ₚ 归约定义、引理 34.3、NP-hard/NP-complete 定义、CIRCUIT-SAT 为第一个 NPC），核实 2026-07-26。
- 一手交叉核对：Cook 1971「The Complexity of Theorem-Proving Procedures」（STOC 3rd, Shaker Heights, pp.151–158）确立布尔可满足性的 NP 完全性（Cook–Levin 定理源头）；Karp 1972「Reducibility Among Combinatorial Problems」用多项式归约证明 21 个问题 NPC——二者与 CLRS 的「第一个 NPC + 归约扩散」叙述一致。MIT 6.046J「Reductions」模块同样以「≤ₚ 传递难度」为主线。
- 边界标注：Cook–Levin 的**严格构造**在 CLRS 4e 亦仅作直觉论证，完整证明归 L3-05（Sipser §7.4），本报告不复现，非冲突而是分账。
- 「≤ₚ」在少数教材写作「≤ₘᵖ」（多对一多项式归约）以区别图灵归约 ≤ᵀᵖ；本课的 ≤ₚ 特指多对一（Karp）归约。

## 13.4 NP完全性证明

### 13.4.1 证明一个问题是 NPC 的通用模板

核心说明：CLRS §34.4 给出证明语言 L 是 NPC 的**五步套路**（有了 CIRCUIT-SAT 这个火种后，其余全靠归约）：

```text
证明 L 是 NP-完全：
  1. 证 L ∈ NP           —— 给出多项式长度证书 + 多项式时间验证器
  2. 选一个已知 NPC 问题 L′
  3. 设计归约 f：把 L′ 的任意实例 x 变成 L 的实例 f(x)
  4. 证 f 可在多项式时间内计算
  5. 证 x ∈ L′ ⟺ f(x) ∈ L   （两个方向都要证：⇒ 和 ⇐）
```

辅助说明：这五步里初学者最常漏的是**第 1 步**和**第 5 步的「⇐」方向**。漏第 1 步就只证了 NP-难、没证 NPC（别忘了 NPC = NP-难 + 自己在 NP 里）。第 5 步必须证**双向等价**：光证「x 是 ⇒ f(x) 是」不够，还要证「f(x) 是 ⇒ x 是」（常用逆否：x 否 ⇒ f(x) 否），否则归约可能把「否」实例也映成「是」实例，等价性就断了。另一个易错点是把归约方向做反（见 13.3.2）——一定是**从已知 NPC 归约到目标 L**。

### 13.4.2 公式可满足性 SAT

核心说明：CLRS §34.4 第一个用归约证明 NPC 的是**（布尔）公式可满足性 SAT**：给定一个布尔公式（变量 + ∧ ∨ ¬ 与括号），问是否存在一组真值赋值使公式为真。证明走

CIRCUIT-SAT ≤ₚ SAT

即把电路的每根导线设成一个变量、每个门设成一条「输出变量 ⟺ 门的逻辑」的小公式，全部合取起来——电路可满足当且仅当该公式可满足，且构造是多项式规模。

辅助说明：这里有个技术细节值得点一下：不能天真地把电路「顺着展开成一个大公式」，因为一根导线若被多个门共享，展开会导致公式规模指数膨胀。CLRS 的做法是**给每根导线引入一个变量**、用合取把各门的局部约束串起来，规模就控制在多项式。这个「引入辅助变量避免爆炸」的技巧在很多归约里反复出现。SAT 是 NP 里的「万能语言」，后续归约常从它或它的规范形式 3-CNF-SAT 出发。

### 13.4.3 3-CNF-SAT

核心说明：**3-CNF-SAT** 是把 SAT 限制成**合取范式（CNF）且每个子句恰含 3 个文字**的版本：公式形如若干子句的合取，每个子句是恰好 3 个文字（变量或其否定）的析取。CLRS §34.4 证

SAT ≤ₚ 3-CNF-SAT

分三步把任意公式化成 3-CNF：先转成公式解析树、引入变量得到类似 CNF 的形式；再用分配律等化为 CNF；最后把过长或过短的子句拆/补成恰好 3 文字（长子句用新变量链式拆分，短子句用补充变量填齐）。全程多项式且保持可满足性。

辅助说明：为什么专挑「恰好 3 文字」这么specific的形式当归约起点？因为 3-CNF-SAT **结构极规整**（全是「3 选 1 为真」的子句），做后续归约（尤其到图问题）时特别顺手——每个子句对应一个统一的「小部件（gadget）」。有趣的对照是 **2-CNF-SAT（每子句 2 文字）反而在 P 里**（可用蕴含图的强连通分量多项式求解），所以「3」是可满足性从易到难的临界点。这个「2 易 3 难」的跳变是初学者印象深刻的知识点。下面 13.5 的团、子集和都直接从 3-CNF-SAT 归约。

（可选实测：为坐实「3-CNF-SAT 到 CLIQUE 的归约保可满足性」，在 scratchpad 用 Python 对随机小 3-CNF 公式做了暴力 SAT 与归约后图的 k-团判定对拍，见 13.5.1 实测块。）

#### 来源与时效
- 锚点：CLRS 4th ed (2022) §34.4「NP-completeness proofs」（五步套路、CIRCUIT-SAT ≤ₚ SAT ≤ₚ 3-CNF-SAT），核实 2026-07-26。
- 一手交叉核对：Cook 1971 已直接给出 CNF-SAT 的 NP 完全性，与 CLRS「SAT/3-CNF-SAT 为 NPC」结论一致；Karp 1972 以 SAT（他记作 satisfiability）为归约链源点，同样印证。
- 常识提示「2-SAT ∈ P」为广泛教材共识（Aspvall–Plass–Tarjan 1979 的强连通分量算法），本课点名不展开、归约细节非本课重点。
- 无冲突。

## 13.5 经典 NPC 问题

> 本节是「已知 NPC 清单 + 归约地图」。CLRS §34.5 的归约主链（含 §34.3–34.4）为：
>
> CIRCUIT-SAT ≤ₚ SAT ≤ₚ 3-CNF-SAT ≤ₚ CLIQUE ≤ₚ VERTEX-COVER ≤ₚ HAM-CYCLE ≤ₚ TSP
>
> 另有一条支链：3-CNF-SAT ≤ₚ SUBSET-SUM
>
> 记住这张图，就掌握了本课「判难工具箱」的骨架。

### 13.5.1 团问题 CLIQUE（§34.5.1）

核心说明：**团（clique）** 是无向图里两两相邻的顶点子集；CLIQUE 判定问题问「图 G 是否含有规模 ≥ k 的团？」。CLRS §34.5.1 证

3-CNF-SAT ≤ₚ CLIQUE

构造：对含 k 个子句的 3-CNF 公式，为每个子句的每个文字造一个顶点（同一子句 3 个顶点一组，共 k 组）；两个顶点连边当且仅当它们**属于不同子句**且**不互相矛盾**（不是同一变量的正负）。则公式可满足 ⟺ 该图有规模为 k 的团。

辅助说明：团的顶点必来自 k 个不同子句（同组内无边），选出的 k 个两两相容的文字正好给出「每个子句都有一个为真的文字」的赋值——这就是把「逻辑可满足」翻译成「图里挑互不冲突的一组代表」。CLIQUE 属 NP 是显然的（证书 = 那 k 个顶点，验证 = 检查两两有边，多项式）。这是「把逻辑问题变成图问题」的范式归约。

可选实测（Python 3.11.15，Linux 6.18.5 x86_64；脚本仅存 scratchpad，跑完即清）：对随机小 3-CNF 公式，分别用暴力 SAT 求解器与「归约后图是否含 (#子句)-团」判定，检验二者结论是否总一致，并对找到的团调用证书验证器确认合法。真实输出：

```text
3-CNF-SAT satisfiable  <=>  reduced graph has a (#clauses)-clique
agreement over 300 random instances: 300/300
subset-sum S=[3, 34, 4, 12, 5, 2], t=9: True, certificate indices=(2, 4), sum=9
```

300/300 一致，佐证「3-CNF-SAT ≤ₚ CLIQUE 保持可满足性」；末行是 13.5.5 子集和的证书演示。此为可选补充，不替代多来源比对。

### 13.5.2 顶点覆盖 VERTEX-COVER（§34.5.2）

核心说明：**顶点覆盖（vertex cover）** 是一个顶点子集，使图中每条边至少有一个端点在其中；VERTEX-COVER 问「G 是否有规模 ≤ k 的顶点覆盖？」。CLRS §34.5.2 证

CLIQUE ≤ₚ VERTEX-COVER

归约靠一个漂亮的对偶：在图 G 中，V′ 是团 ⟺ 在**补图** Ḡ 中 V∖V′ 是顶点覆盖。于是「G 有 k-团」⟺「Ḡ 有 (|V|−k)-顶点覆盖」，取补图即为多项式归约。

辅助说明：这条归约几乎不用造复杂部件，只需「取补图、换阈值」，是理解「归约有时只是换一个等价视角」的好例子。背后的通用事实：**独立集、团、顶点覆盖三者互为对偶**——V′ 是 G 的独立集 ⟺ V′ 是 Ḡ 的团 ⟺ V∖V′ 是 G 的顶点覆盖。三个问题本质同难。顶点覆盖也是大主题14 讲 2-近似的招牌例子，可前后呼应。

### 13.5.3 哈密顿回路 HAM-CYCLE（§34.5.3）

核心说明：**哈密顿回路（Hamiltonian cycle）** 是一条经过图中每个顶点**恰好一次**并回到起点的回路；HAM-CYCLE 问「G 是否存在哈密顿回路？」。CLRS §34.5.3 证

VERTEX-COVER ≤ₚ HAM-CYCLE

通过精心设计的「部件（gadget）」把顶点覆盖实例编码成图：用一种「边部件」强制每条边被覆盖，用 k 条「选择路径」对应覆盖里的 k 个顶点，使得原图有 k-顶点覆盖 ⟺ 构造图有哈密顿回路。

辅助说明：这是本章第一条**重部件归约**——构造相当技术性，本课（广度优先）只需知道「存在这样一条多项式归约、结论成立」，**不要求复现部件构造细节**（那属专家纵深）。要区分**哈密顿回路 vs 欧拉回路**：欧拉回路要求走遍每条**边**恰一次，有简单的多项式判据（连通且每点度为偶）、在 P 里；哈密顿回路要求走遍每个**顶点**恰一次，却是 NPC。「点」与「边」一字之差、难度天壤，是经典易混点。

### 13.5.4 旅行商问题 TSP（§34.5.4）

核心说明：**旅行商问题（traveling-salesman problem, TSP）** 的判定版问「在带权完全图上，是否存在一条经过所有城市各一次、总长 ≤ k 的巡回？」。CLRS §34.5.4 证

HAM-CYCLE ≤ₚ TSP

归约极简：给哈密顿回路实例的图补成完全图，原有边权重设 0（或 1），补出来的边权重设一个大数，则「总长 ≤ 0（或 ≤ n）的巡回」存在 ⟺ 原图有哈密顿回路。

辅助说明：TSP 是最出名的 NPC 问题，几乎是「难解」的代名词。这里点两个边界：其一，上面归约得到的 TSP 实例**不满足三角不等式**（补边权重很大）；一旦限定满足三角不等式，TSP 仍 NPC，但可做 2-近似甚至 3/2-近似（Christofides），这是大主题14 的内容，可前后呼应。其二，判定版难，对应的**最优化 TSP** 至少一样难（见 13.1.1）。归约本身简单，说明「把已知 NPC 塞进一个更一般的问题」往往只需轻量翻译。

### 13.5.5 子集和 SUBSET-SUM（§34.5.5）

核心说明：**子集和（subset-sum）** 问「给定一个正整数集合 S 和目标 t，是否存在子集其元素之和恰为 t？」。CLRS §34.5.5 证

3-CNF-SAT ≤ₚ SUBSET-SUM

构造用**数字编码**：为每个变量和每个子句设计精心安排的十进制大数（每一位对应一个变量或子句），使得「选出一个和为特定 t 的子集」恰好对应「一组令每个子句为真的赋值」，且各位不进位、互不干扰。

辅助说明：子集和是理解 13.1.2「伪多项式」陷阱的最佳落点。它有一个 O(n·t) 的动态规划算法（大主题7 风格），看似多项式——但 t 是一个**数值**，输入里 t 只占约 log t 位，O(n·t) 对**输入位数**而言是**指数**，这叫伪多项式。所以子集和是 NPC 与「有伪多项式算法」并不矛盾：真正的多项式要对二进制输入长度而言。上面 13.5.1 实测末行给了一个子集和的正例（S=[3,34,4,12,5,2], t=9，证书子集 {4,5}，和为 9），演示「证书 = 选中的子集，验证 = 求和比对」这个 NP 验证器。

### 13.5.6 归约地图与本课边界小结

核心说明：把 13.3–13.5 串起来，本课要掌握的「判难工具箱」就是下面这张归约地图（箭头 A→B 表示 A ≤ₚ B）：

```text
                        CIRCUIT-SAT   (第一个 NPC，火种)
                             │
                            SAT
                             │
                         3-CNF-SAT
                        ┌────┴─────────┐
                      CLIQUE        SUBSET-SUM
                        │
                    VERTEX-COVER
                        │
                     HAM-CYCLE
                        │
                       TSP
```

要证一个**新**问题 X 是 NPC，标准动作：(1) 证 X∈NP；(2) 从这张图里挑一个已知 NPC 问题 L′，构造 L′ ≤ₚ X 并证双向等价（13.4.1 五步）。

辅助说明：本课到此为止——**会用归约判难 + 记住这张 NPC 清单/地图**。再往下的「为什么第一个 NPC 成立」的严格构造（Cook–Levin 全证）、P/NP/PSPACE 等复杂度类的图灵机形式定义、层级定理等，归 **L3-05 计算理论 #08**（Sipser 3e Ch7），本课只点名指路、不做严格构造。遇到一个被证 NPC 的问题，实践对策不是「继续找精确多项式算法」，而是转向近似算法（大主题14）、启发式、参数化或对特殊输入的多项式算法。全程谨记：P vs NP 截至 2026-07-26 **仍未解**，「NPC 问题没有多项式算法」是**普遍相信但未被证明**的猜想，不可当定论陈述。
