## 8.1 活动选择问题

### 8.1.1 问题设定：在一个资源上排最多的相容活动

活动选择问题（activity-selection problem）是：给定 n 个活动，每个活动 i 有一个开始时间 sᵢ 和一个结束时间 fᵢ（占用区间 [sᵢ, fᵢ)），同一时刻资源（如一间教室）只能给一个活动用。两个活动 i、j **相容（compatible）** 指它们的时间区间不重叠，即

fᵢ ≤ sⱼ 或 fⱼ ≤ sᵢ

目标是选出一个**两两相容**的活动子集，使被选中的活动**数量最多**（注意：是最大化「个数」，不是最大化占用时长）。

核心说明：CLRS §15.1 给出的贪心策略是——把所有活动**按结束时间 fᵢ 从小到大排序**，然后反复挑「在与已选活动都相容的前提下、结束最早」的那个活动。因为已排序，这等价于：从头扫一遍，谁的开始时间不早于「上一个选中活动的结束时间」，就选谁。

辅助说明：为什么盯着「最早结束」而不是「最早开始」或「时长最短」？直觉是——**越早结束，留给后面的空闲时间越多，机会越大**。「最早开始」会被一个开得早但拖得很长的活动坑掉；「时长最短」也可能选中一个卡在正中间、把两侧都挡住的短活动。这三种贪心里，只有「最早结束」被证明总是最优（8.2 会给证明骨架）。最小反例帮助记忆：活动 A=[1,10)、B=[2,3)、C=[4,5)，按「最早开始」会先选 A 而只得 1 个，按「最早结束」先选 B 再选 C 得 2 个。

### 8.1.2 贪心选择性质与最优子结构（本问题为什么能贪心）

一个问题能用贪心正确求解，靠两块基石：**贪心选择性质**与**最优子结构**。

贪心选择性质（greedy-choice property）：存在一个最优解，它包含「结束时间最早的那个活动」。CLRS §15.1 的证明是**交换论证**（8.2 展开通式）：取任意一个最优解 A，设 A 中结束最早的活动是 k，而全局结束最早的活动是 m；把 A 里的 k 换成 m，因为 m 结束得不比 k 晚，换掉后其余活动仍与 m 相容，得到的解大小不变、仍最优——所以「含最早结束活动」的最优解一定存在。

最优子结构（optimal substructure）：选定第一个活动（全局最早结束的 m）之后，剩下的问题变成「在所有开始时间 ≥ fₘ 的活动里，再选最多的相容子集」，这是一个**规模更小的同类子问题**；原问题的最优解 = {m} ∪ 子问题的最优解。

核心说明：这两条合起来保证「每一步都放心地拿当前最早结束的相容活动」，永远不必回头反悔。

辅助说明：初学者容易把「贪心选择性质」和「最优子结构」混为一谈。区别在于：最优子结构说的是「大问题的最优解**含**子问题的最优解」（这一点 DP 也需要）；贪心选择性质是贪心**独有**的更强条件——「第一步的局部最优选择**不必枚举**就一定能进某个全局最优解」。DP 要在多个子问题里挑最好的（做完子问题才知道怎么选），贪心则是**先选后算**，选完只剩一个子问题。这正是贪心比 DP 快的根源。

### 8.1.3 算法与复杂度

按结束时间排序后，一趟线性扫描即可。伪代码（活动已按 f 升序，f[0]=0 作哨兵或从第 1 个直接起选）：

```text
GREEDY-ACTIVITY-SELECTOR(s, f, n):   // 假定 f[1..n] 已升序
    A = {1}                          // 先选结束最早的活动 1
    k = 1
    for m = 2 to n:
        if s[m] >= f[k]:             // 活动 m 与最近选中的活动 k 相容
            A = A ∪ {m}
            k = m
    return A
```

排序是 Θ(n lg n)，扫描是 Θ(n)，因此总时间：

Θ(n lg n)

若输入已按结束时间排好序，则只需

Θ(n)

核心说明：算法只用一个变量 k 记住「最近一次选中的活动」，因为已排序，后来者只要和 k 相容就一定和之前所有选中的都相容。

辅助说明：CLRS 同时给了递归版（GREEDY-ACTIVITY-SELECTOR 的递归形式）和上面的迭代版，两者等价、迭代版更省栈。易错点：相容判定写成 `s[m] >= f[k]`（后者结束 ≤ 前者开始）——区间取半开 [s,f) 时端点相等 `s[m]==f[k]` 视为相容；若题目定义为闭区间要用严格 `>`。我把贪心的解大小和「暴力枚举所有子集取最大相容子集」对拍，验证贪心确实拿到最大个数：

```text
8.1 activity greedy size == brute-force max size (2000 trials): True
```

2000 组随机活动全部一致（贪心解的**个数**等于暴力最优），加固了「最早结束」贪心的正确性（正确性来源仍是 §15.1 的交换论证）。

## 8.2 贪心策略要素与交换论证

### 8.2.1 贪心的一般套路：如何设计一个贪心算法

贪心算法（greedy algorithm）在每一步都做「当前看起来最好」的选择（局部最优），并寄希望于这些局部最优拼出全局最优。CLRS §15.2 把设计贪心算法归纳成一套固定流程：

1. 把最优化问题转成「做一次选择后剩下一个待解子问题」的形式；
2. 证明**贪心选择性质**：总存在一个最优解，其第一步就是这个贪心选择；
3. 证明**最优子结构**：做完贪心选择后，剩下的子问题的最优解拼上这一步，就是原问题的最优解。

核心说明：一个问题能贪心，充要地依赖上面第 2、3 两条。缺了「贪心选择性质」，局部最优就未必进得了全局最优，贪心会出错。

辅助说明：初学者常把「贪心」当成一种直觉技巧随手就用，但它其实是**需要证明**的——很多问题「贪心看着对、其实错」（下一小节的 0-1 背包就是）。所以 §15.2 的价值不在多记一个算法，而在教你「怎么判断一个贪心该不该信」。设计时的实操顺序通常反过来：先猜一个贪心规则（如「拿性价比最高的」「拿最早结束的」），再试着用交换论证去证它——证得通就用，证不通就找反例、退回 DP。

### 8.2.2 交换论证：贪心正确性的标准证明模式

交换论证（exchange argument）是证明「贪心选择性质」的通用模板，本课**最高教学价值点**之一，务必吃透。它的骨架是：

1. 取任意一个最优解 O（假设它**不**含贪心的第一步选择 g）；
2. 在 O 里找到「贪心本应选 g、O 却选了别的 x」的那个位置；
3. 把 O 中的 x **换成** g（论证换完后解依然**可行**、且目标值**不比原来差**）；
4. 于是得到一个「含 g 且同样最优」的解——说明「含贪心选择的最优解」总是存在。

核心说明：交换论证的精髓是「**不必构造整个最优解，只需证明第一步可以安全地替换成贪心选择**」。它把「贪心全程都对」这个难命题，降解为「第一步能进某个最优解」这个可局部验证的命题，再靠最优子结构递推到全程。

辅助说明：为什么第 3 步「换完不变差」是关键？因为贪心选择 g 是「当前最优」——在活动选择里 g 结束最早，换进去不会挤占更多后续时间；在最小生成树的 Kruskal 里 g 是最轻的安全边，换进去权重不增。所以替换要么让解更好、要么持平，绝不变坏。易错点：交换论证证的是「**存在**一个含 g 的最优解」，不是「**所有**最优解都含 g」——最优解可能不唯一，我们只需要其中一个配合贪心即可。这一节的套路会在大主题11（Kruskal/Prim 的「安全边」「切割性质」）里原样复用，届时回看会更有体感。

### 8.2.3 贪心 vs 动态规划：0-1 背包与分数背包的经典对照

贪心和 DP（大主题7）都要求**最优子结构**，区别在贪心还额外要**贪心选择性质**。CLRS §15.2 用背包问题把这条界线画得最清楚：

- **分数背包（fractional knapsack）**：物品可切成任意比例装。贪心「按单位重量价值 vᵢ/wᵢ 从高到低装，装满为止（最后一件可切一部分）」**是最优的**——它满足贪心选择性质。
- **0-1 背包（0-1 knapsack）**：每件物品要么整件拿、要么不拿。同样的「按 vᵢ/wᵢ 贪心」**会出错**，必须用 DP。

核心说明：同一个「按性价比贪心」的规则，在分数背包对、在 0-1 背包错——差别就在「能不能切」。能切时，最后总能用一小块高性价比物品把背包**恰好填满**，不浪费容量；不能切时，贪心可能被迫留下一段填不满的空隙，反而不如「放弃最高性价比、改装两件把空间用尽」。

辅助说明：一个最小反例（CLRS 风格）：容量 W=50，三件物品 (价值,重量) = (60,10)、(100,20)、(120,30)，单位价值分别是 6、5、4。0-1 贪心先拿 6、再拿 5，装了重量 30、价值 160，剩 20 装不下第三件；但最优是拿后两件（重量 50、价值 220）。分数背包里则可以再切 20/30 的第三件补满，贪心就对了。这个对照的意义：**看到一个最优化问题，先问「贪心选择性质成立吗」——成立才贪心，不成立就退回 DP**。这正是大主题7 与本大主题「选型证明对照」的核心，也是两章刻意相邻编排的原因。

## 8.3 Huffman 编码

### 8.3.1 前缀码与最优编码问题

Huffman 编码解决的是**无损数据压缩**里的最优前缀码问题。给定一组字符及其出现频率 freq(c)，要给每个字符分配一个二进制码字，使**编码后的总位数最小**。所用的是**前缀码（prefix code，又称前缀无关码）**——任何字符的码字都不是另一个字符码字的前缀。

核心说明：前缀码的好处是**解码无歧义且无需分隔符**——从左到右扫码流，一旦匹配到某个码字就立刻确定一个字符，不会与更长的码字混淆。前缀码天然对应一棵**二叉树**：每个字符是叶子，从根到该叶子的路径（左=0、右=1）就是它的码字，字符的码字长度 = 它在树中的深度。

一段编码的总代价（总位数）是：

B(T) = Σ_{c ∈ C} freq(c) · d_T(c)

其中 d_T(c) 是字符 c 在编码树 T 中的深度（= 码字长度）。目标就是找使 B(T) 最小的树 T。

辅助说明：为什么要「前缀」而不用等长码？因为等长码（如每字符固定 3 位）不管字符频率高低都花一样的位数；而让高频字符用短码、低频字符用长码，总位数能显著下降——这就是可变长前缀码的价值。易错点：不是前缀码就无法即时解码，例如码字 {a=1, b=10} 里 `10` 既可能是 b、也可能是 a 后跟某串，产生歧义。

### 8.3.2 Huffman 的贪心构造

Huffman 算法用贪心自底向上建这棵树：**反复取出当前频率最小的两个节点，合并成一个新节点（频率为两者之和），放回集合**，直到只剩一个节点（根）。用二叉最小堆（大主题4 的优先队列）维护「当前最小频率」。

```text
HUFFMAN(C):                      // C 为 n 个字符，各带 freq
    Q = 以 freq 为键的最小优先队列(C)
    for i = 1 to n-1:
        z = new node
        z.left  = x = EXTRACT-MIN(Q)
        z.right = y = EXTRACT-MIN(Q)
        z.freq  = x.freq + y.freq
        INSERT(Q, z)
    return EXTRACT-MIN(Q)        // 剩下的唯一节点即为树根
```

用最小堆时，n 个字符共做 n−1 次合并、每次两抽一插各 O(lg n)，总时间：

O(n lg n)

核心说明：贪心选择性质在这里是——「频率最小的两个字符，一定可以放在最优树的**最深一层、且互为兄弟**」。CLRS §15.3 用交换论证证明：若某最优树里它们不在最深层，把它们和最深层的叶子交换，总代价不会增加。

辅助说明：直觉是「越低频的字符，越该被推到越深（码字越长）的地方，好把浅层的短码留给高频字符」。合并两个最小频率节点，相当于「先把这两个最不重要的字符捆在一起、让它们共享一条长路径」，然后把它们当成一个整体继续参与后续合并。这一步步合并恰好从叶子往根长出一棵最优树。

### 8.3.3 编码长度与熵下界

Huffman 码是**最优前缀码**，其平均码长逼近信息论的熵下界。设各字符概率 p(c)=freq(c)/总频，熵定义为

H = − Σ_c p(c) · log₂ p(c)

Shannon 无噪信源编码定理给出：任何前缀码的平均码长 L 满足 L ≥ H，而 Huffman 这样的最优前缀码满足

H ≤ L < H + 1

核心说明：熵 H 是「每字符平均至少需要多少比特」的理论下界，Huffman 达不到分数比特（码长必须是整数），所以最好情形贴着 H、最坏也不超过 H+1。

辅助说明：CLRS §15.3 的经典例子——6 个字符频率 a:45、b:13、c:12、d:16、e:9、f:5（单位千次），Huffman 得到的平均码长约 2.24 位/字符，而定长 3 位编码要 3.0 位/字符，省下约 25%。我把 Huffman 实现出来，验证这个例子并检验「H ≤ L < H+1」在随机分布上普遍成立：

```text
8.3 Huffman: entropy H <= avg < H+1 held for 500 random dists; max(avg-H)=0.7238
   CLRS example a:45..f:5 -> avg code length = 2.240 bits/char (fixed-3-bit=3.0) codelens= {'a': 1, 'b': 3, 'c': 3, 'd': 3, 'e': 4, 'f': 4}
```

500 组随机频率分布下平均码长都落在 [H, H+1) 内（实测最大超出熵 0.72 位，仍 < 1）；CLRS 例子复现出 2.240 位/字符，与教材一致（a 码长 1、f/e 码长 4，高频短、低频长）。实测加固了「最优前缀码 + 熵下界」的结论（正确性来源仍是 §15.3 的交换论证与 Shannon 定理）。

易错点：Huffman 只在「逐字符独立编码」这个模型下最优；对有上下文相关性的真实数据，算术编码、字典法（LZ 系列）等可突破逐字符熵、压得更狠。本课止于「Huffman 是最优**前缀码**、逼近逐字符熵」，更强的压缩模型属信息论/数据压缩专课，点名即可。

## 8.4 离线缓存

### 8.4.1 问题设定：已知全部请求序列的缓存替换

离线缓存（offline caching）是 CLRS 4e **新增为正文的一节**（3e 中是习题，4e §15.4 扩成完整一节，取代了原 3e 的拟阵两节——见 §8.5）。设有一个能放 k 个数据块的高速缓存和一段**事先完全已知**的数据访问请求序列。处理每个请求时：

- 若请求的块已在缓存中——**缓存命中（cache hit）**，无代价；
- 若不在——**缓存缺失（cache miss）**，须把它调入缓存；若缓存已满，必须**驱逐（evict）** 一个已有块腾位置。

目标是选一套驱逐策略，使整段序列的**缓存缺失次数最少**。

核心说明：「离线」指**整个请求序列在决策前就完全已知**——这是理想化设定，让我们能算出「理论上最少能缺失多少次」，作为衡量现实（在线）策略好坏的标尺。

辅助说明：现实里的缓存（CPU cache、页面置换、CDN）都是**在线（online）** 的——处理当前请求时看不到未来请求，只能靠 LRU（最近最少使用）、FIFO 等启发式。离线缓存回答的是「假如能预知未来，最好能做到多好」。易错点：别把离线缓存的最优策略当成能直接部署的算法——它需要未来信息，现实用不了；它的用途是当**基准（benchmark）**，比如评估 LRU 离最优差多远（这与大主题15「在线算法/竞争分析」直接接续）。

### 8.4.2 furthest-in-future（Belady）：贪心且最优

CLRS §15.4 给出的最优离线策略是 **furthest-in-future（最远将来使用，又称 Belady 最优置换 / MIN 算法）**：发生缺失且缓存已满时，**驱逐「在未来最久才会再次被用到（或今后再也不用）」的那个块**。

核心说明：这是一个贪心策略——每次驱逐都做「当前看最不亏」的选择：赶走最晚才需要的块，因为它最不急着用。CLRS 用**交换论证**证明它给出全局最少的缺失次数：任何其他最优策略的某一步驱逐若与 furthest-in-future 不同，都可以在不增加总缺失数的前提下改成它。

辅助说明：直觉——缓存是稀缺座位，谁最晚才来（用到），谁就最该先让座。把「最快要用的块」赶走显然亏，因为很快又得把它调回来、白白多一次缺失。这个论证是 8.2 交换论证模板的又一次实例化，可与活动选择/Huffman 对照体会「同一套证法、换一个问题」。我实现 furthest-in-future，并与「暴力枚举所有驱逐决策取最小缺失数」对拍：

```text
8.4 offline caching: Belady furthest-in-future == brute-force min misses (400 trials): True
```

400 组随机请求序列（缓存容量 k∈{1,2,3}）下，furthest-in-future 的缺失数都等于暴力最优，证实其最优性（正确性来源仍是 §15.4 的交换论证）。

### 8.4.3 缓存缺失的类型与在线策略指路

CLRS §15.4 还区分了缓存缺失的成因，常见分类（「3C」）：

- **强制缺失（compulsory / cold miss）**：某块第一次被访问，缓存里从没有过，无论如何都会缺失；
- **容量缺失（capacity miss）**：因缓存装不下工作集而被迫驱逐后又重新访问导致；
- （在组相联缓存里还有**冲突缺失 conflict miss**，属体系结构话题）。

核心说明：furthest-in-future 能消除的是「可避免的」容量缺失里最优的那部分；强制缺失谁也躲不掉。

辅助说明：本课在离线最优这里止步。**在线**缓存策略（LRU/FIFO/LFU）及其**竞争比**分析（LRU 是 k-竞争的、随机 marking 更优）属大主题15「在线算法」与下游 L6-01 高级算法「在线算法/竞争分析」，本报告点名指路、不展开。缓存缺失分类与硬件层实现（组相联、替换位）属计算机组成/体系结构课，同样点名即可。furthest-in-future 常被拿来当「在线策略能有多接近最优」的黄金对照。

### 8.5.2 拟阵是什么、与贪心的关系（入门点名 + 指路）

尽管移出正文，拟阵作为「贪心为何有效」的统一理论仍值得初学者知道「是什么、指向哪」。

核心说明：**拟阵（matroid）** 是一个二元组 M=(S, ℐ)，S 是有限集，ℐ 是 S 的某些子集构成的族（称「独立集」），满足两条公理——

- 遗传性（hereditary）：若 A ∈ ℐ 且 B ⊆ A，则 B ∈ ℐ（独立集的子集仍独立）；
- 交换性（exchange property）：若 A, B ∈ ℐ 且 |A| < |B|，则存在 x ∈ B∖A 使 A ∪ {x} ∈ ℐ。

在**带权拟阵**上，「每次贪心地加入不破坏独立性的最大权元素」求出的独立集**一定是最大权的**——这就是拟阵上的贪心正确性定理（Rado–Edmonds 定理）。

辅助说明：拟阵抽象出了「为什么某些贪心一定对」的共性——8.1 的活动选择、大主题11 的最小生成树（图拟阵：森林即独立集，Kruskal 就是拟阵贪心）之所以能贪心，本质上都是「在某个拟阵结构上跑贪心」。它是把 §15.2「贪心选择性质」进一步一般化的理论框架。本课**不展开**这套理论（4e 已不在正文，且属专家纵深）；想深入的读者可查 CLRS 官方在线补充材料对应节、或 3e §16.4–16.5，下游「组合优化 / 高级算法」课会正式讲。这里点名到「知道拟阵是贪心正确性的统一解释、且在 4e 已移线上」即可。
