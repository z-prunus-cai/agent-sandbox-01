## 3.1 雇佣问题与概率分析

### 3.1.1 雇佣问题的设定

雇佣问题（the hiring problem）是 CLRS 用来引入概率分析的一个玩具场景：你要雇一名助理，中介每天送来一位候选人，你当天面试完必须立刻决定；为了「任何时刻手上都是见过的最好的人」，只要今天这位比现任更好，你就辞掉现任、雇下今天这位。面试每人花费小代价 c_i，雇一人花费大代价 c_h（c_h ≫ c_i，因为要付中介费+辞退成本）。面试 n 个人的面试总代价固定是 Θ(n·c_i)，真正波动的是**雇了几次**。

设总共雇了 m 次，则雇佣部分的代价是 m·c_h，总代价为：

O(c_h · m + c_i · n)

核心结论先摆出来：这个 m 完全取决于候选人到来的**顺序**，所以「雇几次」不是一个固定数，而要看输入顺序——这正是把概率引进算法分析的入口。

初学者的直觉锚：把候选人的「好坏」想成一串数字，雇佣一次 = 遇到一个「到目前为止的新纪录」。如果候选人恰好按从差到好的顺序来（最坏顺序），那每个人都是新纪录，要雇 n 次；如果最好的第一个就来，之后再没人超过他，就只雇 1 次。同一批人、不同顺序，雇佣次数从 1 到 n 天差地别。

一个易错点：面试代价和雇佣代价是两笔账。面试是每人都要做的固定开销 Θ(n)，省不掉；概率分析关心的只是那笔会剧烈波动的雇佣开销，也就是「新纪录出现了几次」。

### 3.1.2 最坏情形分析 vs 平均（期望）情形分析

如果只做最坏情形分析，答案很悲观：存在一种输入顺序（候选人严格递增地变好）让你雇满 n 次，代价 Θ(n·c_h)。但这个最坏顺序在实际中往往罕见，用它来估计代价太保守。

于是引入**概率分析**（probabilistic analysis）：不盯着最坏的那一个输入，而是假设输入服从某个概率分布，计算代价在这个分布下的**期望值**。对雇佣问题，我们假设候选人到来的顺序是「n 个人的一个均匀随机排列」（等价于 n! 种顺序等概率出现）。在这个假设下要回答的是：

E[雇佣次数] = ?

概率分析算的是「在假设的输入分布下的平均行为」，它给出的是期望代价，不是对每一个具体输入的保证。

为什么用「平均」而不是「最坏」？因为很多算法的最坏情形只在极少数刁钻输入上出现，用最坏值报价会严重高估典型开销。但平均分析有个前提隐患——它依赖「输入真的随机」这个假设。如果现实里输入不随机（比如对手故意喂最坏顺序），平均分析的结论就落空了。这个隐患正是 3.3 要解决的：与其祈祷输入随机，不如让算法自己去随机化输入。所以本章的叙事是「先假设输入随机（概率分析）→ 再让算法制造随机（随机化算法）」。

### 3.1.3 均匀随机排列假设与「候选人 i 是新纪录」的概率

概率分析需要把「输入随机」这个假设量化。这里的假设是：n 位候选人的到来顺序是一个**均匀随机排列**——n! 种排列每种出现的概率都是 1/n!。在这个假设下有一个关键的小结论：

P(候选人 i 比前 i−1 位都好) = 1/i

在前 i 位候选人里，「最好的那位恰好排在第 i 个位置」的概率是 1/i，因为这 i 个人谁排最后是等可能的。而「候选人 i 触发一次雇佣」当且仅当 i 是前 i 位里的最好者。

这一步是全章的技术支点，务必想清楚。只看前 i 位候选人，他们内部的相对名次有 i! 种排法、等概率；其中「最大者恰在第 i 位」占 (i−1)!/i! = 1/i。注意这里用的是**相对名次**，与这 i 个人具体是谁、他们和后面的人比如何都无关——这正是均匀随机排列假设的威力。这个 1/i 会在 3.2 里乘上指示器随机变量，直接加出期望 ≈ ln n。

## 3.2 指示器随机变量

### 3.2.1 指示器随机变量的定义

指示器随机变量（indicator random variable）是把「某事件是否发生」翻译成 0/1 数字的工具。给定样本空间和事件 A，定义：

I{A} = 1（若 A 发生）; I{A} = 0（若 A 不发生）

它最有用的性质是：它的期望恰好等于事件发生的概率。设 X_A = I{A}，则：

E[X_A] = 1·P(A) + 0·P(¬A) = P(A)

指示器随机变量把「求概率」和「求期望」这两件事焊在一起——一个 0/1 变量的期望就是它取 1 的概率。

初学者可以把 I{A} 理解成一个「打卡计数器」：事件发生就记 1 分，不发生记 0 分。如果你想数「某类事件一共发生了几次」，就给每次机会各设一个指示器，再把它们全加起来——加出来的和就是发生次数。而「和的期望」可以用下面的期望线性性拆成「每个指示器期望之和」，也就是「每次发生概率之和」。这套「设指示器 → 求和 → 拆期望」的三步，是本章（乃至随机化快排、选择算法）反复使用的主力招式。

### 3.2.2 期望的线性性

期望的线性性（linearity of expectation）说：随机变量之和的期望等于期望之和，且**无论这些随机变量是否相互独立都成立**。对任意随机变量 X_1, …, X_n：

E[X_1 + X_2 + … + X_n] = E[X_1] + E[X_2] + … + E[X_n]

这是本章最重要的一条工具。它让我们绕开「联合分布」这个通常极难计算的东西——只要把总量拆成一堆指示器之和，就能逐个算期望再相加。

为什么「不要求独立」这么关键？因为雇佣问题里各次雇佣事件其实**不独立**（前面雇没雇会影响「当前最好者」是谁）。如果期望线性性要求独立，我们就用不了它。正因为它对任意依赖关系都成立，才能放心地把「雇佣总次数」拆成 n 个指示器直接相加。这也是初学者最容易误用的地方——很多人下意识以为「相加要独立」，其实**求和的期望**从不需要独立（需要独立的是**乘积的期望** E[XY]=E[X]E[Y]，那是另一回事，别搞混）。

### 3.2.3 雇佣问题的期望雇佣次数 ≈ ln n

现在把 3.2 的工具用到 3.1 的问题上。设 X_i = I{候选人 i 被雇佣} = I{候选人 i 是前 i 位中最好的}。总雇佣次数 X = X_1 + … + X_n。由 3.1.3 知 E[X_i] = P(候选人 i 是前 i 的最好者) = 1/i。用期望线性性：

E[X] = Σ (i = 1 到 n) E[X_i] = Σ (i = 1 到 n) 1/i = H_n

其中 H_n 是第 n 个调和数，而它有渐进估计（大主题1 §标准函数里的结论）：

H_n = ln n + O(1)，故 E[X] = ln n + O(1) = Θ(ln n)

在均匀随机输入假设下，雇佣次数的期望是调和数 H_n ≈ ln n——远小于最坏情形的 n。于是期望总代价是 O(c_h·ln n + c_i·n)。

这个结果的意义在于对比——同一段代码，最坏要雇 n 次，平均只雇约 ln n 次（n=10000 时约 9.8 次，而不是 10000 次）。「新纪录」越往后越难出现（第 i 位要当新纪录的概率只有 1/i），所以雇佣次数增长极慢。为了给这条「E[X]=H_n≈ln n」一次廉价的证伪机会，我用真随机排列做 Monte Carlo 模拟，把经验期望和 H_n、ln n 三者摆一起比：

```text
hiring n=    10: empirical E[hires]=2.9174  H_n=2.9290  ln n=2.3026
hiring n=   100: empirical E[hires]=5.1826  H_n=5.1874  ln n=4.6052
hiring n=  1000: empirical E[hires]=7.5189  H_n=7.4855  ln n=6.9078
hiring n= 10000: empirical E[hires]=9.7660  H_n=9.7876  ln n=9.2103
```

经验期望（2 万次随机排列平均）与精确的 H_n 每一行都吻合到小数点后一两位；而 ln n 只是 H_n 去掉那个 O(1)≈0.577（欧拉常数 γ）后的主项，所以每行都比 H_n 小 0.5 左右——这恰好印证了 H_n = ln n + γ + o(1) 里那个常数项，说明「E[X]=H_n，其量级为 Θ(ln n)」两句都对，写「≈ln n」时心里要清楚差的是那个常数。

## 3.3 随机化算法设计

### 3.3.1 从「假设输入随机」到「让算法制造随机」

3.1–3.2 的概率分析有个软肋：它假设输入天然服从均匀随机分布。可现实中输入往往不随机，甚至可能是对手故意构造的最坏序列，那时平均分析的结论全部作废。随机化算法（randomized algorithm）换了个思路——不再对输入分布做任何假设，而是让算法**自己**调用随机数生成器，主动把输入打乱或随机选择。

概率分析的随机性来自「输入的分布假设」（假设可能出错）；随机化算法的随机性来自「算法内部的掷骰子」（永远成立，因为掷骰子是算法自己做的）。前者算「平均输入上的平均代价」，后者算「任意固定输入上、对算法自身随机选择取期望的代价」。

这个翻转是本章的思想高潮。对雇佣问题，随机化的做法是：先把送来的候选人名单**随机重排**一遍，再走原来的雇佣流程。这样一来，无论中介按什么顺序送人（哪怕是最坏顺序），经过我们自己的随机重排后，实际处理顺序都成了均匀随机排列——于是 3.2.3 的「E[雇佣]=H_n≈ln n」对**任何**输入都成立了，不再是「假设输入随机才成立」。这就是随机化最朴素的价值：用 Θ(n) 的一次洗牌，把「最坏输入」这个威胁彻底消除。同样的招式在大主题4 的随机化快排里再次出现（随机选主元 ⇒ 期望 O(n log n) 对任意输入成立）。所以真正需要解决的技术问题只剩一个：怎样正确地生成一个「均匀随机排列」？下面两节给两种做法。

### 3.3.2 PERMUTE-BY-SORTING：给每人一个随机优先级再排序

第一种做法：给每个元素随机抽一个优先级数，然后按优先级排序，排完的顺序就是随机排列。伪代码（CLRS §5.3）：

```text
PERMUTE-BY-SORTING(A):
    n = A.length
    令 P[1..n] 为新数组
    for i = 1 to n:
        P[i] = RANDOM(1, n^3)      # 每人抽一个 [1, n^3] 的随机优先级
    以 P 为关键字对 A 排序
    return A
```

只要各优先级互不相同，「按优先级排序」就把 A 打乱成一个均匀随机排列；排序主导，运行时间为：

O(n log n)

为什么优先级范围取到 n^3？为了让「出现重复优先级」的概率足够小（可证 ≤ 1/n 量级）。如果两个元素抽到相同优先级，它们的相对顺序就不再均匀，排列会有偏。初学者记住结论即可：范围取得够大（多项式于 n）时重复可忽略，排序结果是均匀随机排列。这个方法直观好懂，但要 O(n log n)、还要额外的优先级数组，不如下面的 RANDOMIZE-IN-PLACE 划算。

### 3.3.3 RANDOMIZE-IN-PLACE：Θ(n) 原地洗牌

第二种做法（更优）：原地扫描一遍，第 i 个位置随机地和「它自己或它后面某个位置」交换。伪代码（CLRS §5.3，即 Fisher–Yates / Knuth 洗牌）：

```text
RANDOMIZE-IN-PLACE(A):
    n = A.length
    for i = 1 to n:
        j = RANDOM(i, n)        # 从 [i, n] 中等概率取一个下标
        交换 A[i] 与 A[j]
```

这个算法只用 Θ(n) 时间、O(1) 额外空间，就能产生均匀随机排列——n! 种排列每种恰好以概率 1/n! 出现。

它为什么对？关键是 RANDOM(i, n) 的下界是 i 而不是 1（这是最容易写错的地方）。用循环不变式看：每次进入第 i 次迭代前，子数组 A[1..i−1] 已经是「从 n 个元素里选 i−1 个的某个特定有序排列」，且每种这样的 (i−1)-排列出现概率都是 (n−i+1)!/n!；第 i 步从剩下的 n−i+1 个位置里等概率挑一个放到 A[i]，就把不变式推进到 i。循环结束时 A[1..n] 是均匀随机的整排列。

一个极其常见的**错误洗牌**是把 j 取成 RANDOM(1, n)（整段随机，不是 [i,n]）——它看起来也在乱交换，但产生的排列**不均匀**：它一共走 n^n 条等概率路径，而 n^n 通常不能被 n! 整除，必然有的排列偏多、有的偏少。我用 3 个元素、各 60 万次，对「正确洗牌」和「错误洗牌」分别做卡方拟合优度检验（6 种排列理论上各占 1/6）：

```text
RANDOMIZE-IN-PLACE 3! perms counts=[99862, 99924, 99914, 100315, 100078, 99907] chi2=1.462 p=0.917 (expect~100000 each, high p = uniform)
BAD shuffle (j in [0,n-1]) counts=[88980, 110704, 111677, 110999, 88712, 88928] chi2=7433.5 p=0.00e+00 (low p = NOT uniform)
```

正确洗牌 6 种排列都紧贴 10 万、卡方 1.46、p=0.92（无法拒绝「均匀」）；错误洗牌把某些排列压到 8.9 万、某些抬到 11 万，卡方高达 7433、p≈0（强烈拒绝「均匀」）。这就把「下界必须是 i」这个易错点用数据坐实了——只是补充，正确性仍以 CLRS §5.3 的循环不变式证明为准。

- 交叉源：Knuth《TAOCP》Vol.2 §3.4.2 洗牌算法（Fisher–Yates/Algorithm P，二手引用）与 CLRS RANDOMIZE-IN-PLACE 为同一算法，交叉印证 j∈[i,n] 的正确性与均匀性。
- 一致：两一手源都强调随机化算法不假设输入分布、对任意输入给期望界；RANDOMIZE-IN-PLACE 的下标下界为 i（非 1）两源一致。
- 实测：正确洗牌卡方 p=0.917（不拒绝均匀）、错误洗牌 p≈0（拒绝均匀），3 元素各 60 万次；Python 3.11.15/scipy 1.17.1。
- 成熟度：经典，稳定。

## 3.4 概率分析进阶（可选）

### 3.4.1 生日悖论

生日悖论（birthday paradox）问：一间屋里要有多少人，才能让「至少两人同一天生日」的概率超过一半？直觉以为要一两百人（一年 365 天嘛），实际只要 **23 人**。用指示器分析：把 n 记作天数（这里 n=365），对每一对人 (i,j) 设指示器 X_{ij}=I{i,j 同生日}，E[X_{ij}]=1/n；k 个人共 C(k,2) 对，期望的「同生日对数」是：

E[同生日对数] = C(k, 2) / n = k(k−1) / (2n)

令它等于 1，解得阈值：

k ≈ √(2n)

当人数 k 达到约 √(2n) 量级时，期望就会出现一对同生日者——碰撞所需人数只随天数的**平方根**增长，这就是「悖论」（其实并不矛盾）的来源。

这里有个初学者极易混淆的**两条线**，务必分清。第一条线是「期望的同生日对数何时到 1」：解 k(k−1)/2=365 得 k≈27.5，也和 √(2·365)≈27.02 吻合。第二条线是「碰撞概率何时超过 0.5」：这个更早，k=23 就够了。二者不是一回事——概率超过一半，并不需要期望对数先到 1（k=23 时期望对数才 C(23,2)/365≈0.69）。实测同时核对这两条线：

```text
birthday n=365 k=22: P(>=1 collision)=0.4757
birthday n=365 k=23: P(>=1 collision)=0.5073
birthday n=365 k=24: P(>=1 collision)=0.5383
sqrt(2n) for n=365 = 27.019  (analytic threshold where expected pairs=1: k~27.52)
MC birthday k=23 collision prob = 0.5062 (analytic 0.5073)
```

精确公式给出 k=23 时碰撞概率 0.5073（刚过半），k=22 时 0.4757（不到半）——这是「23 人」这个著名答案的来源；而期望对数到 1 的阈值 √(2n)≈27 是另一条线。20 万次 Monte Carlo 在 k=23 测得 0.5062，与解析值 0.5073 吻合。这个例子说明为什么散列表（大主题6 §6.2）在装填因子还很低时就会频繁冲突——碰撞只需 √(桶数) 量级的键。

### 3.4.2 球与箱

球与箱（balls and bins）模型：把球一个个随机扔进 b 个箱子，每个箱子等概率被选中，问各种「要扔多久」的期望。两个经典结论（用指示器/几何分布 + 期望线性性得到）：

期望扔 b 次，某个指定的箱子才第一次进球（几何分布，成功概率 1/b）。

要让**每个**箱子都至少进一个球，期望需要扔的次数是（这就是「赠券收集者问题」coupon collector）：

E[覆盖全部 b 箱] = b·H_b ≈ b·ln b

先让每个箱子都非空，需要约 b·ln b 次投掷——那个 ln 因子又是调和数 H_b 来的，和雇佣问题同源。

赠券收集者的直觉是「越到后面越难集齐」——当已经集到 b−1 种、只差最后 1 种时，每扔一次命中缺的那种的概率只有 1/b，期望要扔 b 次才补上；把「从第 i−1 种到第 i 种」的期望等待次数 b/(b−i+1) 对 i 求和，正好是 b·H_b。这个模型是很多算法分析的骨架：散列表要「填满所有桶」、随机负载均衡「每台机器都分到活」都套它。CLRS §5.4.2 还给出 n=b（球数=箱数）时**单箱最大负载**的期望是 Θ(ln n / ln ln n) 量级的结论——本课点名即可、不展开推导。

### 3.4.3 序列（streaks，点名）

序列（streaks）问题：连续抛一枚均匀硬币 n 次，最长的一段「连续正面」有多长？CLRS §5.4.3 用指示器分析给出结论：最长连续正面的期望长度是：

Θ(lg n)

n 次抛掷里，最长连正面串的期望长度是对数级的 Θ(lg n)——既不会短到常数，也不会长到线性。

直觉是「出现长度为 s 的连正面」的概率按 2^{−s} 指数衰减，而 n 次里大约有 n 个起始位置，两者平衡在 s≈lg n 处。这条结论本课只作为「指示器分析还能算什么」的一个例子点名，不深挖；随机序列里「最长游程 ≈ lg n」的直觉在哈希、随机数质量检验里会再遇到。

### 3.4.4 在线雇佣问题

在线雇佣问题（on-line hiring problem）是 3.1 雇佣问题的「只能雇一次、不能反悔」版本：候选人依次到来，你看完一位必须当场决定「录用（从此停止）还是永久放弃」，目标是**恰好录用到全场最好的那一位**的概率尽量大。CLRS §5.4.4 给的策略是「先看后挑」：先面试并**一律拒绝**前 k 位、只用他们摸底（记下这批人里的最好水平），从第 k+1 位起，遇到第一个「比前 k 位都好」的人就录用。最优的 k 与成功概率是：

取 k ≈ n/e，则 P(录用到最好者) ≥ 1/e ≈ 0.368

把「先拒绝的观察期」定在 n/e（约全场的 37%）时，成功率最高，约 1/e≈37%——一个与 n 几乎无关的常数概率。

这个反直觉的结论（俗称「秘书问题」）说明：即使被逼着当场决策、不能回头，只要先花 37% 的样本纯观察、之后果断出手，仍有超过三分之一的概率精确命中最好者。观察期太短（摸底不足、容易被前期一个次优者骗到手）或太长（真正的最好者很可能落在观察期里被白白拒掉）都更差，n/e 是这条权衡曲线的最优点。实测（n=100，拒绝前 37 位）：

```text
online hiring n=100, reject first k=37 (~n/e=36.8): P(hire best)=0.3704  1/e=0.3679
```

20 万次模拟测得成功率 0.3704，与理论下界 1/e≈0.3679 吻合。这是本课能给的「在线/竞争分析」最初一瞥——系统的竞争比框架与在线算法归 **L6-01 #06**，本课点到为止。
