## 10.1 图的表示

### 10.1.1 邻接表表示

邻接表（adjacency list）用一个长度为 |V| 的数组 Adj 表示图：Adj[u] 是一个链表（或动态数组），存放所有与 u 有边相连的顶点 v。有向图里 Adj[u] 存 u 的所有出边终点；无向图里每条边 {u,v} 在 Adj[u] 和 Adj[v] 里各出现一次。

它的空间占用是：

Θ(V + E)

把邻接表想成「每个人一张通讯录」——第 u 个人的通讯录上只写下他真正认识的人，不认识的一个字都不占。所以总字数 = 人数（V，每人一张表头）+ 认识关系总条数（有向图是 E，无向图是 2E，因为一段友谊两人各记一笔）。这就是为什么空间是 Θ(V+E) 而不是 Θ(V²)。

为什么这是**稀疏图**（边远少于 V² 的图，现实世界大多如此，例如公路网、社交关注）的默认选择：它只为真实存在的边付费。遍历「u 的所有邻居」也很自然，直接扫 Adj[u] 即可，代价与 u 的度数成正比。易错点：邻接表**不能 O(1) 回答「u 和 v 之间到底有没有边」**——你得扫一遍 Adj[u]，最坏要看完 u 的所有邻居。若算法频繁做这种「查单条边是否存在」的问询，邻接表就吃亏了。

### 10.1.2 邻接矩阵表示

邻接矩阵（adjacency matrix）用一个 |V|×|V| 的矩阵 A 表示图：A[i][j] = 1 表示有边 (i,j)，否则为 0（带权图则存权重，无边存 ∞ 或特殊值）。

它的空间占用是：

Θ(V²)

无向图的邻接矩阵是**对称矩阵**（A[i][j] = A[j][i]），因为边没有方向。

邻接矩阵像一张「点名表」，行是「从谁」，列是「到谁」，格子里打勾表示有边。它的最大好处是查一条边**只看一个格子**，即：

判断 (u,v) 是否为边 = 读 A[u][v]，O(1)

代价是无论图多稀疏，都要为**每一对**顶点留一个格子，所以空间恒为 Θ(V²)。当图很**稠密**（边数接近 V²）或算法反复查「某两点间有无边」时，邻接矩阵划算；当图稀疏且顶点很多时，Θ(V²) 会爆掉内存。

稀疏图 + 常做「遍历邻居」→ 邻接表；稠密图 + 常做「查单边」→ 邻接矩阵。后面 10.2–10.5 的所有遍历都默认用邻接表，因为它们的复杂度 O(V+E) 恰好依赖「扫邻居」这个邻接表擅长的操作。

（实测）把同一张图在两种表示间互转再转回，两边邻接关系完全一致：

```

```

## 10.2 广度优先搜索

### 10.2.1 BFS 算法与队列机制

广度优先搜索（BFS）从一个源点 s 出发，**一圈一圈**地向外扩展：先访问 s 的所有直接邻居（距离 1），再访问这些邻居的未访问邻居（距离 2），依此类推。它用一个 **FIFO 队列**保存「已发现但邻居还没处理完」的顶点，并用三色标记顶点状态：白（未发现）、灰（已发现、在队列里）、黑（邻居已处理完）。

伪代码（CLRS 风格，邻接表输入）：

```
BFS(G, s):
    for each u in G.V - {s}:
        u.color = WHITE; u.d = ∞; u.π = NIL
    s.color = GRAY; s.d = 0; s.π = NIL
    Q = empty queue
    ENQUEUE(Q, s)
    while Q not empty:
        u = DEQUEUE(Q)
        for each v in G.Adj[u]:
            if v.color == WHITE:
                v.color = GRAY
                v.d = u.d + 1
                v.π = u
                ENQUEUE(Q, v)
        u.color = BLACK
```

它的运行时间是：

O(V + E)

BFS 像往平静水面丢一颗石子，涟漪一圈圈同心扩散——离源点越近的顶点越早被「涟漪」碰到。队列保证了这个「先来先扩展」的顺序：先进队的（更近的）先出队展开。为什么复杂度是 O(V+E)？每个顶点最多入队/出队一次（贡献 V），每条边在扫描邻接表时最多被看一次（有向）或两次（无向），贡献 O(E)；两者相加即 O(V+E)。这叫**聚合分析**——不逐点算，而是把总工作量一次性加起来。

一个顶点一旦变灰（入队）就不会再被重复入队，靠的正是「只对白色邻居入队」这一句；漏掉颜色判断会导致同一点反复入队、复杂度退化甚至死循环。

### 10.2.2 BFS 树与无权最短路

BFS 在扩展过程中，用 v.π 记录「v 是从哪个顶点第一次被发现的」，这些 π 指针连起来构成一棵 **BFS 树**（也叫广度优先树）。核心结论：在**无权图**中，BFS 算出的 v.d 恰好等于从 s 到 v 的**最短路径长度**（边数最少的路径），记作 δ(s, v)：

v.d = δ(s, v)

因为 BFS 严格按距离由近及远扩展，一个顶点第一次被碰到时，走过的边数一定是最少的——不可能有更短的路先于它到达却没被发现。所以 BFS 天然解决「无权图单源最短路」。

这个「最短」只对**无权图**（或所有边权相等）成立，因为 BFS 只会数「跳了几条边」，不看边的权重。一旦边有不同权重，最少边数 ≠ 最小总权重，就要换 Dijkstra 等算法（属大主题11），不能再用 BFS。这是初学者最常踩的坑：拿 BFS 去解带权最短路。

沿 π 指针从 v 一路回溯到 s，就能打印出这条最短路径本身（CLRS 的 PRINT-PATH 过程）。

（实测）在一张无向图上跑 BFS，得到的距离数组与「反复松弛取最少跳数」的独立算法完全一致：

```
10.2 BFS dist == relaxation min-hops: True [0, 1, 1, 2, 3]
```

## 10.3 深度优先搜索

### 10.3.1 DFS 算法与时间戳

深度优先搜索（DFS）与 BFS 相反：它「一条路走到黑」——从一个顶点出发沿一条边深入，直到走进死胡同再回溯，然后换下一条未走的边。DFS 对每个顶点记两个**时间戳**：发现时间 u.d（第一次访问、由白变灰）与完成时间 u.f（其所有邻居处理完、由灰变黑）。一个全局时钟从 1 开始，每发生一次「发现」或「完成」就 +1，所以时间戳取遍 1 到 2|V| 的整数。DFS 通常对图中所有顶点跑，得到一片**深度优先森林**。

伪代码（CLRS 风格）：

```
DFS(G):
    for each u in G.V:
        u.color = WHITE; u.π = NIL
    time = 0
    for each u in G.V:
        if u.color == WHITE:
            DFS-VISIT(G, u)

DFS-VISIT(G, u):
    time = time + 1
    u.d = time
    u.color = GRAY
    for each v in G.Adj[u]:
        if v.color == WHITE:
            v.π = u
            DFS-VISIT(G, v)
    u.color = BLACK
    time = time + 1
    u.f = time
```

它的运行时间是：

Θ(V + E)

DFS 像走迷宫时「一直往前，撞墙才回头」，用（隐式的递归调用栈，或显式栈）记住回头路。为什么是 Θ(V+E)：外层循环对每个顶点调用一次 DFS-VISIT（贡献 Θ(V)），每个顶点的邻接表在其 VISIT 里被完整扫描一次（所有邻接表长度之和 = Θ(E)）；合起来 Θ(V+E)。注意 CLRS 用的是 **Θ**（紧确界，因为初始化那两个 for 循环下界也是 V+E），BFS 那里用 O 是因为不是每个顶点都一定被访问到——这是两处记号的细微差别，别当成矛盾。

### 10.3.2 括号定理

DFS 的发现/完成时间戳有一条漂亮的结构性质——**括号定理**（parenthesis theorem）。把每个顶点 u 看成一对括号：在时刻 u.d 写「(u」，在时刻 u.f 写「u)」。那么整段 DFS 过程写出的就是一串**正确嵌套的括号**。等价地说，对任意两点 u、v，区间 [u.d, u.f] 与 [v.d, v.f] 只有三种关系，绝不会「部分交叉」：

要么两区间完全不相交（互不为对方后代），

要么 [u.d, u.f] 完全含在 [v.d, v.f] 内（u 是 v 在 DFS 森林里的后代），

要么 [v.d, v.f] 完全含在 [u.d, u.f] 内（v 是 u 的后代）。

这正是函数调用栈的行为——A 调用 B，B 必须先返回 A 才能返回，绝不会出现「A 进、B 进、A 出、B 出」这种交叉。所以「u 是 v 的后代」当且仅当 v 发现时 u 还是白的、且在 v 完成前被发现完成，即 u 的括号被 v 的括号套住。这条定理是后面边分类和 SCC 正确性的地基。

配套的还有**白色路径定理**（white-path theorem）：在发现 u 的那一刻（u.d），顶点 v 是 u 的后代，当且仅当此刻存在一条从 u 到 v、**全部由白色顶点组成**的路径。它给了「谁会成为谁的后代」一个纯图论的判据。

### 10.3.3 边的分类

跑 DFS 时，可以按「看到邻居 v 时 v 的颜色」把每条边 (u,v) 分成四类：

树边（tree edge）：v 是白色，(u,v) 就是发现 v 用的那条边，进入 DFS 森林。

后向边（back edge）：v 是灰色，说明 v 是 u 的祖先（还在栈上没完成）——后向边的存在等价于图里有环。

前向边（forward edge）：v 是黑色且 u.d < v.d，(u,v) 指向一个已完成的后代（但不是树边）。

横向边（cross edge）：v 是黑色且 u.d > v.d，连接两棵不同子树、或同一树里无祖先-后代关系的两点。

一条重要的特例结论：

在无向图的 DFS 中，只会出现树边和后向边，绝无前向边和横向边。

边分类就是问「我踩到这条边时，对面那个点处于什么人生阶段」——还没出生（白，树边）、正在忙还没收工（灰，是我祖先，后向边）、已经收工了（黑，前向或横向，看谁先出生）。无向图为什么只剩两类？因为无向边 {u,v} 两个方向都会被扫到，先扫到的那次就把关系定死为树边或后向边，等另一个方向再看时已成定局，不会再新分出前向/横向。用途：**后向边 ⇔ 有环**，这是拓扑排序（10.4）判「能不能排」的关键。

（实测）在一张有向图上跑 DFS，括号定理（任意两点区间「嵌套或不相交、绝不部分重叠」）成立，边分类计数正常；同一份代码在无向图上确认只产生树边与后向边（forward/cross 均为 0）：

```

```

## 10.4 拓扑排序

### 10.4.1 拓扑排序算法

拓扑排序针对**有向无环图**（DAG）：把所有顶点排成一条直线，使得每条边 (u,v) 都从左指向右（u 排在 v 前面）。只要图无环，这样的线性序一定存在（可能不唯一）。CLRS 的算法极简——跑一遍 DFS，按**完成时间 f 递减**输出顶点即可：

```
TOPOLOGICAL-SORT(G):
    call DFS(G) to compute finish times v.f for each vertex v
    as each vertex is finished, insert it onto the front of a linked list
    return the linked list of vertices
```

它的运行时间与 DFS 同阶：

Θ(V + E)

拓扑排序回答「先做哪个、后做哪个」——课程先修关系、编译依赖、施工工序都是它。为什么「完成时间递减」就对？因为在 DAG 里，若有边 (u,v)，则 v 一定先于 u 完成（v.f < u.f）。道理是：扫到 (u,v) 时 v 要么是白的（那 v 成为 u 的后代，会在 u 之前完成），要么是黑的（早就完成了）；v 绝不可能是灰的——灰意味着 v 是 u 的祖先、(u,v) 是后向边、图里有环，与 DAG 矛盾。所以每条边都满足 f(v) < f(u)，按 f 递减排就让每条边都朝前指。

### 10.4.2 环的检测与适用前提

拓扑排序的前提是**无环**。判环的办法直接落在 10.3 的边分类上：

一个有向图能被拓扑排序 ⇔ 它是 DAG ⇔ 它的 DFS 不产生任何后向边。

如果有环 A→B→C→A，就没法让三者都「前面的排左边」——总有一条边被迫往回指，这对应 DFS 里必然冒出的后向边。所以实践中常把「拓扑排序」和「检测有向图是否有环」合成一步：跑 DFS，一旦遇到指向灰色顶点的边（后向边）就报「有环、无法拓扑排序」。易错点：拓扑序**通常不唯一**（无相互依赖的顶点谁先谁后都行），别把某一个合法输出当成「标准答案」；判定正确性要看「是否每条边都前向」，而非是否等于某个特定序列。

（实测）对一张 DAG 跑「DFS 完成时间递减」得到拓扑序，验证每条边都从前指向后（左→右）：

```
10.4 topo order: [5, 0, 2, 1, 3, 4] | all edges go forward: True
```

## 10.5 强连通分量

### 10.5.1 强连通分量与转置图

有向图的**强连通分量**（SCC）是极大的顶点子集，其中任意两点 u、v 互相可达（u 能走到 v，v 也能走到 u）。把每个 SCC 缩成一个点，就得到**分量图**（缩点图 / condensation），它一定是 DAG。求 SCC 用到**转置图** G^T：把 G 的每条边反向得到的图。关键事实是 G 与 G^T 的强连通分量**完全相同**——因为「u、v 互相可达」这个关系在所有边反向后依然成立（来回两条路径只是各自反了向）。

SCC 就是「一伙能互相串门的顶点」团伙。把整张有向图按团伙缩点后，团伙之间只能单向通行（否则两个团伙就该并成一个），所以缩点图无环、是 DAG。转置图反的是「方向」，不改「谁和谁属于同一团伙」，这一点是下面两遍 DFS 算法正确性的支点。

### 10.5.2 两遍 DFS 求强连通分量

CLRS 的 STRONGLY-CONNECTED-COMPONENTS 用**两遍 DFS**（即 Kosaraju–Sharir 算法）：

```
STRONGLY-CONNECTED-COMPONENTS(G):
    1. call DFS(G) to compute finish times u.f for each vertex u
    2. compute G^T (transpose: reverse every edge)
    3. call DFS(G^T), but in the main loop consider vertices
       in order of DECREASING u.f (from step 1)
    4. output the vertices of each tree in the depth-first forest
       formed in step 3 as a separate SCC
```

它的运行时间是：

Θ(V + E)

为什么「第一遍记完成时间、第二遍在转置图上按完成时间从大到小起点」就能把团伙一个个圈出来？直觉是：第一遍 DFS 里**完成最晚**（f 最大）的那个顶点，一定落在缩点 DAG 的一个「源」分量里（没有别的分量指向它）。到了转置图 G^T，所有分量间的边都反向了，于是这个源分量在 G^T 里变成「出不去」的——从它出发的 DFS 只能在自己分量内打转，正好圈出一整个 SCC 就停。按 f 递减依次挑起点，就等于按缩点 DAG 的拓扑序逐个剥离分量。第二遍 DFS 森林里的**每一棵树**恰好就是一个 SCC。

单遍 DFS 只能告诉你「谁是谁的后代」，分不清「互相可达」；引入转置图 + 完成时间排序，才把「双向可达」这件事拆成两趟单向遍历来判定。复杂度上，两遍 DFS 各 Θ(V+E)、转置图构造 Θ(V+E)，总和仍是 Θ(V+E)。

（实测）对 300 张随机有向图，两遍 DFS 求出的 SCC 划分与「暴力计算可达闭包、按互相可达分组」的独立算法给出的划分完全一致：

```
10.5 two-pass SCC == brute-force mutual-reachability over 300 random digraphs: True
```
