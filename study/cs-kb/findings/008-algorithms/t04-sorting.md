## 4.1 堆与堆排序

### 4.1.1 堆的数据结构与数组表示

（最大）堆是一种可以看成**近似完全二叉树**的数组。数组 A 里除了最底层可能不满、且从左往右填，其余每层都填满。用一个属性 A.heap-size 记录当前堆里有多少个元素（可能小于数组长度）。给定下标 i（1 起始），它的父、左孩子、右孩子分别是：

PARENT(i) = ⌊i/2⌋

LEFT(i) = 2i

RIGHT(i) = 2i + 1

堆分两种。最大堆（max-heap）满足**最大堆性质**：每个结点的值都不小于其孩子的值，即对所有非根结点 i：

A[PARENT(i)] ≥ A[i]

最小堆（min-heap）方向相反，把 ≥ 换成 ≤。堆排序用最大堆；优先队列两种都用。

堆不需要指针，就用一个数组，靠「下标算术」在父子之间跳转——第 i 个位置的两个孩子恰好在 2i 和 2i+1。这一点很关键，它让堆既省空间又缓存友好。注意「堆性质」只约束**父子之间**的大小关系，**不**要求兄弟之间、或跨层的任意两点有序；所以最大堆只保证「根是全局最大」，并不保证数组整体有序——这正是它和「已排序数组」的区别。

一个含 n 个元素的堆，其高度（根到最深叶子的边数）是：

⌊lg n⌋

这是因为它是近似完全二叉树，第 k 层最多 2^k 个结点。高度为 Θ(lg n) 是后面所有堆操作复杂度的来源。

### 4.1.2 MAX-HEAPIFY：维护堆性质

MAX-HEAPIFY 是维护最大堆性质的核心子程序。前提：结点 i 的左右子树都已是最大堆，但 A[i] 本身可能比孩子小（违反堆性质）。它的工作是把 A[i] 这个「过小的值」逐层往下「沉」到合适的位置，让以 i 为根的子树重新成为最大堆。

比较 A[i] 与两个孩子，找出三者中最大的；若最大的是某个孩子，就把 A[i] 与该孩子交换，然后对被换下去的那个孩子位置递归 MAX-HEAPIFY；若 A[i] 本身最大则停止。它沿一条根到叶的路径下沉，故运行时间与堆高同阶：

O(lg n)

像一个「个头不够高」的人在金字塔里往下走——每层都和下面两个人比，谁最高谁上来，自己继续往更矮的一侧沉，直到没人比自己高为止。易错点：递归只发生在**被交换的那一侧**子树，不是两侧都递归；另一侧在调用前就已经是合法最大堆，不用动。另一个易错点是循环终止条件——当 largest == i（父already最大）时必须立刻停，否则会无谓下沉甚至越界。

### 4.1.3 BUILD-MAX-HEAP：线性时间建堆

BUILD-MAX-HEAP 把一个任意顺序的数组原地整理成最大堆。做法是**从最后一个非叶结点往前、到根**，对每个结点调用一次 MAX-HEAPIFY。叶子（下标 ⌊n/2⌋+1 到 n）本身就是大小为 1 的合法堆，无需处理，所以从 ⌊n/2⌋ 开始倒着做即可。

整个建堆过程是**线性时间**，而不是 O(n lg n)：

BUILD-MAX-HEAP 运行时间 = O(n)

为什么不是 n 次 O(lg n) = O(n lg n)？因为绝大多数结点靠近底部、高度很小，MAX-HEAPIFY 在它们身上花的时间也小。高度为 h 的结点最多有：

⌈n / 2^(h+1)⌉ 个

对它们各花 O(h)，把所有高度加起来：

Σ (h = 0 到 ⌊lg n⌋) ⌈n / 2^(h+1)⌉ · O(h) = O( n · Σ h/2^h ) = O(n)

因为 Σ_{h≥0} h/2^h 是一个收敛到常数 2 的级数。所以总代价被 n 的常数倍卡住，是 O(n)。

「上紧下松」——树的一多半结点是叶子（高度 0，零成本），越往上结点越少但单次成本越高，两者相乘再求和，昂贵的顶部结点太少，压不过便宜的底部，总和只有线性。易错点：不要凭「n 个结点、每个 O(lg n)」就写 O(n lg n)——那是宽松上界，紧确界是 O(n)。本报告 §末实测用「建堆过程的总交换次数 ÷ n 趋于常数」佐证了线性。

### 4.1.4 堆排序算法

HEAPSORT 用最大堆做原地排序。步骤：先 BUILD-MAX-HEAP 把数组建成最大堆（此时最大元在根 A[1]）；然后重复 n−1 次「把根 A[1] 与当前堆的最后一个元素交换、堆大小减 1、对新根做一次 MAX-HEAPIFY」。每次交换都把当前最大值放到它最终该在的数组末尾，堆逐渐缩小，数组尾部逐渐变成有序区。

伪代码骨架：

```
HEAPSORT(A, n):
    BUILD-MAX-HEAP(A, n)
    for i = n downto 2:
        exchange A[1] with A[i]
        A.heap-size = A.heap-size - 1
        MAX-HEAPIFY(A, 1)
```

运行时间：建堆 O(n)，之后 n−1 次 MAX-HEAPIFY 每次 O(lg n)，合计：

O(n lg n)

堆排序的两大卖点：一是**原地**（只用 O(1) 额外空间，不像归并排序要额外数组）；二是**最坏情形也保证 O(n lg n)**（不像快速排序最坏会退化到 Θ(n²)）。代价是常数因子偏大、且访问模式跳跃（缓存不友好），所以实际工程里常输给快速排序。

堆排序 = 「反复取出最大值往后放」。它像「选择排序」的思路（每轮挑一个最大值放到末尾），但用堆把「找最大」从 O(n) 降到 O(lg n)，于是总时间从 Θ(n²) 降到 O(n lg n)。易错点：交换后只需对**根**做一次 MAX-HEAPIFY，因为除根外的堆性质都还成立；不要每轮重新建堆。

### 4.1.5 优先队列

优先队列（priority queue）是一种维护「一组带键（key）元素」的抽象数据结构，支持按键取最值。最大优先队列支持四个操作：

- INSERT(S, x, k)：把元素 x 以键 k 插入。
- MAXIMUM(S)：返回键最大的元素。
- EXTRACT-MAX(S)：删除并返回键最大的元素。
- INCREASE-KEY(S, x, k)：把元素 x 的键增大到 k。

用最大堆实现时，MAXIMUM 是 O(1)（读根）；EXTRACT-MAX、INSERT、INCREASE-KEY 都是 O(lg n)（沿一条堆路径上浮或下沉）。最小优先队列对称（EXTRACT-MIN、DECREASE-KEY）。

优先队列就是「随时能拿到当前最重要那一个」的队列——医院分诊、操作系统任务调度、事件模拟都靠它。INCREASE-KEY 是「上浮」：键变大后可能比父亲还大，于是与父亲交换、一路向上，直到堆性质恢复，路径长 O(lg n)。跨课边界（B4）：优先队列的完整实现与更多操作细节属 L2-01；本课列它，是因为它把「堆」从一个排序工具升级为**下游图算法（Dijkstra、Prim，见大主题11）的引擎**——那里用最小优先队列反复取「当前最近的点」。它也是大主题11「Fibonacci 堆能把 Dijkstra 加速到 O(E + V lg V)」这条边界（归 L6-01）的起点。

## 4.2 快速排序

### 4.2.1 快排的分治描述与 PARTITION

快速排序（quicksort）是最广泛使用的原地比较排序，采用分治：

分（divide）：选一个元素当**主元**（pivot），用 PARTITION 把数组 A[p..r] 重排成两段，使左段所有元素 ≤ 主元、右段所有元素 ≥ 主元，主元落在两段之间的最终位置 q。

治（conquer）：递归排序左段 A[p..q−1] 和右段 A[q+1..r]。

合（combine）：无需合并——因为是原地划分，两段排好后整体就有序了。

CLRS 用的 PARTITION 取**最末元素** A[r] 作主元（即 Lomuto 划分），用一个指针 i 维护「已知 ≤ 主元」区段的边界，扫描一遍：

```
PARTITION(A, p, r):
    x = A[r]              // 主元
    i = p - 1
    for j = p to r - 1:
        if A[j] <= x:
            i = i + 1
            exchange A[i] with A[j]
    exchange A[i+1] with A[r]
    return i + 1
```

PARTITION 一趟是 Θ(n) 次比较（n 为该段长度）。整个快排的运行时间取决于每次划分得到的两段有多平衡。

快排像「围绕一个基准分堆」——比它小的扔左边，比它大的扔右边，然后对左右两堆各自再分。与归并排序相反，快排「难在分（划分），易在合（什么都不用做）」；归并排序「易在分（对半切），难在合（归并）」。易错点：PARTITION 结束时主元一定在它**最终正确的位置**上，此后不再移动——这是快排正确性的关键，也是它无需合并的原因。

### 4.2.2 性能：最坏 Θ(n²) 与平衡 Θ(n lg n)

快排的运行时间由划分平衡度决定。

最坏情形：每次划分都极不平衡（一段 n−1 个、另一段 0 个），例如对**已排序**或**逆序**数组用「取末元素为主元」时正会发生。递归式为：

T(n) = T(n−1) + Θ(n)

解得：

T(n) = Θ(n²)

最好情形：每次都对半平分，递归式为：

T(n) = 2·T(n/2) + Θ(n)

由主定理得：

T(n) = Θ(n lg n)

即使划分「按固定比例」偏斜（比如永远 9:1），只要比例是常数，递归树深度仍是 Θ(lg n)，总时间仍是 Θ(n lg n)。也就是说，快排对「不太坏」的划分相当宽容，坏的只是那些持续接近 n:0 的极端划分。

把递归想成一棵树，每层所有划分加起来是 Θ(n) 的工作，总时间 = Θ(n) × 树高。平衡划分树高 Θ(lg n)，极端划分树高 Θ(n)。易错点：「快速排序」这名字容易让人以为它总是最快——它的**最坏**是 Θ(n²)，比堆排序/归并排序差；它赢在**平均/期望**的常数因子小、且原地缓存友好。如何避免最坏？下一节的随机化。

### 4.2.3 随机化快排

为消除「对特定输入（如已排序数组）总是踩到最坏」的风险，用随机化：不再固定取末元素，而是从 A[p..r] 里**等概率随机**挑一个元素、与末元素交换后再照常划分。

```
RANDOMIZED-PARTITION(A, p, r):
    i = RANDOM(p, r)
    exchange A[r] with A[i]
    return PARTITION(A, p, r)
```

这样一来，运行时间不再取决于「输入长什么样」，而只取决于「随机数怎么掷」——没有任何一个固定输入能持续逼出最坏情形。随机化快排的期望运行时间是：

E[T(n)] = Θ(n lg n)

这是大主题3「随机化算法」思想的直接应用——把「对抗性的输入分布」这个不可控因素，换成「算法自己掌握的随机硬币」这个可控因素。它不改善**最坏情形**（理论上仍可能 Θ(n²)，只是概率极低），而是让「坏」与具体输入脱钩，实践中几乎不会遇到。易错点：随机化的是**主元选择**，不是打乱整个数组（虽然「先随机打乱输入再跑确定性快排」也能达到同样的期望效果，是等价的另一种实现）。

### 4.2.4 期望运行时间分析

期望 O(n lg n) 的核心分析对象是「PARTITION 中执行的比较总次数 X」——因为快排除比较外的工作都与比较次数同阶，故运行时间是 O(n + X)。用大主题3 的指示器随机变量来数 X。

设把输入元素按值排序后记为 z₁ < z₂ < … < zₙ。关键观察：任意两个元素 zᵢ 与 zⱼ（i < j）在整个算法里**至多被比较一次**，且它们被比较**当且仅当** zᵢ 或 zⱼ 是集合 {zᵢ, …, zⱼ} 中第一个被选为主元的。因为该集合有 j−i+1 个元素、每个等可能最先被选，所以两者被比较的概率是：

Pr{zᵢ 与 zⱼ 被比较} = 2 / (j − i + 1)

用指示器变量 Xᵢⱼ（比较发生记 1）和期望线性性，期望比较总数为：

E[X] = Σ_{i=1}^{n−1} Σ_{j=i+1}^{n} 2/(j−i+1)

把内层和换元后是调和级数，放缩得：

E[X] < Σ_{i=1}^{n−1} Σ_{k=1}^{n} 2/k = O(n lg n)

（用到调和数 Hₙ = Σ 1/k = ln n + O(1)，故上式约为 2n ln n。）于是随机化快排期望运行时间 Θ(n lg n) 成立。

「越近的两个元素越可能被直接比较，越远的越可能被中间某个主元隔开、从此各奔东西、永不相见」——概率 2/(j−i+1) 正刻画了这一点（相邻元素 j−i=1 时概率为 1，必比；相距很远时概率趋于 0）。易错点：这里数的是「比较次数」而非「递归调用次数」，指示器变量法之所以干净，正是因为「任意两元素至多比较一次」这一结构性事实避开了对递归树形状的直接求解。本报告文末实测显示，随机主元下 n=100..1000 的平均比较次数确实低于 2n ln n 上界、并随 n 增长贴近该阶。

## 4.3 比较排序下界

### 4.3.1 比较排序模型

比较排序是指：算法**只能通过元素之间的相互比较**（<、≤、=、≥、> 之类）来获取输入的顺序信息，不以任何其他方式利用元素的具体值。前面的插入排序、归并排序、堆排序、快速排序**都是**比较排序。

在只许比较的前提下，排序最少需要多少次比较？答案是所有比较排序共同的天花板：

任何比较排序在最坏情形下都需要 Ω(n lg n) 次比较。

这说明堆排序、归并排序的 O(n lg n) 已经是**渐进最优**的，不可能有「只靠比较」的排序算法把最坏情形做到比 n lg n 更快。

这是一个**下界**（lower bound）结论，和前面证某个算法「跑得多快」（上界）方向相反——它证的是「**任何**算法都快不过某个界」。这类结论威力很大：它不针对某个具体算法，而是划出整类算法的能力边界。易错点：下界只约束「比较排序」；4.4 会展示，若允许算法用别的手段（如把元素值当数组下标），就能绕过这个 Ω(n lg n)——那不违反下界，因为它跳出了比较模型。

### 4.3.2 决策树模型

证明下界的工具是**决策树**（decision tree）：把一个比较排序在所有长度为 n 的输入上的行为，抽象成一棵二叉树。

- 每个**内部结点**标记一次比较，形如 aᵢ : aⱼ（「第 i 个元素与第 j 个元素比大小」）。
- 从该结点出发的两条边对应比较的两种结果（≤ 走一边，> 走另一边）。
- 每个**叶子**标记一个最终输出的排列（即「原输入应如何重排才有序」的一个置换）。

算法在某个具体输入上的执行，就对应从根到某叶子的一条路径；路径长度 = 该输入上执行的比较次数。于是「最坏情形比较次数」= 决策树的**高度**（最长根-叶路径）。

把排序算法想成一场「二十问」游戏——每问一个是非问题（一次比较），根据回答走向不同分支，最终必须能确定输入的确切排列顺序。决策树把「算法的所有可能运行」一次性画成一棵树，于是「最坏要问几次」就变成了纯粹的树的几何量——高度。这一步是整个证明的精髓：把「算法快慢」翻译成「树有多高」。

### 4.3.3 Ω(n lg n) 下界的证明

证明分两步。

第一步（叶子数下界）：对 n 个**互异**元素，共有 n! 种可能的排列顺序，每一种都必须对应至少一个可达叶子（否则算法在那种输入上给不出正确答案）。所以决策树的叶子数 ℓ 满足：

ℓ ≥ n!

第二步（树高下界）：一棵高度为 h 的二叉树，叶子数至多 2^h。结合上式：

n! ≤ ℓ ≤ 2^h

两边取以 2 为底的对数：

h ≥ lg(n!)

再用 Stirling 公式 n! > (n/e)ⁿ 估计 lg(n!)：

lg(n!) = Θ(n lg n)

于是：

h = Ω(n lg n)

而 h 就是最坏情形比较次数，证毕。

核心是「信息量」——要在 n! 种可能里锁定唯一答案，每次比较只有两种结果、至多把候选减半，所以至少要问 lg(n!) ≈ n lg n 次。就像在 n! 个嫌疑人里用是非问题找出真凶，每问排除一半，最少要问 log₂(n!) 次。易错点有二：其一，n! ≤ 2^h 的方向别记反——叶子多、树必然高；其二，lg(n!) 不能草率地当成 lg(n) 而要展开——由 Stirling，lg(n!) = n lg n − n lg e + O(lg n)，主项是 n lg n，这才给出 Ω(n lg n) 而非 Ω(lg n)。本报告文末实测用「lg(n!) 与 n·lg n 的比值随 n 上升趋近 1」直观印证了 lg(n!) = Θ(n lg n)。

### 4.3.4 推论：哪些算法是渐进最优的

由 4.3.3，任何比较排序最坏都要 Ω(n lg n)。反过来，堆排序（4.1）和归并排序（大主题2 分治里出现）最坏情形都是 O(n lg n)。上界与下界在同一阶相遇，于是：

堆排序、归并排序在比较模型下都是**渐进最优**的比较排序。

「渐进最优」意思是「在大 O 意义下没有实质更快的比较排序了」——不排除有人把常数因子做得更小，但阶数 n lg n 已经封顶。快速排序略特殊：它的**期望**是 O(n lg n)（最优），但**最坏**是 Θ(n²)（非最优）——所以说快排「期望渐进最优」。这也解释了工程上为何常把快排与堆排序结合（如 introsort：快排为主，递归过深时切换到堆排序兜底最坏情形）。

## 4.4 线性时间排序

### 4.4.1 计数排序

计数排序（counting sort）假设 n 个输入都是 0 到 k 之间的整数。它不做任何元素间比较，而是：对每个值统计「有多少元素等于它」和「有多少元素小于等于它」，据此直接算出每个元素在输出数组中的最终位置。运行时间：

Θ(n + k)

当 k = O(n) 时，总时间为 Θ(n)——线性。

它还是**稳定**的（stable）：值相等的元素，输出中保持它们在输入中的相对先后。稳定性靠「从后往前扫描输入、放置元素」实现，是它能当基数排序子过程的前提。

想象要给一群人按年龄排队，你先数「几岁的各有几人」，再算「n 岁及以下共几人」——这个累计数就直接告诉你「n 岁的人该站到队伍第几号位置」，于是每个人一步到位，全程没有两个人互相比过年龄。易错点：k 必须**已知且不太大**；若值域巨大（如 32 位整数当 k≈4×10⁹），Θ(n+k) 里的 k 会爆炸，计数排序就不划算了——它换来的线性是「用空间/值域范围换的」。这正是它不违反 4.3 下界的原因：它根本不是比较排序。

### 4.4.2 基数排序

基数排序（radix sort）排「多位数」（或多字段记录）。它按位排序，且**从最低位到最高位**（least significant digit first），每一位用一个**稳定**的排序（通常是计数排序）来排。设每个数有 d 位、每位取值范围 0..k−1，运行时间：

Θ(d · (n + k))

当 d 为常数、k = O(n) 时是 Θ(n)——线性。

像整理一叠多位数卡片——先只看个位把牌堆稳定分好，再只看十位稳定分好，再百位……最后一位排完，整叠就完全有序了。关键靠「每位用**稳定**排序」：排高位时，低位造成的相对顺序不能被打乱，稳定性正好保证这一点。易错点：一定要**从最低位开始**（LSD）；若从最高位开始按位独立排就会错。为什么不违反下界？同理——它把每位当作小值域计数排序，不是比较模型。

### 4.4.3 桶排序

桶排序（bucket sort）假设输入**均匀分布**在某个区间（如 [0,1)）。它把区间等分成 n 个「桶」，把每个元素按值扔进对应的桶，桶内用简单排序（如插入排序）排好，最后按桶顺序依次串起来。在输入均匀分布的假设下，平均运行时间：

平均情形 Θ(n)

最坏情形（所有元素挤进同一个桶）会退化到 Θ(n²)。

像把一把随机撒的豆子按位置分进一排小格子——若撒得均匀，每格平均只有常数个豆子，格内排序几乎不费时，最后按格子顺序收起来就有序了。它的线性是**平均意义**的、且依赖「输入分布均匀」这个概率假设——与计数/基数排序「最坏也线性」的确定性线性不同。易错点：桶排序**是**比较排序（桶内用比较排序），它不违反 4.3 下界的原因不是「跳出比较模型」，而是「下界讲的是**最坏**情形，桶排序的线性是**平均**情形、且靠输入分布假设」——两处「绕过下界」的理由不一样，务必分清。

### 4.4.4 如何理解「绕过 Ω(n lg n) 下界」

把 4.4 三种算法与 4.3 下界放在一起看，能澄清初学者最常见的困惑——「不是证明了排序至少要 n lg n 吗，怎么又线性了？」两条不冲突的原因：

一是**换了模型**：计数排序、基数排序不靠元素间比较获取顺序，而是利用「元素本身是小范围整数、可当下标」这一额外信息。4.3 的 Ω(n lg n) 只约束**比较排序**，对非比较模型无效。

二是**换了情形口径**：桶排序仍是比较排序，但它的线性是**平均情形 + 均匀分布假设**下的，而下界说的是**最坏情形**——两者谈的不是同一件事。

下界不是「物理定律禁止线性排序」，而是「在只许比较、且要保证最坏情形的规则下，做不到比 n lg n 快」。一旦放宽规则（多用值信息、或只要求平均表现），就有空间做到线性。这也是选型的实践指南：值域小的整数/定长键优先考虑计数/基数排序；通用、值域大或不可比较为整数的场景，回到 O(n lg n) 的比较排序（快排/堆排序/归并）。
