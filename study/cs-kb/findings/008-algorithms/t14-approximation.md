## 14.1 近似比框架（Ch35 引言）

### 14.1.1 近似算法与近似比 ρ(n) 的定义

当一个优化问题被证明是 NP 难时，我们几乎不指望有多项式时间的**精确**算法。近似算法（approximation algorithm）换一个目标：在多项式时间内给出一个**可行解**，并**保证**这个解离最优不会差得太离谱。「差多少」这件事，用**近似比 ρ(n)** 来量化。

设某问题实例规模为 n，算法给出的解代价为 C，最优解代价为 C\*（最小化问题里 C ≥ C\* > 0，最大化问题里 0 < C ≤ C\*）。称一个算法是 ρ(n)-近似算法（ρ(n)-approximation algorithm），当且仅当对任意规模为 n 的输入都有

max( C / C\* , C\* / C ) ≤ ρ(n)

核心说明：这个定义故意用 max(C/C\*, C\*/C)，让**同一把尺子同时服务最小化和最大化问题**。最小化问题里 C ≥ C\*，起作用的是 C/C\*；最大化问题里 C ≤ C\*，起作用的是 C\*/C。两种情形算出来的 ρ(n) 都是**大于等于 1** 的数，越接近 1 说明近似越好，ρ(n)=1 就是精确算法。

辅助说明：初学者要抓住三个直觉。其一，**ρ(n) 是「最坏情形保证」，不是「平均表现」**——它承诺「无论输入多刁钻，都不会差过 ρ 倍」，这正是近似算法比启发式（heuristic，无保证）更硬的地方。其二，ρ 可以是常数（如后面顶点覆盖的 2），也可以随 n 增长（如集合覆盖的 ≈ ln n），常数比显然更值钱。其三，**方向要摆对**：最小化问题的解「不超过最优的 ρ 倍」，最大化问题的解「不小于最优的 1/ρ 倍」。一个常见易错点是把最大化问题的比写成 C/C\* < 1 就以为「近似比小于 1」——按 CLRS 的约定应取倒数 C\*/C ≥ 1，才与最小化情形口径一致。

### 14.1.2 近似方案：PTAS 与 FPTAS

有些问题不满足于「固定的 ρ」，而能做到「ρ 要多接近 1 就多接近 1」——代价是运行时间随精度上升。这类算法叫**近似方案（approximation scheme）**。

它多接受一个参数 ε > 0，产出一个 (1+ε)-近似解（对最小化问题解 ≤ (1+ε)·C\*）。

- **多项式时间近似方案（PTAS，polynomial-time approximation scheme）**：对**每个固定的 ε**，运行时间是 n 的多项式。注意指数里**允许含 1/ε**，例如 O(n^{2/ε}) 也算 PTAS——ε 一小，指数就爆，实际可能很慢。
- **完全多项式时间近似方案（FPTAS，fully polynomial-time approximation scheme）**：更强，运行时间**同时**是 n 和 1/ε 的多项式，例如 O(n³/ε)。1/ε 只能出现在系数/底数位置、不能钻进 n 的指数。

核心说明：三者是包含关系——精确 ⊂ FPTAS ⊂ PTAS。ε 越小，(1+ε) 越贴近 1，近似越准；FPTAS 是「性价比最高」的一档，因为把精度调高（ε 减小）时代价只多项式地涨。本大主题最后的子集和（§14.6）就是一个 FPTAS 的范例。

辅助说明：为什么要区分「1/ε 在指数里」还是「在系数里」？举个数：取 ε = 0.01（即 1/ε = 100）。若时间是 O(n^{1/ε}) = O(n^{100})，这在实践中等于不可用；若是 O(n³·(1/ε)²) = O(n³·10⁴)，只是多了个常数因子，完全能跑。这就是 FPTAS 比一般 PTAS 珍贵的原因。CLRS 与 Wikipedia 口径一致：PTAS 只要求「对固定 ε 是 n 的多项式」，FPTAS 追加「对 1/ε 也是多项式」。

### 14.1.3 为什么需要近似，以及本课的边界

近似算法是应对 NP 难的**三条常见出路之一**（另两条是：只处理特殊/小规模输入、用无保证的启发式）。它的价值在于「以可控的质量损失，换回多项式时间」。

核心说明：本课（L3-01）在本大主题只做**入门**——给几个能一眼看懂、证明只需一两步交换/求和的经典近似实例，把「近似比」这个概念立住。**边界 B2**：近似的**完整框架**——LP 舍入的一般理论、原始–对偶方法、半定规划（如 Max-Cut 的 Goemans–Williamson 0.878）、以及「某些问题近似到某界以下即 NP 难」的**不可近似性（inapproximability，PCP 定理）**——统一归 **L6-01 #04 高级算法**（先修 L6-01 #03 线性规划）。本报告遇到这些深化点只点名指路，不展开。

辅助说明：一个初学者常问「近似解不是最优，那有什么用？」——现实里很多 NP 难问题（布线、调度、设施选址）规模巨大，等精确解等到天荒地老，而一个「保证不超过最优 2 倍」的解 5 秒钟就能拿到并直接投产，这笔账通常很划算。另一个要点：**并非所有 NP 难问题都同样可近似**。有的能到 (1+ε)（如子集和，FPTAS），有的只能到常数（如顶点覆盖，2），有的只能到 Θ(ln n)（如集合覆盖），还有的（如一般 TSP）除非 P=NP **根本没有任何常数近似**（§14.3）。这种「可近似难度谱系」正是 L6-01 不可近似性理论要精细刻画的对象。

## 14.2 顶点覆盖的 2-近似（§35.1）

### 14.2.1 问题与 APPROX-VERTEX-COVER 算法

顶点覆盖问题（vertex-cover problem）：给定无向图 G=(V,E)，求一个**最小的**顶点子集 C ⊆ V，使每条边至少有一个端点在 C 里。判定版是经典 NP 完全问题（见大主题13）。

CLRS §35.1 的近似算法极其简单——反复挑一条**还没被覆盖**的边，把它的**两个端点都**放进 C，再删掉所有被这两个点覆盖的边，直到没有边剩下。

```text
APPROX-VERTEX-COVER(G):
    C = ∅
    E' = G.E                       // 尚未覆盖的边集合
    while E' ≠ ∅:
        任取一条边 (u, v) ∈ E'
        C = C ∪ {u, v}             // 两端点都放进覆盖
        从 E' 删去所有与 u 或 v 关联的边
    return C
```

核心说明：这个算法在多项式（实际线性 O(V+E)）时间内跑完，返回的 C 一定是合法顶点覆盖（循环退出时 E' 空，即每条边都被某次挑选覆盖过）。关键结论是它是一个 **2-近似算法**：

|C| ≤ 2·|C\*|

辅助说明：初学者最容易犯的错是「贪心地每次挑度数最大的点」——听起来更聪明，但那个策略的近似比其实是 Θ(log n)（会退化成集合覆盖式的坏情况），**远不如**这个「挑边、两端全要」的笨办法。这是近似算法里一个反直觉又深刻的点：**看起来更贪的策略不一定近似比更好**。这里「两端都要」看似浪费，恰恰是证明能卡到 2 的关键。

### 14.2.2 为什么是 2-近似：极大匹配给出下界

设算法挑中的那些边构成集合 A。这些边**两两不共享端点**（一条边被选后，它两端关联的边全被删了，下次不可能再挑到与之相邻的边），所以 A 是一个**匹配（matching）**，而且是**极大匹配（maximal matching）**。

由此有两个事实拼出结论。其一，算法输出的顶点数正好是被选边数的两倍：

|C| = 2·|A|

其二，任何合法顶点覆盖（包括最优的 C\*）都必须**为 A 里的每条边各出至少一个不同的端点**（因为 A 的边互不相邻，覆盖它们的顶点不能重用），于是

|A| ≤ |C\*|

两式相乘合并：

|C| = 2·|A| ≤ 2·|C\*|

核心说明：证明的精髓是**给最优解找一个可计算的下界**——我们不知道 C\* 到底多大，但知道它至少要 |A| 个点。近似算法的证明几乎都是这个套路：把「够不着的最优」夹在「一个能算的下界」和「算法的输出」之间。

辅助说明：为什么 |A| ≤ |C\*|？想象 A 里的边像一根根互不接触的火柴，每根火柴要「被盖住」至少得放一个顶点在它两端之一；火柴互不相邻，所以放的顶点也互不重复，覆盖 k 根火柴至少要 k 个点。最优覆盖 C\* 既然要盖住全图（含这 k 根火柴），就至少有 k=|A| 个点。这一步把「匹配大小」变成了「最优覆盖的下界」，是全证的枢纽。可选实测：在 300 组小随机图上比对本算法输出与暴力最优，比值上确界正好卡在 2.0：

```text
35.1 VC: max ratio approx/opt = 2.0 (<=2 expected): True
```

比值能取到 2（例如一条边的两端，最优只需 1 个而算法要 2 个），说明 2 这个界是**紧的**（tight），不是宽松估计。

## 14.3 旅行商问题的近似（§35.2）

### 14.3.1 三角不等式与「度量 TSP」

旅行商问题（traveling-salesperson problem，TSP；CLRS 4e 用 salesperson，3e 为 salesman，仅措辞改动）：给定完全图上每条边的代价，求一条经过所有顶点恰好一次再回到起点的**最小代价回路（哈密顿回路）**。TSP 判定版 NP 完全。

本节的可近似结论**依赖一个前提**：代价满足**三角不等式（triangle inequality）**——对任意三点 u,v,w，

c(u,w) ≤ c(u,v) + c(v,w)

满足此式的叫**度量 TSP（metric TSP）**，直觉是「绕路不会更省」，现实里的欧氏距离、路网距离都满足。

核心说明：请务必区分「度量 TSP」和「一般 TSP」——前者有 2-近似（本节 §14.3.2），后者除非 P=NP 连任何常数近似都没有（§14.3.3）。这个前提是整节论证的地基。

辅助说明：为什么非要三角不等式？后面的算法会「抄近路」——把 MST 遍历里重复经过的点跳过、直接连到下一个新点。只有三角不等式成立，这种「跳过中间点直连」才保证不增加总代价。若允许绕路更便宜（违反三角不等式），跳点就可能反而更贵，2 倍的保证随之崩掉。

### 14.3.2 MST 加倍：APPROX-TSP-TOUR 的 2-近似

算法思路：先求最小生成树 MST，再对 MST 做**先序遍历（preorder walk）**，按首次访问顺序列出各顶点，即得一条哈密顿回路。

```text
APPROX-TSP-TOUR(G, c):
    选一个顶点 r 作为根
    用 Prim 等算法求以 r 为根的最小生成树 T
    令 H = 对 T 做先序遍历得到的顶点访问序列
    return 哈密顿回路 H（按该序列首尾相接）
```

设 T 为 MST、W 为「把 T 每条边走两遍」的欧拉式环游（full walk）、H\* 为最优 TSP 回路。证明链条：

c(T) ≤ c(H\*)

c(W) = 2·c(T)

c(H) ≤ c(W) = 2·c(T) ≤ 2·c(H\*)

于是本算法是度量 TSP 的 **2-近似算法**，多项式时间（主要开销是求 MST，O(E lg V) 级）。

核心说明：三个不等号各有出处。① c(T) ≤ c(H\*)：把最优回路 H\* 删掉一条边就成了一棵生成树，其代价 ≥ MST，故 MST 不超过 H\*。② c(W)=2c(T)：环游把每条树边走两遍。③ c(H) ≤ c(W)：H 是把 W 里重复访问的点用「抄近路」跳过得到的，**靠三角不等式**保证不增代价。

辅助说明：这里再次看到 §14.2 的同一套路——用「MST 代价」这个能算的量作为 c(H\*) 的**下界**（步骤①），再证算法输出被 2 倍下界卡住。易错点：MST 加倍法给的是 **2**；课程/教材常提到更精细的 **Christofides 算法**能到 **3/2**（用最小权完美匹配替代「加倍」），但 Christofides 属 L6-01 #04 的内容，本课点名即可、不展开。可选实测：200 组小规模欧氏点集上，本算法回路 / 暴力最优回路的比值上确界约 1.36，稳在 2 以内：

```text
35.2 metric TSP: max ratio approx/opt = 1.3627 (<=2 expected): True
```

### 14.3.3 一般 TSP：除非 P=NP，没有常数近似

若去掉三角不等式（任意代价的一般 TSP），结论急转直下：

若 P ≠ NP，则对任意常数 ρ ≥ 1，一般 TSP 都**不存在**多项式时间 ρ-近似算法。

核心说明：证明是一则漂亮的归约——假设存在一般 TSP 的多项式 ρ-近似算法，就能用它在多项式时间内判定哈密顿回路（HAM-CYCLE，NP 完全）。构造：把哈密顿回路实例的图上「有边」的代价设为 1、「无边」的代价设为一个巨大的值（大到 ρ·|V|+1 这种量级）。若原图有哈密顿回路，最优 TSP 回路代价 = |V|，ρ-近似解 ≤ ρ·|V|；若没有，任何回路都得用到至少一条「巨大」边，代价远超 ρ·|V|。于是近似解的代价就能区分两种情形，等于多项式判定了 HAM-CYCLE，逼出 P=NP。

辅助说明：这个反差是本节最值得记住的一课——**「可不可近似」高度依赖问题的结构假设**。同一个 TSP，加上三角不等式就有 2-近似，去掉它连任何常数近似都触不可及。它也预告了 L6-01 的「不可近似性」主题：近似算法研究的一半是「能近似到多好」（上界），另一半是「不可能近似到多好」（下界/hardness），本例正是最干净的一个下界。

## 14.4 集合覆盖（§35.3）

### 14.4.1 问题与 GREEDY-SET-COVER 算法

集合覆盖问题（set-covering problem）：给定一个全集 X 和 X 的一族子集 F = {S₁,…,S_m}（其并集 = X），求**最少数目**的子集，其并仍覆盖 X。它是顶点覆盖等一大类覆盖型 NP 难问题的推广。

CLRS §35.3 的贪心算法：每一轮都挑「能覆盖**当前尚未覆盖元素**最多」的那个子集，直到全部覆盖。

```text
GREEDY-SET-COVER(X, F):
    U = X                                  // 尚未覆盖的元素
    C = ∅                                  // 已选子集
    while U ≠ ∅:
        选 S ∈ F 使 |S ∩ U| 最大
        U = U − S
        C = C ∪ {S}
    return C
```

核心说明：这是「每步吃掉最多新元素」的自然贪心，多项式时间。它的解不保证最优，但有一个**对数级的近似保证**（下一节）。

辅助说明：直觉上贪心很合理——先解决覆盖面最广的。但它会被精心构造的实例坑到 ln n 倍：存在一族实例，最优只需 2 个集合，贪心却被诱导选出 Θ(log n) 个。这正说明近似比是「最坏情形保证」，贪心的平均表现通常好得多。这里的贪心与大主题8 的贪心同源，但那里贪心能给**最优**（活动选择/Huffman），这里只能给**近似**——差别在于集合覆盖不具备「贪心选择性质」那种保最优的结构。

### 14.4.2 近似比 H(n) ≈ ln n，及不可近似下界（指路）

GREEDY-SET-COVER 的近似比是一个调和数：

ρ = H( max{ |S| : S ∈ F } ) ≤ H(|X|) ≤ ln|X| + 1

其中 H(d) = Σ_{k=1}^{d} 1/k 是第 d 个调和数，H(d) ≤ ln d + 1。粗略记作

ρ = H(n) ≈ ln n

核心说明：即「贪心解的集合数 ≤ (ln n + 1) × 最优集合数」。这是一个随 n 缓慢增长的比，比顶点覆盖的常数 2 弱，但对集合覆盖这类问题已接近理论极限（见下）。

辅助说明：为什么会冒出调和级数？证明给每个元素**摊派费用**：某元素在它「首次被覆盖」的那一轮，若该轮选中的集合新覆盖了 t 个元素，就给它记 1/t 的费用。分析每个最优集合 S\* 时，把 S\* 里元素被覆盖的先后排序，第 i 个被盖住时那一轮至少还能覆盖 |S\*|−i+1 个（否则贪心会先选 S\*），于是 S\* 分摊到的总费用 ≤ 1/|S\*| + 1/(|S\*|−1) + … + 1 = H(|S\*|)。把所有最优集合的费用加起来即得 ρ ≤ H(max|S|)。这就是调和数的来处。

关于**下界（不可近似性）**：Dinur–Steurer (2013) 证明，除非 P=NP，集合覆盖无法近似到 (1−o(1))·ln n 以内——也就是说贪心的 ≈ ln n **已基本触到理论极限**，不可能有本质更好的多项式近似。这个 hardness 结果与 PCP 机器属 **L6-01 #04**，本课只点名、不证。

可选实测（200 组小实例，贪心 vs 暴力最优）：

```text
35.3 set cover: max ratio greedy/opt = 1.5 | within H(max|S|) bound: True | ln n+1 for n=9 = 3.197
```

每个实例的贪心解都落在其 H(max|S|) 理论界内；小规模下实测比值（≤1.5）远小于 ln 9+1≈3.2 的松界，符合「最坏情形才逼近 ln n」的预期。

#### 来源与时效
- 锚点：CLRS 4e §35.3「The set-covering problem」p.1115（GREEDY-SET-COVER、定理 35.4 的 ρ = H(max{|S|}) ≤ ln|X|+1、调和数摊派证明）；核实 2026-07-26。
- 交叉核对：贪心近似比 H(n) ≤ ln n + 1 经 Wikipedia「Set cover problem」交叉确认（并给出更紧的 ln n − ln ln n + Θ(1) 与 Dinur–Steurer 2013 的 (1−o(1))·ln n 不可近似下界，二者是 CLRS 界的加细/补充，非冲突）。

## 14.5 随机化与线性规划视角（§35.4）

### 14.5.1 MAX-3-CNF：随机赋值的 7/8 期望

MAX-3-CNF 可满足性问题：给定一个 3-CNF 公式（合取范式，每个子句恰含 3 个**不同变量**的文字），求一组赋值使**被满足的子句数最多**。这是最大化型 NP 难问题。

CLRS §35.4 的算法出奇简单——**每个变量独立地以概率 1/2 取 1、1/2 取 0**。分析：单个子句（3 个不同变量的文字或）被违反当且仅当 3 个文字全假，概率 (1/2)³ = 1/8，故被满足的概率是

Pr[子句被满足] = 1 − 1/8 = 7/8

由期望的线性性（大主题3 的指示器随机变量），m 个子句里被满足的期望个数为

E[满足子句数] = (7/8)·m

由于最优也至多满足 m 个，这是一个（按 CLRS 约定 ρ = C\*/C 的最大化口径）**随机化 8/7-近似算法**。

核心说明：随机赋值这个「什么都没想」的策略，期望就能满足 7/8 的子句——这是随机化近似最惊艳的入门例子。8/7 = (最优 m)/(期望 7m/8) 是把最大化比统一成 ≥1 的写法。

辅助说明：初学者要留意两点。其一，「每子句 3 个**不同**变量」这个前提保证 3 个文字的真假相互独立，(1/2)³ 才成立。其二，这是**期望**保证，不是每次都满足 7/8；但由期望存在，**至少存在一组**赋值满足 ≥7/8·m 个子句（可用条件期望法去随机化成确定算法，属 L6-01 深化）。顺带一提，Håstad 证明 MAX-3-SAT 近似到 7/8+ε 即 NP 难，故 7/8 是紧的——这个 hardness 归 L6-01 #04。可选实测（4000 次随机 3-CNF + 随机赋值）：

```text
35.4 MAX-3-CNF: empirical mean satisfied fraction = 0.8732 (7/8 = 0.875 )
```

经验均值 0.8732 与理论 0.875 = 7/8 吻合到小数第二位，佐证期望分析。

### 14.5.2 加权顶点覆盖：LP 松弛 + 舍入的 2-近似

加权顶点覆盖：每个顶点 v 有权 w(v) ≥ 0，求**总权最小**的顶点覆盖。它推广了 §14.2 的无权版本。

先写成 0-1 整数规划（每个顶点一个变量 x(v)∈{0,1}，选入覆盖则为 1）：

minimize  Σ_v w(v)·x(v)

subject to  x(u) + x(v) ≥ 1   （对每条边 (u,v)）

把约束 x(v)∈{0,1} **松弛**为 0 ≤ x(v) ≤ 1，就得到可多项式求解的**线性规划（LP relaxation）**。解出分数最优 x̄ 后**舍入**：

x(v) = 1  当 x̄(v) ≥ 1/2 ； 否则 x(v) = 0

核心说明：这个「LP 松弛 + 按 1/2 阈值舍入」的方法给出加权顶点覆盖的 **2-近似算法**。证明两步：① 每条边 (u,v) 有 x̄(u)+x̄(v)≥1，故 x̄(u)、x̄(v) 中至少一个 ≥1/2，被舍入进覆盖 ⟹ 输出是合法覆盖；② 舍入只在 x̄(v)≥1/2 时把它抬到 1，即 x(v) ≤ 2·x̄(v)，于是

Σ_v w(v)·x(v) ≤ 2·Σ_v w(v)·x̄(v) ≤ 2·w(C\*)

（末式因 LP 最优值 ≤ 整数最优 w(C\*)，LP 是放宽约束）。

辅助说明：这是 L6-01「LP 舍入」框架最干净的入门样本——**先在连续空间求一个便宜的分数解（下界），再舍入回整数解，并证明舍入放大不超过某常数倍**。这里第三次出现「拿一个能算的下界（LP 最优）夹住最优」的套路，与 §14.2/§14.3 一脉相承。易错点：LP 最优值一般是分数，它 ≤ 整数最优，绝不会更大——因为整数解是 LP 可行域里的一个特例。可选实测（150 组小加权图，scipy.optimize.linprog 解 LP 后按 1/2 舍入，比暴力最优）：

```text
35.4 weighted VC LP-round: max ratio = 2.0 (<=2 expected): True
```

比值上确界正好 2.0，界是紧的。

#### 来源与时效
- 锚点：CLRS 4e §35.4「Randomization and linear programming」p.1119（MAX-3-CNF 随机 8/7-近似、每子句满足概率 7/8、期望线性性；加权顶点覆盖 LP 松弛 + 阈值 1/2 舍入的 2-近似）；核实 2026-07-26。
- 交叉核对：MAX-3-CNF 每子句 7/8、随机 8/7-近似经 University of Hawaii ICS 311 Topic-25 讲义确认；加权/无权顶点覆盖 LP 松弛按 x̄≥1/2 舍入得 2-近似（整性间隙 = 2）经 Wikipedia「Vertex cover」确认。均与 CLRS 一致。

## 14.6 子集和（§35.5）

### 14.6.1 精确指数算法与「列表合并」

子集和问题（subset-sum problem，此处优化版）：给定正整数集合 S = {x₁,…,x_n} 和目标 t，求**不超过 t 的最大子集和**。判定版 NP 完全。

先看精确解法：维护一个「用前 i 个元素能凑出的所有子集和」的列表 Lᵢ。从 L₀={0} 出发，加入 xᵢ 时把上一列表与「上一列表每个值 +xᵢ」合并：

L_i = MERGE-LISTS( L_{i-1} , L_{i-1} + x_i )   （只保留 ≤ t 的值）

核心说明：这是精确的，但 |Lᵢ| 可能翻倍增长到 2ⁿ 量级——正是 NP 难的体现。合并（MERGE-LISTS）是把两个有序表归并成一个有序去重表。

辅助说明：这一步本质是「幂集和」的紧凑枚举——每加一个元素，可选/不选让可达和的集合至多翻倍。理解这个指数爆炸，才能体会下一步「修剪」为什么是把可行的近似从不可行的精确里抢出来的关键动作。

### 14.6.2 修剪（trimming）与 FPTAS

FPTAS 的核心动作是**修剪列表**：给一个修剪参数 δ，若列表里两个值很接近（后者 ≤ 前者 × (1+δ)），就删掉较大的那个，只留一个「代表」。这样列表长度被压到关于 n、1/ε 的多项式，同时保证误差可控。取

δ = ε / (2n)

每加入一个元素后修剪一次。最终返回列表里 ≤ t 的最大值 y。可证

y\* / y ≤ 1 + ε

即算法是一个 **(1+ε)-近似**，且运行时间是 **n 与 1/ε 的多项式**——一个 **FPTAS**（是本大主题唯一达到「任意精度」的例子）。

核心说明：修剪用「相对误差不超过每步 δ」换来「列表长度多项式」。n 次修剪累积的相对误差被 δ 的选取压在 (1+ε) 之内（(1+δ)ⁿ ≤ e^{ε/2} ≤ 1+ε 量级的估计）。这就把一个 NP 难问题的「近似版」做到了 FPTAS。

辅助说明：直觉是「值挨得太近的就合并成一个代表，反正差不了多少」。为什么 δ 要除以 2n？因为要做 n 轮修剪，误差会像复利一样叠 n 次，把每轮的相对误差控制在 ε/(2n) 量级，n 轮累乘后总相对误差才不超过 ε。这解释了 FPTAS 运行时间里 1/ε 只以多项式出现（列表长度 ~ n·ln(...)/ε 量级），符合 §14.1.2 对 FPTAS 的定义。可选实测（200 组随机实例，FPTAS 对比暴力精确）：

```text
35.5 subset-sum FPTAS: all instances satisfy (opt-approx)/opt <= eps : True
```

对随机取的 ε∈{0.1,0.2,0.4}，每个实例都满足 (最优 − 近似)/最优 ≤ ε，即近似解落在 (1−ε)·最优 与最优之间，佐证 (1+ε) 保证（最大化口径下解 ≥ 最优/(1+ε) ≥ (1−ε)·最优）。

#### 来源与时效
- 锚点：CLRS 4e §35.5「The subset-sum problem」p.1124（EXACT-SUBSET-SUM 的列表合并、TRIM 修剪、APPROX-SUBSET-SUM 的 FPTAS、δ=ε/(2n)、(1+ε)-近似与多项式于 n 和 1/ε 的时间界）；核实 2026-07-26。
- 交叉核对：FPTAS「对 n 与 1/ε 同时多项式、(1+ε)-近似」的定义经 Wikipedia「Polynomial-time approximation scheme」确认，与 CLRS §35.5 构造一致；MIT 6.046J syllabus 亦将 PTAS/FPTAS 列于「Approximation Algorithms」模块。
- 无来源冲突。
