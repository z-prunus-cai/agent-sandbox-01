## 2.1 矩阵乘法与分治引入

### 2.1.1 分治法的三步骤模板

分治法（divide-and-conquer）是一种算法设计范式：把一个规模为 n 的问题拆成若干个规模更小的同类子问题，递归求解，再把子解合并成原问题的解。CLRS 把它概括为固定的三步：

分（divide）：把问题分成若干个规模更小的同类子问题。
治（conquer）：递归求解子问题；当子问题小到基例（base case）就直接求解。
合（combine）：把子问题的解组合成原问题的解。

分治天生带来一个递归式（recurrence），描述运行时间 T(n) 如何由子问题规模的运行时间加上「分」与「合」的代价构成。所以本大主题一半在讲「怎么用分治设计算法」（2.1、2.2），另一半在讲「怎么解分治产生的递归式」（2.3–2.6）。

初学者的直觉锚：分治就像「把一摞要处理的文件对半分给两个人，各自再对半分下去，直到每人手里只剩一张（基例），最后逐层把结果汇总」。归并排序（大主题4会细讲）是最经典的例子——分成两半、各自排序、再归并。本章用「方阵乘法」当引子，是因为它能自然演出从朴素分治到 Strassen 加速的整个故事。

一个易错点：递归必须有基例，否则永不停机。基例通常是「规模小到某个常数就直接算」，对应递归式里 n 小于某常数时 T(n) = Θ(1)。

### 2.1.2 方阵乘法问题与朴素算法

给定两个 n×n 矩阵 A、B，它们的乘积 C = A·B 的每个元素定义为：

c[i][j] = Σ (k = 1 到 n) a[i][k] · b[k][j]

直接按这个定义算，需要三重循环——对每个 (i, j) 位置做一次长度为 n 的内积。因此朴素方阵乘法的运行时间是：

Θ(n³)

核心说明到此：朴素算法就是「照定义硬算」，n² 个输出元素、每个花 Θ(n) 次乘加，合起来 Θ(n³)。

辅助说明：初学者容易以为「矩阵乘法本来就得 n³，没别的办法」。本章要打破的正是这个直觉——通过分治重新组织计算，可以做到比 n³ 更快。为此先要看「分治怎么套到矩阵乘法上」。注意这里我们默认 n 是 2 的幂，方便对半分块；一般的 n 可以补零到 2 的幂，不影响渐进量级（补零至多让 n 翻倍，是常数因子）。

### 2.1.3 分块分治框架

把 n×n 矩阵按行列各对半切，得到 4 个 (n/2)×(n/2) 的子块。A、B、C 都这样切：

A = [[A11, A12], [A21, A22]]，B = [[B11, B12], [B21, B22]]，C = [[C11, C12], [C21, C22]]

于是乘积 C 的四个子块满足（每个都是两个 (n/2) 矩阵相乘再相加）：

C11 = A11·B11 + A12·B21
C12 = A11·B12 + A12·B22
C21 = A21·B11 + A22·B21
C22 = A21·B12 + A22·B22

核心说明：这一步把「一个 n 阶乘法」化成「8 个 n/2 阶乘法 + 4 个 n/2 阶加法」。加法是 Θ(n²) 级的（逐元素相加）。所以直接分块分治的递归式是：

T(n) = 8·T(n/2) + Θ(n²)

辅助说明：这个递归式用后面 2.5 的主方法一解，答案仍是 Θ(n³)——也就是说，天真地分块并没有变快！原因是子问题个数 8 太多了。CLRS 用这个「失败的尝试」作为悬念：既然瓶颈是「8 次乘法」，能不能想办法少做几次乘法？这正是 2.2 Strassen 的出发点。

易错点：分块时不要把「乘法」和「加法」的代价混为一谈。矩阵加法只要 Θ(n²)，矩阵乘法才是 Θ(n³) 的贵操作；分治加速的关键永远是「减少递归的乘法次数」，哪怕代价是多做几次便宜的加法。

#### 来源与时效
- 锚点：CLRS 4th ed (2022) §4.1「Multiplying square matrices」——分治三步骤模板、方阵乘法定义、朴素 Θ(n³)、四子块公式与 T(n)=8T(n/2)+Θ(n²) 分块递归；Ch4 章首「递归式」导言（基例、算法性递归式）；核实 2026-07-26。
- 锚点：MIT 6.046J (Spring 2015) syllabus「Divide and Conquer」——分治范式（divide/conquer/combine）与由此产生的递归式；核实 2026-07-26。
- 一致：两源都以「分/治/合 → 递归式」为分治的统一叙述，方阵乘法四子块公式与朴素 Θ(n³) 无分歧。
- 实测：分治矩阵乘法（含 Strassen）与 numpy `@` 在 200 组随机整数矩阵上逐元素相等（见 2.2）。
- 成熟度：经典，稳定，无版本漂移。

## 2.2 Strassen 算法

### 2.2.1 核心思想：用 7 次乘法代替 8 次

Strassen 算法（1969）在分块分治的基础上，用巧妙的加减组合，把「8 次 (n/2) 阶子矩阵乘法」减少到 **7 次**，代价是多做一些矩阵加减法（仍是 Θ(n²)）。它的递归式变成：

T(n) = 7·T(n/2) + Θ(n²)

用主方法（2.5）解出：

T(n) = Θ(n^{lg 7}) ≈ Θ(n^2.807)

核心说明：把递归乘法次数从 8 降到 7，指数就从 lg 8 = 3 降到 lg 7 ≈ 2.807——这就是分治「省一次子乘法」带来的量级收益。

辅助说明：为什么「7 vs 8」能改变指数？因为分治递归式里，子问题个数 a 出现在指数 log_b a 上（b=2 是每维缩小倍数）。8 个子问题给 log₂8 = 3，7 个给 log₂7 ≈ 2.807。别小看这 0.19 的指数差：n 越大差距越夸张，这正是「渐进量级」的威力。实测确认这两个指数：

```text
lg 7 = log2(7) = 2.807355  (Strassen exponent)
naive divide (8 mults): exponent log2(8) = 3.0
```

易错点：Strassen 的加速纯粹来自「减少乘法个数」，不是来自更聪明的循环。它多付出的加减法让常数因子变大，所以小矩阵上 Strassen 反而更慢，只有 n 大到越过某个拐点才划算——工程里常在递归到中等规模时切回朴素算法。

### 2.2.2 七个积与结果重组

Strassen 先算 7 个中间积（每个是一次 (n/2) 阶递归乘法），CLRS §4.2 的一种标准写法是：

P1 = A11·(B12 − B22)
P2 = (A11 + A12)·B22
P3 = (A21 + A22)·B11
P4 = A22·(B21 − B11)
P5 = (A11 + A22)·(B11 + B22)
P6 = (A12 − A22)·(B21 + B22)
P7 = (A11 − A21)·(B11 + B12)

再用加减把四个结果子块拼出来：

C11 = P5 + P4 − P2 + P6
C12 = P1 + P2
C21 = P3 + P4
C22 = P5 + P1 − P3 − P7

核心说明：只用到 P1…P7 这 7 次乘法（外加若干加减），就能还原出 C 的全部四块。

辅助说明：初学者不必背这组公式，也不必手推它为何成立——记住「存在这样一组恒等式，能用 7 次乘法算出 4 个子块」即可。它的正确性靠展开验证：把每个 Pᵢ 代入右边，逐项化简后正好等于 2.1.3 的四个子块公式。为了给这组常量一次廉价的证伪机会（而非凭记忆相信它对），我把上面公式实现成递归 Strassen，与 numpy 的 `@` 在大量随机矩阵上对拍：

```text
Strassen == numpy @ over 200 random matrices (n in {1,2,4,8}): True
```

200 组随机整数矩阵全部逐元素相等——加固了这组公式的实现正确性；但真正的正确性来源仍是 CLRS §4.2 的恒等式推导，实测只是补充。

易错点：Strassen 的实用意义主要是理论上「打破 Θ(n³) 屏障」。此后有更快的算法（如 Coppersmith–Winograd 系及后续改进，指数逼近 2.37），但那些常数巨大、不实用，属本课边界之外，点名即可。工程库（BLAS/numpy 底层）通常用高度优化的朴素 Θ(n³) 加缓存分块，而非 Strassen。

#### 来源与时效
- 锚点：CLRS 4th ed (2022) §4.2「Strassen's algorithm for matrix multiplication」——7 次乘法的 P1…P7 与 C 子块重组公式、递归式 T(n)=7T(n/2)+Θ(n²)、解为 Θ(n^{lg7})；核实 2026-07-26。
- 锚点：MIT 6.046J (Spring 2015) syllabus「Divide and Conquer」——Strassen 作为分治减少子问题数的范例、n^{lg7} 结论；核实 2026-07-26。
- 一致：两源对「7 次乘法 → Θ(n^{lg7})≈n^2.81」结论一致。P1…P7 的具体分组在不同教材有多种等价写法（都能验证正确），本报告采用 CLRS §4.2 的一组并经对拍确认，不同写法之间非「冲突」而是同一恒等式的等价重排。
- 实测：Strassen（CLRS 分组）与 numpy `@` 在 200 组随机矩阵逐元素相等；lg7=2.807355、lg8=3（Python 3.11.15/numpy 2.4.6）。
- 成熟度：经典，稳定。

## 2.3 代入法解递归式

### 2.3.1 方法：先猜解，再用归纳法验证

代入法（substitution method）分两步解递归式：先猜一个解的形式（一个渐进界），再用数学归纳法证明这个界对所有足够大的 n 成立（并顺便定出归纳需要的常数）。名字里的「代入」指的是：在归纳步里，把「对更小的 n 归纳假设已成立」这一事实代入递归式右边。

以归并排序式为例，要证：

T(n) = 2·T(⌊n/2⌋) + Θ(n)  的解是  T(n) = O(n·lg n)

具体做法是猜 T(n) ≤ c·n·lg n（c 为待定正常数），假设它对小于 n 的规模成立，代入右边推出它对 n 也成立。

核心说明：代入法能证任意递归式的界，但前提是你得先「猜对」一个界——它验证猜测，不产生猜测。

辅助说明：初学者最大的困惑是「怎么猜」。实用套路是：先用递归树法（2.4）或主方法（2.5）猜出量级，再用代入法把它严格证出来。所以代入法常和后两个方法搭配用。数学上，代入法就是「对递归深度做归纳」，和大主题1里循环不变式的归纳三段论是同一套逻辑，只不过这里归纳的是「规模更小的子问题」。

### 2.3.2 常见陷阱：常数必须精确匹配

代入法有一个经典易错点：只验证到「≤ 某个界」还不够，必须让归纳步里的不等式常数严丝合缝地闭合。比如想证 T(n) = 2T(⌊n/2⌋) + n 是 O(n)，猜 T(n) ≤ c·n，代入得：

T(n) ≤ 2·c·⌊n/2⌋ + n ≤ c·n + n = (c+1)·n

这里推出的是 (c+1)·n，不是 c·n——归纳没闭合，所以 O(n) 的猜测是错的（真解是 Θ(n lg n)）。

核心说明：归纳步末尾必须恰好推回「≤（同一个常数）·（同一个界）」的形式，多出任何低阶项都说明界猜小了。

辅助说明：另一个常见修补技巧是「减去一个低阶项」——当直接猜 c·g(n) 差一点点闭合不上时，改猜 c₁·g(n) − c₂·（低阶项），反而能证成。初学者知道有这回事即可，不必深挖。为给猜测一次数值上的证伪机会，我把 T(n)=2T(⌊n/2⌋)+n 真跑出来，检查它是否始终被 2·n·lg n 压住（即 O(n lg n) 猜测）：

```text
substitution guess T(n)<=2 n lg n holds for n=2..1999: True
```

n 从 2 到 1999 全部满足 T(n) ≤ 2·n·lg n，与「解是 Θ(n lg n)、故 O(n lg n)」一致。这只是经验加固，正式证明仍靠上面的归纳。

#### 来源与时效
- 锚点：CLRS 4th ed (2022) §4.3「The substitution method for solving recurrences」——猜测+归纳两步、归纳步常数闭合要求、「减去低阶项」修补技巧、以 T(n)=2T(⌊n/2⌋)+Θ(n) 为示例；核实 2026-07-26。
- 锚点：MIT 6.046J (Spring 2015) syllabus——解递归式的方法（substitution / recursion tree / master）与其相互配合；核实 2026-07-26。
- 一致：两源都将代入法定位为「验证猜测的归纳法」，强调常数必须闭合；无分歧。
- 实测：T(n)=2T(⌊n/2⌋)+n 对 n=2..1999 满足 ≤ 2 n lg n（Python 3.11.15）。
- 成熟度：经典，稳定。

## 2.4 递归树法

### 2.4.1 方法：把递归式画成树、逐层累加成本

递归树法（recursion-tree method）通过把递归式展开成一棵树来「看出」解的量级：树的每个节点代表一个子问题，节点上标注该次调用「分」与「合」的代价（即 f(n)），子节点是它的递归子问题；把每一层的成本加起来，再把所有层的成本加起来，就得到总代价。

对递归式：

T(n) = a·T(n/b) + f(n)

第 i 层有 aⁱ 个节点，每个节点的规模是 n/bⁱ、成本是 f(n/bⁱ)；树高约 log_b n，最底层是 n^{log_b a} 个叶子（基例）。

核心说明：递归树法的产物通常是一个「猜测」——把逐层求和算出来，得到解的候选量级，再交给代入法（2.3）严格验证。

辅助说明：初学者把它当成「用图形做求和」就对了。关键是回答一个问题：**成本主要花在哪一层？** 有三种典型情形——(a) 每层成本递减、根部（顶层）主导；(b) 每层成本大致相等、总成本 = 每层成本 × 层数；(c) 每层成本递增、叶子（底层）主导。这三种情形正好对应 2.5 主定理的三种情形，递归树法是理解主定理「为什么长这样」的最直观途径。

### 2.4.2 两个典型例子

例一，归并排序式 T(n) = 2·T(n/2) + n：每层总成本都是 n（第 i 层有 2ⁱ 个节点、每个成本 n/2ⁱ，乘起来还是 n），共约 lg n 层，故：

T(n) = Θ(n·lg n)

这是「每层等成本」情形。例二，T(n) = 3·T(n/2) + n：每往下一层节点数 ×3、单节点成本 ÷2，每层总成本按 (3/2)ⁱ 递增，叶子层主导，叶子数 3^{lg n} = n^{lg 3}，故：

T(n) = Θ(n^{lg 3}) ≈ Θ(n^1.585)

辅助说明：我用「沿递归树把所有节点成本真加起来」的方式，数值核对这两个量级（叶子成本记为 1）：

```text
T(n)=2T(n/2)+n at n=1024: tree-sum=11264, n*lg n=10240, ratio=1.100
T(n)=3T(n/2)+n at n=1024: tree-sum=1.751e+05, n^lg3=5.905e+04, ratio=2.965
```

第一行比值 1.100 稳定接近常数（恰好是 1 + 1/lg n = 1 + 1/10，因为除了 n·lg n 的内部成本还有 n 个叶子各 1），印证 Θ(n lg n)；第二行比值 2.965 也是一个常数（叶子层主导），印证 Θ(n^{lg3})。比值不随 n 发散、稳定在常数附近，正是 Θ 的经验特征。

易错点：递归树法容易在「层数」「每层节点数」「单节点成本」三者上算错其一。稳妥做法是分别写清这三样，再相乘、再对层求和；对不确定的量级，最后一定用代入法复核，别把递归树的直觉当证明。

#### 来源与时效
- 锚点：CLRS 4th ed (2022) §4.4「The recursion-tree method for solving recurrences」——树的层数 log_b n、第 i 层 aⁱ 个节点与成本 f(n/bⁱ)、叶子数 n^{log_b a}、逐层求和产生猜测再交代入法验证；核实 2026-07-26。
- 锚点：MIT 6.046J (Spring 2015) syllabus——递归树作为解递归式与建立主定理直觉的手段；核实 2026-07-26。
- 一致：两源都把递归树法定位为「产生猜测/建立主定理直觉」的可视化求和法，T(n)=2T(n/2)+n → Θ(n lg n) 的示例一致。
- 实测：树成本求和在 n=1024 处比值稳定（Θ(n lg n) 比值 1.10、Θ(n^{lg3}) 比值 2.965）（Python 3.11.15）。
- 成熟度：经典，稳定。

## 2.5 主方法与主定理

### 2.5.1 主定理的适用形式与三种情形

主方法（master method）给分治递归式一个「查表即得解」的公式，适用于形如下式的递归式：

T(n) = a·T(n/b) + f(n)，其中 a > 0、b > 1 为常数，f(n) 是给定的驱动函数（driving function）

核心是把驱动函数 f(n) 和「分水岭函数」n^{log_b a} 作比较（后者由叶子数决定）。CLRS 4th ed 主定理（Theorem 4.1）分三种情形：

情形 1：若 f(n) = O(n^{log_b a − ε}) 对某常数 ε > 0，则 T(n) = Θ(n^{log_b a})。
情形 2：若 f(n) = Θ(n^{log_b a} · lg^k n) 对某常数 k ≥ 0，则 T(n) = Θ(n^{log_b a} · lg^{k+1} n)。
情形 3：若 f(n) = Ω(n^{log_b a + ε}) 对某常数 ε > 0，且 f 满足正则性条件 a·f(n/b) ≤ c·f(n)（某常数 c < 1、n 足够大），则 T(n) = Θ(f(n))。

核心说明：直觉就是「比谁大」——情形 1 是叶子（n^{log_b a}）比 f 大、叶子主导；情形 3 是 f 比叶子大、根部主导；情形 2 是两者同阶（可差一个 lg^k 因子）、每层均摊、结果多出一个 lg 因子。

辅助说明：为什么拿 n^{log_b a} 当分水岭？因为它正是递归树叶子层的总成本（2.4）。log_b a 越大表示子问题越多/缩得越慢、叶子越占分量。把 f(n) 和它比，就是问「成本主要在根还是在叶」——这与 2.4 三情形一一对应，主定理只是把递归树的结论固化成公式。**注意 CLRS 4th ed 对情形 2 做了推广**：3rd ed 的情形 2 只处理 f(n)=Θ(n^{log_b a}) 给出 Θ(n^{log_b a} lg n)，4th ed 直接把 lg^k n 因子（k≥0）纳入情形 2，结论相应变成 lg^{k+1} n，覆盖面更广。

### 2.5.2 套用示例与验证

几个必须会算的例子（先算 log_b a，再和 f 比）：

归并排序 T(n) = 2T(n/2) + n：log₂2 = 1，f(n)=n=Θ(n¹)，属情形 2（k=0），得 Θ(n·lg n)。
Strassen T(n) = 7T(n/2) + Θ(n²)：log₂7 ≈ 2.807 > 2，叶子主导，情形 1，得 Θ(n^{lg7})。
T(n) = 9T(n/3) + n：log₃9 = 2，f(n)=n=O(n^{2−ε})，情形 1，得 Θ(n²)。
T(n) = 3T(n/4) + n：log₄3 ≈ 0.793，f(n)=n=Ω(n^{0.793+ε})，情形 3（须验正则性），得 Θ(n)。

我用 Python 核对了这些分水岭指数 log_b a 与情形判别：

```text
Master watershed exponents log_b(a):
  a=9,b=3: log_b a = 2.0000   f=n  -> case1 (n < n^2)
  a=1,b=2: log_b a = 0.0000   f=1  -> case2 (n^0, k=0) -> lg n
  a=3,b=4: log_b a = 0.7925   f=n  -> case3 (n > n^0.79)
merge-sort recurrence T=2T(n/2)+n: log_2 2 = 1, f=n=Theta(n^1) -> case2 -> Theta(n lg n)
```

指数与情形归属和上面的手算一致（a=1,b=2 即二分查找式 T(n)=T(n/2)+1，属情形 2，解 Θ(lg n)）。

易错点（两个「非情形」缝隙）：主定理不是万能的。情形 1 与情形 2 之间、情形 2 与情形 3 之间各有缝隙——如果 f(n) 比 n^{log_b a} 大但「大得不到一个 nᵋ 的多项式因子」（例如 f(n)=n·lg n 对分水岭 n），三个情形都套不上，此时得改用递归树法或 Akra–Bazzi（2.6）。另一个易错点是情形 3 千万别忘了验正则性条件 a·f(n/b) ≤ c·f(n)，绝大多数多项式类 f 都满足，但它是情形 3 结论成立的必要前提，不能跳过。

## 2.6 主定理证明与 Akra–Bazzi

### 2.6.1 连续主定理及其证明思路

CLRS §4.6 给出主定理的严格证明，做法是先证一个「连续版本」的主定理（continuous master theorem）——把 n 当作连续实变量、忽略取整（floor/ceiling），在这个干净的设定下用递归树逐层求和证出三情形；然后再论证「加回取整对渐进量级没有影响」，把结论迁移回原始的整数递归式。

核心说明：证明的骨架就是 2.4 的递归树——把总成本写成「各层 f 成本之和 + 叶子成本」，再分三种情形估计这个和由谁主导，分别得到三条结论。

辅助说明：初学者不必掌握完整证明，只需知道两件事。第一，主定理不是凭空规定的，它的三情形来自递归树「成本在根/均摊/在叶」三种走向的严格求和，2.4 的直觉是可以证严格的。第二，实际递归式里的 T(⌊n/b⌋)、T(⌈n/b⌉) 取整，只会带来低阶扰动，不改变 Θ 量级——这就是为什么平时套主方法可以放心「乱丢取整」（大主题1 §1.5.1 里已埋过这条惯例）。CLRS 把「连续版证明 + 取整无碍」拆成 §4.6，正是为了严谨地兑现这条平时被默认的便利。

### 2.6.2 Akra–Bazzi 方法：非均匀分割的推广

主定理要求所有子问题规模都是 n/b（均匀分割、单一 b）。当子问题规模不一致时（例如一个 n/3、一个 2n/3），主定理套不上，需要更一般的 Akra–Bazzi 方法（CLRS §4.7）。它处理形如下式的递归式：

T(n) = Σ (i = 1 到 k) aᵢ·T(n/bᵢ) + f(n)，其中 aᵢ > 0、bᵢ > 1

第一步，解出唯一的实数 p（分水岭指数），使：

Σ (i = 1 到 k) aᵢ · (1/bᵢ)^p = 1

第二步，解由一个积分给出：

T(n) = Θ( n^p · ( 1 + ∫₁ⁿ f(u) / u^{p+1} du ) )

核心说明：Akra–Bazzi 把主定理的「n^{log_b a}」推广成「由方程 Σ aᵢ bᵢ^{−p} = 1 定出的 n^p」，并用一个积分统一了三种情形——它是主定理的严格超集（单一均匀分割时退化回主定理）。

辅助说明：这个方程 Σ aᵢ bᵢ^{−p} = 1 就是「让各层总成本保持平衡」的条件，p 就是均衡时叶子层的增长指数；积分项 ∫ f(u)/u^{p+1} du 则衡量驱动函数 f 相对分水岭 n^p 累积起来有多重。以一个经典例子核对（这类不均匀分割正是主定理无能为力、Akra–Bazzi 派上用场的地方）：

```text
Akra-Bazzi T=T(n/3)+T(2n/3)+n: solve (1/3)^p+(2/3)^p=1 -> p = 1.0
  n=729: T(n)=7.486e+03, n(1+ln n)=5.534e+03, ratio=1.353
  n=6561: T(n)=8.969e+04, n(1+ln n)=6.422e+04, ratio=1.397
  n=59049: T(n)=1.007e+06, n(1+ln n)=7.078e+05, ratio=1.422
```

对 T(n)=T(n/3)+T(2n/3)+n：方程 (1/3)^p+(2/3)^p=1 解出 p=1；代入积分 ∫₁ⁿ u/u² du = ln n，得 T(n)=Θ(n(1+ln n))=Θ(n·lg n)。把真实递归值与 n(1+ln n) 比，比值稳定在 1.35–1.42（缓慢有界变化，不发散），印证 Θ(n log n)。这个例子说明：即便两个子问题一大一小、主定理套不上，Akra–Bazzi 仍能给出解。

易错点：Akra–Bazzi 的门槛是「解出 p」和「算那个积分」，比主方法麻烦得多，所以实践中能用主定理就用主定理，只有遇到非均匀分割/多项不同 bᵢ 才动用 Akra–Bazzi。另外 Akra–Bazzi 还允许子问题规模有小扰动项（如 n/bᵢ + O(n/lg²n)），细节属专家纵深，本课点名即可、不展开。
