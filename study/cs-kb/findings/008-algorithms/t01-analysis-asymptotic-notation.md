## 1.1 算法在计算中的角色与 RAM 模型

### 1.1.1 什么是算法：从问题到良定义计算过程

算法（algorithm）是把某个良定义（well-defined）的计算问题的输入变换为正确输出的、有限步骤的计算过程。CLRS 把算法定义为「任何良定义的计算过程，取某个值或值集合作为输入，产生某个值或值集合作为输出」，并要求它对每个合法输入都在有限步内停机并给出正确结果。一个算法之所以「正确（correct）」，是指它对每一个合法输入实例都停机并输出该实例的正确答案。

初学者容易把「算法」和「程序」混为一谈。区别在于：算法是解决问题的抽象方法（可以用自然语言、伪代码或流程图表达），程序是算法在某种语言里的具体实现。同一个算法（比如插入排序）可以用 Python、C、Java 各写一遍，它们是不同的程序，但背后是同一个算法。本课研究的是算法本身的性质（对不对、快不快），刻意不绑定具体语言。

再强调「良定义问题」这一前提：一个计算问题要先说清「输入是什么、期望输出满足什么关系」，算法才有可评判的对象。比如排序问题的规范是「输入一个 n 个数的序列，输出它的一个非降重排」——有了这个规范，我们才能判断某个过程是不是它的正确算法。

### 1.1.2 算法作为一种技术

CLRS §1.2 提出一个重要观点：算法本身是一种「技术」，其地位不亚于快的硬件。原因是，随着输入规模增大，算法之间的效率差距会远远盖过硬件之间的差距。

举一个 CLRS 用来说明的对比：插入排序运行时间约为 c₁·n²，归并排序约为 c₂·n·lg n。即使把插入排序放在一台快得多的机器上、并用高度优化的编译器，只要 n 足够大，运行在慢机器上的归并排序仍会全面胜出，因为

n² 终将远大于 n·lg n

这条增长率的差距，任何常数倍的硬件加速都补不回来。这就是为什么「选对算法」常常比「换更快的机器」更划算——尤其在数据规模不断增长的今天。

初学者由此该建立的第一印象是：本课后面所有的「快慢」讨论，比较的都是运行时间随规模 n 的增长率（growth rate），而不是某台机器上的绝对秒数。这也是 1.3、1.4 要把「快慢」抽象成渐进量级的根本动机。

### 1.1.3 RAM 计算模型

要脱离具体机器谈「一个算法要花多少步」，必须先约定一个抽象的机器模型。CLRS 采用随机存取机（random-access machine, RAM）模型：单处理器、指令顺序执行、没有并发；每条基本指令（算术、比较、数据移动、访存等）花费常数时间；每次访问内存中任意一个字（word）也花常数时间（这正是「随机存取」的含义——不像磁带要顺序扫）。

关键约定还包括：整数字长为 c·lg n 比特（c ≥ 1 的常数），即字够宽装得下问题规模，但又不允许「一个字里塞下无限信息」这种作弊。RAM 模型里不把幂运算等当作单条常数指令（除非另有说明），以免掩盖真实代价。

为什么需要这样一个模型？因为如果不固定「哪些操作算一步、每步多久」，谈「运行时间」就没有共同标尺。RAM 模型的价值在于：它足够贴近真实计算机（顺序执行、常数时间访存），又足够简单，让我们能用「基本操作的执行次数」作为运行时间的代理，进而只关心这个次数随 n 的增长率。

易错点：RAM 模型是一种理想化。它假设每次访存等代价，忽略了真实机器的多级缓存、分页等层次结构（那些属于 L2-01 / 组成原理的话题）。在本课的分析里，我们默认接受 RAM 的理想化，除非题目特别指出要考虑存储层次（如 L3-01 大主题 6 的 B 树用的是外存模型）。

### 1.1.4 伪代码约定

本课用伪代码（pseudocode）而非某种真实语言来描述算法，目的是最清楚地表达算法思想，而不被语言语法细节干扰。CLRS §2.1 给出一套伪代码约定，初学者需要熟悉的要点包括：

- 缩进表示块结构（代替 C 的花括号或 Python 的显式缩进语义）；
- 赋值用「=」，相等判断用「==」；
- 数组元素记作 A[i]，子数组记作 A[i..j]（含两端）；数组通常从下标 1 开始（这与从 0 开始的多数语言不同，读伪代码时要留意）；
- `//` 引导注释；变量默认是过程的局部变量；
- 对象/数组按引用传递，属性用 `obj.attr` 访问；
- 循环变量在 `for` 循环结束后保留其「越界后的第一个值」。

伪代码只在乎「把每一步说清楚」，因此它会省略错误处理、模块化、类型声明等工程细节。初学者读伪代码时的心态应是「翻译成任意语言都能跑」，而不是纠结某一行的语法是否合法。1.2 的插入排序就是第一个完整的伪代码例子。

## 1.2 循环不变式与正确性

### 1.2.1 插入排序算法

插入排序（insertion sort）是本课第一个完整算法，也是循环不变式的示范舞台。它的思路和摸牌整理手牌一样：从左到右扫描数组，把当前元素插入到它左侧「已排好序的那段」中的正确位置。CLRS §2.1 的伪代码（数组从下标 1 起）为：

```text
INSERTION-SORT(A, n)
  for j = 2 to n
      key = A[j]
      // 把 A[j] 插入已排序子数组 A[1..j-1]
      i = j - 1
      while i > 0 and A[i] > key
          A[i+1] = A[i]
          i = i - 1
      A[i+1] = key
```

外层每前进一步，「已排序前缀」就多纳入一个元素；内层 while 把比 key 大的元素逐个右移，为 key 腾出插入位。

初学者的直觉锚：想象手里从左往右一张张理扑克，每拿到新的一张，就在左手已排好的牌里从右往左找位置插进去。插入排序对「已经近乎有序」的数组特别快（内层几乎不移动），这是它在小数组、近有序数组上作为子程序被沿用的原因。

### 1.2.2 循环不变式：三段论证正确性

要证明插入排序「排得对」，CLRS 用循环不变式（loop invariant）——一个在循环每一轮开始时都成立的性质。对插入排序外层循环，不变式是：

在 for 循环每次迭代开始时，子数组 A[1..j-1] 恰由原来 A[1..j-1] 的元素构成，且已按非降序排好。

证明一个循环不变式能保证正确性，需要走三段论（和数学归纳法同构）：

- 初始化（initialization）：第一次进入循环前不变式成立。（j=2 时，A[1..1] 只有一个元素，天然有序。）
- 保持（maintenance）：若某轮开始时不变式成立，则下一轮开始时它仍成立。（内层把 A[j] 插入正确位置后，A[1..j] 变得有序，正好是「下一轮开始（j 增 1）时 A[1..j-1] 有序」。）
- 终止（termination）：循环结束时，不变式配合「循环为何终止」这一事实，能推出算法正确。（循环在 j 超过 n（即 j=n+1）时结束，不变式给出 A[1..n] 是原元素的有序重排——正好是排序问题的正确输出。）

初学者最该记住的一点：终止这一步不是走过场，它是把「每轮都成立的不变式」兑现成「最终结果正确」的临门一脚——必须结合「循环停下来时循环变量取什么值」来读不变式。

### 1.2.3 与数学归纳法的关系及易错点

循环不变式的三段论和数学归纳法一一对应：初始化 ≈ 归纳基例（base case），保持 ≈ 归纳步（inductive step，从 k 推 k+1）。差别在于，普通归纳的「步数」可以无限，而循环不变式的归纳在循环终止时就停——所以必须额外有「终止」这一段，把有限次归纳的结论收口成正确性。

一个常见易错点是只证了「保持」就宣称算法对。但若不检查初始化，归纳没有起点；若不分析终止，就没把不变式和最终输出连起来。三段缺一不可。

另一个易错点是把不变式写得太弱或太强。太弱（如只说「A[1..j-1] 是原元素」，不提有序）证不出正确性；太强（加入实际不成立的性质）则「保持」通不过。设计一个恰到好处的不变式，本身就是理解算法的核心。

可选的实证不能替代正确性证明，但能做一次廉价的证伪尝试：把插入排序与 Python 内置 `sorted()` 在大量随机数组上对拍，若有一例不一致就说明实现错了。实测（环境 Python 3.11.15 / Linux 6.18.5 x86_64）：

```text
insertion_sort == sorted() over 2000 random lists: True
```

2000 个随机长度、随机取值的数组全部一致——这加固了实现的信心，但真正保证正确性的仍是上面的循环不变式论证，实证只是补充。

## 1.3 运行时间与增长量级

### 1.3.1 运行时间与输入规模

一个算法的运行时间（running time）指它在某个输入上执行的基本操作总数（在 RAM 模型下每条基本操作是常数时间，故操作数正比于时间）。运行时间几乎总是随输入规模（input size）增大而增大，所以我们把运行时间写成输入规模的函数 T(n)。

「输入规模」是什么，取决于问题：排序问题里是元素个数 n；图算法里通常是顶点数与边数两个量 V 和 E；大整数运算里是数字的位数。选对规模度量是分析的第一步。

分析一个算法的运行时间，做法是：数出每条语句执行多少次，乘以各自的（常数）单位代价，加起来得到 T(n)。CLRS §2.2 对插入排序逐行做过这样的加总，得到一个形如 a·n² + b·n + c 的表达式。但我们很快会发现，纠结 a、b、c 这些常数意义不大——真正要紧的是最高次项，这引出下面的增长量级抽象。

### 1.3.2 最坏、平均与最好情形

对固定的规模 n，同一个算法在不同具体输入上的运行时间可能不同。于是在「所有规模为 n 的输入」这个集合上，我们分别取三种统计量：

- 最坏情形（worst case）：规模 n 的输入里运行时间最长的那个，记 T_worst(n)；
- 最好情形（best case）：运行时间最短的那个；
- 平均情形（average case）：在某个输入概率分布下运行时间的期望。

以插入排序为例：输入已经升序时，内层 while 每次都立刻不满足条件，是最好情形 Θ(n)；输入完全降序时，每个元素都要一路移到最前，是最坏情形 Θ(n²)。

CLRS 说明为什么最常报告最坏情形，理由有三：

- 它给出运行时间的上界保证——无论输入多坏都不会更慢，这对有时限的系统是硬承诺；
- 对许多算法，最坏情形经常发生（如查找一个不存在的元素）；
- 平均情形往往与最坏情形同阶，且平均情形还需额外假设输入分布，最坏情形不需要。

初学者直觉：最坏情形像体检报告的上限值——未必是日常的样子，但它是你能对外做出的安全承诺。工程里说「这个操作是 O(log n)」，默认指最坏情形上界，除非另行说明。

### 1.3.3 增长量级：扔掉常数与低阶项

分析出 T(n) = a·n² + b·n + c 之后，CLRS 做一个关键抽象：只保留最高次项，并丢掉它的常数系数，得到增长量级（order of growth / rate of growth），记作 Θ(n²)。

之所以能这么做，是因为当 n 很大时，最高次项主导一切。以

3n² + 100n + 500

为例，n = 10⁶ 时 3n² 已是 3×10¹²，而 100n 才 10⁸，相差上万倍；系数 3 相对增长率也无关紧要（它依赖机器/编译器，不可移植）。所以我们说它是「n² 量级」，把 3、100n、500 全扔掉。

初学者要建立的直觉是：增长量级是一副「只看大局的望远镜」，回答「输入翻倍/翻十倍时代价大致怎么变」，而不回答「跑几毫秒」。两个都是 Θ(n²) 的算法在具体机器上可能差几倍（常数不同），但只要 n 足够大，任何 Θ(n) 算法终将碾压任何 Θ(n²) 算法——这正是 1.1.2「算法作为技术」那条论证的数学内核。

可选实证——把插入排序喂逆序输入（最坏情形），测不同规模的耗时，看它是否按 n² 增长。若真是 Θ(n²)，n 翻倍时耗时应约 4 倍（2²）；在对数-对数坐标下拟合出的斜率应约等于 2。实测（环境 Python 3.11.15 / Linux 6.18.5 x86_64）：

```text
n=  200  t=0.00084s
n=  400  t=0.00310s
n=  800  t=0.01276s
n= 1600  t=0.05285s
  t(n=400)/t(n=200) = 3.69  (expect ~4 for n^2)
  t(n=800)/t(n=400) = 4.12  (expect ~4 for n^2)
  t(n=1600)/t(n=800) = 4.14  (expect ~4 for n^2)
log-log slope (empirical exponent) = 1.997  (expect ~2)
```

翻倍比接近 4、拟合指数 ≈ 1.997，与理论最坏情形 Θ(n²) 吻合。注意这只是经验加固，不是证明；理论增长量级仍以逐行计数分析为准。

### 1.3.4 情形与量级是正交的两件事

必须反复强调：最坏/平均/最好是「在哪种输入上量」，而增长量级（以及下节的 O/Ω/Θ）是「用什么界表达这个量随 n 的增长」。二者正交，可自由组合。

于是下面都是合法且互不矛盾的陈述：「插入排序最坏情形 Θ(n²)」「插入排序最好情形（已排序输入）Θ(n)」。给出「Θ(n²)」时若不说是哪种情形，默认理解为最坏情形。

一个常见错误说法是「插入排序是 Θ(n²) 所以永远慢」——它忽略了插入排序在近乎有序输入上最好情形只有 Θ(n)。把「情形」和「量级」分清，才能读懂这类看似矛盾的效率描述，也才能正确衔接 1.4 的记号系统。

## 1.4 渐进记号的形式定义

### 1.4.1 五个记号的直觉与集合观点

渐进记号（asymptotic notation）是给「增长量级」配的一套严格数学语言，共五个：O、Ω、Θ、o、ω。CLRS 强调，每个记号其实定义的是一个函数集合——O(g(n)) 是「增长不快于 g(n)」的所有函数组成的集合。习惯写法 f(n) = O(g(n)) 里的「=」实为「∈（属于）」的约定俗成滥用，是单向的。

一句话记忆锚（都在「忽略常数」的意义下）：

O 像 ≤，Ω 像 ≥，Θ 像 =，o 像 <（严格小于），ω 像 >（严格大于）。

其中 O/Ω/Θ 是「松/紧」的界（允许同阶），o/ω 是「严格」的界（必须差一个量级）。下面给出 CLRS §3.2 的形式定义，逐一独占展示。

### 1.4.2 O、Ω、Θ 的形式定义

O(g(n))（渐进上界）：

O(g(n)) = { f(n) : 存在正常数 c 和 n₀，使 0 ≤ f(n) ≤ c·g(n) 对所有 n ≥ n₀ 成立 }

Ω(g(n))（渐进下界）：

Ω(g(n)) = { f(n) : 存在正常数 c 和 n₀，使 0 ≤ c·g(n) ≤ f(n) 对所有 n ≥ n₀ 成立 }

Θ(g(n))（渐进紧界）：

Θ(g(n)) = { f(n) : 存在正常数 c₁、c₂、n₀，使 0 ≤ c₁·g(n) ≤ f(n) ≤ c₂·g(n) 对所有 n ≥ n₀ 成立 }

三者共用同一套「存在常数 c、门槛 n₀，从 n₀ 起不等式恒成立」的骨架，差别只在夹的方向：O 只压上界（天花板），Ω 只托下界（地板），Θ 上下同时用 g(n) 夹住（正好同阶）。

最小例子：2n + 3 = O(n)，取 c = 3、n₀ = 3 即可（n ≥ 3 时 2n+3 ≤ 3n）。同时 2n+3 也 = O(n²)——O 只要求「不快于」，宽松的上界照样合法。对称地 2n+3 = Ω(n)，也 = Ω(1)。而 2n+3 = Θ(n)，因为它既 = O(n) 又 = Ω(n)。

### 1.4.3 Θ 是 O 与 Ω 的交集（定理 3.1）

O、Ω、Θ 的核心关系可用一句话概括：Θ 就是 O 与 Ω 的交集。CLRS 定理 3.1 正式陈述：

f(n) = Θ(g(n)) 当且仅当 f(n) = O(g(n)) 且 f(n) = Ω(g(n))

O 是天花板、Ω 是地板，两者贴着同一个 g(n) 时，f 被夹成「正好这个量级」，这是最精确的刻画。所以给出紧界（Θ）总比只给松界（O 或 Ω）信息更多——能说 Θ 时就别只说 O。

一个高频易错点：很多人把 O 当「最坏情形」、把 Ω 当「最好情形」。这是混淆。O/Ω/Θ 是关于函数增长方向的界，与最坏/平均/最好（1.3.4）是正交维度。可以说「插入排序最坏情形是 Θ(n²)」，也可以说「插入排序的运行时间是 O(n²) 且是 Ω(n)（因为最好情形 n、最坏情形 n²）」——后者用一个跨越所有情形的界来陈述，与「情形」无关。

### 1.4.4 o 与 ω：严格（非紧）的界

o(g(n))（严格上界，读作 little-o）要求 f 的增长严格慢于 g——不只是不快于，而是被 g 甩开任意常数倍：

o(g(n)) = { f(n) : 对任意正常数 c > 0，存在 n₀ > 0，使 0 ≤ f(n) < c·g(n) 对所有 n ≥ n₀ 成立 }

注意与 O 的定义差别：O 是「存在某个 c」使不等式成立，o 是「对每个 c」都成立，而且是严格小于。ω(g(n))（严格下界，little-omega）对称：

ω(g(n)) = { f(n) : 对任意正常数 c > 0，存在 n₀ > 0，使 0 ≤ c·g(n) < f(n) 对所有 n ≥ n₀ 成立 }

当极限存在时，o 和 ω 有更好用的等价刻画：

f(n) = o(g(n))  ⟺  lim (n→∞) f(n)/g(n) = 0
f(n) = ω(g(n))  ⟺  lim (n→∞) f(n)/g(n) = ∞

对照 Θ：f(n) = Θ(g(n)) 时该比值趋于一个有限正常数。这给了区分「同阶」与「严格不同阶」的操作办法。

易错点：o 比 O 强（严格），O 允许同阶而 o 不允许。例如 2n² = O(n²) 但 2n² ≠ o(n²)（比值趋于 2，不趋于 0）；而 2n = o(n²)（比值趋于 0）。

可选实证——用 sympy 求这些比值的极限，核对 o/Θ 关系（环境 Python 3.11.15 / sympy 1.14.0）：

```text
lim n->oo  (n)/(n**2)      = 0   -> n = o(n^2)
lim n->oo  lg^3 n / n^0.5  = 0   -> lg^3 n = o(n^0.5)
lim n->oo  n^100 / 2^n     = 0   -> n^100 = o(2^n)
lim n->oo  (3n^2+100n+500)/n^2 = 3   -> Theta(n^2) (finite>0)
```

前三行比值趋 0 印证 o 关系（多项式对指数、polylog 对多项式都是严格更慢，见 1.5），末行比值趋有限正数 3 印证 Θ(n²)。符号极限与形式定义一致。

## 1.5 标准记号与常用函数

### 1.5.1 单调性、取整与模运算

分析里反复出现一批标准函数，先厘清几个基础约定。单调性：函数 f 单调递增指 m ≤ n 蕴含 f(m) ≤ f(n)；严格递增指 m < n 蕴含 f(m) < f(n)（递减对称）。

取整函数（floor/ceiling）把实数压到整数：⌊x⌋ 是不超过 x 的最大整数，⌈x⌉ 是不小于 x 的最小整数。核心不等式：

x − 1 < ⌊x⌋ ≤ x ≤ ⌈x⌉ < x + 1

以及对任意整数 n，⌊n/2⌋ + ⌈n/2⌉ = n。取整在分治算法里无处不在（把 n 个元素分成 ⌈n/2⌉ 和 ⌊n/2⌋ 两半），但它们只差常数，通常不影响渐进量级——分析时常可先忽略取整（CLRS 称之为分析中的「乱丢取整」惯例），最后再确认无碍。

模运算 a mod n 表示 a 除以 n 的余数，满足 a mod n = a − n·⌊a/n⌋，取值在 [0, n)。这些是后续散列（大主题 6）、数论（大主题 15）的基础，此处先建立记号。

### 1.5.2 多项式、指数与对数

多项式（polynomial）指形如 p(n) = Σ aᵢ·nⁱ（最高次为 d、a_d > 0）的函数，它渐进等于其最高次项：p(n) = Θ(n^d)。若一个函数 f(n) = O(n^k) 对某常数 k，就称 f 是多项式有界的。

指数函数（exponential）指底数为大于 1 的常数、指数含 n 的函数，如 2ⁿ。对数函数里，本课两个高频简写务必记牢：

lg n = log₂ n（以 2 为底），  ln n = logₑ n（自然对数）

一条影响一切算法比较的事实——指数碾压多项式：任何底数大于 1 的指数函数，其增长最终超过任何多项式。形式化为，对任意常数 a > 1 与 b：

lim (n→∞) n^b / aⁿ = 0，  即 n^b = o(aⁿ)

对偶地，对数（乃至任意正次幂的对数幂 lg^b n，称 polylogarithmic）增长最终慢于任何正次幂 n^a（a > 0）：

lg^b n = o(n^a)

初学者最反直觉的往往是后一条：「log 比任何正次幂都慢」。这解释了为什么 O(n log n) 只比 O(n) 略慢一点点（log 因子增长极缓），却远优于 O(n²)。

数值直观（多项式 vs 指数交叉点）实测（环境 Python 3.11.15）：

```text
n^3 vs 2^n crossover:
  crossover between n=9 and n=10
  at n=10: n^3=1000, 2^n=1024 -> 1000 1024
```

n³ 在 n=10 前后被 2ⁿ 反超，此后 2ⁿ 一骑绝尘——小规模看不出、大规模天壤之别，正是「渐进」二字的含义。

### 1.5.3 对数的换底与幂等式

对数在渐进里有一个方便性质：换底只改变一个常数因子，

log_a n = (log_b n) / (log_b a)

因为 1/log_b a 是常数，所以在 O/Θ 里对数的底无关紧要——O(log₂ n)、O(log₁₀ n)、O(ln n) 是同一件事，常直接写 O(log n) 不标底。这是「底可丢」，但要分清：底数（对数的底、幂运算里换底）可丢，幂次和指数的底不可丢——n² 与 n³ 不同阶，2ⁿ 与 3ⁿ 也不同阶（后者 3ⁿ/2ⁿ = (3/2)ⁿ → ∞）。

另一个常用恒等式（CLRS §3.3）：

a^{log_b c} = c^{log_b a}

它在把指数塔化简、比较不同底的表达式时很有用。初学者不必背证明，记住「log 底可丢、幂底不可丢」这条实用红线即可。

### 1.5.4 阶乘与 Stirling 近似

阶乘 n! = 1·2·3···n 增长极快。它的精确增长由 Stirling 近似给出：

n! = √(2πn) · (n/e)ⁿ · (1 + Θ(1/n))

由此可推出几条常用的渐进关系：

n! = o(nⁿ)，  n! = ω(2ⁿ)，  lg(n!) = Θ(n·lg n)

其中 lg(n!) = Θ(n lg n) 尤为重要——它是「比较排序至少要 Ω(n lg n) 次比较」这一下界的数学核心（本课大主题 4 会用到）。直觉：n! 大约是 n 个数每个约 lg n 位，乘起来的对数就是约 n·lg n。

实测核对 lg(n!) 与 n·lg n 的比值（应随 n 增大趋于 1，环境 Python 3.11.15）：

```text
lg(n!) vs n*lg n:
  n=    8  lg(n!)=       15.30  n lg n=       24.00  ratio=0.6375
  n=   64  lg(n!)=      296.00  n lg n=      384.00  ratio=0.7708
  n=  512  lg(n!)=     3875.17  n lg n=     4608.00  ratio=0.8410
  n= 4096  lg(n!)=    43250.05  n lg n=    49152.00  ratio=0.8799
```

比值单调上升并趋近 1，与 lg(n!) = Θ(n lg n) 一致（收敛慢是因为 Stirling 里还有 −n·lg e 等低阶项，但不改变量级）。

### 1.5.5 斐波那契数与黄金比

斐波那契数（Fibonacci numbers）由递归定义：F₀ = 0，F₁ = 1，F_i = F_{i−1} + F_{i−2}（i ≥ 2）。它与黄金比（golden ratio）

φ = (1 + √5) / 2 ≈ 1.618

密切相关。CLRS §3.3 给出闭式（其中 ψ = (1 − √5)/2 ≈ −0.618 为共轭）：

F_i = (φ^i − ψ^i) / √5

由于 |ψ| < 1，ψ^i 迅速趋于 0，故 F_i 约等于 φ^i/√5 四舍五入到最近整数，即

F_i = round(φ^i / √5)

这说明斐波那契数按底为 φ 的指数增长——一个「增长率藏在无理数里」的经典例子。它在算法里出现在斐波那契堆（L6-01）、辗转相除法最坏输入分析（大主题 15 数论）等处。

实测核对闭式（环境 Python 3.11.15）：

```text
round(phi^i/sqrt5)==fib(i) for i=1..29: True  phi= 1.618034
```

i 从 1 到 29，闭式四舍五入与迭代计算的斐波那契数完全相符，印证了黄金比闭式。
