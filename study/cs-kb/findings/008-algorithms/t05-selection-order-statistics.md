## 5.1 同时求最小值与最大值

### 5.1.1 顺序统计量与选择问题

在一个由 n 个元素构成的集合里，第 i 个顺序统计量（order statistic）就是把这些元素从小到大排好后处在第 i 位的那个元素。最小值是第 1 个顺序统计量，最大值是第 n 个，中位数是排在正中间的那个（n 为奇数时是第 (n+1)/2 个）。**选择问题（selection problem）** 就是：给定一个数组和一个下标 i，找出第 i 小的元素。

选择问题可以形式化为：

输入：n 个（互不相同的）数构成的集合 A，以及整数 i（1 ≤ i ≤ n）
输出：A 中恰好比其他 i−1 个元素大的那个元素 x（即第 i 小）

一个显而易见的解法是「先排序，再取第 i 个」，代价是排序的

Θ(n·lg n)

**求单个顺序统计量，能不能比『整体排序』更快？** 答案是能——期望甚至最坏情形都能做到线性时间 Θ(n)。因为我们只想要一个位置上的元素，没必要把全部元素都排好序。

排序等于「把每个人都站到自己的名次上」，而选择只是「找出第 i 名是谁」。找一个人显然不该比给全班排名更贵。本章 5.1 先拿最简单的「找最大/最小」当引子，5.2、5.3 再攻一般的第 i 小。这里默认元素互不相同以简化叙述；有重复元素时算法照样能跑，只是「第 i 小」的表述要按稳定的划分来理解。

### 5.1.2 单独求最小值（或最大值）需要 n−1 次比较

只求最小值，标准做法是「擂台赛」：先把第一个元素当擂主，依次拿后面每个元素来比，比擂主小就换擂主。

```text
MINIMUM(A):
    min = A[1]
    for j = 2 to n:
        if A[j] < min then min = A[j]
    return min
```

它恰好做

n − 1

次比较。求最大值完全对称，也是 n−1 次。

n−1 次比较是求最小值的**最优**比较次数——因为除最终的最小值外，其余 n−1 个元素每个都必须在某次比较里「输」至少一次（否则无法排除它是最小值的可能），每次比较最多淘汰一个候选，所以至少要 n−1 次。

这个「淘汰赛」下界论证是初学者理解比较模型下界的好起点，和大主题4 的比较排序下界 Ω(n lg n) 是同一类思路（用「每次比较能提供多少信息/淘汰多少候选」来推下界），只是这里问题简单，下界紧到 n−1。易错点：别把「至少 n−1 次比较」误读成「随便怎么写都恰好 n−1 次」——擂台法恰好达到这个最优，但写得笨（比如两两嵌套）可能更多。

### 5.1.3 同时求最小与最大：3⌊n/2⌋ 次比较的成对扫描

如果同时要最小值和最大值，最朴素的做法是「分别各跑一遍擂台赛」，共

(n − 1) + (n − 1) = 2n − 2

次比较。CLRS §9.1 给出一个更省的办法：**成对处理**。把元素两两分组，每对内部先比一次（1 次比较）分出这对的较小者和较大者，然后只用较小者去挑战当前的 min、只用较大者去挑战当前的 max（2 次比较）。于是每处理 2 个元素只花 3 次比较，总比较次数是：

3⌊n/2⌋

从 2n−2 降到 3⌊n/2⌋ ≈ 1.5n，省下约四分之一的比较——关键在于「一对里的较小者不可能是全局最大值，较大者不可能是全局最小值」，所以每个元素只需和 min、max 中的一个较量，而不必两个都比。

处理起点要看奇偶。若 n 为奇数，先把第一个元素同时设为 min 和 max，再对剩下的 n−1 个（偶数个）成对处理，得 3·(n−1)/2 = 3⌊n/2⌋ 次；若 n 为偶数，先比较前两个元素（1 次）定出初始 min、max，再对剩下的 n−2 个成对处理，得 1 + 3·(n−2)/2 = 3n/2 − 2 次，仍不超过 3⌊n/2⌋。所以 CLRS 的表述是「**至多** 3⌊n/2⌋ 次比较」。

我把成对扫描实现出来，逐次数比较，验证它确实不超过 3⌊n/2⌋、且远少于朴素的 2n−2：

```text
n=    5 correct=True comps=6 bound 3*floor(n/2)=6 naive(2n-2)=8
n=    6 correct=True comps=7 bound 3*floor(n/2)=9 naive(2n-2)=10
n=   99 correct=True comps=147 bound 3*floor(n/2)=147 naive(2n-2)=196
n=  100 correct=True comps=148 bound 3*floor(n/2)=150 naive(2n-2)=198
n= 1000 correct=True comps=1498 bound 3*floor(n/2)=1500 naive(2n-2)=1998
```

奇数 n（5、99）恰好打到 3⌊n/2⌋；偶数 n（6、100、1000）是 3n/2−2，都 ≤ 3⌊n/2⌋，且都比 2n−2 少。结果与 CLRS 的分析一致（实测仅加固，正确性来源仍是 §9.1 的比较计数论证）。

成对扫描省的是**比较次数**（关注的是常数因子），量级仍是 Θ(n)——单跑两遍擂台也是 Θ(n)。本节的意义在于展示「顺序统计量问题里，比较次数的常数因子是可以精算和优化的」，这为后面 5.2、5.3 里「用线性次数就选出第 i 小」做了铺垫。

#### 来源与时效
- 锚点：CLRS 4th ed (2022) §9.1「Minimum and maximum」——单独求最小值需 n−1 次比较且最优、朴素同时求需 2n−2 次、成对扫描每 2 元素 3 次比较、总数至多 3⌊n/2⌋（奇/偶起点处理）；Ch9 章首选择问题与顺序统计量定义；核实 2026-07-26。
- 锚点：MIT 6.046J syllabus / Lecture「Divide and Conquer: Median Finding」——顺序统计量与选择问题的定位（选择应快于整体排序）；核实 2026-07-26。
- 一致：两源都把「选择快于排序」作为本章动机；「n−1 次求最小、3⌊n/2⌋ 次同时求最值」为 CLRS §9.1 一手结论，无来源分歧。
- 实测：成对扫描比较次数 ≤ 3⌊n/2⌋ 且 < 2n−2（n∈{5,6,99,100,1000}，Python 3.11.15）。
- 成熟度：经典，稳定，无版本漂移。

## 5.2 期望线性时间选择

### 5.2.1 RANDOMIZED-SELECT：借快排的划分来选

一般的选择问题（求第 i 小）有一个漂亮的随机化算法 RANDOMIZED-SELECT，它直接复用大主题4 快速排序里的 RANDOMIZED-PARTITION：随机挑一个主元把数组划成「小于主元」和「大于主元」两段，主元落到它最终排好序后的正确位置 q 上。设主元在子数组里排第 k 小（k = q − p + 1），那么：

- 若 i = k，主元就是答案；
- 若 i < k，第 i 小落在左段，递归进左段找第 i 小；
- 若 i > k，第 i 小落在右段，递归进右段找第 (i − k) 小。

伪代码（p、r 为当前子数组边界，i 为要找的第 i 小，1-based）：

```text
RANDOMIZED-SELECT(A, p, r, i):
    if p == r: return A[p]
    q = RANDOMIZED-PARTITION(A, p, r)
    k = q - p + 1
    if i == k:      return A[q]
    elif i < k:     return RANDOMIZED-SELECT(A, p, q-1, i)
    else:           return RANDOMIZED-SELECT(A, q+1, r, i-k)
```

它和快速排序的唯一区别是——快排划分后要**递归处理两段**，而选择只需要**递归处理其中一段**（另一段整段丢弃）。正是「只走一边」把期望代价从 Θ(n lg n) 压到 Θ(n)。

初学者可以把它想成「二分查找的划分版」——每次随机切一刀，看目标在哪半边，只追进那半边。区别是这里切的位置是随机主元决定的、不保证对半，但期望上每次能砍掉常数比例的元素，累加起来的期望总代价仍是线性。我把它与「排序后取第 i−1 位」在 2000 组随机数组上对拍：

```text
2000 random trials, RANDOMIZED-SELECT == sorted()[i-1]: True
```

全部一致，加固了实现正确性（正确性来源仍是 §9.2 的划分不变式）。

### 5.2.2 为什么期望是线性：只走一边的代价累加

RANDOMIZED-SELECT 的期望运行时间是：

E[T(n)] = Θ(n)

CLRS §9.2 的分析用**指示器随机变量**（大主题3 的工具）：RANDOMIZED-PARTITION 选出的主元在子数组里等概率地排在第 1、2、…、n 位。设主元排第 k 位，则递归只进入较大的那一段，规模是 max(k−1, n−k)。对主元位置取平均，期望满足如下递归不等式：

E[T(n)] ≤ (1/n) · Σ (k = 1 到 n) E[T(max(k−1, n−k))] + O(n)

用代入法（大主题2 的方法）猜 E[T(n)] ≤ c·n，代入右边即可闭合，解出：

E[T(n)] = O(n)

直觉是「每次随机划分，期望上把问题规模缩到原来的常数比例（不超过约 3/4）」，规模按几何级数递减，各层代价 n + (3/4)n + (9/16)n + … 是收敛的几何级数，求和仍是 Θ(n)。

为什么是「不超过约 3/4」？因为主元位置在 [1, n] 上均匀分布，落在中间一半（第 n/4 到 3n/4 位）的概率是 1/2，只要落在这个区间，较大段就 ≤ 3n/4。所以「至少一半的划分是好划分」，好划分把规模砍到 ≤ 3/4——这和大随机快排的期望分析是同一套逻辑。我统计了求中位数时的平均比较次数，看它是否随 n 线性增长（即平均比较次数 / n 应稳定在常数）：

```text
  n= 1000 avg_comps=    3305.7 avg_comps/n= 3.306
  n= 2000 avg_comps=    6823.3 avg_comps/n= 3.412
  n= 4000 avg_comps=   13703.7 avg_comps/n= 3.426
  n= 8000 avg_comps=   26686.1 avg_comps/n= 3.336
```

比较次数 / n 稳定在 3.3~3.4 之间、不随 n 发散——正是期望线性 Θ(n) 的经验特征（这个常数约为 3~4，与理论上「求中位数期望约 3n~4n 次比较」相符；实测为可选加固）。

### 5.2.3 最坏情形仍是 Θ(n²)，随机化只保证「期望」

RANDOMIZED-SELECT 的最坏情形运行时间是：

Θ(n²)

如果每次划分都极端不平衡（主元每次都恰好是当前段的最小或最大值，较大段只比原来少 1 个元素），规模按 n, n−1, n−2, … 递减，各层代价累加成 Θ(n²)。这与随机快排的最坏情形同源。

这就是「随机化」的含义——它不改变**最坏情形**（对手若能看到随机数仍可构造坏输入的概率，或运气极差时），只是让「坏划分连续发生」的概率极低，从而把**期望**拉到线性。这里要与 5.3 的确定性算法分清：RANDOMIZED-SELECT 是 O(n) *期望*、O(n²) *最坏*；5.3 的「中位数的中位数」是 O(n) *最坏*（用确定性方法根除坏划分）。易错点：初学者常把「期望线性」误当成「一定线性」——不是，个别运行可能慢到二次方，只是平均而言快。实践中 RANDOMIZED-SELECT 因常数小、实现简单而更常用（C++ 的 `std::nth_element` 就以 quickselect 为主、必要时退回 5.3 的确定性算法兜底最坏情形）。

#### 来源与时效
- 锚点：CLRS 4th ed (2022) §9.2「Selection in expected linear time」——RANDOMIZED-SELECT 只递归一段、期望递归式 E[T(n)] ≤ (1/n)Σ E[T(max(k−1,n−k))] + O(n) 用指示器随机变量分析、期望 O(n)、最坏 Θ(n²)；核实 2026-07-26。
- 锚点：MIT 6.046J Lecture「Divide and Conquer: Median Finding」——随机化选择（randomized select / quickselect）期望线性时间、只走一段的分析；核实 2026-07-26。
- 一致：两源对「期望 O(n)、最坏 Θ(n²)、机制=快排划分只递归一段」完全一致。RANDOMIZED-SELECT 复用大主题4 的 RANDOMIZED-PARTITION，期望分析复用大主题3 的指示器随机变量与期望线性性。
- 实测：与 sorted()[i−1] 对拍 2000 组全一致；求中位数平均比较次数/n 稳定在 3.3~3.4（Python 3.11.15）。
- 成熟度：经典，稳定。

## 5.3 最坏线性时间选择（中位数的中位数 / BFPRT）

### 5.3.1 用「中位数的中位数」当主元，保证划分不会太偏

5.2 的软肋是「主元靠运气」，坏运气会退化到 Θ(n²)。SELECT 算法（由 Blum、Floyd、Pratt、Rivest、Tarjan 于 1973 年提出，常称 BFPRT）用一个**确定性**方法选主元，保证每次划分都足够平衡，从而做到**最坏情形也线性**：

最坏情形 T(n) = Θ(n)

它选主元的办法叫「中位数的中位数（median of medians）」，五步：

1. 把 n 个元素分成 ⌈n/5⌉ 组，每组 5 个（最后一组可能不足 5 个）。
2. 各组内部排序，取出各组的中位数（每组 5 个，排序是 O(1)），共 ⌈n/5⌉ 个中位数。
3. 递归调用 SELECT，求这 ⌈n/5⌉ 个中位数的中位数 x。
4. 用 x 作主元做一次划分（PARTITION 的变体）。
5. 设 x 排第 k 位：若 i = k 返回 x，若 i < k 递归左段，否则递归右段——和 5.2 一样只走一边。

与 RANDOMIZED-SELECT 唯一的不同是「主元怎么选」——不再随机，而是花线性时间精心算出一个「保证不太偏」的主元 x，代价是多一次对 ⌈n/5⌉ 个中位数的递归选择。

初学者会问「为什么绕这么大圈子选主元」——因为要**根除**坏划分。x 是「中位数们的中位数」，它天然处在数据的中间地带：不会太大也不会太小。下一节量化这个「不太偏」。我把 BFPRT 实现出来（分组、组内取中位数、递归求中位数的中位数、划分、只走一边），与 sorted()[i−1] 在 3000 组随机数组上对拍：

```text
3000 random trials, BFPRT == sorted()[i-1]: True
```

全部一致，加固了实现正确性。

### 5.3.2 划分保证：至少约 3n/10 个元素被分到每一侧

选出 x 后，可以证明：**至少约 3n/10 − 6 个元素 ≤ x，同样至少约 3n/10 − 6 个元素 ≥ x**。因此以 x 划分后，需要递归的那一段元素个数至多是：

7n/10 + 6

于是 SELECT 的最坏情形递归式为（第一项来自第 3 步对 ⌈n/5⌉ 个中位数的递归，第二项来自第 5 步只走一段，O(n) 是分组、求组内中位数、划分的成本）：

T(n) ≤ T(⌈n/5⌉) + T(7n/10 + 6) + O(n)

这个递归式解出 T(n) = O(n)，关键在于两段规模之比

1/5 + 7/10 = 9/10 < 1

严格小于 1——每层递归处理的总规模按比例 9/10 收缩，是收敛几何级数，用代入法猜 T(n) ≤ c·n 即可闭合，得线性。

「3n/10」是怎么来的？x 是 ⌈n/5⌉ 个组中位数的中位数，所以约一半（⌈n/5⌉/2 个）的组中位数 ≥ x。对这每一个「中位数 ≥ x」的组，组内还有 2 个元素 ≥ 它自己的中位数、从而 ≥ x（每组 5 个，中位数上方有 2 个）。于是「≥ x」的元素约有 3 · (⌈n/5⌉/2) ≈ 3n/10 个（减去含 x 的组与不满 5 个的末组带来的常数修正，即 −6）。对称地另一侧也至少约 3n/10。因此另一侧至多 n − 3n/10 = 7n/10（加常数），保证了递归段 ≤ 7n/10 + 6。我用递归式的子问题规模做了个数值核对，确认两段之和 < n：

```text
  n=   100 ceil(n/5)=20 7n/10+6=76 sum=96 (<n: True)
  n=  1000 ceil(n/5)=200 7n/10+6=706 sum=906 (<n: True)
  n= 10000 ceil(n/5)=2000 7n/10+6=7006 sum=9006 (<n: True)
```

三个规模下 ⌈n/5⌉ + (7n/10+6) 都稳定 < n（比例约 9/10），这正是递归式能解出线性的算术前提（实测仅示意子问题规模关系，非正式证明）。

### 5.3.3 为什么分组大小取 5：奇偶、常数与「必须 < 1」

分组大小选 5 不是随意的。核心约束是「两段规模之和的比例必须严格 < 1」，否则代入法闭合不上、算法退化。

分成 g 个一组时，「保证被分到一侧」的比例约为 (g+1)/2 · (1/2) / g 这类形式随 g 变化；取 g = 5 时得到 1/5 + 7/10 = 9/10 < 1，成立；而取 g = 3 时相应递归式变成 T(⌈n/3⌉) + T(2n/3 + …) + O(n)，两段之和 ≥ n，解出

T(n) = Θ(n·lg n)

不再线性。

直觉是——组太小（如 3），每个组中位数「压住」的元素太少，选出的主元保证不了足够平衡的划分，比例凑不到 < 1；组太大（如 7、9），划分更平衡但「组内求中位数」和常数开销变大，虽然仍线性但常数更差。5 是「刚好让比例 < 1、且常数尽量小」的经典折中，用奇数还便于取组内中位数（无需在两个中间值里纠结）。CLRS 的习题专门让读者验证「组大小 7 仍线性、组大小 3 退化到 Θ(n lg n)」。

BFPRT 虽然**最坏**线性，但它的常数因子和实现复杂度都远大于 5.2 的 RANDOMIZED-SELECT，所以**实践中很少单独使用**——工程实现（如 introselect）通常以随机 quickselect 为主，只在检测到划分连续变坏时才退回 BFPRT 兜底，兼得「平均快」与「最坏有保障」。本课止于「知道存在最坏线性的确定性选择算法、理解其分组—递归—划分骨架与 9/10 < 1 的关键」；更细的常数优化、组大小的精确权衡属专家纵深，点名即可、不展开。
