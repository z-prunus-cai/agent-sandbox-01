## 15.1 并行算法（CLRS 4e Ch26）

### 15.1.1 fork-join 并行模型

现代计算机有多个处理核心，若能把一个任务拆成若干可**同时执行**的子任务，就能比单核更快完成。CLRS §26.1 用 **fork-join（分叉—汇合）** 模型来描述这种并行：`spawn`（分叉）让一个子计算与父计算**并发**进行，`sync`（汇合）让父计算**等待**它分叉出的所有子计算都完成后再继续。

fork-join 模型的好处是它**与具体多少个核心无关**——程序员只需标出「哪些子计算逻辑上可以并行」，由底层调度器（运行时）去把这些逻辑并行任务映射到实际的物理核心上。这叫**动态多线程（dynamic multithreading）**。

可以把 `spawn` 想成「派一个人去干这件事，我自己继续往下做」，`sync` 想成「等派出去的人都回来我们再汇总」。最典型的例子是并行归并排序（CLRS §26.3）或并行矩阵乘法（§26.2）：把数组一分为二，`spawn` 一半、自己做另一半，两半都排好后再合并。初学者容易误以为「并行 = 一定更快」——实际上能不能加速、加速多少，取决于任务里到底有多少「必须串行」的部分，这就要引出下面的 work 和 span。

### 15.1.2 work、span 与并行度

**work（工作量）** 和 **span（跨度，也叫 critical-path length 关键路径长度）**。

T₁ = work = 单核（串行）执行全部操作所需的总时间

T∞ = span = 在**无限多**核心下所需的时间（= 计算 DAG 上最长的依赖链）

并行度（parallelism）= T₁ / T∞

work 是「总活儿有多少」，span 是「就算人手无限，也因为前后依赖而绕不过去的最长链条」。并行度 T₁/T∞ 表示「这个算法最多能被多少个核心有效利用」——超过这个数再加核心也基本没用了。

直觉上，span 就是「关键路径」：有些步骤必须等前一步的结果才能做（比如归并必须等两半都排好），这些串起来的最长链就限死了并行的极限。用 p 个核心的实际运行时间 T_p 有个经典界：

T_p ≥ max(T₁ / p, T∞)

也就是「再快也快不过把活儿平摊到 p 个核心」且「再快也快不过关键路径」。可选实测：对 8 个数做平衡二叉树求和，加法总数（work）= n−1 = 7，树高（span）= lg n = 3，并行度 ≈ 7/3 ≈ 2.33——手算与程序核对一致（见下）。

```text
15.1 sum of 8: work(adds)= 7 span= 3 parallelism~= 2.333
```

初学者只需记住这张「地图钉子」：并行算法的分析核心就是 work 和 span 两个量；本课点到为止，真正的并行编程模型、GPU、分布式并行归 **L4-05／L6-06**。

## 15.2 在线算法（CLRS 4e Ch27）

### 15.2.1 在线问题与离线最优

**在线算法（online algorithm）** 指必须**边看输入边做决定**、且决定后不能反悔的算法——它看不到未来的输入。与之对照，**离线算法（offline）** 事先就掌握了全部输入，能算出真正的最优解。

CLRS §27.1 用「等电梯」、§27.3 用「在线缓存（页面置换）」作引子。在线场景的难点在于：你现在做的选择可能被将来的输入证明是坏的，但你当时并不知道将来会发生什么。

最好懂的例子是缓存置换——内存满了要踢掉一页，但你不知道接下来会访问哪些页。离线最优（Belady 的 MIN 算法）能「预知未来」，踢掉「最久之后才会再用」的页；而真实的在线算法（LRU、FIFO）只能靠历史猜。在线算法研究的就是：在「看不到未来」这个硬约束下，最好能做到多好。

### 15.2.2 竞争分析与竞争比

衡量在线算法好坏的标准是**竞争比（competitive ratio）**：把在线算法的代价与「离线最优」的代价相比。

一个在线算法是 c-竞争的（c-competitive），若对任意输入序列 σ，

cost_online(σ) ≤ c · cost_optimal(σ) + 常数

竞争比 c 就是「因为看不到未来，最坏情况下要多付几倍代价」。c 越接近 1 越好。这是一种**最坏情况相对最优**的度量，不假设输入的概率分布。

注意竞争分析用的是「相对离线最优」，不是「相对某个绝对时间」——它衡量的是「无知未来」这一件事本身造成的损失。经典结论：任何确定性缓存算法的竞争比至少是 k（缓存槽数），而 LRU 恰好达到 k-竞争；随机化能把期望竞争比降到 O(log k)。这些**完整框架**（对手模型、势函数分析、随机化打破下界）在本课不展开，归 **L6-01 #06**（锚 Borodin–El-Yaniv）。本课只需知道「在线 = 看不到未来」和「竞争比 = 相对离线最优的最坏倍数」这两个概念。

- 锚点：CLRS 4th ed (2022) Ch27「Online Algorithms」§27.1（等电梯）、§27.2（维护搜索链表）、§27.3（在线缓存），章节号据官方 4e 目录 PDF 核实，2026-07-26。

## 15.3 矩阵运算（CLRS 4e Ch28）

### 15.3.1 解线性方程组与 LU 分解

CLRS §28.1 讲怎样高效求解线性方程组

A x = b

主流方法是 **LU 分解**：把矩阵 A 分解成一个下三角矩阵 L 与一个上三角矩阵 U 的乘积（配合行置换 P），

P A = L U

之后解 Ax=b 就化成「先解 Ly=Pb（前向替换）、再解 Ux=y（回代）」两步三角方程。

LU 分解的意义在于**一次分解、多次复用**——A 分解好后，换不同的右端项 b 都能快速求解，无需重复消元。它本质是高斯消元的矩阵形式记录。

为什么要 P（行置换）？因为消元时主元（对角元）可能是 0 或很小，直接除会出错或数值不稳，所以要把绝对值大的行换到主元位置，这叫**部分选主元（partial pivoting）**。可选实测：对一个 3×3 矩阵做 LU 分解并重构、再解方程，scipy 结果与直接求解一致：

```text
15.3 LU reconstruct ok: True
15.3 solve Ax=b: [ 1. -0.  2.]
```

### 15.3.2 求逆与最小二乘

§28.2 讲**矩阵求逆**，§28.3 讲**对称正定矩阵与最小二乘近似**。

求逆矩阵 A⁻¹ 与解方程组是「多项式等价」的问题（能快速做其中一个就能快速做另一个）。最小二乘解决的是「方程比未知数多、无精确解」时求最优近似——找 x 使残差 ‖Ax−b‖ 最小，其正规方程是

AᵀA x = Aᵀb

最小二乘是数据拟合（如线性回归）的数学核心——现实数据有噪声、方程组「超定」无精确解，就退而求「误差平方和最小」的解。对称正定矩阵之所以单列，是因为它能用更稳更快的 **Cholesky 分解**（LU 的对称特例）。本课只点名这些运算「是什么、干什么」；数值稳定性、条件数、迭代法等纵深归数值分析／线性代数课，实践中直接用 `numpy.linalg` / `scipy.linalg`。

- 锚点：CLRS 4th ed (2022) Ch28「Matrix Operations」§28.1（解线性方程组/LU）、§28.2（求逆）、§28.3（对称正定矩阵与最小二乘），章节号与标题据官方 4e 目录 PDF 核实，2026-07-26。

## 15.4 线性规划（CLRS 4e Ch29）

### 15.4.1 线性规划是什么

**线性规划（linear programming, LP）** 是在一组**线性不等式约束**下，**最大化或最小化一个线性目标函数**。标准型（CLRS §29.1）可写成

maximize   cᵀx
subject to A x ≤ b,  x ≥ 0

LP 的可行域（满足所有约束的点集）是一个**凸多面体**；线性目标的最优值一定在多面体的某个**顶点**上取到。大量组合优化问题（最大流、二部匹配、最短路等）都能写成 LP 或其整数版本，所以 LP 是优化的「通用语言」。

直觉上，你在一个多面体（被平面切出来的凸块）里，沿着目标方向往「最高处」走，最优点必落在某个角（顶点）上。可选实测：最大化 x+y，约束 x+2y≤4、3x+2y≤6、x,y≥0，scipy 求得顶点 (1, 1.5)、最优值 2.5：

```text
15.4 LP opt x,y= [1.  1.5] obj(max x+y)= 2.5
```

### 15.4.2 单纯形、对偶与建模

CLRS 4e §29.1 介绍 LP 的形式化与求解算法（含单纯形思想），§29.2 讲怎样把实际问题**建模**成 LP，§29.3 讲**对偶（duality）**。

**单纯形法（simplex）** 是从一个顶点沿棱走到相邻更优顶点、直到最优的经典方法；**对偶**指每个 LP（原问题）都对应一个「对偶 LP」，两者最优值相等（强对偶），对偶变量还能给出「约束的影子价格」。

需注意版本差异——CLRS **3e** 曾有独立的「§29.3 The simplex algorithm」详解单纯形转轴步骤；**4e 已重组** Ch29，节标题变为 §29.1「LP 的表述与算法」、§29.2「把问题建模为 LP」、§29.3「对偶」，单纯形的详细转轴被并入 §29.1 并**精简**（章节号与标题据官方 4e 目录 PDF 核实）。本课只需知道「LP = 线性约束下的线性最优化，解在顶点，有对偶」；单纯形完整推导、退化/反循环、椭球法与内点法等归 **L6-01 #03**，实践中直接用 `scipy.optimize.linprog`。

## 15.5 多项式与 FFT（CLRS 4e Ch30）

### 15.5.1 多项式的两种表示与 DFT/FFT

一个 n−1 次多项式可以用**系数表示**（列出各项系数）或**点值表示**（给出它在 n 个点上的取值）。CLRS §30.1–30.2 的核心洞见是：这两种表示可以互相转换，而做这个转换的高效工具就是 **FFT（快速傅里叶变换）**。

DFT（离散傅里叶变换）把系数向量在 n 个「单位根」上求值；FFT 是用**分治**在 O(n log n) 时间内算出 DFT（朴素求值需 O(n²)）。

FFT 是分治（大主题2）的一个漂亮应用——它把长度 n 的 DFT 按奇偶下标拆成两个 n/2 的子问题，递归式

T(n) = 2 T(n/2) + Θ(n)  ⇒  T(n) = Θ(n log n)

正是主定理情形 2。

FFT 最实用的后果是**快速多项式乘法／卷积**：两个多项式相乘（= 系数卷积）朴素要 O(n²)，但「转成点值 → 逐点相乘 → 转回系数」借助 FFT 只需 O(n log n)。可选实测：对 [1,2,3,4] 与 [5,6,7,8] 做卷积，FFT 法与直接卷积结果完全一致：

```text
15.5 FFT conv match: True direct= [5, 16, 34, 60, 61, 52, 32] fft= [5, 16, 34, 60, 61, 52, 32]
```

这里易错点是**浮点误差**——FFT 走复数运算，整数结果需四舍五入取回。§30.3 还讲 FFT 的电路实现。本课讲到「FFT = O(n log n) 算卷积的分治利器」即可；信号处理、数论 FFT 等纵深不展开，实践用 `numpy.fft`。

#### 来源与时效
- 锚点：CLRS 4th ed (2022) Ch30「Polynomials and the FFT」§30.1（多项式表示）、§30.2（DFT 与 FFT）、§30.3（FFT 电路），章节号据官方 4e 目录 PDF 核实，2026-07-26。
- 交叉核对：FFT 递归式 T(n)=2T(n/2)+Θ(n)=Θ(n log n) 与大主题2 主定理情形 2 自洽；卷积结果经本机 numpy.fft 与 numpy.convolve 对拍一致（scratchpad）。

## 15.6 数论算法（CLRS 4e Ch31）

### 15.6.1 GCD 与欧几里得算法

CLRS §31.2 讲求**最大公约数** gcd(a,b) 的**欧几里得算法**，基于恒等式

gcd(a, b) = gcd(b, a mod b)

不断用「大数除以小数取余」替换，直到余数为 0，此时的除数就是 gcd。

欧几里得算法的运行时间是 O(log(min(a,b))) 次取模——极快。扩展欧几里得还能顺带求出满足 ax+by=gcd(a,b) 的整数系数 x,y，这是求模逆元的关键。

可选实测——gcd(30,21)：30=1·21+9，21=2·9+3，9=3·3+0，故 gcd=3，与 `math.gcd` 一致：

```text
15.6 gcd(30,21): 3 (Euclid: 30=1*21+9,21=2*9+3,9=3*3+0 -> 3)
```

### 15.6.2 模幂、RSA 与素性测试

§31.3–31.6 讲模运算与**模幂**（快速求 aᵇ mod n），§31.7 讲 **RSA 公钥密码**，§31.8 讲**素性测试**。

模幂用「反复平方」在 O(log b) 次乘法内完成：

aᵇ mod n  ——  按 b 的二进制位反复平方并按位累乘

RSA 的安全性建立在「大整数分解很难」上——公钥 (e, n) 加密、私钥 d 解密，满足 (mᵉ)ᵈ ≡ m (mod n)，其正确性来自欧拉/费马定理。素性测试（如 Miller–Rabin）用来快速找大素数以构造 n。

可选实测——模幂 7^560 mod 561 与内置 `pow(7,560,561)` 一致（都为 1，561 是 Carmichael 数的性质）；RSA 玩具参数 (n=3233, e=17, d=2753) 对 m=65 加密得 2790、解密回 65：

```text
15.6 modexp 7^560 mod 561: 1 builtin: 1
15.6 RSA toy: m=65 -> c= 2790 -> dec= 65 roundtrip ok: True
```

本课讲到「GCD/模幂/RSA/素性测试是什么、能做什么」即可；RSA 的安全性证明、素性测试的概率误差分析等纵深归 **L5-04 密码学**。实践中模幂直接用 `pow(a,b,m)`。

## 15.7 字符串匹配（CLRS 4e Ch32）

### 15.7.1 从朴素到 Rabin–Karp

**字符串匹配**问题：在长度 n 的文本 T 中找长度 m 的模式 P 首次（或全部）出现的位置。CLRS §32.1 先给**朴素算法**——把 P 在 T 上逐位对齐、逐字符比对，最坏 O((n−m+1)·m)。

§32.2 的 **Rabin–Karp** 用**滚动哈希**加速：把每个长度 m 的窗口算成一个哈希值，窗口右移时 O(1) 更新哈希，只有哈希相等才做字符校验。平均接近 O(n+m)，最坏（哈希频繁碰撞）退化到朴素。

滚动哈希的诀窍是「进一个字符、出一个字符」时哈希能增量更新，不用重算整段——就像看一个滑动窗口里的数字，右移时减掉最高位、乘基数、加上新末位。

### 15.7.2 KMP、有限自动机与后缀数组

§32.4 的 **KMP（Knuth–Morris–Pratt）** 达到最坏 **O(n+m)**：预处理模式 P 得到**前缀函数（部分匹配表）**，匹配失败时不回退文本指针，而是让模式「滑动」到下一个可能匹配的位置。

KMP 的关键是「失配时已知前面匹配了多少，利用 P 自身的重复结构决定往后跳多远」，从而每个文本字符至多被检查常数次。§32.3 用**有限自动机**给出另一种 O(n) 匹配视角；§32.5 讲**后缀数组**（4e 内容）。

可选实测——在 "abxabcabcaby" 中找 "abcaby"，自实现 KMP 返回索引 6，与 `str.find` 一致：

```text
15.7 KMP idx: 6 str.find: 6 match: True
```

需注意 4e 的 Ch32 里 §32.4 KMP 是**带星号（选读）**的，且新增了 §32.5 后缀数组——这与只记「朴素/Rabin–Karp/KMP」的旧印象略有出入，广度上应知道有限自动机法（§32.3）和后缀数组（§32.5）也在其中。本课讲到「这些算法各自的思路和复杂度目标」即可，深挖归字符串算法/编译等下游课。

## 15.8 机器学习算法（CLRS 4e Ch33）

### 15.8.1 聚类与梯度下降

CLRS 4e 新增 Ch33「Machine-Learning Algorithms」，§33.1 讲**聚类（clustering）**、§33.3 讲**梯度下降（gradient descent）**。

**聚类**（如 k-means）把无标签数据点分成若干组，使同组内点尽量近、异组间点尽量远；k-means 反复「分配点到最近中心 → 重算中心」直到收敛。**梯度下降**是最小化可微目标函数的通用迭代法：沿目标函数梯度的反方向一小步一小步下山，更新式

x_{t+1} = x_t − η · ∇f(x_t)

其中 η 是步长（学习率）。

梯度指向函数上升最快的方向，取负号就是下降最快的方向；步长太大会越过最低点来回震荡，太小则收敛很慢——这是初学者最常踩的坑。k-means 的易错点是它只保证收敛到**局部**最优，结果依赖初始中心的选取。

### 15.8.2 乘性权重算法

§33.2 讲**乘性权重（multiplicative-weights）算法**——一种在线决策/学习的通用框架：维护一组「专家」的权重，根据每轮谁预测得好就**乘性地**调高/调低权重。

乘性权重能证明「跟得上事后最优专家」（regret 界很好），是连接在线学习、博弈论、优化的一条主线。

直觉是「相信历史上更准的专家，但保留对所有人的一点信任」，通过指数式加权自动放大好专家、抑制差专家。本课对 Ch33 只做「是什么、干什么」的入门点名——聚类的完整算法族、梯度下降的收敛性分析、乘性权重的 regret 证明、以及神经网络等一切纵深，归 **L5-02 机器学习**。本课不展开推导。
