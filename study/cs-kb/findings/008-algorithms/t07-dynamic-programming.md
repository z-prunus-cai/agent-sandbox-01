## 7.1 钢条切割

### 7.1.1 钢条切割问题与「为什么是 DP」

钢条切割（rod cutting）问题：给定一根长度为 n 英寸的钢条，和一张价格表（长度 i 的一段卖价 p[i]，i = 1..n），问把钢条切成若干整数长度段后，能卖出的最大总收益 r[n] 是多少（不切也算一种方案，切割本身不计成本）。

它的最优收益满足下面这个递推式：

r[n] = max( p[i] + r[n − i] )，其中 i 取遍 1..n

初学者的直觉锚：想象你要卖钢条，第一刀在哪切？你不知道，那就把所有可能的「第一段长度 i」都试一遍——第一段卖 p[i]，剩下的 n − i 长度是一个规模更小、结构完全相同的子问题，它的最优解是 r[n − i]。把每种第一刀的「本段收益 + 剩余最优收益」取最大，就是答案。这个「枚举第一步决策 + 递归求剩余子问题最优值」的模式，正是动态规划的骨架。

为什么这里能用 DP（而不是别的方法）？关键在两点，后面 7.3 会正式命名：一是最优子结构——整根钢条的最优切法，包含了「剩余段」的最优切法；二是子问题会大量重复——求 r[4] 要用到 r[3]、r[2]、r[1]、r[0]，而求 r[3] 又要再用一次 r[2]、r[1]、r[0]……同一个 r[k] 被反复要到。DP 就是「把这些重复的子问题只算一次、存起来复用」。

一个常见的等价写法（CLRS 也给了）把递推式改成只在「第一段」上枚举，剩下整块递归，这样每个子问题只有一层 max，便于分析。上面那条式子就是这种写法。

### 7.1.2 朴素递归为何是指数级

如果直接按递推式写成朴素递归函数（不存结果），运行时间是：

T(n) = 2^n （准确地说 T(n) = 2^{n−1} 次调用量级，即 Θ(2^n)）

朴素递归会把同一个子问题重算无数次，导致指数爆炸，n 稍大就跑不动。

为什么是 2^n？因为长度为 n 的钢条，每个内部位置「切 / 不切」是独立的二选一，一共有 n − 1 个内部位置，故不同的切割方案数是 2^{n−1}——朴素递归相当于把每一种方案都走了一遍。画出递归调用树能更直观：根是 n，它调用 n−1、n−2、…、0；而 n−1 又调用 n−2、n−3、…；于是 n−2 这个节点在整棵树里出现了很多次，每次都从头重算。这正是「重叠子问题」的现场——也是 DP 要消灭的浪费。

### 7.1.3 自顶向下备忘化

备忘化（memoization，注意不是 memorization）保留朴素递归的自然写法，但加一张备忘表 r[]：每次要算 r[n] 前先查表，算过就直接返回，没算过才递归、算完存表。伪代码：

```
MEMOIZED-CUT-ROD(p, n):
    令 r[0..n] 全部初始化为 −∞
    return MEMOIZED-CUT-ROD-AUX(p, n, r)

MEMOIZED-CUT-ROD-AUX(p, n, r):
    if r[n] ≥ 0:            # 已算过，直接复用
        return r[n]
    if n == 0:
        q = 0
    else:
        q = −∞
        for i = 1 to n:
            q = max(q, p[i] + MEMOIZED-CUT-ROD-AUX(p, n − i, r))
    r[n] = q
    return q
```

加了备忘后，每个子问题 r[0..n] 只被真正计算一次，计算 r[k] 时内部循环做 Θ(k) 次工作，总运行时间降到：

Θ(n^2)

备忘化的心智模型是「懒惰求值 + 缓存」——你还是按最自然的「从大问题往小问题问」的顺序写代码，但每个子问题的答案只算一次。它的好处是：如果某些子问题在实际输入下根本用不到，就不会去算（自顶向下天然只碰「可达」的子问题）。易错点：备忘表要用一个「不可能是合法答案」的哨兵值初始化（这里收益非负，故用 −∞ 或 −1 表示「未算」），否则无法区分「算出来恰好是 0」和「还没算」。

### 7.1.4 自底向上表格法

自底向上（bottom-up）反过来：先把最小的子问题解出来，再按规模从小到大逐个填表，填 r[j] 时它依赖的所有 r[j − i] 都已经就绪。伪代码：

```
BOTTOM-UP-CUT-ROD(p, n):
    令 r[0..n] 为新数组
    r[0] = 0
    for j = 1 to n:
        q = −∞
        for i = 1 to j:
            q = max(q, p[i] + r[j − i])
        r[j] = q
    return r[n]
```

运行时间同样是：

Θ(n^2)

自底向上不用递归，靠两层普通循环，外层规模 j 从 1 到 n、内层枚举第一段 i——因为填到 j 时，所有更小的 r[j−i] 都在前面填好了，这就是「按子问题依赖的拓扑序填表」。它和备忘化解出的答案完全一样，渐进时间也一样（都是 Θ(n²)）；实践中自底向上常数更小（没有递归调用开销、无栈溢出风险），备忘化则在「子问题稀疏、只需一部分」时更省。这两种正是 DP 的两副面孔，CLRS 明确并列介绍它们。

### 7.1.5 重构最优解（不只要值，还要方案）

上面只求出了最优收益这个「数」。若还想知道具体怎么切，就再存一张 s[] 表：填 r[j] 时记录取到最大值的那个第一段长度 s[j]，最后从 n 出发不断输出 s[n]、跳到 n − s[n]、再输出……直到 0，即可复原完整切割方案。

这是几乎所有 DP 的通用套路——先用一张表算「最优值」，再用一张辅助表记「每步的最优决策」，最后顺着决策表回溯出「最优解本身」。回溯的代价通常远小于填表，一般是 O(n) 或与解的长度成正比。记住区分两件事：DP 主表存的是「最优目标值」，辅助表存的是「达成它的选择」。

## 7.2 矩阵链乘法

### 7.2.1 问题：最优括号化

矩阵链乘法（matrix-chain multiplication）问题：给定一串要连乘的矩阵 A₁·A₂·…·Aₙ，其中 Aᵢ 的规模是 p[i−1] × p[i]（相邻矩阵维度对齐才能乘）。矩阵乘法满足结合律，所以乘的「顺序」（即怎么加括号）不影响结果，但会大幅影响标量乘法的总次数。目标是找一种加括号方式，使标量乘法次数最少。

一次 (p×q) 与 (q×r) 矩阵相乘的标量乘法次数是：

p · q · r

初学者的直觉锚：注意这里要优化的不是「矩阵乘法本身怎么算」，而是「先算哪两个、再算哪两个」这个调度顺序。举例：A₁(10×100)、A₂(100×5)、A₃(5×50)。按 ((A₁A₂)A₃) 是 10·100·5 + 10·5·50 = 5000+2500 = 7500 次；按 (A₁(A₂A₃)) 是 100·5·50 + 10·100·50 = 25000+50000 = 75000 次。同一结果，代价差 10 倍——这就是为什么值得优化括号化。

### 7.2.2 括号化数目为何不能暴力枚举

设 n 个矩阵的不同完全括号化方案数为 P(n)，它满足一个卡特兰数式的递推，其增长量级是：

P(n) = Ω(4^n / n^{3/2}) （即指数级）

括号化方案数随 n 指数爆炸，逐一枚举不可行，必须用 DP。

直觉上，「最外层那一刀」可以落在 A₁…Aₖ 与 A_{k+1}…Aₙ 之间的任意位置 k，左右两块又各自独立地继续括号化，于是 P(n) = Σ P(k)P(n−k)，这正是卡特兰数的递推，增长比 2^n 还快。所以和钢条切割一样，暴力不行，得靠「子问题只算一次」。

### 7.2.3 最优子结构与递推式

设 m[i][j] 为把子链 Aᵢ…Aⱼ 乘起来所需的最少标量乘法次数。最外层括号把链在某个 k（i ≤ k < j）处劈成 Aᵢ…Aₖ 和 A_{k+1}…Aⱼ 两块，则递推式为：

m[i][j] = 0，当 i = j

m[i][j] = min over k in [i, j−1] of ( m[i][k] + m[k+1][j] + p[i−1]·p[k]·p[j] )，当 i < j

读这条式子的方法——m[i][k] 是左块的最优代价，m[k+1][j] 是右块的最优代价，p[i−1]·p[k]·p[j] 是把这两块的结果（一个 p[i−1]×p[k]、一个 p[k]×p[j] 的矩阵）最后相乘的代价；对所有可能的劈点 k 取最小。这里体现了最优子结构：整条链的最优括号化，其左右两个子链也必须各自最优（否则把某个子链换成更优的，总代价还能更小，矛盾）。这是一类典型的「区间 DP」——子问题由一个区间 [i, j] 刻画。

### 7.2.4 自底向上算法与复杂度

按「区间长度」从短到长填表：先填所有长度为 1 的区间（代价 0），再填长度 2、3……直到整条链。伪代码：

```
MATRIX-CHAIN-ORDER(p):        # p[0..n]，共 n 个矩阵
    n = p.length − 1
    令 m[1..n][1..n]、s[1..n][1..n] 为新表
    for i = 1 to n: m[i][i] = 0
    for L = 2 to n:                       # L = 链长
        for i = 1 to n − L + 1:
            j = i + L − 1
            m[i][j] = ∞
            for k = i to j − 1:
                q = m[i][k] + m[k+1][j] + p[i−1]·p[k]·p[j]
                if q < m[i][j]:
                    m[i][j] = q
                    s[i][j] = k          # 记录最优劈点，供重构括号化
    return m, s
```

三层循环（区间长度、左端点、劈点）给出运行时间：

Θ(n^3)

空间为 Θ(n²)。辅助 s 表记录每个区间的最优劈点 k，据此可递归打印出最优括号化。

为什么外层要按区间长度 L 递增？因为填 m[i][j] 用到的 m[i][k] 和 m[k+1][j] 都是更短的区间，必须先就绪——这又是「按依赖拓扑序填表」。易错点：注意维度数组 p 的下标——n 个矩阵需要 n+1 个维度值 p[0..n]，Aᵢ 是 p[i−1]×p[i]，写代码时最容易在这里错位。

## 7.3 动态规划要素

### 7.3.1 最优子结构

最优子结构（optimal substructure）：一个问题具有最优子结构，是指它的最优解「包含」其子问题的最优解。这是一个问题能用 DP（也能用贪心）的必要前提。

验证最优子结构的标准套路是「剪切—粘贴」（cut-and-paste）反证法——假设整体最优解里某个子问题用的不是子问题的最优解，那就把这个子解「剪掉」、「粘上」子问题真正的最优解，得到一个更优的整体解，与「整体最优」矛盾。钢条切割里「剩余段必须最优」、矩阵链里「左右子链必须最优」都是这样论证的。刻画最优子结构时要关注两点：一个最优解用到多少个子问题，以及在每个决策里要考虑多少种选择——这两者的乘积大致决定 DP 的运行时间（如矩阵链是 Θ(n²) 个子问题 × 每个 O(n) 种劈点 = Θ(n³)）。易错点：不是所有最优化问题都有最优子结构。CLRS 特意用「无权最短路径有最优子结构、但无权最长简单路径没有」作对比——最长简单路径的子路径拼起来可能不再简单（顶点会重复），子问题之间不独立，故不能这样分解。

### 7.3.2 重叠子问题

重叠子问题（overlapping subproblems）：递归求解时，同一批子问题被反复遇到。子问题的「总数」是输入规模的多项式，但朴素递归会指数次地重复访问它们。这是 DP 相对于分治的关键区别。

分治（大主题2，如归并排序）每次产生的是「全新、不重叠」的子问题，所以不需要存表；而 DP 的子问题会大量重合，才值得「算一次、存起来」。判断一个问题是否重叠，可以画递归调用树/子问题图——若同一个子问题节点在树里出现很多次（如钢条切割里 r[k] 反复出现），就是重叠。正是「多项式个不同子问题 + 指数次重复访问」这个反差，让备忘/填表能把指数时间压成多项式时间。

### 7.3.3 备忘化与自底向上：两种等价实现

同一个 DP 递推可以两种方式落地：自顶向下备忘化（递归 + 缓存）与自底向上填表（循环 + 依赖序）。二者解出的答案相同、渐进时间通常也相同。

怎么选？CLRS 给的经验是——若所有子问题都至少要算一次，自底向上通常常数因子更小（无递归调用与栈开销），且能精确控制填表顺序；若只有一部分子问题会被用到（子问题空间稀疏），自顶向下备忘化更省，因为它只碰「从初始问题可达」的子问题。两者都要求先想清「子问题依赖图」：自底向上要按这个图的拓扑序填，自顶向下则靠递归自动保证「先算依赖」。

### 7.3.4 重构解与子问题图

DP 主表存的是「最优值」；要拿到「最优解本身」，需额外记录每个子问题的最优决策，再回溯重构。子问题及其依赖构成一张有向无环图（子问题图），DP 的运行时间大致正比于「图的顶点数 × 每个顶点的边数（可选决策数）」。

把 DP 看成「在子问题图上做工作」是个很有用的统一视角——顶点是子问题、有向边表示「解某子问题要先解另一子问题」，自底向上就是按图的逆拓扑序访问顶点，备忘化就是这张图上的一次深度优先遍历。运行时间 = Σ(每个子问题内部的决策枚举量)，这解释了为什么钢条切割是 Θ(n²)（n 个子问题、每个 O(n) 决策）、矩阵链是 Θ(n³)（Θ(n²) 个子问题、每个 O(n) 决策）。

这里也是与大主题8 贪心的分水岭：贪心问题同样要求最优子结构，但额外满足「贪心选择性质」——每一步的局部最优选择就能导向全局最优，不必像 DP 那样枚举所有子问题决策再取最优。所以凡是「贪心选择性质」不成立、只能靠「枚举决策 + 子问题最优值比较」的最优化问题，就归 DP。完整对照见大主题8。

#### 来源与时效
- 锚点：CLRS 4th ed (2022) §14.3「Elements of dynamic programming」（p382）——最优子结构（剪切-粘贴论证、最短路 vs 最长简单路径反例）、重叠子问题、备忘化 vs 自底向上取舍、子问题图与运行时间；核实 2026-07-26。
- 锚点：MIT 6.046J (Spring 2015) syllabus「Dynamic Programming」——DP 两要素（最优子结构 + 重叠子问题）作为判定一个问题可用 DP 的标准；核实 2026-07-26。
- 一致：两源都把「最优子结构 + 重叠子问题」列为 DP 的两个标志性要素，并都以「重叠」区分 DP 与分治。
- 对照（非冲突）：本节「贪心选择性质」的对照点锚定 CLRS §15.2（大主题8），此处仅点名指路，不展开证明。
- 成熟度：经典，稳定，无版本漂移。

## 7.4 最长公共子序列

### 7.4.1 问题定义：子序列不是子串

最长公共子序列（Longest Common Subsequence, LCS）问题：给定两个序列 X = ⟨x₁,…,xₘ⟩ 与 Y = ⟨y₁,…,yₙ⟩，求它们最长的公共子序列。子序列是从原序列中「按原顺序、可不连续地」删去若干元素得到的序列。

初学者的直觉锚：务必把「子序列（subsequence）」和「子串（substring）」分清。子串必须连续，子序列只要保持相对顺序、允许中间跳过。例如对 X = ABCBDAB、Y = BDCABA，BCBA 或 BCAB 都是长度 4 的公共子序列（也是最长），而它们在原串里并不连续。LCS 是 diff 工具、DNA 序列比对的核心，实用价值很高。

### 7.4.2 最优子结构与递推式

设 c[i][j] 为前缀 Xᵢ = ⟨x₁,…,xᵢ⟩ 与 Yⱼ = ⟨y₁,…,yⱼ⟩ 的 LCS 长度。递推式按「两序列的最后一个字符是否相等」分情形：

c[i][j] = 0，当 i = 0 或 j = 0

c[i][j] = c[i−1][j−1] + 1，当 i,j > 0 且 xᵢ = yⱼ

c[i][j] = max( c[i−1][j], c[i][j−1] )，当 i,j > 0 且 xᵢ ≠ yⱼ

这条式子的直觉——看两串的末尾字符。如果末尾字符相同（xᵢ = yⱼ），那这个字符一定可以放进 LCS 的末尾，于是问题缩成「去掉两串各自末尾」的子问题再 +1。如果末尾不同，那这两个末尾字符至少有一个用不上：要么丢掉 xᵢ（转而看 c[i−1][j]），要么丢掉 yⱼ（看 c[i][j−1]），取两者较大。这里的最优子结构同样能用剪切-粘贴证明。易错点：末尾相同的分支千万别再对 c[i−1][j]、c[i][j−1] 取 max——一旦末尾字符相同，最优解里必然含这个匹配，走对角 c[i−1][j−1]+1 即可（CLRS 有严格证明）。

### 7.4.3 表格法、复杂度与回溯重构

按行（i 从小到大）、每行按列（j 从小到大）填 (m+1)×(n+1) 的表 c，填每格是 O(1) 工作，运行时间与空间为：

Θ(m · n)

要重构出 LCS 本身，再存一张方向表 b（或直接用 c 反推）：从 c[m][n] 出发，遇到「对角来的（xᵢ=yⱼ）」就把该字符加入结果并往左上走，否则往「c 值更大的那个上/左方向」走，回溯 O(m+n) 步得到一个最长公共子序列。

LCS 是初学 DP 后最该手推一遍的例子，因为它的「二维表 + 分情形递推 + 回溯」是无数序列型 DP（编辑距离、序列比对……）的模板。若只需要长度、不需要序列本身，可用滚动数组把空间从 Θ(mn) 压到 Θ(min(m,n))——只保留相邻两行；但那样就丢了回溯所需的历史，需要方案时仍要完整表或分治式重构。

#### 来源与时效
- 锚点：CLRS 4th ed (2022) §14.4「Longest common subsequence」（p393）——子序列定义、c[i][j] 三情形递推式、LCS-LENGTH 表格法 Θ(mn)、b 表 O(m+n) 回溯重构；核实 2026-07-26。
- 锚点：MIT 6.046J (Spring 2015) syllabus「Dynamic Programming」——LCS/编辑距离作为二维表 DP 的标准实例；核实 2026-07-26。
- 一致：两源对 c[i][j] 递推式与 Θ(mn) 无分歧。
- 实测：DP 结果与「暴力枚举 X 的所有子序列并检验是否为 Y 的子序列」在 300 组随机短串上逐例相等；lcs(ABCBDAB, BDCABA)=4 与 CLRS §14.4 示例一致（见文末实测汇总）。
- 成熟度：经典，稳定，无版本漂移。

## 7.5 最优二叉搜索树

### 7.5.1 问题：最小化期望搜索代价

最优二叉搜索树（Optimal Binary Search Tree, OBST）问题：给定 n 个有序关键字 k₁ < k₂ < … < kₙ，每个 kᵢ 被搜索到的概率是 pᵢ；还有 n+1 个「虚拟键」d₀,…,dₙ 表示落在关键字之间/两端的失败搜索，概率是 qᵢ。目标是构造一棵二叉搜索树，使一次搜索的期望比较代价最小。

一次搜索到达某节点的代价 = 它的深度 + 1（根深度记为 0，故根的访问代价为 1）。整棵树的期望搜索代价为：

E[搜索代价] = Σ (depth(kᵢ)+1)·pᵢ + Σ (depth(dᵢ)+1)·qᵢ

其中所有概率之和为 1：Σ pᵢ + Σ qᵢ = 1。

初学者的直觉锚：这不是问「树平衡不平衡」，而是问「怎么安排树形使高频关键字更靠近根」。高频的键应该浅（少比较几次），低频的可以深。但不能光按频率贪心地放——因为二叉搜索树必须维持中序有序，节点位置互相牵制，所以要 DP 全局权衡。注意这里连「查不到」（虚拟键 dᵢ）也计入期望，因为失败搜索也要花比较次数。

### 7.5.2 最优子结构与递推式

设 e[i][j] 为包含关键字 kᵢ…kⱼ（及其间虚拟键 d_{i−1}…dⱼ）的子树的最小期望搜索代价。若这棵子树选 kᵣ 作根，则左子树含 kᵢ…k_{r−1}、右子树含 k_{r+1}…kⱼ，各自独立最优。定义区间概率和：

w(i, j) = Σ (l=i..j) pₗ + Σ (l=i−1..j) qₗ

递推式为：

e[i][j] = qᵢ₋₁，当 j = i − 1（空子树，只含一个虚拟键）

e[i][j] = min over r in [i, j] of ( e[i][r−1] + e[r+1][j] + w(i, j) )，当 i ≤ j

为什么每选一个根 r 就要整体加 w(i,j)？因为把左右子树接到新根下面时，子树里每个节点的深度都 +1，于是它们对期望代价的贡献各增加「自己的概率」，全部加起来正好是这一层所有节点的概率和 w(i,j)。这个「换根一次、整块深度 +1、代价加区间概率和」的技巧是 OBST 递推的精髓。它和矩阵链一样是区间 DP——枚举根 r 相当于枚举劈点。w(i,j) 可以用 w(i,j) = w(i,j−1) + pⱼ + qⱼ 递推地 O(1) 增量算出，避免每次重新求和。

### 7.5.3 算法与复杂度

和矩阵链同构：按区间长度从短到长填 e 表，每个区间枚举根 r，另用 root 表记录最优根以便重构树形。三层循环给出运行时间：

Θ(n^3)

空间 Θ(n²)。（CLRS 提到用 Knuth 的单调性可优化到 Θ(n²)，属进阶，本课不展开。）

OBST 是本章「DP 技法」的收官练习——它把 7.2 矩阵链的「区间 DP + 枚举劈点/根」和「辅助表重构结构」两件事又练了一遍，只是目标函数从「乘法次数」换成了「期望搜索代价」。学到这里应能看出：钢条切割、矩阵链、OBST 共享同一套骨架（定义子问题 → 分情形/枚举决策写递推 → 按依赖序填表 → 用辅助表重构解），区别只在「子问题怎么定义、决策怎么枚举、代价怎么算」。

#### 来源与时效
- 锚点：CLRS 4th ed (2022) §14.5「Optimal binary search trees」（p400）——期望搜索代价定义、w(i,j) 与 e[i][j] 递推式、按区间长度填表的 Θ(n³) 算法与 root 表重构、Knuth 单调性可达 Θ(n²) 的提示；核实 2026-07-26。
- 锚点：MIT 6.046J (Spring 2015) syllabus「Dynamic Programming」——OBST/区间 DP 作为进阶 DP 实例；核实 2026-07-26。
- 一致：两源对 e[i][j] 递推式与 Θ(n³) 基本算法无分歧；Θ(n²) 优化两源均作为「进阶提示」列出、不作本课要求。
- 实测：DP 结果与「暴力枚举所有 BST 树形并按深度计期望代价」在 CLRS §14.5 的 n=5 数据上均为 2.75，且在 50 组随机概率实例上逐例相等（见文末实测汇总）。
- 成熟度：经典，稳定，无版本漂移。
